## 一、差分与误差阶数

### 1.（手算）`x³` 在 `x = 2`、`h = 1e-3`

```text
前向   (f(2.001) − f(2)) / 0.001 = (8.012006001 − 8) / 0.001 = 12.006001
后向   (f(2) − f(1.999)) / 0.001 = (8 − 7.988005999) / 0.001 = 11.994001
真值   f'(2) = 3·2² = 12
误差   前向 6.001e-3    后向 5.999e-3        （两者都在 O(h) = 1e-3 的量级）
中心   (f(2.001) − f(1.999)) / 0.002 = 12.000001    误差 1e-6（O(h²)）
```

**验证**：`central_difference(f, 2.0, step=1e-3) = 12.000000999998317`。

要点：误差不是"前向比中心差一点"，而是**差一个数量级**（`h` 与 `h²`）。
`h` 再小 100 倍，差距还会拉大到 100 倍。

### 2.（推导）中心差分的两条泰勒展开

```text
f(x+h) = f(x) + h f'(x) + h² f''(x)/2 + h³ f'''(x)/6 + O(h⁴)
f(x−h) = f(x) − h f'(x) + h² f''(x)/2 − h³ f'''(x)/6 + O(h⁴)
```

相减时：

```text
f(x+h) − f(x−h) = 2h f'(x) + 2·h³ f'''(x)/6 + O(h⁵) = 2h f'(x) + h³ f'''(x)/3 + O(h⁵)
```

**三项各自的下场**：

```text
f(x)          两次都是 +f(x)，相减抵消
±h f'(x)      一正一负 → 2h f'(x)      ← 这就是我们要的
h² f''(x)/2   两次都是正 → **相减抵消** ← 关键的一项
h³ f'''(x)/6  一正一负 → 留下 h³ 项
```

于是 `(f(x+h) − f(x−h))/(2h) = f'(x) + O(h²)`。
"`h f''(x)` 那一项被减掉"说的是**前向差分里那一项**：
`(f(x+h) − f(x))/h = f'(x) + h f''(x)/2 + O(h²)`，误差的第一项是 `O(h)`。

### 3.（概念）阶数只在截断误差主导区有意义

误差由两种机制共同决定：

```text
截断误差    随 h 下降（O(h) 或 O(h²)）
舍入误差    随 h 上升（≈ eps·|f|/(2h)）
```

只有在前者主导的区间，"误差之比"才等于"步长之比的幂"。
用 `h = 1e-12` 与 `h = 1e-14` 去算，得到的是**负数**：

```text
前向 -0.667      中心 -0.824
```

负数不代表"阶数变负"，而是**误差不再随 h 单调下降**——
那里两条读数之比由浮点噪声决定，是一个随机量。数字本身没有意义，
但它**看起来像一个结果**，这正是危险之处。

**验证**：`step_size_study(exp, 1.0, math.e).observed_order("forward", index=10) = -0.667`。

### 4.（动手）`step_size_study(exp, 1.0, math.e)`

```text
实测阶数     前向 1.01    后向 1.01    中心 2.00        （缺省取最初两条读数）
触底         h = 1e-5，中心误差 5.859e-11（更细的表里 h = 1e-6 是 1.635e-10）
最大误差     h = 1e-14，中心误差 9.338e-03   ← 比最优处差 8 个数量级
```

**最后两列在前 4 行是常数**：

```text
h = 1e-1 → 1e-4    前向/h ≈ 1.36    中心/h² ≈ 0.453
h = 1e-05          中心/h² = 0.586   ← 开始偏离（舍入已经出场）
h = 1e-06 之后     中心/h² 变成 1.6e2、5.9e3、6.6e7 …   ← 完全失去意义
```

**为什么在那里应当是常数**：截断误差的形式是 `C·h^p`，
于是 `误差/h`（前向）与 `误差/h²`（中心）都等于常数 `C`。
它们偏离常数的那一刻，就是另一种机制（舍入）开始主导的那一刻——
这也是**判断"误差阶数还成立吗"的最直观的办法**。

### 5.（设计）二阶差分的步长为什么必须更大

二阶差分 `(f(x+h) − 2f(x) + f(x−h))/h²` 的分母是 `h²`，
舍入误差因此被放大 `1/h²` 倍：

```text
分子上的舍入误差 ≈ 4·eps·|f|
导数上的舍入误差 ≈ 4·eps·|f| / h²
h = 1e-6（缺省）   |f| ≈ 8（x³ 在 2 处）→  4·2.22e-16·8/1e-12 ≈ 7.1e-3
h = 1e-4           同上 ≈ 7.1e-7
```

第一次跑 `test_second_difference_of_cubic` 时得到 `12.002843`——
误差 `2.8e-3`，与上面的估算同量级；换成 `h = 1e-4` 之后误差降到 `1e-5` 以下。

**这就是"误差量级知识直接用在了选参数上"**：不是"步长越小越准"，
而是"分母的次数越高，步长就要越大"。

## 二、梯度与方向导数

### 6.（手算）`f(x, y) = 3x² + y² + xy` 在 `(0.7, −0.4)`

```text
∂f/∂x = 6x + y = 6·0.7 + (−0.4) = 4.2 − 0.4 = 3.8
∂f/∂y = 2y + x = 2·(−0.4) + 0.7 = −0.8 + 0.7 = −0.1
‖∇f‖ = √(3.8² + 0.1²) = √(14.44 + 0.01) = √14.45 = 3.801316
```

沿 `(1, 1)` 的**单位**方向（`(1,1)/√2 = (0.707107, 0.707107)`）：

```text
D_u f = ∇f · û = (3.8 + (−0.1)) / √2 = 3.7 / 1.414214 = 2.616295
```

**验证**：`directional_derivative(surface, (0.7, −0.4), (1.0, 1.0)) = 2.6162950906849503`。

### 7.（概念）方向为什么必须归一化

`directional_derivative` 内部做 `unit = direction / ‖direction‖`，因此：

```text
沿 (2, 0) 的方向导数 = 沿 (1, 0) 的方向导数 × 1     （两者都变成 û = (1, 0)）
```

如果**不**归一化，沿 `(2, 0)` 会得到 `∂f/∂x` 的 2 倍。后果是：

```text
"方向导数"变成了一个既取决于方向、又取决于向量长度的量——
而"方向"这个词本身不该带长度信息（长度是步长的事）
```

零方向（`(0, 0)`）当场报错：零向量没有方向，沿它没有"变化率"可言
（与 day073 的 `normalize` 拒绝零向量是同一条纪律）。

### 8.（推导）最大方向导数 = `‖∇f‖`

设 `u` 是单位向量，`D_u f = ∇f · u`。柯西–施瓦茨不等式给出

```text
|∇f · u| ≤ ‖∇f‖·‖u‖ = ‖∇f‖         （因为 ‖u‖ = 1）
```

取等条件是 `u` 与 `∇f` **线性相关**；在单位向量的约束下只有两个解
`±∇f/‖∇f‖`。因此：

```text
最大值 = ‖∇f‖，在 u = +∇f/‖∇f‖ 处取到
最小值 = −‖∇f‖，在 u = −∇f/‖∇f‖ 处取到（最陡下降方向）
```

**验证**：沿 `∇f` 的方向导数 = `3.8013155616578587`，而 `‖∇f‖ = 3.8013155619713963`
（差 3e-10，就是数值差分自身的分辨率）。

### 9.（动手）四个方向与 36 方向扫描

```text
沿 (1, 0)     +3.800000    = ∂f/∂x
沿 (0, 1)     −0.100000    = ∂f/∂y
沿 (1, 1)     +2.616295    两个单位方向的合成（除以 √2）
沿 ∇f         +3.801316    = ‖∇f‖（柯西–施瓦茨取等）
扫 36 个固定方向取最大值   +3.800000
```

最大值**严格小于** `‖∇f‖`，差值 `1.32e-03`。
原因是网格是**离散的**：36 个方向的角度间隔是 `π/18 = 10°`，
而 `∇f` 的方向角是 `atan2(−0.1, 3.8) ≈ −1.5°`——它**不在网格上**。

```text
差值的量级   二阶小量：Δθ²/2 ≈ (0.026 rad)²/2 ≈ 3.4e-4 × ‖∇f‖ ≈ 1.3e-3  ✓ 与实测吻合
```

这条读数的价值在于：**"扫一圈取最大"永远只能给一个下界**，
而"沿 ∇f 算一次"给的是精确值。两者之差就是网格分辨率的精度代价。

### 10.（概念）`n` 维梯度的代价

中心差分对每个分量要做 2 次函数求值，因此 `n` 维梯度需要 **`2n` 次求值**
（前向/后向差分是 `n` 次，但精度差一个数量级）。

```text
n = 768（一个常见 embedding 维度）    →  1536 次函数求值
n = 4096（一个小模型的一层权重）      →  8192 次
n = 1e8（7B 模型全参数）              →  2e8 次
```

day064 的向量检索里，一次查询是 `n_docs × d` 次乘加——**规模同量级但常数完全不同**：
检索是"一次查询要扫全库"，而这里是"一个梯度要扫全参数"。
两者都不适合"用最朴素的实现每次都重算"，区别是检索可以建索引、
而数值梯度**没有索引可建**。这就是"生产里用解析梯度（反向传播）、
数值梯度只用来验证"的全部算术理由。

## 三、链式法则与反向传播

### 11.（手算）`d/dx sin(exp(2x))` 在 `x = 0`

三段局部导数，**每层在自己的点上取值**：

```text
最内层   u = 2x          du/dx = 2
中间层   v = exp(u)      dv/du = exp(u) = exp(0) = 1
最外层   w = sin(v)      dw/dv = cos(v) = cos(1)
```

相乘：

```text
dw/dx = cos(1) · 1 · 2 = 2cos(1) = 2 × 0.540302 = 1.080605
```

**验证**：`chain_rule([sin, exp, 2x], 0.0)` 给出 `(1.080604611736, 1.080604611763)`——
第一条是"对复合函数整体做差分"，第二条是"局部导数之积"，两者相差 2.7e-11
（数值差分的分辨率）。

### 12.（概念）在哪个点取值

复合 `g(f(x))` 其中 `f(x) = x²`、`g(u) = u + 1`，于是 `g(f(x)) = x² + 1`：

```text
正确写法   g'(f(x)) · f'(x) = 1 · 2x = 2x
错法       g'(x) · f'(x) = 1 · 2x = 2x        （这个例子里恰好相同，因为 g' 恒为 1）
```

换一个能暴露问题的例子：`f(x) = x + 1`、`g(u) = u²`，复合为 `(x + 1)²`：

```text
正确   g'(f(x)) · f'(x) = 2(x + 1) · 1 = 2(x + 1)     在 x = 3 处是 8
错法   g'(x) · f'(x) = 2x · 1 = 2x                    在 x = 3 处是 7
```

**验证**：`2·(3+1) = 8.0`，`2·3+1 = 7.0`。
错值 7 比正确值 8 只小 12.5%——在训练里表现为"慢一点"，而不是"坏了"。
这就是为什么 `chain_rule` 要把两条路并排打印出来。

### 13.（手算）`y = x·x` 的计算图

```text
两个节点：
  x         leaf    值 3     梯度 6
  y = x·x   mul     值 9     梯度 1（它在图上是根，seed = 1）
```

`x` 的梯度是 **6**。"两份 3"来自：

```text
乘法节点的局部导数规则：对左乘数是"右乘数的值"、对右乘数是"左乘数的值"
两条边（x→y 出现两次）各调用一次这个规则，各推一份 3
```

于是 `x.grad = 3 + 3 = 6 = 2x` ✓（与解析式一致）。

**验证**：`gradients_of(x * x)["x"] = 6.0`，`len(node.trace()) == 2`。

### 14.（设计）写成 `=` 会怎样

```text
x 的梯度会变成 3（而不是 6）——**少了一半**
```

在训练里它看起来像：

```text
梯度小一半 → 每一步的位移小一半 → 损失下降更慢 →
"像是学习率设小了" → 于是有人去把 lr 调大 2 倍
```

而调大 lr 之后在别处（没有共享子表达式的分支上）又会过大——
因为**误差只出现在"一个值被用多次"的地方**，不是全局一致的缩放。
这与"抛异常"的差别在于：异常会告诉你哪一行错了，
而它只会告诉你"这个超参好像要调"。

### 15.（概念）`propagate` 读错 `self.grad`

正确写法是 `node._propagate(node.grad)`（把**本节点的上游梯度**传进去）。

**在什么形状的图上会恰好正确**：只有一个运算节点、且它的左操作数就是叶子时。

```text
y = x·x, x = 3   乘法节点的上游梯度恰好是 1（它是根），
                 而 bug 版本用的是"局部导数不乘上游"——
                 在单层图上 |上游| = 1，乘不乘一样 → 恰好正确
exp(x²) 在 x = 2 两层图：bug 版本给出 4.0，正确值是 218.392600
                 （丢了 e⁴ = 54.598 这个上游因子，差 54 倍）
```

**为什么"恰好正确"更危险**：第一版实现跑通了一个"单层例子"的冒烟测试——
它给了错误的安全感。真正变绿的是 `gradcheck` 的 `autograd_chain` 那一项
（误差从 2.88 降到 1.99e-10），也就是**与一个独立方法对照**才发现。

### 16.（动手）拓扑序为什么用迭代

Python 缺省递归深度是 1000。一条 2000 层的加法链在递归实现下会抛
`RecursionError: maximum recursion depth exceeded`。

**验证**：`test_deep_chain_does_not_hit_the_recursion_limit` 构造 2000 层加法链，
迭代实现跑完并给出 `x.grad == 1.0`。

为什么值得单独处理：

```text
"层数一多就崩"这个现象，与"模型太大"在直觉上长得很像——
但两者一个是**实现方式**的问题（改用迭代 / 提高上限），
一个是**资源**的问题（换机器 / 减 batch）。分不清就会修错方向。
```

### 17.（设计）`zero_grad()` 的必要性

`backward()` 里的累积是 `+=`，而 `self.grad = float(seed)` 只重置**根节点**。
因此同一张图跑两次：

```text
第一次 backward   x.grad = 6
第二次 backward   x.grad = 12      ← 两次的和
```

**验证**：`test_repeated_backward_stacks_gradients` 断言 `x.grad == 12.0`。

在日志里它看起来像：

```text
"梯度比预期大两倍" → 训练更快但更不稳 → 被解释成"动量有点大"
```

而 `zero_grad()` 存在的意义就是把这个"隐藏的累加"变成一次**显式决定**。
**验证**：`test_zero_grad_resets_the_whole_graph` 断言清零后重建为 `6.0`。

## 四、优化器

### 18.（手算）SGD 一步

```text
θ ← θ − lr·g = (1, 2) − 0.1·(0.5, −0.25) = (1 − 0.05, 2 + 0.025) = (0.95, 2.025)
```

**验证**：`SGDOptimizer(0.1).step((1.0, 2.0), (0.5, −0.25)) == (0.95, 2.025)` ✓

### 19.（手算）动量法两步（累加型，`β = 0.9`、`lr = 0.1`、`g ≡ 1`）

```text
v₁ = β·v₀ + g₁ = 0.9·0 + 1 = 1        θ₁ = 0 − 0.1·1 = −0.1      位移 −0.1
v₂ = 0.9·1 + 1 = 1.9                   θ₂ = −0.1 − 0.1·1.9 = −0.29  位移 −0.19
```

**验证**：实测 `v = (1.0,)` 然后 `(1.9,)`，位移 `−0.1` 与 `−0.19` ✓

`β` 改成 `0.99`：稳态幅度 `g/(1−β) = 1/0.01 = 100`。
**验证**：实测 `1/(1−0.99) = 99.99999999999991`。

对等效学习率的影响：

```text
β = 0.9   稳态速度是梯度的 10 倍  →  等效 lr ≈ 10·lr
β = 0.99  稳态速度是梯度的 100 倍 →  等效 lr ≈ 100·lr
```

也就是说**"把 β 从 0.9 调到 0.99"约等于"把学习率调大 10 倍"**——
而它看起来只是"动量更平滑了"。

### 20.（概念）累加型 vs EMA 型

```text
累加型（本实现）  v ← βv + g            稳态幅度 g/(1−β)
EMA 型           v ← βv + (1−β)g        稳态幅度 g
```

**能换算**：把 EMA 型的更新式整体除以 `(1−β)` 就得到累加型的形式，
因此"用累加型 + lr"与"用 EMA 型 + lr/(1−β)"是**同一条轨迹**。

**混用的后果**：等效学习率差一个 `1/(1−β) = 10` 倍的因子（`β = 0.9`）。
看起来像：

```text
"换成这个优化器之后需要重新调 lr" → 被归成"不同优化器风格不同"
```

这是"两处实现都对、但口径不同"的典型：它不报错，只是参数的含义变了。

### 21.（手算）Adam 第一步（`lr = 0.1`、`β₁ = 0.9`、`β₂ = 0.999`、`g = 1`）

```text
m₁ = (1−β₁)·g = 0.1           （真值的 1/10）
v₁ = (1−β₂)·g² = 0.001        （真值的 1/1000）
修正因子  1 − β₁¹ = 0.1        1 − β₂¹ = 0.001
修正后    m̂ = 0.1/0.1 = 1      v̂ = 0.001/0.001 = 1
位移      −lr·m̂/(√v̂ + ε) = −0.1·1/(1 + 1e-8) = −0.099999999
未修正    −lr·m/(√v + ε) = −0.1·0.1/(0.031623 + 1e-8) = −0.316228
```

**验证**：实测 `-0.09999999900000002` 与 `0.31622766601686964` ✓
未修正是正确值的 **3.16 倍**。

### 22.（推导）梯度恒定时每步位移都是 `lr`

设 `g_t = g`（常数）。两个动量的递推是几何级数：

```text
m_t = (1−β₁)·g·Σ_{k=0}^{t−1} β₁^k = (1−β₁^t)·g
v_t = (1−β₂)·g²·Σ_{k=0}^{t−1} β₂^k = (1−β₂^t)·g²
```

于是

```text
m̂_t = m_t/(1−β₁^t) = g
v̂_t = v_t/(1−β₂^t) = g²
m̂_t / √v̂_t = g / |g| = sign(g)        ← 两个修正因子恰好抵消
```

代回更新式：

```text
θ_{t+1} = θ_t − lr·sign(g)/(1 + ε/|g|) ≈ θ_t − lr·sign(g)
```

**结论**：每步位移都是 `lr`，与 `|g|` 的大小无关。
**验证**：`test_constant_gradient_gives_approximately_lr_per_step`——
梯度 `1e-3` 与 `1e3`（差 100 万倍）走 30 步的位移都是 `−3.0`。

**推论**（副作用）：后期在最优点附近，梯度方向会来回翻，而每步仍是 `lr`
→ 在最优点附近**来回横跳**。这就是 Adam 需要后期退火的原因。

### 23.（动手）两种地形上的三个优化器

```text
碗形 (x−1)² + 4(y+2)²，100 步             峡谷 x² + 20y²，60 步
SGD    lr=0.05  →  损失 0.000000          SGD    lr=0.01  →  损失 0.796841
动量    lr=0.05  →  损失 0.002793          动量    lr=0.01  →  损失 0.002437
Adam   lr=0.20  →  损失 0.000131          Adam   lr=0.10  →  损失 0.029205
```

- 碗形：**SGD 最低**（0.000000），三者差别很小。
- 峡谷：**动量最低**（0.002437），SGD 明显最差（0.796841）。

"哪个优化器更好"离开地形没有意义，因为它们的差别来自**地形的曲率分布**：

```text
曲率相同（碗形）   三个方向都被同样缩放，动量的历史信息没有额外价值，
                   Adam 的额外状态反而是开销 → SGD 够用甚至更快
曲率差 20 倍（峡谷）SGD 在陡方向步长过大、在缓方向步长过小（反复横跳），
                   动量把历史梯度累成速度、Adam 给每个参数各自的等效步长 → 明显更好
```

### 24.（设计）两种裁剪，同一个输入

取 `g = (100, 1)`、阈值 `1`：

```text
clip_by_global_norm(g, 1)   ‖g‖ = 100.005 → 乘 1/100.005 = 0.0099995
                            → (0.99995, 0.0099995)      **方向不变**
clip_by_value(g, 1)         → (1, 1)                    **方向变了**
```

方向变化的量级：原始方向角 `atan(1/100) = 0.57°`，裁剪后 `45°`。

```text
整体范数裁剪   适合"这一步整体太长"（梯度爆炸的常见形式）：
               它约束的是**步长**，因此方向信息完整保留
逐分量裁剪     适合"个别分量爆炸"（例如某个 embedding 的某个维度）：
               它更像"削顶"，会改变方向——必须知道这一点再用
```

**验证**：演示脚本第 10 节把两组数都打印出来，`clip_by_global_norm` 还返回
缩放系数 `0.099995`（"生效"的证据）。

## 五、学习率调度

### 25.（手算）`step_decay(base_lr = 0.1, drop_every = 3, gamma = 0.5)`

指数是 `⌊(t−1)/3⌋`：

```text
t=1   ⌊0/3⌋ = 0   0.1 × 0.5⁰ = 0.1
t=3   ⌊2/3⌋ = 0   0.1
t=4   ⌊3/3⌋ = 1   0.1 × 0.5  = 0.05
t=6   ⌊5/3⌋ = 1   0.05
t=7   ⌊6/3⌋ = 2   0.1 × 0.25 = 0.025
t=9   ⌊8/3⌋ = 2   0.025
```

**验证**：实测六个值分别为 `0.1 / 0.1 / 0.05 / 0.05 / 0.025 / 0.025` ✓

注意 `t = 3` 仍然是 `0.1`：`⌊(t−1)/drop_every⌋` 里的 `−1` 就是"从第 1 步开始数"的体现。
写成 `⌊t/3⌋` 的话 `t = 3` 就会掉到 `0.05`——**提前一步**掉档。

### 26.（手算）`cosine(base_lr = 0.1, total_steps = 5, min_lr = 0)`

公式 `lr(t) = 0.1·(1 + cos(π(t−1)/4))/2`：

```text
t=1   cos(0)      = 1        0.1·(1+1)/2 = 0.1
t=2   cos(π/4)    = 0.707107 0.1·(1.707107)/2 = 0.085355
t=3   cos(π/2)    = 0        0.1·(1)/2 = 0.05          ← 中点恰好是一半
t=4   cos(3π/4)   = −0.707107 0.1·(0.292893)/2 = 0.014645
t=5   cos(π)      = −1       0.1·0/2 = 0.0              ← 端点恰好是 min_lr
```

**验证**：实测 `0.1 / 0.08535533905932738 / 0.05 / 0.014644660940672627 / 0.0` ✓

两端都取到端点（`t = 1` 是 `base_lr`、`t = T` 是 `min_lr`），
中间点恰好是一半——这三条都是"分母用 `T−1`"的直接结果。

### 27.（设计）分母用 `T` 会怎样

用 `T = 10` 时，第 10 步的进度是 `(10−1)/10 = 0.9`：

```text
lr(10) = 0.1·(1 + cos(0.9π))/2 = 0.1·(1 − 0.951057)/2 = 0.002447
```

而正确值（分母 `T−1 = 9`）是 `0.0`。

```text
偏差是 0.002447 —— 相对于 base_lr 0.1 是 2.4%
```

**为什么不会被注意到**：

```text
① 学习率曲线上它只是"最后一步比预期大一点点"，肉眼看不出
② 它不影响任何中间步（只有最后一步）
③ 训练早已进入收敛平台区，最后一步的 2.4% 差异被噪声完全淹没
```

而它的危害不在于"最后一步大一点"，而在于**"我说了退火到 0 但实际没有"**——
一个调度器的承诺与行为不一致，比调度器本身差更麻烦。

### 28.（设计）warmup 第 1 步不能是 0

`warmup_cosine(base_lr = 0.1, warmup_steps = 4)` 的第 1 步是 `0.1/4 = 0.025`。
如果写成 `base_lr·(t−1)/warmup`（第 1 步为 0）：

```text
第 1 步的更新量 = 0 · g = 0    参数**一点没动**
```

日志里会出现：

```text
step 0 | lr      — | loss 2.41234567
step 1 | lr 0.000000 | loss 2.41234567     ← 两次一模一样
```

它会被误读成**"梯度算错了"**——因为"损失没变"最常见的解释是"梯度是 0"。
而这个现象与梯度毫无关系。

> 这一条与第三章的"低于分辨率的容差"是同一类错误：
> **一个"看起来很保守"的选择，产生了一个会被归因到别处去的现象。**

### 29.（概念）常数调度是基线

`warmup_cosine` 的实验只能回答"它相对**某个东西**更好还是更差"。
没有常数调度作为对照，能说明与不能说明的是：

```text
能说明   "损失降到了多少"（一个绝对数字）
不能说明 "这个降幅是调度的功劳，还是 Adam / 数据 / 步数的功劳"
```

常数调度正是那个"把一切都固定住，只让学习率曲线变化"的对照臂。
这和 day073 里"零向量的三种约定必须并排写出来"是同一种工程判断：
**一个决策的价值，由它被对比的那个基线定义。**

（实测差距：演示脚本第 8 节用的是常数 lr，因此那里的结论是
"优化器之间的差别"；要得到"调度之间的差别"，只需把 `minimize(..., schedule=...)`
换成 `make_schedule("warmup_cosine", ...)`，其余全不动。）

## 六、梯度对照与工程

### 30.（概念）`rejected` 为什么不会出现在 `gradcheck`

`bridge` 的三种结论：

```text
agrees     逐点在容差内一致
differs    超出容差——这才是需要改代码的信号
rejected   两边的**拒绝行为**不同（一边报错、一边给出值）
```

`rejected` 存在的前提是"两侧是**两个不同用途的实现**"：

```text
教学实现   零向量归一化 → 报错（零向量没有方向）
生产实现   零向量归一化 → 原样返回（写入侧不能因此抛异常）
两条都对，因此必须被**记录**而不是被"统一"
```

`gradcheck` 里两侧是**解析式**与**数值差分**——输入完全由我们选定，
因此"一边拒绝一边放行"不可能出现。如果数值差分被拒
（例如 `perplexity` 的定义域边界 `L = 0` 上要取 `−1e-6`），
那说明"这个点不适合做双向差分"，正确处理是**换掉样本**：

```python
PERPLEXITY_INPUTS: Vector = (0.25, math.log(2.0), 1.0, math.log(100.0), 3.0)
```

> 一个"没有出现过的状态"与"处理了但没发生"不一样。
> 报告里两者都只会留下一片空白——因此"为什么这里只有两种结论"必须写下来。

### 31.（手算）`z = (1, 2)` 的 softmax 与雅可比

```text
e¹ = 2.718282    e² = 7.389056    和 = 10.107338
p₀ = 2.718282/10.107338 = 0.268941
p₁ = 7.389056/10.107338 = 0.731059
```

雅可比 `J_ij = p_i(δ_ij − p_j)`：

```text
J₀₀ = p₀(1 − p₀) = 0.268941 × 0.731059 = 0.196612
J₀₁ = p₀(0 − p₁) = −0.268941 × 0.731059 = −0.196612
J₁₀ = p₁(0 − p₀) = −0.731059 × 0.268941 = −0.196612
J₁₁ = p₁(1 − p₁) = 0.731059 × 0.268941 = 0.196612
```

**验证**：实测 `(0.1966119332619254, −0.1966119332619254)` 与
`(−0.19661193317865866, 0.19661193317865866)`（第 1、3 位相差 1e-10，是数值差分的分辨率）。

**每一行之和为 0** ✓ 实测 `行和 0.0`。

原因：`Σ_j J_ij = Σ_j p_i(δ_ij − p_j) = p_i(Σ_j δ_ij − Σ_j p_j) = p_i(1 − 1) = 0`。
几何含义是"softmax 的输出永远在同一张概率单纯形上"——
任何方向的扰动都不能改变"和为 1"，因此每一行的导数和必然为 0。

### 32.（推导）`∂(−log p_y)/∂z = p − onehot(y)`

设 `L = −log p_y`。链式法则：

```text
∂L/∂z_j = Σ_i (∂L/∂p_i) · (∂p_i/∂z_j)
```

只有 `i = y` 那一项非零（`L` 只依赖 `p_y`），而 `∂L/∂p_y = −1/p_y`，于是

```text
∂L/∂z_j = (−1/p_y) · J_yj = (−1/p_y) · p_y(δ_yj − p_j) = −(δ_yj − p_j) = p_j − onehot(y)_j
```

`p_y` 与 `1/p_y` **约掉了**——这就是"雅可比被抵消"的确切含义。

**验证**（`z = (1, 2)`、`y = 1`）：

```text
−J[:,y]/p_y     = (0.2689414213979594, −0.26894142128406057)
p − onehot(y)   = (0.2689414213699951, −0.2689414213699951)      ← 逐位相同（差 3e-11）
```

**为什么"雅可比写错"时这个结论看起来仍然正确**：
因为实现这条公式的代码**根本不用雅可比**——它直接算 `p − onehot`。
于是：

```text
雅可比写错 → 若没有人单独用它，这个错误**永远不会被发现**
           而"softmax 的雅可比"这个知识本身没有任何护栏
```

这就是 `check_softmax_jacobian` 必须单独存在的原因。
测试 `TestSoftmaxJacobianCancellation` 把上面这条等式**当作断言**写了下来。

### 33.（设计）容差是怎么定出来的

分辨率公式（第三章 3.4）：

```text
导数上的分辨率下限 = eps·|f| / (2h)
|f| = 30，h = 1e-6    →  2.220446e-16 × 30 / (2e-6) = 3.331e-09
|f| = 10，h = 1e-6    →  1.110e-09
```

`GRADIENT_TOLERANCE = 1e-8` 的两条理由：

```text
① 它比最坏案例（|f| ≈ 10 → 1.11e-9）高约一个数量级      ← 不会假警报
② "真的写错了"通常差 1e-3 以上，中间隔着 5 个数量级      ← 区分度充足
```

如果取 `1e-12`（低于分辨率）：

```text
log_sigmoid 那一项（|f| ≈ 30，分辨率 3.3e-9）会报 differs
→ 报告里出现一条"不一致"，而两边都没错
→ 有人去改一份本来正确的代码；改完仍然"不一致"（因为下限在那里）
→ 最终结论多半是"这个对照不可信" → 整项被关掉
```

**验证**：`check_softmax_jacobian(tolerance=1e-30).status == "differs"`——
同一份正确实现，只因为容差低于分辨率就被判为"分歧"。

### 34.（写作）判据不进配置：什么情况下这个取舍不合适

day073 与 day074 共同的选择是"容差、温度、秩、步长、学习率曲线都进函数参数，
不进 `config.py`"。它的正面理由：

```text
配置    一次设定、多处共享、改了影响**系统行为**
判据    一次计算一份、改了只影响**这一份报告或这一次训练**
```

`GRADIENT_TOLERANCE` 若进了 `.env`，"CI 上通过、本地失败"就会变成
一个需要读多人环境变量才能解释的问题——而根因只是某台机器上是 `1e-9`。

**它反而不合适的情况有三种**，都需要具体机制：

```text
① 判据必须**全局一致**时
   例如"所有评估器的通过阈值"——如果 20 个调用点各自传一个浮点数，
   那么"这次评估为什么通过"要看 20 处。此时应当有一个**共享常量**
   （而不是环境变量）：它的改动会出现在 diff 里，而不是某个人的 .env 里。

② 判据需要按**环境**切换时
   例如本地调试想把步长放大到 1e-3 快一点，而 CI 用 1e-6。
   这时该进配置——但要写成"两个有名的档位"（debug / ci），
   而不是一个自由浮点数：自由浮点数会让"这次结果不可比"变成一个查不出的现象。

③ 判据是**实验变量**时
   例如"扫一遍不同 tolerance 看对照的敏感度"。
   这属于实验参数，应当进**实验配置**（脚本的参数表），
   而不是产品配置——两者的读者与生命周期都不同。
```

一句话总结这个取舍的判据：

```text
改动它会不会让**两次结果变得不可比**？
  不会（只影响这一次）  → 函数参数
  会（影响系统行为）    → 常量或配置，且必须可审计
```

## 参考答案小结

这一课 34 道题里有 12 道需要**动手跑**。它们共同的形状是：
先算出一个**手推的期望值**，再与实现在同一点上的输出对照。
如果两者不一致，有三种可能：

```text
① 实现错了        用 gradcheck / 数值差分定位（第五章的 bug 就是这么找到的）
② 期望值错了      第三章 3.2、第十二章 12.4 都是这种情况
③ 容差低于分辨率  第三章 3.4（1e-9 那条假警报）
```

**三种可能都必须先被区分开，再动手改代码**——
这一课最重要的收获不是"会求导"，而是"知道一个数字为什么可信"。
