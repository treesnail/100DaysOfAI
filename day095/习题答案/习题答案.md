# day095 习题答案：训练技巧与正则化 —— 给一条能跑的链装上四个旋钮

> 参考答案。每题都尽量给出"为什么"与"看源码的哪里"。
> 涉及的模块都在 `smart_research_agent/regularization/` 下。

## 一、速答

**1.** 两条轴：

```text
batch（BatchNorm）    μ_j = (1/N)·Σ_n x_nj；σ²_j = (1/N)·Σ_n (x_nj − μ_j)²   （固定一个特征 j）
feature（LayerNorm）  μ_n = (1/F)·Σ_j x_nj；σ²_n = (1/F)·Σ_j (x_nj − μ_n)²   （固定一条样本 n）
```

**`feature` 那一条与"批里有多少条样本"无关**：它只在一行内部取平均，
因此单条样本也能算。`batch` 那一条相反——它的统计量是整批的函数，
批大小变成 1 时方差恒为 0。见 `types.AXIS_FORMULAS` 与 `normalization.batch_statistics`。

**2.** 链条只有三步：

```text
批大小 1 ⇒ 该特征的 N 个取值只有 1 个 ⇒ 方差 = (1/1)·(x − x)² = 0
        ⇒ x̂ = (x − x)/√(0 + ε) = 0
        ⇒ y = γ⊙x̂ + β = β
```

于是整层输出是一个**与输入无关的常数**。本课的网络因此一次前向处理**一批样本**
（把每条的 h_T 竖着堆成 `(N, H)` 再交给 BN）——否则 BN 这一层是"装上了但等于没装"。
第一版实现真的撞上了这件事：三条不同配置给出**同一个 loss**（`0.542374`）。
读数见 `normalization.batch_size_one_report`。

**3.** 训练相用**这一批自己的** μ/σ（同时把 running 统计量往这批靠一步）；
推理相用 **running** 统计量。写反的后果是：

```text
推理时用本批统计量 ⇒ 输出随批抖动（单条样本时方差为 0，整层被压成常数 β）
⇒ 线上结果忽好忽坏，而所有形状检查、有限性检查全部通过
```

因此本包把"推理相缺 running"做成一个显式的 `PhaseError`，
并用第 ③ 条性质（下界）与第 ⑤ 条（推理相反向的数值对账）共同钉住它。

**4.** 因为**口径要对齐**：PyTorch 的 BatchNorm 与 day079 的 LayerNorm 都用有偏方差。
用 `N = 2` 的两条样本 `(a, b)` 说明：

```text
有偏   σ² = ((a−μ)² + (b−μ)²)/2 = (a−b)²/4
无偏   σ² = ((a−μ)² + (b−μ)²)/1 = (a−b)²/2      ← 恰好是两倍
```

批很小时这个差别很明显；而它**不会报错**，只会让标准化后的尺度整体偏小
（`√2` 倍），于是下游看到的是"激活幅度不太对"，而不是"方差算错了"。

**5.** 训练相 **3 项**、推理相 **1 项**：

```text
训练相   dx_nj = (1/σ_j)·( dŷ_nj − mean_n(dŷ_j) − x̂_nj·mean_n(dŷ_j ⊙ x̂_j) )
推理相   dx_nj = dŷ_nj / σ_j
```

多出来的两项存在，是因为训练相的 μ/σ **也是 x 的函数**：
`x̂` 里"减掉 μ"与"除以 σ"这两件事都会把 x 的变化传导回自己身上，
于是求导时多出"减掉均值那一项"与"σ 也依赖 x 那一项"。推理相的 μ/σ 来自 running（常数），这两项就不该出现。
见 `normalization.batch_norm_backward` 的文档串。

**6.** 由 **day092 的 `TrainingOptimizer`** 执行（`set_schedule`），
它在每一步**之前**取一次学习率。不自己乘系数的理由：

```text
对 SGD     θ ← θ − lr·g ⇒ 把 g 乘 (lr_t/lr_base) 与把 lr 换成 lr_t **等价**
对 Adam    等效步长 ≈ lr·m̂/(√v̂ + ε) 不是 lr 的线性函数
           ⇒ 缩放梯度会同时改变 m 与 v，得到的轨迹与"换 lr"不同
```

因此本课把曲线交给优化器（它内部按同一条公式走），
而 `RegularizationConfig.schedule_kwargs` 只负责给出**精确**的参数表。

**7.** 因为两把尺子量的是两件事：

```text
训练损失   带 dropout、BN 用本批统计量   （会被 dropout 抬高，且与批绑定）
推理损失   不带 dropout、BN 用 running    （这才是上线时的样子）
```

只报训练损失会把 **dropout** 的代价看反：训练损失变大是 dropout 的正常现象，
而真正该关心的是"推理损失有没有变好"。本课把它们做成报告里的两列
（`final_loss` / `eval_loss`）与一个差（`loss_gap`）——day081 已经留下
"两个损失口径都要给"这条纪律。

**8.** **缺席**（`RETURNED_FAMILY is None`、`ABSENT_FAMILY == "GradientError"`）。
差别在于：

```text
day094  抛它是因为"梯度真的会爆"——BPTT 把同一个权重乘了 T 次 ⇒ 做成**运行期守卫**
day095  那个守卫**已经装好了**（sequence_models.train.check_gradient_norm），
        本课只是**调用**它；本课自己的梯度对账（第 ④ / ⑤ 条）是**离线校验**，不改变控制流
```

同一个族在五天里有五种不同的理由在场或不在场（day082~089 缺席 / day090 回来 /
day092 缺席 / day093 缺席 / day094 回来 / day095 缺席）——这就是"缺席要可断言"的意义。

## 二、连线

**9.**

| 名称 | 职责 |
|------|------|
| `batch_norm_forward` | c. 一次前向：统计量 → 标准化 → γ/β，返回 `(y, cache, running')` |
| `batch_statistics` | d. 逐特征算批内的 μ 与**有偏**方差 |
| `running_update` | b. 把一批统计量折进 running |
| `batch_norm_backward` | e. 训练相三项、推理相一项 |
| `dropout_vector` | f. 把行向量塞进 day081 的 dropout（形状换了、数学没变） |
| `early_stopping_watch` | a. 把一串损失喂给 day081 的 EarlyStopping，返回它的报告 |

**训练相 / 推理相的分水岭是两个函数**：

```text
batch_norm_forward    按 phase 选择"本批统计量"还是"running 统计量"（并在推理相缺 running 时抛错）
batch_norm_backward   按 cache.phase 选择"三项"还是"一项"
```

它们各自是本课唯一"两相会分家"的地方——第 ③ 与第 ⑤ 条性质钉的正是这两处。
（`batch_statistics` 与 `running_update` 一起构成"训练相如何把 running 往前推"，
它们本身不属于某一个相，而是两个相之间的那条**桥**。）

## 三、对照计算

**10.**

```text
列 0：取值 1.0 与 3.0 ⇒ μ = 2.0；σ² = ((1−2)² + (3−2)²)/2 = 1.0
列 1：取值 −1.0 与 1.0 ⇒ μ = 0.0；σ² = ((−1)² + 1²)/2 = 1.0

σ = √(1.0 + 1e-5) ≈ 1.000005
x̂（列 0）：(1 − 2)/σ = −0.999995； (3 − 2)/σ = +0.999995
γ = 2、β = 0 ⇒ y（列 0）= (−1.99999, +1.99999)

回传 dy 全 1：
  dβ_j = Σ_n dy_nj = 2（每个特征都是 2）
  dγ_j = Σ_n dy_nj·x̂_nj = (−0.999995) + (+0.999995) = 0（**每一列的 x̂ 和为 0**）
```

`dx = 0` 的三项：

```text
dŷ = γ⊙dy = 2
第 1 项 dŷ_nj = 2
第 2 项 −mean_n(dŷ_j) = −2
第 3 项 −x̂_nj·mean_n(dŷ_j ⊙ x̂_j)：mean_n(2·x̂) = 2·(x̂ 的列均值) = 2·0 = 0 ⇒ 这一项是 0
⇒ dx = (1/σ)(2 − 2 − 0) = 0
```

**因为标准化的定义就是"每一列的和为 0"**，所以"均匀回传"时前两项恰好抵消。
（同一批在**推理相**上给出的是 `γ⊙dy/σ = 2/σ ≈ 2`——这就是两条路径分家的地方。）
`test_batch_norm_backward_train_three_terms_known_value` 逐位断言了 `dx = 0`。

**11.** 余弦退火的公式（`t` 从 1 开始计数）：

```text
lr(t) = min_lr + (base_lr − min_lr)·(1 + cos(π·(t−1)/(total_steps−1)))/2

t = 1   ⇒ (1 + cos 0)/2 = 1                       ⇒ lr = 0.1
t = 5   ⇒ (1 + cos(4π/9))/2 ≈ (1 + 0.1736)/2      ⇒ lr ≈ 0.0587（实测 0.058682）
t = 10  ⇒ (1 + cos π)/2 = 0                       ⇒ lr = 0.0 = min_lr
```

（`cos(4π/9) = cos(80°) ≈ 0.173648`，因此第 5 步是 `0.1 × 0.5868 ≈ 0.058682`。）

第 10 步是**合法的端点**：它是"退火到 min_lr"这个设计的最后一步，
那一步的更新量是 0。用"学习率必须为正"去卡它，会让"退火到 0"这个配置无法跑完
——day092 撞过这个坑，因此本包只拒绝负数与非有限数。

（示范脚本里跑的是 `total_steps = 10` 的那条曲线：第 1 步 `0.100000`、
第 5 步 `0.058682`、第 10 步 `0.000000`。）

**12.**

```text
间隔 = 推理损失 − 训练损失（TrainReport.loss_gap = eval_loss − final_loss）
     = 2.240945 − 0.666587 = +1.574358
```

`全开` 的训练损失**更大**，是因为它带着 dropout：dropout 会主动抬高训练损失，
这是它的正常代价。而推理损失**大得多**（2.24 对 0.0034），原因在**两相**上：

```text
训练相   BN 用"这一批"的统计量
        ⇒ 模型可以走一条捷径："这一批里谁的 h_T 最大"——因为批统计量是所有样本的函数
推理相   BN 用 running 统计量，这条捷径消失了 ⇒ 之前学到的规则不再成立
```

**不能用它说明"BatchNorm 对序列模型没用"**。三条理由：
① 这是一个 32 条样本、5 步序列、H=4 的玩具任务——规模上不足以回答这种问题；
② 同一张表里 `lstm` 上四个变体都到 100%，说明"BN 在序列模型上坏掉"不是普遍结论；
③ 本课的定位是"把每个旋钮的代价变成一列可读的数字"，
`loss_gap = +1.574358` 就是这个代价的读数，而不是一个关于 BatchNorm 的判决。

## 四、诊断

**13.** 最可能的原因：**BatchNorm 的批大小是 1**（把 BN 插在了单条序列的 h_T 上）。
此时每个特征的方差恒为 0，输出恒为 β——

```text
如果 β 的初值是 0（本包 build_regularized 就是这样），整层输出恒为 0
⇒ head 只看到常数输入 ⇒ logits 恒等于 head_bias ⇒ 损失停在"模型还没学"的位置（≈ ln 2）
⇒ 梯度仍然有限（因为链本身没写错）、形状全对、数值差分也能对上（它作用在常数上）
```

**怎么验证**：跑一次 `normalization.batch_size_one_report(batch)` 看 `max_variance`——
若是 `0.0`，就是它。另一个更直接的验证是**换成一个真正的批**（`batch_size >= 2`），
看损失会不会开始动。本课把这件事做成了一条可断言的读数，
`test_batch_size_one_collapses_to_beta` 还断言"输出恰好等于 β"。

**14.** 两个可能（都不是"写错了"，而是"两相不匹配"）：

```text
可能一：模型真的走了"批内相对关系"的捷径
        训练相用本批统计量 ⇒ 模型可以学到"这一批里谁的 h_T 最大"
        推理相换 running ⇒ 捷径消失 ⇒ 推理损失暴涨
        发现者：TrainReport.loss_gap（+3.89 与 1e-3 的差）；第 ③ 条（两相必须不同）

可能二：running 统计量**滞后**（表示在训练中漂移得比 momentum 跟得还快）
        发现者：同样看 loss_gap；把它调大（momentum → 1.0，只看最近一批）后 gap 会变小
                ——本课实测：rnn 上 m=0.1 → gap +3.630002，m=1.0 → gap +3.227741
```

（本课实测这两个原因**同时存在**：把 momentum 从 0.1 调到 1.0 之后 gap 只从 3.63 降到 3.23，
说明滞后不是全部原因——剩下的是"批内捷径"。）

## 五、推导

**15.** 记 `σ_j = √(v_j + ε)`，其中 `v_j` 是第 j 列的批内**有偏**方差。
对 `x̂_nj = (x_nj − μ_j)/σ_j` 求 `∂x̂_n/∂x_m`，三部分分别是：

```text
① 分子里的直接项：      ∂(x_n − μ)/∂x_m = δ_nm                ⇒ 贡献 δ_nm/σ
② 分子里的均值项：      ∂μ/∂x_m = 1/N                          ⇒ 贡献 −1/(Nσ)
③ 分母里的方差项：      ∂σ/∂x_m = (1/(2σ))·∂v/∂x_m，
                       而 ∂v/∂x_m = 2(x_m − μ)/N
                       ⇒ 贡献 −(x_n − μ)(x_m − μ)/(N σ³)
```

三项合起来：`∂x̂_n/∂x_m = δ_nm/σ − 1/(Nσ) − (x_n−μ)(x_m−μ)/(Nσ³)`。
于是

```text
dx_m = Σ_n dŷ_n · ∂x̂_n/∂x_m
     = dŷ_m/σ − (1/(Nσ))Σ_n dŷ_n − ((x_m−μ)/(Nσ³))·Σ_n dŷ_n(x_n−μ)
```

最后一项用 `x_n − μ = σ·x̂_n` 化简：

```text
((x_m−μ)/(Nσ³))·Σ_n dŷ_n(x_n−μ)
  = (σ x̂_m)/(Nσ³) · Σ_n dŷ_n · σ x̂_n
  = x̂_m/(Nσ) · Σ_n dŷ_n x̂_n
  = x̂_m · mean_n(dŷ_n x̂_n) / σ
```

代回，把 `1/σ` 提到括号外，就得到公式里的三项：

```text
dx_m = (1/σ)·( dŷ_m − mean_n(dŷ_n) − x̂_m·mean_n(dŷ_n·x̂_n) )
```

第 ① 项是"除以 σ"，第 ② 项是"减掉均值"，第 ③ 项是"σ 自己也依赖 x"。

**16.** 把批记作 `X`（形状 `N×F`：N 条样本、F 个特征）。

```text
BatchNorm 对"每一个特征 j"在 N 条样本上算 μ/σ ⇒ 平均跨越的是**行**（N 维）
LayerNorm 对"每一条样本 n"在 F 个特征上算 μ/σ ⇒ 平均跨越的是**列**（F 维）
```

`Xᵀ` 的形状是 `F×N`，它的"第 j 行"正好是 `X` 的"第 j 列"（一个特征的全部取值）。
于是 `layer_norm(Xᵀ)` 对第 j 行求的是"特征 j 在 N 条样本上的 μ/σ"——
**与 BatchNorm 求的是同一对统计量，只是行列换了位置**。再转置回来，两者逐位相同。
本课实测：`batch_norm_forward(X)` 与 `transpose(layer_norm(transpose(X)))` 的最大差是 `0.000e+00`。

**γ/β 不均匀时为什么不成立**：`layer_norm` 的 γ/β 是**逐列**的（长度必须等于输入的列数 N），
而 BatchNorm 的 γ/β 是**逐特征**的（长度 F）。在 `Xᵀ` 里，"列"是样本维，
因此一个长度 N 的 γ 会把**同一组数**加到每一行上——它无法表达"第 j 行用 γ_j"。
只有一个 γ 值对所有特征都相同时，两套参数才能互相表示。
这正是第 ② 条性质刻意用 θ 恒等（γ=1、β=0）的原因：
**"仿射参数在哪条轴上"本身就是这一课要讲清的一件事。**

## 六、情景题

**17.** 我会选 **LayerNorm**。理由只有一条：**线上一次只来一条工单 ⇒ 批大小为 1**。

```text
BatchNorm 的统计量来自批 ⇒ 线上单条时方差恒为 0 ⇒ 整层输出恒为 β
  （如果硬要用，只能要求"线上也攒批"，而那与"工单一条一条来"的业务事实冲突）
LayerNorm 的统计量来自**特征** ⇒ 与批里有几条样本完全无关
  ⇒ 训练时一条也能算、推理时一条也能算，两相天然一致
```

如果一定要用 BatchNorm，两条工程路线：

```text
① 攒批 / 微批：把若干条工单缓冲成一批再推理（代价是延迟）
② 用 running 统计量推理（本课的做法）：训练时把 running 折出来，
   推理相全部走 running——此时批大小 1 也成立（因为它只用常数统计量）
   ⇒ 这正是"两个相"存在的意义：把"需要批"的那部分**只留在训练侧**
```

本课的第 ③ / ⑤ 条性质钉的就是第 ② 条路走对了没有。

**18.**

**第一条**："图的极值位置必须等于 argmin / argmax"值得单独断言，因为它是一条
**整数判据**，而且它检验的是"映射方向"：

```text
读数 = |作图长度 − 序列长度| + （最低值位置是不是最低档 ? 0 : 1）
                                  + （最高值位置是不是最高档 ? 0 : 1）
⇒ 它只能取 0、1、2 三个值（外加长度差）
⇒ 把档位映射方向写反（最大值映成最低档）会让它立刻变成 2，而不是"看起来差不多"
```

如果只断言"图非空 / 字符都在 8 个档位里"，那么**方向写反的图仍然会通过**——
而方向写反是一张"看起来完全正常、结论完全相反"的图。
第 ⑦ 条性质因此把"图的极值位置"钉在 `argmin` / `argmax` 这两个可由函数直接算出的整数上。

**两个必须回到 `study` 取数的例子**：

```text
① 损失的具体数值：文本图只有 8 个档位，`0.08` 与 `0.11` 可能画成同一个字符；
   而"最终损失是多少"要精确到有效数字 ⇒ 去 TrainReport / study.ablation_rows 取
② 准确率与损失间隔：条形图给的是"谁更长"，不是"长多少"；
   "间隔 +1.574358 还是 +3.630002"这种读数必须从报告的两列相减得到
```

一句话：**图是"第一眼"，表是"结论"**——任何一个要写进报告的结论都必须有表里的数支撑。
