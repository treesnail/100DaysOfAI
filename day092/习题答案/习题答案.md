# day092 习题答案：优化器 —— 往哪走、走多远

> 参考答案。每题都尽量给出"为什么"与"看源码的哪里"，而不是只给结论。
> 涉及的模块都在 `smart_research_agent/optimizers/` 下。

## 一、速答

**1.** 学习率是一个**标量**，回答"这一步走多远"；更新规则决定这个标量**作用在什么上**
（当前梯度、梯度的滑动平均、被归一化后的梯度）。混着调的典型症状是：loss 不降时
先去调学习率，但真正错的其实是"更新规则用错了地方"（例如把解耦衰减写成了耦合）。
见 `types.OPTIMIZER_FORMULAS` 与 `optimizer.TrainingOptimizer.step`。

**2.** 速度从 0 出发，所以 `v₁ = β·0 + g = g`，方向仍是 `g`，与 SGD 的第一步完全相同。
动量的作用从**第二步**开始：`v₂ = β·g₁ + g₂` 里才带上历史。这可以在
`study.one_step_rows()` 的读数里直接看到（sgd 与 momentum 的第一行都是 0.95）。

**3.** 多的是 `β·v`（当前的、由本步梯度更新后的速度）这一项。速度更新两者**逐字相同**
（`v ← β·v + g`），差别只在**用哪一项当方向**：

```text
momentum: 方向 = v
nesterov: 方向 = g + β·v
```

代码上就是 `rules.nesterov_step` 里 `direction = tuple(slope + beta * speed ...)` 那一行——
普通动量用的基座是 day074 的 `MomentumOptimizer`，它直接把 `v` 当方向。

**4.** RMSProp 的二阶动量 `s` 从 0 出发：第一步 `s₁ = (1−ρ)g²`，分母 `√s` 很小，
于是 `lr·g/(√s+ε)` 会远大于 `lr`（本课读数里是 lr 的约 17 倍）。
Adam 用**偏差修正**解决同类问题：把两个滑动平均分别除以 `1−β₁ᵗ` 与 `1−β₂ᵗ`。
见 `math_foundations.optim.AdamOptimizer` 的 `correction1` / `correction2`。

**5.** 耦合 L2：`g ← g + λθ`（在更新前，加进梯度）；解耦：`θ ← θ·(1 − lr·λ)`（在更新后，缩参数）。
**行为不同**，不只是写法不同。具体后果：耦合版里 `λθ` 会与梯度一起被 Adam 的分母 `√v̂`
除一下，于是**梯度大的参数衰减得更弱**——同一份衰减系数在不同层上强度不一致。
见 `rules.l2_gradient` 与 `rules.apply_decoupled_decay`。

**6.** 因为顺序决定了这两项各自"作用在什么上"：

```text
耦合衰减在更新之前   它要成为梯度的一部分（g + λθ）
解耦衰减在更新之后   它是"更新完再缩一下参数"，不能进梯度
```

若把耦合衰减放到更新之后（或把解耦当成梯度项），**不会报错**：结果看起来正常，
只是那个衰减系数不再等于你设的值。这正是 `step` 把顺序写死、不给调用方拼的原因。

**7.** 因为余弦退火的**最后一步**会合法地取到 `min_lr`，而 `min_lr = 0` 是允许的终点
（"这一步不再更新"）。若用"必须为正"去卡调度，常见的 `warmup_cosine` 会在**最后一步**
报错，而前面每一步都对。构造函数里的学习率则是一个**你手动设的步长**，为 0 等于
"我根本没打算训练"，因此要求为正。

**8.** day092 的输入是一个**已经算好的梯度向量**：本课一行都不计算梯度。
因此"两条独立路径的梯度对不上"在今天不可能发生——`GradientError` 不是被忘记，
而是被**交给了上一步**。而 day082~089 的缺席理由是"根本没有手写反向"。
两条理由写在 `errors.ABSENT_FAMILY_REASON` 与 `errors.RETURNED_FAMILY_REASON` 里，
并被 `test_optimizers.py` 逐字断言。

## 二、连线

**9.**

| 规则 | 状态 | 核心规则 |
|------|------|----------|
| sgd | b. 无 | sgd（复用 day074） |
| momentum | d. velocity | momentum（复用 day074） |
| nesterov | e. velocity | nesterov（本课新增） |
| rmsprop | c. square_avg | rmsprop（本课新增） |
| adam | a. first_moment / second_moment | adam（复用 day074） |
| adamw | f. first_moment / second_moment | **adam**（AdamW 的核心就是 Adam，更新之后再缩参数） |

`adam` 与 `adamw` 共享同一个核心规则：`optimizer.CORE_RULE_FOR["adamw"] == "adam"`。
因此 AdamW 不需要重写一套 Adam，只需要在 Adam 的更新之后加一步解耦衰减。

## 三、对照计算

**10.** 依次算：

```text
decay=none        直接用 g=(1,0)
                  θ ← (1,2) − 0.1·(1,0)               = (0.9, 2.0)
decay=l2          先 g ← g + λθ = (1,0) + 0.5·(1,2) = (1.5, 1.0)
                  θ ← (1,2) − 0.1·(1.5,1.0)          = (0.85, 1.9)
decay=decoupled   先按 none 更新 → (0.9, 2.0)
                  再乘 (1 − lr·λ) = (1 − 0.05) = 0.95 → (0.855, 1.9)
```

与 `scripts/optimizers_demo.py` 第 4 节的读数一致（none 0.900000 / l2 0.850000 /
decoupled 0.855000）。

**11.**

```text
‖g‖ = √(3² + 4²) = 5
缩放系数 = max_norm / ‖g‖ = 1/5 = 0.2
裁剪后 = (3,4)·0.2 = (0.6, 0.8)，其范数 = √(0.36+0.64) = 1  ✔
方向余弦 = 1（整体范数裁剪只把梯度**同比缩放**，方向不变）
```

与 `study.clip_row()` 同源（那里是 `‖g‖=1.118e+02 → ‖g'‖=1.0，系数 8.944e-03，cos 1.000000`）。

**12.**

```text
第 1 步   lr = base_lr · 1 / warmup = 0.1 · 1/5 = 0.02
第 5 步   lr = base_lr · 5 / 5      = 0.1（热身结束）
第 20 步  lr = min_lr = 0.0（余弦退火末步）
```

第 1 步不是 0 的原因：`lr = 0` 会让第一次更新完全不发生，它在日志里表现为
"第 1 步的 loss 与初始 loss 一模一样"，看起来像"梯度算错了"。
第 20 步为 0 的麻烦：如果训练回路用"必须为正"去校验调度给出的学习率，
它会在**最后一步**抛 `ParameterError`——因此回路必须用**非负**校验。
（这条坑在教程第十一章被写下来，也在 `rules.checked_non_negative` 的文档串里。）

## 四、诊断

**13.** 最可能的原因：换了任务（参数形状变了）却**忘记 `reset()`**，于是上一段任务的
动量 / 二阶动量被带进新任务的前几步。应该去看 `TrainingOptimizer.reset()`
（它清空步数与全部跨步状态，参数不动），对应的错误类是 `errors.StateError`。
`test_optimizers.py::test_state_error_on_wrong_velocity_length` 就是它的最小复现。

**14.** 最可能写错的地方：把解耦衰减实现成了"耦合 L2"——即把 `λθ` 加进了梯度，
而不是在更新之后缩参数。这样 AdamW 与 Adam+L2 就变成同一个东西。
本课的 `decoupled_decay_differs_under_varying_gradients` 会发现它，
用的是**下界**判据（读数必须 ≥ 1e-9）：因为两条"都看起来正常"的轨迹只靠上界判据
是区分不开的。

## 五、推导

**15.** 设梯度恒为 `g`，二阶动量按 `s ← ρ·s + (1−ρ)g²` 迭代，从 `s₀ = 0` 出发：

```text
sₜ = (1−ρ)g² · (1 + ρ + ρ² + … + ρ^{t−1}) = g²(1 − ρᵗ)
t → ∞ 时  s∞ = g²
```

稳态下 `√s∞ = |g|`，于是每步位移 `lr·g/(√s + ε) ≈ lr·g/|g| = lr·sign(g)`：
它的**绝对值只由 lr 决定**，与 `g` 的尺度无关。因此梯度 100 与梯度 0.01 的参数
走得一样快。本课读数里两者的差只有 `5.773e-08`（来自 `ε` 的相对影响）。

**16.** 第一步 `m₁ = (1−β₁)g = 0.1g`、`v₁ = (1−β₂)g² = 0.001g²`。
不做修正时更新量：

```text
lr · m₁ / (√v₁ + ε) ≈ lr · 0.1g / √(0.001 g²) = lr · 0.1/0.0316... ≈ lr · 3.16
（√0.001 ≈ 0.031623，0.1/0.031623 ≈ 3.162）
```

做了偏差修正后 `m̂ = m₁/(1−β₁) = g`、`v̂ = v₁/(1−β₂) = g²`，更新量变成
`lr·g/(|g|+ε) = lr·sign(g)`——恰好是设定值。这就是"3.16 倍"的来源。

## 六、情景选型

**17.**

```text
sft-lora → adamw, lr = 1e-4, 解耦衰减 0.01
  理由：大模型微调的默认起点是 AdamW——它的解耦衰减不随梯度尺度变化，
        若用耦合 L2，各层的实际衰减强度会因梯度尺度不同而不一致。
dpo → adamw, lr = 5e-7, 解耦衰减 0.00
  理由：偏好对齐的目标比 SFT 更尖锐，学习率通常再小两三个数量级；
        此时常把 weight_decay 设为 0（再叠正则容易把策略拉回参考模型）。
```

见 `advisor.RECOMMENDATIONS`。注意：这些是**起点配置**，不是最优配置——
真正的调参必须在自己的数据上跑。

**18.** 因为"哪个优化器更好"是**相对于目标函数几何**说的，不是绝对排名：

```text
良态碗    各方向尺度相同 ⇒ SGD 一步一个脚印走到底就很顺
          自适应方法把每步压到 ≈lr，反而"走不快"（本课读数里 Adam 1.513 最差）
病态峡谷  一个方向陡 24 倍 ⇒ SGD 在陡方向来回横跳，动量/自适应把横跳平均掉或归一
香蕉窄谷  弯曲的窄谷 ⇒ 各方法相对排名又变（本课读数里普通动量第一、Nesterov 第二）
```

再加上：本课的对比是**单条确定性轨迹**（固定起点、固定 lr、固定步数），
不是统计结果。要下普遍结论，必须扫参、跑多次、换多组目标与数据。
这正是教程第八章那条"必须写下来的边界"。
