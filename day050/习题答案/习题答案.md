## 第一部分：选择题

### 第 1 题（SFT 与预训练的差别）

**答案：C**

损失函数与优化器**完全相同**（都是 next-token 交叉熵 + AdamW/SGD），区别只在"求和的集合与分母"：

```text
预训练：  L = -(1/T)   Σ_{t=1..T}  log p(y_t | y_<t)
SFT：     L = -(1/T')  Σ_{t∈S}     log p(y_t | y_<t)      S = 监督位置集合
```

工程上这个"只对答案段"落在 `labels` 数组的一个约定值上：`IGNORE_INDEX = -100`（PyTorch `nn.CrossEntropyLoss` 的 `ignore_index` 默认值，也是 HF / TRL 生态的通行约定）。

A 错在"交叉熵"与"负对数似然"其实是同一个东西（交叉熵就是负对数似然）；B 错在优化器差异不是 SFT 与预训练的分界；D 错在"冻结参数"是 PEFT 的手段，全参 SFT 照样更新全部权重。

### 第 2 题（渲染与编码）

**答案：C**

C 的自相矛盾之处：它承认"字符级分词下分别编码与整体编码结果相同"，却又据此说 B 没有实际影响。B 是一条**面向真实分词器**的纪律：

在 BPE / WordPiece 上，**跨边界的字符合并会产出一个"同时属于 prompt 与 answer"的 token**。例如整段文本在边界处被合并成一个子词，那么"先编码整段、再按字符偏移切片"无论怎么切都不对——切给 prompt 就丢了答案的第一个词；切给 answer 就让模型学着预测一个它本不该预测的 token。

本课的字符级分词器让边界恰好落在 token 边界上，**这只是掩盖了问题，不代表问题不存在**。所以 `RenderedSample` 用两个字符偏移表达边界，而 `encode_supervised` 严格按偏移分别编码：

```python
prompt_ids = tokenizer.encode(rendered.prompt_text)
answer_ids = tokenizer.encode(rendered.supervised_text)
input_ids = prompt_ids + answer_ids
```

A、B、D 都是正确描述。

### 第 3 题（截断策略）

**答案：B**

`keep-answer`（缺省）的完整语义：

```python
budget = max_length - len(answer_ids)
if budget < 1:
    raise SFTDataError(...)              # 答案放不下 → 直接失败
kept_prompt = prompt_ids[len(prompt_ids) - budget :]   # 从左侧裁
ids = kept_prompt + answer_ids
```

从**左侧**裁 prompt 的理由：靠近答案的那部分指令信息密度最高，丢掉开头的客套话代价最小。

A 错（从右侧截断答案 = 教模型"说一半就停"）；D 错（自动调大 `max_length` 会让显存用量不可预测，且掩盖了"数据长度分布与配置不匹配"这个真问题）；C 错（随机丢弃会破坏可复现性）。

### 第 4 题（loss 的分母）

**答案：C**

返回两个值**直接关系到正确性**。测试里有一条断言把"分母不能用序列长度"钉死：

```python
def test_denominator_is_not_sequence_length(self):
    logits = [[0.0, 0.0]] * 4
    labels = [0, 0, IGNORE_INDEX, IGNORE_INDEX]
    loss, count = masked_cross_entropy(logits, labels)
    assert count == 2
    assert loss == pytest.approx(LN2)   # 而不是 LN2 * 2 / 4
```

B 与 D 都是 `loss.py` 里写明的设计理由：分母变大 → loss 被系统性压低 → 梯度被缩小 `T'/T` 倍（等于把学习率偷偷改小一个数量级）；而"零监督位置返回 0"会把 mask 配置错误伪装成"loss 完美"。

### 第 5 题（`max_length` 的标定）

**答案：C**

本日实测（train 30 条）：

```text
max_length=84   成功  9 / 失败 21 / 截断  9   （失败率 70%）
max_length=128  成功 27 / 失败  3 / 截断 27   （失败率 10%）
max_length=256  成功 30 / 失败  0 / 截断 15   （失败率  0%）
max_length=320  成功 30 / 失败  0 / 截断  0   （失败率  0%）
max_length=512  成功 30 / 失败  0 / 截断  0   （失败率  0%）
```

A 错：取 2048 时约 **87.75%** 的位置是 padding，而 **padding 同样参与注意力计算**（对序列长度是平方复杂度）。B 错：84.24 是"指令 + 答案原始文本"的估计，渲染成 ChatML 并分词后平均是 250.9，差近三倍。D 错：padding 不只影响显存，还直接影响计算量与显存占用（注意力是 O(L²)）。

`max_length` 只能由**渲染并分词之后的长度分位数**决定，代码里就是 `suggest_max_length()`。

### 第 6 题（学习率与步数）

**答案：D**

`2e-4` 是 **7B 全参 + AdamW** 的合理量级；对 557×557、纯 SGD、每次更新在上千个监督 token 上求均值的参考模型，它小了四个数量级。实测：

```text
lr = 2e-4  ->  6.3212 -> 6.3212   降幅  0.00%   ← 完全学不动
lr = 8.0   ->  6.3212 -> 5.9048   降幅  6.59%
lr = 20.0  ->  6.3212 -> 5.3933   降幅 14.68%
```

原因不神秘：**梯度幅度与参数量、批大小一起决定了步长**。所以本课把区间显式写成 `LR_SOFT_RANGE`（7B 全参）/ `LR_SOFT_RANGE_PEFT` / `LR_SOFT_RANGE_REFERENCE`（参考模型）三个常量，并由 `plan_training(lr_range=...)` 选用——**告警阈值必须与模型规模匹配，否则它只会变成噪声**。

A、B、C 都是 day049 预先算出、今天在运行时逐项验证过的数字。

## 第二部分：判断题

### 第 7 题

**答案：错。**

零监督样本（`labels` 全为 `-100`）是一条**消费算力但不产生梯度**的死数据。它的危害比"没用"更大：

1. **它会让 loss 曲线看起来正常**——其余批次仍在下降，指标不会报警；
2. **它悄悄降低样本利用率**——你以为是 30 条样本在训练，实际只有 25 条在贡献梯度；
3. **它占用 padding 预算**——batch 内最长样本决定了补齐长度，一条长而无用的样本会让同批其他样本也跟着多算。

所以本课在两处直接拦截它：`EncodedSample.__post_init__` 断言 `supervised_tokens > 0`，`ReferenceSFTModel.accumulate` 在 `count == 0` 时抛 `SFTLossError`。**宁可失败，也不产出零监督样本。**

### 第 8 题

**答案：对。**

缺省 `include_turn_terminator=True`，监督区间是 **`答案 + 轮次终止符`**。模型必须学会"在哪里停下"，而 EOS/终止符正是这个信号。如果只监督答案本身，模型学到的是"永远继续写下去"——它会生成语义正确但**不会结束**的输出，而这在评测里往往表现为"回答太长"而不是"回答错误"，更难定位。

TRL 的官方文档里也有同类提醒：对 Qwen 这类自带 chat 模板的模型，"有必要把 `eos_token` 与 chat 模板对齐，以保证模型的回复正确终止"。本课把这条要求直接做进了监督区间。

### 第 9 题

**答案：错。**

这不是 bug，而是 `torch.optim.lr_scheduler.LambdaLR` 的初始化行为：它在**构造时就会求值一次** `lr_lambda(0)`（`last_epoch=-1` 的语义），所以 warmup 段的第 0 步学习率确实是 0——**第一次参数更新是一次空更新**。

它对训练循环提出一个硬要求：这一步必须照常执行，**并把梯度清零**，否则这段梯度会漏进下一个窗口，把两次更新混成一次。本课的实现：

```python
if learning_rate > 0:
    self.model.apply_update(learning_rate)
else:
    self.model.zero_grad()   # 零 lr：更新无效果，但梯度必须丢弃
```

测试用 `warmup_ratio=0.5` 专门守这条路径：`records[0].learning_rate == 0.0`，且 `model.updates == 总步数 - 1`。

### 第 10 题

**答案：错。**

这正是本课要防的**指标陷阱**。两组 loss 的**求和集合与分母不同**：

| 变体 | 监督 token 占比 | 报告 loss | 统一尺子下的答案 loss |
|------|----------------|-----------|---------------------|
| 屏蔽 prompt | 39.31%（2933 / 7462） | 5.4770 | **5.3607** |
| 不屏蔽 prompt | 100.00%（7462 / 7462） | **4.6352** | 5.5487 |

不屏蔽时 loss 更低，一部分来自"prompt 段更好预测"，而不是"答案学得更好"。换到统一尺子（评估集一律按屏蔽口径编码）下，**结论反转**：屏蔽更好（差 0.1880）。

**任何"某个设计更好"的说法，如果不配一个可复现的对照实验、且比较口径不一致，它就只是一句话。**

### 第 11 题

**答案：错。**

`packing=True` 确实能提高吞吐，但它的代价必须算清楚：

1. 改变样本边界（一条序列里混了多条样本）；
2. **改变 loss 的分母口径**（一次前向里的监督 token 数不再对应一条样本）；
3. 让"第 N 步看到哪些样本"不可复现。

在 37 条样本这个规模上，吞吐收益远小于可解释性损失，所以本课**刻意关闭**它（`to_trl_dict()` 里写死 `"packing": False`，`generated_script_summary()` 把它作为自述信息返回）。真正的判据是：**当"想知道每步在学什么"比"快一点"更重要时，就不该开**——而在调试阶段这个条件几乎总是成立。

## 第四部分：简答题

### 第 14 题（"同一把尺子"与"把分母交出来"）

**（1）为什么不能直接比较两组的 `final_loss`？"同一把尺子"指什么？**

因为两组 loss 的**求和集合与分母不同**：

```text
屏蔽 prompt    L = -(1/2933) Σ_{t ∈ 答案段} log p(y_t | y_<t)
不屏蔽 prompt  L = -(1/7462) Σ_{t ∈ 全序列} log p(y_t | y_<t)
```

这两个数字是**两个不同的问题的答案**："答案 token 预测得多准"与"整条序列预测得多准"。后者天然更低，因为 prompt（系统提示词 + 用户问题）比答案更有规律、更容易预测。直接比较等于拿"跑步速度"和"骑行速度"比谁快。

**"同一把尺子"** 具体指：**评估集一律按屏蔽口径编码**，两个模型都在同一批 `input_ids` / `labels` 上做前向，衡量的都是"模型在答案 token 上的预测能力"。代码里的做法是先建一个 `mask_prompt=True` 的 trainer 专门用来编码评估集，再把这份张量交给两个待评估的模型：

```python
ruler_batches = iter_batches(ruler.encode(eval_set)[0], batch_size=...)
loss, tokens = model.evaluate(ruler_batches)
```

为什么必须这样设计：**否则"结论"会随口径变化而反转**。实测不屏蔽的"报告 loss"更低（4.6352 < 5.4770），但统一尺子下屏蔽更好（5.3607 < 5.5487）。若不做统一口径，就会得出完全相反的结论——而且这个错误结论**有数据支撑**，极难被质疑。

**（2）`masked_cross_entropy` 为什么把监督 token 数一起返回？**

因为**分母是 SFT 里最容易写错、且错了不报错的地方**。把分母交出来，调用方就能核对"它是否等于我预期的监督 token 数"。这条链在本课里是贯穿的：

| 层 | 字段 | 含义 |
|----|------|------|
| 编码 | `EncodedSample.supervised_tokens` | 这条样本有多少 token 参与 loss（构造期校验 > 0） |
| 批次 | `Batch.supervised_tokens` | 本批的监督 token 总数（由各样本相加） |
| 损失 | `masked_cross_entropy(...) -> (loss, count)` | 本批实际用于求平均的分母 |
| 模型 | `accumulate(...) -> (loss_sum, count)` | **不除 N**：N 要等累积窗口数完才确定 |
| 更新 | `apply_update(lr)` 里 `scale = 1 / self._pending_tokens` | 累积窗口的**总** N |
| 记录 | `StepRecord.supervised_tokens` | 这一步的分母（= 窗口内各 micro-batch 之和） |
| 报告 | `SFTReport.supervised_tokens_seen` | 全部步的分母之和（= 真正参与更新的 token） |

这条链的终点是最后一项，而它有一个刻意的口径选择：取 **`records` 的求和**，而不是"曾经累加进缓冲的总量"。因为 `drop_last` 会丢弃每个 epoch 尾部未满的累积窗口——那部分 token **没有参与任何一次参数更新**。用后者会至少高估 20%（每 epoch 的 15 个 micro-batch 里只有 12 个进入窗口），属于典型的"账对不上"。

**（3）"可观测"为什么比"正确"更难做好？**

因为**正确是局部的，可观测是全局的**。实现一个"正确的" mask 只需要写对一行 `[ignore_index] * len(prompt_ids) + answer_ids`；而要保证"这条链路上任何一环出错都会暴露"，需要额外付出四类工作：

1. **在每个可能"什么都没发生"的地方放一个数字**——`EncodingReport.supervised_ratio`（39.31%）、`Batch.padding_tokens`、`StepRecord.micro_batches`、`model.updates`；
2. **在构造期校验不变式**——`EncodedSample.__post_init__` 的四条断言，把故障从 loss 处提前到数据处；
3. **把"差异"显式暴露**——`plan.total_steps`（9）与 `plan.total_steps_flushing`（12）同时给出，并告警"口径不同则步数不可比"；
4. **把阈值按规模标定**——三个学习率区间，否则告警会永久误报，而**天天误报的告警一定会被忽略**。

本日两个真实发现正好各说明一半：

- **`warmup_steps` 退化为 0 是可观测救回来的**：`int(9 × 0.03) = 0` 这个事实如果只写在日志里没人会看；写成 `warnings` 之后，它变成"要么调比例、要么接受无 warmup"的一个决策点。
- **`max_length=128` 时模板被静默破坏，恰恰是可观测没做到位的地方**：27/30 条样本"成功编码"，但 prompt 被砍成 `')?<|im_end|>\n<|im_start|>assistant\n'`——系统提示词与 `system` 标记全丢了。脚本不报错、loss 照样下降，**只是训练模板与推理模板不再是同一个**。本课只能通过 `EncodingReport.truncated` 把这 27 条的数量报出来，**但"截断到什么程度才不能接受"仍然需要人判断**。

这就是"可观测比正确更难"的含义：**正确可以用一条断言守住，可观测要持续回答"我还能不能看出自己错了"。**

## 第五部分：编程题

### 第 15 题（参考答案）

```python
"""day050 #15 参考答案：长度分位决定 max_length（只读脚本）."""

from __future__ import annotations

from smart_research_agent.finetune import build_dataset, split_dataset
from smart_research_agent.sft import (
    SFTDataError,
    CharTokenizer,
    encode_supervised,
    length_summary,
    render_supervised_list,
    suggest_max_length,
)

DAY048_ESTIMATE = 84.24

bundle = build_dataset()
train, eval_set = split_dataset(bundle.examples, eval_ratio=0.2, seed=42)
rendered_all = render_supervised_list(bundle.examples)
rendered_train = rendered_all[: len(train)]
tokenizer = CharTokenizer.from_texts([item.text for item in rendered_all])

summary = length_summary(rendered_train, tokenizer)
print(summary.summary_line())
for label, ratio in (("p50", 0.50), ("p90", 0.90), ("p95", 0.95), ("p100", 1.00)):
    print(f"  {label:<5} = {summary.quantile(ratio):>4} token")

suggested = suggest_max_length(rendered_train, tokenizer, quantile=0.95)
print(f"suggest_max_length(p95, 32 的倍数) = {suggested}")

print(f"\n各候选 max_length 下的实际编码结果（train {len(train)} 条）：")
for cap in (84, 128, 256, 320, 512):
    ok = truncated = failed = 0
    for item in rendered_train:
        try:
            sample = encode_supervised(item, tokenizer, max_length=cap)
        except SFTDataError:
            failed += 1
            continue
        ok += 1
        truncated += int(sample.truncated)
    print(
        f"  max_length={cap:<4} 成功 {ok:>2} / 失败 {failed:>2} / 截断 {truncated:>2}"
        f"  （失败率 {failed / len(rendered_train):.0%}）"
    )

# 断言 1：day048 的估计值附近，凡成功编码的样本**全部**被截断
for cap in (int(DAY048_ESTIMATE), 128):
    ok = truncated = 0
    for item in rendered_train:
        try:
            sample = encode_supervised(item, tokenizer, max_length=cap)
        except SFTDataError:
            continue
        ok += 1
        truncated += int(sample.truncated)
    assert truncated == ok, "该上限下所有成功编码的样本都应当是截断的"
    min_answer = min(len(tokenizer.encode(i.supervised_text)) for i in rendered_train)
    print(f"断言 1（max_length={cap}）：成功 {ok}/30、其中**全部**截断（{truncated} 条）")
    print(f"  即：失败 {30 - ok} 条硬报错；成功的那 {ok} 条，prompt 最多只剩 "
          f"{max(1, cap - min_answer)} token（原始 prompt 平均 {summary.prompt_mean:.1f} token）")

# 而这些"成功"的样本已经把系统提示词与角色标记砍掉了——模板被静默改变
with_cap = encode_supervised(rendered_train[0], tokenizer, max_length=128)
kept_prompt_text = tokenizer.decode(with_cap.input_ids[: with_cap.prompt_tokens])
assert "system" not in kept_prompt_text
print(f"  第一条样本在 max_length=128 下保留的 prompt = {kept_prompt_text!r}")
print("  → 系统提示词与 <|im_start|>system 标记已全部丢失，训练模板与推理模板不再一致")

# 断言 2：按建议值编码，全部成功且 0 截断
ok_at_suggested = truncated_at_suggested = 0
```

**几处必须理解的细节**：

1. **"截断"和"失败"是两种不同的坏结果，而且前者更危险。** 失败会立刻抛 `SFTDataError`（84 时 21 条、128 时 3 条）——这是**好的失败**。而"成功但截断"的样本会进入训练集，且**模板已经和推理时不一致**。所以本课的 `EncodingReport` 把 `truncated` 单独计数，就是为了让这种"静默的坏数据"有一个数字。
2. **`prompt_mean` 是 150.2 token，而 day048 的估计只有 84.24。** 差距来自三处：ChatML 的系统提示词与角色标记（约 100 字符）、轮次终止符、以及字符级分词把中文按 1 字 1 token 计。**这是"渲染会显著改变长度"的直接证据**，也是不要照抄 `DatasetStats` 的原因。
3. **`p95` 与 `p100` 在本数据集上都是 320**（train 口径 p95=303，向上取整到 32 的倍数后也是 320）。所以"取 p95 容忍长尾"这一次没有实际损失。但换一份长尾更明显的数据，两者会分开——**`suggest_max_length(quantile=1.0)` 就是"一条都不截断"的旋钮**。
4. **train 30 条与全部 37 条的分位数不同**（`p50` 253 vs 248、`mean` 254.3 vs 250.9）。这不是矛盾：分位数是**数据子集的属性**。实操上要用**训练集**（模型实际见到的分布）来定 `max_length`；而评估集若更长，宁可让它截断（评估样本被截断不会污染训练），也要保持训练模板完整。

```python
"""day050 #16 参考答案：mask 对照实验（同一把尺子）."""

from __future__ import annotations

import tempfile

from smart_research_agent.finetune import build_dataset, split_dataset
from smart_research_agent.sft import (
    CHATML,
    REFERENCE_LEARNING_RATE,
    SFTTrainer,
    SFTTrainingArgs,
    CharTokenizer,
    ReferenceSFTModel,
    iter_batches,
    render_supervised_list,
    suggest_max_length,
)

bundle = build_dataset()
train, eval_set = split_dataset(bundle.examples, eval_ratio=0.2, seed=42)
rendered_all = render_supervised_list(bundle.examples)
tokenizer = CharTokenizer.from_texts([item.text for item in rendered_all])
max_length = suggest_max_length(rendered_all[: len(train)], tokenizer, quantile=0.95)


def run_variant(mask_prompt: bool) -> dict:
    """训练一个变体，并用同一把尺子（评估集按屏蔽口径）测量答案 loss."""
    args = SFTTrainingArgs(
        learning_rate=REFERENCE_LEARNING_RATE,
        num_train_epochs=10.0,
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        max_length=max_length,
    )
    with tempfile.TemporaryDirectory() as tmp:
        args = args.with_overrides(output_dir=tmp)
        # 统一的尺子：评估集一律用 mask_prompt=True 的 trainer 编码
        ruler = SFTTrainer(
            ReferenceSFTModel(tokenizer.vocab_size, seed=42),
            tokenizer,
            args,
            template=CHATML,
            mask_prompt=True,
        )
        ruler_batches = iter_batches(ruler.encode(eval_set)[0], batch_size=2)

        model = ReferenceSFTModel(tokenizer.vocab_size, seed=42)
        trainer = SFTTrainer(
            model, tokenizer, args, template=CHATML, mask_prompt=mask_prompt
        )
        report = trainer.fit(train, eval_set, save_at_end=False)
        answer_loss, tokens = model.evaluate(ruler_batches)
        return {
            "supervised_ratio": report.train.supervised_ratio,
            "reported_loss": report.final_loss,
            "answer_loss": answer_loss,
            "tokens": tokens,
        }


masked = run_variant(True)
unmasked = run_variant(False)
for label, result in (("屏蔽 prompt（标准 SFT）", masked), ("不屏蔽 prompt", unmasked)):
    print(f"\n{label}")
    print(f"  监督 token 占比 {result['supervised_ratio']:.2%}")
    print(f"  训练报告 loss（各自口径） {result['reported_loss']:.4f}")
    print(f"  统一尺子下的答案 loss    {result['answer_loss']:.4f}"
          f"（{result['tokens']} 个监督 token）")

# 断言 1：同一把尺子 → 两次评估的张量必须完全相同
assert masked["tokens"] == unmasked["tokens"], "同一把尺子的 token 数必须相同"
# 断言 2：屏蔽 prompt 更好
assert masked["answer_loss"] < unmasked["answer_loss"], "屏蔽 prompt 应当更好"
# 断言 3：不屏蔽的**报告 loss** 反而更低——这正是指标陷阱
assert unmasked["reported_loss"] < masked["reported_loss"], (
    "不屏蔽时的报告 loss 更低：只看报告 loss 会得出相反结论"
)
print(
    f"\n断言 1-2 通过：统一尺子下 屏蔽 {masked['answer_loss']:.4f} < "
    f"不屏蔽 {unmasked['answer_loss']:.4f}（差值 "
    f"{unmasked['answer_loss'] - masked['answer_loss']:.4f}）"
)
print(
    f"断言 3 通过：不屏蔽的报告 loss 更低（{unmasked['reported_loss']:.4f} < "
    f"{masked['reported_loss']:.4f}）——只看报告 loss 会得出相反结论"
)
print(
    f"监督 token 占比：屏蔽 {masked['supervised_ratio']:.2%} / "
    f"不屏蔽 {unmasked['supervised_ratio']:.2%}"
)
print("\n全部断言通过")
```

**几处必须理解的细节**：

1. **"统一的尺子"必须在训练之外单独构造。** 尺子的作用是把两次训练的结果投影到同一个空间；如果把尺子建在某个变体内部（例如用不屏蔽的 trainer 去编码评估集），那么"被评估的对象"和"评估的口径"就会一起变，比较立刻失去意义。所以脚本里那个 `ruler` 的模型是**一次性**的（只用来编码，`evaluate` 时传的是待评估模型）。
2. **`unmasked["reported_loss"] < masked["reported_loss"]` 这条断言是本题的"反直觉"部分，但它是必须断言的。** 因为它说明了一件很容易被误读的事：**报告里的 loss 是"相对于本次训练目标"的 loss，不是可跨实验比较的质量指标。** 把它写成断言，是为了让"看到更低的 loss 就说更好"这个错误在任何一次运行里都会被拦下。
3. **两个变体的 `tokens` 必须相同（734）**，这是"同一把尺子"的直接可验证形式。若两次 `evaluate` 的分母不同（例如误用了各自的编码），差值就失去了意义。实测两次都是 734。
4. **数值与教程/演示略有差异（5.3607 vs 5.3596）不是矛盾。** 差异来自评估批大小：本脚本用 `batch_size=2`，演示脚本用 `per_device_eval_batch_size=4`；不同批组成会让 padding 量不同，进而让同一批 token 的 loss 有极小差异（`4e-4` 量级）。**这说明"loss 的第三位小数不可跨配置比较"**——要比较就必须固定批组成，这也是本课 `split_dataset` 与 `data_seed` 存在的理由。
