## 一、基础

### 1. 四件东西

```text
AttentionRecord   "这一层这一头看到了什么"（权重 + 它用的掩码 + 标签）
HeadProfile       "这张表有多尖"（熵 / 天花板 / 归一化熵 / 峰值 / 支撑 / Frobenius / 对角质量）
Attribution       "谁在被看"（列和，归一化）
文本热力图         "它长什么样"（10 级字符 + 图例，而且能**画回去**）
```

### 2. 不重写任何算术

因为它读的是 day075~082 已经算好并验过的权重——`extract.self_records`
直接取自 `arch_variants.variant_forward` 的记录（`block_weights` /
`decoder_self_weights` / `cross_weights`），因此"读出来的东西"与"模型实际算的东西"
**逐位相同**（测试里有一条断言钉住它）。

这条设计与前八天"**转发而不是重写**"（day073~082 的 `controls.py`、`masks.py`）
同源：重写一遍的代价不是多写几十行，而是**两处口径会慢慢分开**。

### 3. `GradientError` 为什么缺席

因为它属于"改推导"那一族，而**本课不改任何算术**——没有新公式可错。
这条缺席说明了本课的一条边界：**可解释性不能替训练兜底**。
它读到的权重好不好，取决于模型怎么被训（day081 的四个旋钮）；
本课只负责把权重读出来、画出来、并给出可被断言的读数。

## 二、两条读法

### 4. 四处差别

```text
① 缩放        单头 1/√d_k；多头 1/√(d_k/heads)  ⇒ 差 √heads 倍
② 作用位置     head_records 作用在**某一层的输入**上（单头路径重放到那一层）
③ 块类型       day079 的块要求 day075 的 AttentionForward，而多头那份是 MultiHeadForward
④ 唯一接缝     head_records(heads=1) 必须**逐位**等于 self_records
```

### 5. 那条断言与它抓到的 bug

它值得存在，因为它是**两处实现之间唯一可以比的地方**：一旦"分头"这一侧
与"模型那一侧"读的不是同一段输入、或者缩放口径走散，它立刻为假。

第一次运行时它就是这样抓到 bug 的：

```text
heads = 1 在第 0 层逐位相等、在第 2 层**不相等**
⇒ 说明 head_records 读的不是"第 2 层的输入"，而是"把模型输入直接喂给第 2 层"
```

修法是先按单头路径重放到那一层（`_stream_input_at_layer`），再在那里做多头读法。

### 6. 为什么两块不能直接拼

因为 day079 的 `encoder_block` / `decoder_block` 的签名要求一个
`forward: AttentionForward`（day075 的类型），而 `multi_head_attention` 返回的是
`MultiHeadForward`——**两种类型**，因此"整条链都换多头"在本仓的实现里做不到。

day085（源码精读）会看到对照：Hugging Face 的 `T5Attention` 同时支持
`n_heads` 与因果掩码，因为它把"分头"放在**投影内部**（`view(...).transpose(...)`），
而不是换一个块类型。

### 7. 缩放与比值

```text
单头（day075）  1/√d_k
多头（day076）  1/√(d_k/heads)
比值            √heads（day076 的 scale_ratio）
```

因此"把单头的权重按头切开"这件事根本不存在：多头不是"单头切成几份"，
而是**投影划分与缩放都不同**的另一个算子。

## 三、文本热力图

### 8. 三条理由

```text
① 它能进仓库：一张 PNG 进 diff 没有意义；而一段文本可以被 review、被逐行比
② 它能被断言：渲染 → 解析 ⇒ 逐级相同（第 4 条性质）
③ 它零依赖：不需要 matplotlib，任何终端都能看（本机的演示脚本就是证据）
```

### 9. 三个等级

```text
level_of(0.111)              int(0.111 × 9) = int(0.999) = 0
level_of(1.0/9.0)            int(1.0) = 1
level_of(1.0/9.0 - 1e-12)    int(0.999…) = 0
```

第 2 行说明"第 k 级的**下界**属于第 k 级"：`1/9 × 9 = 1` 恰好落到 1（浮点上
`0.111…× 9` 略有误差，但向下取整把它变成 0 或 1 的分界只在这一点上）。
第 3 行说明它用的是**向下取整**而不是四舍五入。

### 10. 为什么拒绝大于 1 的权重

因为一个权重是**分布里的一项**，它不可能大于 1。越界只可能来自两件事：
"两张表被加在了一起"（比如把两个头的权重求和后没归一化），或者"没有归一化"。

照常渲染会骗人：`1.0000001 × 9 = 9.0000009 → int → 9` ⇒ 最右边那一列全是 `@`，
**看起来完全正常**，而整张图在说"这个位置占了全部注意力"。

### 11. 解析侧怎么区分

判据是两条一起用：

```text
① 整行恰好两个 `|`（标题行有三个：流名与熵各一个）
② `|` 前面的部分 `.strip().isdigit()`（图例行没有这个前缀）
```

如果改成"任何含 `|` 的行都算"，标题行会被切成三段并当成格子去解析，
于是"等级字符"里出现中文——而解析侧会把它当成未知字符**拒绝**
（而不是猜一个最接近的），因此错误会以 `ParameterError` 的形式出现，
而不是画出一张偏了一格的图。

## 四、熵与天花板

### 12. 第一条纪律

```text
一行的熵 ≤ ln(这一行能看到的位置数)
```

它不是经验规律，而是 **Jensen 不等式**的直接推论：一个支集大小不超过 `k`
的分布，其 Shannon 熵的最大值在**均匀**时取到，等于 `ln k`。
0.794513（因果、n = 4）就是 `(1/4)Σln(i+1)`。

### 13. 两个天花板

```text
全开     ln 4 = 1.386294
因果     (1/4)·(ln 1 + ln 2 + ln 3 + ln 4)
        = (0 + 0.693147 + 1.098612 + 1.386294) / 4
        = 0.794513
```

因果/全开 = `0.573120`（n 越大越接近 1：`n = 64` 时是 0.77 量级）。

### 14. 那 0.588 说明了什么

```text
熵的差    1.380526 − 0.792550 = 0.587976
归一化差  0.997528 − 0.995839 = 0.001689
```

"GPT 的注意力比 BERT 尖得多"这句话里，**那 0.588 全部是掩码的账**：
因果掩码把第 0 行的天花板压到 `ln 1 = 0`，整张表的天花板被压低了 42.7%。
归一化之后两者**几乎一样**（都接近 1，也就是"几乎均匀"）。
这正是本课要教的那件事：**跨掩码比较之前必须先归一化**。

### 15. 未训练模型带来的结论

归一化熵 ≈ 0.996~0.998 说明：**"尖"是训出来的，不是初始化出来的**。
本课读的是**没有训练过**的模型（参数来自 day082 的确定性初始化），
因此五张表量的是"这个结构在初始点上能看到什么"。
要让注意力真的变尖，需要 day081 的四个旋钮（初始化 / 调度 / 裁剪 / dropout）——
这条边界写在教程第 9 章里。

### 16. 什么时候熵正好等于天花板

**当每一行在允许的位置上均匀时**。样本里的
`samples.causal_uniform_record(4)` 就是这样：第 i 行在 `i + 1` 个位置上各放
`1/(i+1)`，于是它的熵是 `(1/n)Σln(i+1)`，**正好等于**天花板。
测试 `test_causal_uniform_record_sits_at_the_ceiling` 把它钉住。

### 17. 熵超过天花板说明了什么

说明**权重与掩码来自两次不同的前向**：掩码说"这一行只能看到 1 个位置"
（天花板 `ln 1 = 0`），而权重却在两个位置上都有质量（熵 `ln 2 > 0`）。
一个自洽的实现里这不可能发生——因此这条判据一旦亮红，问题不在"注意力"
而在"两张表配错了"（这正是 day082 第 6.3 节那类"判据被写松"的反面）。

## 五、六个读数与两张表

### 18. 均匀表（n = 4）的六个读数

```text
entropy          ln 4 = 1.386294
ceiling          ln 4 = 1.386294（全开掩码）
normalized       1.0
peak_weight      0.25 @ 0（任何一格都是 0.25）
support          16（全部格子都 > 1e-6）
frobenius        √(16 × (1/4)²) = √1 = 1.0
diagonal_mass    4 × (1/4) / 4 = 0.25
sparsity         0.0
```

### 19. Frobenius 的区间

行随机矩阵的 `√Σa²` 落在 `[1, √n]`：

```text
下界 1      每一行都均匀（1/n）时：Σ = n²·(1/n²)·… 见下
            Σa² = n × (n·(1/n)²) = n·(1/n) = 1     ⇒ √1 = 1
上界 √n     每一行都独热时：Σa² = n × 1 = n          ⇒ √n（n = 4 时是 2）
```

因此它是"有多尖"的一个**标量**读数：越接近 √n 越尖。

### 20. 两个质量读数

```text
diagonal_mass = offset_mass(record, 0)     平均每行"看自己"的比例
offset_mass(k)                            平均每行落在 (i, i−k) 上的质量
```

`offset ≥ 列数` 时返回 `0.0` 而不是报错，因为那是一条**合法的读数**：
"这一层的注意力不可能看那么远"。报错会迫使调用方先自己判断"这一层够不够长"，
而那个判断与"这一层看了多远"是两件事。

### 21. 余弦

```text
两个头完全一样   1.0
均匀表 vs 独热表 1/√n（n = 4 时 0.5）
```

计算过程（n = 4）：

```text
均匀表 u_ij = 1/4，独热表 o_ij = [i == j]
dot   = Σ_i u_ii × 1 = 4 × (1/4) = 1
|u|   = √(16 × 1/16) = 1
|o|   = √4 = 2
cos   = 1 / (1 × 2) = 0.5
```

### 22. 为什么拒绝"掩码不同的两张表"

因为那时它比的是"**能看到多少**"而不是"看了哪里"：
一张全开的表与一张因果的表，即使"注意力形状"完全一样，
在前者上算出来的余弦也会因为"多出来的那些格子有质量"而偏小或偏大——
而这个偏差与"两个头像不像"无关。修法是入口处要求掩码相同
（`AssemblyError`），而不是在报告里加一句注释。

### 23. 0.9947 / 0.9998 / 0.9972 意味着什么

它意味着：**在这一点上（随机初始化）两个头几乎在看同一件事**——
"多头能捕捉不同子空间"这件事在初始点上还没有发生。

它**不能**说明：

```text
① 多头没有用   —— 它只说明"未训练的模型上两个头长得像"（要变尖需要训练）
② 模型不好     —— 这是初始点的读数，不是训练结果的读数
③ 两者的因果   —— 余弦是"形状像不像"，它不区分"看同一个位置"与"看同一片区域"
```

第 ③ 条是本课写下来的一条已知边界（`analyze.py` 的模块说明第三节）。

## 六、滚动

### 24. 公式与那一项

```text
Â = α·A + (1−α)·I
R = Â_L · Â_{L−1} · … · Â_1
```

`(1−α)·I` 就是**残差**：day079 的 `y = x + F(x)` 里那个 `+x`。
在注意力层面它让"这一层什么都没做"也有一条直通车——**信息可以不经过任何混合
就往后传**。`α = 0` 时 `R = I`：所有质量都在对角线，信息一跳都没走。

### 25. 三条性质

```text
① R 仍然行随机                 每个因子行随机（凸组合）⇒ 乘积行随机
② 掩码挡掉的格子仍然逐位为 0     下三角 × 下三角 = 下三角，而且那些 0 是**精确的**
③ α = 0 时 R = I               一条把"这个公式在做什么"说清的判据
```

第 ② 条"只对因果表有内容"：全开掩码的表在上三角本来就没有 0。
报告里用的是它的**按掩码版本** `mask_respected_after_rollout`
（"掩码说的每一格"），因为那一版对两种掩码都说得通。

### 26. 为什么两个都要存在

```text
preserves_causal_zeroes        只看上三角；对因果表有内容，对全开表恒为 False
mask_respected_after_rollout   看掩码说的每一格 ⇒ 对两种掩码都说得通，并给出 (格子数, 最大读数)
```

两张表上的读数：

```text
因果掩码    (掩码外 6 个格子, 最大读数 0.0) + 上三角全 0 = True
全开掩码    (掩码外 0 个格子, 最大读数 0.0) + 上三角全 0 = False
```

第二个读数（"0 个格子"）要如实印出来：否则"通过"会显得比实际更强。

### 27. `gain` 可能是负数吗

可能。`gain = 最后一层的归一化熵 − 滚动的归一化熵`，
而一个**已经很尖**的模型滚动之后可能更散（多个因子相乘会把质量摊开）。
本课的处理是：**如实返回三个数**（最后一层的熵、滚动的熵、差），
判词留给调用方（`more_focused` 只是一个布尔读数，不是判据）。

## 七、性质与工程

### 28. 哪两条不可能失败

```text
rows_are_distributions        它的分辨力在**构造期**：AttentionRecord 直接拒绝坏行和
deterministic                没有随机数的实现里它必然通过
```

不删掉、而是如实说明的理由：**"它通过"与"它被删掉"必须可区分**。
第一条的证据里印出实测的最大行和误差（`1.110e-16`），
第二条的证据里印出两次比较的布尔值——读者要能自己判断"这条通过有多少信息量"。

### 29. 为什么交叉那一路是"0 个格子"

因为交叉注意力**没有掩码**（day082 第 4 条性质：`cross_spans_all_sources`
量到的就是"一格 0 都没有"），因此它在这一条上被查 0 个格子。
这与 day082 的 `mask_zeroes_are_exact`、"掩码外共 **0** 个权重"
是同一条纪律：**把那个 0 如实印出来，而不是把它藏起来**。

### 30. 第一个坑

```python
# 第一版（错的）：把模型的原始输入直接喂给第 layer 层
normed, _cache = layer_norm(inputs, gamma=..., beta=...)      # ← inputs 是模型的输入
forward = multi_head_attention(attentions[layer], normed, heads=heads)
```

它"看起来完全正确"是因为：形状对（LN 保形）、行随机、熵与天花板都算得出来、
热力图也画得出来——只是那些数属于"把输入直接喂给第 k 层"这件事。

抓到它的是**唯一那条跨口径的判据**：

```text
heads = 1 在第 0 层逐位相等、在第 2 层不相等 ⇒ 读的不是那一层的输入
```

修法（一行）：

```python
current = _stream_input_at_layer(checked, checked_inputs, layer, source=source,
                                 placement=resolved_placement)
```

它按 day082 的**单头**路径重放到那一层，因此 `heads = 1` 与模型真实权重逐位相同。
