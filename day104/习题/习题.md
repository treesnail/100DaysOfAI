# day104 习题：把 100 天的对外承诺编成一份清单

> 对应教程：[../教程/教程.md](../教程/教程.md)
> 对应手册：[../源码/smart-research-agent/docs/symbol_catalog.md](../源码/smart-research-agent/docs/symbol_catalog.md)
> 建议用时：30~45 分钟。答案在 [../习题答案/习题答案.md](../习题答案/习题答案.md)。

题目分为四类：**速答**（1~6）、**对照**（7~9）、**诊断**（10~13）、**推导与动手**（14~18）。

---

## 一、速答

1. 本课把什么当成"一行"？一个模块的"承诺来源"有哪三种？它们分别对应源码里的什么写法？

2. 四类绑定（`defined` / `assigned` / `imported` / `unresolved`）的判定顺序为什么不能换？
   请各举一个"换顺序就会判错"的例子。

3. 为什么本课规定"落点必须**在模块级**"？`class Foo:` 里的 `def bar` 与 `try:` 里的
   `from x import Y`，哪一个是本模块的落点？为什么？

4. 什么是**幽灵导出**？本仓库里真的存在一个——它在哪里、叫什么？
   它为什么"比一个报错更难被发现"？

5. 本课第 ③ 条性质（`phantom_exports_are_sound`）走的是哪条独立的路？
   它与 `ModuleBindings.binding_of` 分别看什么？这条性质能抓住哪一类错误？

6. 本课"回来的族"与"缺席的族"分别是哪一个？各自给出一条理由。

---

## 二、对照

7. 把本课的七条性质与 day103 的七条性质对照：哪几条是"同一个问题的同一句话"，
   哪几条是本课**特有**的？

8. 本课有一条**子进程测试**（两个不同的 `PYTHONHASHSEED` 必须给出同一个摘要）。
   它和 day101 的"倒排表文档名必须排序"、day102 的"族按包名升序 × 源码顺序排"、
   day103 的"候选按 `(-len, name)` 排"是不是同一条纪律？请说明它们各自在防什么。

9. day103 的 `import_graph` 与 day104 的 `symbol_catalog` 都用 `ast` 读同一批 `.py`。
   它们的**问题**与**材料口径**各有什么不同？为什么"同一个名字"在两张产物里会有两种结论
   （例如 `STAGE_ITEMS` 在 day103 的图里可能是一条边，在本课的清单里是一个幽灵）？

## 三、诊断

10. 某次运行 `phantom_exports_are_sound` 报"不成立 2 个"。请说出**三种**可能原因及各自该改哪里。

11. 有人把 `collect_bindings` 里那句 `if seen_all > 1 or read is None: declared = None`
    删掉了，只保留"最后一次赋值算数"。请构造一个会出问题的例子，并说明现象。

12. `outside_all_names` 的实现里有一行 `segment = ast.get_source_segment(text, node) or _NO_SEGMENT`。
    这里的 `_NO_SEGMENT` 是干什么用的？为什么本课宁愿用一个"不可能出现的哨兵字符串"，
    也不写一条 `if segment is None:` 的分支？

13. 一个模块的 `__all__` 写成了 `sorted({"A", "B"})`。请问：
    - 它的承诺来源是哪一种？
    - 它在性质 ⑥ 里被算进去吗？
    - 它的"对外名字"是什么？

## 四、推导与动手

14. 给定两个模块：
    - `pkg.a`：`__all__ = ["Alpha", "Beta"]`，其中 `def Alpha`、`Beta = 1`；
    - `pkg.b`：`__all__ = ["Beta", "Gamma"]`，其中 `def Gamma`（`Beta` 没定义、没赋值、没导入）。
    请写出：① 每个模块的 `phantoms()`；② 清单的 `shared_names()`；③ 性质 ③ 与 ⑦ 的读数。

15. 证明：如果 `declared` 里没有重复项，那么 `duplicate_declarations()` 一定是空元组。
    （提示：看 `ModuleBindings.__post_init__` 的两条护栏。）

16. 用本包的公开 API 写一段 5 行以内的代码，打印出"承诺总数"与"跨模块重名数"。

17. 写一条**新的**性质（不要求实现进源码），要求：
    - 它是一条**下界**判据；
    - 它检查"至少有一个模块用了 `computed` 来源的 `__all__`"；
    - 说明它的失败意味着什么。

18. 本课把"幽灵导出"当成一个**读数**而不是一次失败。
    请再举一个**本仓库里真实存在**的类似例子（可以是 day101 / day102 / day103 的），
    说明"什么情况下一个看起来像缺陷的现象应当被印出来、而不是被一条性质删掉"。
