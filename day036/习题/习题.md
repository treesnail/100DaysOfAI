# day036 课后习题

共 10 题，覆盖今天所有学习目标：四种 Prompt 技巧的原理与适用场景、好提示词的五要素解剖、PromptLibrary 的版本管理与持久化、与 PromptEvaluator 的回归联动。建议完成时间：45~55 分钟。

## 第一部分：选择题

### 第 1 题（CoT 为什么有效）

关于 Chain-of-Thought（思维链）提示能提高数学/推理题正确率的机制，下列哪一项解释是**正确**的？

- A. 引导语"让我们一步一步思考"激活了模型参数中专用于数学推理的隐藏模块
- B. 模型是逐 token 自回归生成的，先写下的推理步骤会成为后续 token 的生成条件，中间计算被分摊到整个生成序列，而非压缩在单次前向传播里"心算"完成
- C. 引导语提高了模型的采样温度，使输出更加多样化
- D. 引导语让模型在回答前先联网检索相关资料，获得额外信息

### 第 2 题（Few-shot 示例的作用）

Few-shot 提示中示例的主要作用是：

- A. 向模型传授它预训练时没学过的新知识
- B. 校准输出的格式、粒度与风格——示例是精确的"模式规范"，模型会模仿示例的呈现方式
- C. 增加 prompt 长度，让模型分配更多计算资源
- D. 占用上下文窗口，防止模型输出过长

### 第 3 题（ToT 与 CoT 的关系）

关于 Tree-of-Thoughts（ToT）相对 Chain-of-Thought（CoT）的改进，下列哪一项描述是**错误**的？

- A. CoT 是单链推理，早期步骤的错误会作为条件沿链放大，模型没有"回头看"的机会
- B. ToT 把推理当作搜索问题：并行展开多条分支，再由汇总步评估、比较、择优
- C. ToT 的 LLM 调用数约为分支数 + 1 次汇总，成本显著高于单链 CoT
- D. ToT 中各分支使用完全相同的提示词效果最好，因为可复现性更强

## 第二部分：判断题

### 第 4 题

提示词改一个词就可能改变线上模型行为，因此提示词应当享受与代码同级的工程纪律：版本化、变更留痕（changelog）、可回滚、上线前过回归评估。（对 / 错）

### 第 5 题

`PromptTemplate.render()` 使用 `str.format` 做变量替换，因此模板中给模型看的 JSON 示例（如 `{"k": 1}`）必须写成 `{{"k": 1}}` 才能正常渲染。（对 / 错）

### 第 6 题

在 `PromptLibrary` 中调用 `lib.get("react_system")` 不传版本号时，返回的是版本号字符串字典序最大的模板，而不是最后注册的模板。（对 / 错）

## 第三部分：问答题

### 第 7 题（五要素解剖）

一条高质量提示词可解剖为"角色 / 任务 / 上下文 / 格式 / 约束"五要素。请回答：（1）每个要素各自回答什么问题？（2）缺少"约束"要素时会出现什么典型症状？（3）用五要素分析 day026 的 `REACT_SYSTEM_PROMPT_V2`，指出每一要素分别落在模板的哪一段。

### 第 8 题（四种技巧的选型）

给定以下四个任务，分别为其选择最合适的技巧（zero-shot / few-shot / CoT / ToT 各用一次），并说明理由：

1. 把一段中文新闻翻译成英文；
2. 让模型把用户反馈分类为固定的 12 种业务标签，输出必须是单行 JSON；
3. 求解一道多步骤的奥数应用题；
4. 为一个重要客户设计数据迁移方案，方案错误的代价很高，且有多种合理的技术路线。

### 第 9 题（版本管理与回归联动）

请回答：（1）为什么说 `PromptTemplate.changelog` 不是可有可无的装饰品？（2）`PromptEvaluator.compare` 为什么设置 `TIE_THRESHOLD=0.05` 的平局区间，分差不超过它就判定不分胜负？（3）描述"改提示词 → 回归评估 → 上线"的完整工作流，并说明 `PromptLibrary` 的"默认取最新版"机制在其中扮演什么角色。

## 第四部分：编程题

### 第 10 题（四技巧对比 + PromptLibrary 版本管理演示）

**功能要求**：

在项目根目录新建 `scripts/prompt_techniques_demo.py`，全程离线（LLM 用 MockLLM 脚本化扮演，持久化写入系统临时目录）：

1. **四技巧对比**：选定一个翻译任务，用 `zero_shot` / `few_shot`（含 2 个示例）/ `chain_of_thought` 各构造一次 messages 并调用 `MockLLM.chat`；再用 `tree_of_thoughts(task, n_branches=2)` 生成 2 条分支提示分别调用 LLM，最后用 `ToTPlan.synthesis_messages` 汇总出最终答案。断言：（a）zero-shot / few-shot / CoT 三条提示词互不相同；（b）MockLLM 的总调用次数 = 3 + 2 + 1 = 6（ToT 占 3 次：2 分支 + 1 汇总）。
2. **版本管理**：创建一个 `PromptLibrary`，注册名为 `translate` 的模板两个版本（v1：`'把『{text}』翻译成{lang}'`；v2 在 v1 基础上补充角色与约束要素，changelog 说明变更原因）。断言：（a）`history("translate")` 返回的版本序列是 `["v1", "v2"]`；（b）`get("translate")` 默认取 v2；（c）`render("translate", text="你好", lang="英文")` 正确填充两个变量。
3. **持久化往返**：把库 `save_jsonl` 到临时文件，新建空库 `load_jsonl` 读回。断言加载数为 2，且读回的 v1 模板文本与注册时逐字节一致、v2 渲染结果与直接渲染一致。
4. 打印各技巧的关键输出与断言结论，最后打印"全部断言通过"。

**提示**：脚本顶部需要 `sys.path.insert(0, str(Path(__file__).resolve().parent.parent))` 以确保导入的是本快照内的包；`tree_of_thoughts` 的汇总提示必须用 `plan.synthesis_messages(branch_outputs)` 生成，分支输出数量与分支数不符时会抛 `ValueError`。
