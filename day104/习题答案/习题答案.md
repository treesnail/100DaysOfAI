## 一、速答

**1.** 一行是**每一个 `.py` 文件**（`smart_research_agent/**/*.py`，当前快照 464 行）。
三种承诺来源是：

```text
declared   __all__ = ["A", "B"]            ⇒ 字面量，可以逐字核对
computed   __all__ = sorted({...})          ⇒ 写了，但不是字面量，这一课读不出来
implicit   根本没有写过 __all__
```

来源之所以要分开记，是因为**"没有 `__all__`"不等于"没有承诺"**，
只等于"这份承诺没有被写下来"；把三者混成一类，读者会把"没写"读成"写错"。

**2.** 判定顺序写死为 `defined → assigned → imported → unresolved`。换顺序会判错的例子：

```text
先 assigned 后 defined      一个名字既是 class 又是模块级变量时，会被记成变量
先 imported 后 defined      本模块定义的 foo 会被记成"从别处导进来的同名"
先 imported 后 assigned     从别处导入的常量会被记成"本模块赋的值"
```

这与 day102 的"四类归属"是同一条纪律：**顺序不是风格，是语义。**

**3.** 因为一个名字的落点必须**在模块级**——它才回答"这个对外名字从哪里来"：

```text
class Foo:
    def bar(...): ...        bar 不算本模块的落点（它在 Foo 里面）
try:
    from x import Y          Y **算**（它就在模块级作用域里）
```

`try:` 是**模块级控制流**（它不改作用域），而 `class` / `def` **开了新作用域**。
本课里这条规则写成 `iter_module_scope`："进 if / try / with / for / while，不进 def / class"。

**4.** **幽灵导出** = 在 `__all__` 里承诺了、却在本模块里既没定义、也没赋值、也没导入的名字。
本仓库里真的存在一处：

```text
smart_research_agent/transformer_stack/verify.py 的 __all__ 里写着 "STAGE_ITEMS"
```

它"比一个报错更难被发现"，因为 `__all__` 读起来永远像一份**已经兑现**的清单；
而真正的错误只在有人 `from ... import *` 的那一刻才以 `AttributeError` 出现。

**5.** 第 ③ 条性质走的是**纯文本**这条路（`parse.outside_all_names`）：
把每一段 `__all__ = [...]` 的源码片段从文本里挖掉，再正则找出剩下的标识符。
它与 `ModuleBindings.binding_of` 是两条独立的路：

```text
binding_of(name)          看"这个名字被哪一类**绑定**兜住了"（AST 语法结构）
outside_all_names(path)   看"这个名字在 __all__ 之外**出现过没有**"（纯文本）
```

它能抓住的错误是：**解析漏了一类绑定**（比如忘了 `try` 里的 import）。
那时一个名字会被误报成幽灵，而独立复核会发现它写在正文里，于是第 ③ 条当场变红。

**6.** 回来的族是 `CoverageError`（`RETURNED_FAMILY`）：它由 day102 第一次命名，
当时记的是"某个子包没有 `errors.py`"——一句关于**覆盖**的话；day103 没有它，
本课换了一个对象（承诺）却问同一个问题："一个模块承诺了 N 个名字，这 N 个名字落到了哪里？"
缺席的族是 `GradientError`（`ABSENT_FAMILY`）：本课是纯静态分析，连一次 import 都不执行。

## 二、对照

**7.** 同一句话的三条：① 覆盖（day103 是"每个 `.py` 都在图里"，本课是"每个 `.py` 都在清单里"）、
② 可复算、以及"报出来的东西是不是真的"（day103 是"环是不是真的"，本课是"幽灵是不是真的"）。
本课**特有**的四条：④ 重名条目是真的、⑤ 同一模块内不重复声明、
⑥ 每个承诺的模块至少承诺一个名字、⑦ 跨模块重名确实存在。
其中 ⑥ ⑦ 是"承诺"这件事独有的：图没有"承诺数"，台账没有"跨模块重名"。

**8.** 是同一条纪律：**把并列 / 未固定的顺序显式消掉，让"两次运行逐位相同"成为一条 `==`。**

```text
day101  防的是 dict 插入序（倒排表里文档名必须排序）
day102  防的是集合序（族按"包名升序 × 源码顺序"排）
day103  防的是排序键并列（sorted(key=len) 在等长候选上回到 set 的迭代序）
day104  防的是集合序 + 绝对路径（comparable 里既不放 set / dict，也不放 path）
```

本课多防了一条：**绝对路径**——同一份源码在两台机器上必须给出同一个摘要。

**9.** 两条产物的**问题**不同、**材料口径**也不同：

```text
day103  import_graph     问题：我依赖谁 / 动了我谁受影响      材料：**任意位置**的 import 语句
day104  symbol_catalog   问题：承诺了什么 / 落到了哪里          材料：**模块级**的 def / 赋值 / import 别名
```

因此同一个名字在两张产物里会有两种结论：day102 / day103 关心的是"有没有一条语句提到它"，
本课关心的是"**模块级**有没有一个绑定兜住它"。`STAGE_ITEMS` 在 day103 的图里可能被一条
`from ... import STAGE_ITEMS` 记成一条边（如果有），而在本课的清单里它是**幽灵**——
因为 `__all__` 声明了它，模块级却没有任何绑定。

## 三、诊断

**10.** "不成立 2 个"的三种可能原因：

```text
① 解析漏了一类绑定   某个名字其实被兜住了（如 try 里的 import），却被报成幽灵 ⇒ 改 parse
② __all__ 读错       把一段本该挖掉的片段漏掉了，导致正文里"看起来"出现了这个名字 ⇒ 改 outside_all_names
③ 源码真的写错了     名字确实承诺了却找不到落点 ⇒ 改源码或改 __all__（这是**正确**的报警）
```

**11.** 删掉那句之后，"写了两次 `__all__`"或"`__all__ += [...]`"会被当成最后一次赋值算数：

```python
__all__ = ["A"]
__all__ += ["B"]      # 结果表其实是 [A, B]，但只保留第一个会漏掉 B
```

现象很具体：`declared` 会**少几个名字**，于是性质 ① 的"承诺总数"偏小、
而"幽灵"也可能因此算不出来（少算的那些名字没被检查）。本课的判据是
**"读不出来就说读不出来"**：来源记成 `computed`，而不是猜一个。

**12.** `_NO_SEGMENT` 是一个**不可能出现在源码里的哨兵字符串**，用来代替 `None`：

```python
segment = ast.get_source_segment(text, node) or _NO_SEGMENT
stripped = stripped.replace(segment, " ")
```

`ast.get_source_segment` 对真实文本永远给得出片段，所以 `None` 那条分支**永远走不到**。
一个走不到的分支会永远算"未覆盖"，逼着人给它写一条假的测试或一条 pragma——
本课宁愿用一个哨兵把分支消掉：**分支少了，"这条性质覆盖了哪些情形"才说得清。**
（这是本课唯一一处"为覆盖率让路"的设计，理由写在这里。）

**13.** `__all__ = sorted({"A", "B"})`：

```text
来源      computed（写了 __all__，但不是字面量）
性质 ⑥    不计入（它只统计 declared 的模块）
对外名字   退而取**顶层公开 def / class**（exports() 在来源不是 declared 时走这条路）
```

## 四、推导与动手

**14.** 给定 `pkg.a`（`__all__ = ["Alpha", "Beta"]`，`def Alpha`、`Beta = 1`）
与 `pkg.b`（`__all__ = ["Beta", "Gamma"]`，只有 `def Gamma`）：

```text
① phantoms()：
     pkg.a ⇒ ()            （Alpha 有定义、Beta 有赋值，都兜住了）
     pkg.b ⇒ ("Beta",)      （Beta 既没定义、也没赋值、也没导入）
② shared_names()：
     Beta  被 pkg.a 与 pkg.b 同时导出 ⇒ (("Beta", ("pkg.a", "pkg.b")),)
     Alpha / Gamma 只出现在一个模块里 ⇒ 不进表
③ 性质 ③ 读数 = 0（pkg.b 的 Beta 在 pkg.b 的正文里一次都不出现 ⇒ 是真幽灵）
   性质 ⑦ 读数 = 1（跨模块重名 Beta ≥ 下界 1 ⇒ 通过）
```

**15.** 因为 `ModuleBindings.__post_init__` 里有两条护栏：

```text
第一：declared 必须是"一份排序且不重复的名单"（len(set(rows)) == len(rows)）
第二：来源是 declared 时，declared 不能为空
```

于是任何一份合法的 `ModuleBindings`，其 `declared` 里天然没有重复项；
`duplicate_declarations()` 又是对 `set(entry.declared)` 与 `len(entry.declared)` 的比较，
因此它**按构造**一定是空元组。性质 ⑤ 因此是一条"上界恒成立"的护栏性质——
它的价值不在"现在能抓住谁"，而在"**如果有人把这个不变式改坏了，它当场变红**"。

**16.** 五行以内：

```python
from smart_research_agent.symbol_catalog import build_catalog
catalog = build_catalog()
print("承诺总数", catalog.promise_count())
print("跨模块重名", len(catalog.shared_names()))
```

**17.** 一条新的**下界**性质（示例）：

```text
id         computed_sources_exist
判据       lower_bound
描述       至少有 1 个模块用了 computed 来源的 __all__（读数 >= 1）
失败意味着 这份清单只剩"字面量承诺"与"隐式承诺"两种形态——
           模块们要么逐字列出、要么干脆不写，中间那一档（写了但读不出来）消失了。
```

阈值定在 1 上，是因为它是一条"存在性"断言：**"有"这件事只能从下面兜住**
（写成 `== 1` 会在仓库多出两个 computed 模块时误报失败）。

**18.** 本仓库里"是读数、不是失败"的例子（至少一个即可）：

```text
day103  模块级的图有 4 个环（含 api ↔ tools 那个跨包环）：环是**读**出来的，不是**删**掉的。
        理由：把它们做成"必须无环"的性质，会在仓库合理地变化时变红，最后被人关掉。
day102  18 个子包没有 errors.py：这是"这一族的覆盖情况"，不是"这些子包错了"。
day104  1 个幽灵导出：它是一条**要被修**的读数，而不是一条"引擎必须自证清白"的性质。
```

判断标准可以写成一句话：
**当这个现象是"仓库的真实状态"、而不是"工具算错了"时，它就该被印出来；
只有当它是"工具自己算错了"时，才该让一条性质当场变红。**
