## 一、Dropout 与它的反向

### 1. 缩放与期望

```text
缩放 = 1/(1 − 0.25) = 1.333333
E[掩码 × 缩放] = 1.0                        ← 这就是 inverted dropout 的判据
不做缩放时均值 ≈ 1 − p = 0.75               ← 原版的写法在推理时要把整层乘回 0.75
```

`200 × 200` 的掩码上实测均值与 1.0 的偏差在 `1%` 以内（有限样本效应）。

### 2. 两版差别在代码

```text
原版      训练时只置零；**推理时**把整层乘 (1 − p)  ⇒ 推理路径必须知道 p
inverted  训练时置零并放大 1/(1 − p)；推理时什么也不做 ⇒ 推理路径**不需要** p
```

本课选 inverted，因为它换来一条很硬的性质：**推理路径与"没有 dropout 的模型"
逐位相同**。这条性质在代码里的样子是——`forward_output_at(..., phase="eval")`
的输出与 day080 的 `stack_forward` **逐位相等**（测试里有一条专门盯它）。
原版做不到这一点：它的推理路径必须多一个参数，于是"训练用一套、推理用另一套"
这种最坏的偏差有了可乘之机。

### 3. 准确的版本

```text
不准确的    "dropout 是随机的，所以它的梯度没法用数值差分校验"
准确的      "掩码**也随机**时，整个算子带一个随机变量（函数在变），差分没有意义；
            而掩码**被固定**时，y = x ⊙ m · s 是一个线性、对角的东西，
            它的梯度完全能用中心差分逐项核对"
```

"随机"这个性质属于**掩码的生成**，而不属于**这一次计算**。
把掩码记下来（`StepCache.masks`）就是把前者与后者分开——
这也正是第 4 题存在的原因。

### 4. 为什么要保存掩码

反向需要三样东西才能正确地把梯度送回去：

```text
掩码 m     决定哪些位置的梯度被切断
缩放 s     决定活下来的位置乘几倍
顺序        先穿掩码、再调用 encoder_block_backward
```

只保存输出是不够的：**从输出反推掩码是不可能的**（被丢掉的位置与"原值恰好是 0"
无法区分）。而没有掩码，第 3 题那条数值校验就做不了，第 3.2 节那处顺序错误
也就没有东西能抓住它。

### 5. 动手

```text
rate=0.0 的输入输出逐位相同（train 相也走恒等那一支）
rate=0.5 时：被丢的位置输出 0.0；活下来的位置输出 = 原值 × 2.0
```

`scale = 1/(1−0.5) = 2.0`，掩码由 `(seed, step, layer)` 唯一决定——
因此同一颗种子跑两次得到同一张掩码（可复现），而换一个 `step` 就换一张。

## 二、初始化

### 6. `fan_in = 4`、`fan_out = 16`

```text
xavier_uniform    √(2/(4+16)) = √0.1  = 0.316228
kaiming_uniform   √(2/4)      = √0.5  = 0.707107
normal            1/√4        = 0.5
从小到大          xavier (0.316) < normal (0.500) < kaiming (0.707)
```

顺序与"对 ReLU 的补偿"的关系：

```text
xavier    假设激活是线性的（配 tanh/sigmoid）  ⇒ fan_in 与 fan_out 都进分母 ⇒ 最小
normal    只按 fan_in 取 1/√fan_in             ⇒ 居中
kaiming   按 fan_in 且把 ReLU 关掉的一半补回来  ⇒ 最大
```

### 7. `fan_in = fan_out = 8`

```text
xavier    √(2/16) = 0.353553
kaiming   √(2/8)  = 0.500000
比值      0.5 / 0.353553 = √2 ≈ 1.414214
```

那个 `√2` 就是"ReLU 关掉一半单元"在公式里的样子：一半的单元输出为 0，
要让**输出的方差**与**输入的方差**相等，权重的方差就得放大一倍
（`ReLU` 会把一半平方项抹掉），而方差翻倍对应标准差乘 `√2`。
第一版把这里写成"两者在 `fan_in == fan_out` 时相等"，而它们**恒**差 `√2`。

### 8. 为什么两个标准差都要印

```text
只印实测值     "0.146935 对不对？"——没有参照物
只印理论值     "公式写对了没有？"——没有证据说它真的被实现了
两个都印       比值是**唯一**能判"公式与实现一致"的读数（本课判据：落在 [0.5, 2]）
```

理论值是"无穷多样本下的期望"，而 `24 × 6` 只有 144 个数：实测差几个百分点是正常的，
差一倍就不是。样本实测四个比值：`1.0180 / 1.0180 / 1.0180 / 0.9679`。
测试里有一条反证：把理论值故意乘 10，比值立刻越界——**判据真的能失败**。

### 9. 为什么 LN 的 `γ/β` 不初始化

```text
γ = 1、β = 0  是 LayerNorm 的自然初始点（初始时 LN 就是标准化本身）
```

它与 day080 的逐层增益的关系很直接：初始增益 `‖y_i‖/‖x_i‖` 里同时含
"权重矩阵的幅度"与"γ/β 的初值"两个因素。把 `γ/β` 固定成恒等之后，
**这个读数只反映权重矩阵的幅度**——于是"换初始化方案"与"增益变了"之间
才有干净的一一对应（样本上 uniform 2.24、xavier 3.50、normal 3.56、kaiming 7.76）。

### 10. 动手：四组比值

```text
uniform         1.0180
xavier_uniform  1.0180
kaiming_uniform 1.0180
normal          0.967932
```

三条均匀方案的比值**恰好相同**：它们的半宽相差 `√2` 倍，而"实测/理论"的
偏差是一个**比例**，因此这个比值不随半宽变。正态方案走的是 Box–Muller
（另一套映射），偏差略有不同。四组都落在 `[0.5, 2]` 之内。

## 三、调度、裁剪与早停

### 11. `warmup_cosine` 的手算

```text
热身段（t ≤ 5）    lr(t) = base_lr · t / warmup = 0.3 · t / 5
  第 1 步 0.06   第 2 步 0.12   第 3 步 0.18   第 4 步 0.24   第 5 步 0.30
峰值               第 5 步（0.30 = base_lr）
第 20 步           0.0（cos 退火到 min_lr = 0）
```

本包允许学习率是 0 的理由：**"退火到 0"是余弦调度的端点**，那一步不做更新是它故意的。
第一版把"学习率必须是正的"当判据，于是 `warmup_cosine` 在最后一步抛
`NumericError`——把一个合法配置挡在了门外。本包只拒绝负数与非有限数。

### 12. 第 1 步为什么不是 0

```text
第 1 步 = base_lr / warmup（本课样本 0.02）
```

如果它是 0，日志里会出现：**第 1 步的损失与初始损失一模一样**
（第一次更新完全没有发生）。而那个现象最容易被读成"梯度算错了"或"学习率没接上"——
排查会走向"检查反向"这条错误的路，而真正的问题是热身公式少了一个"从 1 数起"。

### 13. 手算 `(100, 1)`

```text
逐分量裁剪到 [−1, 1]      → (1, 1)
  cos = 101 / (√10001 · √2) = 101 / 141.421356 = 0.714142
  方向从"几乎水平"变成 45°

整体范数裁剪（阈值 1）   ‖g‖ = √10001 = 100.004999
  scale = 1/100.004999 = 0.0099995
  → (0.999950, 0.00999950)，‖·‖ = 1.0
  cos = 1.0（整体乘一个正标量，方向不变）
```

### 14. 为什么三个数都要留下

```text
没设阈值            裁剪 0.5 但 ‖g‖ = 0.2      裁剪 0.5 且 ‖g‖ = 2.5
scale 1.0            scale 1.0                  scale 0.196
max_norm None        max_norm 0.5               max_norm 0.5
```

只看梯度的话前两者完全一样（都原样返回），而它们的**含义**完全不同：
一个是"没有这道闸门"，一个是"闸门开着但没有车经过"。
`ClipReport` 因此留下 `original_norm / max_norm / scale` 三个数——
判断"这一步有没有被裁"要的是 `scale < 1`，判断"闸门存不存在"要的是 `max_norm`。

### 15. `min_delta = 0` 的问题

```text
序列      1.0, 1.0 − 1e-15, 1.0 − 1e-15
patience  1，min_delta = 0
结果      第 2 步被当成"变好"（1e-15 的下降），waited 归零；
          第 3 步 waited = 1 ⇒ 触发
```

也就是说，**浮点噪声级的下降会被当成进展**，而早停的"连续没变好"这条判据
因此永远差一点才满足。本课默认 `min_delta = 0`（与"任何下降都算变好"这条朴素读法一致），
而把它写进配置、并在报告里印出来——判据不是事实，它必须可见。

### 16. "最好的一步"与回滚

本课的处理：`EarlyStopReport` 同时给出 `best_step` 与 `best_loss`，
而**不回滚**。理由有两条：

```text
① 回滚是调用方的决定      ——它取决于"这份参数接下来要干什么"（部署？继续训？）
② 回滚要有地方存"最好的那一份" ——那是模型版本管理的事（day058 会讲）
```

本课只把这件事**写进报告**：报告里有 `best_step`，于是"我该回去拿哪一份"有答案。

## 四、训练循环与记录

### 17. 参数量的算术

```text
一块     4d + 2·d·d_ff + d_ff + d = 24 + 288 + 24 + 6 = 342
整条链   4 × 342 = 1368                     ← 只含**块参数**，不含注意力的 4d²
flatten_block_gradients 的长度 = 1368
```

为什么可以"取每一环的前 342 个数"：

```text
BlockGradients.flatten()   的顺序是"八块参数 + 输入梯度"（342 + 24 = 366）
BlockParameters.flatten()  的顺序只有那八块（342）
两边的八块**来自同一张表**（BLOCK_GRADIENT_TARGETS），而输入梯度排在最后
⇒ 前 342 个数逐位对应那一层的八块参数
```

切片的位置不是猜的：它由"输入梯度排在最后"这个约定保证。

### 18. 两个损失口径

```text
只看训练损失       rate 0.2 那一行看起来更差（末损失 0.136940 vs 0.098223）
                   ⇒ 会得出"dropout 有害"的结论
只看推理损失       看不到"训练时发生了什么"（比如掩码把多少单元丢掉了）
                   ⇒ 无法判断"训练相与推理相差多大"
```

两个都给的另一个理由：`gap = eval_loss − loss` 本身就是一个读数。
在 `rate = 0.2` 时它是 `-0.04` 量级（推理损失更低），而在 `rate = 0` 时是 `-0.004`——
**它的变化量就是 dropout 的强度**。

### 19. 判据为什么落在 `eval_loss` 上

```text
"最好的一步的 loss"   训练相 ⇒ 带掩码噪声
                      样本上 rate 0.2 的"最好"是 0.062719，而那是一个**幸运掩码**
                      换一颗种子就会变
eval_loss             推理相 ⇒ 没有掩码、没有缩放 ⇒ **同一份参数给同一个数**
```

也就是说 `eval_loss` 是"参数的一个函数"，而训练损失是"参数与掩码的一个函数"。
判据要落在前者身上，否则它测的是运气。

### 20. 三处顺序各防什么

```text
① 学习率先取、再更新     防止"第 t 步用了第 t−1 步的学习率"——那会让整条曲线
                        相对计划错开一格，而两条曲线（对与错）看起来都"有升有降"
② 裁剪在优化器之前       防止优化器拿到**未裁剪**的梯度（裁剪就白设了）
③ 评估用推理相           防止把掩码噪声带进判据（第 19 题）
```

### 21. 动手：40 步的曲线

```text
损失**不是**单调下降的。
样本（lr=0.1）：最好的一步是第 23 步（0.098026），而末损失是 0.098223——
即"过了最好那一步之后又轻微变差"，而 curve.best_is_before_the_end 为 True。
```

这正是"`best_step` 是读数的一部分"那条纪律的来源：只看首末两个数会得到
"还在下降"的印象，而序列告诉你的是一段轻微的回升。

### 22. 两个族各自的例子

```text
只有 NumericError        调用方传进来的损失里有 nan —— 数据的问题，改数据
只有 DivergenceError     学习率 0.8、每一步都合法，而损失（或数值）越走越坏
                         —— 过程的问题，改超参
```

`DivergenceError` 继承 `NumericError`（它的数值确实不可用了），
但值得有自己的名字：**修法不同**。这条判据从 day075 起没变过。

## 五、四组实验

### 23. 初始增益与发散

```text
uniform   2.237007   收敛
xavier    3.496730   收敛
normal    3.559168   收敛
kaiming   7.756731   **第 7 步发散**
```

粗略判据（本样本、lr=0.1、40 步）：

```text
初始第一层增益 ≈ 2 ~ 3.6  ⇒ 收敛
初始第一层增益 ≈ 7.8      ⇒ 发散
```

也就是说分界线落在 `3.6 ~ 7.8` 之间，而本课只给出"7.8 一定炸、3.6 一定不炸"。
它把 day080 的"逐层增益"从一个**前向读数**变成了一个**可操作的判据**。

### 24. 为什么发散也要记成一行

```text
一行不缺       读者会以为"这一组没测"——而实际上它是"测了，而且炸了"
记成一行       表里的 state 列写着"发散"，failure 里是原始消息
               ⇒ "哪几组超参不能这么设"变成一条可检索的记录
```

实现上，`_run` 抓住 `DivergenceError` 之后仍然返回一个 `StudyRow`：
`steps = 0`（还没更新就炸）、`diverged = True`、`first_loss` 取"第 1 步更新之前"
的损失（而不是填 0——填 0 会让它在"最小损失"的排序里排到第一）。

### 25. pre / post 的三个数

```text
pre-LN    0.247506 → 0.098223    改善 2.5249 倍
post-LN   0.962255 → 0.040555    改善 23.7270 倍
```

"改善倍数"这个读数的意义在于**它把起点的影响除掉了**。
两个变体的**起点不同**（post-LN 的每层输出过一次 LN，初始前向的输出尺度差很多），
因此直接比末损失是"两个不同的起跑线比终点"；改善倍数回答的是"从自己的起点走了多远"。

### 26. day079 那句话的答案与三条边界

```text
答案      在本课的配置下，**热身在整张表上没有救下任何东西**
          pre-LN   0.247506 → 0.098223（关热身）/ 0.098038（开热身）
          post-LN  0.962255 → 0.040555（关热身）/ 0.044697（开热身）
          而且 post-LN 本来就**不发散**——它根本不需要被救
```

三条边界：

```text
① 规模      这是 4 层、d=6、固定随机注意力、40 步、单一目标、单一种子的**一次观测**
② 档位      预热的收益要在"学习率接近发散边界"时才显形；本配置下 post-LN
            在 lr=1.2 都跑得完，它没有走到需要预热的那一档
③ 方向      在固定注意力 + 小模型这个配置里，**反而是 pre-LN 先炸**
            （它的残差流没有被归一化）：lr=0.8 第 8 步、lr=1.0 第 7 步、lr=1.2 第 6 步
```

第 ③ 条同时解释了第 9.3 节那条反直觉的结论：post-LN 的**每层输出都过一次 LN**，
于是参数长到多大都不会让残差流无界增长——它对大学习率更耐受，
而它在 day079 的 `‖∂loss/∂x‖` 上确实更差。**两个问题，两个答案。**

### 27. 学习率边界（关掉裁剪）

```text
lr=0.5   pre-LN 收敛（0.098000）；post-LN 收敛（0.040495）
lr=0.8   pre-LN **第 8 步发散**：范数护栏（分量有限、平方和溢出）
         post-LN 收敛（0.040498）
lr=1.0   pre-LN **第 7 步发散**：参数溢出护栏（Python 的 OverflowError）
         post-LN 收敛（0.040499）
lr=1.2   pre-LN **第 6 步发散**（同上）；post-LN 收敛（0.040593）
```

三条消息分别是哪条护栏给的：

```text
范数护栏（_ensure_finite_norm）       "梯度范数溢出成 inf……每一个分量都还是有限数"
参数护栏（_ensure_finite）            "参数变成了非有限数……"
溢出护栏（except OverflowError）      "数值溢出（(34, 'Result too large')）……"
```

而第三种（`math.fsum` 的 `ValueError`）出现在 `kaiming` 那一组
（"数值失去意义（-inf + inf in fsum）"），见第 30 题。

## 六、边界与踩过的坑

### 28. 相邻小种子为什么不能用来求期望

```text
第一版做法    用 40 颗小种子（0..39）各生成一张小掩码，再对输出求平均
实测          稳定地得到 0.0
原因          LCG 的第一个值是 (M·s + I) mod MOD —— 它随 s **近似线性增长**，
              因此 s 在 0..39 时前几个值几乎都落在 [0, p) 里 ⇒ 第一个元素几乎总被丢掉
正确做法      把**一张大掩码**（200 × 200 = 40000 个元素）当成一个样本
```

这不是 bug，而是 LCG（day073 的那一串）的性质，而"换一颗种子重跑一遍"
是实验里最常见的动作。本课把这条边界写成了两条测试：
一条用大掩码验期望，一条**断言相邻小种子的第一个元素彼此接近**。

### 29. 漏传 `placement` 的现象

```text
现象      "post-LN"那几行与"pre-LN"那几行**重合成一条曲线**——
         连首个损失、末损失、改善倍数四个读数都一模一样
为什么难发现
         它不报任何错：`step_loss` 用了默认值 `placement="pre"`，
         而默认值是合法的；两条曲线各自看起来都完全正常
真正的信号
         **两条本来就该不同的配置给出了同一个结果**
```

修法是让 `placement` 一路传下去（`train → step_loss → training_forward`），
并加一条测试专门盯它（`test_placement_is_threaded_through`）。

### 30. `except ValueError` 必须先把"自己的错"放过去

```python
try:
    ...                      # 前向 / 反向 / 更新 / 评估
except OverflowError as error:
    raise DivergenceError(...) from error
except ValueError as error:
    if isinstance(error, TrainingError):
        raise                # ← 这一行是必须的
    raise DivergenceError(...) from error
```

原因：

```text
math.fsum 遇到 (-inf) + (+inf) 抛的是 **ValueError**（"−inf + inf in fsum"）
而本包那五族（ParameterError / ShapeError / NumericError / GradientError /
DivergenceError）都继承 TrainingError，而 TrainingError 继承 ValueError
```

写错的后果：**本包自己的真 bug（比如某个形状检查失败）会被改写成
"训练发散了"**——于是排查方向从"改代码"被引到"改超参"，而后者永远修不好它。
`isinstance` 那一行把两类失败分开，是本课唯一一处"catch 一个宽异常"的地方，
而它存在的理由就写在这三行注释里。
