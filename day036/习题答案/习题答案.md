## 第一部分：选择题

### 第 1 题

**答案：B**

**解析**：CoT 的有效性根植于自回归生成机制（day033）：模型生成每个 token 都以前面所有 token 为条件。不加引导语时，模型必须在产出答案的那一个 token 里，靠单次前向传播完成全部计算——等于心算多位数乘法。追加"一步一步思考"后，中间结果（"进水速度 1/4，净速度 1/12"）先被写成 token，后续 token 直接以这些中间结果为条件——**计算被分摊到整个生成序列上，有效计算深度随输出长度增长**。A 错误：不存在被"激活"的专用模块，同一组参数，改变的是计算的编排方式；C 错误：引导语与温度无关，我们的实现里 `chain_of_thought` 与 `zero_shot` 的唯一差别就是追加一句 `COT_INSTRUCTION`（测试 `test_differs_from_zero_shot_only_by_instruction` 精确断言这一点）；D 错误：纯提示词技巧不涉及任何联网检索。

### 第 2 题

**答案：B**

**解析**：Few-shot 示例的价值不在"教知识"——翻译"你好"这种示例没有任何新知识。它校准的是**输出的呈现方式**：要不要解释、要不要引号、标签用全称还是缩写、风格正式还是口语。模型是强大的模式匹配器，示例就是最精确的模式规范，这也是为什么 few-shot 对格式敏感型任务（固定 JSON、固定分类标签）提升最大。A 是经典误解；C 把副作用（prompt 变长、token 成本上升）当成了机制；D 完全颠倒——占用上下文窗口是 few-shot 的代价而非目的。

### 第 3 题

**答案：D**

**解析**：D 错误——分支同质正是 ToT 退化的原因。若 n 条分支用完全相同的提示词，低温度下模型会产出高度雷同的结果，"搜索"退化成"把同一条链跑 n 遍再裁决"，白白付出 n+1 倍成本却得不到多样性收益。我们的实现专门用 `_BRANCH_ANGLES`（稳妥思路 / 非常规角度 / 排错优先 / 粗估后细化）给每条分支注入不同探索视角，测试 `test_generates_n_distinct_branch_prompts` 断言三条分支提示互不相同。A、B、C 都是 ToT 的正确描述：A 是 CoT 的结构性弱点（单链、错误沿链放大），B 是 ToT 的搜索思想（分支 = 展开候选路径，汇总 = 评估 + 选择），C 是它的代价（我们的测试精确断言调用数 = n + 1）。

## 第二部分：判断题

### 第 4 题

**对。**

提示词在 Agent 系统里同时是"程序"（模型执行的条件逻辑）、"配置"（定义语气与边界）和"代码"（多人协作、改动影响线上行为）。三重身份决定了它必须享受代码级纪律：**版本化**（`PromptTemplate.version`）让每次修改可追溯；**changelog** 回答"当初为什么改"；`PromptLibrary.history()` 支撑回滚；`PromptEvaluator.compare` + `PromptEvalHarness` 把"改版不掉分"固化为上线前的回归门禁。day026 的"模块常量 + 版本注释"是朴素版，day036 的 PromptLibrary 把它正式化为可持久化、可查询的工程制品。

### 第 5 题

**错。**

`render()` **故意不用** `str.format`，而是用正则 `\{([a-zA-Z_][a-zA-Z0-9_]*)\}` 做显式替换：只认 `{合法标识符}` 形式的占位符。提示词里经常出现给模型看的 JSON 示例（`{"k": 1}`），若用 format，所有这类花括号都要转义成 `{{ }}`，模板可读性报废。我们的实现中 JSON 片段自然穿过替换过程不受影响——测试 `test_render_ignores_non_identifier_braces` 用 `'输出 JSON：{"k": 1}，任务 {task}'` 专门守护这个行为，只有 `{task}` 被替换。

### 第 6 题

**错。**

`PromptLibrary` 内部按注册顺序维护 `dict[name, list[PromptTemplate]]`，`get(name)` 不传版本时返回**最后注册**的一版（`versions[-1]`），不做版本号字符串排序。这个设计的含义是：注册顺序即演进顺序，`history(name)` 返回的就是"旧 → 新"的完整时间线，"最新版"等价于"最后注册的版本"。这也要求团队遵守"v1、v2、v3……按序注册"的约定——库的"默认取最新"指针天然就是发布机制。

## 第三部分：问答题

### 第 7 题

（1）**角色**：你是谁、能力边界在哪；**任务**：要完成什么；**上下文**：基于什么信息做（工具清单、检索结果、对话历史）；**格式**：输出长什么样；**约束**：禁止什么、必须什么。

（2）缺"约束"时模型的发挥空间过大：ReAct 场景的典型症状是编造不存在的工具名、同一步既输出 Action 又输出 Final Answer、信息不足时凭记忆编造事实。约束要素把"隐含在示例里的规则"变成"显式的禁止清单"，而 `PromptEvaluator.check_rules` 第 4 条规则（正则 `必须|严格|要求|禁止|不要`）正是对约束要素存在性的机器检查。

（3）`REACT_SYSTEM_PROMPT_V2` 的五要素落位：**角色** = 首行"你是 SmartResearch 智能研究助手，使用 ReAct 范式解决用户的研究与计算任务"；**任务** = "## 任务"段（通过思考-行动-观察循环逐步推进）；**格式** = "## 输出格式"段（Thought/Action/Action Input 与 Final Answer 两种形态）；**约束** = "## 约束"段四条（禁止编造工具、Action 与 Final Answer 二选一、Action Input 非空、禁止凭记忆编造）；**上下文** = 末尾"可用工具：{tools}"——`{tools}` 占位符渲染出的工具清单就是模型行动所基于的信息。v1 → v2 的 changelog 逐条对应五要素缺失症状的修复。

### 第 8 题

1. **新闻翻译 → Zero-shot**。翻译是指令微调后模型的"基本功"，任务简单常见、输出形式无特殊约定，zero-shot 基线即够用，任何额外支架都是浪费 token。
2. **12 标签分类 + 单行 JSON → Few-shot**。这是格式敏感型任务的教科书场景：用自然语言描述"单行 JSON、标签必须是 12 种之一"词不达意，而 2~3 个"反馈文本 → JSON"示例能精确校准输出模式。few-shot 对格式的约束力远强于文字描述。
3. **多步骤奥数题 → CoT**。多步推理是 CoT 的主场：把中间计算落成 token 后，每一步都是简单推理，避免单次前向传播"心算"整道题。正确率提升最显著的就是数学/逻辑类任务。
4. **高代价数据迁移方案 → ToT**。两个特征指向 ToT：错误代价高（值得用 n+1 倍调用成本换鲁棒性）、存在多种合理技术路线（需要并行探索不同路径再汇总裁决）。单链 CoT 一旦开头选错路线就会一路错下去，ToT 的多分支 + 评估择优正是为这种场景设计。

### 第 9 题

（1）模型行为对措辞极其敏感，而 prompt 的修改动机无法从 diff 本身读出——"把『请』改成『必须』"这种改动的理由只存在于修改者的脑子里。三个月后面对"v3 比 v2 效果差"的回归时，changelog 是唯一能回答"当初为什么改"的信息，它等价于代码的 commit message。没有它，版本历史就只是一堆无法决策的字符串。

（2）`compare` 的评委侧是 LLM-as-a-judge，打样本就带着噪声——同一提示词评两次都可能差零点几分。若"差 0.01 分就判胜负"，大量结论会是噪声造成的伪提升/伪回归。`TIE_THRESHOLD=0.05` 是显性的噪声容差：只有分差大到超出噪声量级才采信，这与 A/B 检验里"效应量要大于置信区间"是同一思想。

（3）工作流：① 修改者把新版本注册进 `PromptLibrary`（同 name、新 version、必填 changelog）；② 用 `PromptEvaluator.compare(旧版文本, 新版文本)` 做版本间对比，新版 overall 不低于旧版（或落在平局区间内）才继续；③ 用 `PromptEvalHarness` 跑固化的回归用例（overall >= 阈值的 EvalCase 集合），全绿即上线。"默认取最新版"机制（`get(name)` 返回最后注册版本）就是发布开关：新版本注册完成即自动成为生效版本，回滚等价于重新注册旧版文本为最新版——版本历史完整保留，发布与回滚都是 O(1) 操作。

## 第四部分：编程题

### 第 10 题

参考实现见 `../源码/smart-research-agent/scripts/prompt_techniques_demo.py`，核心结构：

```python
def demo_techniques() -> None:
    llm = MockLLM(responses=[...])  # 6 条脚本化回复：3 技巧 + 2 分支 + 1 汇总
    prompts = {
        "zero_shot": zero_shot(TASK),
        "few_shot": few_shot(TASK, examples),
        "cot": chain_of_thought(TASK),
    }
    for name, messages in prompts.items():
        print(f"[{name}] 回复: {llm.chat(messages)}")

    plan = tree_of_thoughts(TASK, n_branches=2)
    branch_outputs = [llm.chat(msgs) for msgs in plan.branch_messages]
    final = llm.chat(plan.synthesis_messages(branch_outputs))

    first_prompts = [msgs[0].content for msgs in prompts.values()]
    assert len(set(first_prompts)) == 3          # (a) 三技巧提示词互不相同
    assert len(llm.calls) == 3 + 2 + 1           # (b) 总调用 = 6，ToT 占 3 次

def demo_library() -> None:
    lib = PromptLibrary()
    lib.register(PromptTemplate(name="translate", template="把『{text}』翻译成{lang}",
                                version="v1", changelog="初始版本：直接指令式"))
    lib.register(PromptTemplate(name="translate",
                                template="你是专业译者。请把『{text}』翻译成{lang}，只输出译文，禁止解释。",
                                version="v2", changelog="补充角色定义与输出约束（角色/约束两要素）"))
    assert [t.version for t in lib.history("translate")] == ["v1", "v2"]
    assert lib.get("translate").version == "v2"
    rendered = lib.render("translate", text="你好", lang="英文")
    assert rendered == "你是专业译者。请把『你好』翻译成英文，只输出译文，禁止解释。"

    with tempfile.TemporaryDirectory() as tmp:
        path = Path(tmp) / "prompts.jsonl"
        lib.save_jsonl(path)
        loaded = PromptLibrary()
        assert loaded.load_jsonl(path) == 2
        assert loaded.get("translate", "v1").template == "把『{text}』翻译成{lang}"
        assert loaded.render("translate", text="你好", lang="英文") == rendered
```

**踩坑点提示**：

1. **导入路径**：venv 里的包是旧快照的 editable 安装，脚本顶部必须 `sys.path.insert(0, str(Path(__file__).resolve().parent.parent))` 才能导入本快照的 `prompt_library` / `techniques` 模块（与 `scripts/token_budget_demo.py` 同款处理）。
2. **ToT 的两阶段协议**：`synthesis_messages` 必须在拿到全部分支输出之后调用，且输出数量必须等于分支数，否则抛 `ValueError`——这个校验防的就是"汇总时漏了分支"的静默错误。
3. **MockLLM 回复数要备足**：6 次调用（3 技巧 + 2 分支 + 1 汇总）对应 6 条脚本化回复；脚本用尽后会落到 `default` 兜底，不影响断言但输出语义会变差。
