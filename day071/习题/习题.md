## 第一部分：选择题

### 第 1 题（两段召回）

`retrieval_recall = 1.0` 而 `packed_recall = 0.5`。最可能的成因是：

- A. 检索器抓少了一条金标准
- B. **金标准都在检索名单里，但有一条没进提示词（被上下文预算从尾部丢掉）**
- C. 生成器漏掉了半句结论
- D. 索引版本漂移导致少召回

### 第 2 题（指标方向）

下面哪一组指标的"好"的方向是**相反**的？

- A. `retrieval_recall` 与 `retrieval_precision`
- B. `packed_recall` 与 `retrieval_recall`
- C. **`grounded_rate` 与 `hallucination_rate`**
- D. `llm_call_rate` 与 `fallback_rate`

### 第 3 题（neutral 方向）

`llm_call_rate` 被标成 `neutral`（不参与回归判定）。理由是：

- A. 它不重要
- B. 它永远等于 1.0，判也白判
- C. **它下降既可能是护栏生效（检索为空时不调模型），也可能是"该调没调"——硬安方向会制造"看起来像回归、其实是设计"的误报**
- D. 它是描述性指标，不该进基线

### 第 4 题（判定口径）

质量基线用**差值**判定，而性能基线用**比值**判定。质量侧不能照抄比值的最关键理由是：

- A. 差值算起来更快
- B. **`hallucination_rate` 与 `fallback_rate` 的健康基线就是 0，而比值在 0 基数下没有定义——照抄会让"从零变坏"永远不被发现**
- C. 比值只能用于耗时类指标
- D. 差值不需要设置容忍度

### 第 5 题（三档判定）

某指标方向为 `higher_better`，容忍度 0.05，死区 0.02。基线 0.80，当前 0.76。判定是：

- A. `degraded`（掉了 0.04）
- B. **`unchanged`（变化方向是"差"，但 |delta| = 0.04 没超过容忍度 0.05）**
- C. `improved`（|delta| 超过死区）
- D. 无法判定，缺 `k`

### 第 6 题（可比性）

下面哪一项会**阻塞**对比（`conclusive=false`），而不是只作为"自变量"被记下来？

- A. 两次采集的 `prompt_version` 不同
- B. **两次采集的 `index_version` 不同**
- C. 两次采集的用例数不同
- D. 两次采集的标签分布不同

## 第三部分：诊断题

给定五条来自 `CaseOutcome.to_dict()` 的记录（字段名与取值都是真实的：

```json
{
  "retrieved": {"stage": "retrieved", "count": 3, "ids": ["c-1","c-2","c-3"], "recall": 1.0, "ndcg": 1.0},
  "packed":    {"stage": "packed",    "count": 3, "ids": ["c-1","c-2","c-3"], "recall": 1.0, "ndcg": 1.0},
  "empty_reason": "", "llm_called": true, "fallback_reason": "",
  "grounded": true, "coverage": 1.0, "given": 3, "cited": 3,
  "valid_count": 3, "unused_count": 0, "hallucinated": 0,
  "truncated_hits": 0, "dropped_hits": 0,
  "dropped_by_rerank": 0, "dropped_by_top_k": 0
}
```

### 第 11 题（干净用例）

上面这条记录的归因结果是 `None`（不是坏例）。请逐条说明它**为什么**没触发 12 条判据里的任何一条（至少点出六条）。

### 第 12 题（预算丢掉依据）

```json
{
  "retrieved": {"count": 3, "ids": ["c-1","c-2","c-3"], "recall": 1.0},
  "packed":    {"count": 2, "ids": ["c-1","c-2"],         "recall": 0.5},
  "empty_reason": "", "llm_called": true, "fallback_reason": "",
  "grounded": true, "coverage": 0.5, "given": 2, "cited": 2,
  "valid_count": 2, "unused_count": 0, "hallucinated": 0,
  "truncated_hits": 0, "dropped_hits": 2,
  "dropped_by_rerank": 0, "dropped_by_top_k": 0   ← 金标准 2 条：c-1 与 c-3
}
```

请回答：这一条的标签是什么？为什么不是 `retrieval_miss`？它的动作会去动哪个配置项？

### 第 13 题（幻觉引用）

```json

  "grounded": false, "coverage": 0.6667, "given": 3, "cited": 3,
  "valid_count": 2, "unused_count": 1, "hallucinated": 1,
```

请回答：标签是什么？`grounded` 为什么是 false（写出定义）？如果把 `valid_count` 改成 0、`hallucinated` 改成 0，标签会变成什么？

### 第 14 题（生成侧回退）

```json

  "fallback_reason": "llm_error", "grounded": false,
  "coverage": 0.0, "given": 3, "cited": 0, "valid_count": 0, "unused_count": 3,
```

## 第四部分：编程题（必做）

### 第 15 题（跑一次评估并核对 11 个指标）

写一个脚本 `run_eval.py`，要求：

1. 用 `build_suite()` 装载自带评测集与语料；
2. 用 `default_embedding()` 编码、`FlatVectorStore` 建库并灌语料（打印 `WriteReport` 的四个数）；
3. 用一个**自己写的** `BaseLLM` 子类作答（要求：从提示词里**行首**的编号读出片段序号，
   并在答案里逐个引用——直接抄 `scripts/rag_debug_demo.py` 的 `DemoLLM` 也可以，但要写明你为什么锚行首）；
4. 跑 `baseline` 变体，打印 `summary_line()` 与 **11 个指标**的完整读数；
5. 断言 `report.cases == 6` 且 `set(report.to_dict()["metrics"]) == set(QUALITY_METRICS)`。

### 第 16 题（自定义变体 + A/B）

在第 15 题的脚本上加一个变体 `top1`（只把 `top_k` 改成 1），要求：

1. 用 `Variant(name="top1", top_k=1, note="...")` 构造，并说明 `note` 为什么是必填的；
2. 在同一份库上跑 `baseline` 与 `top1`，用 `compare_variants` 给出逐指标差值；
3. 打印发生变化（`improved` / `degraded`）的指标，**并解释这三个数字**：
   - `retrieval_precision` 为什么升到 1.0000；
   - `retrieval_recall` 为什么**没有**下降（给出算术依据：评测集里金标准的条数分布、`k`、名单长度）；
   - 在**什么语料/评测集**下 `retrieval_recall` 会下降（举一个具体例子）。

### 第 17 题（验证门禁的三档判定与"不下结论"）

写一个脚本 `verify_guard.py`，只用 `RagBaseline` 与 `RagBaselineGuard`（**不跑任何用例**），要求覆盖四种情形并打印结论：

1. **改善**：`grounded_rate` 从 0.50 → 0.90；
2. **回归**：`hallucination_rate` 从 0.00 → 0.20（注意基线是 0）；
3. **变差但在容忍度内**：`grounded_rate` 从 0.80 → 0.76（容忍度 0.05）；
4. **不下结论**：`k` 从 3 变成 5（或样本数降到 2）；
5. 额外：把第 2 种情形的 `hallucination_rate` 基线改成 0.0 与 0.5 各跑一次，
   说明"0 基数"为什么照样能判（并解释如果照抄性能基线的比值口径会发生什么）。
