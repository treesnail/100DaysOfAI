# day093 习题答案：卷积神经网络 CNN —— 同一组权重，用在每一个位置

> 参考答案。每题都尽量给出"为什么"与"看源码的哪里"。
> 涉及的模块都在 `smart_research_agent/conv_net/` 下。

## 一、速答

**1.** **同一组权重在输入的不同位置被重复使用**。它把参数量从"随图尺寸平方增长"
（全连接：`H·W × 输出维`）降到"只随核尺寸增长"（`C_out·(C_in·k²)`）。
本课的两个数：6×6 图直连 18 维全连接头要 `36×18+18 = 666` 个权重；
一层 `conv(1→2, k=3)` 只要 `2×9+2 = 20` 个。见 `types.CONV_NOTES["weight_sharing"]`
与 `layers.ConvSpec.parameter_count`。

**2.** 是**互相关**（核不翻转）：`y[i,j] = Σ x[i·s+u·d, j·s+v·d]·K[u,v]`。
PyTorch 的 `nn.Conv2d` 也是互相关。约定写在 `ops.conv2d` 的文档串里；
`test_conv_net.py::test_conv2d_is_cross_correlation_not_flipped` 用一个不对称的核钉住了它
（若翻转，那个测试会取到另一个角的值）。

**3.** 只在**步长 1** 且**核为奇数**时精确成立。补边数是 `(d·(k−1))//2`；
偶数核 + 步长 1 会得到 `size − 1`（差一列），因此本包在 `resolve_padding` 里**验算**
输出尺寸是否等于输入，不等就抛 `WindowError`。见 `ops.resolve_padding`。

**4.** 因为"丢掉最后一块"**不会报错**，只会让**实际下采样率与你以为的不同**——
而下游所有"特征图尺寸"的推导都会随之错位（例如 `flatten` 的宽度、
`dense` 的输入维、`unflatten` 的形状表）。本包要求窗口整除地盖满，否则抛 `WindowError`
（`ops.pool2d`）。

**5.** 可以理解为一次**全连接式的混合**：`C_in` 个通道 → 1 个通道，
每个输入通道配一张核（权重），求和后加偏置、过激活。见 `layers.conv_block_forward`。

**6.**

```text
d_kernel   与 kernel 同形（k_h × k_w）
d_bias     与 bias 相同（每个输出通道一个标量）
d_image    与 image 同形（原图尺寸）
```

**7.** **形状完全正确**（`dK` 还是 `k×k`、`dX` 还是原图大小），只是**数值全错**。
最早发现它的是 day074 的**数值差分**（第 ⑤ 条性质
`conv_backward_matches_numerical`，实测读数 `1.579e-10 <= 1e-9`）——
因为它是唯一一把**独立于这段推导**的尺子。

**8.** 本课**真的**算了卷积的梯度，也真的与数值差分对了一次账；但**没有**把"对不上"
做成一个控制流事件——对账发生在确定性样本上，结论写进性质表。
而 day090 抛 `GradientError` 是因为"训练不可信"必须**当场停下**。
区分是"运行期守卫"与"离线校验"。见 `errors.ABSENT_FAMILY_REASON`。

## 二、连线

**9.**

| 算子 | 职责 |
|------|------|
| `output_size` | b. 只接受整数补边，算一次尺寸公式 |
| `resolve_padding` | a. 把 valid / same / 整数解析成具体补边数 |
| `feature_size` | e. 解析填充之后再套尺寸公式（调用方不用自己解析） |
| `pad2d` | f. 对称常量补零 |
| `conv2d` | c. 单通道互相关 |
| `receptive_field` | d. 逐层递推感受野 |

`resolve_padding`（解析）与 `output_size`（计算）是分工的两半；`feature_size` 是它们的**接缝**——
正是把"字符串填充"与"整数补边"这两件事收到一处的那个函数。

## 三、对照计算

**10.** 公式 `out = ⌊(H + 2p − d·(k−1) − 1)/s⌋ + 1`，H=6、k=3：

```text
s=1, p=0, d=1   ⌊(6 + 0 − 2 − 1)/1⌋ + 1 = ⌊3⌋ + 1 = 4
s=1, p=1, d=1   ⌊(6 + 2 − 2 − 1)/1⌋ + 1 = ⌊5⌋ + 1 = 6
s=2, p=1, d=1   ⌊(6 + 2 − 2 − 1)/2⌋ + 1 = ⌊2.5⌋ + 1 = 3
s=1, p=1, d=2   ⌊(6 + 2 − 4 − 1)/1⌋ + 1 = ⌊3⌋ + 1 = 4
```

与 `study.size_rows()` 的读数一致。

**11.** 通道 0 全零，是因为**那一张核恰好没被这根竖线激活**：卷积输出在整张图上
都是负的（或 0），ReLU 把它们全部压成 0。这说明**每张核是一个"检测器"**：
它只对某种局部模式响应；没有响应时那一张特征图就是全零。
"多通道"的意义正是**同时装若干个检测器**——有的对竖线响应、有的对横线响应。
（`study.feature_rows` 第 ④ 张表。）

**12.**

```text
两层 3×3   感受野 = 3 + (3−1)×1 = 5；参数 = 2 × 9 = 18
一层 5×5   感受野 = 5；            参数 = 25
```

**两层更划算**：感受野相同，参数更少（18 < 25），而且中间多了一次非线性——
这正是"小核堆深"（VGG 那类设计）的两个直接理由。见第七章与 `study.field_rows`。

## 四、诊断

**13.** 原因：`output_size` 的职责是"算一次公式"，它**只接受整数补边**；
而调用点把 `spec.padding = "same"` 直接喂了进去。修法是本课新增的
`ops.feature_size`：**先 `resolve_padding` 解析、再 `output_size` 计算**，
把这个接缝收到一个函数里，而不是在每个调用点各解析一次。
（本课真的撞到了这个坑：`network.pooled_size` 最初就是这样报错的。）

**14.** 两个可能：

```text
可能一：梯度算对了，但参数被装错了位置（压平/还原的顺序不一致）
        发现者：unflatten_params 的长度检查（ShapeError）；顺序一致性由
        flatten_params / flatten_gradients 的**同一顺序**保证
可能二：把 dK 与 dX 写反了（形状仍然正确，数值全错）
        发现者：第 ⑤ 条性质 conv_backward_matches_numerical（数值差分）
```

注意"loss 停在 0.69 附近"（≈ ln 2）等于"模型输出接近均匀分布"，
即梯度信号确实存在但没能把参数推向可分的方向——这两类错误都会产生这个现象。

## 五、推导

**15.** 一个输出通道要"看"全部 `C_in` 个输入通道，每对配一张 `k_h × k_w` 的核，
因此卷积核的总元素数是 `C_out·(C_in·k_h·k_w)`；再加每个输出通道一个偏置 `C_out`。
所以：

```text
params = C_out·(C_in·k_h·k_w) + C_out

C_in=3, C_out=8, k=3：
    8 × (3 × 3 × 3) + 8 = 8 × 27 + 8 = 216 + 8 = 224
```

**16.** 递推 `r ← r + (k−1)·∏s`，从 `r₀ = 1`、`∏s` 初值 1 出发：

```text
第一层： r₁ = 1 + (3−1)×1 = 3； ∏s 变成 1×1 = 1
第二层： r₂ = 3 + (3−1)×1 = 5； ∏s 变成 1
⇒ 感受野 = 5
```

区间传播（从输出的一格往回推）：

```text
初值 [0, 0]
往回第一层（k=3, s=1）： [0×1, 0×1 + 2] = [0, 2]
往回第二层（k=3, s=1）： [0×1, 2×1 + 2] = [0, 4]
感受野 = 4 − 0 + 1 = 5   ✔ 两条路径一致
```

`verify.check_receptive_field_matches_direct` 用的就是这套区间传播。

## 六、情景题

**17.** **不成立**。权重共享的假设是"同一个特征在任何位置含义相同"；
而表格截图里"表头 / 行标签 / 数据格"的语义**随位置变化**。
改法有两条：

```text
① 在全连接层之前把**位置信息**加回去（例如位置编码 / 把行列索引作为额外特征）——
   这正好呼应 day092 之后 day095 的"训练技巧"与 M7 的位置编码一整块；
② 直接用**全连接**处理"位置即语义"的输入（本课的第二章结尾就写了这条边界：
   对"每个位置含义都不同"的数据，卷积的假设不再合适）。
```

如果一定要用卷积，通常是"卷积抽局部纹理 + 位置特征拼接"的混合结构，
而不是让卷积独自承担"定位"。

**18.** **不会改变数值结果**。可以保证这一点的性质是第 ① 条

```text
conv_matches_sliding_dot：ops.conv2d 的输出与手写滑窗点积逐位一致
```

它足够，因为它把 `conv2d` 钉在**定义本身**上：任何"新的实现"只要仍然等于
"滑窗点积"这个定义，就与旧实现逐位相同。im2col + 矩阵乘只是同一个求和的
另一种求值顺序（数学上是同一个和式），因此改动只影响**速度**，不影响**数值**。
（若新实现对浮点求和顺序做了重排，会有最后几位比特的差异——那属于浮点误差，
不是这一课讨论的"对/错"。）
