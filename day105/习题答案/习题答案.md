## 一、速答

**1.** 一条常量是**模块级作用域里的一次 `UPPER_CASE = 单个 Name 目标` 赋值**（当前快照 2430 条）。
三种"看起来像常量、本课却不收"的写法：

```text
DELTA, EPS = 1, 2        不收：解包赋值——一个右端对两个名字，取值说不清该记给谁
lower = 1 / _PRIVATE = 1 不收：不是全大写 / 以 _ 开头，它们不是"被钉死的常量"
def f(): INSIDE = 1      不收：不在模块级作用域——它是那一层的实现细节
```

另外 `class C:` 里的 `KAPPA = 9` 也不收，理由与第三种相同。

**2.** `literal` 是**可以用 `ast.literal_eval` 求出值**的那一类（如 `EPSILON = 1e-5`、`NAMES = ("a","b")`）；
`opaque` 是**求不出来**的那一类（如 `ROOT = Path(__file__).resolve().parents[2]`、f-string、函数调用）。
它们必须分开记，因为：

> 如果不分开，把 `opaque` 当成"空值"去和别的模块比，会让两个**根本无关**的常量"看起来一致"。

这正是 day102 那条纪律（"四类归属里必须有一类是'我承认我不知道'"）在本课的形态。

**3.** 判定顺序写死为：

```text
① 成员只来自一个模块              ⇒ unique
② 有成员是 opaque                 ⇒ incomparable（**拒绝下结论**）
③ 所有字面值只有一个              ⇒ consistent
④ 否则                            ⇒ conflict
```

不能换顺序的理由：**先判"能不能比"，再判"比出来是什么"。**
若把 ② 与 ③④ 换位，per-opaque 的常量会被拿去作相等比较，于是"我算不出来"被读成"它们对不上"。

**4.** 因为**同名不同值本身不是错误**：现场读数里 38 组同名不同值中，
`DEFAULT_BATCH_SIZE`（2 / 32 / 8 …）、`DEFAULT_ALPHA`（0.5 / 0.99 …）这类差异是
"每个包给自己的模型挑了一个合理的参数"，`FAMILY_OUTCOMES` 这类差异是
"每个包各写一份自己的处置表"。

一条"同名必须同值"的性质会在**仓库合理地变化**时变红（多一个包、多一个参数），
然后一定会被人关掉——而一条被关掉的性质，等于不存在。
本课给它留的出口是 `ledger.require_consistent(ledger)`：

```text
调用点**显式**要求"这些同名常量必须一致"时，它才抛 ConflictError（拒绝交付）。
```

**5.** 独立复核走的是**源码片段**这条路（`parse.value_segments`）：
把该名字在每个成员模块里的**右端源码**取出来、去掉空白，这一组必须至少有两种不同片段。
两条路各自看的是：

```text
fingerprint(node)          看"这条赋值**求出来**是什么"（AST → literal_eval → 规范化字符串）
value_segments(path)       看"这条赋值**写的是什么**"（AST → get_source_segment → 折空白）
```

它能抓住的错误是：**取值指纹算错了**（比如少了排序归一化、或误把某个字面量当成 opaque）。
那时台账会报出一组"实际相同"的假冲突，而源码片段复核会立刻发现它们一模一样。

**6.** 回来的族是 `ShapeError`（`RETURNED_FAMILY`）：它由 day075 第一次命名，
是 day102 那份台账里跨包重名之最；day103 / day104 都没有它，
本课换了一个对象（取值）却问同一个问题："同一个名字在不同包里长成了什么形状？"
缺席的族是 `GradientError`（`ABSENT_FAMILY`）：本课是纯静态分析，连一次 import 都不执行。

## 二、对照

**7.** 同一句话的四条：① 覆盖（day104 是"每个 `.py` 都在清单里"，本课是"每个 `.py` 都在台账里"）、
② 可复算、以及"报出来的东西是不是真的"（day104 是"幽灵是不是真的"与"重名表是不是真的"，
本课是"冲突是不是真的"与"同名表是不是真的"）。
本课**特有**的一条：⑤ 同一模块里不重复给同一个常量名赋值。
两条下界（⑥ 常量数、⑦ 同名组数）在**对象**上与 day104 不同（承诺数 / 重名数），
但**形式**相同——这就是这一系列"七条性质、三类判据"的稳定骨架。

**8.** 是同一条纪律：**把并列 / 未固定的顺序显式消掉，让"两次运行逐位相同"成为一条 `==`。**
本课防的具体容器是 **`set` / `frozenset`**：

```text
day101  防的是 dict 插入序（倒排表的文档名必须排序）
day102  防的是集合序（族按"包名升序 × 源码顺序"排）
day103  防的是排序键并列（sorted(key=len) 在等长候选上回到 set 的迭代序）
day104  防的是集合序 + 绝对路径
day105  防的是 set / frozenset 的 repr——它藏在一个"看起来完全合理"的 repr 里
```

**9.** 两条产物的**问题**不同、**材料口径**不同：

```text
day104  symbol_catalog    问题：承诺了什么 / 落到了哪里   材料：模块级的 __all__ 与 def / 赋值 / import 别名
day105  constant_ledger   问题：把哪个名字钉成了什么值     材料：模块级的 UPPER_CASE = 单个 Name 目标
```

`ABSENT_FAMILY` 在 day104 里是一个**承诺**（写在 `__all__` 里、且在本模块里有落点），
在本课里它是一条**取值**（每个包写成 `"GradientError"` 或 `None`），
于是它在 day104 的角度是"一个被很多模块导出的名字"，在本课的角度是"一组同名不同值"。
**同一个名字、两条口径、两个结论都对**——它们回答的不是同一个问题。

## 三、诊断

**10.** "不成立 3 个"的三种可能原因：

```text
① 取值指纹算错了        本该相同的两条赋值被算成不同（例如忘了给集合作归一化） ⇒ 改 canonical_value
② 源码片段取错了        片段为空 / 取了错误的语句（如段落被注释掉） ⇒ 改 value_segments
③ 源码真的写错了        两个模块的同名常量确实不同 ⇒ **这是正确报警**，改数据或改调用
```

**11.** 删掉排序归一化后，下面的常量会让摘要在两次运行之间**漂移**：

```python
LETTERS = {"a", "b", "c"}
```

`literal_eval("{'a','b','c'}")` 给出的是一份 `set`，而 `set` 的迭代序随 `PYTHONHASHSEED` 变化，
于是 `repr` 也随之变化。现象很具体：台账照样编得出来、同名表照样算得出来，
**只有第 ② 条性质（两次构建逐位相同）会被它顶破**——
而且是"同一台机器、同一个输入、两个摘要"，比跨机器不一致更难发现。

**12.** 因为两处都在表达同一个约定：**同一个名字的最后一条赋值，就是它在该模块里的最终取值**
（Python 在导入期就是这么做的）。`value_segments` 用覆盖写实现"最后一条算数"，
`primary_of` 用 `rows[-1]` 实现同一件事。
若两处取的不是同一个定义（例如 `value_segments` 取第一条、`primary_of` 取最后一条），
第 ③ 条性质就会**拿 A 条的源码**去复核**B 条的取值**：一组真冲突会被报成假冲突
（或反之），而两边的读数都"看起来对"。

**13.** 对

```python
EPSILON: float = 1e-5
EPSILON = 1e-6
```

① 本课记下 **2 条**常量定义（一 `AnnAssign`、一 `Assign`，同一名字、不同行号）；
② `primary_of("EPSILON")` 给出**第二条**（`EPSILON = 1e-6`，行号更大）；
③ 第 ⑤ 条性质读的是 `ModuleConstants.duplicate_names()` → 这个名字出现两次 ⇒ 它进
`duplicate_modules()` ⇒ 第 ⑤ 条（上界 0）**当场变红**。
这正是"读的人不知道台账该记哪一个数"的那种含糊——本课不替它挑一个，而是把它点出来。

## 四、推导与动手

**14.** 给定 `pkg.a`（`EPSILON = 1e-5`、`BATCH = 8`）、`pkg.b`（`EPSILON = 1e-5`、`BATCH = 32`）、
`pkg.c`（`ROOT = Path(__file__)`、`EPSILON = 1e-5`）：

```text
① 关系类别：
     EPSILON  三个模块、能比较、值只有一个  ⇒ consistent
     BATCH    pkg.a 与 pkg.b 能比较、值有两个 ⇒ conflict
     ROOT     只在一个模块里                 ⇒ unique
② shared_groups() 有 2 个名字（EPSILON、BATCH）
③ conflicts() 有 1 个名字（BATCH）
④ 性质 ⑥：这份小台账只有 4 条常量，读数 4 < 下界 500 ⇒ **当场地、正确地变红**。
   它的阈值定在"这批文件必然成立"的地方，本来就**不是**为小样本准备的。
   （一旦某组同名常量里出现了 opaque，那一组的关系会从 conflict / consistent 变成 incomparable。）
```

**15.** 结论：`duplicate_names()` 与"跨模块"无关，它只可能来自**同一个模块内的重复写入**。
证明：

```text
ModuleConstants 的两条护栏保证了：
  (a) constants 的（名字, 行号）键排序且不重复；
  (b) 每一条定义的 module 都等于本行的 module。
于是"同一行里同一个名字出现两次"必然落在两行不同的源码上（行号不同 ⇒ 键不同 ⇒ 不违反 (a)）；
而"另一个模块里的同名"因为 (b) 根本进不来。
因此 duplicate_names()（count > 1）只能来自同一个模块里同一个名字被写了两行。□
```

**16.** 五行以内：

```python
from smart_research_agent.constant_ledger import build_ledger
ledger = build_ledger()
print("同名组", len(ledger.shared_groups()))
print("冲突组", len(ledger.conflicts()))
```

**17.** 一条新的**上界**性质（示例）：

```text
id         opaque_ratio_within_ceiling
判据       upper_bound
描述       读不出取值的常量占比 <= 0.25（读数 = opaque_count / constant_count()）
失败意味着 这份台账里"说不清取值"的常量太多——它能比较的部分太少，
           同名表里会出现大片的 incomparable，于是"同名不同值"这条读数会被稀释掉。
```

阈值取 0.25 是一条**有方向**的界：它是"越少越好"的量，所以只能用上界；
写成 `==` 会在仓库写入一批 `Path(__file__)` 常量时误报失败。
（当前快照读数是 582 / 2430 ≈ 0.239——**它离这条界并不远**，这正是上界该在的地方。）

**18.** 本仓库里"是读数、不是失败"的例子（至少一个即可）：

```text
day103  模块级的依赖图有 4 个环（含 api ↔ tools 那个跨包环）：环是**读**出来的，不是**删**掉的。
day102  18 个子包没有 errors.py：这是"这一族的覆盖情况"，不是"这些子包错了"。
day104  1 个幽灵导出（STAGE_ITEMS）：它是一条**要被修**的读数，而不是"引擎必须自证清白"的性质。
day105  38 组同名不同值：其中大部分是"每个包给自己的模型挑了一个合理的参数"。
```

判断标准可以写成一句话：
**当这个现象是"仓库的真实状态"、而不是"工具算错了"时，它就该被印出来；
只有当它是"工具自己算错了"时，才该让一条性质当场变红。**
