## 今日目标

## 第一章：从"每个位置一个权重"到"一组权重走遍全图"

### 1.1 day089 到 day093 的那句话

```text

```

## 第二章：权重共享 —— 到底省了多少参数

### 2.1 两个数摆在一起

```text
6×6 的图直连 18 维全连接头     36 × 18 + 18 = 666 个权重
一层 conv(1→2, k=3, same)      2 × 9 + 2   = 20 个权重
```

`study.layer_rows()` 印出的正是后者：

```text
conv(1→2, k=3, s=1, pad=same, act=relu) | 参数 20 | 输出 2×6×6
```

**少了 33 倍**。这不是靠"更小的网络"换来的：输出仍然是 2 通道 × 6 × 6 = 72 个数，
只是产生它们的参数从 666 变成了 20。省下的全部来源就是那一句：

> 同一组核，被用到了全图的**每一个位置**。

### 2.2 参数量公式

```text
params = C_out·(C_in·k_h·k_w) + C_out
```

后一项是偏置（每个输出通道一个）。注意它**与图的大小无关**——
这是卷积能与大图共处的根本原因。实现见 `types.CONV_PARAM_FORMULA` 与
`layers.ConvSpec.parameter_count`。

### 2.3 代价是什么

权重共享不是免费的午餐，它同时带来一个**假设**：同一个特征在图的任何位置都应有同样的含义。
对图像这是对的（一条竖线在左边还是在右边，都是竖线）；对"每个位置含义都不同"的数据
（例如一个表格的每一列有不同语义），它就不再合适——那时该用全连接。

## 第三章：算子层 —— 先算尺寸，再谈别的

### 3.1 尺寸公式

```text
out = ⌊(H + 2p − d·(k−1) − 1)/s⌋ + 1
```

`study.size_rows()` 在 6×6 输入上给出五组读数：

```text
k=3 s=1 p=0 d=1 | 6 → 4
k=3 s=1 p=1 d=1 | 6 → 6
k=3 s=2 p=1 d=1 | 6 → 3
k=2 s=2 p=0 d=1 | 6 → 3
k=3 s=1 p=1 d=2 | 6 → 4
```

公式里有四个可以调的旋钮（核 k、步长 s、填充 p、膨胀 d），而这四个旋钮都会改变
"下一个像素看多远"。因此本包把它放在 `ops.output_size` 里**只写一遍**，
所有别的函数都调用它（第 ④ 条性质就是拿它与实际形状对账）。

### 3.2 接缝：`output_size` 与 `spec.padding`

`output_size` 只接受**整数**补边（它的职责是"算一次公式"）；而实际调用点拿到的
往往是 `spec.padding`（可能是字符串 `"same"`）。两者的接缝放在 `ops.feature_size` 一处：

```python
def feature_size(size, kernel, *, stride=1, padding=PADDING_VALID, dilation=1):
    pad = resolve_padding(size, kernel, stride=stride, padding=padding, dilation=dilation)
    return output_size(size, kernel, stride=stride, padding=pad, dilation=dilation)
```

这个函数是这一课**真的撞到的第一个坑**：最初的 `pooled_size` 直接把 `spec.padding="same"`
喂给了 `output_size`，于是 `build_cnn` 在建网时就抛了 `ParameterError`。
修法不是"在调用点各解析一次"，而是把接缝收到一个函数里。

### 3.3 互相关 vs 卷积：一个必须写下来的约定

深度学习里的"卷积"实际是**互相关**（cross-correlation）：核**不翻转**。

```text
y[i,j] = Σ_{u,v} x[i·s + u·d, j·s + v·d] · K[u,v]
```

PyTorch 的 `nn.Conv2d` 也是互相关。本包沿用这个约定——否则"核要不要翻转"会成为一个
永远说不清的分歧。

### 3.4 `same` 只在奇数核、步长 1 时精确成立

`same` 的补边数是 `(d·(k−1))//2`。解析之后本包会**验算**输出尺寸是否等于输入；
偶数核 + 步长 1 会得到 `size − 1`，于是当场抛 `WindowError`：

```text
resolve_padding(6, 3, padding="same")  → 1     ✔
resolve_padding(6, 2, padding="same")  → WindowError（偶数核没有解）
resolve_padding(6, 3, stride=2, ...)   → WindowError（same 要求步长 1）
```

## 第四章：多通道 —— 在通道维再做一次加权求和

### 4.1 一个输出通道是怎么来的

```text
对每一个输出通道 c_out：
    y = Σ_{c_in} conv2d(x[c_in], K[c_out][c_in]) + b[c_out]
    y = activation(y)
```

"通道维上的加权求和"就是一次**全连接式的混合**：`C_in` 个通道 → 1 个通道。
这也是为什么 `ops.conv2d` 只做单通道——多通道只是把单通道的结果按不同的核加起来
（`layers.conv_block_forward`）。

### 4.2 形状约定与 PyTorch 对齐

```text
kernels[o][i]  就是 torch 的 weight[o, i]（一张 k×k 的核）
bias[o]        就是 torch 的 bias[o]
```

`ConvParams` 在构造时就检查"每个输出通道都对**全部**输入通道各有一张核"——
少一张会抛 `ShapeError`，否则那一层的输出会静默地少一项贡献。

## 第五章：池化 —— 降采样，且窗口必须整除地盖满

### 5.1 两种池化

```text
max   窗口取最大值   保留最强的响应（对微小平移不敏感）
avg   窗口取均值     保留整体强度（对噪声更平滑）
```

`study.pool_rows()` 在同一次 6×6 输入上给出两行：

```text
max  | 3×3 | 均值 +0.333333
avg  | 3×3 | 均值 +0.166667
```

两者都把 6×6 降成 3×3（下采样 2 倍），差别只在"保留了窗口里的什么"。
在"竖线"这张图上，max 把那条线保留得更亮（均值被周围的 0 拉低），
这正是 max 池化对**稀疏特征**更友好的直观原因。

### 5.2 为什么拒绝"丢掉最后一块"

"6×6 的图按 2×2、步长 3 下采样"会得到 `(6−2)/3 + 1 = 2.33` 个窗口。
"取前 2 个、把 0.33 丢掉"不会报错，只会让**实际下采样率与你以为的不同**——
而下游所有"特征图尺寸"的推导都会随之错位。因此本包要求窗口**整除地**盖满输入，
否则抛 `WindowError`。

## 第六章：特征图 —— 一次卷积之后看到了什么

### 6.1 特征图的画像

`study.feature_rows()` 用 `ops.feature_stats` 给每张特征图印一行"画像"
（形状 / 均值 / 最大值 / 非零比例）：

```text
通道 0 | 6×6 | 均值 +0.000000 | 最大 +0.000000 | 非零 0.000
通道 1 | 6×6 | 均值 +0.140565 | 最大 +0.389712 | 非零 0.972
```

**通道 0 整张全零**——那一张核恰好没被这根竖线激活，ReLU 把它压平了。
这是理解卷积的一个关键：**每张核是一个"检测器"**，它只对某种局部模式响应；
没有响应时，那张特征图就是全零。多通道的意义正是"同时装若干个检测器"。

### 6.2 特征图是本项目里 CNN 的位置

在「智研 AI 助手」这条主线上，CNN 的位置是**视觉预处理**：
把图像变成特征，再交给上层的 Agent。这与 day040 的 `ImageAnalysisTool`
（把图像交给视觉-语言模型）是一个栈里的两层——一层是"我们自己的卷积看起来像什么"，
一层是"交给外部大模型看图"。本包把前者做成可对账的最小实现。

## 第七章：感受野 —— 为什么两层 3×3 等于一层 5×5

### 7.1 递推公式与读数

```text
r₀ = 1；r ← r + (k − 1)·∏s
```

`study.field_rows()` 同时印出公式与"逐层区间传播"两条路径：

```text
一层 3×3              | 感受野 3 | 区间传播 3
两层 3×3              | 感受野 5 | 区间传播 5
三层 3×3              | 感受野 7 | 区间传播 7
两层 3×3 + 池化 2×2   | 感受野 6 | 区间传播 6
```

最后一行说明池化**不只看窗口内的数**：它把每个输出的感受野乘上了自己的步长
（2×3 = 6）——这就是"堆几层之后一个输出能看到整张图"的机制。

### 7.2 参数对比：为什么小核堆深更划算

```text
两层 3×3    感受野 5×5    参数 2 × 9 = 18
一层 5×5    感受野 5×5    参数 25
```

感受野相同，**两层小核的参数更少**，而且中间多了一次非线性——这是 VGG 那类
"用 3×3 堆深"的设计的两个直接理由。

### 7.3 区间传播为什么值得单独写一遍

`verify.direct_receptive_field` 用的是一条**完全不同的路径**：

```text
区间初值 [0, 0]（输出的一格只看输入的 0 号位置）
每往回一层： new_start = start·s；new_end = end·s + (k−1)
感受野 = new_end − new_start + 1
```

闭式递推与区间传播是同一件事的两种算法；第 ⑦ 条性质断言它们给出同一个整数。
**自证是不成立的**：一条公式自己算两遍不算对账。

## 第八章：反向 —— dK / dB / dX，两块最容易写串的梯度

### 8.1 三块梯度的形状口诀

```text
d_kernel   与 kernel 同形   每个核元素被用到的次数（加权和）
d_bias     与 bias 相同     这个输出通道被用到的总强度
d_image    与 image 同形    每个输入位置对损失的贡献（所有输出位置累加）
```

实现是最朴素的"按定义累加"（`gradients.conv2d_backward`）：不用 im2col、不做向量化——
这一课要的是**每一个索引都对得上**，而不是速度。

### 8.2 为什么这是这一课的命门

`d_kernel` 与 `d_image` **互为"转置"**：

```text
d_kernel[u,v] = Σ_{i,j} grad_out[i,j] · x_pad[i·s+u·d, j·s+v·d]
d_image ...   = Σ_{u,v} grad_out[i,j] · K[u,v]        （把 grad_out 散布回输入位置）
```

把两者写反，**形状仍然完全正确**——`d_kernel` 还是 `k×k`、`d_image` 还是原图大小。
唯一能发现它的是**一把独立于这段推导的尺子**：day074 的数值差分。

```python
# verify.check_conv_backward_matches_numerical 的核心
numeric = gradient(objective, flat_start)          # day074 的尺子
analytic_kernel, analytic_image = conv2d_backward(...)  # 本包的推导
```

实测读数：

```text
通过 conv_backward_matches_numerical | 读数 1.579e-10 <= 1.0e-09
```

`1.579e-10` 是解析梯度与数值差分在 9 个核元素 + 16 个图像元素上的最大绝对差——
它落在中心差分的分辨率之内（相对误差约 1e-10，与 day090 同一量级）。

### 8.3 激活的反向导数不重写

卷积块里的激活（relu / gelu / sigmoid / tanh）的导数**只有一份**，写在 day090 的
`backprop.gradients`。本模块直接调用 `backprop.gradients.elementwise_backward`：

```python
d_pre = tuple(
    backprop_gradients.elementwise_backward(spec.activation, pre, grad)
    for pre, grad in zip(pre_activations, grad_outputs)
)
```

因此 `conv_block_backward` 需要前向时**激活之前**的值（`pre_activations`）。
缺了就抛 `BackwardError`——**relu 的导数必须知道这一格原来是正是负**，
少了这份缓存只能重跑一次前向。

## 第九章：一个小 CNN 的完整链

### 9.1 结构写死

```text
1×6×6 → conv(1→2, k=3, same, relu) → maxpool(2) → flatten(18) → dense(18→2) → logits
```

三个接缝都在 `network.py` 里被钉住：

```text
① 卷积与池化    conv 的输出（含 pre_activation 缓存）直接喂给池化
② 池化与全连接  池化后的每张特征图按行优先压平、通道序拼接 ⇒ dense 的输入
③ 反向          dense 的 d_flat 拆回各通道 ⇒ 逐通道池化反向 ⇒ 卷积反向
```

### 9.2 参数压平：day090 的契约第一次被真正用上

```text
flatten_params 的顺序（写死）：
    conv.kernels[o][i] → conv.bias → head_weight → head_bias
unflatten_params 用**参数本体当形状表**（template）
```

day092 的 `TrainingOptimizer` 的更新公式是**逐分量**的（`θ ← θ − lr·…`），
与"参数是不是卷积核"无关。于是"优化器第一次遇到卷积"这件事，只差一次压平与还原：

```python
flat_params = flatten_params(params)
flat_grads = flatten_gradients(grads)
updated = optimizer.step(flat_params, flat_grads)
params = unflatten_params(updated, template=params)
```

`unflatten_params` 在长度对不上时抛 `ShapeError`——而不是"按顺序切"：
后者会给出若干"形状正确、数值错位"的参数，而它们会让 loss 停在某个不动的高位，
看起来像"学习率不对"。

## 第十章：训练一次 —— 合成"竖线 vs 横线"

### 10.1 为什么用合成数据

```text
① 可复现    图像由 LCG 生成 ⇒ 每一次训练曲线都逐位相同
② 可判定    "竖线 vs 横线"是局部纹理差异，卷积核恰好能学到方向性
```

每一步都是**全批量**（把整个小数据集的梯度求平均再走一步）：数据集只有 8 条，
全批量既便宜又稳定——它先把"单样本 SGD 的抖动"这个与卷积无关的变量消掉，
让这一课的读数只在讲"卷积学没学会"。

### 10.2 读数

```text
200 步 | 损失 7.672e-01 → 1.288e-04（↓100.0%）| 准确率 100.0% | adam
step   1 | loss 0.767182
step  51 | loss 0.000617
step 101 | loss 0.000276
step 151 | loss 0.000182
step 200 | loss 0.000129
```

起点损失 `0.767` 略高于 `ln 2 ≈ 0.693`（初始参数把两个类分得比随机还差一点），
50 步之内就掉到 `6e-4`。**梯度来自本包的解析反向，优化器来自 day092**——
两条独立的实现第一次在同一个回路里合上了。

> **必须写下来的边界**：这是一个**单层卷积 + 2×2 池化 + 小全连接头**的最小网络，
> 数据集只有 8 条合成样本。它证明了整条链"跑通、可对账、可复现"，
> 不证明"这个网络在真实图像上有多好"——那需要更大的网络与更多的数据（day095 / day096）。

## 第十一章：七条性质与七张表

### 11.1 七条性质

```text
通过 conv_matches_sliding_dot            | 读数 0.000e+00 == 0       | ops.conv2d vs 手写滑窗点积
通过 conv_is_linear                      | 读数 0.000e+00 <= 1.0e-12 | conv(αx+βy) vs α·conv(x)+β·conv(y)
通过 same_padding_preserves_size         | 读数 0.000e+00 == 0       | conv2d(padding=same) vs 输入 4×4
通过 output_size_formula_matches_shape   | 读数 0.000e+00 == 0       | 实际形状 vs 输出尺寸公式
通过 conv_backward_matches_numerical     | 读数 1.579e-10 <= 1.0e-09 | conv2d_backward vs 数值差分
通过 pool_returns_window_extreme         | 读数 0.000e+00 <= 1.0e-12 | pool2d 输出 vs 窗口极值 / 均值
通过 receptive_field_matches_direct      | 读数 0.000e+00 == 0       | 递推 = 10 vs 区间传播 = 10
```

判据两类：**相等**（逐位 / 整数）与**不超过上界**（误差）。本课没有"下界"判据——
因为这一课没有"两个东西必须不同"的断言，它的每一条都在问"这个对不对"。

### 11.2 七张表

```text
① 层表       一层的画像：通道 / 核 / 步长 / 填充 / 激活 / 参数 / 输出尺寸
② 尺寸表     尺寸公式在五组 (k, s, p, d) 上的读数
③ 感受野表   递推公式 vs 区间传播
④ 特征图表   一次卷积之后每张特征图的画像（通道 0 全零是最有信息量的一行）
⑤ 池化表     max / avg 在同一次输入上
⑥ 训练表     合成数据集上真训练一次：损失曲线 + 准确率
⑦ 性质表     七条性质的标准读数
```

每张表的每一行都带**两个数**（读数 + 参照）——一行只写"通过"的表是没法反驳的。

## 第十二章：失败族与那条纪律

### 12.1 五个族，按"该谁去修"分

```text
ShapeError       形状不符      输入 / 核 / 输出尺寸对不上           → 改调用
ParameterError   参数越界      核 / 步长 / 填充 / 膨胀 / 窗口非法    → 改调用
NumericError     数值不可用    nan / inf 混进特征图                 → 改数据或改实现
WindowError      窗口不成立    池化窗口盖不满输入                   → 改窗口 / 步长
BackwardError    反向不成立    梯度与缓存不是同一次前向              → 改调用
```

`WindowError` 独立成族的理由是**时机**：形状合法，但"窗口与步长的组合"让最后一块越界。
把它与 `ShapeError` 混成一族，会让"下采样率与预期不同"被误诊成"图喂错了"。

### 12.2 GradientError 第三次缺席——理由又换了一条

```text
day082~089   没有手写反向              ⇒ 连续缺席八天
day090       有手写反向 + 自动微分      ⇒ **回来了**
day092       消费梯度、不计算梯度        ⇒ 再次缺席（梯度被交给了上一步）
day093       算了梯度，但对账是离线校验  ⇒ 第三次缺席
```

本课**真的**算了卷积的梯度，也**真的**与数值差分对了一次账（第 ⑤ 条性质）。
但它**没有**把"对不上"做成一个控制流事件：对账发生在确定性样本上，
它的结论写进性质表，而不是改变控制流。

```text
day090 抛 GradientError   因为"训练不可信"必须当场停下
day093 记进性质表          因为这是一次离线校验，不是一个运行期守卫
```

这条区分写进了 `errors.ABSENT_FAMILY_REASON`，并被 `test_conv_net.py` 逐字断言。

## 结语：三条工程线索

1. **向量化还没做**：本课的 `conv2d` 是最朴素的四重循环。把它换成 im2col + 矩阵乘
   （或直接用 `torch.nn.functional.unfold`）是**性能**问题，不是数学问题——
   第 ① 条性质已经保证"换了实现数值不变"。
2. **参数分组 / 多卷积层**：本课只有一层卷积。把它堆成多层时，`pooled_size`
   与 `flatten_params` 的契约都能原样复用（它们只依赖"张量形状"）。
3. **视觉预处理的位置**：本包的输出是一张特征图。把它接到 day040 的
   `ImageAnalysisTool`（视觉-语言模型）前面，就是"自己做特征 + 交给大模型看图"的完整栈。

明天（day094）我们将进入 **循环神经网络 RNN / LSTM**：又一次权重共享，
但这次共享的维度从"空间的每一个位置"变成了"时间轴的每一个时刻"。
