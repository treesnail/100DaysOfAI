# 微调模型评估（day053 / M5-D5）

> 本文是 day053 的参考文档：把教程里的判断、公式与实测数字集中成一份可查阅的手册。
> 所有数字都可以在快照上复现：`python scripts/finetune_eval_demo.py`（本机实测约 6 秒）。

## 1. 为什么"微调评估"要单独一课

适配器只改了 2.787% 的参数（day051 实测：8 912 / 319 718），输出往往"看起来
差不多"。这意味着**肉眼与直觉在这里失效**：一个 `r=8` 的适配器足以把格式改对、
把出处的习惯改掉，也足以把某几类用例悄悄改坏，而 loss 曲线从头到尾都很正常。

所以这一课的目标不是"再算一个分数"，而是三件事：

1. **把"评什么"钉死**（评估集的四个体检）；
2. **把"合格"与"好多少"分开**（合取判定 vs 加权总分）；
3. **让分数可追溯到"评的是哪一份权重与哪一份评估集"**（报告绑定）。

## 2. 评估集的四个体检

| 体检 | 函数 | 不做会怎样 |
|------|------|-----------|
| 难度体检 | `audit_suite` | "难例上的表现"这个结论整体不可信（声明与结构负载不一致） |
| 自洽体检 | `audit_references` | 该条对**完全正确的输出**也判不合格，却只表现为"这条很难" |
| 泄漏体检 | `detect_leakage` | 评估分数虚高，且虚高集中在最像训练样本的那些用例上 |
| 切分体检 | `split_suite` | 训练集为空 / 难度单一 / 两臂跑在不同子集上 |

### 2.1 六个能力桶

| 桶 | 含义 | 条数 |
|----|------|------|
| `citation` | 给出处：答案要能指回课程源码或文档的具体位置 | 3 |
| `tool_use` | 工具语义：说清 ReAct 循环里怎么发起与接收工具调用 | 3 |
| `format` | 格式契约：按要求的段落标记组织答案 | 3 |
| `factuality` | 事实一致：数字与结论必须与源码实测一致 | 3 |
| `refusal` | 安全边界：越界请求必须拒答且不给可执行步骤 | 3 |
| `conciseness` | 简洁度：在硬字数上限内说全事实点 | 3 |

### 2.2 难度是"结构负载"

```text
structural_load = |required_facts| + |forbidden_facts| + |must_contain| + |must_not_contain|
                + (1 if max_chars <= 150 else 0)

load <= 2 → easy      load <= 4 → normal      否则 → hard
```

实测分布：`easy 4 / normal 9 / hard 5`，平均负载 `3.6111`，最大 `6`。

### 2.3 切分的粒度与位次

```text
n <= 1  → n_eval = 0（整桶留在训练侧）
n >= 2  → n_eval = min(n - 1, max(min_eval_per_bucket, round(n · ratio)))
```

- **粒度选桶而不是"桶 × 难度"**：18 条用例在 6 桶 3 难度下每格只有 1 条，
  按格子切分时 `max(1, round(0.25)) = 1` 会把每一条都划进评估集，训练集为空。
- **位次用轮转**：第 `i` 个桶取"按难度升序 + 同难度内按种子打乱"后的第
  `i mod n` 位。每桶都取第 0 位会让评估集退化成"同一个难度档的六条"。
  实测默认切分（`ratio = 0.25`、`seed = 42`）：

```text
训练集 12 条：cite-01 cite-03 tool-02 tool-03 fmt-01 fmt-02
              fact-01 fact-03 ref-01 ref-03 conc-01 conc-02
评估集  6 条：cite-02 tool-01 fmt-03 fact-02 ref-02 conc-03
评估集难度：easy 1 / normal 3 / hard 2
```

### 2.4 泄漏体检的口径

对 `instruction + reference` 取规范化后的字符 3-gram 集合，算 Jaccard：

```text
threshold = 0.5（显式参数）
leakage_rate = 被可疑命中的评估条目数 / 评估条目数   ← 恒 ≤ 1
```

实测：真实切分的 `max_jaccard = 0.054348`（无可疑对）；把一条用例原样复制进
评估集时立刻报到 `1.0`。

> **"率"的分母要对**：第一版把 `leakage_rate` 写成"配对数 / 评估条目数"，
> `threshold = 0.0` 时它等于 `12.0`——一个名叫"率"却大于 1 的数字没法解释。

## 3. 六个文本分量

| 分量 | 权重 | 尺度 | 边界约定 |
|------|------|------|---------|
| `fact_recall` | 0.40 | 语义（事实点子串命中） | 空清单 → 1.0；空事实点 → 报错 |
| `token_f1` | 0.20 | 词面（字符多重集） | 双空 → 1.0；单空 → 0.0 |
| `rouge_l` | 0.15 | 顺序（LCS 的 F 度量，`β=1`） | 双空 → 1.0；LCS=0 → 0.0 |
| `chrf` | 0.15 | 片段（字符 1..6-gram，`β=2`） | 两侧都无这一阶 → **跳过该阶** |
| `format` | 0.05 | 契约（必须/禁止片段 + 长度） | `1/(1+违规数)` |
| `refusal` | 0.05 | 安全（拒答行为是否符合预期） | 二值 |

两条**必须记住的口径差异**：

- **事实点走规范化、格式片段走原文**。规范化会抹掉标点，于是"必须写 `结论：`"
  这条规则对任何含"结论"的文本都成立——**规则一旦被软化就拦不住任何东西**。
- **字符级而不是词级**。中文没有天然分词，引一个分词器会让指标随分词器版本漂移；
  代价是英文单词被拆成字母（属于更严格的方向）。

### 3.1 chrF 的短文本陷阱（本课踩过）

`char_ngrams` 在 `order > len(text)` 时返回空。第一版把"某一侧取不到 gram"
记成 `(0.0, 0.0)`，于是**不存在的阶也进了宏平均的分母**：

```text
chrf("中文测试", "中文测试", n=4) = 1.0
chrf("中文测试", "中文测试", n=5) = 0.8      ← 相同文本拿不到 1.0
chrf("中文测试", "中文测试", n=6) = 0.6667   ← 默认值就是 6
```

修法：某一阶**两侧都不存在**时跳过该阶（这一阶量不到任何东西）。修完后
相同文本在 `n=4/5/6` 上都是 `1.0`。

### 3.2 β 的方向

`β → 0` 收敛到精确率、`β → ∞` 收敛到召回率。因此"β 越大越严格"是**错的**：
当召回低于精确率时，增大 β 会让分数下降。

### 3.3 合格是合取

```text
passed = (缺失事实点为空) and (禁项命中为空) and (格式违规为空) and (拒答行为符合预期)
```

加权总分（`MetricBreakdown.total`）单独报告。**两者都必须看**：
"少说一个要点"与"编造一个数字"不该互相抵消，而"好多少"又不是布尔值能回答的。

## 4. 三种统计口径

| 口径 | 函数 | 回答的问题 | 本课实测 |
|------|------|-----------|---------|
| Wilson 区间 | `wilson_interval` | 这个合格率有多不确定 | `2/6` → `[9.68%, 70.00%]`；`5/6` → `[43.65%, 96.99%]` |
| McNemar 精确检验 | `mcnemar_exact` | 翻转方向是否可信 | `过→不过 0 / 不过→过 3`，卡方 1.3333，`p = 0.25`，**不显著** |
| 配对自助法 | `paired_bootstrap_delta` | 平均总分差有多大、方向确定吗 | `+0.2957`，95% 区间 `[+0.1994, +0.4059]`，**不含 0** |

三点值得单独说：

1. **不用正态近似**。`p = 1.0`（全对）时 `p ± z·sqrt(p(1-p)/n)` 给出宽度 0 的
   区间，等于说"18 条全对 ⇒ 合格率精确等于 100%"。
2. **McNemar 用精确二项检验**。本课只有 3 个不一致对，卡方近似不可靠；
   精确检验在这个规模上只要几个组合数。卡方值（带连续性修正）只作参考报出。
3. **自助法必须是"配对"的**。抽的是条目（保留"同一条用例"的配对信息），
   对两臂各自抽样的区间会宽到得不出结论。

> **本课最重要的一条实测**：合格率 `33.33% → 83.33%`（`+50%`），自助法说
> 平均总分差的方向确定，而 **McNemar 说"合格/不合格"的翻转在统计上不显著**
> （`p = 0.25`）。两个结论并不矛盾——它们量的不是同一件事：
> 前者是"连续分数升高了"，后者是"通过与否的翻转足够多吗"。
> 在 6 条用例上，`+50%` 与"运气"无法区分。

## 5. 白盒探针

文本指标是**黑盒**视角（只看输出文本），探针是**白盒**视角（看模型对领域答案
有多熟）。两个可以从真实模型上算出来的量：

```text
逐 token 平均对数概率  mean_logprob = (1/N) Σ_{t≥1} log p(y_t | y_{t-1})
困惑度                perplexity  = exp(-mean_logprob)
下一 token 命中率      accuracy    = #(argmax logits == y_t) / N
```

- **按 token 加权**，不是"先按条目平均再对条目平均"（后者会让短条目权重过大）；
- 探针与模型**必须同一套词表**（`CharTokenizer` 的词表从语料现造），
  越界 id 直接报错——否则得到的是"模型很差"的假象；
- **探针 ≠ 训练 loss**：分母差 1。训练时"答案的第一个 token"被计分
  （上下文是 prompt 的最后一个 token），探针在只喂答案 id 时从第二个 token 起算。
  正确用法是**同口径对比**（前后都用探针）。

### 5.1 三组配置的实测（参考模型，词表 422）

| 配置 | 步数 | 训练集困惑度 | 评估集困惑度 | 评估 loss | 泛化间隙 |
|------|------|-------------|-------------|-----------|---------|
| 基座（未微调） | 0 | 421.8238 | 421.7649 | 6.0444 | — |
| `lr = 2.0`（标定） | 120 | 140.7894 | 290.4877 | 5.6663 | 149.7573 |
| `lr = 8.0`（过拟合） | 120 | 14.4577 | 587.6399 | 6.3749 | 573.2411 |
| `lr = 20.0`（发散） | 120 | inf | inf | 2.978e+68 | nan |

参考值：`ln(422) = 6.0448`（"完全瞎猜"），基座评估 loss `6.0444` 就贴着它。

**泛化间隙 = 训练集困惑度降幅 − 评估集困惑度降幅**：`lr=8.0` 把训练集背到了
`14.46`，代价是评估集从 `421.76` 退到 `587.64`；标定配置则是两边都降。
`lr=20.0` 直接发散（困惑度 `inf`）——**学习率没有绝对尺度**（day050 的原话）。

### 5.2 逐桶探针（标定配置，评估集）

| 桶 | 监督 token | 困惑度 | 命中率 |
|----|-----------|--------|--------|
| `citation` | 73 | 169.2532 | 0.1096 |
| `conciseness` | 91 | 439.5037 | 0.0110 |
| `factuality` | 61 | 235.2772 | 0.1475 |
| `format` | 72 | 353.5180 | 0.0694 |
| `refusal` | 32 | 454.2968 | 0.0000 |
| `tool_use` | 71 | 239.0405 | 0.1268 |

### 5.3 预算外推

```text
白盒探针实测：6 条 / 497.3 毫秒 → 单条 82.89 毫秒（每条约 70 次 bigram 前向）
外推：100 条 / 4 并发 = 2.0721 秒；1000 条 / 4 并发 = 20.7215 秒
```

与 day052 的 `logistic_estimate_hours` 同一条取舍：**线性外推，不做非线性建模**。
把不确定的东西乘进一个精确公式，得到的是精确的错。

## 6. 报告与门禁

```text
EvalReport = 适配器绑定（content_sha256 / base_model / step）
           + 评估集指纹 + 权重快照
           + 总体与分桶结果 + 对比结果
           + 三项门禁 + 失败清单（最多 10 条）
```

| 门禁 | 判据 | 为什么要有 |
|------|------|-----------|
| `min_pass_rate` | `pass_rate >= threshold` | 让"合格率下限"可配置，而不是写死在代码里 |
| `no_regression` | 每个分组（桶 / 难度）的回退都不超过 `max_regression` | 微调的典型事故是"总体涨了、某一类掉得厉害" |
| `execution` | `error_count == 0` | runner 崩了不能算绿 |

三条纪律：

1. **绑定**：`verify_manifest_binding` 核对哈希 / 基座 / 步数，任一项不一致就报错。
   一份对不上适配器的评估报告，比没有报告更危险——**它会被当成证据引用**。
2. **失败路径必须被测试**：每条门禁都有"构造一个失败"的用例。一个永远不会
   失败的门禁不是门禁（day052 的纪律）。
3. **报告不写时间戳**：时间戳让两份报告必然不同，于是"这两份是不是同一件事"
   只能靠人眼；要留时间信息就写进 `notes`，让它显式成为内容的一部分。

## 7. 常见故障对照表

| 现象 | 真实原因 | 定位手段 |
|------|---------|---------|
| 分数涨了但没人信 | 评估集与训练集重叠 | `detect_leakage` 的 `max_jaccard` |
| 某一条怎么都不过 | 参考答案不满足自己的事实点 | `audit_references` |
| `by_difficulty` 全是 100% | 评估集难度单一 / 难例不在评估集 | `split_suite` 的轮转位次 |
| 相同文本拿不到满分 | 指标定义里的边界（如 chrF 短文本） | 对 `f(x, x) == 1.0` 做不变式断言 |
| 训练 loss 一路下降但评估变差 | 过拟合 | 探针的**泛化间隙** |
| 两个分数没法比 | 评估集指纹或适配器哈希变了 | 报告里的两个哈希 |
| "涨了 50% 但结论不显著" | 样本太小 | McNemar 的 `p` 与自助法区间一起看 |
