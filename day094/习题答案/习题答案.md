# day094 习题答案：循环神经网络 RNN / LSTM —— 同一组权重，用在每一个时刻

> 参考答案。每题都尽量给出"为什么"与"看源码的哪里"。
> 涉及的模块都在 `smart_research_agent/sequence_models/` 下。

## 一、速答

**1.** **同一组权重在时间轴的每一个时刻被重复使用**。它带来的性质是：
**参数量与序列长度 T 完全无关**。本课的两个数：`D=2、H=3` 的 RNN 是
`H·D + H·H + H = 6 + 9 + 3 = 18` 个；LSTM 是 `4×18 = 72` 个；
序列从 1 步涨到 8 步，这两个数**一个也不多**（`study.parameter_rows`）。
见 `types.RECURRENT_NOTES["time_sharing"]` 与 `ops.parameter_count`。

**2.** 差别在于**同一个时刻的各个位置彼此独立，而不同的时刻彼此依赖**：

```text
卷积   全图的每个位置都用同一张核独立点积 ⇒ 可以一次算完（向量化 / GPU 并行）
循环   第 t 步的输入包含第 t−1 步的输出   ⇒ **只能按顺序算**（T 次串行乘法）
```

后果：循环网络的时间维**无法并行**，这是它被注意力机制取代的原因之一
（另一个是信息路径长度，见第十一章的对比表）。

**3.** `4H·(D + H + 1)` 前面那个 **4** 来自"四个门"（输入 / 遗忘 / 输出 / 候选
各要一套 `H·D + H·H` 的权重）。偏置项是括号里的那个 **1**——
它对应 `H` 个偏置（或 LSTM 的 `4H` 个偏置），对 RNN 是 `+ H`、对 LSTM 是 `+ 4H`。
见 `types.RNN_PARAM_FORMULA` / `types.LSTM_PARAM_FORMULA`。

**4.** 应当返回 **T 个**状态（`h₁ … h_T`）。把初值 `h₀` 也算进输出会得到 **T+1 个**。
后果是：下游 `zip(状态, 输入)` 会静默按较短的一边截断，
于是"第 t 个状态"与"第 t 个输入"**整体错位一格**——
训练仍然在跑、损失仍然在降（降得更慢），而"模型记不记得住"这个结论是假的。
**它不会报错**，因为两个序列都合法，只是语义对不上。见 `layers.rnn_forward`
的文档串与 `errors.TimeStepError`（这一族就是为它单列的）。

**5.** `f = σ(b_f)`：

```text
b_f = 0  ⇒  f = 0.5          记忆每一步被砍掉一半（8 步之后只剩 0.5⁸ ≈ 0.39%）
b_f = 1  ⇒  f = σ(1) ≈ 0.731059   记忆通道一开始就基本连通
```

所以本包把遗忘门那一块偏置写成 `types.DEFAULT_FORGET_BIAS = 1.0`。
它是本课唯一一处不由 LCG 决定的数（刻意写死，不是漏掉随机性）。
现场读数：`study.gate_rows()` 里遗忘门的均值 `+0.719303` 明显高于另两个门
（输入门 `+0.549824`、输出门 `+0.508696`）。

**6.** `∂c_T/∂c_0 = ∏_{t=1..T} f_t`（逐分量）。
因为 `c_t = f⊙c_{t−1} + i⊙g` 里，`c_{t−1}` 的系数**只有 f**——
没有 `W_h`、也没有 `tanh'`。于是梯度沿记忆通道往回走时**只乘 f**；
`f` 接近 1 时几乎不衰减，这就是"梯度高速公路"。
第 ⑤ 条性质把它写成一条可断言的等式（实测 `5.551e-17 <= 1e-12`）。

**7.** 用的是 **`+=`**（累加）。写成 `=` 的后果不是报错，而是
**只留下最后一步的贡献**：梯度整体偏小，看起来像"学习率设小了"。
现场读数：三步都回传 `‖dW‖ = 3.014188`，只留最后一步 `1.503321`——**只剩 49.9%**。
`test_rnn_bptt_accumulates_across_time` 把"整段必须严格大于只算最后一步"写成断言。

**8.** **回来了**（`errors.RETURNED_FAMILY == "GradientError"`，且 `ABSENT_FAMILY is None`）。
理由与 day090 那一次不同：

```text
day090  抛它是因为"解析梯度与数值差分对不上"   ← 一次**离线对账**的结论：这次训练不可信
day094  抛它是因为"梯度真的爆了"               ← 一个**运行期守卫**：这一步就不该继续
```

守卫是 `train.check_gradient_norm`：在进入优化器之前看一次范数，
非有限或超过 `MAX_GRADIENT_NORM` 就抛。见 `errors.RETURNED_FAMILY_REASON`。

## 二、连线

**9.**

| 名称 | 职责 |
|------|------|
| `matvec` | b. `W·x`（行是输出、列是输入） |
| `matvec_transpose` | c. 把回传梯度投影回输入空间（反向的一半） |
| `outer` | d. `g ⊗ x`，`dW` 的每一时刻那一片 |
| `gate_blocks` | a. 把 `4H` 的打分切成 i / f / o / g 四块 |
| `check_gradient_norm` | e. 进入优化器之前看一次梯度范数，越界就抛 `GradientError` |
| `rnn_carry_norm` | f. 量"信号从末步回到起点还剩多少" |

`matvec` 与 `matvec_transpose` 是一对"转置"。
把它们写反的症状很具体：

```text
H == D（方阵）时  形状仍然合法 ⇒ **不报错**，只是数值全错
H != D 时         形状当场不合法 ⇒ 抛 ShapeError（"运气好"才被发现）
```

这正是第 ⑥ 条性质要用数值差分的原因——它是唯一能发现"乘法方向错了"的尺子。

## 三、对照计算

**10.**

```text
RNN    H·(D + H + 1) = 3 × (2 + 3 + 1) = 3 × 6 = 18
LSTM   4H·(D + H + 1) = 4 × 3 × 6 = 72
```

**不会变。** 两个公式里**都没有 T**。`study.parameter_rows()` 在 `T = 1 / 3 / 8`
三行上给出同一对数（18 / 72），这就是"时间轴权重共享"最直接的证据。

**11.** 权重全为 0，于是四个门的打分 `z` 就等于各自的偏置：

```text
i = σ(b_i) = σ(−40) = 4.248354255291589e-18 ≈ 4.25e-18
f = σ(b_f) = σ(+40) = 1.0        （**恰好**：e^{−40} ≈ 4.25e-18 < eps/2 ≈ 1.11e-16）
o = σ(b_o) = σ(+40) = 1.0        （同上）
g = tanh(b_g) = tanh(0) = 0.0
```

于是：

```text
c₁ = f ⊙ c₀ + i ⊙ g = 1.0 × 0.75 + 4.25e-18 × 0.0 = 0.75（与 c₀ **逐位**相同）
h₁ = o ⊙ tanh(c₁) = 1.0 × tanh(0.75) = 0.6351489523872873 ≈ +0.635149
```

`h₁` 恰好等于 `tanh(c₁)`，是因为输出门恰好被钉成了 `1.0`（`σ(40)` 在双精度里就是 1）。
第 ② 条性质（`lstm_gates_control_state`）量的正是这两件事，读数 `0.000e+00 == 0`。

**12.**

RNN 侧：`∂h_T/∂h_0 = ∏_{t=1..T} diag(tanh'(z_t))·W_h`。每个因子的范数满足

```text
‖diag(tanh'(z_t))·W_h‖ ≤ ‖diag(tanh'(z_t))‖·‖W_h‖ ≤ 1 × 0.5 = 0.5
```

（`|tanh'| ≤ 1`，取范数为算子 2-范数。）由次乘法性逐项连乘：

```text
‖∂h_T/∂h_0‖ ≤ 0.5⁸ = 3.906250e-03
```

实测读数 `2.864e-03`，**确实不超过上界**。

LSTM 侧：`∂c_T/∂c_0 = ∏ f_t = 1⁸ = 1.0`，实测 `1.000000`。

**为什么必须是下界判据**：因为第 ⑦ 条要证的是一件"必须足够大"的事——
`LSTM 的 carry 减去 RNN 的 carry ≥ 0.5`（实测差 `9.971e-01`）。
如果写成上界（"不能太大"），那么把 LSTM 做成"记忆通道不独立"的假 LSTM 时，
第 ①②③④⑤⑥ 条会**全绿**（它们在那个假 LSTM 上照样成立），
只有这条下界会红——它把"LSTM 必须比 RNN 强"变成一条不能少的断言。

## 四、诊断

**13.** 最可能的原因：**`dW` 写成了 `=` 而不是 `+=`**（或者 BPTT 的循环只跑了最后一步，
例如把 `range(len(caches) - 1, -1, -1)` 写成了 `range(len(caches) - 1, len(caches))`）。
症状是梯度整体偏小 → 学习变慢，而形状、有限性全都正常。

两条断言都会发现它，但**时机与代价不同**：

```text
第 ⑥ 条 bptt_matches_numerical
    解析梯度与数值差分差得远大于 1e-9 ⇒ 会红
    但它是**离线对账**：要跑 2n 次前向、不在训练回路里

test_rnn_bptt_accumulates_across_time
    "整段的 ‖dW‖ 必须严格大于只算最后一步的 ‖dW‖" ⇒ 会红
    它是一个**结构性断言**：不依赖数值差分，更便宜、也更早能跑
```

这一课把两者都留下，正是因为"能发现同一个 bug"与"能便宜地发现它"是两件事。

**14.** 错位把"第 t 个状态"与"第 t 个输入"对错了（整体偏移一格）：
`states[t]` 本该是"读完 `inputs[t]` 之后的状态"，实际变成了"读完 `inputs[t−1]` 之后的"。

为它准备的：

```text
错误族   errors.TimeStepError  （bptt 里 grad_states 与 caches 的步数必须相同）
性质     第 ④ 条 sequence_alignment_matches_input（T 个输入 ⇒ T 个状态，整数判据）
```

loss 停在 `0.69 ≈ ln 2` 等于"模型输出接近均匀分布"，这与会话里 day093 的第 14 题
是同一个读数——**错位不会让训练崩掉，只会让它学不到东西**。

## 五、推导

**15.** 从两条式子出发：

```text
c_t = f ⊙ c_{t−1} + i ⊙ g
h_t = o ⊙ tanh(c_t)
```

把 `W_h` 置零之后，隐状态那条链在反向里被切断：

```text
dh_{t−1} 的那一条来源是 W_hᵀ·dz_t = 0        （因为 W_h = 0）
  ⇒ grad_hidden 全零、carry_h 全零
  ⇒ 每一时刻的 dc 只剩"从 t+1 带上来的那部分" + grad_cell[t]
```

于是逐分量地：

```text
dc_{t−1} = dc_t ⊙ f_t
```

从 `t = T` 递推到 `t = 1`：

```text
∂L/∂c_0 = ∂L/∂c_T ⊙ ∏_{t=1..T} f_t
```

把末步的种子取成全 1，就得到 `∂L/∂c_0 = ∏f_t`（逐分量）。
第 ⑤ 条性质用的正是这个设置（`verify.check_lstm_cell_gradient_is_forget_product`
里把 `wh` 置零），并把"BPTT 的累乘"与"把前向缓存里的门直接相乘"两条路径对起来。
**注意**：`h_t` 通过 `tanh(c_t)` 依赖 `c_t` 的那条链在 `W_h = 0` 时**仍然存在**
（它贡献 `dh ⊙ o ⊙ (1 − tanh²)` 到 `dc`），只是我们的种子只给了 `c`，
`dh` 全零 ⇒ 那一条链的贡献是 0。这是"刻意构造"而不是"漏掉"。

**16.** 由链式法则展开：

```text
∂h_T/∂h_0 = ∏_{t=1..T} ∂h_t/∂h_{t−1} = ∏ diag(act'(z_t))·W_h
```

对上式取范数并用**次乘法性**（`‖AB‖ ≤ ‖A‖‖B‖` 逐项连乘）：

```text
‖∂h_T/∂h_0‖ ≤ ∏ ‖diag(act'(z_t))‖ · ‖W_h‖ ≤ ‖W_h‖ᵀ
```

最后一个不等号用了 `|tanh'| ≤ 1` ⇒ `‖diag(tanh'(z_t))‖ ≤ 1`。
代入 `‖W_h‖ = 0.5`、`T = 8`：

```text
上界 = 0.5⁸ = 3.906250e-03
```

实测 `2.864e-03` ← 落在上界之内。这就是"tanh-RNN 记不住远处"的算术来源：
上界随 T **指数衰减**，而 LSTM 的 `∏f`（f 接近 1）几乎不变——第 ⑦ 条性质的差值。

## 六、情景题

**17.** **成立**。"工单是变长文本"正好落在"时间轴权重共享"的适用面上：
同一个变换（一层循环单元）作用在每一个 token 上，与句子的长度无关。
接法：

```text
① 把每个 token 的 embedding（day041）当成 x_t，喂进 sequence_models 的循环单元；
② 取最后一步的 h_T（或对所有 h_t 做平均池化）送进 dense(C→3)；
③ 参数压平 / BPTT / 优化器都能原样复用（day090 与 day092 的契约）。
```

变长批量的处理（**这不是数学问题，是工程问题**）：

```text
① padding + mask：把短序列补到批内最长，并在**损失里**把补齐位置屏蔽掉
   （本课的 BPTT 没有 mask 项，因此这一步要新增；
    注意 padding 的位置**不能计入** h_T——否则 h_T 会被"垫出来的 token"污染）
② 按长度分桶（bucket）再组批：把长度相近的样本放一批，减少 padding 浪费
③ 干脆逐条前向（本课的做法）：32 条样本的循环代价在纯 Python 里已经偏慢，
   真正生产里用 ① + ② 配 GPU。
```

**18.** **不会等价**，而且这个"不等价"正是本课想讲清的一件事。

```text
循环     h_t 是**串行**算出来的：h_t 依赖 h_{t−1}，信息路径长度 T
注意力   每个位置的输出是"全序列两两打分的加权和"，一次矩阵乘算完，路径长度 1
```

两者的**参数量都只随宽度变化**（都是"权重共享"），但：

```text
① 计算依赖不同    循环有"第 t 步依赖第 t−1 步"，注意力没有
② 输出不同        循环输出的是 h_T（一条链的末状态），注意力输出的是每个位置的加权和
③ 位置信息来源不同 循环的"顺序"由计算顺序自带；注意力必须显式加位置编码（day078）
```

指出"本来就不是同一个东西"的那一条性质是第 ③ 条
`weight_sharing_across_time`：它把循环钉在**"同一个函数被调用 T 次"**上
（逐步复算与整段逐位相同）。注意力**没有**这个"逐步复算"的结构——
它一次就是全部。所以"换成注意力"不是"换一种算法算同一个数"，
而是**换一个模型**；两者能比较的只有"在同一任务上的表现"，不是数值。
