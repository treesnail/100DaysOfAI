## 第二章：BatchNorm 的第一句话 —— 统计量沿哪条轴

### 2.1 两条轴摆在一起

```text
BatchNorm（本包）    固定一个特征，在**批**上算 μ/σ    （N 条样本 → 1 对统计量）
LayerNorm（day079）  固定一条样本，在**特征**上算 μ/σ  （每条样本各一份统计量）
```

`study.axis_rows()` 印出的正是这件事：

```text
batch   | μ_j = (1/N)·Σ_n x_nj；σ²_j = (1/N)·Σ_n (x_nj − μ_j)²   （对每个特征 j）
        | 批大小变成 1 时方差恒为 0 ⇒ 输出被压成常数（β）——这是它的签名
feature | μ_n = (1/F)·Σ_j x_nj；σ²_n = (1/F)·Σ_j (x_nj − μ_n)²   （对每条样本 n）
        | 每条样本各自标准化 ⇒ 与批里有多少条样本完全无关
```

最后那一列是本课反复要用的东西：**一个算子"最能暴露它的一个事实"**。
对 BatchNorm，那就是"批大小为 1 会塌"。

### 2.2 前向的四行

```text
μ_j  = (1/N)Σ_n x_nj；σ²_j = (1/N)Σ_n (x_nj − μ_j)²      ← **有偏**方差（分母是 N）
x̂_nj = (x_nj − μ_j)/√(σ²_j + ε)
y_nj = γ_j·x̂_nj + β_j                                     ← γ/β 是**逐特征**的
running ← (1−m)·running + m·这批                            ← momentum 是"每个批占多少"
```

三个可读的细节：

```text
① 方差是**有偏**的（除以 N）：与 PyTorch 的 BatchNorm 以及 day079 的 LayerNorm 同口径
② ε 在**分母**里：它的作用是"别让 0 方差炸掉"，不是"提高数值精度"
③ γ/β 是可学的：把它们设成 (σ, μ) 就能**撤销**标准化——恒等映射是它的一个特例
```

### 2.3 一个可查的读数

用同一批样本跑一遍（`verify.SAMPLE_BATCH`，4×3）：

```text
这一批 4×3：μ 均值 +0.233333 | σ² 范围 [0.583333, 0.916667]
输出第一行：(−0.150221, ...)   ← 由 γ=1.3/0.7/−1.1 与 β=0.2/−0.4/0.9 决定
第一步之后 running（1 批）| μ 均值 ...
```

第 ① 条性质把它与**手写的逐特征标准化**逐位对账：

```text
通过 batchnorm_matches_manual_standardization | 读数 0.000e+00 == 0
    | normalization.batch_norm_forward vs 手写逐特征标准化
```

两条路径**共用** `ε = 1e-5` 这个常量与"求和用 `math.fsum`"这条数值约定，
因此逐位比较检验的是**结构**（哪个量在哪条轴上），而不是浮点的求值顺序。

## 第三章：批大小为 1 的塌缩（本课真的撞到的第一堵墙）

### 3.1 一个把三条配置变成同一条的 bug

第一版实现把 BatchNorm 直接插在"单条序列的 h_T"上。批大小就是 1：

```text
批大小 1 ⇒ 每个特征的批内方差恒为 0
        ⇒ x̂ = (x − x)/√(0 + ε) = 0
        ⇒ y = γ⊙0 + β = β = 0
        ⇒ 整层输出是一个常数，与输入完全无关
```

于是三条**不同**的配置——`rnn`、`lstm`、带不带 dropout——给出**同一个 loss**：

```text
[rnn  rate=0.0] 参数量 29 最大|差| = 8.046e-11 | 批损失 0.542374
[rnn  rate=0.3] 参数量 29 最大|差| = 1.035e-10 | 批损失 0.542374
[lstm rate=0.3] 参数量 74 最大|差| = 1.035e-10 | 批损失 0.542374
```

**三条不同配置的 loss 一模一样**——这不是巧合，而是"BN 把输入抹平了"的直接后果。
更值得注意的是：**数值差分当时仍然全绿**（8e-11、1e-10），因为整条链的导数是对的，
只是它作用在一个常数上。

### 3.2 修法不是"去掉 BN"，而是"让它见到批"

```text
BatchNorm 的统计量来自批 ⇒ 这一层**必须**一次看 N 条样本
⇒ 本课的网络是**批版本**：一次前向处理一批序列，把每条的 h_T 竖着堆成 (N, H)
```

而"批大小为 1 会塌"这件事被写成一个可读的读数（`normalization.batch_size_one_report`）：

```text
批大小 1：最大方差 0.000000，最大 |输出| 0.000000
```

演示脚本里可以直接看到它；`test_batch_size_one_collapses_to_beta` 还断言了更强的一条：
**批大小为 1 时输出恰好等于 β**（把 β 设成 (5, −3, 1) 就得到 (5, −3, 1)）。

## 第四章：两个相 —— 训练用本批、推理用 running

### 4.1 谁用哪一套统计量

```text
训练相   μ/σ 来自**这一批**，同时把 running 统计量往这批靠一步
推理相   μ/σ 来自 **running**（**必须由调用方给出**，否则抛 PhaseError）
```

`study.phase_rows()` 在同一个批上把两个相的读数并排印出来：

```text
train  | 本批统计量（同时更新 running 统计量）      | μ 均值 +0.233333 | 最大 |y| 2.551194
eval   | running 统计量（**必须由调用方给出**）     | μ 均值 +0.288878 | 最大 |y| 1.506195
```

两行**不一样**——而第 ③ 条性质把这件事写成一条**下界**判据：

```text
通过 train_and_eval_phases_differ | 读数 1.678e+00 >= 5.0e-01
    | 训练相输出 vs 推理相输出（同一批、同一组 γ/β）
```

### 4.2 为什么这一条必须是下界

因为"两相"这件事的可证伪形式是"它们**不一样**"。设想把两相写成同一件事
（推理相也用本批统计量）：

```text
① BN 前向 = 手写标准化      → 仍然通过（训练相本来就那样）
② BN = transpose(LN)        → 仍然通过（等价性只依赖训练相）
④ 训练相反向 = 数值差分      → 仍然通过（训练相的反向照样对）
⑤ 推理相反向 = 数值差分      → **会红**（推理相的反向被写成了三项版本）
③ 两相必须不同               → **会红**（两相给出了同一个输出）
```

**七条里只有两条能发现它，而这两条一条是下界、一条是"另一条路径的数值对账"。**
没有它们，"两相被写成一相"会在报告里全绿——这正是每一条性质都要被认真设计的原因。

### 4.3 推理相缺统计量时抛什么

```text
batch_norm_forward(batch, phase="eval")  且没有 running
  ⇒ PhaseError（**不是** ParameterError）
```

这一族值得独立，因为它与"参数越界"处置的**对象**不同：

```text
ParameterError  调用点的**某一个数**越界了        → 去改那个数
PhaseError      两个都合法的东西被**配错了对**     → 去看"这一步是谁在跑"
```

把"推理时输出抖动"这种症状归到参数族，会让人去调一个根本不存在的超参。

## 第五章：反向 —— 三项 vs 一项

### 5.1 一边是"μ/σ 也是 x 的函数"，一边不是

```text
递归那部分（h_t、BPTT）是 day094 的事，本课一行不改。本课只关心一件事：
y = γ ⊙ x̂ + β 里，x̂ 依赖 μ 与 σ——而它们依赖谁？

训练相   μ/σ 是**这一批 x 的函数**   ⇒ 求导要多两项
推理相   μ/σ 来自 running（常数）    ⇒ 求导只剩一项
```

于是：

```text
训练相   dβ_j = Σ_n dy_nj；dγ_j = Σ_n dy_nj·x̂_nj；dŷ = γ⊙dy
         dx_nj = (1/σ_j)·( dŷ_nj − mean_n(dŷ_j) − x̂_nj·mean_n(dŷ_j ⊙ x̂_j) )
推理相   dx_nj = dŷ_nj / σ_j
```

那三项的来历只有一句话：`x̂` 的第 1 项来自"除以 σ"，第 2 项来自"减掉 μ"，
第 3 项来自"σ 自己也依赖 x"。把它写全的过程在 `normalization.batch_norm_backward`
的文档串里；这里值得记下来的是**形状检查对这件事完全无能为力**——
把推理相写成训练相，`dx` 还是 `(N, H)` 的矩阵。

### 5.2 一个可以手算的读数

取一批 `((1, −1), (3, 1))`、`γ = 2`、回传 `dy` 全 1：

```text
x̂ 每一列的和是 0（标准化的定义）
dŷ = 2、mean(dŷ) = 2、mean(dŷ⊙x̂) = 0
dx = (1/σ)(2 − 2 − x̂·0) = 0        ← 训练相的三项在这里**恰好**抵消
```

而**推理相**在同一个缓存上给出的是 `γ⊙dy/σ = 2/σ ≈ 2`——两条路径从同一个 cache 分家。
第 ④ / ⑤ 条性质各钉一条路。

### 5.3 对账读数（**四级链**上的数值差分）

```text
通过 batchnorm_backward_matches_numerical | 读数 5.143e-09 <= 1.0e-07
    | 整条链的解析梯度（训练相） vs calculus.gradient（数值；‖∇‖ ≈ 14.245）
通过 eval_backward_matches_numerical | 读数 3.115e-10 <= 1.0e-07
    | 整条链的解析梯度（推理相） vs calculus.gradient（数值；‖∇‖ ≈ 3.152）
```

被检验的对象是**一条四级的链**（BPTT → BN → dropout → dense）在一批样本上的梯度，
梯度量级 ~14，因此绝对容差取 **1e-7**（day093 / day094 是 1e-9）。
换算成相对误差是 **3.6e-10**——与那两天同一量级。容差不是越紧越好：
**容差低于分辨率时，判据会无辜地反复变红**（day074 已经把这件事写下来过）。

## 第六章：BatchNorm 与 LayerNorm 是同一条公式在两条轴上

### 6.1 一条可以精确成立的等式

把批**转置**之后，两条轴互换：

```text
batch_norm_forward(X)  ==  transpose(layer_norm(transpose(X)))
```

第 ② 条性质**真的调用** day079 的 `encoder_decoder.layers.layer_norm` 来对账：

```text
通过 batchnorm_equals_transposed_layer_norm | 读数 0.000e+00 <= 1.0e-12
    | normalization.batch_norm_forward vs transpose(encoder_decoder.layer_norm(transpose(X)))
```

实测**逐位相同**（0.000e+00），而判据写成"不超过 1e-12"——它是一条上界判据，
承认"两条路的求和顺序可以不同"，只要求它们给出同一个数。

### 6.2 为什么这条等式只在"没有仿射"时成立

`layer_norm` 的 γ/β 是**逐列**的（长度必须等于输入的列数），而 BatchNorm 的 γ/β 是**逐特征**的。
把批转置之后，"列"就是"特征"，于是：

```text
γ 均匀（全是同一个数）时，两套参数可以互相表示 ⇒ 等式成立
γ 不均匀时，两套参数停在**不同的轴**上        ⇒ 等式不成立（这不是 bug）
```

因此这条性质刻意用"什么都不改"的那一组（γ=1、β=0）。
"仿射参数在哪条轴上"本身就是这一课要讲清的一件事——它比"两条公式长得像"更重要。

### 6.3 两处 ε 必须同值

```text
本包                              types.DEFAULT_EPSILON = 1e-5
day079 encoder_decoder.types      DEFAULT_EPSILON        = 1e-5
```

`test_tolerance_is_same_as_day079_epsilon` **真的 import 了 day079 的常量**来断言这一点。
跨天对账最常见的失效方式就是"两处各自取一个 eps"——而那种失效只在
第 6 位小数之后才看得见。

### 7.2 转发层里唯一的"新东西"：把行向量塞进 day081

day081 的 dropout 作用在 `Matrix` 上（一层激活之后的整张特征图）。
本课需要对**最后一步的隐状态**做 dropout——它是一行 `H` 个数。于是：

```python
def dropout_vector(vector, *, rate, seed, phase="train"):
    checked = as_vector(vector, name="vector")
    output, mask, scale = dropout_forward((checked,), rate=rate, seed=seed, phase=phase)
    return output[0], mask, scale        # ← 形状换了，数学没变
```

三个返回值（输出、掩码、缩放）都留下，因此反向不需要重算掩码——
这正是 day081 "掩码固定之后梯度可校验"那条不变量成立的前提。

### 7.3 调度由**优化器**执行，不由本课执行

day092 的 `TrainingOptimizer` 原生支持 `set_schedule`：它在每一步**之前**取一次学习率。
这一点很重要：

```text
把"学习率衰减"实现成"把梯度乘一个系数"对 **SGD** 是等价的（θ ← θ − lr·g）
对 **Adam** 不等价（等效步长不是 lr 的线性函数）
⇒ 本课不自己乘系数，而是把曲线交给优化器（它内部按同一条公式走）
```

四种调度的参数本来就不一样，因此 `RegularizationConfig.schedule_kwargs(total_steps)`
给出一份**精确**的参数表（多传一个就会 TypeError）：

```text
constant       {base_lr}
step_decay     {base_lr, drop_every, gamma}
cosine         {base_lr, total_steps, min_lr}
warmup_cosine  {base_lr, warmup_steps, total_steps, min_lr}
```

第一条读数是"常数调度也要 base_lr"——day074 的四个工厂函数**都有**这个参数。

### 7.4 早停的两条纪律（day081 留下，本课照用）

```text
① "变好"必须带一个 min_delta     → min_delta = 0 时浮点噪声也算"进展"，早停永不触发
② 它记录 best_step 而不是 last_step → "最好的一步"才是该保存的那份参数
```

演示脚本里的两行读数：

```text
早停：最好第 2 步（0.900000），已等 3 步，触发=True     ← (1.0, 0.9, 0.9, 0.9, 0.9)、patience=3
cosine 第  1 步的学习率：0.100000
cosine 第  5 步的学习率：0.058682
cosine 第 10 步的学习率：0.000000                     ← 退火到 min_lr 的端点，合法
```

最后那一行是 day092 撞过的那个坑：**余弦退火的最后一步合法地取到 0**，
用"必须为正"去卡调度会让它跑不完——本包只拒绝负数与非有限数。

## 第八章：装上旋钮的链 —— 批版本与"不重写 BPTT"

### 8.1 结构写死

```text
一批样本 → day094 的循环单元（**一行不改**） → 每条的 h_T
                                              ↓
                                    BatchNorm(γ, β)      ← 本包新写
                                              ↓
                                    Dropout（训练相）     ← 转发 day081
                                              ↓
                                    dense(H→C)           ← day094 的分类头
                                              ↓
                                            logits
```

现场读数（`H=4、D=1`、`lstm`）：

```text
结构：lstm(H=4, D=1) → bn(4) → dropout → dense(4→2) | 参数 114
参数量 114（day094 的网络 + γ/β 共 8 个）
压平后长度：114
这一批的损失：2.216157；梯度整体范数：4.357177
```

BatchNorm 只加了 **2H = 8** 个参数（γ 与 β 各 H 个）。`study.parameter_rows()` 三行：

```text
H = 2  | BatchNorm 参数 4（2H）
H = 4  | BatchNorm 参数 8（2H）
H = 8  | BatchNorm 参数 16（2H）
```

### 8.2 本课最值得看的一处：**没有重写 BPTT**

反向的路线是 `dense → dropout → BN → 逐条 dh_T → day094 的 BPTT`：

```python
# ④ 把每一行的 dh_T 交回 day094 的 BPTT（**逐条**），权重梯度相加
for index, sequence_cache in enumerate(cache.sequences):
    d_hidden = d_inputs[index]
    grad_hidden = (zeros(...), …, d_hidden)        # 只在最后一步有梯度
    result = sequence_gradients.lstm_bptt(cell, sequence_cache.lstm_steps, grad_hidden)
    _accumulate_cell_gradients(accumulator, result.cell)
```

三个细节，每一个都对应一次真实的取舍：

```text
① 逐条调用 BPTT（而不是"批版本的 BPTT"）：day094 的实现本来就是"一条序列"的，
   把它批化意味着一份新实现——本课不做这件事
② 只在最后一步有梯度：分类头只读 h_T，因此 dh 只挂在最后一步
③ 权重梯度**相加**：损失是批均值，而 cross_entropy_grad_rows（day090）已经除过批大小，
   所以这里不再除第二次——除两次会让梯度小 N 倍，看起来像"学习率要乘 N"
```

### 8.3 一次"刻意的浪费"，以及一条被它挡住的坑

`regularized_forward_cached` 调用的是 day094 的 `sequence_forward_cached`，
而它会**顺带算出 head 的 logits**——本课不用那一份（本课在 head 之前插了两层）。
这次多算只有 `C × H` 次乘法，换来的是"序列前向仍然只有一份实现"。

另外，`use_norm=False` 时本课**整层跳过** BatchNorm（恒等），而不是"用一个接近恒等的 BN 冒充"：

```python
if use_norm:
    normalized, bn_cache, running_out = batch_norm_forward(...)
else:
    normalized, bn_cache = hidden_matrix, None          # bn_cache 是 None ⇒ 反向走恒等
    running_out = initial_running(params.features) if running is None else running
```

反过来，反向里 `if cache.bn is None:` 那一条分支把"恒等"的导数写成 `d_inputs = d_normalized`
并让 γ/β 的梯度为 0——**消融实验的"没有归一化"那一组因此是真的没有归一化**。

## 第九章：训练回路 —— 四个动作的顺序，与两把尺子

### 9.1 每一步的顺序是写死的

```text
取 lr（调度在优化器内部，day092 的 set_schedule）
  → 算这一步的批均值梯度（day094 的 BPTT）
  → 过 day094 的梯度范数守卫（check_gradient_norm；本课只是调用它）
  → optimizer.step → unflatten（day090 的压平契约）
```

注意第三步：**本课没有自己的梯度护栏**。梯度爆炸的守卫是 day094 装的
（`sequence_models.train.check_gradient_norm`），本课只是**调用**它——
这正是 `errors.ABSENT_FAMILY_REASON` 里写下的那句话：`GradientError` 今天缺席，
因为它不属于这一层的控制流。

### 9.2 两把尺子：训练损失与推理损失

```text
训练损失   带 dropout、BN 用本批统计量   ← 每一步一份
推理损失   不带 dropout、BN 用 running    ← 每个 epoch 一份
```

**只报训练损失会把 dropout 的代价看反**（训练损失被 dropout 抬高是正常的）。
day081 已经留下"两个损失口径都要给"这条纪律，本课把它做成报告里的两列：

```text
TrainReport.final_loss   最后一步的训练损失
TrainReport.eval_loss    最后评估的推理损失
TrainReport.loss_gap     = eval_loss − final_loss
```

### 9.3 为什么必须分批（也是为什么 batch_size 有下界）

```text
BatchNorm 的统计量来自批 ⇒ 批越大越稳、批大小为 1 时整层塌成常数
⇒ shard_batches 拒绝 batch_size < 2（**当场抛 ParameterError**，不是取默认值）
```

本课用 `batch_size = 8`（32 条样本 ⇒ 每个 epoch 4 批，160 步）。

## 第十章：训练日志可视化 —— 四张脸

### 10.1 为什么值得单列一个模块

一份**只能读数字**的训练日志有三个具体问题：

```text
① 几十个损失值排成一列，看不出"哪一段在下降、哪一段在平台期"
② "最好的一步"要靠肉眼在一串小数里找，而它正是早停与回滚的判据
③ 两组配置对比时，读者要在两列数字之间来回数——条形图把这件事变成"看长度"
```

因此 `visualize` 提供了四张脸，而它们都遵守同一条纪律：**只做映射，不做判断**。

```text
sparkline(values)          一行迷你曲线（8 个档位）
loss_curve(values)         ASCII 折线（最上一行标注最大值、最下一行标注最小值）
bar_chart(pairs)           水平条形图（条长与数值成正比）
curve_summary(values)      一行：步数 / 首末 / 最好的一步与最坏的一步（**都带下标**）
```

### 10.2 现场读数

```text
sparkline : █▇▅▄▃▂▂▁▁▁▁▁
ASCII 折线:
      0.920000 |*
               | *
               |  **
      0.080000 |    ********
               +------------
                 第 1 步 → 第 12 步（抽样成 12 列）
条形图（最终准确率）:
    全开 |████████████████········| 0.687500
  无归一化 |████████████████████████| 1.000000
   无丢弃 |████████████············| 0.500000
12 步 | 首 0.920000 → 末 0.080000 | 最好第 12 步（0.080000）| 最坏第 1 步（0.920000）
```

### 10.3 第 ⑦ 条性质：图的极值位置必须等于 argmin / argmax

```text
通过 sparkline_matches_extremes | 读数 0.000e+00 == 0
    | sparkline（12 个字符） vs argmin = 10 / argmax = 9
```

读数是一个**整数**（不一致的项数）。它足够严格：把档位映射的方向写反
（最大值映成最低档）会让它立刻变成 2。

### 10.4 一条必须写下来的边界

文本图会**丢精度**（8 个档位、几十列宽）。因此它的定位是"日志的第一眼"，
而不是"读数的唯一来源"：**任何一个要写进结论的数都必须回到 `study` 的表里取。**

## 第十一章：消融表 —— 这张表**不**证明"正则化有用"

### 11.1 四个变体 × 两种单元

```text
rnn   | 全开     | 训练 0.666587 | 推理 2.240945 | 间隔 +1.574358 | 准确率 68.8% | 早停@2
rnn   | 无归一化   | 训练 0.005928 | 推理 0.003449 | 间隔 -0.002479 | 准确率 100.0% | —
rnn   | 无丢弃    | 训练 0.262312 | 推理 3.892314 | 间隔 +3.630002 | 准确率 50.0% | 早停@1
rnn   | 无调度    | 训练 0.612144 | 推理 1.344223 | 间隔 +0.732078 | 准确率 59.4% | 早停@2
lstm  | 全开     | 训练 0.018691 | 推理 0.000004 | 间隔 -0.018687 | 准确率 100.0% | —
lstm  | 无归一化   | 训练 0.017225 | 推理 0.000201 | 间隔 -0.017024 | 准确率 100.0% | 早停@38
lstm  | 无丢弃    | 训练 0.003022 | 推理 0.000001 | 间隔 -0.003022 | 准确率 100.0% | —
lstm  | 无调度    | 训练 0.024393 | 推理 0.000000 | 间隔 -0.024393 | 准确率 100.0% | —
```

### 11.2 怎么读这张表

**它不证明"正则化有用"。** 它证明的是三件更具体的事：

```text
① 四个旋钮每一个都被真的装上了（关掉一个，读数就变）
   ——否则八行会两两相同，而"两组一样"在读表时看起来像"这个旋钮没用"
② lstm 上四个变体都到 100% ⇒ 旋钮没有把它们弄坏
③ rnn 上带 BN 的三个变体都被**拉开**：间隔 +0.73 ~ +3.63
```

第 ③ 条是本课第二堵墙的读数。它的机制可以命名：**BatchNorm 让模型可以
利用"这一批里的相对关系"**——因为批统计量是所有样本的函数，"这一批里谁的 h_T 最大"
是一条模型能走通的捷径；而推理相用 running 统计量时，这条捷径就消失了。

```text
训练损失  0.666587（BN 那几组都能把"这一批"拟合得不错）
推理损失  2.240945（换到 running 统计量之后，之前学到的规则不再成立）
```

**这正是把两相分开报的理由。** 只报训练损失的话，`全开` 那一行看起来只是"学得慢一点"。

### 11.3 早停在这里做对了它该做的事

```text
rnn | 全开   早停@2     ← 推理损失从第 3 个 epoch 起就没再变好
rnn | 无丢弃 早停@1     ← 同上
lstm| 无归一化 早停@38   ← 几乎到最后一刻才触发（它一直在缓慢变好）
```

早停**只给建议**，不在循环里 break——因为"停下之后用哪一份参数"是调用方的决定
（day081 把 `best_step` 一起交出来，正是为此）。本课只记录、不回滚，并把这件事写进报告的 notes。

### 11.4 一个必须说清的边界

这是一个 **32 条样本、5 步序列、H=4** 的玩具任务。在这个规模上，
"正则化有没有用"这个问题**本身就不该被回答**——数据太少、任务太容易。
本课把它做成一个**读数**（每个旋钮的代价都出现在一列数字上），而不是一个结论。

## 第十二章：失败族与那条纪律

### 12.1 四个族，按"该谁去修"分

```text
ShapeError       形状不符      批的特征数 / γ β 长度 / 梯度形状对不上     → 改调用
ParameterError   参数越界      ε / momentum / rate / patience 非法       → 改调用
NumericError     数值不可用    非有限读数、统计量出现 nan                 → 改数据或改实现
PhaseError       相不成立      两相被配错、推理相缺 running 统计量        → 改调用
```

`PhaseError` 独立成族的理由在第四章写过：它处置的是"两个都合法的东西被配错了对"。

### 12.2 GradientError 的第五种理由

```text
day082~089   没有手写反向                 ⇒ 连续缺席八天
day090       有手写反向 + 自动微分         ⇒ 回来了（对账结论：这次训练不可信）
day092       消费梯度、不计算梯度          ⇒ 再次缺席（梯度被交给了上一步）
day093       算了梯度，但对账是离线校验     ⇒ 第三次缺席
day094       算了梯度，而且梯度真的会爆     ⇒ 第二次回来（运行期守卫）
day095       守卫**已经装好了，本课只是调用** ⇒ 再次缺席
```

同一个族在五天里有五种不同的理由在场或不在场。这条区分写进了
`errors.ABSENT_FAMILY_REASON`，并被 `test_returned_and_absent_families_are_constants`
逐字断言（`RETURNED_FAMILY is None` 且 `ABSENT_FAMILY == "GradientError"`）。

**"缺席要可断言"的意义就在这里**：一个"今天没有这一族"的结论，
如果不写成常量，就无法与"我忘了加"区分开。

## 结语：三条工程线索

1. **BN 的降级路径**：本课在小批上看到了 BatchNorm 的代价。生产里的三条降级路线
   都能在这里找到对应：换成 LayerNorm（沿特征，与批无关，day079 已实现）、
   换成分组归一化（在批与特征之间取一个折中）、或者干脆不做归一化——
   而**每一条路都要用本课这套读数去量**。
2. **旋钮的正交性**：本课的四个旋钮共用一套"读数 → 决策"的骨架
   （`RegularizationConfig` + `TrainReport`）。把"要不要用某个技巧"变成配置里的一项，
   比在每个训练脚本里复制一遍 if/else 更可靠——因为**配置可以被断言**。
3. **训练日志的位置**：本包的输出是四张文本图。把它接到本项目里
   day081 的 `training_study` 报告、或 day059 的 MLOps 流水线上，
   就是"看一眼就知道这次训练发生了什么"的第一层。

明天（day096）我们将进入 **PyTorch 高级与综合实践**：DataLoader、Dataset、
GPU 训练流程、模型保存/加载与推理封装，并把 M8 这七天串成一个端到端的小项目。
day095 留下的这套"旋钮 + 两把尺子 + 四张图"会在那一天被搬进真实的数据管线里。
