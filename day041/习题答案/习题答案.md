## 第一部分：选择题

### 第 1 题

**答案：D**

**解析**：定长（A）、归一化后余弦=点积且阈值可解释（B）、语义近则方向近（C）正是教程第一章的三条性质。D 错在两点：其一，维度高不等于检索准——语义质量取决于训练数据与目标，维度只是容量；其二，维度直接决定存储与检索成本（每条记录的字节数、余弦计算的乘法次数），生产选型要在质量与成本之间权衡，这也是教程给出 384/512/1536 多档模型对照表的原因。

### 第 2 题

**答案：B**

**解析**：SHA-256 是密码学哈希，核心性质是**雪崩效应**：输入改动一个字符，输出摘要面目全非。两句只差"喜欢/爱"两个字，摘要就完全不同，折算出的向量接近正交（实测约 0.05）。A 错——维度不是瓶颈，换成 1024 维的哈希照样没有语义；C 错——MockEmbedding 的问题与归一化无关；D 错——哈希不需要分词，字符级照样可以哈希，问题在于哈希本身不编码"重叠"信息。

### 第 3 题

**答案：B**

**解析**：`CharNgramEmbedding` 是**词汇层面**的表示：把文本切成字符 n-gram（n=2,3），每个片段哈希到桶并计数，最后 L2 归一化。两句共享"学习""机器""机器学习"等大量片段，计数向量方向接近，余弦相似度约 0.69。A 错——没有任何"理解"，这是纯字面统计；C 错——归一化后模长都是 1，相似度与长度无关；D 错——MD5 同样是雪崩效应，"相似输入产出相似摘要"恰恰不成立；相似的是**计数向量的方向**，不是任何单个片段的哈希值。

### 第 4 题

**答案：B**

**解析**：`text-embedding-3-small` 的官方规格：默认 1536 维、$0.02/1M tokens、支持 `dimensions` 参数截断（Matryoshka 表示学习）。A 把 `text-embedding-3-large` 的规格（3072 维、$0.13）安在了 small 上；C 错——输入上限是 8191 token；D 错——ada-002 作为旧版仍存在（1536 维、$0.10），只是不再推荐。

## 第二部分：判断题

### 第 5 题

**答案：对**

**解析**：`sentence-transformers` 依赖 torch，体积以 GB 计，绝不能做硬依赖。`SentenceTransformerEmbedding.__init__` 在 `model` 注入为空时才 `from sentence_transformers import SentenceTransformer`，`ImportError` 被转成带安装命令的 `RuntimeError`。效果：未安装者照常使用其他三个提供方，整个包的 import 不受影响；测试注入假模型对象，不下载权重即可覆盖全部逻辑。

### 第 6 题

**答案：错**

**解析**：`embed_batch` 是**带默认实现的具体方法**（默认逐条调用 `embed`），不是抽象方法。设计意图是向后兼容：既有提供方（`MockEmbedding`、`CharNgramEmbedding`）不覆写也能继续工作——逐条哈希本来就没有批处理收益；需要批处理收益的实现（神经模型一次前向、云端 API 一次 HTTP）才去覆写它。这与 day040 `supports_vision` 默认 `False` 是同一套"扩展抽象时让旧实现零改动"的哲学。

### 第 7 题

**答案：对**

**解析**：这正是 day041 修复的真值性陷阱。`InMemoryVectorStore.__len__` 返回记录数，空库长度为 0，布尔值为假；`store or InMemoryVectorStore()` 在传入空库时会走到右侧，把调用方的库静默换成新库——写入进了新库，调用方拿着旧库永远查不到。修复是显式 `store if store is not None else InMemoryVectorStore()`。教训：容器定义了 `__len__`/`__bool__` 后，默认值回退必须判 `None`，不能用 `or`。

## 第三部分：简答题

### 第 8 题

**参考答案要点**：

| 维度 | 本地 SentenceTransformers | 云端 OpenAI API |
|------|---------------------------|-----------------|
| 隐私 | 数据不出机器 | 文本发给第三方 |
| 成本 | 一次下载，永久免费 | 按 token 计费（$0.02/1M 起） |
| 延迟 | 取决于本机 CPU/GPU，无网络往返 | 网络往返 + 服务端排队 |
| 语义质量 | 受模型大小限制 | 通常更强（更大模型蒸馏） |

- **优先本地**：私有数据（医疗、法务、内部文档）的向量化——合规上不允许文本出机器；或离线/弱网环境的批量建库。
- **优先云端**：追求最高检索质量且数据不敏感的场景，如公开语料的语义搜索；或本机算力极弱（无 GPU 的轻量服务器）而语料规模大，本地编码耗时不可接受。

### 第 9 题

**参考答案要点**：

- **阈值只对真实语义有意义**：`MockEmbedding` 的相似度在 0 附近随机波动（雪崩效应），"低于 0.2 判为不相关"没有任何统计依据，阈值只是噪声过滤器；`CharNgramEmbedding` 与神经向量的相似度有可解释的梯度——同文为 1、共享片段/语义越多越接近 1、无关内容接近 0，阈值才对应"相关性的下限"。
- **不递补的理由**：检索的下游是 RAG 生成——把相似度低于阈值的结果硬凑进 top_k，等于把不相关上下文塞进提示词，轻则稀释答案质量，重则诱导模型胡说；返回更少（甚至空）让下游走"检索不到"的回退分支（day069 的 RAGGenerator 回退策略），比硬凑安全。**宁缺毋滥**是检索场景的正确语义。

## 第四部分：编程题

### 第 10 题

**参考答案**（可直接追加到 `tests/test_embedding.py`）：

```python
class RecordingEmbedding(EmbeddingProvider):
    """记录 embed 入参的最小提供方：验证 embed_batch 默认实现的契约."""

    def __init__(self):
        self.recorded: list[str] = []

    @property
    def dimension(self) -> int:
        return 2

    def embed(self, text: str) -> list[float]:
        self.recorded.append(text)
        return [float(len(text)), 1.0]


class TestEmbedBatchContract:
    def test_default_batch_calls_embed_in_order(self):
        emb = RecordingEmbedding()
        vectors = emb.embed_batch(["甲", "乙乙", "丙丙丙"])
        assert emb.recorded == ["甲", "乙乙", "丙丙丙"]  # 逐条、按序
        assert len(vectors) == 3
        assert all(len(v) == 2 for v in vectors)
```

**设计问答**：`embed_batch` 设计成"带默认实现的具体方法"，是为了**扩展抽象时不破坏既有实现**——如果它是抽象方法，`MockEmbedding`、`CharNgramEmbedding` 以及任何第三方提供方都必须立刻补写一个批量方法才能继续实例化，这是一次破坏性变更。带默认实现后：旧提供方零改动继续工作（默认逐条调用 `embed`，功能正确）；只有真正有批处理收益的实现（神经模型一次前向、云端 API 一次 HTTP）才覆写它。这与 day040 `supports_vision` 默认 `False`、`chat_vision` 默认抛错是同一套向后兼容哲学：**新增能力以"默认值"落地，而不是以"强制义务"落地**。
