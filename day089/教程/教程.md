## 第二章：神经元 —— 一次点积 + 一个偏置 + 一个非线性

### 2.1 一个神经元就三件事

```text
z = Σ w_i · x_i + b     （一次点积 + 一个偏置）
a = act(z)              （一个非线性）
```

本课把它写成记录 `NeuronSpec`，参数个数 = `inputs + 1`（权重 + 偏置）。演示读数：

```text
神经元：neuron(3→1) | 激活 relu | 初始化 zeros | 参数 4 | 前向 = 0.0
```

前向是 0.0 不是 bug：初始化是 `zeros`，而零权重的点积就是 0、`relu(0) = 0`。
这正说明"读一个标量看不出实现对不对"——

### 2.2 为什么需要那个非线性

```text
没有非线性    z₃ = W₃(W₂(W₁x + b₁) + b₂) + b₃ = (W₃W₂W₁)x + (…)   **还是仿射**
有非线性      z₃ = W₃·act(W₂·act(W₁x + b₁) + b₂) + b₃               无法再折成一层
```

第 8 章把这条写成一次矩阵乘，并逐点量出偏差。

## 第三章：六个激活 —— 一条口径表与三个数值稳定点

### 3.1 口径表（是否饱和 / 是否零中心 / 值域 / 公式）

```text
relu        max(0, x)                            不饱和、非零中心、[0, +∞)
leaky_relu  x if x > 0 else 0.01x                不饱和、非零中心、(-∞, +∞)
sigmoid     1 / (1 + e^{-x})                     饱和、  非零中心、(0, 1)
tanh        (e^x - e^{-x}) / (e^x + e^{-x})      饱和、  零中心、 (-1, 1)
gelu        0.5x(1 + erf(x/√2))                  不饱和、非零中心、[-0.17, +∞)
softmax     e^{z_i - max} / Σ_j e^{z_j - max}    不饱和、非零中心、(0, 1) 且行和为 1
```

tanh 是六个里**唯一零中心**的——这条口径差是"选哪个激活"的第一判据。

### 3.2 三个数值稳定点，每一个都对着一个可观察的坏结果

```text
sigmoid   按符号分支：x>=0 ⇒ 1/(1+e^{-x})、x<0 ⇒ e^x/(1+e^x)
          单式 1/(1+e^{-x}) 在 x=-1000 时要去算 e^{1000}：CPython 的 math.exp 直接抛
          OverflowError（numpy / torch 里则是 inf）；按符号分支后两端都只算 e^{≤0}
softmax   先减最大值：这是**恒等变形**（分子分母同乘 e^{-max}）
          不做它，z=1000 会去算 e^{1000}（同样抛 OverflowError）；做了它，
          得到 [0.2689414213699951, 0.7310585786300049] 这样的有限分布
gelu      用**精确 erf 式**（不是 tanh 近似）
          因为它与项目里已存在的实现（encoder_decoder.layers.activate 的 gelu、
          hf_source.blocks.gelu_exact）是同一个式子，于是跨天对账可以逐位
```

### 3.3 有限性：写死的网格，含 ±1000

```text
有限性网格（11 点）：[-1000, -100, -10, -1, -0.5, 0, 0.5, 1, 10, 100, 1000]
relu        非有限个数=0  min=+0  max=+1000
sigmoid     非有限个数=0  min=+0  max=+1
tanh        非有限个数=0  min=-1  max=+1
gelu        非有限个数=0  min=-0.158655  max=+1000
softmax     非有限个数=0  min=+0  max=+1
```

读数 `sigmoid(-1000) = 0.0`、`tanh(-1000) = -1.0` 是**饱和**（定义域代价），不是 nan。

### 3.4 值域：开区间与闭区间不是一回事（一个真实的陷阱）

```text
relu       [0, +inf)   闭下界：relu 真的取到 0
sigmoid    (0, 1)      双开：但在 x=±1000 上会饱和到 0.0 / 1.0
tanh       (-1, 1)     双开：同理
```

**因此值域检查不能在含 ±1000 的网格上做严格开区间断言**——
那是把"饱和"误报成"越界"。本课用两套网格：有限性用含 ±1000 的，
值域用有界的 9 点网格。演示读数：

```text
值域网格（9 点）：[-10, -5, -1, -0.5, 0, 0.5, 1, 5, 10]
六个激活越界个数全为 0
softmax 行和 = 0.9999999999999999（与 1 的偏差 1.110e-16）
softmax 每项落在 (0, 1)：(min=2.046773e-09, max=0.993023)
```

## 第四章：一层全连接 —— 与 `nn.Linear` 逐一对应

### 4.1 形状就是口径

```text
weight  (out_features, in_features)      ← 与 nn.Linear 一致
bias    (out_features,)                  ← nn.Linear(bias=True) 的默认
前向    y = x · Wᵀ + b                    ← 对每一行 x 都成立
参数    in_features × out_features + out_features
```

**"Wᵀ"不是笔误**：`nn.Linear` 的内部权重形状是 `(out, in)`，前向做的是
`x @ W.T + b`。本课用同一个约定，因此演示里能直接比较：

```text
一层账：{'in_features': 3, 'out_features': 4, 'weight_shape': '(4, 3)', 'weights': 12, 'biases': 4, 'total': 16}
输入 ((0.3, -0.7, 1.1),)
affine 输出 ((-0.9379341873172151, -1.6127885871584553),)
gelu 输出   ((-0.1633310305907053, -0.08611520664135948),)
两步（affine → 逐行 gelu）与一步一致：True
```

最后一行是一条结构性质：带激活的一层 = 先 affine 再逐行激活，**两步与一步逐位一致**。

### 4.2 累加方式要对齐，否则逐位对账会失败

本课的 `dense_linear` 用 `math.fsum` 累加，与项目里前馈的累加方式**相同**：

```python
math.fsum(unit * value for unit, value in zip(weight_row, row)) + bias
```

这不是"随便挑了一个更精确的求和"——而是为了第 10 章的**逐位**对账。
换一个求和顺序，两个实现会在最后一位上分家，而"最后一位不同"与"实现写错了"
在读一个标量时**看不出来**。

## 第六章：五种初始化 —— LCG + 四种尺度

### 6.1 可复现是前提，不是附加项

```text
state ← (1103515245 · state + 12345) mod 2^31        glibc 的 LCG 常数
u     ← state / 2^31                                 落在 [0, 1)
```

种子注入到每一条 `DenseSpec`，因此"同一份 spec 得到同一组权重"是可断言的。
演示读数（同一份 `4 → 3` 的 spec、同一个种子）：

```text
zeros     W[0][0]=+0.000000 b[0]=+0.000000
uniform   W[0][0]=+0.069327 b[0]=-0.416808
normal    W[0][0]=-0.026966 b[0]=+0.199829
xavier    W[0][0]=+0.128369 b[0]=-0.771779
he        W[0][0]=-0.038135 b[0]=+0.282601
xavier 半宽 a = sqrt(6/(4+3)) = 0.925820
he 标准差 = sqrt(2/4) = 0.707107
```

### 6.2 四种尺度，各自看什么

```text
uniform   U(−1/√fan_in, 1/√fan_in)          尺度只看 fan_in
normal    N(0, 1/√fan_in)                   Box-Muller 从 LCG 造
xavier    U(−a, a)、a = √(6/(fan_in+fan_out)) 同时看两侧的宽度
he        N(0, √(2/fan_in))                  为 ReLU 一族设计
```

`zeros` 的读数全为 0，而它有一个**具体后果**：每个神经元学到的东西完全相同
（对称性不破）——因此它只适合对账。

### 6.3 xavier 分母为 0 的坑

```text
xavier 的尺度 = √(6 / (fan_in + fan_out))
当 fan_in + fan_out = 0 时，上式没有定义
```

本包当场抛 `InitializationError`（而不是让它崩成 `ZeroDivisionError`）——
因为"这一层没有宽度"与"随机崩了"是两种不同的诊断。

## 第七章：一个网络 —— 前向与 `forward_trace`

```text
x → Dense_1 → act_1 → Dense_2 → act_2 → … → Dense_n →（可选 act_n）
```

`MLPSpec` 在构造时就检查"相邻两层宽度接得上"，接不上抛 `ForwardError`
（**结构**问题，不是某一次调用的形状问题）。`forward_trace` 只把**接口**写下来：

```text
网络 MLP 4→8→3 | 2 层 | 参数 67
前向账：4 → 8 → 3 | 层形状 4 -> 8、8 -> 3
第 1 层 dense(4→8) | W (8, 4) | 权重 32 + 偏置 8 = 40
第 2 层 dense(8→3) | W (3, 8) | 权重 24 + 偏置 3 = 27
参数总数 67
```

参数是**加出来**的：`40 + 27 = 67`，不是估的。

## 第八章：结构事实一 —— 恒等激活的多层网络塌缩成仿射

### 8.1 它是一次矩阵乘，不是一个比喻

```text
x·W₁ᵀ + b₁  再  ·W₂ᵀ + b₂   =   x·(W₂·W₁)ᵀ + (b₁·W₂ᵀ + b₂)
```

`compose_affine` 把一串 `(W, b)` 折成一个。演示读数（`3 → 4 → 5 → 2`、全恒等）：

```text
多层输出 ((0.35264764058789555, -0.06055667669721776), (3.9362572681318193, 2.689106583018261))
单层输出 ((0.3526476405878956, -0.06055667669721798), (3.936257268131819, 2.68910658301826))
最大偏差 8.882e-16 <= 容差 1e-12：True
```

偏差不是 0（浮点合成有舍入），但被 `1e-12` 的界兜住——这就是 `CrossCheck` 带
`upper_bound` 字段的用处：这一条是**上界**判据，不是"相等"判据。

### 8.2 这条事实的反证

```text
只要有一层带激活（不是 None），塌缩就抛 ParameterError
```

因为这条等式只在仿射映射上成立。**"多层比一层强"的全部来源，就是那个非线性。**

## 第九章：三个损失与交叉熵的两条路径

### 9.1 三个损失

```text
mse            mean((pred − target)²)     预测等于目标时**恰好**为 0.0
mae            mean(|pred − target|)
cross_entropy  −log softmax(logits)[target]
```

演示读数：

```text
mse            = 6.250000e-01
mae            = 7.500000e-01
cross_entropy  = 2.407606e+00
perplexity(1.0) = 2.718282
```

`mse` 的"恰好 0"是一条硬判据：`mse(P, P) = 0.0`——不是"接近 0"。
任何多余的正则项或错误的分母都会让它不再是 0。

### 9.2 两条路径，以及它们为什么不是逐位

```text
路径 A（稳定）  −log_softmax(logits)[target]
路径 B（直白）  −log(softmax(logits)[target])
```

演示读数：

```text
logits=(1.0, 2.0, 3.0) target=0    | A=2.407605964444 B=2.407605964444
logits=(10.0, -10.0, 0.0) target=1 | A=20.000045400960 B=20.000045400960
两条路径最大偏差 4.441e-16（容差 1e-12：一条走 sum、一条走 fsum）
```

偏差 4.441e-16 的来源是**刻意的**：A 的 `log_softmax` 用内置 `sum`（对齐 `sft.loss`），
B 的 `softmax` 用 `math.fsum`（对齐 `math_foundations`）。两处求和各自服务一个对账对象，
因此这一条的判据是"偏差 <= 1e-12"，而不是"相等"。

### 9.3 为什么在极端点上必须走稳定路径

```text
logits = (-1000, 0)，target = 0
路径 B：softmax 把第一项下溢成 0.0 ⇒ −log(0) 没有定义
```

本包在 `cross_entropy_via_probability` 里当场抛 `LossError`：
"概率为 0 取 log"不被允许以 `-inf` 的形式混进平均值里。

## 第十章：结构事实二 —— FFN = Dense → 激活 → Dense（接回 M7）

### 10.1 Transformer 的前馈块不是新东西

```text
dense_1：x (n, d) → (n, 4d)      ← 先扩张 4 倍
激活：   relu / gelu（逐行）
dense_2：(n, 4d) → (n, d)        ← 再压回来
```

本课的 `ffn_block` 接受任何"有 `w_in / b_in / w_out / b_out` 四个属性"的对象，
因此可以把项目里真实的 `encoder_decoder.types.FFNWeights` 直接传进来，与
`encoder_decoder.layers.feed_forward` 对账。演示读数：

```text
hidden=4、d_ff=16
[relu] 本包第 0 行 (0.7517430751343896, -0.10007198360943836, -1.2085595550078807, -0.36658339458837097)
[relu] 项目第 0 行 (0.7517430751343896, -0.10007198360943836, -1.2085595550078807, -0.36658339458837097)
[relu] 逐位不一致 0 个
[gelu] 逐位不一致 0 个
```

### 10.2 为什么能逐位，而不是"容差内相近"

```text
① 权重是同一组对象   ffn_block 直接用 FFNWeights 的四块，不重新初始化
② 形状约定相同       w_in (d_ff, d)、w_out (d, d_ff)，前向 x·Wᵀ + b
③ 累加方式相同       都用 math.fsum，且乘法顺序相同
④ 激活公式相同       relu = value if value > 0 else 0.0；gelu = 精确 erf 式
```

四条里少任何一条，两个实现都可能在最后一位分家——而"最后一位不同"会被误读成"接错了"。

```text
    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

```

### 11.2 这个坑值钱在哪

```text
表面     "少了一个逗号"——报错信息甚至这样提示
真相     那一行里出现了三个 ASCII 双引号：字符串提前结束、后面的中文成了语法错误
```

它值钱的地方在于**它不是一个缩进或逗号问题，而是一个"文本里的字符"问题**：

```text
Python 的字符串定界符是 ASCII 双引号 ""
而中文里最自然的强调方式也是引号——两者长得像，语义完全不同
```

修法不是加逗号，而是把内层的引号换成不参与定界的全角引号：

```python
"这不是「数值误差」，而是它们作为激活在两端的**定义域代价**——因此才有 relu 一族。"
```

## 失败族的第五次换理由

```text
day075~081   有手写反向            ⇒ 有 GradientError 那一族
day082~089   没有手写反向          ⇒ 这一族连续缺席八天
```

今天的理由与前四天的**都不同**：

```text
day085   只读别人的推理路径（HF 的反向由 autograd 推出来）
day086   装进来的层都是别人写好的，全部落在前向之外
day087   量化不可微（round 的导数几乎处处为 0）
day088   本日一个新式子都没有：全部动作是跨包对账与串联
day089   今天**有新式子**（六个激活的前向、三个损失），它们每一个都可微，
         看上去"该有梯度"了——但本课手写反向一行都没有，
         也没有调用自动微分（本仓库不依赖 torch）。反向传播是 day090 的主题。
```

而今天新增的四个族，各自要改的东西都不同：

```text
ActivationError       "这一组数配这个激活不成立"   换激活或缩放输入
LossError             "这一批没有可用的监督信号"   补样本 / 改标签 / 在定义域外先拒绝
ForwardError          "这一摞层的接口对不上"       改网络结构
InitializationError   "这一层的宽度让尺度没有定义"  先决定这一层的宽度
```

`LossError` 值得单独说一句：把它静默兜成 `0.0` 的后果是——
"这一批全被屏蔽了"与"这一批学得完美"在报告里都写成 `loss = 0`，
而前者恰恰是最需要被发现的训练故障。

## 边界与后续

### 五条边界（**本课明确不承诺的事**）

```text
① 本包实现的是**前向与损失**，一行反向都没有：反向传播是 day090 的主题
② 本包不安装、也不调用 torch / numpy：PyTorch 的语义只写在 TORCH_COUNTERPARTS 对照表里，
   对照的是公式与语义，不是"实测 torch 输出"；具体版本以官方文档为准
③ 六个激活只覆盖课程口径下的那一组（relu / leaky_relu / sigmoid / tanh / gelu / softmax）
④ 权重由 LCG 生成、输入写死，因此复现的是**读数**、不是统计规律
⑤ 不承诺浮点意义上的"位逐位跨平台一致"——跨天对账的容差由各自的口径给出
```

### 两个悬念

```text
反向传播   今天每一个前向算子都可微（sigmoid、tanh、gelu、softmax、CE），
           但一行反向都没有——day090 会把 "谁对谁的导数" 逐一算出来
自动检查   七条性质已经可断言；下一步是"每次改动都重跑这七条"——那是 CI 的事
```

今天最值得带走的三句话，与前几天那几句对着看：

```text
day086  "因果 ⇒ 填充惰性"只在**单条样本内**成立              —— 装进来才撞上的工程事实
day087  缓存不是"变快"而是"换"；位置必须由**缓存长度**决定    —— 做减法才撞上的两件事
day088  原理只有落到一个**能被解析的函数**上、并且能被**现场量出读数**，才算真的串起来了
day089  深度本身不产生非线性：让"多层"区别于"一层"的，是**那个激活函数**
```

四句都是"一句话 + 一个能失败的判据"，而今天这一句的判据就是第 8 章那个
`8.882e-16`：把激活换成恒等，多层与单层的偏差立刻缩小到 0 附近。
