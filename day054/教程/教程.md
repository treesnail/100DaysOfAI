## 第一章：为什么 SFT 之后还要"对齐"

### 1.1 一条分界线

day048~day052 的 SFT 数据是"输入 → 唯一输出"，day053 的评估数据是
"输入 → 参考答案 + 合格判定"。它们的共同前提是**答案有对错**。
而偏好数据只告诉你"A 比 B 好"——**这正是对齐与监督微调的分界线**：

```text
SFT 教模型"该怎么答"     → 模仿训练集里的那个唯一答案
对齐教模型"更偏好哪一种" → 在两种都说得通的答法里选一种
```

同一个提问往往有很多"都说得通"的回答："信息更全"的那个通常更长，
"更简洁"的那个通常更短——两个都对，但**偏好哪一个**是一个 SFT 回答不了的问题。

### 1.2 本课的五个对齐维度

"更偏好哪一种"这句话太笼统，必须拆成**维度**。本课固定五个
（`preference.ALIGNMENT_DIMENSIONS`）：

| 维度 | 一句话 |
|------|--------|
| `citation` | 给出处：结论要能指回具体文件或文档位置 |
| `format` | 格式合规：按段落标记组织（结论 / 依据 / 风险） |
| `conciseness` | 简洁：同样信息量下更短 |
| `refusal` | 安全边界：越界请求拒答，且不给可执行步骤 |
| `honesty` | 不编造：不确定就说不确定 |

**为什么必须把维度写在数据里**：偏好标注的分歧几乎总发生在"维度不明确"的时候——
同一条回答在"信息更全"上更好、在"更简洁"上更差，标注者按各自的维度打分
会得到相反的结果。把维度写进每条样本，是**降低标注噪声最便宜的手段**
（比增加标注人数便宜得多）。

## 第二章：偏好数据——chosen / rejected 与四道体检

### 2.1 一对样本的样子

```python
@dataclass(frozen=True)
class PreferencePair:
    id: str
    prompt: str
    chosen: str      # 更被偏好的回答
    rejected: str    # 更差的回答
    dimension: str = "honesty"
```

12 条手写种子样本（`SEED_PAIRS`）覆盖五个维度，每条都围绕 SmartResearch Agent 场景，
且**差别必须"能指出来"**——少了出处、少了段落标记、多了一句废话、该拒答却给了步骤、
用编造的数字把话说圆。例如 `pref-honest-01`：

```text
chosen  ：每设备 75.31 GiB（权重 12.55 + 梯度 12.55 + 优化器状态 50.20），
          单张 24 GB 卡放不下。
rejected：大概 20 GB 左右吧，4 卡的话显存压力不大，单卡 24 GB 应该够用。
```

### 2.2 体检一：`chosen == rejected` 必须直接报错

`validate` 里对"规范化后两侧相同"直接抛错，而不是留到训练时表现成
"loss 一直等于 ln 2"：

> **一对相同的样本在 DPO 里不产生任何梯度**（margin 恒为 0），
> 而它在数据统计里仍然计一条——分母被稀释，训练看起来"跑过了"却什么都没学到。

### 2.3 体检二：长度偏置——偏好数据里最经典的混淆变量

如果 chosen 系统性比 rejected 长，奖励模型（PPO）或策略（DPO）首先学会的就是
"**长 = 好**"，而它在评估里表现为"更啰嗦但没更对"。`length_bias_report` 输出
`chosen_longer_fraction`、`mean_length_ratio` 与**逐维度分解**。

本课种子数据的实测是一个活例子：总体 `chosen_longer_fraction = 0.8333`（看着像严重偏置），
拆开看是两个方向相反的合力：

```text
citation / honesty   chosen 更长（要写出处、要说明不确定性）—— 维度本身决定，不是偏置
conciseness          chosen 更短（这一维度的目标就是更短）—— 恰好抵消了一部分
```

**为什么必须有逐维度分解**：总量上的长度偏置会被"维度混合"放大或掩盖，
只在总量上看到 0.8333 会误判"数据全是长度偏置"。

### 2.4 体检三：近似重复——这一对没有信息量

`near_duplicates` 用规范化字符 3-gram 的 Jaccard（阈值 `NEAR_DUPLICATE_THRESHOLD = 0.9`）
挑出"chosen 与 rejected 几乎一样"的样本：**两者的差别小于噪声时，模型学不到任何东西**。

### 2.5 体检四：指纹——这次对齐用的是哪一份数据

`preference_fingerprint` 与 day053 的评估集指纹是同一条纪律（规范化 JSON + `sha256` 前 16 位）。
对齐结果必须能指回"这次用的是哪一份偏好数据"，否则换一批数据之后旧的结论就说不清了。

### 2.6 分层切分

`split_preferences` 与 day053 的评估集切分同源：**按维度分层**，验证集不能为空。
`DEFAULT_VALID_RATIO = 0.25`。理由很具体——偏好准确率是"留出数据"上的判据，
训练集上的 margin 会单调地涨（那是被直接优化的量），只有留出数据能回答"涨到哪有害"。

## 第三章：DPO 的数学——隐式奖励与 ln 2 起点

### 3.1 两个目标，差别在"偏好怎么进到策略里"

```text
RLHF（PPO）：偏好 → 训一个奖励模型 r(x,y) → 用强化学习最大化 E[r] − β·KL(π_θ ‖ π_ref)
DPO       ：偏好 → 直接在策略上做监督式优化
             −log σ( β·[(logπ_θ(y_w) − logπ_θ(y_l)) − (logπ_ref(y_w) − logπ_ref(y_l))] )
```

### 3.2 DPO 的括号与 loss

`dpo_margin` 算的是括号（**不含 β**）：

```python
margin = (policy_chosen - policy_rejected) - (reference_chosen - reference_rejected)
```

四个参数都是**对数概率**（整条序列的逐 token 对数概率之和）。把 β 留到 loss 里乘，
是为了让 margin 保持"纯数据"的语义：**换 β 不改变 margin，只改变它对 loss 的影响强度**。

```python
def dpo_loss_from_margin(margin, *, beta):
    return -log_sigmoid(beta * margin)     # = -log σ(β·margin)
```

三种情况都必须看得见：

```text
margin = 0    → ln 2（0.6931）
margin 很大   → 趋近 0
margin 很负   → 趋近 −β·margin（线性增长）
```

第三种尤其重要：**一条被写错的偏好样本（chosen 其实更差）会给出很大的 loss，
而它不该被任何"数值保护"悄悄压平。**

### 3.3 ln 2 起点自检——本课最值钱的一行数字

未训练时策略就是参考模型，括号里的差为 0，于是：

```text
−log σ(0) = ln 2 ≈ 0.6931    （ZERO_MARGIN_LOSS）
```

它是一条**接线检查**：**如果你的 DPO loss 一开始不是 ln 2，那么你的 ref 或 β 接错了**——
这类错误在训练日志里只表现为"loss 有点怪"。`pipeline` 在第一步之前就检查它
（容差 `ZERO_MARGIN_TOLERANCE = 1e-9`）。

### 3.4 隐式奖励——DPO 名字里没明说的那一半

```python
def implicit_reward(logprob, reference_logprob, *, beta):
    return beta * (logprob - reference_logprob)     # r(x,y) = β·log(π_θ/π_ref)
```

**DPO 并不是"不需要奖励"**，而是把奖励定义成策略与参考模型的对数概率比。
由此得到三个推论：

```text
- 参考模型一动，全部隐式奖励一起平移（所以参考模型必须冻结）；
- β 同时缩放奖励与 KL 约束，两者没法独立调；
- 训练初期（π_θ = π_ref）所有隐式奖励都是 0——这就是 loss 恰好为 ln 2 的另一面。
```

### 3.5 数值稳定：按符号分支，不做截断

`sigmoid` / `log_sigmoid` / `softplus` 都按符号分支实现。**截断会把"margin 很大"
这种正常情况变成一个假的常数**，而真正的解法是在数学上避免 `exp` 溢出：

```python
def log_sigmoid(value):
    if value >= 0:
        return -math.log1p(math.exp(-value))       # = log σ(x)
    return value - math.log1p(math.exp(value))     # 避免了 exp(x) 上溢
```

### 3.6 梯度：越接近最优，步长越小

```python
def dpo_gradient(margin, *, beta):
    return -beta * sigmoid(-beta * margin)          # ∂L/∂margin
```

margin 为 0 时等于 `−β/2`（一半的步长），margin 很大时趋近 0。**这正是"越接近最优、
梯度越小"的自适应行为**，也是 DPO 比"用正确/错误做监督"更稳的原因之一。

### 3.7 β 只能实测标定

β 同时出现在两个地方：它是 DPO loss 里的"温度"，也是梯度系数 `−β·σ(−βm)` 的一部分。
"β 越大策略偏离参考模型越少"这句常见说法在本课的实测里**并不成立**——
固定学习率与步数时，KL 随 β **先升后降**：

```text
β = 0.05 → KL 0.0125     β = 0.5 → KL 0.4460     β = 2.0 → KL 0.4987
β = 0.1  → KL 0.0449     β = 1.0 → KL 0.5940
```

β 大则早期步长大，但 margin 一大梯度就迅速衰减，反而早早刹住。
所以 β 只能实测标定——`BETA_SOFT_RANGE = (0.01, 5.0)` 只是常用量级的提示，不是可选的界。

## 第四章：RLHF（PPO）与 DPO——KL 的两种写法

### 4.1 同一个约束的两种写法

RLHF 的目标里有显式的 KL 惩罚 `E[r] − β·KL(π_θ ‖ π_ref)`，
DPO 把它藏进了"与参考模型的对数比"里。两者是同一件事的两种写法，
`objectives.objective_requirements` 把差别做成了数据：

```text
RLHF（PPO）需要：奖励模型 + 在线采样（rollout） + 参考模型
DPO 需要       ：偏好数据 + 参考模型（不需要奖励模型、不需要 rollout）
```

代价也对称：DPO 便宜，**便宜的地方正是它信息少的地方**——隐式奖励是闭式量，
无法像 PPO 的奖励模型那样被复用到别的用途。

### 4.2 KL 的三个估计器——"看起来都对"的坑

`kl_estimators` 对每个样本给出三个估计器（`KL(π_θ ‖ π_ref)`）：

```text
k1 = log p − log q
k2 = 0.5 · (log p − log q)²
k3 = exp(r) − r − 1         其中 r = log q − log p
```

三者的取舍是本课最典型的"三个都像正确答案"的场景：

```text
k1  有偏且可能为负——单样本的 log 比可以是负数，于是"KL 惩罚"偶尔会奖励偏离；
k2  恒非负，但方差大（把 log 比平方，放大了离群样本）；
k3  恒非负、方差最小、无偏（Schulman 提出的那一个），代价是它需要 exp。
```

本课报告里**三个都报**（缺省用 `k3`），因为"只报一个"会掩盖它们的分歧：
训练早期 k1 常常给出负数，而 k3 已经稳定为正。

### 4.3 奖励塑形与最优策略

`reward_with_kl_shaping` 是 PPO 里"把 KL 惩罚折进奖励"的写法：

```python
return reward - beta * (logprob - reference_logprob)    # r(x,y) − β·(logπ_θ − logπ_ref)
```

它与 DPO 的关系值得说清：把上式对策略取期望、并把奖励模型换成 DPO 的隐式奖励，
两条路径在数学上会汇合到**同一个最优策略**：

```text
π* ∝ π_ref · exp(r / β)
```

## 第五章：真的走几步 DPO——参考模型冻结与梯度符号

### 5.1 两个独立对象

`dpo_trainer` 用的是 day050 的 bigram 参考模型，但**策略与参考模型是两个独立对象**：

```text
参考模型（reference）  冻结，永不更新，它的对数概率是隐式奖励的基准
策略（policy）         初始化为参考模型的副本，DPO 只更新它
```

于是"未训练时 loss = ln 2"这条起点检查成立：两者逐位相同，括号里的差恰好为 0。

### 5.2 梯度怎么来，以及那个负号

```text
L = −log σ(β·m)              m = (l_c − l_r) − (r_c − r_r)
∂L/∂l_c = −β·σ(−βm) =: g     ∂L/∂l_r = +β·σ(−βm) = −g
∂logp/∂logits_t = onehot(y_t) − softmax(logits_t)      ← 注意方向
⇒ chosen 的每个位置累加 (−g)·(softmax − onehot)
  rejected 的每个位置累加 (+g)·(softmax − onehot)
```

**上面那一行的符号是本课踩过的坑**：`softmax − onehot` 是**交叉熵**的梯度
（`∂(−log p)/∂logits`），而 DPO 需要的是**对数概率**的梯度，两者相差一个负号。
于是"把 chosen 的梯度乘 g 直接累加"会让 p(chosen) 一路下降、p(rejected) 一路上升——
loss 从 `ln 2` 单调涨到几十，而代码没有任何地方报错。

本课实测（符号修正前）：**12 步后 loss 0.693 → 0.716、验证准确率从 0 掉到 0.2**；
修正后方向才对。这也解释了为什么起点检查必须写成断言：
**起点 loss = ln 2 在两种符号下都成立**（那时 margin 恰好为 0，方向还没显形），
只有走几步才能看出来。

### 5.3 只用公开 API

整个训练器**没有碰任何私有字段**：读参数用 `state_dict()`、写参数用 `load_state()`、
前向用 `logits()`。这不是洁癖——它意味着"换一个模型就能换一个训练对象"
（day051 的 `LoRAReferenceModel` 同样满足这组接口），也意味着测试不需要任何 mock。

## 第六章：离线的对齐信号——偏好准确率、policy KL、GAE

### 6.1 一个边界先说清

`reward` 里的"奖励"是 DPO 的**隐式奖励**（闭式，见 3.4），**不是 PPO 里那个训练出来的
奖励模型**。它是一个只要有两个模型与一段文本就能算出来的量，不需要采样、
不需要 rollout——这正是 DPO 相比 PPO 在工程上"便宜"的地方。

### 6.2 偏好准确率——对齐训练唯一的离线判据

```text
判据：隐式奖励之差 > 0，也就是 σ(β·margin) > 0.5
```

**为什么必须用留出数据**：训练集上的 margin 会单调地涨（那是被直接优化的量），
用训练集 margin 当早停判据，等价于"训练 loss 降到 0 就停"——
对齐任务里这两件事之间的差距比 SFT 大得多。`preference_accuracy` 返回
`total` / `correct` / `accuracy` / `by_dimension`，**分母交出来**。

### 6.3 policy KL 与过优化体检

`policy_kl` 量的是策略相对参考模型偏离了多少。`over_optimization_flags`
用三条判据把"过优化"做成可读的旗标（对应 `ALIGNMENT_RISKS` 里的"过优化"风险）：

```text
训练 margin 一路涨，留出偏好准确率先升后降；格式与出处开始丢
```

`DEFAULT_KL_BUDGET = 0.5` 定义在 `reward` 而不是 `dpo_trainer`，理由是**避免循环导入**：
KL 预算是"读历史"的判据，训练器只负责把历史交出来。

### 6.4 GAE——PPO 用来加权梯度的那一项

`gae_advantages` 保留在这里（而不是删掉），因为它是理解 PPO 目标的必要一环：
PPO 用**优势**而不是回报来加权策略梯度，而优势里那个 `γλ` 决定了"奖励归因到多远"：

```text
DEFAULT_GAMMA = 1.0    折未来奖励
DEFAULT_LAMBDA = 0.95  折优势的自举（两个都取 1 退化为"回报减基线"，取 0 只看即时奖励）
```

## 第七章：对齐策略——样本量、κ 与四个风险

### 7.1 要多少样本：先算再开工

偏好数据的边际成本很高（每条都要人读两个回答），而"要多少条才够"是一个纯粹的
样本量问题。`pairs_for_margin` 用"二元比例 vs 0.5"的样本量公式（正态近似），
`DEFAULT_TARGET_ACCURACY = 0.6`（让偏好准确率从"抛硬币"提升到 60% 可被检出）。

一个必须写清楚的近似：公式回答的是"想在偏好准确率上分辨出 60% 与 50%，
需要多少条**独立**样本"。真实情况更复杂（配对、分层、标注噪声），
所以本课把它当作**下界**——算出来的数偏小，不会偏大。

`Z_BY_ALPHA` / `Z_BY_POWER` 是**查表**（`z = 1.96` 这类每个人都认识的数字），
不引 scipy——与 day053 拒绝统计库是同一条理由：这一节要能被手算核对。

### 7.2 标注一致性 κ——放量之前先双标一小批

`annotator_agreement` 算 Cohen's κ，`interpret_kappa` 给出解释（`< 0.4` 表示一致度低到
数据不可用）。它对应"维度混淆"风险：**每条样本标注 dimension，双标一小批算 κ 再放量**。

### 7.3 四个主要风险（做成数据）

`ALIGNMENT_RISKS` 把四个风险做成可测试、可返回、可渲染的数据：

| 风险 | 症状 | 检测 |
|------|------|------|
| 长度偏置 | chosen 系统性更长，模型学会"越长越好" | `length_bias_report.chosen_longer_fraction` |
| 过优化 | margin 一路涨、留出准确率先升后降 | `over_optimization_flags` 三条判据 |
| 维度混淆 | 标注者一致度低（κ < 0.4） | `annotator_agreement` 的 κ |
| 参考模型漂移 | 隐式奖励整体平移，前后 margin 不可比 | 报告里的 reference 哈希与数据指纹 |

几条值得记的测试写法：

1. **起点检查写成断言**：`dpo_loss(margin=0) == ln 2`。它在两种符号下都成立，
   所以还必须有"走几步之后方向要对"的用例（见 5.2 的那个负号）。
2. **手算值写进断言**：`ln 2 ≈ 0.6931`、`σ(0) = 0.5`、`k3` 的 `exp(r)−r−1`。
   没有手算值，"公式写错了但看起来合理"不可能被发现。
3. **不变式优于样例值**：`sigmoid(x) + sigmoid(-x) == 1.0` 这类恒等式，
   能证明"这一类输入都对"。
4. **分母交出来**：`preference_accuracy` 返回 `total` / `correct`，`dpo_step` 返回

## 结语：三条可以带进 DPO 实践（day055）的工程结论

1. **偏好数据要先过体检，再进训练。** 长度偏置、近似重复、chosen==rejected
   这三类样本不会报错，只会让"长 = 好"或"什么都没有学到"悄悄渗进模型。
   本课最深的坑（梯度符号）**在两种符号下 loss 都等于 ln 2**，
   只有"走几步之后方向要对"这条用例能抓住它。
   **起点检查是必要的，但不够。**

2. **隐式奖励是 DPO 便宜的地方，也正是它信息少的地方。**
   `r = β·log(π_θ/π_ref)` 是闭式量，不需要奖励模型、不需要 rollout；
   代价是它无法像 PPO 的奖励模型那样被复用。所以"选 DPO 还是 PPO"
   本质是在"工程成本"与"奖励信号的可复用性"之间做取舍。

3. **对齐的验收标准不是"会不会"，而是"更偏好哪一种"。**
   这意味着两件事必须先做：说清偏好的是哪几个维度（否则标注一致度低到数据不可用），
   以及提前算样本量（否则开工之后才发现"要分辨 60% 与 50%"这件事根本没希望）。

> **诚实的说明**：本课是**离线、确定性、零 GPU** 的——所有数字（loss、margin、
> 隐式奖励、KL、偏好准确率）都在上下文长度为 1 的 bigram 参考模型上算出，
> 每一步都能手算核对。它们**不代表 7B 模型的行为**：真实对齐的过优化、KL 漂移
> 取决于数据量、β、学习率与参考模型规模。本课要传达的是"这些信号存在、可算、
> 能区分接线错误与方向错误"，以及 day055 会接手的那件事——**偏好数据从哪来**。

明天（day055）进入 **DPO 对齐实践**：把今天讲透的公式落成一次真的能跑、
可复现、可审计的对齐工程——偏好数据的**构造流程**（拒绝采样 vs 规则劣化）、
TRL 配置的离线镜像、以及三种 DPO 损失的取值 / 梯度 / 数值核对。
