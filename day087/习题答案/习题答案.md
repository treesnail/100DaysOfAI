## 一、选择题

**1. B。** 缓存不改变精确性（K/V 是同一批数，逐位相同），它换的是**时间**：
把每步的计算量从 O(T) 降到 O(1)，代价是 O(T) 的**显存**。
C 说反了——存的就是投影之后的 K/V；D 错在缓存只作用于推理。

**2. B。** `2 · L · T · h · bytes`：那个 2 是因为缓存里存了**两**张表（K 与 V）。
C 把层数漏了（差一个整数倍），A 把那个 2 漏了（差一半）——两种错法都只会在
**某一个长度**上碰巧对，因此本课在五个长度上各核一次。

**3. B。** 两条路径的算术**逐字相同**（都走 day085 的 `project` / `split_heads` /
`row_softmax` / `merge_heads`），因此必须逐位相同。允许"数值相近"的后果是：
"在归一化之前取 K/V"这类错法会以"误差很小"的形式漏过去。

**4. B。** 位置由**缓存长度**决定。这是本课第一个真实撞上的坑：
按行内下标编号（`range(len(row))`）时，一步只有一个 token ⇒ 位置永远是 0。
真实实现里的说法是"缓存必须带 `position_ids`"。

**5. B。** 它从 `round` 的误差 ≤ 0.5 格推出，两条前提是
"每个元素都落在量程内"（否则取整会夹断）与 `scale ≠ 0`（整块同值）。

**6. B。** 粒度只在**行与行的动态范围差得很大**时才明显有效：
本课在带离群值的样本上量到 1.9~2.2 倍，而在每行分布相同的权重上只有 1.2 倍。

**7. B。** 只在"请求条数 ≤ 批大小"（槽位够用）时成立。
本课的一组读数就是反例：长度 `[9, 2, 5, 1, 7]`、批大小 3，
下界是 9 步而**实际 10 步**——第 5 条请求要等第 3 条腾出位置才进得来。

## 二、简答题

**8.** 存投影之后的 K/V，是为了让**每步只投影新的一行**：

```text
存 hidden state（归一化之后）   每步要把前面 T 行再投影一遍 ⇒ 每层 O(T·h²)
存 K/V（投影之后）              每步只投影 1 行           ⇒ 每层 O(h²)
```

两者差的不是一个常数，而是 `T` 倍——**它正是缓存省下的另一半收益**
（另一半是打分次数那一侧：T(T+1)/2 → T）。

而"归一化之后"这一条是**必须的**：pre-LN 块里注意力吃的是 `ln_1(x)`，
在归一化之前取 K/V，形状一模一样、数值全变。

**9.** 两条跨天对账：

```text
① 缓存 vs 整段      cache.compare_with_recompute ↔ hf_integration.forward.logits
                    比法：**逐位**（==）
                    抓的错法：在归一化之前取 K/V、K 与 V 弄反
② prefill vs 整段    cache.prefill 的 hidden states ↔ hf_integration.forward.hidden_states
                    比法：**逐位**（==）
                    抓的错法：prefill 用了逐 token 的方式（掩码不同）、
                              缓存的行与整段路径用到的行不是同一次投影
```

两条都只有一处差别（K/V 从哪来），而它们的**逐位相同**正是
"缓存接对了"的最强证据。

**10.** 因为量化那一条性质的判据是"实测误差 **≤** 上界"，而
"两个操作数相等"**不该成立**（一个是实测值、一个是推导出来的界）。只用相等那一种判据的后果：

```text
把 reading=实测、expected=上界 传进"相等"判定 ⇒ 它永远失败（除非误差恰好等于上界）
把 reading=上界、expected=上界 传进去        ⇒ 它永远通过（**什么都没证明**）
```

前者的表现是"性质永远红"（于是有人会把它删掉），后者的表现是"性质永远绿"
（于是没人会去看它）。两种都属于 day083 那条纪律说的"不可能失败的判据不算判据"。

**11.** 因为粒度收益**只在有离群值时才出现**，而且必须用**均值**看：

```text
离群值放在每一行    ⇒ 每一行的 scale 都被抬高 ⇒ per_channel 与 per_tensor 一样粗 ⇒ 收益 ≈ 1.0 倍
改用最大误差        ⇒ 最大值被那一行离群值占住，而两种粒度下都是同一行 ⇒ 收益被完全掩盖
只有一行带离群值 + 均值 ⇒ per_tensor 被那一行抬高、其余各行跟着变粗；per_channel 只抬高那一行
                        ⇒ 均值上看得见"其余各行细了 2 倍"
```

本课的三组读数就是这三句话：带离群值 + 均值 = 1.9~2.2 倍；
每行分布相同 + 均值 = 1.2 倍；带离群值 + 最大值 ≈ 1.0 倍。

**12.** 因为那条不变量是唯一能把"表里的行"与"请求的长度"对上的东西：

```text
表里只有成员下标与 -1（空位）⇒ 形状、步数、占用率全都对
某一条提前结束时   它后面的行会被别的请求填上 ⇒ "步数"与"占用率"看不出差别
若不核对次数        ⇒ 那一条少了 1 次（甚至少很多次）在表里**完全不可见**
```

本课的第一版实现里 `remaining` 忘了减 1，于是**没有一条请求会结束**：
表看起来完全合法，而第 5 条请求只出现了 6 次而不是 7 次。
抓住它的正是 `per_request_steps(schedule) == lengths` 这条断言。

## 三、诊断题

**13.** 错误是**位置取错了**：`embed_tokens` 按行内下标编号位置
（`tuple(range(len(row)))`），而这里一行只有一个 token ⇒ 位置永远是 0。
正确做法是 `_embed_at(card, weights, token_id, cache.length)`。

它"看起来正常"的原因有三层：

```text
① 形状全对：一行 (1, hidden)、输出也是一行
② 不报错：位置表里第 0 行确实存在，取它不是一个越界
③ 数值"看起来合理"：这一行的输入整块被换掉了（本机实测最大差 3.658558e-01），
   而它的量级与正确输入**同一个数量级**
```

能抓住它的是 `check_cached_equals_recompute`（缓存路径 vs 整段重算，**逐位**）：
一旦位置取错，两条路径的 logits 立刻分家。

**14.** 错误是**阶段与结束条件都写错了**：`finished` 的判据用的是
`remaining[member] <= 1` 而不是"减 1 之后为 0"，而且**没有任何一处把 `remaining` 减 1**。
后果是：

```text
没有一条请求会结束   ⇒ 表里每一步的成员都是同几条 ⇒ 表长会**无限增长**（这个循环最后会挂住）
即便它退出           ⇒ 每条请求出现的次数与它的长度无关 ⇒ 表在数值上完全错
```

能抓住它的判据是 `check_schedule_occupancy_is_counted` 里那条不变量：
**每一条请求出现的次数必须恰好等于它的长度**。修正后的写法是

```python
    for member in active:
        remaining[member] -= 1           # ← 先减 1
    active = [member for member in active if remaining[member] > 0]
```

**15.** 三条读数各自的诊断与动作：

```text
读数 A  三项之和 62528 > 预算 61440 ⇒ **放不下**（差 1088 字节）
        诊断：这不是参数错，而是部署/精度问题
        动作：换精度（int8 立刻降到 15632）或换卡；**不要**去偷偷截短上下文——
              "上下文被截断"与"上下文够用"在生成结果上不一定看得出来

读数 B  实测 1.91e-03 > 上界 9.53e-04（约 2 倍）
        诊断：上界失效 ⇒ 要么"夹断"发生了（有元素越出量程，例如某个值是别的行的一个数量级？），
              要么取整方向写错（floor 会让上界变成 scale）
        动作：先查 scale —— 若 scale = 1.905e-03 而最大误差约等于 scale，那就是**取整方向**错了；
              再查是否有元素越出 [-A, A]（本包在入口就拒绝 inf/nan，因此这一条通常不成立）

读数 C  decode 每步应当是固定增量（本课 256 字节），而第 2 步是 384
        诊断：增量不齐 ⇒ 某一层多追加了一行（或两次方一次）
        动作：对照 cache_account_line —— 它把"公式"与"逐层相加"两个数并排印出来；
              两数不等就说明某一层的长度与其余层不同（KVCache.length 会当场报错）
```

## 四、推导题

**16.** （a）设每步只算一个**新位置**的输出：

```text
不缓存    第 t 步要把前面 t 个位置重算一遍 ⇒ 1 + 2 + … + T = T(T+1)/2 次打分
缓存      第 t 步只算新位置对前面 T 个位置 ⇒ 每步 T 次 ⇒ 总共 T 次
```

两者之比：

```text
T / [T(T+1)/2] = 2 / (T+1)        ✔
```

（b）投影那一侧：每层每步要投影的是"这一步参与计算的行数"。

```text
不缓存    第 t 步投影 t 行 ⇒ Σ t = T(T+1)/2 行
缓存      第 t 步投影 1 行 ⇒ T 行
```

两者之比同样是 `2/(T+1)`——**两处收益是同一个比例**，这也是"缓存把 O(T²) 变成 O(T)"
这句话的完整含义（打分与投影各占一半）。

（c）显存代价：

```text
缓存显存 = 2 · L · T · h · b      （K 与 V 各一份；b = 每元素字节数）
```

它随 `T` **线性增长**，而不缓存的显存代价是 0。因此：

```text
T 小的时候缓存省得少（2/(T+1) 接近 1）
T 大的时候缓存省得多，但显存也占得多
⇒ 当显存紧（或 T 的上界很大）时，"不缓存"可能是唯一跑得起来的方案
⇒ "缓存一定更好"这句话只在"显存不是约束"时成立
```

读数：`L=2, h=16, fp32, T=9` ⇒ 缓存 2304 字节；而同一步的权重是 46144 字节——
**权重是地基、缓存是变量**，这正是预算表里两者占比差别那么大的原因。

**17.** （a）对任意 `x ∈ [−A, A]`：

```text
x/s ∈ [−A/s, A/s] = [−(2^{b-1} − 1), 2^{b-1} − 1]
```

因此 `x/s` 落在格号区间内，取整不会夹断。设 `q = round(x/s)`，则 `|x/s − q| ≤ 0.5`，
两边乘 `s > 0`：

```text
|x − x̂| = |x − q·s| = s·|x/s − q| ≤ 0.5·s = s/2        ✔
```

（b）当某个元素是 `inf` 时，`A = max|x| = inf`，于是 `s = inf`。
证明的第一步就失效了：`x/s` 变成 `nan` 或 0，`round` 的结果没有意义，
**上界本身也变成 `inf`**（一个恒成立的界等于没有界）。因此本包在入口就拒绝非有限数。

（c）若整块同值（`A = 0`）：`s = 0 / (2^{b-1} − 1) = 0`，
而 `x/s = 0/0` 没有定义——这一步不是"得到 0"，而是**没有定义**。
本包因此**拒绝**（`QuantError: 这一块的所有元素都是同一个值 ⇒ scale = 0`），
理由是"误差很大"与"这一层本来就没东西"读起来不一样：
前者要去看数据，后者要去看这一层为什么是空的。

**18.** （a）三项之和（缓存与激活都线性于 `T`）：

```text
total(T) = W + T·(2·L·h·b) + T·(n·f·b) = W + T·(n·f·b + 2·L·h·b)
```

（b）记斜率 `k = n·f·b + 2·L·h·b > 0`，`T_max = ⌊(B − W) / k⌋`（要求 `B ≥ W`）：

```text
total(T_max) = W + ⌊(B − W)/k⌋·k ≤ W + (B − W) = B        ✔
```

再取 `T_max + 1`：因为 `⌊(B−W)/k⌋·k > (B−W) − k`，所以

```text
total(T_max + 1) = W + (⌊(B−W)/k⌋ + 1)·k > W + (B − W) = B      ✔
```

即 `total(T_max) ≤ B < total(T_max + 1)`——这就是"最大"的定义。

（c）只查 `T_max` 放得下**不足以**验证它是最大值。反例：设
`W = 1000`、`k = 100`、`B = 1500`，那么真正的最大值是 `T = 5`（`total(5) = 1500 ≤ B`，
`total(6) = 1600 > B`）。若报告给出的是 `T_max = 2`（一个偏小的值）：

```text
total(2) = 1200 ≤ 1500   ⇒ "放得下" 通过了
```

而 `2 + 1 = 3` 也放得下（1300 ≤ 1500）——它根本不是最大值。
**"保守"与"算错"读起来一样**，因此本课两侧都查：
`inside.fits is True` 且 `outside.fits is False`，两者缺一不可。

读数（本课实测）：

```text
fp32  | 权重 46144 + 缓存 8192 + 激活 8192 = 62528 / 65536 ✓ | T_max 37
                  T=37 合计 65088 ✓、T=38 合计 65600 ✗
int4  | 权重  5768 + 缓存 1024 + 激活 1024 =  7816 / 65536 ✓ | T_max 933
                  T=933 合计 65480 ✓、T=934 合计 65544 ✗
```
