## 一、一页速答

**1.**
```text
应用层（M1 / M2）        "能做什么"：Agent 自己会做事，能力能标准化对外
评估与系统层（M3 / M4）  "系统好不好、能干什么"：先造尺子，再造系统
模型与数据层（M5 / M6）  "模型怎么专属、知识怎么接"：微调 + RAG
原理层（M7 / M8）        "底层是什么"：一次点积 → 一次反向 → 一条训练管线
底座（P）                "怎么把上面四层跑起来"：依赖倒置、测试与覆盖率、Git/Docker
```
出处：教程第一章；根 README 的「学习路径设计逻辑」。

**2.** M1 造内核（单进程内让 Agent 会思考、行动、记忆、规划、协作、被编排、被评估）；
M2 标准化对外（把内核的能力用 MCP 协议封装，让任何兼容客户端都能发现和调用）。
两者的接缝是 **`ToolRegistry`**——对内注册进程内 `BaseTool`，对外注册 MCP 远程工具的本地代理。
出处：day024 第四章；教程 2.2。

**3.** 依赖倒置体现为 `ReactAgent` 依赖 `BaseLLM` 抽象而非具体实现（day005）：
生产注入 `OpenAICompatibleLLM`，测试注入 `MockLLM`。**没有抽象层，`MockLLM` 就不存在**——
它是架构决策的产物，不是"测试技巧"。没有它，后面每一天的测试都要访问网络，FIRST 原则全部失守。
出处：day005；day024 2.3。

**4.** "M×N → M+N" 解释的是 MCP 的价值：没有 MCP 时，M 个框架接 N 个工具要写 M×N 对定制代码；
把工具侧与框架侧各标准化一次后，复杂度降为 M+N。
三原语里承诺"只读、无副作用"的是 **`Resource`**（用 URI 寻址的只读数据），
因此客户端才敢安全地预取、缓存、索引它。
出处：day016 / day017；day024 3.1 / 3.2。

**5.** 四步骨架：`load_dataset（数据集）→ evaluate（执行）→ 评分（判定）→ summary（汇总）`。
`summary` 必须按 `by_tag` 分组，因为**总分掩盖塌方**：day025 的示例数据集 6 条
（math / qa / safety）当天 `pass_rate = 5/6 = 0.8333`，而 knowledge 组只有 **0.5**。
出处：day025；day047 2.1。

补：四步各对应一条纪律——数据集必须含边界用例；Harness 内不写业务逻辑；
评分规则显式可审计；汇总必须分组。三把尺子的现场读数：
Prompt 评估（规则 0.4 + 裁判 0.6，`TIE_THRESHOLD = 0.05`，V2 得 4.80 / V1 得 4.00）、
输出质量（0.4/0.4/0.2 三因子）、Agent 评估（完成率 0.625 / 步数效率 0.79 /
工具 F1 0.71 / 顺序 1.00）。红队 16 条用例把整体拦截率从 **56.3% 提到 100%**。
出处：day026 / day027 / day030 / day031。

**6.**
```text
输入侧护栏 → 语义缓存 → 模型路由与生成 → 成本归因 → 输出侧审核 → 缓存回写
 guard       cache       generate          account     moderate     store
```
"护栏最先"：被判定为注入的请求**模型完全不被调用**（`llm.calls == []`）。
"缓存在护栏之后"：否则一条恶意请求会先命中缓存并直接返回，护栏形同虚设。
（第三条同理：审核必须在回写缓存之前，否则缓存会存下未脱敏文本，把一次性泄漏变成持续性泄漏。）
出处：day046 / day047 3.3。

**7.** 一句话：**这条链上每一件事都必须"能被证伪"**——训练产物自描述（词表随检查点落盘）、
适配器与基座配对（`base_model` 校验）、部署记录与端点自述一致（五条绑定检查）、
上线前有对比（同一批用例上的两个推理臂）、成本有两个模型（固定 vs 可变）互相校验。
出处：day060。

补三条现场读数：LoRA 与全参的显存（7B 上 75.31 / 12.65 / 3.33 GiB，不含激活）；
合并门禁在全部上下文上逐位比较 logits（实测差 `0.00e+00`，tolerance 缺省为 0）；
"一个基座 + 10 个适配器"比 10 个合并模型省 **10.00×**。
另有两条纪律：降级只向一个方向（专属失败可回落云端，云端失败绝不回落专属）；
"缺失就是缺失"（端点没自述 → 不一致，而不是跳过）。
出处：day051 / day052 / day060。

## 三、对照题

**12.**

```text
（甲）M1 解决"智能体自己怎么可靠地完成复杂任务"（内核：循环、工具、记忆、规划、反思、编排、安全）；
      M2 解决"这些能力如何被任意客户端标准化地发现、调用与分发"（协议：JSON-RPC 2.0、

（乙）因为 M2 自己不产生任何能力，它只把 M1 造出来的工具/资源/提示词包一层，

（丙）同一个 ToolRegistry 抽象同时装得下两种来源：进程内的 BaseTool（day004/005），
      以及 MCP 远程工具的本地代理（day020）。上层 ReAct 循环对两者无感。

（丁）体现在 day019 的 FastMCP Server：同一套装饰器代码，改一个参数就在
      stdio（本地子进程）与 SSE（HTTP 长连接）之间切换。
      好处是"能力定义"写一次，换部署形态不用改逻辑；stdio 天然隔离，SSE 可被共享。
```
出处：day024 第四 / 五章；day019 / day020。

**13.**

```text
（甲）M3：不可度量 ⇒ 不可优化。M4：能力不集成 ⇒ 只是零件。

（乙）因为 M3 的所有模块（harness / prompt_eval / rag_eval / redteam）都不参与线上请求，

（丙）两例：
      ① day037 有了 function calling，day030 的"工具使用正确性"才有意义；

（丁）因为"抽象方法"会逼所有既有实现同时改造；"带默认值的具体方法/属性"让所有人
```

命中路径 3 阶段 7.0"，三个数字分别等于 14 / 4 / 8 次时钟读取的步进差——
**耗时断言即阶段数断言**。M4 的失败安全方向也统一：能退避就不崩溃，且退避必须留痕。
出处：day046；day047 3.3 / 4.3。

**14.**

```text
（甲）非阻塞的是 registry_head（绑定版本不是注册表 head）。
      因为灰度发布的本质就是"部署的不是 head"——先部署新版本、再逐步切流量。

```

## 四、诊断题

**15.**

```text
读数 A  RAG 基线：retrieval_recall = 0.9167、grounded_rate = 1.0、hallucination_rate = 0.0
  **不动作。** 这是 data/eval/rag_baseline.json 里的锚点读数，三个指标都在"好"的一侧
  （接地率 1.0、幻觉率 0.0）。但要带一句提醒：它绑定了 prompt_version=v2 与 6 条样本，
  **换了提示词或数据这条基线就不可比**（day053 的纪律：没有绑定信息的分数不是证据）。
  出处：data/eval/rag_baseline.json；day071；day053。

读数 B  灰度切换：200 个问题里专属服务 11 条、成功率 100%、fallback_count = 1
  **要动作（去看 fallback_count）。** 成功率 100% 是假象：fail_open=True 时，
  专属模型失败会被云端兜住，请求仍然全成功。`fallback_count = 1` 说明有一次专属调用
  其实失败了。需要一次诚实的测量（严格模式 fail_open=False 跑一次）。
  另外 200 条里分走 11 条（5.5%）是稳定分桶的正常波动，不是问题。
  出处：day060 4.2 / 4.3。

读数 C  部署绑定：passed=False，阻塞失败 = ['adapter_hash']
  **要动作。** 阻塞项非空就是失败：adapter_hash 对不上，最可能是 adapter_dir 指到了旧目录
  （线上加载的是上一份适配器）。这是"不报错但答的是上一版"最典型的一种。
  出处：day060 3.1 / 1.2。
```

## 附：本课最值得带回工作现场的五句话

```text
① 全栈的每一层都不是"知识点"，而是一条可被反驳的判据——
   上层说"这个系统能做什么"，下层说"凭什么相信它做对了"。            （教程 1 / 6.3）

② 越往上判据越像"业务阈值"（留裕度），越往下越像"数值对账"（不给裕度）；
   把两类混成一条，必然有一类错误被放过。                          （教程 1 / day096 10.1）
```
