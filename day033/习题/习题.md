# day033 课后习题

共 10 题，覆盖今天所有学习目标：自回归生成原理、采样参数数学、Agent 场景的温度选择、多模型路由与降级。建议完成时间：45~55 分钟。

## 第一部分：选择题

### 第 1 题（自回归生成）

关于 GPT 类模型的自回归生成，下列哪一项描述是**错误**的？

- A. 模型的原子操作是"给定一段文本，输出词表上下一个 token 的概率分布"
- B. 生成一句话是把选出的 token 追加回输入、反复调用模型的过程
- C. 模型每生成一个 token 都会联网检索一次以核对事实
- D. 生成必须逐 token 串行，这是输出 token 比输入 token 贵的根本原因

### 第 2 题（temperature 的数学）

对同一组 logit，随着 temperature 从 0.5 调到 2.0，softmax 输出的概率分布会如何变化？

- A. 最大概率的 token 概率更高，分布更尖锐
- B. 最大概率的 token 概率更低，分布更平坦，趋于均匀
- C. 概率分布不变，temperature 只影响生成速度
- D. 分布形状随机变化，无规律可循

### 第 3 题（核采样的自适应性）

对分布 `[0.9, 0.05, 0.05]` 与 `[0.34, 0.33, 0.33]` 分别做 `top_p=0.9` 的核采样，保留的候选数分别是：

- A. 都是 3 个
- B. 都是 1 个
- C. 1 个和 3 个——核大小随分布形状自适应，这正是核采样优于 top-k 之处
- D. 3 个和 1 个

## 第二部分：判断题

### 第 4 题

`temperature=0` 在数学上是"温度趋近于零的 softmax"，因此 `softmax_with_temperature(logits, 0.0)` 应返回 one-hot 分布而不是抛异常。（对 / 错）

### 第 5 题

Agent 场景推荐 `temperature=0`，是因为 LLM 的输出在 Agent 里是给解析器看的、且早期步骤的随机波动会被 ReAct 循环放大；而创意写作等"输出本身就是目的"的场景反而适合调高温度。（对 / 错）

### 第 6 题

`CostFirstStrategy` 在首选模型调用失败时，降级链按成本从低到高排序——优先尝试更便宜的模型，以最小化故障期间的成本。（对 / 错）

## 第三部分：问答题

### 第 7 题（原理推导经验法则）

请用自回归生成原理解释以下三个经验现象：（1）为什么 `max_tokens` 只能是硬截断而不是"说完才停"？（2）为什么系统提示词里的 ReAct 格式模板能有效约束模型输出？（3）为什么幻觉（编造事实）是 LLM 的结构性问题而非单纯的"模型不够聪明"？

## 第四部分：编程题

### 第 10 题（路由收益实验：成本优先 vs 质量优先）

**功能要求**：

1. 在项目根目录新建 `scripts/route_cost_demo.py`，构造三档 MockLLM 模型（cheap/mid/strong，capability 2/3/5，cost_per_1k 分别为 0.001/0.01/0.1），准备一份混合任务清单（至少 3 条简单任务 + 2 条复杂任务，复杂任务需含"分析/对比/推理"类关键词使复杂度 ≥ 4）。
2. 用同一份任务清单分别驱动两个 router：`CostFirstStrategy` 与 `QualityFirstStrategy`；每个任务经 `router.chat()` 调用后，用 `CostTracker` 按**实际生效模型的价格表**记账（提示：给 `CostTracker` 传自定义 `price_table`，键为模型名，输入输出同价取 `cost_per_1k`；实际生效模型 = `decision.fallback_used or decision.chosen`）。
3. 打印两种策略的总费用对比与每条任务的路由决策理由，并断言：成本优先的总费用严格小于质量优先；简单任务在成本优先下全部路由到 cheap。
4. 附加验证：把 cheap 模型换成一个抛异常的实现，重跑成本优先策略，断言简单任务经降级链仍全部得到回复，且 `decision.fallback_used` 非空。

**提示**：MockLLM 的 `usage_log` 按实例独立累计，记账时机为每个任务调用结束之后；`estimate_complexity` 对短文本无复杂关键词返回 1。
