## 第一部分：选择题

### 第 1 题（短期记忆 · 截断策略）

`ShortTermMemory(max_messages=4)` 中依次加入 1 条 system 消息和 5 条 user 消息后，记忆内容、最老 user 消息的去向分别是：

- A. 保留 system + 最早的 3 条 user 消息；最新的 user 消息被丢弃
- B. 保留 system + 最新的 3 条 user 消息；最老的 user 消息被 FIFO 丢弃
- C. 5 条 user 消息全部保留；system 消息被丢弃以腾出容量
- D. 抛出 `ValueError`，因为消息总数超过了 max_messages

### 第 2 题（长期记忆 · 相似度度量）

长期记忆检索选择**余弦相似度**而不是欧氏距离，根本原因是：

- A. 余弦相似度计算速度更快，与向量内容无关
- B. 语义主要由向量的"方向"承载，"长度"多反映文本长短等噪声；余弦只比较方向，天然免疫长度噪声
- C. 欧氏距离无法处理高维向量
- D. 余弦相似度的值域是 [0, 1]，方便排序

### 第 3 题（Planner · 防御式解析）

`parse_plan` 对 LLM 输出 `"好的，这是计划：\n[\"查资料\", \"写总结\"]\n请确认。"` 能解析成功，靠的是：

- A. 提示词里写了"不要输出其他内容"，模型一定不会加废话
- B. `find("[")` 与 `rfind("]")` 定位最外层数组边界，截取后再交给 `json.loads` 做权威解析
- C. 正则表达式剔除所有中文字符
- D. `json.loads` 本身可以跳过 JSON 前后的自由文本

### 第 4 题（Reflexion · 机制本质）

关于 Reflexion 反思机制，下列说法**正确**的是：

- A. 它通过梯度更新微调了模型权重，使模型下次不再犯同样的错
- B. 它让 LLM 对完整的失败轨迹（Thought/Action/Observation 历史）复盘，生成文字形式的改进建议存入记忆，带着它重试任务——模型权重不变，变的是下一轮的输入上下文
- C. 它通过更换更强的模型来避免失败
- D. 它可以无限重试，直到任务成功为止

### 第 5 题（LangGraph · 状态图模型）

在 LangGraph 状态图中，节点之间传递信息的正确方式是：

- A. 节点 A 直接 import 并调用节点 B 的函数
- B. 通过全局变量共享数据
- C. 每个节点接收 State、返回对 State 的增量更新，节点之间只通过 State 通信；走哪条边由路由函数根据 State 决定
- D. 通过 LLM 在节点之间转发消息

### 第 13 题（编程题 · 短期记忆截断的行为锁定）

为 `ShortTermMemory` 编写测试文件 `tests/test_memory_review.py`，用断言锁定以下三条行为承诺（每条至少一个测试）：

1. **容量不变量**：`max_messages=4` 时灌入 1 条 system + 5 条 user，任何时刻 `get_all()` 的长度不超过 4；
2. **system 钉在头部**：截断发生后，`get_all()[0].role == "system"`，且最老的 user 消息已被丢弃、最新的保留；
3. **防御性拷贝**：对 `get_all()` 的返回值做 `append`，不影响内部状态（再次 `get_all()` 长度不变）。

并回答：`others[-0:]` 在 Python 中得到什么结果？`_truncate()` 里 `keep == 0` 的退化分支为什么在语法上必须显式处理？

### 第 14 题（编程题 · 长期记忆的检索注入链路）

基于 day010 快照的 `LongTermMemory`、`MockEmbedding`、`InMemoryVectorStore`、`cosine_similarity`：

1. 实现一个函数 `build_context_with_recall(memory, query, base_messages, top_k=2)`：先 `memory.recall(query, top_k)`，再把取回的文本拼成一条 `role="user"` 的 Message（前缀 `"相关资料："`）插入到 `base_messages` 的 system 消息之后、其余消息之前，返回新的消息列表；
2. 用 `MockEmbedding` 编写测试验证**链路正确性**：`remember` 两条文本后调用你的函数，断言返回的消息列表中包含以 `"相关资料："` 开头的消息，且位置在 system 之后；
3. 再用手工构造的向量（不经过 `MockEmbedding`）直接往 `InMemoryVectorStore` 里 `add` 三条 `VectorRecord`，验证 `search` 按余弦相似度正确排序 top-1，并解释：为什么这一小步不能用 `MockEmbedding` 做？

### 第 15 题（综合编程题 · 用 LangGraph 写最小状态图）

不依赖任何 LLM，用 langgraph 1.2 实现一个"猜数字收敛"状态图并测试：

1. 定义 `State`（TypedDict），字段：`target: int`、`guess: int`、`steps: int`；
2. 实现两个节点：
   - `adjust_node`：若 `guess < target` 则 `guess += 1`，若 `guess > target` 则 `guess -= 1`，同时 `steps += 1`；返回状态增量；
   - 路由函数 `route(state)`：`guess == target` 时返回 `"done"`，否则返回 `"continue"`；
3. 组图的 API 约束：`from langgraph.graph import StateGraph, START, END`；`add_node` / `add_edge(START, "adjust")` / `add_conditional_edges("adjust", route, {"continue": "adjust", "done": END})`；`compile(checkpointer=MemorySaver())`（`from langgraph.checkpoint.memory import MemorySaver`）；
4. 编写测试：`target=7, guess=1, steps=0` 起步，`invoke(state, config={"configurable": {"thread_id": "t1"}})`，断言最终 `guess == 7` 且 `steps == 6`；
5. 附加思考：如果把 `checkpointer` 去掉，对本次 invoke 的结果有影响吗？checkpointer 的价值在什么场景才显现？
