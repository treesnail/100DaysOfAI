## 第一部分：选择题

### 第 1 题

**答案：B**

**解析**：两条路的代价与性质恰好相反。**拒绝采样**让模型对同一 prompt 采 K 个回答（K 倍推理，贵），但 chosen/rejected 的分布与当前策略一致，因此是"在线"方法；**规则劣化**以金标准为 chosen、用算子把答案改坏成 rejected，便宜、完全离线、可审计，但 rejected 的分布是人工构造的，与模型真实错误不同。A 把两者说反了；C 错——分布不同正是取舍的核心；D 错——本课实现的是两者的**交集**（劣化算子造候选池，`score_candidate` 排序）。

### 第 2 题

**答案：B**

**解析**：`pad_verbose`（追加套话）与 `add_overclaim`（追加承诺）都**只追加、不删改**，所以它们的关键短语覆盖率与金标准完全相同。打分器若只有覆盖率一项，这两个候选会得满分、与金标准打成平手——"更啰嗦/更过头"这件事就被丢掉了，两个算子等于白造。因此超长惩罚（`OVERLENGTH_PENALTY = 0.5`，每超出 1 倍扣 0.5 分）是这两个算子唯一的区分度来源。A 错（它们的长度更长）；C 错（它们不删原文，覆盖率不降）；D 错（覆盖率才是主项）。

### 第 3 题

**答案：B**

**解析**：代码注释写得很直接——`format` / `refusal` 这些维度需要**结构化判定**，不是字符级覆盖率能表达的。用一个字符级覆盖率冒充"格式合规"，比对未知的诚实还要糟：它会给数据一个**看起来有依据、实际无意义**的分数。所以本课把这两类维度交给手写种子数据与安全偏好集，而不是硬塞进打分器。A、C、D 都不是设计理由。

### 第 4 题

**答案：B**

**解析**：`worst` 语义上最像拒绝采样（取最差候选），但实测它会让四个算子退化成两个——"删掉半数句子"永远比"多说两句废话"错得更狠，于是 `drop_tail` 与 `pad_verbose` 垄断全部样本。`rotate` 按序号轮转，牺牲"rejected 一定最差"，换来四个算子各有覆盖，于是"模型对哪类改坏方式区分度最差"才有数据可答。C 错——`worst` 不需要随机性；D 错——`rotate` 恰恰**不保证** rejected 最差。

### 第 5 题

**答案：C**

**解析**：IPO 的损失是 `(m − 1/(2β))²`，在 `m = 0` 处取值为 `1/(4β²)`。`β = 0.01` 时是 `1/(4 × 0.0001) = 2500`。A 是 `sigmoid` 的起点值（**继续沿用 ln2 做起点自检就会漏掉真实的接线错误**——这正是 `expected_zero_margin_tolerance` 要防的）；B 是 `hinge` 的起点值；D 错（IPO 的零损失点在其目标 margin `1/(2β)` 处，不在原点）。

## 第二部分：判断题

### 第 6 题

**答案：错**

**解析**：这条配置**不会报错**——它只会让每一批的序列都被截断，一部分答案在训练时被悄悄切掉，模型学到的是"答一半就停"。正因为它是静默的，`validate()` 才必须在**构造期**主动把它拦下（`DPOError`），而不是留给训练循环。**静默的错误比响亮的错误危险得多**，这是本课反复强调的一条。

### 第 7 题

**答案：对**

**解析**：`complete_epochs` 定义为 `int(num_train_epochs)`，小数部分不产生任何参数更新，因此不计。`2.9` → 2 个完整 epoch。要特别留意 `num_train_epochs < 1` 的情形：`complete_epochs` 为 0，损失函数一次都不会被调用——而框架不会报错。`step_plan` 会显式抛 `DPOError` 拦住它。

### 第 8 题

**答案：对**

**解析**：`hinge_dpo_gradient` 在 `β·m < 1` 时返回 `−β`，否则返回 `0.0`。间断点在 `β·m = 1`。真实实现（TRL 用 `torch.relu`）在不可导点取次梯度 0，本实现与之保持一致；若在该点取 `−β`，测试里的中心差分会在该点两侧给出不同结果，从而掩盖真正的符号错误。

## 第三部分：简答题

### 第 9 题

**参考答案要点**：

**两条体检**（都发生在候选池造好之后、写入数据集之前）：

1. **自洽体检**：`pool[0].op != "gold"` 即"得分最高的候选不是金标准"，丢弃并记入 `drop_reasons["gold_not_best"]`；
2. **区分度体检**：`gold.score − rejected.score < min_gap`（默认 `MIN_SCORE_GAP`），丢弃并记入 `drop_reasons["insufficient_gap"]`。

**自洽体检为什么必须存在**：一条"chosen 并不更好"的偏好样本，在 DPO 里贡献的梯度方向是**反的**——它在教训模型"应该更倾向于那个更差的回答"。而这种样本不会报错、不会崩，在统计里仍然算一条合格数据，因此它是**静默地**把模型往反方向推。这与 day053 的"参考答案必须能通过它自己的用例"是同一条纪律：数据本身必须先自洽，训练才可能收敛到正确的方向。

**补充**：区分度体检针对的是另一类问题——得分差接近 0 的一对几乎不产生梯度（margin ≈ 0），却照样占一条样本位置，等于用噪声稀释有效数据。两条体检一个防"方向错"，一个防"信号弱"。

## 第四部分：编程题

### 第 10 题

**参考答案**（可直接追加到 `tests/test_dpo_losses.py`）：

```python
class TestGradientCheckByHand:
    def test_numeric_matches_analytic_for_all_losses(self):
        """三种损失 × 三个 margin：解析梯度必须等于中心差分。"""
        beta = 0.1
        for name in ("sigmoid", "hinge", "ipo"):
            for margin in (-1.0, 0.5, 3.0):
                numeric = numeric_gradient(name, margin, beta=beta)
                analytic = loss_gradient(name, margin, beta=beta)
                assert abs(numeric - analytic) < 1e-5, (name, margin)

    def test_hinge_subgradient_is_zero_at_threshold(self):
        """β·m = 1 处取次梯度 0（与 TRL 的 relu 一致），不是 −β。"""
        assert hinge_dpo_gradient(10.0, beta=0.1) == 0.0
        assert hinge_dpo_gradient(9.999, beta=0.1) == pytest.approx(-0.1)
```

**关键点说明**：

1. **为什么要三级 margin**：`-1.0` 测试负 margin（此时 chosen 反而更差）；`0.5` 在 hinge 的间隔内（产生梯度）；`3.0` 对 hinge 已越过间隔 `1/β = 10`？——没有（`β·m = 0.3 < 1`），所以三种损失在 `3.0` 处都仍有非零梯度，对照有效。若想看 hinge 的梯度归零，要取 `margin ≥ 10`，这正是第二段断言做的事。
2. **为什么把数值梯度放进生产代码而不是只放进测试**：因为它**同时是文档的一部分**。`scripts/dpo_demo.py` 会把数值梯度与解析梯度并排打印出来，让"梯度确实是我写下的那个式子"这件事在报告里可见、可复现——只在 CI 里静默通过的检查，学员看不到，也无法在排障时复用。这也是本课 "读表先于调参" 那条纪律的延伸：**能被打印出来的自检，比只能被断言的更可信。**
3. **容差为什么取 `1e-5`**：中心差分的误差量级约为 `O(step² · L''')`，本课 `step = 1e-6`，实测误差在 `1e-12` 量级，`1e-5` 留了三个数量级余量，既能吸收浮点噪声，又不会放过真的符号错误（量级差至少是 `β = 0.1`）。

**验证**：运行 `python -m pytest tests/test_dpo_losses.py -q`；day055 快照的全量测试见 `../教程/教程.md` 第五章。
