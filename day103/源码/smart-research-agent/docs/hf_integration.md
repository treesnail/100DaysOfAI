>
> 本手册回答一个问题：**"把那份东西接进来"到底要接什么，以及怎么把"接上了"变成一条能失败的判据。**

## 一、本课承诺什么，不承诺什么

```text
承诺      给定同样的文件与输入，复现"装载与调用"那几层的**解析与装箱**语义
          （文件怎么被找齐、配置怎么变成形状、token 怎么切、向量怎么池化）
不承诺    某个符号在第几行、某个内部变量的名字、某个版本的缓存目录细节
```

day085 承诺的是"那几个类怎么算"，今天承诺的是"那几个文件怎么被找齐、被解释、
被喂进模型"。两者的**反证方式**也不同：day085 用扰动量（改一个数、看谁不变），
今天用**换一个来源**（换 revision、换 padding 宽度、换批量大小，看读数是否一致）。

还有一条边界必须写在最前面：

```text
本课一行反向都不写。
  from_pretrained 之后每一层都是别人写好的；本课做的是解析、缓存、分词、池化与编排，
  全部落在**前向之外**。因此本课连续第二天**没有** GradientError 那一族。
```

## 二、`from_pretrained` 的第一步不是加载权重

是把文件**找齐**。三段结构，缺一不可：

```text
① 名字 → commit      C:/cache/hub/models--org--tiny-gpt2/refs/main  的内容是一串 commit hash
② commit → 文件      快照目录 snapshots/<commit>/ 里的相对路径**与仓库一致**（平铺）
③ 文件 → 实体        blobs/<sha256> 存实体；快照里的路径与实体之间是"两个名字"
```

演示脚本第 1 节的读数（同一个缓存、两轮解析 + 一次离线解析）：

```text
第2次  config.json          387 B  命中
第2次  merges.txt           618 B  命中
第2次  model.safetensors      8 B  命中
第2次  vocab.json          2860 B  命中
...
离线解析（local_files_only=True，复用同一个缓存）：下 0 个 / 命中 4 个
换个缓存根再离线解析同一个 revision：HubError —— 离线模式下缓存里没有版本 'main' 的引用
```

三条值得单独指出的：

```text
① "逐文件"这三个字是有代价的        把它写成 all-or-nothing 会让"少了一个文件"变成"整仓重下"
② "名字在"与"东西在"是两件事        快照表里有路径、实体被清掉时，本包**当场报错**而不是回绕
③ 离线不是"参数错"                  同一个 HubError 族里，网络断掉与缓存缺失长得一样
```

第 ③ 条解释了三族为什么必须分开：`HubError` 的出路是**改环境**，
而 `ParameterError` 的出路是**改调用**。把前者归进后者，修法就会指错方向——
有人会把 `local_files_only` 改成 `False` 再试一遍，而网络那一步的失败**长得完全一样**。

## 三、配置即形状：同一个量的两个键名

`config.json` 不是"元数据"，它是模型的**定义**。两个架构给的是同一个量的两个键名：

| 量 | GPT-2（`GPT2Config`） | BERT（`BertConfig`） |
|----|----------------------|---------------------|
| 隐藏维 | `n_embd` | `hidden_size` |
| 头数 | `n_head` | `num_attention_heads` |
| 层数 | `n_layer` | `num_hidden_layers` |
| 位置表长度 | `n_positions` | `max_position_embeddings` |
| 前馈中间维 | `n_inner`（**缺省 4·hidden**） | `intermediate_size`（**缺省 3072，与 hidden 无关**） |
| 激活 | `activation_function`（`gelu_new`） | `hidden_act`（`gelu`） |
| LayerNorm 的 eps | `layer_norm_epsilon`（`1e-5`） | `layer_norm_eps`（`1e-12`） |

前馈那一行是本课与**真库对账**时冒出来的一条"看起来一样、其实不一样"：

```text
bert-base-uncased   hidden=768  intermediate=3072  ⇒ 比例恰好 4.0（于是"都是 4 倍"看起来成立）
一个 hidden=16 的小 BERT                               ⇒ 比例 192.0（"4 倍"这句话立刻不成立）
```

因此"前馈是 4 倍"对 BERT 只是**一个模型碰巧**，对 GPT-2 才是**缺省规则**。
它值一条断言，因为一句"两个架构都是 4 倍"听起来完全合理——而它是错的。

## 四、参数量是**算出来的**

这是本课最值钱的一条判据：把"我理解了这个架构"变成两个**整数**。

```text
tiny GPT-2   vocab=277 n_embd=16 n_head=2 n_layer=2 n_positions=32 tie=True   →    11 536
gpt2（124M） vocab=50257 n_embd=768 n_head=12 n_layer=12 n_positions=1024     → 124 439 808
bert-base    vocab=30522 hidden=768 heads=12 layers=12 positions=512 type=2   → 109 482 240
```

三个数都能在真库里复核（`tests/test_hf_real_bridge.py`）：

```python
sum(p.numel() for p in transformers.GPT2LMHeadModel(transformers.GPT2Config(**tiny)).parameters())
```

两条公式的差别集中在三处：

```text
LN 的个数       GPT-2 每层 2 个 + 栈尾 1 个；BERT 每层 2 个 + 嵌入后 1 个
嵌入的三张表     BERT 多一张 token_type（type_vocab × hidden）与一次**带参数**的嵌入后 LN
池化            BERT 多一个 pooler（hidden² + hidden）
```

还有一个常被说反的默认值：`tie_word_embeddings` 的缺省是 **True，两个架构都是**。
真实 `bert-base-uncased` 的配置文件里没有这个键，因此它**共享**词嵌入——
证据就是一个整数：带共享算出来是 109 482 240，不共享会多出 23 440 896。

## 五、差值必须被逐项解释（day080 那条纪律的第四次）

本包的前向**省略了注意力的偏置**（day075 的四个投影都不带偏置），
因此它的真实参数量比配置口径少。差值是多少？可以被**算出来**：

```text
配置口径的每一层    12h² + 13h
本包权重每一层      12h² +  9h
差                 4h        = 注意力的偏置
```

而 4h 在两边的**拆法不同**——这正是值得留下来的那一句话：

```text
GPT-2   c_attn 的偏置 3h  +  c_proj 的偏置 h        （一次融合投影，分成两段）
BERT    query / key / value 各 h  +  output.dense 的 h   （四次独立投影，各一）
```

演示读数：`配置 11536 / 权重 11408 / 差 128 = 4·16·2`。
于是"差值恰好是 `4·hidden·layers`"是一条**可失败**的断言（`weights_gap_is_explained`）。

## 六、byte-level BPE：两个文件加一个循环

```text
vocab.json      token 字符串 → id      （含 256 个"字节字符"作为基元）
merges.txt      合并规则，**顺序即名次**（先出现的先被用）
一个循环        每一步挑"名次最小"的那一对合并，直到没有可合并的对
```

三条必须说清的事：

```text
① "字节级"是什么意思
   先把文本按 UTF-8 编成字节，再把每个字节映射成一个**可打印字符**
   （bytes_to_unicode：256 ↔ 256 一一对应）。于是**没有 unknown token 这件事**。

② 一个汉字几个 token 是**词表的性质**
   本包玩具词表 256 个基元 ⇒ 一个汉字恰好 3 个 token（UTF-8 三字节）；
   真实 GPT-2 的 50257 词表 ⇒ 常见汉字常被合并成 1~2 个。两边都没错。

③ 预分词是四条分支，不是"按空格切"
   缩写（'s / 't / 're / 've / 'm / 'll / 'd）+ 三条"可选空格 + 同类串" + 一段空白。
   **顺序即优先级**：因此 " world" 是一个 token（词首空格与词绑在一起），
   而 "  leading" 里的两个空格是**另一个** piece。
```

两条被复刻的怪癖，各配一条测试：

```text
· 缩写识别**区分大小写**（真实实现的模式里没有 IGNORECASE）
  "don't" → ("don", "'t")   而 "I'M" → ("I", "'", "M")
· 重复的合并对由**最后一次**出现决定名次（复刻 dict(zip(...)) 的行为）
```

## 七、一次真前向：填充什么时候是惰性的

```text
GPT-2    embed = wte[id] + wpe[pos]                      （不加 LN）
         L ×  x = x + attn(ln_1(x)); x = x + ln_2 前的 mlp    pre-LN
         ln_f   最后一次 LayerNorm；lm_head 与 wte **共享**
BERT     embed = LN(wte[id] + wte_type[0] + wpe[pos])     （多一次 LN）
         L ×  x = ln_1(x + attn(x)); x = ln_2(x + mlp(x))     post-LN
         pooler tanh(W·x[0] + b)
```

### 一个真实的坑（本课最值钱的一条工程结论）

```text
因果侧：填充排在真实位置**之后**，因果掩码让它们一格都传不回来
        ⇒ 同一段之内的填充是惰性的 ✔
```

**但这句话只在单条样本内成立。** 把三条样本首尾相接成一条长序列之后，
那张 `(n, n)` 的下三角会让**第 2 条样本看到第 1 条样本的全部 token**——
因为它落在"下三角之内"，而掩码不知道"段"这件事。它不报错，输出只是偏了。

正确做法是把掩码升级成**段内下三角**（`forward.block_causal_mask`），
也就是真实实现里那张 `(batch, 1, seq, seq)`：

```text
三条各 2 长的样本：
  0: 1 1 . . . .
  1: 1 1 . . . .
  2: . . 1 1 . .
  3: . . 1 1 . .
  4: . . . . 1 1
  5: . . . . 1 1
```

而**第 1 条样本在 naive 下碰巧是对的**——这正是这类 bug 最难被发现的地方：
拿一条样本试，永远试不出来。演示读数：naive 与 safe 的最大差 `3.657138e+00`
（归因：跨样本串味）；双向侧对应的是另一回事（填充污染，因为它没有切开）。

## 八、池化：那个只差一个分母的 bug

```text
mean_correct = sum(真实位置) / 真实长度     # ← 分母是真实长度
mean_buggy   = sum(全部位置) / 总宽度       # ← 分母是总宽度：填充越多，向量越"短"
```

演示读数（三条真实长度 `[5, 2, 9]`）：

```text
正确池化在两种填充宽度下的最大差 0.000000e+00   ← **逐位**要求 0
违反 mask 的代价：宽 12 时 1.451731e+00（填充占比 55.6%）、宽 16 时 1.524318e+00
```

手算锚点（`states = (1,1) (3,3) (5,5) (9,9)`、`mask = 1 1 1 0`、`mean`）：

```text
正确版 (3.0, 3.0)   真实 3 格之和 ÷ 3
违反版 (4.5, 4.5)   4 格之和 ÷ 4
```

两个读数放在一起才有意义：**没有填充时两版逐位相同**——
因此"我本地测过没问题"与"它在线上是错的"可以同时成立。

## 九、两条管线，零数学

```text
text_generation     逐条跑（长度不齐、各自停在 eos）；settings **原样**透传给 day085
feature_extraction  可以合批；池化按 mask；双向侧**先切开**
```

**为什么生成不能合批**：生成是自回归的，第 t 步的输出是第 t+1 步的输入。
合批之后两条样本的第 t 步落在同一个矩阵乘法里，而其中一条可能已经该停了——
把它们绑在同一个循环里只有两种结局：一起停（另一条被提前截断）或不停（该停的那条继续生成）。
本包因此逐条跑，并把每条的长度印出来。

"换管线不改模型"的可断言形式是：两条管线的结果来自**同一份权重对象**
（一次都没重新造过参数）。演示读数：

```text
生成：策略 greedy | 新生成 [3] 个 token | 文本 '...'
特征：向量 3 条 × 16 维，策略 mean
```

## 十、"接进来"要接的是接口面

day045 的 `LocalModel` 走的是**协议**路线（Ollama / vLLM 的 OpenAI 兼容端点）；
今天出现第三条路线：**模型就在这个进程里**。三条路线并存时，上层代码凭什么一行不改？

答案是**方法面一致**——本包把它写成一张常量清单，并逐名核对（一条能被失败的对账）：

```text
chat / stream / chat_with_tools / is_available / describe / model_name / backend / context_length
```

三条路线各自的**事实**（不是偏好）：

| | 服务端 | 离线 | 视觉 | 工具调用 | 上下文窗口来自 |
|--|-------|------|------|---------|---------------|
| `in-process` | 不需要 | 是 | 由模型 | **不支持** | `n_positions` / `max_position_embeddings`（写死在配置里） |
| `ollama` | 需要 | 是 | 支持 | 支持 | `OLLAMA_CONTEXT_LENGTH`（默认 4096） |
| `vLLM` | 需要 | 是 | 按模型 | 支持 | `--max-model-len` |

第四条差别最容易被忽略而后果最大：**上下文窗口的来源不同**。
在进程模型的窗口是"模型的硬上界"，而 Ollama 的默认 4096 是"我们的一个选择"——
同一段长文本在两条路线上的"够不够用"是两个不同的答案。

`chat_with_tools` 这一格也值得单独说：`in-process` **明确抛错**，
而不是静默降级成一段自由文本——后者会让 Agent 带着"模型决定不调工具了"的假象继续跑。

## 十一、十条性质与三条跨天对账

```text
逐位（==）    两种填充宽度下的池化、批量与逐条、encode/decode 往返、
              本包的一层 vs day085 的 gpt2_block
整数相等      本包公式 vs 库读数、权重 vs 配置口径
逐名对齐      在进程模型 vs LocalModel
```

三条跨天对账：

```text
画像 vs 配置      day085 从源码读出的默认值 ↔ 今天从 config.json 解析出来的卡片
生成策略          pipeline 的生成 ↔ day085 的 generate（同一个 token 序列）
块的接线          本包的一层 ↔ day085 的 gpt2_block（**逐位**）
```

第三条最强：两条路径的差别只有一处（day085 造一张加性偏置、本包给一张显式掩码），
而它们必须在每一个浮点数上一致——接线走散（LN 放错一侧、残差少加一次）时形状完全看不出来。

**两条性质会走到"不适用"，而"不适用"必须与"通过"分开**：

```text
params_match_library   只对两个**记录在案**的真实模型适用（玩具卡片没有库读数可对）
block_matches_day085   只在 L=1 且 heads=1 的 GPT-2 卡片上适用
```

报告里印的是 `[不适用]`——因为"把这条检查删掉"与"它通过了"在报告里长得一模一样。
