## 一、形状与参数量

### 1. 四个数

```text
d = 6，d_ff = 4d = 24，n = 4，N = 4

块参数   4d（两个 LN 的 γ/β） + 2·d·d_ff（两层线性） + d_ff（b_in） + d（b_out）
         = 24 + 288 + 24 + 6 = 342
注意力   4d² = 4 × 36 = 144
一层     342 + 144 = 486
整条链   4 × 486 = 1944
```

六项来源逐条对应 `BlockParameters` 的八个字段：

```text
norm1_gamma (d) + norm1_beta (d) + norm2_gamma (d) + norm2_beta (d)   = 4d = 24
ffn_w_in  (d_ff, d)   = 144      ffn_b_in  (d_ff) = 24
ffn_w_out (d, d_ff)   = 144      ffn_b_out (d)    = 6
```

### 2. 为什么注意力那一份不算在"块新增"里

它的**来源**不同：四个投影是 day075 的 `AttentionParams`，在 day079 的
`BlockShape.parameter_count` 里就被排除过一次。今天 `StackShape` 把两者做成
**两个属性**（`block_parameter_count` 与 `attention_parameter_count`），
而 `layer_parameter_count` 只是它们的和。

这样做有一个具体好处：第五章"解析式 vs 逐块数出来的"那条性质可以把
两个来源分开核。如果合成一个公式，"公式错了"与"构造漏了一块"就无法区分。

### 3. `d = 8`、`ffn_ratio = 4`、`N = 6`

```text
d_ff = 32

块参数   = 4×8 + 2×8×32 + 32 + 8 = 32 + 512 + 32 + 8 = 584
注意力   = 4×64 = 256
一层     = 840
六层     = 5040
```

把 `ffn_ratio` 改成 2（`d_ff = 16`）：

```text
块参数   = 32 + 2×8×16 + 16 + 8 = 32 + 256 + 16 + 8 = 312
一层     = 312 + 256 = 568
六层     = 3408
少了     5040 − 3408 = 1632 = 6 × 272
```

`272 = 2·d·(d_ff_old − d_ff_new) + (d_ff_old − d_ff_new) = (2d + 1) × 16 = 17 × 16`。
**注意力那一份完全不变**——它只跟 `d` 有关（`4d²`），这正好回答第 2 题。

### 4. 两个数相等；参数少三层时判据亮红

```text
make_shape()                 → total_parameter_count = 1944
make_stack_parameters(...)   → parameter_count       = 1944     ✔ 相等
```

`check_parameter_count_matches(shape(), parameters(layers=1))` **会亮红**：
解析式说的是 `4 × 486 = 1944`（形状里有 `layers=4`），而逐块数出来只有 `486`。
证据行是 `解析式 1944、逐块数 486、层数 1`——三个数一起给，
因此"哪个数不对"一眼能看出来（这里是参数少了三份，而形状没跟着改）。

## 二、链式前向与五个阶段

### 5. 五个阶段

```text
① enter    校验输入形状并把输入当成第 0 层的输出     —— 不改张量
② block    第 i 层的六个子层（day079 的 encoder_block）—— 改张量（但保形）
③ census   记下这一层的几个范数                     —— **不碰张量**
④ carry    把 y_i 交给第 i+1 层                     —— 不改张量（同形传递）
⑤ exit     返回 y_N                                —— 不改张量
```

只有 ② 改张量，而且**改完的形状与改之前一样**——这就是"块可以被复制"的全部内容。

"记账"必须不碰张量，有两条理由：

```text
① 它一旦参与运算，就会出现在反向的图里（而它不该影响任何梯度）
② 读数要能**重放**：StackForward 的构造检查会拿第 i 行的 output_norm
   与第 i+1 行的 input_norm 做逐位比较——记账只要动过一次张量，这个比较就不成立了
```

### 6. `StackForward` 的四条检查

```text
① 输入与输出同形           防的是"某一层改了形状"（那样它不能被复制）
② (n, d) 与 shape 的 (tokens, hidden) 一致
                           防的是"形状与账来自两次不同的前向"（参数按 A 形状造、数据是 B 形状）
③ 环数 == shape.layers     防的是"账少了一层"（反向会静默地少走一层）
④ 第 i 层输出 == 第 i+1 层输入（逐位），且 output == 最后一层输出
                           防的是"链上重算了一遍"与"output 指向了别的张量"
```

②是本课新增的严格性：`tokens` 与 `hidden` 都在记录里，而它们**必须**与张量对得上。

### 7. 那两个数为什么必须相同

因为链上传递的是**同一个值**：`current = forward.output` 之后，
第 i+1 层的 `inputs` 就是它（记录构造时过了一遍 `validate_matrix`，
得到一份**等值**的元组）。因此

```text
forward.censuses[0].output_norm = ‖y_0‖
forward.censuses[1].input_norm  = ‖x_1‖ = ‖y_0‖
```

它对应性质 1 `stack_preserves_shape_at_every_layer`（其中"传递逐位一致"那一部分）。

> 注意判据是 `==` 不是 `is`：记录会**重建**一份等值元组，因此不承诺同一个对象（第八章）。

### 8. 自己写一遍摆放位置的风险

风险是踩 day079 的第二个坑（5.3 节）：**数值侧看不到的那条链，解析侧也不能算进去**。

```text
day079 的实测    norm1_gamma 那一项差 1e-1 量级
根因             块没有拥有它的第一个子层 ——
                 pre-LN 时注意力作用在 LN(x) 上，因此 γ₁/β₁ 会改变注意力的输出，
                 而"从外面传一份算好的注意力账进来"会让数值侧看不到那条链
修法             block_attention(params, inputs, attention_params, placement=...)
                 ——**同一个构造函数**负责"造"与"用"
```

今天的 `stack_forward` 直接调用 `block_attention`，因此这条纪律自动继承下来：
不需要在堆叠这一层再写一次 `if placement == "pre"`。

### 9. 残差关时的 `carry_profile()`

```text
残差 开 | 直通占比 ['0.2937', '0.5655', '0.6079', '0.6363']
残差 关 | 直通占比 ['0.0000', '0.0000', '0.0000', '0.0000']
```

必须是**恰好 0.0**。如果按纯比例 `‖x‖/(‖x‖+‖b1‖+‖b2‖)` 算，残差关时也会得到正数——
于是同一张表里的 `0.30` 既可能指"三成来自直通"，也可能指"残差其实关着"。
修法是把 `use_residual` 记进 `LayerCensus`，并在关掉时直接返回 `0.0`。

## 三、链式反向与两处梯度校验

### 10. 反向循环的三行

```python
layer_grads = encoder_block_backward(layer.block, layer.params, current, activation=...)
grads[index] = layer_grads          # 先存账（按层号）
current = layer_grads.grad_inputs   # 再换手
```

**第三行漏掉不会报错。** 漏掉之后每一层都拿同一份 `grad_output`（也就是 `dLoss/dy_N`），
于是第 0 层收到的梯度只反映了最后一层的影响——形状全对、损失曲线也真的在动。

### 11. 反证

```text
最后一层为什么是对的   它的 grad_output 本来就**应该**是 dLoss/dy_N
                       因此"每层都用 dLoss/dy_N"这个错法在第 N-1 层上完全正确
哪一层先暴露           第 N-2 层（它应该收到第 N-1 层的 grad_inputs，而不是 dLoss/dy_N）
                       本课查的是第 0 层，因为它离得最远、错得最明显
第 0 层 dW_in 的相对差 2.176965e-01（演示脚本第 11 节实测）
```

这也是为什么"只在最后一层做校验"会全绿——而那一份全绿的报告没有意义。

### 12. 少掉的那一项

`BLOCK_GRADIENT_TARGETS` 的第九项是 `"inputs"`（`GRAD_INPUTS`）。

它不能出现在**中间层**的报告里，因为中间层的输入不是自变量：
第 k 层的输入由第 k−1 层算出来，扰动它意味着"同时改了前面所有层的输出"。
数值侧没法只扰动"第 k 层的输入"而不影响前面——那个对象在链上指两个不同的东西。

因此：

```text
kind=stack  查整条链的输入（**只有一个**，它有明确定义）
kind=layer  查第 k 层的**八块参数**（不含输入）
```

### 13. 三个比值与两个商

```text
相邻比值
  0.286225 / 0.317052 = 0.902771
  0.257685 / 0.286225 = 0.900288
  0.227080 / 0.257685 = 0.881232

‖dx_0‖ / ‖dx_3‖ = 0.317052 / 0.227080 = 1.396209      ← 链**内部**首尾之比
‖dx_0‖ / ‖dy_N‖ = 0.317052 / 0.203104 = 1.561036      ← 整体比
```

两个商不同，理由是**数一数个数**：`dx` 序列有 N = 4 个数（`dx_0 … dx_3`），
因此只有 N−1 = 3 个相邻比值，它们的乘积是 `‖dx_3‖/‖dx_0‖`；
而 `dy_N = dy_4` **不在那个序列里**——它是损失对最后一层输出的梯度，
是链**外面**的那一项。

### 14. 为什么数值侧天然能抓住链断

数值侧测的是一个**明确定义的函数**：

```text
f(第 k 层的参数) = stack_loss(用这份参数跑完整条链，与目标比)
```

它每扰动一次就**重跑整条链**，因此它测的是"这一层的改动穿过上面所有层之后对损失的影响"。

而"每层都用 `dLoss/dy_N`"那个错法算的是另一个函数：

```text
它忽略了"上面每一层都会把梯度乘一遍自己的雅可比"这件事
⇒ 它测的不是 f 的梯度，而是"如果这条链只有一层"的梯度
```

因此两者的差会稳定地出现在**离最后一层最远**的那些参数上（第 0 层的 `dW_in`
相对差 `2.18e-01`）。

### 15. 四份报告都通过；只跑 `layer = 3` 抓不到

```text
layer = 0、1、2、3 四份都通过（每份 8 项，最大相对误差在 1e-10 量级）
```

只跑 `layer = 3` **抓不到链断**：第 3 层（最后一层）的 `grad_output` 本来就应该是
`dLoss/dy_N`，因此正确实现与"每层都用同一份"的错法在它身上给出**同一个答案**。

要让这条校验有意义，必须**至少**查一层"离最后一层足够远"的层。本课查第 0 层，
而把四层都查一遍是最省事的做法（`test_it_covers_every_middle_layer` 就是这么写的）。

## 四、逐层读数与两条约定

### 16. 三个读数

```text
carry_share = 2.0 / (2.0 + 1.0 + 1.0) = 0.5
gain        = ‖y‖ / ‖x‖ = 1.0 / 2.0 = 0.5
carry_share（残差关） = 0.0
```

### 17. 为什么既不返回 `nan` 也不返回 `1.0`

```text
nan    会静默污染整张表：第 2 行之后的增益全是 nan，看不出是哪一步坏的
1.0    看起来像"这一层什么都没干"——它其实说的是"这一层的输入是零"
0.0    在一张增益表里是**显眼的**：任何一次真实的堆叠都不会出现它
```

这是一条通用纪律：**"没有定义"要用一个不可能被误读的值表示**，
而不是用"最接近的合理值"（`1.0`）或"传播下去的空值"（`nan`）。

### 18. 为什么要存 `use_residual`

不存的话，`carry_share` 只能写成与残差开关无关的纯比例。于是同一个数字会指两件事：

```text
表里出现 0.30
  残差开时   直通占了输出能量的三成
  残差关时   入口那一份**根本没有被传下去**（这个 0.30 只是三个范数之间的比例）
```

两种情况的工程含义完全不同（前者说明残差在起作用，后者说明残差被关掉了），
因此必须由读数自己带上这个布尔量。

### 19. 动手验证

```text
censuses[i].output_norm == censuses[i+1].input_norm    （i = 0, 1, 2）→ 逐位相等
censuses[0].max_abs_input == max(|x|) 手算             → 相等
```

样本输入的绝对值最大项出现在第 4 行第 1 列：`0.1 × 4 − 0.05 × 1 = 0.35`，
因此 `max_abs_input = 0.35`（一个**单点**读数，与 `‖x_0‖ = 0.781025` 不是一个东西）。

## 五、六条性质

### 20. 哪几条用 `==`

```text
逐位（==）  ① 保形        形状是整数、传递是同一个值 ⇒ 没有容差一说
            ② 与手写循环    两条路径做的是同一串浮点运算
            ③ 确定性        本包没有随机数
            ④ 分支全零即恒等 IEEE 下 x + 0 精确等于 x
整数        ⑤ 参数量        解析式与逐块数都是整数
逐键        ⑥ 组装带形状    从生成的脚本里把 CONFIG 读回来比（数字与字符串）
```

四条逐位判据的共同点是：**它们比较的不是"两次近似计算"，而是"同一串运算的两个入口"**。
有容差的地方只有数值差分（resolution 决定）与两个浮点累积量之间的比较。

### 21. 这条性质要抓的错法

主要抓两类：

```text
① 中间多过一次运算（比如把值存成 float32 再传下去）——**逐位**判据会亮红
② **参数错位一层**（blocks / attentions 的 zip 顺序写反、或者从某一层开始错位）
```

②不会以形状错误的形式出现，因为：

```text
链上每一层都同形（(4, 6) 进、(4, 6) 出）
参数也都同形（每层 486 个，形状一模一样）
⇒ 用错一份参数得到的结果**仍然是一张合法的 (4, 6) 矩阵**
```

具体构造（本题的"错法"）：

```python
params = parameters(layers=3)
forward = stack_forward(params, inputs())            # 账来自 3 层、正确参数
shifted = StackParameters(blocks=params.blocks[1:], attentions=params.attentions[1:])
check_stack_matches_loop(shifted, inputs(), forward)  # → 亮红
```

`test_stack_matches_loop` 的失败证据会说"第 0 层的手写输出与 stack_forward 的输出不符"——
它精确定位到**第一处**对不上的层号。

### 22. 性质函数自己关分支带来的反直觉后果

```text
后果         传一份"只关了一半"的参数进来，这条性质**也会通过**
             （因为它内部会把前馈的 w_out/b_out 与注意力的四个投影都置零）
负例放哪里   必须放在 tests/test_stack_layers.py 里，用 stack_forward 手工构造
为什么         性质函数的判据是"分支全零 ⇒ 恒等"，
             而"只关一个分支 ⇒ 不是恒等"是**另一件事**，
             把它挂在性质上会得到一个**永远为真**的断言
```

> 一条永远为真的断言比没有断言更坏：它占据了一个"已验证"的位置。

### 23. 如果把 `use_residual` 也关掉

一层时：`y = F(LN(x))`，两个分支全零 ⇒ 输出是**全零矩阵**（这是一个合法结果）。

两层时失败路径是：

```text
第 0 层   输出 y_0 = 0（零矩阵）
第 1 层   注意力拿到一个全零行 ⇒
          transformer_core.layers.self_attention 的 _check_inputs 抛
          **transformer_core.errors.NumericError**
          消息："输入第 0 行全零：它会让这一行的打分全是 0、softmax 给出均匀分布，
                而均匀分布看起来像'模型还没学到'。"
```

这不是 bug，而是两天的判据在这里接上：day075 显式决定"全零行不交给这一层猜"
（它是软化成均匀分布还是真的没学到，这两种情况的修法人完全不同）。
对应的测试是 `test_a_deep_bare_stack_hits_day075_zero_row_guard`。

### 24. `CONFIG` 与形状逐项对照

```text
assembly_facts(assembly_script(shape()))["config"]
{'hidden': 6, 'ffn': 24, 'tokens': 4, 'layers': 4, 'num_heads': 2, 'epsilon': 1e-05,
 'placement': 'pre', 'activation': 'relu', 'batch': 2,
 'analytic_layer_parameters': 486, 'analytic_total_parameters': 1944}
```

四项与 `StackShape` 的对应：

```text
hidden 6 == shape.hidden      ffn      24 == shape.ffn
tokens 4 == shape.tokens      layers    4 == shape.layers
```

把 `layers` 改成 `8`，`check_assembly_carries_shape` **会亮红**：它读的是
脚本里的 `CONFIG` 赋值节点（`ast.literal_eval` 出来的字典），
因此 `layers` 与 `analytic_total_parameters` 两项都会对不上，
证据行里会写出 `对不上的 ['layers', 'analytic_total_parameters']`。

关键点是：它读的是**结构**而不是文本——把 `"layers": 4` 写成注释里的 `8` 不会影响它，
而把数字真的改掉一定会被抓住。

## 六、PyTorch 组装与参数量的差异

### 25. 为什么生成而不是导入

那条依赖纪律（day001）是：

```text
运行时依赖只有 requirements.txt 里那几个（torch **不在其中**）
⇒ 包里的模块必须能在任意环境里导入、被测试
```

而"用 PyTorch 组装"是今天的学习目标。两条放在一起，本课选了 day052
（`sft/hf_script.py`）已经用过的那条路：**生成一段脚本文本**，
把"能跑"与"能导入"分开。

为什么用 `ast.parse` 而不是 `"LayerNorm" in script`：

```text
"LayerNorm" in script    对**注释里的**那三个字母也返回 True；
                         对语法错的脚本也返回 True（它根本不是一段代码）
ast.parse + 遍历节点      能回答"这段文本里有几个类、用了哪些 nn.xxx、CONFIG 是什么"
                         ——而这些才是"组装齐不齐"的判据
```

`assembly_facts` 还会在解析失败时**当场报错**：一段连 `ast.parse` 都过不去的脚本
在被运行之前就已经没有意义了。

### 26. 那 `96` 个参数是什么

```text
d = 6，N = 4

本课解析式（每层）     4d² = 144
PyTorch（每层）        in_proj_weight  (3d, d)  = 108
                      in_proj_bias    (3d,)     = 18
                      out_proj.weight (d, d)    = 36
                      out_proj.bias   (d,)      = 6
                      ─────────────────────────────
                      168 = 144 + 24 = 4d² + 4d

差值（每层）           24 = 4d
差值（整条链）         96 = N × 4d = 4 × 24
```

本机实测：

```text
可训练参数 2040（PyTorch）
本课解析式 1944
差值 96 —— 与手算一致
```

**两边的 LayerNorm 与前馈是完全一样的**（`nn.LayerNorm(d)` 的 `weight/bias` 各 `d` 个，
两个 LN 共 `4d = 24`；`nn.Linear` 两次共 `2·d·d_ff + d_ff + d = 318`），
差异**全部**来自注意力的四个偏置。

处理方式是把两个数都打印出来、把差值讲清——**差异必须被看见，而不是被凑平**。

### 27. 为什么把 `num_heads` 的检查挡在生成那一刻

不挡的话，`nn.MultiheadAttention` 会在 `d % num_heads != 0` 时于**前向**报错：

```text
那时已经     模型建好了、权重初始化了、数据搬到设备上了
而真正的错因  一行参数（num_heads=4 而 d=6）
```

"晚报"在工程上更贵，因为报错位置与错因离得很远——排查要跨过好几层调用栈。
本包把这类检查全部放在**最靠外的入口**（生成器、记录构造器），
于是"报错位置 == 出错位置"。

对应的测试是 `test_heads_must_divide_the_hidden_width`（参数化 `4 / 5 / 7`）。

## 七、堆叠实验与几何平均

### 28. 几何平均与那条恒等式

```text
三个相邻比值        0.902771, 0.900288, 0.881232
几何平均            0.894712（演示脚本实测）

恒等式
  mean_step_ratio ^ (N − 1) = 0.894712³ = 0.716225
  ‖dx_{N−1}‖ / ‖dx_0‖       = 0.227080 / 0.317052 = 0.716225    ✔ 逐位对上
```

它**不**等于 `overall_ratio`，因为：

```text
dx 序列里有 N = 4 个数（dx_0 … dx_3）⇒ 只有 N − 1 = 3 个相邻比值
它们的乘积 = ‖dx_3‖ / ‖dx_0‖          ← 链**内部**首尾之比
而 overall_ratio = ‖dx_0‖ / ‖dy_N‖     ← 分母是链**外面**的那一项
dy_N 不在 dx 序列里 ⇒ 两个量不是一回事
```

样本上 `overall_ratio = 1.561036`，而 `‖dx_0‖/‖dx_3‖ = 1.396209`。

### 29. 为什么用几何平均

因为比值是**相乘**的。算术平均会给出一对互为例数的数一个没有含义的"中间值"：

```text
3.0 与 0.333…
  几何平均  √(3 × 1/3) = 1.0     ← 正确：乘起来恰好回到 1
  算术平均  (3 + 1/3)/2 = 1.667  ← 没有任何含义
```

在链上，`(3.0, 1/3)` 的意思是"某两层分别把梯度放大到 3 倍、缩小到 1/3，
两层的净效果是 1 倍"。几何平均能读出这件事，算术平均读不出。

（`geometric_mean(()) == 1.0`：空序列返回乘法的**单位元**，而不是 0。）

### 30. 两列的含义、判决与边界

```text
残差开的“每层倍数”   0.693868 ~ 0.948060，极差 max/min = 1.441197
                    ——每一层平均把梯度乘上（约）0.9 倍，而且这个因子与总深度几乎无关
残差关的“每层倍数”   1.430753 ~ 11.097718，极差 = 11.097718
                    ——它自己就开始乱跳：2 层时 1.11e+01、3 层时 3.29e+00、
                      4 层时 1.43e+00、6 层时 2.06e+00、8 层时 3.12e+00
```

**为什么"极差"能作为判据**：一个与深度无关的因子应当是一个**常量**
（只差随机波动），因此它在整条深度序列上的 `max/min` 应该保持在 1 附近。
量级上的"差不多"用 `max/min < 2` 表达：**这个判据宽松到不会被浮点噪声翻面，
又严格到能把"乱跳"与"稳定"分开**（1.44 与 11.10 相距很远）。

判决 `verdict_ok` 由**两个**条件组成：

```text
① 最深一层上 bare 的整体比 < residual 的 1/10     （实测 6.90e-05 vs 1.61e+00）
② 残差开的每层倍数极差 < 2                        （实测 1.441197）
```

只有条件 ① 不够，因为 **bare 那一列是非单调的**：

```text
bare 的整体比    2.10e-01 → 8.49e-02 → 1.33e-01 → 8.90e-02 → 3.40e-03 → 6.90e-05
                 （3 层时比 2 层时更大、4 层时又回落）
```

也就是说"关掉残差之后梯度一定单调衰减"这句话**是错的**——它取决于每一层
随机到的雅可比谱。条件 ① 只保证"终点塌了"，条件 ② 才保证"残差开时那个因子是稳定的"。
两条合起来才支撑得住"残差给出了一条与深度无关的路"这个结论。

**这一课不回答的问题**：

```text
它回答      "每层梯度乘上多少、它与总深度有没有关系"（一个**数值**问题）
它不回答    "这摞块能不能训好"——那要看损失曲线、学习率与数据（day081 接手）
```

而且 `overall_ratio` 大于 1 **不一定是好事**：那同样可能是"梯度在放大"。
这条读数只说明**那条路没有被掐断**。最后，这份表是一次观测（一颗种子、
一个初始化幅度、一条深度序列）——要下"残差一定更好"的结论需要多种子与统计检验。
