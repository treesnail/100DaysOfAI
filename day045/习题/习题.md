## 第一部分：选择题

### 第 1 题（显存构成）

估算本地部署显存时，`KV 缓存 = 2 × batch × 序列长度 × 层数 × KV 头数 × head_dim × 精度字节数` 中的 "2" 与 `KV 头数` 分别指什么？

- A. "2" 指输入和输出两次推理；`KV 头数` 等于注意力头数
- B. "2" 指 Key 与 Value 两份张量；`KV 头数` 是 GQA 架构里的 KV 头数，通常远小于注意力头数
- C. "2" 指 FP16 的 2 字节；`KV 头数` 等于隐藏层数
- D. "2" 指模型权重的两份副本（显存 + 内存）；`KV 头数` 与上下文长度无关

### 第 2 题（量化档位）

在项目的 `QUANTIZATION_BITS` 表里，GGUF 的 `q4_k_m` 被记作 **4.5** bpw 而不是 4.0 bpw，原因是：

- A. 四舍五入误差，实际就是 4.0
- B. k-quant 是混合量化：关键张量用更高位宽、其余压到 4 位，加权平均约 4.5 bpw；按 4.0 估算会低估显存、压着上限部署会 OOM
- C. 4.5 是为了兼容 FP16 的对齐要求
- D. `q4_k_m` 里含 embedding 层，多出的 0.5 是 embedding 的固定开销

### 第 3 题（协议兼容）

`LocalModel` 继承 `OpenAICompatibleLLM` 而不是从零实现一个"Ollama 客户端"，最核心的理由是：

- A. 继承能减少代码行数，纯粹为了省事
- B. Ollama 与 vLLM 都提供 OpenAI 兼容端点，本地与云端的差异只在部署与运维层，不在调用协议层——继承是在声明这个架构事实
- C. 因为 `BaseLLM` 是抽象类，子类必须继承某个具体实现
- D. 为了让 `LocalModel` 自动获得 `ModelRouter` 的路由能力

### 第 4 题（端点规范化）

`normalize_base_url("http://localhost:11434")` 返回 `http://localhost:11434/v1`，而 `normalize_base_url("https://gw.example.com/proxy/llm")` 原样返回。后者的设计意图是：

- A. 说明函数对 https 不做处理，是待修 bug
- B. 只在路径为空或 "/" 时自动补 `/v1`；用户显式写了反向代理前缀就不该被改写，避免画蛇添足
- C. 因为 `/proxy/llm` 已经是完整的 OpenAI 兼容路径
- D. 防止在非本机地址上意外泄漏 API Key
