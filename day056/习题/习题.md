### 第 1 题（SFT 的核心机制）

SFT 里 `IGNORE_INDEX = -100` 的作用是：

- A. 标记分词失败的位置
- B. 把 **prompt 段**的 label 置为忽略，使交叉熵只计算答案 token——这是"同一个模型为什么能学会跟随指令"的工程答案
- C. 把超长的样本截断掉
- D. 标记 padding 位置，与 mask 无关

### 第 2 题（`max_length` 的口径）

day049 预算的 `max_length` 是 128~256（按 day048 画像的 token 估计），而 day050 实际缺省取了 **384**。最根本的原因是：

- A. 384 是 32 的整数倍，便于对齐
- B. day049 的估计口径是**未渲染未分词的字符→token 估算**（平均 84.24），而 day050 实测的是**渲染并分词之后**的长度分位数（`p95 = 302`、`max = 320`）——**口径变了，数字就得跟着变**
- C. 384 是模型的上下文窗口
- D. day049 算错了

### 第 3 题（QLoRA 的每参数字节数）

`llama-2-7b` 用 nf4 + `block=64` + 二级量化的实测值是：

- A. 每参数 4.0 bit，即 0.5 字节
- B. 每参数 **4.126953** bit，因为二级量化与块常数额外占用存储；写成 4 会让 7B 的权重估算少算约 100 MB
- C. 每参数 8.0 bit，与 int8 相同
- D. 每参数 2.0 bit

### 第 4 题（"训练 loss 降了"）

day053 的白盒探针里，`lr=8.0` 那一组的训练集困惑度从 421.82 降到 **14.46**，而评估集困惑度变成 **587.64**。这个现象的正确解读是：

- A. 训练成功，评估集数据有问题
- B. 典型的**过拟合**：只看训练 loss 的人会以为找到了最佳配置，而评估集上的泛化间隙是 573.24
- C. 说明 LoRA 不擅长领域适配
- D. 说明参考模型的困惑度不可信

### 第 5 题（DPO 的起点自检值）

`loss_type="ipo"`、`beta=0.1` 时，`margin = 0` 处的损失期望值是：

- A. `ln2 ≈ 0.693`

### 第 12 题（重做一次步数算术并核对 `warmup_floor`）

写一个离线、确定性、不联网的脚本，完成两件事：

1. **重做 DPO 步数算术**：用 `DPOTrainingConfig()` 的默认配置（batch=2 / 累积=2 / epochs=3.0），对 `train_pairs ∈ {7, 16, 32}` 分别打印 `micro_batches_per_epoch` / `optimizer_steps_per_epoch` / `total_steps` / `warmup_steps` / `effective_batch_size` / `warmup_degenerate`，并**手算核对**每一行（把取整过程打印出来）。
2. **核对 `warmup_floor` 的语义**：对每个 `total_steps`，用 `warmup_floor(total_steps)` 得到一个比例下界，再把它喂回 `warmup_ratio` 重算 `warmup_steps`，断言重算结果**至少为 1**；同时断言"比例略小于下界时 `warmup_steps` 退化为 0"。

要求给出完整可运行的代码与实测输出，并回答：为什么"`warmup_degenerate` 是一个布尔量"比"在文档里写一句'小数据集上 warmup 不生效'"更有价值？
