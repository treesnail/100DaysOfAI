## 第 1 题

**答案：C**

解析：Git 分支只是一个指向 commit 的指针文件（41 字节的 SHA-1 哈希）。创建分支 = 写一个指针文件 + 移动 HEAD，没有任何文件被复制，所以是 O(1) 的瞬时操作。A 是 SVN 式思维；B 错误，创建分支不产生新 commit；D 错误，未修改的内容不会重复入库。

## 第 2 题

**答案：B**

解析：Docker 镜像分层缓存的规则是"某层变化后，其后的所有层都失效"。把变化频率低的 `requirements.txt` 和 `pip install` 放前面，变化频率高的源码 COPY 放后面，这样改代码时依赖层命中缓存，不用重装依赖。A 每次改代码都会重装依赖；C 无法工作（依赖文件还没 COPY 进来）；D 没有利用缓存的思想。

## 第 3 题

**答案：B**

解析：行覆盖 100% 只说明每行代码都执行过；分支覆盖 60% 说明有 40% 的分支路径（如某些 `if` 为真或为假的情况）从未被测试走到。A 错误，覆盖率不等于测试充分性；C 与行覆盖 100% 矛盾；D 混淆了覆盖率与正确性。

## 第 4 题

**答案：错**

解析：`--soft` 只移动 HEAD 指针回到上一个提交，暂存区和工作区的改动都完整保留。会丢失工作区修改的是 `git reset --hard`。三档对比：

| 模式 | HEAD | 暂存区 | 工作区 |
|------|------|--------|--------|
| `--soft` | 回退 | 保留 | 保留 |
| `--mixed`（默认） | 回退 | 清空 | 保留 |
| `--hard` | 回退 | 清空 | 清空（危险！） |

## 第 7 题

**参考答案**：

幂等性是指脚本执行 1 次和执行 N 次，系统最终状态相同。它重要的原因：

1. **容错重试**：自动化流程中失败是常态（网络抖动、依赖暂时不可用）。幂等脚本可以直接重跑；非幂等脚本可能留下半成品状态（如建了一半的 venv），重跑反而报错或造成更脏的状态。
2. **CI/CD 可重复执行**：流水线可能被重试、被并发触发，幂等性保证行为可预期。
3. **降低使用心智负担**：用户不需要记住"这个脚本是不是已经跑过了"。

不幂等在 CI 中的典型问题：第一次构建失败在"创建 venv"之后、"装依赖"之前；重试时脚本试图重建 venv 但目录已存在导致报错，流水线永远无法自愈，必须人工介入清理。

## 第 8 题

**参考答案**：

merge 方式：

```bash
git checkout day005-tool-registry
git merge main
```

会在你的分支上产生一个合并提交，历史呈分叉汇合状，真实保留"此时合并过 main"的事实。

rebase 方式：

```bash
git checkout day005-tool-registry
git rebase main
```

把你分支上的提交摘下，依次重放到 main 最新提交之后，历史变成直线。

**已推送的分支用 rebase 是危险的**：rebase 会重写提交的 SHA-1 ID（相当于"销毁旧提交、创建新提交"）。远程仓库上存的是旧 ID，你本地是新 ID，push 时会被拒绝，只能 `--force` 强推。如果这个分支有任何其他人基于它工作过，他们的历史会和新历史彻底错乱。

黄金法则：**只在本地未推送的分支上 rebase；已共享的历史用 merge。**

## 第 10 题

**参考答案**（`scripts/push.sh`）：

```bash
#!/usr/bin/env bash
# 推送脚本：提交并推送当前分支
set -euo pipefail

COMMIT_MSG="${1:-}"

if [ -z "$COMMIT_MSG" ]; then
    echo "错误：请提供提交信息，例如: ./scripts/push.sh 'feat: Day X - 内容摘要'"
    exit 1
fi

# 检查是否有未提交改动（若有则必须先提交，本脚本负责提交）
# git diff --quiet 有改动时返回非零
if ! git diff --quiet || ! git diff --cached --quiet; then
    echo "[1/3] 检测到未提交改动，暂存并提交: $COMMIT_MSG"
    git add .
    git commit -m "$COMMIT_MSG"
else
    echo "[1/3] 无未提交改动，跳过提交"
fi

# 自动识别当前分支
CURRENT_BRANCH="$(git rev-parse --abbrev-ref HEAD)"

echo "[2/3] 推送当前分支: $CURRENT_BRANCH"
git push origin "$CURRENT_BRANCH"

echo "[3/3] 推送完成"
```

要点解析：

1. `git rev-parse --abbrev-ref HEAD` 输出当前分支名，不再写死 `main`。
2. `git diff --quiet`（工作区 vs 暂存区）+ `git diff --cached --quiet`（暂存区 vs HEAD）组合检查是否有未提交改动。
3. `set -euo pipefail` 保留失败即停；无改动时跳过 commit 步骤，重复执行不产生空提交，保持幂等。
