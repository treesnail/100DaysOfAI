## 二、简答题

**8.** "预测等于目标时**恰好 0**"这条判据抓的是**分子里多了东西**的实现错误：

```text
能失败    多了正则项 / 常数偏移 / 少了一次平方 ⇒ mse(P, P) != 0.0，当场被抓
不能失败  分母写错 ⇒ 分子恒为 0，任何分母都得 0.0 ⇒ **这条判据抓不到**
```

这正是"错误的分母"要**小心**的地方：`p = t` 时逐元素平方差全为 0，
所以 `0 / 4` 与 `0 / 3` 都是 `0.0`——**恰好 0 抓不住分母**。
抓分母的是第 5 条性质的**第二半**：`mse(P, T)` 必须等于逐元素平方差的均值。读数：

```text
正分母：mse(P, T) = 0.625000（4 个元素，平方和 2.5 ⇒ 2.5/4）
错分母：同一个平方和除以 3 ⇒ 0.833333 ≠ 0.625（当场被抓）
```

所以一条性质里"恰好 0"与"等于手算均值"是两把不同的尺子，缺一不可。

**9.** 本课 `gelu` 的对账对象是**两个真实函数**：

```text
encoder_decoder.layers.activate(..., "gelu")   （day079 的前馈/块里用的那个）
hf_source.blocks.gelu_exact                     （day085 读源码时落下来的那个）
```

它们用的是同一个**精确 erf 式** `0.5x(1+erf(x/√2))`，因此可以逐位比：
演示读数 `gelu vs hf_source.blocks.gelu_exact：11 点上不一致 0 个`。

**不是**对账 tanh 近似，因为它与精确式**本来就不一样**，逐位对账必然失败：

```text
x = 0    两式函数值同为 0、导数同为 0.5
x = ±3   偏差 4.123020e-04（可量出）
x = ±1.5 偏差 2.176211e-04
```

复算：`python -m pytest tests/test_neural_basics.py -k "gelu_tanh"`。

**10.** 四条前提（缺一条都可能在最后一位分家）：

```text
① 同一组权重对象    ffn_block 直接用 FFNWeights 的四块，不重新初始化
② 形状约定相同      w_in (d_ff, d)、w_out (d, d_ff)、前向 x·Wᵀ + b
③ 累加方式相同      都用 math.fsum，且乘法顺序相同（逐行、逐 in_features）
④ 激活公式相同      relu = value if value > 0 else 0.0；gelu = 精确 erf 式
```

把求和顺序换一下（例如先按列求和再相加），两个实现会在最后一位不同——
这时"逐位不一致 12 个元素"这条判据会变红，而**两个实现都不算错**。
这正是本课坚持逐位对账的理由：它把"口径不同"与"接错了"分开。
复算：演示第 9 节（relu / gelu 各逐位不一致 0 个）。

**11.** 偏差 `4.441e-16` 来自两条路径的**求和方式不同**：

```text
路径 A  −log_softmax(logits)[target]     log_softmax 用内置 sum    （对齐 sft.loss）
路径 B  −log(softmax(logits)[target])    softmax 用 math.fsum      （对齐 math_foundations）
```

`math.fsum` 用更精确的补偿求和，`sum` 是朴素累加，因此两者在小数第 16 位分家。
这个选择是**刻意的**：A 要与 `sft.loss.log_softmax` 逐位一致（判据 0 个不一致），
B 要与 `math_foundations.linalg.softmax` 逐位一致（判据 0 个不一致）。
两条"逐位"都对上之后，A 与 B 之间的差只能落在一个**上界**里，所以判据写成
"偏差 <= 1e-12"，而不是"相等"——把两类判据混在一起，就会出现
"偏差恰好是 0（因为输入全是 0）被当成通过"。
复算：演示第 7、8 节。

**12.** 如果拿含 `±1000` 的网格去做 `sigmoid ∈ (0, 1)` 的**严格**开区间断言：

```text
sigmoid(-1000) = 0.0    （下溢饱和）  ⇒ 0.0 不在 (0, 1) 里        ⇒ 被判为"越界"
tanh(-1000)    = -1.0   （饱和）      ⇒ -1.0 不在 (-1, 1) 里      ⇒ 被判为"越界"
```

这属于**问题问错了**，不是实现错了：`sigmoid` 在 `x=-1000` 上**本来就**该趋近 0，
浮点下溢成 `0.0` 是定义域代价。修法是把两种问题用两套网格分开：

```text
FINITE_GRID（含 ±1000）  问"还有限吗"（数值稳定）
RANGE_GRID （有界 9 点） 问"值域被遵守吗"（严格开区间）
```

本课的演示读数：6 个激活在 `RANGE_GRID` 上**越界个数全为 0**。
复算：演示第 2、3 节。

## 三、诊断题

**13.** 单式 `sigmoid` 的失败点在 **`x = -1000`**（以及任何小于约 `-710` 的点）：

```text
1.0 / (1.0 + math.exp(-(-1000))) = 1.0 / (1.0 + math.exp(1000))
math.exp(1000) ⇒ OverflowError: math range error    （CPython 行为）
```

它**不是**"返回了一个错的数"，而是"根本算不出来"。归族与动作：

```text
族      NumericError（出路：改实现——写成按符号分支的两条式子）
不是     ActivationError（那一族是"输入本身 nan/inf 或激活名未知"；
         这里的输入 -1000 完全合法，坏的是实现的数值稳定）
不是     LossError（它不经过任何损失）
```

哪一条性质会当场抓住它：**第 1 条** `activations_are_finite`——
它的网格含 `±1000`，单式实现会在这里抛 `OverflowError`（或给出越界读数），
读数不为 0。

一个值得记住的细节：在 numpy / torch 里 `exp(1000)` 返回 `inf`，
于是单式得到 `1/(1+inf) = 0.0`——**恰好是正确的**。也就是说这个 bug
"在一种环境里崩、在另一种环境里悄悄对"，这比"到处都错"更难被发现。
复算：`python -m pytest tests/test_neural_basics.py -k finite`。

**14.** 它**先**报 `ForwardError`，而且在 `MLPSpec(...)` **构造那一刻**就报：

```text
第 0 层的输出宽度 4 与第 1 层的输入宽度 5 接不上：前向的定义要求相邻两层共享同一个宽度
```

原因是"宽度接不上"是**结构**问题，不是某一次调用的形状问题——
等前向时才报，就分不清"网络定义错了"与"我把某一行的长度写错了"。
修法有两条（改哪一个字段取决于设计意图）：

```text
改第 1 层的 in_features：DenseSpec(5, 2, ...) → DenseSpec(4, 2, ...)
或改第 0 层的 out_features：DenseSpec(3, 4, ...) → DenseSpec(3, 5, ...)
```

改完宽度链变成 `3 → 4 → 2`（或 `3 → 5 → 2`），前向才有一致的定义。
复算：`python -m pytest tests/test_neural_basics.py -k chain`。

**15.** 三条读数各自的诊断与动作：

```text
读数 A  softmax 行和 = 0.98（偏差 2.0e-02）
        诊断：归一化不完整——多半是分母漏掉了一部分项（只对一部分 logits 取了 exp），
              或者按错了轴（对列而不是行做归一化）
        动作：让分母恰好是"这一行全部 logits 的 exp 之和"；改完行和偏差应回到 1.110e-16
              抓它的性质：softmax_rows_are_distributions（读数应为 0 个不一致）
        （本课正确读数：行和 0.9999999999999999，偏差 1.110e-16）

读数 B  FFN 对账：逐位不一致 12 个元素
        诊断：口径不同而不是"算错"——最可能是三处之一：

读数 C  mse(P, P) = 1e-17（不是 0.0）
```

## 四、推导题

**16.** （softmax 的平移不变性）设 `c = max(z)`，记 `S = Σ_j exp(z_j - c)`。
对任意 `i`：

```text
exp(z_i - c) / Σ_j exp(z_j - c)
  = exp(z_i)·exp(-c) / ( Σ_j exp(z_j)·exp(-c) )
  = exp(z_i)·exp(-c) / ( exp(-c)·Σ_j exp(z_j) )
  = exp(z_i) / Σ_j exp(z_j)                                  ✔
```

关键是 `exp(-c)` 同时出现在分子与分母、被约掉，因此这是**恒等**而不是近似。
它的**全部价值在数值**：`max` 之后 `z_i - c <= 0`，于是每个 `exp <= 1`，不会上溢。

```text
不做它   z = (1000, 1001)，max = 1001：CPython 的 math.exp(1000) 直接抛 OverflowError
         （numpy / torch 里是 inf，随后 inf/inf = nan）
做了它   z - max = (-1, 0) ⇒ [0.2689414213699951, 0.7310585786300049]（有限）
```

复算：`python scripts/neural_basics_demo.py` 第 3 节。

**17.** （恒等塌缩）设一层 `y = x·W₁ᵀ + b₁`（`W₁` 形状 `(m, k)`、`b₁` 形状 `(m,)`），
第二层 `z = y·W₂ᵀ + b₂`（`W₂` 形状 `(n, m)`、`b₂` 形状 `(n,)`）。代入：

```text
z = (x·W₁ᵀ + b₁)·W₂ᵀ + b₂
  = x·(W₁ᵀ·W₂ᵀ) + (b₁·W₂ᵀ) + b₂
  = x·(W₂·W₁)ᵀ  + (b₁·W₂ᵀ + b₂)          （用了 (A·B)ᵀ = Bᵀ·Aᵀ）
```

因此取：

```text
W = W₂·W₁                    （形状 (n, k)）
b = b₁·W₂ᵀ + b₂              （形状 (n,)）
```

就有 `z = x·Wᵀ + b`。把这条推导逐层叠下去，就是任意多层仿射的合成
（本课 `compose_affine` 做的事）。

如果两层之间插一个 `relu`：

```text
z = relu(x·W₁ᵀ + b₁)·W₂ᵀ + b₂
```

`relu` 是**非线性**的：`relu(a + b) != relu(a) + relu(b)`，因此上式的第一项
不能再展开成 `x·(W₂W₁)ᵀ`。**等式在插入非线性的那一刻失效**——这就是"深度需要激活"的来源。

演示读数：恒等网络 `3 → 4 → 5 → 2` 的多层输出与单层输出最大偏差 `8.882e-16`（<= 1e-12）。
复算：演示第 6 节。

**18.** （两个下界 / 恰好值）

（甲）设 `p, t` 形状相同，共有 `N` 个元素。`mse(p, t) = (1/N)·Σ_i (p_i - t_i)²`。
因为每一项 `(p_i - t_i)² >= 0`，平方和等于 0 当且仅当每一项为 0，
即 `p_i = t_i`（对所有 `i`）。所以：

```text
mse(p, t) = 0  ⇔  p = t（逐元素）                    ✔
```

它挡住的是"分子里多了正贡献"这一类错误（正则项、常数偏移、多余的加法）。

（乙）设 `q = softmax(z)`，`target = k`。由 softmax 的定义，每个分量
`q_k = exp(z_k - max) / Σ_j exp(z_j - max) > 0`，且 `q_k <= 1`（它是某个分布的某一项）。
于是 `log q_k <= 0`，从而：

```text
CE = −log q_k >= 0                                    ✔
```

等号当且仅当 `q_k = 1`（这一步模型对正确答案给出概率 1）。
它挡住的是"把概率当 logits 传进去"或"符号写反"这一类错误：
一旦 CE 出现负值，就说明"这一项不是一个概率的对数"。

本课读数：`4 个用例中 CE<0 的 0 个`；`mse(P, P) = 0.0`。
复算：`python -m pytest tests/test_neural_basics.py -k "cross_entropy_paths or mse_is_zero"`。
