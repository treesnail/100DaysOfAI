## 今日目标

day093 结束时，那句话是被明写的：**"同一组核被用到全图的每一个位置"**。
今天把同一句话搬到**时间轴**上。

```text
时间轴权重共享  →  参数量与序列长度 T **完全无关**   （一个循环体被调用 T 次）
隐状态          →  对"到目前为止的全部历史"的有损摘要  （宽度就是记忆预算）
LSTM 的记忆通道  →  c_t = f⊙c_{t−1} + i⊙g            （梯度沿它走**只乘 f**）
```

三个问题：

1. **时间上的权重共享到底省了什么？** D=2、H=3 的单元，序列是 1 步还是 8 步，
   参数量都是 18（RNN）/ 72（LSTM）——**一个也不多**（第二章）。
2. **`h₀` 与 `h_T` 差一个会怎样？** 把初值算进输出会得到 `T+1` 个状态，
   下游 `zip` 静默截断，于是"第 t 个状态"与"第 t 个输入"整体错位一格，
   **而它不会报错**（第四章）。
3. **为什么 LSTM 能记住远处、tanh-RNN 不能？** `∂h_T/∂h_0 ≤ ‖W_h‖ᵀ` 指数衰减，
   而 `∂c_T/∂c_0 = ∏f_t` 几乎不衰减（第六、七章）。

最终产出：10 个新文件（`sequence_models/`）、1 个新测试文件（**80 个用例**）、
一本手册（`docs/sequence_models.md`，11 节）与一份演示脚本（`scripts/sequence_models_demo.py`，十一节）。

## 第一章：从"每个位置一个权重"到"每个时刻一组权重"

### 1.1 day093 到 day094 的那句话

```text
day089   Dense：**每个输入位置用一个独立的权重**      回答"最小的零件长什么样"
day090   反向：梯度怎么原路传回去                     回答"往回走时每一步写什么"
day092   优化器：拿到梯度后一步走多远                 回答"走多远"
day093   卷积：**同一组核在每一个位置复用**            回答"图像这类数据凭什么更省"
day094   循环：**同一组权重在每一个时刻复用**          回答"序列这类数据凭什么更省"
```

区别就一句话：

```text
全连接     每个输入分量 × 每个输出分量 各有一个独立权重   ⇒ 参数随输入宽度**平方**增长
卷积       同一张核滑过全图（**空间**共享）               ⇒ 参数只随核尺寸增长
循环       同一组权重被 T 个时刻复用（**时间**共享）       ⇒ 参数与序列长度 T 完全无关
```

### 1.2 一个必须先说清的对比：并行 vs 串行

同样是"权重共享"，卷积与循环有一个**根本差别**：

```text
卷积   全图的每一个位置**彼此独立**（都是用同一张核去点积）
       ⇒ 可以一次算完（向量化 / im2col / GPU 的并行）

循环   第 t 步的输入包含第 t−1 步的输出
       ⇒ **只能按顺序算**（T 步就是 T 次串行的乘法）
```

这条差别不是实现细节，它是 RNN 在工业界被注意力机制取代的两个原因之一
（另一个是信息路径长度，见第十一章）。本课会反复回到它。

### 1.3 今天的架构：一个包 + 六个失败族

```text
errors.py    六个失败族（含 TimeStepError：状态数差一个；**GradientError 今天回来了**）

```

## 第二章：时间轴上的权重共享 —— 到底省了多少

### 2.1 两个数摆在一起

```text
D=2、H=3 的朴素循环单元：
    W_x (3×2) 6 个数 + W_h (3×3) 9 个数 + 偏置 3 个数 = 18 个可学的量
    序列是 1 步还是 8 步？——**都是 18**（study.parameter_rows）
```

`study.parameter_rows()` 印出的正是这件事：

```text
T = 1   | rnn 18 | lstm 72
T = 3   | rnn 18 | lstm 72
T = 8   | rnn 18 | lstm 72
```

**一个也不多。** 产生的对比是：如果换成"每个时刻一套权重"（把 8 步的序列当成 16 维的
一个大向量喂进全连接），参数量会随 T **线性增长**；而循环网络让"同一组权重被复用 T 次"。

### 2.2 参数量公式

```text
rnn    params = H·D + H·H + H = H·(D + H + 1)
lstm   params = 4·(H·D + H·H + H) = 4H·(D + H + 1)
```

后一项是偏置。LSTM 前面的那个 **4** 是"四个门各要一套权重"——
输入门、遗忘门、输出门、候选。实现见 `types.RNN_PARAM_FORMULA` /
`types.LSTM_PARAM_FORMULA` 与 `layers.RNNSpec.parameter_count`。

### 2.3 代价是什么

与卷积一样，时间共享也带来一个**假设**：同一个变换在序列的每一个时刻都应当成立。
对"词序 / 时间序列 / 音频帧"这类数据这是对的；对"每一步含义都不同"的数据
（例如一张表的每一列语义不同），它就不再合适——那时该把它当成一个普通向量，
让每个位置有自己的权重（全连接）。

## 第三章：算子层 —— 行是输出、列是输入

### 3.1 一个必须写下来的约定

```text
W 的形状 (H, D)：H 行 = H 个输出单元，D 列 = D 个输入分量
W·x 的第 i 个分量 = Σ_j W[i][j]·x[j]        ← 第 i 行与 x 的点积
```

本包与 `torch.nn.Linear`（`weight` 形状 `(out, in)`）以及 day089 的 `Dense`
（`(out_features, in_features)`）**同口径**。

### 3.2 四个算子

```text
matvec              W·x          仿射的一半
matvec_transpose    Wᵀ·g         反向的一半（把梯度投影回输入空间）
outer               g ⊗ x        dW 的**每一时刻那一片**
gate_blocks         4H → (i,f,o,g) 四块  LSTM 的门切块
```

### 3.3 为什么这四行值得单列

因为**写反了不会报错**。举一个具体的例子：

```text
把 dx = W_xᵀ·dz 写成 dx = W_x·dz
  ⇒ H == D 时形状仍然合法（方阵！），数值全错
  ⇒ H != D 时形状不合法，当场抛 ShapeError —— "运气好"才被发现
```

因此第 ⑥ 条性质用 day074 的数值差分把 `dW_x` / `dW_h` / `dx` 一起钉住：
它们形状都对，但乘法方向错了，只有一把独立的尺子能发现。

`gate_blocks` 的顺序同理：把 i / f / o / g 的**行块顺序**弄错，
四个块仍然都是长度 H 的向量，只是"输入门"在做"遗忘门"的事——
第 ② 条性质（三门钉死）就是为这件事准备的探针。

## 第四章：一步与整段 —— 状态对齐为什么值钱

### 4.1 `h₀` 是初值，不是输出

```text
rnn_forward(cell, x₁…x_T)    ⇒  返回 h₁ … h_T   （T 个）
                                h₀ 是**初值**（缺省全零），不出现在输出里
```

这是本课最容易踩、而且**永远不会报错**的一个坑：

```text
若实现里顺手把 h₀ 也塞进输出 ⇒ 得到 T+1 个状态
  下游 zip(状态, 输入) 会静默按较短的截断
  ⇒ "第 t 个状态"与"第 t 个输入"整体错位一格
  症状：训练仍然在跑、损失仍然在降（降得更慢），
        而"模型记不记得住"这个结论是假的
```

本课把它单列成一族错误 `TimeStepError`（第五章会讲它与 `ShapeError` 的分工）。
第 ④ 条性质把它写成一条可断言的整数判据：

```text
通过 sequence_alignment_matches_input   | 读数 0.000e+00 == 0  | rnn 3 / lstm 3 个状态 vs T = 3
```

### 4.2 前向只写一遍

`layers.rnn_forward` 是"整段"的唯一实现；`gradients.rnn_forward_with_cache`
在数值上与它**逐位一致**，只是多留了每一步的 `(x_t, h_{t−1}, z_t)`。
测试里有一条专门断言这件事：

```python
def test_rnn_forward_with_cache_matches_layers() -> None:
    states, caches = gradients.rnn_forward_with_cache(cell, study.SAMPLE_SEQUENCE)
    assert states == layers.rnn_forward(cell, study.SAMPLE_SEQUENCE)   # 逐位
```

理由与 day093 相同：反向要用到"激活之前的值"，但**前向不能因此写两遍**。

### 4.3 权重在时间上真的被复用了吗

第 ③ 条性质用两条独立的路径回答它：

```text
① 参数量由公式算出（H(D+H+1) = 12），与参数本体自己数出来的数逐位对齐
② 整段的第 t 步 vs "拿 states[t−1] 调一次单步函数" —— 逐位相同
```

第二条是关键：它证明"循环体"确实**只有一个**，整段只是把它调用了 T 次。

## 第五章：LSTM 的四个门 —— 记忆通道是怎么被管起来的

### 5.1 四条方程

```text
i = σ(W_xi·x_t + W_hi·h_{t−1} + b_i)     输入门：这一步**写多少**新信息
f = σ(W_xf·x_t + W_hf·h_{t−1} + b_f)     遗忘门：旧记忆**保留多少**
o = σ(W_xo·x_t + W_ho·h_{t−1} + b_o)     输出门：**读出多少**给外部
g = tanh(W_xg·x_t + W_hg·h_{t−1} + b_g)  候选：准备写进去的**内容**

c_t = f ⊙ c_{t−1} + i ⊙ g                记忆（**加法**通道）
h_t = o ⊙ tanh(c_t)                      对外读数
```

权重在代码里的形状是 `wx (4H, D)` 与 `wh (4H, H)`——四块门**按顺序拼在一个矩阵里**，
顺序写进 `types.GATES` 与 `types.GATE_ROW_BLOCKS`。

### 5.2 门在一次真实前向里的读数

`study.gate_rows()` 用同一个 H=3、D=2 的单元跑 4 步，把每个门的所有取值统计出来：

```text
input     | sigmoid | 均值 +0.549824 | 范围 [+0.477511, +0.635283]
forget    | sigmoid | 均值 +0.719303 | 范围 [+0.642939, +0.795461]
output    | sigmoid | 均值 +0.508696 | 范围 [+0.370548, +0.712091]
candidate | tanh    | 均值 -0.162068 | 范围 [-0.752739, +0.106089]
```

两个可读的事实：

```text
① 三个门的均值都在 0.5 附近 —— 因为 σ(0) = 0.5，而门的偏置尺度是 1/√fan_in
② 遗忘门的均值明显偏高（0.719）—— 因为它的偏置被初始化成 1（σ(1) ≈ 0.731059）
```

### 5.3 遗忘门偏置为什么初始化成 1

`f = σ(b_f)`：

```text
b_f = 0  ⇒  f ≈ 0.5      记忆每一步被砍掉一半（8 步之后只剩 0.4%）
b_f = 1  ⇒  f ≈ 0.731    记忆通道一开始就**基本连通**
```

这是 PyTorch / fastai 圈子里最常见的做法，本包把它写成一个常量
（`types.DEFAULT_FORGET_BIAS = 1.0`）并逐字记进笔记。
它是本课**唯一一处不由 LCG 决定**的数——**刻意写死的，不是漏掉了随机性**
（`test_initialize_lstm_reproducible_and_forget_bias` 逐位断言了它）。

## 第六章：记忆通道 —— 为什么它能原样带回

### 6.1 把三个门钉死，看 c 会不会动

这是理解 LSTM 最直接的一个实验：把权重全部置零、四个偏置写成 `−40 / +40 / +40 / 0`。

```text
σ(+40) = 1.0        （**恰好**，因为 e^{−40} ≈ 4.25e-18 < eps/2 ≈ 1.11e-16）
σ(−40) = 4.25e-18    （不是 0，但 g = tanh(0) = 0 ⇒ i⊙g 恰好是 0.0）
⇒ c_t = 1.0·c_{t−1} + 0.0 = c_{t−1}      （**逐位**相等）
```

读数（第 ② 条性质）：

```text
通过 lstm_gates_control_state | 读数 0.000e+00 == 0 | c_t（三门钉死） vs c₀ = (0.75, −0.4)
```

演示脚本里可以看到具体值：`c₁ = (+0.750000, −0.400000)` 与 `c₀` 逐位相同，
而 `h₁ = (+0.635149, −0.379949)`——那正是 `tanh(c₁)`（因为 `o = 1` 恰好）。

### 6.2 这条通道在反向里意味着什么

```text
c_t = f ⊙ c_{t−1} + i ⊙ g
      ↓
∂c_t/∂c_{t−1} = f_t            （**只有 f**，没有 W_h、没有 tanh'）
```

于是一路带回起点：

```text
∂c_T/∂c_0 = ∏_{t=1..T} f_t
```

`f` 接近 1 时它**几乎不衰减**——这就是"梯度高速公路"。
第 ⑤ 条性质把它写成一条可断言的等式：

```text
通过 lstm_cell_gradient_is_forget_product | 读数 5.551e-17 <= 1.0e-12
    | BPTT 的 ∂L/∂c₀ vs ∏f_t = (0.268599, 0.282584)
```

为了让这条等式**精确**成立，那一条性质刻意把 `W_h` 置零：
此时隐状态那条链不再回传（`W_hᵀ·dz = 0`），记忆通道上只剩 `dC_{t−1} = dC_t ⊙ f_t`，
于是"BPTT 的累乘"与"把前向的门读出来直接相乘"必须给出同一个向量。
**自证是不成立的**：两条路径来自两个不同的地方（BPTT 的循环 / 前向缓存里的门值）。

## 第七章：BPTT —— 累加那一条纪律

### 7.1 反向的六行

```text
对 t = T … 1（倒序）：
    d_h  = grad_states[t] + 从 t+1 带上来的那部分
    dz_t = d_h ⊙ act'(z_t)                  ← 激活的导数来自 day090
    dW_x += dz_t ⊗ x_t                      ← **累加**
    dW_h += dz_t ⊗ h_{t−1}
    db   += dz_t
    dx_t  = W_xᵀ·dz_t；h_{t−1} ← W_hᵀ·dz_t
```

这六行与 day090 的那六行是同一件事：**链式法则 + 累加**。
区别只有一个：这一条链是**在时间上**展开的，因此"累加"发生在 T 个时刻上。

### 7.2 写成 `=` 会怎样

```text
三步都回传：  ‖dW‖ = 3.014188
只留最后一步：‖dW‖ = 1.503321      ← 只剩 49.9%
```

**它不会报错。** 梯度整体偏小，看起来像"学习率设小了"。
`test_rnn_bptt_accumulates_across_time` 把这件事写成一条断言：
整段的 `‖dW‖` 必须**严格大于**"只算最后一步"的 `‖dW‖`。

### 7.3 激活的导数不重写

```python
dz = backprop_gradients.elementwise_backward(activation, (cache.pre_activation,), (combined,))[0]
```

`tanh` / `relu` / `sigmoid` 的导数**只有一份**，写在 day090 的
`backprop.gradients`。LSTM 的四个门也一样——`sigmoid` 与 `tanh` 都在那张表里。
这也是为什么缓存里必须留下**激活之前**的 `z_t`（与 day093 的 `pre_activation` 同源）。

## 第八章：LSTM 的反向 —— 多带一条 dc

### 8.1 两条通道一起往回走

```text
h_t = o ⊙ tanh(c_t)
    ⇒ d_o  = dh ⊙ tanh(c_t)
    ⇒ dc  += dh ⊙ o ⊙ (1 − tanh(c_t)²)       ← 最容易漏的一条链
c_t = f ⊙ c_{t−1} + i ⊙ g
    ⇒ d_f  = dc ⊙ c_{t−1}
    ⇒ dc_{t−1} = dc ⊙ f                        ← 记忆通道：只乘 f
    ⇒ d_i  = dc ⊙ g；d_g = dc ⊙ i
四个门各自过激活的导数，拼回 4H ⇒ 线性部分与 RNN **完全一样**
```

最后那一句是本课最重要的结构观察：**LSTM 只多了"算门"与"多带一条 dc"，
线性部分（`dW_x += dz ⊗ x`、`dW_h += dz ⊗ h`、`db += dz`、`dx = W_xᵀ·dz`）
与 RNN 逐字相同。** 因此本课的两段反向共用同一张纪律表。

### 8.2 那一条最容易漏的链

`dc += dh ⊙ o ⊙ (1 − tanh(c_t)²)` 说的是"`h_t` 通过 `tanh(c_t)` **间接**依赖 `c_t`"。
漏掉它的后果很具体：

```text
漏掉 ⇒ 反向只走 c 的直接路径 ⇒ 梯度仍然是有限、仍然在下降
       ⇒ 只有第 ⑥ 条（数值差分）会发现少了一项
```

### 8.3 对账读数

```text
rnn   | 解析范数 2.654833 | 与数值差 2.222e-10
lstm  | 解析范数 0.984630 | 与数值差 2.222e-10
```

第 ⑥ 条性质同时钉住两个单元：

```text
通过 bptt_matches_numerical | 读数 2.222e-10 <= 1.0e-09
    | rnn_bptt / lstm_bptt（解析） vs math_foundations.calculus.gradient（数值）
```

`2.222e-10` 落在中心差分的分辨率之内，与 day093 的 `1.579e-10` 同一量级。

## 第九章：一个序列分类器的完整链

### 9.1 结构写死

```text
x₁…x_T → 循环单元逐步吃进去 → 取**最后一步**的 h_T → dense(H→C) → logits
                                                              ↓
                                              softmax + 交叉熵（day089）
```

三个接缝都在 `network.py` 里被钉住：

```text
① 整段与单步     循环体被 for 循环调用 T 次；每一步的缓存（z_t 或四个门）都留下
② 循环与全连接    只取 h_T 送进 dense ——分类头读的是"看完整条序列之后的状态"
③ 反向           dense 的 dh_T ⇒ 从末步往前走的 BPTT（grad 只挂在最后一步）
```

### 9.2 参数压平：day090 的契约第二次被真正用上

```text
flatten_params 的顺序（写死）：
    cell.wx → cell.wh → cell.bias → head_weight → head_bias
unflatten_params 用**参数本体当形状表**（template）
```

与 day093 的卷积核一样：`TrainingOptimizer` 的更新公式是**逐分量**的，
与"参数是不是循环权重"无关。于是"优化器第一次遇到循环网络"这件事，
只差一次压平与还原：

```python
flat_params = flatten_params(params)
flat_grads = flatten_gradients(grads)
updated = optimizer.step(flat_params, flat_grads)
params = unflatten_params(updated, template=params)
```

`unflatten_params` 在长度对不上时抛 `ShapeError`——而不是"按顺序切"。
本课的现场读数：`lstm(H=3, D=2) → dense(3→2)` 参数量 80（循环 72 + 头 8），
压平后长度 80，与梯度压平后的长度逐位对齐。

## 第十章：训练一次 —— 合成 ±1 序列

### 10.1 为什么用这个任务

```text
数据集    长度 T=5 的 ±1 序列，**枚举全部 2⁵ = 32 条**（没有随机性）
标签      1 ⇔ 序列的和为正（长度取奇数 ⇒ 和永远不为 0，边界不会落在未定义处）
两类均衡  和为正 16 条 / 和为负 16 条
```

两个理由：

```text
① 可复现    序列是枚举出来的 ⇒ 每一次训练曲线都逐位相同
② 可判定    标签是"和的正负"，而循环单元的隐状态天然可以做一个累加器
            ⇒ "学会了"就是学会了，不依赖运气
```

每一步都是**全批量**：32 条样本既便宜又稳定——它把"单样本 SGD 的抖动"
这个与循环结构无关的变量先消掉。

### 10.2 读数

```text
rnn  | 250 步 | 损失 7.212e-01 → 4.180e-04（↓99.9%）| 准确率 100.0% | adam
rnn  step   1 | loss 0.721151
rnn  step  63 | loss 0.002596
rnn  step 126 | loss 0.001041
rnn  step 250 | loss 0.000418

lstm | 250 步 | 损失 7.572e-01 → 2.412e-04（↓100.0%）| 准确率 100.0% | adam
lstm step   1 | loss 0.757234
lstm step  63 | loss 0.001062
lstm step 126 | loss 0.000533
lstm step 250 | loss 0.000241
```

起点损失 `0.721` / `0.757` 都略高于 `ln 2 ≈ 0.693`（初始参数把两类分得比随机还差一点），
60 步出头就掉到 `1e-3` 量级。**梯度来自本包的 BPTT，优化器来自 day092**——
两项独立的实现第一次在"序列"这个形状上合上了。

> **必须写下来的边界**：这是一个 **H=4 的单元 + 一个线性分类头**的最小网络，
> 数据只有 32 条、序列只有 5 步。它证明了整条链"跑通、可对账、可复现"，
> 不证明"任意任务都能训到 100%"——真正的长序列依赖需要截断 BPTT
> 与门控结构（day095 / day096 再谈）。

### 10.3 护栏：梯度爆炸当场拦下

`train.check_gradient_norm` 在**进入优化器之前**看一次范数：

```text
非有限（nan / inf）  ⇒ 抛 GradientError
范数 > MAX_GRADIENT_NORM  ⇒ 抛 GradientError
```

它有真实的存在理由：BPTT 把同一个循环权重乘了 T 次，范数随 T **指数增长**，
一次爆炸就足以把参数甩出可训练的区域，而 `nan` 会一路污染到很久以后
（那时再查已经失去现场）。

本课两次训练的实测最大梯度范数：

```text
rnn  的 MAX_GRADIENT_NORM ≤ 50 ⇒ 实测最大 1.2690
lstm 的 MAX_GRADIENT_NORM ≤ 50 ⇒ 实测最大 0.3288
```

离上界还有很远——这正是"这一课的任务不需要裁剪"的读数。护栏本身由
`test_check_gradient_norm_guard` 用一个很小的上界单独验过。

## 第十一章：七条性质与七张表

### 11.1 七条性质

```text
通过 rnn_cell_matches_manual_recurrence           | 读数 0.000e+00 == 0       | layers.rnn_cell_forward vs 手写递推
通过 lstm_gates_control_state                     | 读数 0.000e+00 == 0       | c_t（三门钉死） vs c₀ = (0.75, −0.4)
通过 weight_sharing_across_time                   | 读数 0.000e+00 == 0       | 参数量 12（与 T 无关）+ 逐步复算 vs 同一组权重
通过 sequence_alignment_matches_input             | 读数 0.000e+00 == 0       | rnn 3 / lstm 3 个状态 vs T = 3
通过 lstm_cell_gradient_is_forget_product         | 读数 5.551e-17 <= 1.0e-12 | BPTT 的 ∂L/∂c₀ vs ∏f_t
通过 bptt_matches_numerical                       | 读数 2.222e-10 <= 1.0e-09 | 解析 BPTT vs 数值差分
通过 lstm_outlasts_rnn_on_long_range              | 读数 9.971e-01 >= 5.0e-01 | LSTM carry 1.000000 vs tanh-RNN carry 2.864e-03
```

判据**三类**：相等（逐位 / 整数）、不超过上界、不超过下界。
第 ⑦ 条是本课唯一的下界判据，它的必要性很具体：

```text
把 LSTM 写成"记忆通道不独立"的假 LSTM：
  ① 仍然通过（一步的结构没变）
  ② 仍然通过（门还是一样的门）
  ③④ 仍然通过（步数与参数量都没变）
  ⑤ 仍然通过（两条路径都在这个假 LSTM 上算，乘法照样一致）
  ⑥ 仍然通过（梯度照样对）
  只有 ⑦ 会红：因为"LSTM 必须比 RNN 强"被写成了一条不能少的断言。
```

第 ⑦ 条的两侧读数：

```text
LSTM 侧   权重全 0、f = 1、i = 0、c₀ = 1 ⇒ ‖∂L/∂c₀‖ = 1.000000
RNN 侧    W_h = 0.5、h₀ = 1、T = 8      ⇒ ‖∂h_T/∂h_0‖ = 2.864e-03 ≤ 0.5⁸ = 3.906e-03
```

RNN 那一侧的上界是**可推导的**：每个因子的范数 ≤ `|tanh'|·‖W_h‖ ≤ 0.5`，
T 个因子连乘就是 `0.5⁸`。

② 门表       LSTM 四个门在一次前向里的实际读数（均值 / 最小 / 最大）

## 第十二章：失败族与那条纪律

### 12.1 六个族，按"该谁去修"分

```text
ShapeError       形状不符      输入维 / 隐层宽 / 权重行列对不上        → 改调用
ParameterError   参数越界      hidden_size / 序列长度 / 步数非法        → 改调用
NumericError     数值不可用    nan / inf 混进状态或梯度               → 改数据或改实现
TimeStepError    时间步不成立  返回 / 缓存的状态数与输入步数不是同一个 T → 改调用
BackwardError    反向不成立    BPTT 的缓存与回传梯度不是同一次前向      → 改调用
GradientError    梯度爆炸      一次 BPTT 的梯度范数越界                 → 改超参
```

`TimeStepError` 独立成族的理由是**时机**：形状全部合法，
只是"数量差一个"（多半是把初值 `h₀` 算进了输出）。把它与 `ShapeError` 混成一族，
会让"状态与输入整体错位一格"这种症状被误诊成"张量喂错了"。

### 12.2 GradientError 回来了 —— 理由与 day090 那一次**不同**

```text
day082~089   没有手写反向                ⇒ 连续缺席八天
day090       有手写反向 + 自动微分        ⇒ **回来了**（对账结论：这次训练不可信）
day092       消费梯度、不计算梯度          ⇒ 再次缺席（梯度被交给了上一步）
day093       算了梯度，但对账是离线校验    ⇒ 第三次缺席
day094       算了梯度，而且梯度真的会爆    ⇒ **第二次回来**（运行期守卫：这一步就不该继续）
```

三个"回来 / 缺席"的理由互不相同，这正是这一族值得被认真对待的地方：
**同一个名字，在不同的一天指的是不同的控制流事件。**

```text
day090 抛 GradientError   因为"解析梯度与数值差分对不上"（**离线对账**的结论）
day094 抛 GradientError   因为"梯度真的爆了"（**运行期**的守卫：train.check_gradient_norm）
```

这条区分写进了 `errors.RETURNED_FAMILY_REASON`，并被 `test_sequence_models.py`
逐字断言（`RETURNED_FAMILY == "GradientError"` 且 `ABSENT_FAMILY is None`）。

## 结语：三条工程线索

1. **串行性还没解决**：本课的 `rnn_forward` 是逐时刻的 for 循环——它**必须**串行。
   把 T 步并行化有两种路线：一是用 `nn.RNN` 那类把循环体做成算子（仍然串行），
   二是换成注意力（day075）——一次算完全序列的两两打分，把 T 步压成一次矩阵乘。
2. **状态还可以更宽**：本课的隐状态只有 H 个数。把它堆成多层、
   或者引入双向（前向 + 后向各一个状态）都是"接法"问题：
   `flatten_params` 与 BPTT 的累加纪律都能原样复用。
3. **序列分类器的位置**：本包的输出是一个 logits。把它接到本项目里
   "用户输入是一段日志 / 一串工单"的场景上，就是"先判类型、再走 Agent"的完整栈——
   与 day093 的卷积放在 `ImageAnalysisTool` 前面是同一个思路。

明天（day095）我们将进入 **训练技巧与正则化**：给这条链装上批量归一化、
Dropout、学习率衰减与早停，并把训练日志变成**可以看一眼就懂**的图。
day094 留下的两个旋钮（学习率、展开长度）会在那一天第一次被系统地扫一遍。
