## 一、选择题（每题只有一个最佳答案）

**第 1 题（M1 · ReAct）** ReAct 循环必须设置 `max_steps` 上限，其根本原因是：

A. 节省 API 调用费用  
B. LLM 是概率模型，可能永远输出 Action 而不收尾，上限把"可能无限"变成"必然终止"  
C. 上下文窗口装不下太多步骤的历史  
D. 工具执行有超时限制

**第 2 题（M1 · 工具安全）** `CalculatorTool` 用 AST 白名单解析表达式而非 `eval`，主要是为了防御：

A. 表达式语法错误导致的异常  
B. 除零错误  
C. 形如 `__import__("os").system("rm -rf /")` 的任意代码执行  
D. 浮点数精度丢失

**第 3 题（M1 · 记忆）** 关于短期记忆与长期记忆的分工，下列说法正确的是：

A. 短期记忆存向量，长期记忆存消息列表  
B. 短期记忆是每次请求重发的历史消息列表加截断策略；长期记忆是 Embedding 入库、按语义相似度召回  
C. 两者都由 LLM 自己在权重中维护，代码无需干预  
D. 长期记忆精确记录所有历史，召回结果必然相关

**第 4 题（M2 · 协议）** MCP 协议的传输层消息格式是：

A. 自定义二进制协议  
B. gRPC/Protobuf  
C. JSON-RPC 2.0  
D. GraphQL

**第 5 题（M2 · 三原语）** 需求："把知识库中的一篇 Markdown 文档提供给客户端读取"。按 MCP 三原语的语义，最合适的实现是：

A. Tool——因为它有参数（文档 ID）  
B. Resource——URI 寻址、只读、无副作用  
C. Prompt——因为文档内容最终要进提示词  
D. 三者等价，随便选

## 四、编程题（跨阶段综合）

**第 14 题（M1 综合：规划 → 执行 → 记忆）**  
基于 day010 的快照（[../../day010/源码/smart-research-agent/](../../day010/源码/smart-research-agent/)，含 `Planner`、`ReactAgent`、`ToolRegistry`、`CalculatorTool`、`MockLLM`），编写一个 `PlanExecuteMemoryPipeline` 类并配测试，要求：

1. `run(goal: str) -> dict`：先用 `Planner` 拆出计划，再对每个子任务新建独立 `ReactAgent`（注入同一个 `ToolRegistry`，内含 `CalculatorTool`）执行，收集每个子任务的结果；
2. 每个子任务完成后，把 `f"{step} => {result}"` 追加到一个简单的"运行日志"列表（模拟写入长期记忆的动作，本练习用列表代替向量库即可）；
3. 某个子任务的 ReAct 循环跑满 `max_steps` 仍未得出 Final Answer 时（此时 `ReactAgent.run` 返回提示未完成的文本），**不中断整个计划**，在结果字典里把该子任务标记为 `"status": "failed"`，继续执行后续子任务；
4. 返回 `{"goal": ..., "results": [{"step": ..., "status": "ok"|"failed", "output": ...}, ...], "memory_log": [...]}`；
5. 测试必须用 `MockLLM` 离线驱动，至少覆盖：(a) 全部子任务成功的 happy path；(b) 一个子任务失败但计划不中断；(c) Planner 输出非法 JSON 时抛出 `PlanParseError`。

提示：MockLLM 是按顺序弹出预设回复的，规划调用消耗第 1 条回复，之后每个子任务的 ReAct 循环依次消耗后续回复；给失败子任务喂一串永远不含 `Final Answer` 的回复即可制造"跑满 max_steps"。每个子任务用独立的 MockLLM 更容易控制。

**第 15 题（M2 综合：把 M1 的工具暴露为 MCP Tool 并离线测试）**  
编写一个 FastMCP Server 与配套测试，要求：

1. 用 `FastMCP("calc-server")` 创建 Server，注册一个 MCP Tool `safe_calculate`，其内部**复用** M1 的计算逻辑——直接调用 day004 快照中 `CalculatorTool` 同款思路实现的 `_safe_eval`（AST 白名单求值，本练习可把该函数复制进你的解答文件），参数为 `expression: str`，返回字符串结果；表达式非法时**不抛异常**，而是返回 `"计算失败: <原因>"` 文本（模拟 Client 包装层的错误翻译思想）；
2. 再注册一个 Resource `guide://usage`，返回计算器的使用说明文本；
3. 测试用 `create_connected_server_and_client_session` 建立内存内客户端，断言：
   - (a) `list_tools()` 能看到 `safe_calculate`，`list_resources()` 能看到 `guide://usage`；
   - (b) 调用 `safe_calculate` 传 `"2 + 3 * 4"` 得到 `"14"`；
   - (c) 调用传 `"__import__('os')"` 得到以 `"计算失败"` 开头的文本而非异常；
   - (d) 读取 `guide://usage` 资源能拿到说明文本。
4. 全程离线、异步测试用 `pytest-asyncio`（`@pytest.mark.asyncio`）。

提示：mcp 1.29 的 `create_connected_server_and_client_session` 可以直接接收 `FastMCP` 实例并产出一个已连接的 `ClientSession`：`async with create_connected_server_and_client_session(app) as session: await session.initialize()`，随后 `await session.call_tool("safe_calculate", {"expression": "..."})`；读取资源用 `await session.read_resource(AnyUrl("guide://usage"))`（`from pydantic import AnyUrl`）。
