# 优化器：往哪走、走多远（day092 / M8-D3）

> 一本可随手翻的手册，与 `smart_research_agent/optimizers/` 一一对应。
> 每一节的每个结论都能在包内找到对应函数；每个读数都能现场重跑。

## 1. 这一课要回答什么

day074 的 `math_foundations.optim` 已经写了三个更新公式（sgd / momentum / adam）、
四种学习率调度与两个裁剪原语；day090 的 `backprop` 交出了可信的梯度。
本课把两者接成**一次真正的训练期更新**，并补上 day074 刻意留白的三个变体。

```text
一步 = 学习率 × 更新规则
方向由 day090 给（梯度）；本课只决定这个标量作用在什么上、按什么顺序作用
```

## 2. 六个更新规则

| 规则 | 公式 | 状态 | 归属 |
|------|------|------|------|
| sgd | θ ← θ − lr·g | 无 | 复用 day074 |
| momentum | v ← β·v + g；θ ← θ − lr·v | velocity | 复用 day074 |
| nesterov | v ← β·v + g；θ ← θ − lr·(g + β·v) | velocity | **本课新增** |
| rmsprop | s ← ρ·s + (1−ρ)·g²；θ ← θ − lr·g/(√s + ε) | square_avg | **本课新增** |
| adam | m,v 各带偏差修正；θ ← θ − lr·m̂/(√v̂+ε) | first/second_moment | 复用 day074 |
| adamw | Adam 更新后再 θ ← θ·(1 − lr·λ) | first/second_moment | **本课新增** |

对应实现：`optimizers/rules.py`（新增规则的纯函数）、
`optimizers/optimizer.py`（把规则接进训练回路）。

### 2.1 momentum 与 nesterov 差在哪一行

```text
速度更新          v ← β·v + g        两者**逐字相同**
方向              动量: v            方向 = 当前速度
                  Nesterov: g + β·v  方向 = 当前梯度 + 一点未来的速度
```

因此 Nesterov **不是**"换个动量系数"，而是"取另一个点的梯度"。
在接近过冲时它会提前刹车。

### 2.2 rmsprop 是 adam 的一半

它只保留二阶动量。好处是状态最省（每参数一个数）；代价是没有一阶动量，
因此梯度方向来回变时会抖。

### 2.3 adamw 与 adam + l2 不是一回事

```text
耦合 L2        g ← g + λθ        λθ 会一起被 Adam 的分母 √v̂ 除一下
解耦（AdamW）  θ ← θ·(1 − lr·λ)   λθ 不进梯度，与分母无关
```

后果：耦合版里"梯度大的参数衰减得更弱"，不是我们想要的"人人等量衰减"。
`optimizers/verify.py` 的第 ③ 条性质用一个**下界判据**钉住了这件事。

## 3. Adam 的偏差修正

两个滑动平均都从 0 出发：第一步 `m₁ = (1−β₁)g₁`、`v₁ = (1−β₂)g₁²`。
不做修正时第一步更新量约 `lr·3.16`（比设定值大 3 倍多），
而它看起来只是"前期有点抖"。除以 `1−β₁ᵗ`、`1−β₂ᵗ` 之后，
第一步恰好是 `lr·sign(g)`。

## 4. 三种衰减

| 模式 | 位置 | 公式 |
|------|------|------|
| none | 无 | 无附加项 |
| l2 | 更新之前，加进梯度 | g ← g + λθ |
| decoupled | 更新之后，缩参数 | θ ← θ·(1 − lr·λ) |

实现：`rules.l2_gradient` 与 `rules.apply_decoupled_decay`。

## 5. 更新顺序（写死，不给调用方拼）

```text
① 取学习率   步号自增；有调度就取 lr(t)
② 裁剪       可选：整体范数裁剪，记录缩放系数与裁剪前范数
③ 更新规则   sgd/momentum/adam 交给 day074；nesterov/rmsprop 用本包纯函数
④ 衰减       耦合在③之前，解耦在③之后
```

顺序错了不会报错，只会算错：先加 λθ 再裁剪，衰减会被裁剪系数一起缩掉；
解耦写成"当梯度用"，它就会被自适应分母除。

## 6. 学习率调度：为什么先升后降

```text
前期 lr 太大   随机初始化时方向信息量低，一大步就推到坏区域  → 热身
后期 lr 太大   已接近谷底，大步来回横跳                      → 退火
```

两者方向相反，因此"同时满足"的唯一形式是先升后降：`warmup_cosine`。
本课不重写调度——`TrainingOptimizer.set_schedule` 直接调用 day074 的 `make_schedule`，
`verify` 的第 ⑦ 条性质逐点对账。

**一个真实撞到的坑**：余弦退火的最后一步合法地取到 `min_lr`，而 `min_lr = 0` 时
学习率为 0。若用"必须为正"去卡它，常见的 `warmup_cosine` 会在**最后一步**报错，
而前面每一步都对。因此训练回路对调度用的是**非负**校验（`rules.checked_non_negative`），
构造函数仍要求正学习率。

## 7. 梯度裁剪：整体范数而不是逐分量

```text
整体范数   方向不变，只改长度（缩放系数 max_norm/‖g‖）
逐分量     会把方向改掉：(100, 1) → (1, 1)，从"几乎水平"变成 45°
```

本课复用 day074 的 `clip_by_global_norm`：**裁剪的数学只有一份**，
`verify` 的第 ⑥ 条性质断言"接线没有改动它"。

## 8. 七条性质（三类判据）

```text
相等（逐位）  ① 共享规则与 day074 逐位一致
              ⑥ 裁剪与 day074 逐位一致
              ⑦ 调度与 day074 逐点一致
上界          ④ RMSProp 把相差 1e4 的梯度归一到相同的步长
              ⑤ 裁剪只改长度不改方向
下界          ② Nesterov 与普通动量必须不同
              ③ AdamW 与 Adam+L2 必须不同
```

**为什么有"下界"这一类**：把 Nesterov 写成普通动量、把解耦写成耦合，
两种写法都能算出"看起来正常"的参数——只写上界判据时报告会全绿。
下界判据专门用来钉住"它们确实不同"。

## 9. 六类场景的选型

| 场景 | 推荐 | 起点 lr | 衰减 | 为什么 |
|------|------|---------|------|--------|
| sft-lora | adamw | 1e-4 | 解耦 0.01 | 解耦衰减不随梯度尺度变化 |
| sft-full | adamw | 2e-5 | 解耦 0.10 | 全参更敏感、更易过拟合 |
| dpo | adamw | 5e-7 | 解耦 0.00 | 偏好优化对 lr 极敏感 |
| scratch-mlp | adam | 1e-2 | 无 | 小网络用 Adam 起步快 |
| ill-conditioned | nesterov | 1e-2 | 无 | 病态峡谷靠动量与 lookahead |
| cpu-tiny | rmsprop | 1e-2 | 无 | 只归一化尺度、最省内存 |

> **这些数字是本仓库的"起点配置"，不是"最优配置"。** 它们来自"公式能读出的默认值 +
> 工程惯例"，真正的调参必须在自己的数据上跑。实现见 `optimizers/advisor.py`。

## 10. 三条边界

- 只做一阶方法：不涉及 Newton / L-BFGS。
- 不做参数分组：所有参数共享一个学习率与一个衰减系数。
- 不做收敛证明：只给确定性的对比读数，不给任何优化器的收敛性定理。
