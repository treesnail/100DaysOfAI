## 第二章：四个主题的复盘（本质 → 为什么 → 误区）

每个主题按同一套心智模型复盘。**试着先看小标题自己复述，再展开对照**——
先复述后阅读，是提取练习的正确顺序。

### 2.1 线性代数 + 概率论（day073）

- **本质**：`math_foundations` 把"注意力"拆成四个学过的算子：
  `linalg`（点积、矩阵乘、转置、归一化、幂迭代）、`probability`（softmax、熵、
  交叉熵、KL、期望方差、LCG 采样）、`attention`（把前两者拼成
  `softmax(QKᵀ/√d_k)·V`），再加一层 `bridge`（八项公式 ↔ 实现的对照）。
- **为什么**：这一天最重要的产出不是公式，而是一条**纪律**：
  **掩码必须是一张可以被打印出来的表**（`True/False` 矩阵），
  而不是"把打分写成 `-inf` 再指望 `exp` 把它变成 0"。理由是 `-inf` 会进入
  概率层：`0 · (-inf) = nan`，而一个 `nan` 会顺着"平均熵"污染整张表。
- **误区**：把数学课当成"复习公式"。这一天的每个算子都带着一条**工程判据**：
  除零怎么处理、零向量为什么在四种读法里有四种正确行为、求和为什么用 `math.fsum`
  （而不是 `sum`：后者在某些顺序下会累积舍入）。
- 代码：[../../day073/源码/smart-research-agent/smart_research_agent/math_foundations/attention.py](../../day073/源码/smart-research-agent/smart_research_agent/math_foundations/attention.py)

**这一课埋下、今天兑现的两句话**（就在 `attention.py` 的 `multi_head_attention` 里）：

```text
① "每个头的 d_k = d / heads，因此缩放系数是 1/√(d/heads) —— **不是** 1/√d"
② "每个头的注意力分布都不一样……全相等说明这个多头结构退化成了一头"
```

### 2.2 微积分 + 优化（day074）

- **本质**：`calculus`（三种差分的误差阶数）、`autograd`（计算图 + 拓扑序 + 反向累积）、
  `optim`（SGD / 动量 / Adam + 四种调度 + 两种裁剪 + `TrainingTrace`）、
  `gradcheck`（六项解析式 vs 数值的对照）。
- **为什么**：这一天确立了后面两课**调试方法的骨架**：
  **一次只留一个不确定性**。用碗形函数验证优化器（"梯度对不对"与"优化器对不对"解耦）、
  用 MSE 验证注意力（"损失对不对"与"注意力对不对"解耦）。
  它还量出了两件很具体的事：
  ```text
  误差阶数：从"记住 O(h²)"到**量出 2.00**
  分辨率公式：容差取多少不再拍脑袋（低于分辨率的校验必然"失败"）
  ```
- **误区**：以为"优化器越复杂越好"。这一课量出 Adam 的一个副作用：
  它按 `√v̂` 归一化，会放大梯度分量的**相对**误差——
  因此 day075/076 做梯度对账时**优先用 SGD**（实测差 1000 倍）。
- 代码：[../../day074/源码/smart-research-agent/smart_research_agent/math_foundations/optim.py](../../day074/源码/smart-research-agent/smart_research_agent/math_foundations/optim.py)、
  [calculus.py](../../day074/源码/smart-research-agent/smart_research_agent/math_foundations/calculus.py)

### 2.3 可训练的自注意力（day075）

- **本质**：把 `Attention(Q, K, V)` 里的 Q/K/V 换成 `x·Wᵀ`，于是这一层有了参数，
  也有了**一件全新的工作：反向传播**。七步前向、七步反向，每一步都是
  "上游梯度 × 局部导数"。
- **为什么**：这一天的全部风险集中在**三处"漏掉不会报错"的地方**：
  ```text
  ① softmax 的雅可比    dScores = dWeights 不报错，方向"大致"对、幅度不对
  ② 缩放系数            反向漏乘 1/√d_k → 整体差 √d_k 倍（d_k = 6 时 2.45 倍）
  ③ 掩码位置的梯度      前向看起来完全正确，只有 key 的梯度里混进了"未来"
  ```
  第 ③ 条最隐蔽：它不会让权重出现非零（前向掩码仍然生效），
  只会让梯度多一条不该有的路径——而损失曲线看起来一切正常。
- **误区**：以为"损失降到 0"就等于"学到了机制"。
  这一课用 induction 任务做了**冻结对照**：
  ```text
  四块全训   损失 → 0、命中率 100%，而峰值权重只有 0.44
  只训 q/k   注意力**确实变尖了**（峰值 0.59），而损失几乎不动
  ```
  两个方向都反直觉，结论是：**没有任何一个读数能单独说明"学到了什么"。**
- 代码：[../../day075/源码/smart-research-agent/smart_research_agent/transformer_core/layers.py](../../day075/源码/smart-research-agent/smart_research_agent/transformer_core/layers.py)、
  [verify.py](../../day075/源码/smart-research-agent/smart_research_agent/transformer_core/verify.py)

### 2.4 多头注意力（day076）

- **本质**：把"一行一份混合系数"变成"一行 `heads` 份，各自只作用于一段子空间"。
  前向七步变九步（多了 `split` 与 `merge`，而它们只是一次切片与一次拼接），
  反向多了一处新的"漏掉不会报错"：
  ```text
  ④ 分头之后必须**相加**    四个投影被所有头共用：
                            只回第一头梯度不报错，只会让其余头"学得慢"
  ```
- **为什么**：因为"一个分布"与"`heads` 个分布"之间的差别是**结构性**的，
  而且可以被算出来。把一行输出写成
  ```text
  output_i = Σ_j w_j · contrib_j          （单头：一组系数作用于所有 value 维）
  ```
  于是两种结构的可达集合分别是：
  ```text
  单头   conv{ contrib_j }                  一个凸包
  多头   Σ_h conv{ contrib^h_j }             heads 个凸包的闵可夫斯基和
                                             = 网格点集的凸包
  ```
  在一个能手工算完的样本上，两者的差别是"**一条线段**"与"**一个正方形**"。
- **误区**（三条，都值得记住）：
  ```text
  ① 以为多头 = 更多参数      参数量一字不差（四个投影的形状里根本没有 heads）
  ② 以为可达集合 = 训练能找到 前者是**存在性**（几何问题），后者是**优化问题**
  ③ 以为头间差异大就一定有用 它是一个**前向读数**；"各头有没有学到不同机制"
                             要看梯度与训练曲线
  ```
- 代码：[../../day076/源码/smart-research-agent/smart_research_agent/multi_head/reachability.py](../../day076/源码/smart-research-agent/smart_research_agent/multi_head/reachability.py)、
  [layers.py](../../day076/源码/smart-research-agent/smart_research_agent/multi_head/layers.py)

## 第三章：全链路走读 —— 一次前向穿过两个包

这一节是今天最重要的一段。带着一个问题读每一步：
**"这一层的输出，依赖前一层的哪一条结论？"**

```text
输入 x                                   (n, d_in) 的一串数
  │
  ├─ day076  layers._check_inputs        拒绝全零行（数据问题 ≠ 模型问题）
  ├─ day075  layers.resolve_mask         掩码是一张显式的表（"没有掩码"也是那张表）
  │
  ├─ day075/076  project(x, W_qᵀ)        W 的形状 (d_out, d_in)、投影 = x·Wᵀ（**唯一口径**）
  │                                       └─ 依赖 day073 的 matmul / transpose
  ├─ day076  split_columns(Q, 划分)      激活按**列**切（权重按**行**切）
  │
  ├─ 每头 raw_h = Q_h·K_hᵀ               ← 依赖 day073 的点积读法
  ├─ 每头 scores_h = raw_h / √d_h        ← 依赖 day073 的"为什么除 √d_k"（day076 换成 √d_h）
  ├─ 每头 weights_h = masked_softmax_rows ← 依赖 day073 的显式掩码（被掩码位置**恰好 0.0**）
  ├─ 每头 ctx_h = weights_h·V_h          ← 依赖 day073 的"加权平均 = 凸组合"
  │
  ├─ day076  merge_columns(ctx)          拼回 (n, d_v)
  └─ project(merged, W_oᵀ)               (n, d_out)

反向（同样九步，顺序恰好相反）
  │
  ├─ day075/076  softmax_backward_row    dScores_i = s_i(g_i − Σ_j g_j s_j)
  │                                       └─ 依赖 day073 已验证过的 softmax 雅可比
  ├─ 缩放乘回、掩码位置再置一次 0          ← day075 的"三处漏掉不会报错"
  ├─ 分头梯度按行拼回                     ← day076 的"每一行只由一头贡献"
  └─ dx = heads × 3 条链之和              ← 它是**堆叠**的前提（day079/080）

参数更新
  │
  ├─ day074  flatten_matrices            参数压平成一行数（与形状无关）
  ├─ day074  AdamOptimizer.step          θ ← θ − lr·m̂/(√v̂+ε)
  └─ day075/076  unflatten               形状表来自同一处（顺序错了会串位）
```

### 3.1 走读的四个提问点

```text
① 为什么"掩码是显式的表"这件事要一路传下来？
   因为它让"被掩码位置的梯度恰好是 0"变成一条**推论**（s_j = 0 →
   s_j(g_j − 平均) = 0），而不是需要额外处理的特例
② 为什么"投影 = x·Wᵀ"这条口径只写一次？
   因为反向的两条式子（dW = gradᵀ·x、dx = grad·W）完全由它决定；
   口径写两遍 = 两条可以分家的真相
③ 为什么"权重按行切、激活按列切"必须分开记？
   因为 d_k 在两张表的不同轴上——切错**不会报错**，只会让每一头看到混合维度
④ 为什么压平与形状表要来自同一处？
   因为"压平参数"与"压平梯度"必须逐位对齐；错位只会让某一层的权重
   按另一层的梯度更新（症状是"训练变慢"）
```

### 3.2 两个包之间的"接线"共八处

| 接线 | 上游（day073/074/075） | 下游（day075/076） |
|------|------------------------|--------------------|
| 显式掩码 | `masked_softmax_rows` / `causal_mask` | 两天的 `resolve_mask` 都复用它 |
| softmax 反向 | day073 验证过的雅可比 | 两天的 `softmax_backward_row`（各自一份实现） |
| 缩放系数 | `scaling_factor` | day075 `softmax_shape_scale` / day076 `head_scale` |
| 数值差分 | `calculus.gradient` / `DEFAULT_STEP` | 两天的五项校验 |
| 参数压平 | `flatten_matrices` / `unflatten_matrices` | 两天的训练回路 |
| 优化器 | `SGD/Momentum/Adam` + 四种调度 | 两天的 `train_*` |
| 样本 | `probability.uniforms`（LCG） | 两天的 induction 任务生成 |
| 参数形状 | `AttentionParams`（day075） | day076 直接用，**一个字节都没改** |

## 第四章：四条接缝与两张对照表

### 4.1 四对"同一件事的两种写法"

```text
① day073 scaled_dot_product_attention(Q,K,V)    ↔  day075 self_attention(x; W)
   给定 Q/K/V 的纯函数                              参数投影出来的可训练版本

② day073 multi_head_attention(Q,K,V; heads)     ↔  day076 multi_head_attention(x; W; heads)
   同样是纯函数                                     同样是可训练版本
   （它甚至已经写了"缩放系数是 1/√(d/heads)"）

③ day074 calculus.gradient（数值）              ↔  day075/076 五项梯度校验（解析 vs 数值）
   慢但不依赖推导                                    用同一个数值侧当独立参照

④ day073 的 AttentionReport                     ↔  day075 的 AttentionForward
   前向的账（权重、熵、峰值）                        前向的账 + 反向要用的**全部中间量**
```

**四对都在说同一件事**：一个概念在"纯函数版"里第一次出现，
在"可训练版"里被重写一遍——而重写时必须**留一条断言把两处钉在一起**：

```text
day076 的 tests/test_multihead_gradients.py::test_matches_day075_helper_bit_for_bit
        head_scale(head_dim) == softmax_shape_scale(head_dim) == scaling_factor(head_dim)
day075 的 tests/test_attention_layer.py::test_scale_helper_matches_day073
day076 的 tests/test_multihead_layer.py::test_heads_one_reproduces_day075_bit_for_bit
day076 的 tests/test_multihead_train.py::test_single_head_report_equals_day075_training
```

### 4.2 五处"必须逐位相等"的常量

| 常量 | 两处实现 | 钉住它的断言 |
|------|----------|--------------|
| `scale` | day073 `scaling_factor` / day075 `softmax_shape_scale` / day076 `head_scale` | 三者对同一输入逐位相等 |
| `GRADIENT_TOLERANCE` | day075 `1e-6` / day076 `1e-6` | `==` |
| `DEFAULT_INIT_SCALE` | day075 `0.25` / day076 `0.25` | `==` |
| `PARAMETER_BLOCKS` | day075 / day076 四个块名 | `==` |
| `GRADIENT_SOURCES` | day075 / day076 两种来源 | `==` |

> 这一节就是"复习"的硬部分：**一个量只要被写了两遍，就必须有一条断言让它无法分家。**
> 而"两处分别跑一遍看起来都对"从来不是证据。

### 4.3 一处**落族差异**（读代码时发现的口径差异）

```text
同一个条件："最后一维不能被头数整除"
  day073  math_foundations.attention.split_heads   → NumericError（按"改数据"分族）
  day076  multi_head.types.HeadPartition           → PartitionError（按"改调用"分族）
```

两者都能用，只是**跨包按异常类型筛错误时要记得这件事**。
（本课程有一条纪律：不改既有模块——它的代价就是这类差异会被保留下来，

## 第五章：误区清单

逐条自测。**先凭记忆回答"为什么错了"，再点链接核对。**

| # | 常见误区 | 正确的说法 | 证据位置 |
|---|----------|-----------|----------|
| 1 | 注意力除以 `√d_k` 是为了"防溢出" | 它是为了把打分的**方差**拉回与维度无关（否则 softmax 饱和、梯度消失） | day073 第八章 |
| 2 | 把被掩码的位置写成 `-inf` 再 softmax | `-inf` 会进入概率层，`0·(-inf) = nan` 会污染整张表 | day073 第七章 |
| 3 | 多头 = 更多参数 | 参数量与 `heads` **完全无关**（四个投影的形状里没有 heads） | day076 第二章 |
| 4 | `heads=2` 时缩放还是 `1/√d_k` | 是 `1/√d_h`，`d_h = d_k/heads`；用错时打分偏小 `√heads` 倍 | day076 第 2.3 节 |
| 5 | 反向漏掉缩放只是"差一个常数，没事" | 差 `√d_h` 倍且**不报错**，只表现为"训练慢" | day075 第五章 / day076 第五章 |
| 6 | 掩码位置的梯度会自动是 0，不用管 | 前向是 0，但 `dWeights` 一般不为 0；**必须显式再置一次** | day075 第 5.1 节 |
| 7 | `dWeights` 就是 `dScores` | softmax 的雅可比要"减去整行加权平均"；简写不报错，只是幅度不对 | day075 第六章 |
| 8 | 多头反向"每一头各回一遍就好" | 四个投影被所有头**共用**，heads 条链必须**相加/拼回** | day076 第 5.2 节 |
| 9 | 激活与权重可以按同一个方向切 | `d_k` 在 `W_q` 的**行**上、在 `Q` 的**列**上 | day076 第四章 |
| 10 | 损失降到 0 = 学到了机制 | 冻结对照：`heads=1` 也把损失压到 0，而峰值只有 0.44 | day075 第十章 |
| 11 | 多头一定比单头强 | 可达集合更大**不**意味着训练能找到；同参数量对照也说明不了"更好" | day076 第九、十章 |
| 12 | 头间差异越大越好 | 它是一个前向读数，且"差异"本身不保证有用 | day076 第八章 |
| 13 | 容差可以随便设 | 容差必须**高于**数值差分的分辨率，否则校验必然失败 | day074 第三章 |
| 14 | 数值侧与解析侧"算的是同一个损失"是显然的 | day075/076 各栽过一次（损失口径、heads、掩码），差 15% / 1e-4 量级**而两边都对** | day075 第 7.3 节、day076 第 6.3 节 |
| 15 | 优化器越复杂越好 | Adam 会放大梯度的**相对**误差；要验证梯度实现请优先用 SGD | day074 / day076 第十一章 |
| 16 | 动量法的两种写法可以混用 | 累加型与 EMA 型差一个 `1/(1−β)` 的等效学习率，混用＝"换了优化器之后要重调 lr" | day074 第 6.3 节 |

```text
① 为什么除 √d_k        方差随 d_k 线性增长 → 打分尺度 ~ √d_k → 除回去
```

## 今日总结

复习不是"再看一遍"，而是**把离散的知识点压缩成少数几个可提取的心智模型**。
今天的内容可以压缩成五句话：

1. **一切可手算性来自"选对支点"**：单位矩阵配置（day075/076）、碗形函数（day074）、
   `softmax([0, 1/√2])`（day073）——期望值来自推导，而不是"上次跑出来的值"。
2. **一切可靠性来自边界处的显式校验**：显式掩码、AST 白名单（day004）、
   解析器的四道防线（day010）、划分的不可整除拒绝（day076）。
3. **一切"不报错"的错误都要专门设一条读数**：缩放系数、掩码梯度、softmax 雅可比、
   分头相加（day075/076 的四处）——**它们只会让训练慢一点**。
4. **一切可测试性来自"两处实现 + 一条断言"**：数值 vs 解析（day074/075/076）、
   `heads=1` vs day075（day076）、`range` 往返恒等（day076）、五个常量（第 4.2 节）。
5. **一切"更强"的说法都要能被算出来或被限定**：多头的"更强"落在可达集合
   （线段 vs 正方形，**存在性**），而"训练能不能找到"是另一个问题——
   这一课把这两件事分开写，而不是混在一句"多头更强"里。
