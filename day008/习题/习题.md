## 第一部分：选择题

### 第 1 题（LLM 的无状态本质）

你在某聊天产品中先发送"我叫小明"，再发送"我叫什么名字？"，AI 正确回答了"小明"。这说明：

- A. 模型在第一次请求后把你的名字写进了自己的权重
- B. 服务端在第二次请求时把第一次的问答历史也一起发给了模型
- C. 模型内部有一个专门为每个用户维护的记忆数据库
- D. 模型通过 cookie 识别了你的身份

### 第 2 题（截断策略选择）

你的 Agent 需要在长达数小时的客服会话中始终记得"用户在开场白里提到的订单号"，以下哪种策略最合适？

- A. FIFO 丢弃最老消息
- B. 只保留最近 5 条消息的滑动窗口
- C. 摘要压缩：定期用 LLM 把老消息压缩成摘要保留要点
- D. 不做任何截断，全部历史都发给模型

### 第 3 题（system 消息保留）

`ShortTermMemory` 截断时始终保留 system 消息，最主要的原因是：

- A. system 消息通常很短，丢了也省不了多少 token
- B. system 消息承载着 Agent 的行为契约（输出格式、可用工具、角色设定），丢失会导致后续输出全面崩坏
- C. Python 的列表不允许删除第一个元素
- D. OpenAI API 强制要求 messages 第一条必须是 system

### 第 4 题（Python 切片陷阱）

执行 `[1, 2, 3, 4][-0:]` 的结果是：

- A. `[]`（空列表）
- B. `[4]`（最后一个元素）
- C. `[1, 2, 3, 4]`（整个列表）
- D. 抛出 `IndexError`

## 第四部分：编程题

### 第 10 题（扩展 ShortTermMemory：支持 assistant 与 user 成对淘汰）

在 ReAct 场景里，assistant 消息（Thought/Action）和紧随其后扮演 Observation 的 user 消息是**语义成对**的——只留 Observation 而丢掉它对应的 Action，模型会看不懂这条观察是哪来的。

请在 `tests/` 下新建 `test_memory_pair.py`，先为下面的 `PairwiseMemory` 写测试，再实现它。要求：

1. 继承或复用 `ShortTermMemory` 的思路，但截断时保证：system 保留，其余消息被淘汰时**成对淘汰**（最老的一对一起丢）；
2. 至少覆盖三个用例：未满容量不截断、超容量时成对淘汰且总数不超上限、system 始终保留在头部；
3. 提示：可以假设非 system 消息总是 user/assistant 交替成对出现，截断时把 `others` 按每 2 条一组从最老开始丢弃。
