# 领域数据准备与增强（M5-D8 / day057）

> 本文是 `smart_research_agent/domain_data/` 的设计说明，与
> [`scripts/domain_data_demo.py`](../scripts/domain_data_demo.py) 的实际输出逐项对应。
> 文中所有数字都是**本课程数据集上的实测值**，不是经验估计。

## 0. 这一课补的是哪半个问题

day048 的 `finetune/` 包回答了"这一批数据能不能用"：

```text
采集 → 清洗（三段管道 + 七条硬规则）→ 精确去重 → 统计 → 切分 → 落盘
```

它的产出是一份 37 条的数据集。但它回答不了下一句：**下一批来了怎么办？**
`domain_data/` 就是这半句话的实现，六个阶段：

```text
clean → quality → near_dedup → mixing → augment → freeze
清洗     五维打分   两级去重       削峰     填谷      打指纹
```

顺序不能换，每条理由都在 `pipeline.py` 的模块 docstring 里；其中三条最容易
被忽略：

| 顺序 | 换位后的后果 |
|------|-------------|
| quality 在 near_dedup **之前** | 会给一批注定被拒的样本付两两比较的钱 |
| near_dedup 在 mixing **之前** | 配比算的是重复项堆出来的占比，削掉的也是重复项 |
| mixing 在 augment **之前** | 刚补进来的样本可能因为所属组超额而被立刻砍掉 |

## 1. 实测总账（`python scripts/domain_data_demo.py`）

```text
raw_counts = {'seed': 18, 'eval/agent_tasks': 7, 'eval/redteam_cases': 16}，合计 41 条
  [clean     ] 进  41 → 出  37 | 丢弃   4 新增   0
      drop_reasons = {"output_too_short": 1, "placeholder_output": 1, "unverified_source": 2}
  [quality   ] 进  37 → 出  37 | 丢弃   0 新增   0
      distribution = {"min": 0.675, "p25": 0.875, "p50": 0.875, "p75": 0.95, "max": 0.95, "mean": 0.8939}
  [near_dedup] 进  37 → 出  37 | 丢弃   0 新增   0   （精确 0 / 近重复 0，阈值 0.7）
  [mixing    ] 进  37 → 出  37 | 丢弃   0 新增   0   （0.5 上限，迭代 1 轮，未触发）
  [augment   ] 进  37 → 出  66 | 丢弃   0 新增  29
      by_op = {"prefix": 13, "constraint": 12, "paraphrase": 4}
      no_change = {"paraphrase": 8}，dropped_duplicates = 0
  [freeze    ] 进  66 → 出  66 | 指纹 ffa3f96a774809ee（v1）
```

前五行的 clean 阶段账与 day048/day049 的已发布结论**逐项一致**
（41 = 18 + 7 + 16，丢 4 条的原因也一样）。这说明本课是**接在** day048
后面继续走，而不是另起一条并行链路。

**一个必须解释的"0"**：`near_dedup` 阶段在本课程语料上一条近重复都没有
检出。这不是功能失效（阈值敏感性表见第 4 节），而是数据本身干净——
那 37 条是人工撰写的种子 + 评估轨迹 + 红队样本，不存在"同一段内容被
复制两遍"。近重复能力要到 `augment` 阶段才有机会被行使，而这件事本身
就是一条可供评审核对的负结果。

## 2. 五维质量打分：为什么门槛是 0.6，以及它到底拦什么

五个维度、五个权重，全部可从代码现场读出（`render_dimension_table()`）：

| 维度 | 含义 | 计算 | 挡住的故障 | 权重 |
|------|------|------|-----------|------|
| `length` | 输出长度落在舒适区 | 梯形分：`<8` / `8~40` 上升 / `40~800` 满分 / `800~4000` 下降 | 太短没信息量、太长是粘贴长文 | 0.25 |
| `repetition` | 自我重复程度 | 3-gram 重复率反向线性：`<=0.10` 满分、`>=0.35` 零分 | 车轱辘话（模型退化的典型输出） | 0.25 |
| `structure` | 结构完整性 | 三档：结构化收尾 1.0 / 有句末标点 0.75 / 都没有 0.25 | 半句话、被截断的输出 | 0.20 |
| `traceability` | 来源可追溯性 | `source` 与 `license` 各计 0.5 | 来源不明、许可证不明的语料 | 0.15 |
| `placeholder` | 无占位符 | 命中 TODO/待补充/lorem 记 0.0，否则 1.0 | 答案没写完的占位样本 | 0.15 |

### 2.1 门槛 0.6 的精确含义（必算，否则是玄学）

总分满分 1.0，门槛 0.6 等价于"**加权质量损失超过 0.4 才拒**"。
五维里最大的权重是 0.25，于是有一条容易被误读的性质：

> **任何一个维度单独归零，总分都还在 0.75 以上，不会被拒。**

这不是漏洞，而是与 day048 硬规则的分工：**单点致命问题**（占位符答案、
空指令、超长粘贴）由那七条布尔规则一票否决；质量分负责"都合格但有好劣"
的排序，因此必须对单点不敏感。要被拒，得**多个维度同时不合格**：

| 样本 | 五维明细 | 总分 | 结论 |
|------|---------|------|------|
| `"TODO：待补充。"` | length 0.0312 / repetition 1.0 / structure 0.75 / traceability 0.5 / placeholder **0.0** | **0.4828** | 拒（最低维 `placeholder`） |
| `"好的好的好的好的好的"` | length 0.0625 / repetition **0.0** / structure 0.25 / traceability 0.5 / placeholder 1.0 | **0.2906** | 拒（最低维 `repetition`） |
| 正常答案（无许可证） | length 0.6875 / repetition 1.0 / structure 0.75 / traceability 0.5 / placeholder 1.0 | 0.7969 | 通过 |

两条被拒样本都是**两个以上维度同时不合格**（第一条：长度 + 占位符；
第二条：长度 + 重复 + 结构），这正是门槛设计想筛的那一类。

### 2.2 覆盖不了的维度就不打分

`format`（格式合规）、`refusal`（拒答边界）、`factuality`（事实性）
本课**一律不给分数**——它们需要结构化或人工判定，用字符级统计量冒充
"事实正确"比承认测不了更糟（day055 的同一条纪律）。

推论：**day055 的四个劣化算子在这套打分器下几乎不变分**。实测把
`drop_tail` / `pad_verbose` / `add_overclaim` 的产物喂进来，总分仍是
`0.9500`（`vague_specifics` 在样例上不适用）。原因是它们优先后仍然
"长度合规、有收尾、来源完整"——**质量分测的是格式与治理，不是内容正确性**。
抓内容问题要靠 day053 的评估套件与 day055 的偏好打分。

## 3. 两级去重：精确打底，近重复补漏

| 级别 | 判据 | 成本 | 结论的性质 |
|------|------|------|-----------|
| 精确 | 归一化后 prompt 的 SHA-1 前 16 位（与 day048 同定义） | O(1) 查表 | 确定：键相同必然重复 |
| 近重复 | MinHash 签名的 Jaccard 估计 | O(已入库条数) 逐条比较 | 估计：有方差，阈值需留裕度 |

顺序不能反：先精确后近似，才能让"完全相同"这一档永远由确定性判据裁决。

`NearDuplicateIndex` 支持**增量**——历史进索引（视为已接受），新批次
`filter` 一遍就得到跨批次去重结果：

```text
增量合并：历史 20 条 + 新批次 10 条
  去重：10 条进 / 5 条留 | 精确重复 5 / 近重复 0（阈值 0.7） → 合并后 25 条
```

这是"可持续更新"的实现基础：不必每来一批就把历史重读重洗一遍。

### 3.1 近重复 ≠ 语义重复

本模块抓的是**字面**重复。实测七组文本对：

| 场景 | 精确 Jaccard | MinHash 估计 | 精确键相同 |
|------|-------------|-------------|-----------|
| 逐字相同 | 1.0000 | 1.0000 | True |
| 加 2 字前缀 | 0.8667 | 0.8906 | False |
| 加 6 字前缀 | 0.6842 | 0.5469 | False |
| 尾部追加一句 | 0.6842 | 0.7969 | False |
| 同义改写（换疑问词） | 0.7333 | 0.6875 | False |
| 同义改写（换两个词） | **0.3000** | **0.3438** | False |
| 完全不同的问 | 0.0000 | 0.0000 | False |

最后两行是关键：**"怎么评价 RAG 的检索效果？"与"如何评估 RAG 的检索
质量？"意思几乎一样，Jaccard 只有 0.3000**。把阈值调到 0.3 去抓它，
会把同一个领域里正常的不同提问全部判死。**语义重复要靠 embedding 与
向量检索**（day041、M6），那是另一条链路、另一份报告。

### 3.2 阈值 0.7 是标定出来的，不是抄来的

在一份 69 条的探针语料（37 条真实样本 + 16 条逐字复制 + 16 条前缀复制）上：

| threshold | 保留 | 精确重复 | 近重复 | 说明 |
|-----------|------|---------|--------|------|
| 0.6 | 40 | 16 | 13 | 抓 13/16 前缀复制 |
| **0.7** | **44** | **16** | **9** | 37 条真实样本零误判 |
| 0.8 | 53 | 16 | **0** | 近重复链路**空转** |
| 0.9 | 53 | 16 | 0 | 同上 |

很多资料给的近重复经验值是 0.8~0.9，但那对应**较长文档**的 shingle 统计。
照抄到短中文提问上，整条近重复链路会一条都检不出来——**静默失效**，
比报错危险。取 0.7 的理由是它在不误伤 37 条真实样本的前提下抓出
9/16 条前缀复制；再往下（0.6）收益只多 4 条，误判风险开始上升。

## 4. 配比控制：上限会连锁收紧，且未必可达

### 4.1 连锁收紧

给"任一组不超过 40%"，直觉答案是"把超过的组砍到 40%"——**这是错的**：
砍掉一组之后总数变小，其余组占比反而变大，必须重算。实测跑 6 轮：

```text
16 : 5 : 16  （T=37，cap=14）→  14 : 5 : 14  （T=33，cap=13）
  →  13 : 5 : 13  （T=31，cap=12）→  12 : 5 : 12  （T=29，cap=11）
  →  11 : 5 : 11  （T=27，cap=10）→  10 : 5 : 10  （T=25，cap=10）收敛
```

最终 25 条，两个大组各占 `10/25 = 40.0%`，**代价是丢掉 12 条（32%）**。
这就是 day049 那句"正确做法不是删安全样本，而是调权或分阶段训练"的
定量答案：硬删的账太贵了。所以本课把缺省上限设成 **0.5（安全网档）**，
它在同一份数据上一条都不丢：

```text
max_ratio=0.5: quotas {seed:16, agent_tasks:5, redteam:16}，dropped 0，迭代 1 轮
```

### 4.2 未必可达——所以必须有 `feasible` 字段

同一份数据换成 `group_by="safety"`（21 正常 : 16 安全）再收 0.4：

```text
21 : 16 → 14 : 14 → 11 : 11 → 8 : 8 → 6 : 6 → 4 : 4 → 3 : 3 → 2 : 2 → 1 : 1（保底生效）
```

**9 轮之后剩下 2 条**，两组各占 50%——约束根本达不到：

```json
{"quotas": {"normal": 1, "safety": 1}, "total_in": 37, "total_out": 2,
 "dropped": 35, "iterations": 9, "feasible": false,
 "final_ratios": {"normal": 0.5, "safety": 0.5},
 "warnings": ["实际占比无法全部落在 0.4 以内（每组至少保留 1 条与取整所致），
               最终占比 {'normal': 0.5, 'safety': 0.5}"]}
```

两组各占一半时，"任一组不超过 40%"**无解**。此时正确的做法不是假装
成功，而是把结论标出来——**一个悄悄违反自己约束的护栏，比没有护栏更糟**，
它会让评审以为"配比已经守住 40% 了"。

收敛性可以证明：每轮把超额组精确压到 `cap`，而 `n > cap` 意味着总数严格
下降，因此一定在有限步内收敛。**收敛不等于可达**。

### 4.3 缺口报告：增强的靶子

`deficit_report` 给定目标权重，用最大余数法算出目标条数（`sum(targets) ==
sum(counts)` 恒成立），于是"谁欠多少条"变成一个具体数字：

```text
等权目标（66 条）：targets {seed:22, agent_tasks:22, redteam:22}
                  deficits {seed:-8, agent_tasks:+13, redteam:-5}
                  → under {agent_tasks: 13}，over {seed: 8, redteam: 5}
```

**这 13 条就是增强该去补的地方。** 本课的增强是无向的（对所有样本轮转
算子），因此它近似等比放大、不会破坏刚削好的配比；**定向增强（只补欠采样组）
需要生成新内容，也就需要模型参与，不再属于"离线可复现"的范畴**——
这是本课明确划出的边界。

## 5. 数据增强：三条纪律

四个算子（`render_augment_table()` 现场生成）：

| 算子 | 改善维度 | 做法 | 风险 | 默认启用 |
|------|---------|------|------|---------|
| `prefix` | 问法多样性 | 在指令前加一句口语化开场白（四个固定变体轮转） | 否 | 是 |
| `constraint` | 指令跟随 | 追加一条原答案本来就满足的输出约束（三条约束，先过守门） | 否 | 是 |
| `paraphrase` | 词汇鲁棒性 | 按受控词表替换指令里的第一处同义词 | 否 | 是 |
| `noise` | 噪声鲁棒性 | 首尾插入口语填充词（会降低质量，且质量打分察觉不到，默认关闭） | 是 | 否 |

### 纪律一：只改 prompt 侧，`output` 逐字不动

增强样本的答案**从亲本继承**。动了 output，"换一种问法"就变成"生成新答案"，
而生成意味着可能出错——一条错了的增强样本会在训练里被当成金标准反复强化。
demo 第 9 节逐条打印核对：

```text
op=aug:prefix      output 与亲本逐字相同=True  source 继承=True  license 继承=True
   亲本：什么是检索增强生成(RAG)?
   增强：请帮我看看：什么是检索增强生成(RAG)?
op=aug:constraint  output 与亲本逐字相同=True  source 继承=True  license 继承=True
   亲本：RAG 检索阶段最常用的相似度度量是什么?
   增强：RAG 检索阶段最常用的相似度度量是什么?\n回答请控制在 200 字以内。
```

**来源与许可证必须原样继承**：增强不改变数据出处，`source` 一变，
按来源的治理统计就全部失真。

### 纪律二：能改写答案正确性的增强，必须自证"答案本来就满足"

`constraint` 往指令后追加输出约束。若原答案 300 字而约束写"200 字以内"，
这条样本就是**自相矛盾**的：模型要么学会忽略指令，要么学会把答案砍短
（而参考答案并没有砍短）。所以每个约束都带 `satisfied_by` 判定，
**只有原答案本来就满足才追加**：

| 约束 | 守门条件 | 本课程数据上的效果 |
|------|---------|------------------|
| `请用中文回答。` | 答案中文占比 >= 0.3 | 4 条英文/代码密集的答案被正确跳过 |
| `回答请控制在 200 字以内。` | `len(output) <= 200` | 37 条全部满足（实测输出 67~165 字） |
| `请直接给出结论，不要复述问题。` | 答案前 8 字不在问题里 | 全部满足 |

不满足就跳过并记进 `guard_rejected`——**跳过是正确行为，不是失败**。

### 纪律三：默认不启用会降低质量的算子

`noise` 加口语填充词，模拟真实用户的口语输入。它默认关闭，理由是：

> 噪声增强造成的质量下降**恰好不在质量打分的五个维度里**——填充词不会
> 让长度越界、不产生 n-gram 重复、也不影响收尾与来源。也就是说
> `quality` 拦不住它。

这种"打分器看不见的风险"只能靠**显式标签**（`aug:noise`）与默认关闭治理。
可以带走的判断：**给流水线加一个算子之前，先问"它出错时谁会报警"**。
没人报警的算子，就必须默认关闭。

### 5.1 一个真实的冲突：增强样本会被自己的亲本判重

第一版把原样本也放进了增强阶段的去重索引，结果是 13 次 `prefix` 尝试里
**5 次**被丢弃（38% 的产出白白浪费）——因为"请帮我看看：X"与"X"的
Jaccard 实测 0.8667，超过阈值。

看起来是"去重器工作正常"，实际上是**去重的判据与增强的意图撞车**：
去重要防的是"同一份语料被无意采集两遍"，而 `prefix` 增强**天生就是要
产出与亲本高度重叠的样本**。判据相同、意图不同，就必须让意图显式化——
于是增强阶段的去重范围被收窄为**增强样本之间**：原样本已经在
`near_dedup` 阶段去过重，而"与自己的亲本像"是设计意图。改动之后：

```text
增强：37 条进 → 新增 29 条（扩容 0.78×）| 算子分布 {prefix:13, constraint:12, paraphrase:4}
     守门拦下 0 / 无变化 8 / 撞车丢弃 0
```

本课程数据上 29 条增强样本彼此零撞车，但这条护栏仍然必要：**两条本来就
相近的原样本被同一算子改成几乎一样的问法**时，它会救场（测试里用
"四条只差一个编号的指令 × 3 次尝试"复现了 12 条产出里丢 4 条的情形）。

### 5.2 算子轮转：覆盖度优先于单条样本的丰富度

每条原样本只产出 1 个增强样本（缺省），算子按 `ops[(序号 + 第几次尝试) % 算子数]`
轮转，**不使用随机数**。这与 day055 的 `pick_rejected` 是同一条取舍：
随机抽样会让一部分算子完全抽不到样本，而"哪个算子对模型更有用"这个问题
必须有数据才能回答。确定性轮转保证每个算子在每个批次里都被行使。

## 6. 清单（manifest）：版本链的载体

`DomainDataManifest` 落盘为 `manifest.json`，字段包括版本号、内容指纹、
父版本指纹、六个阶段的账、来源分布、配比与实际占比、质量分分布、
拒绝归因、增强算子分布、配比缺口，以及**所有影响结果的参数快照**。

- **内容指纹** = 逐条样本 prompt 精确键按顺序拼接后的 SHA-1 前 16 位。
  它与去重口径一致（回答"这是不是同一批问题"），并且**顺序敏感**：
  批次顺序会影响可复现切分与训练时样本先后，因此"顺序变了"就是"版本变了"。
- **父版本指纹**把版本串成链，配合 `merge_with_history` 构成"可持续更新"。
- **参数快照**是"同一指纹在别人机器上能复现"的前提。缺了它，
  指纹只是一串好看的字符。

一份没有清单的 jsonl，三个月后没人说得清它是哪一版、按什么参数生成的。

## 7. 常见错误对照表

| 错误做法 | 后果 | 正确做法 |
|---------|------|---------|
| 把近重复阈值照抄 0.8 | 短中文提问上近重复**一条都检不出**（静默失效） | 在自有语料上标定（本课 0.7），并输出阈值敏感性表 |
| 期待近重复抓"语义重复" | 阈值被迫调到 0.3，正常提问全被判死 | 语义重复交给 embedding（M6）；两条链路分开报告 |
| 用质量分替代硬规则 | 占位符样本"扣 0.15 分"之后照样过线 | 先硬规则一票否决，再用分数排序 |
| 期待质量分抓内容错误 | `drop_tail` 的产物仍是 0.95 分 | 内容正确性靠评估套件与偏好打分 |
| 单条约束不检查答案是否满足 | 训出"忽略指令"或"把答案砍短"的模型 | 每条约束配 `satisfied_by` 守门 |
| 增强改动 `output` | 引入幻觉答案，并在训练里被当金标准强化 | 只改 prompt 侧；测试对每个算子断言 output 不变 |
| 增强阶段把原样本放进去重索引 | 与亲本撞车，实测浪费 38% 的 `prefix` 产出 | 去重范围收窄为"增强样本之间" |
| 默认开启看不见风险的算子 | `noise` 的质量损失不被任何维度察觉 | 显式标签 + 默认关闭；先问"出错时谁报警" |
| 上限约束只砍一轮 | 其余组占比反弹，约束静默失效 | 不动点迭代到收敛（本课 6 轮 / 9 轮） |
| 假设上限约束一定可达 | 两组接近时无解，护栏悄悄失效 | 输出 `feasible` 与告警，把"做不到"说出来 |
| 数据集不带清单 | 三个月后没人说得清它是哪一版 | 指纹 + 父指纹 + 参数快照随数据集落盘 |
| 让 stage 的"丢弃"记净变化 | 增强阶段印出"丢弃 -29"，评审以为账错了 | `dropped` / `added` 分开，另给有符号的 `net_change` |
