## 一、选择题

### 1. B

`q·k` 在 `q`、`k` 的各维独立同分布（均值 0、方差 1）时，方差是 `d_k`。
因此打分尺度随 `√d_k` 增长；不除的话 softmax 的输入会越来越大、
分布越来越尖（趋于 one-hot），而饱和区里的梯度极小 —— 训练会"显得不动"。
除以 `√d_k` 把方差拉回 1，与维度无关。

- A 错：溢出不是主要问题（`softmax` 本身有减最大值的稳定实现，day073 讲过）。
- C 错：方向反了——除以 `√d_k` 是**防止过尖**，而不是让分布更均匀。
- D 错：它与训练直接相关（梯度大小受影响）。

出处：day073 第八章（"为什么要除以 √d_k"）。

### 2. B

显式掩码让被掩码位置的权重**恰好是 0.0**，于是

```text
dScores_i = s_i(g_i − Σ_j g_j s_j)      当 s_i = 0 时自动是 0
```

**零梯度成为一条推论**，而不是需要额外处理的特例。

- A 错：`-inf` 会进入概率层，`0·(-inf) = nan` 会顺着"平均熵"污染整张表（day073 第 7.3 节）。
- C 错：反向里的梯度会受影响（第 ③ 处"漏掉不会报错"）。
- D 错：两个来源同时给时**当场报错**（`causal=True` 与显式掩码互斥）。

出处：day073 第 7.3 节、day075 第 4.2 节。

### 3. B

四个投影的形状是 `W_q/W_k: (d_k, d_in)`、`W_v: (d_v, d_in)`、`W_o: (d_out, d_v)`
——`heads` 一个都不出现。它决定的只是"这些维度被切成几段"。

也正因为如此，`heads=1/2/3` 的对照是**同参数量对照**：比较的是"注意力被组织成几份"，
而不是"参数多了多少"（D 是这一课最想澄清的误解）。

出处：day076 第 10.2 节。

### 4. B

```text
head_dim = d_k / heads = 12 / 3 = 4
scale    = 1/√head_dim = 1/√4 = 0.5
```

- A 是**单头**的缩放（day075 用的那个）。
- C 把 `heads` 本身当成了分母（`1/√3 = 0.577`）——一个常见的记混。
- `scale_ratio = (1/√4)/(1/√12) = √3 = √heads`。

出处：day076 第 2.3 节。

### 5. B

数值差分的误差由两部分组成：舍入误差（约 `ε/h`）与截断误差（约 `h²`），
在某个"最优步长"处取到最小 —— 那个最小值就是**分辨率**。
容差低于分辨率时，即使推导完全正确，对照也会失败（day074 第 3.4 节量出过这个数）。

- A 错：`1e-12` 在损失量级 `1e-1`、步长 `1e-6` 时已经低于分辨率。
- C 错：分辨率还与函数曲率、步长有关。
- D 错："能红就行"正是分辨率问题的反面。

出处：day074 第三章；day075/076 的容差都取 `1e-6`（比分辨率松三个数量级）。

### 6. B

```text
pairs = 1·0/2 = 0      → 没有可比的头对
mean_total_variation = 0.0
degenerate = False     ← 实现里写的是 self.pairs >= 1 and mean <= 1e-9
```

`degenerate=False` 的理由是语义上的：**"没有第二个头"与"多头退化了"不是同一件事**——
前者结构如此、不需要动作；后者各头学到了同一分布、需要改训练。
两者在数值上都表现为 `TV = 0`，因此必须靠 `pairs >= 1` 这半句区分开。

出处：day076 第 8.3 节。

## 二、简答题

### 7. 为什么要除 `√d_k`

**一句话**：因为 `q·k` 的方差随 `d_k` 线性增长（因此标准差随 `√d_k` 增长），
不除的话 softmax 会随着维度变大而越来越尖、梯度越来越小。

方差论证要点：

```text
设 q、k 的各维独立同分布，均值 0、方差 1
q·k = Σ_{i=1}^{d_k} q_i k_i
E[q_i k_i] = 0
Var(q_i k_i) = E[q_i²]·E[k_i²] = 1     （独立性 + 均值 0）
Var(q·k) = Σ Var(q_i k_i) = d_k        （各项独立 → 方差可加）
→ 打分标准差 ~ √d_k，除以它之后方差回到 1
```

出处：day073 第八章（它同时给了"手推"与"量出来"两条路）。

### 8. 四处"漏掉不会报错"

| # | 位置 | 漏掉之后 | 症状 |
|---|------|----------|------|
| ① | softmax 的雅可比 | 写成 `dScores = dWeights` | 方向"大致"对、幅度不对 → **训练慢**（看起来像 lr 设小了） |
| ② | 缩放系数 | 反向漏乘 `1/√d_h` | 梯度整体差 `√d_h` 倍（`head_dim=2` → 1.414 倍）→ **训练慢/步长像偏大** |
| ③ | 掩码位置的梯度 | 不显式置 0 | 前向完全正确，只有 key 的梯度里混进"未来" → **损失曲线看起来正常** |
| ④ | 分头之后相加 | 只回第一头/漏一头 | 形状完全正确 → **其余头"学得慢"**（多头白买一半） |

第 ③ 条最隐蔽（前向看起来毫无问题），第 ④ 条最"像正确实现"（形状对、损失真在降）。

出处：day075 第一/五章、day076 第一/五章。

### 9. 为什么"两处分别跑一遍看起来都对"不是证据

因为两处实现是**两条独立的真相**：

```text
各自"看起来对"     只说明各自能自洽（能跑出形状正确、数值合理的输出）
不能说明两者一致   一致性是一个**关系**，而不是两个个体各自的属性
```

正确的做法：**留一条断言把两处钉在一起**。四天里这样的断言有五条：

```text
scale              head_scale(d) == softmax_shape_scale(d) == scaling_factor(d)（逐位）
GRADIENT_TOLERANCE day075 的 1e-6 == day076 的 1e-6
DEFAULT_INIT_SCALE day075 的 0.25 == day076 的 0.25
PARAMETER_BLOCKS   两天的四个块名逐项相等
GRADIENT_SOURCES   两天的两种来源逐项相等
```

还有一条更强的：`heads=1` 的输出必须与 day075 的自注意力**逐位相等**
（`test_heads_one_reproduces_day075_bit_for_bit`）——它是"多头是单头严格超集"
这句话的工程证据。

出处：day076 第 4.2 节（那张"必须逐位相等的常量"表）。

### 10. 数值 vs 解析

| | 两个优点 | 一个死穴 |
|---|----------|----------|
| **数值差分** | ① 不依赖任何推导（因此它是**独立参照**）② 实现极简 | 慢：`2 × 参数量` 次前向；精度受步长与分辨率限制 |
| **解析梯度** | ① 快：一次反向拿到全部参数梯度 ② 精度高：不受步长影响 | 推导写错了**不会报错**（四处"漏掉不会报错"就是它的表现形式） |

为什么必须**同时存在**：

```text
解析梯度是**生产路径**（训练用它），数值差分是**校验路径**（只用来对账）
把两者当成"两种实现"而不是"一条路径 + 一次独立检查"，就会漏掉这条纪律：
校验的一方不能依赖被检查的一方
```

这也解释了为什么数值侧只在小规模上跑（"数值差分只适合校验、不适合训练"）。

出处：day074 第一章与第十章；day075/076 的五项校验。

### 11. 提取练习（Retrieval Practice）

术语：**提取练习（Retrieval Practice）**——主动回忆的效果好于重复阅读。

**工程上的等价物**：构造一个**能被证伪的检查**，而不是重读代码觉得"看起来对"。

```text
"我读了一遍实现，逻辑没问题"          ← 重复阅读
"我写一条断言，让错误版本会红"          ← 提取练习
```

四天里这种等价物出现了很多次：

```text
head_scale 与 scaling_factor 的逐位比较      让"两处实现分家"能被证伪
heads=1 逐位等于 day075                      让"退化关系被破坏"能被证伪
merge(split(M)) == M                          让"切法改了"能被证伪
四项梯度校验 + inputs 那一项                  让"漏了一条链"能被证伪
```

## 三、诊断题

### 12. 索引写死了 `[0]`

错误：`forward.head_keys[0]` / `forward.head_queries[0]` —— **每一头都用第 0 头的 K/Q 回传**。
对第 `h` 头应当用**它自己**的那一份：

```python
        grad_queries = matmul(grad_raw, forward.head_keys[head])
        grad_keys = matmul(transpose(grad_raw), forward.head_queries[head])
```

为什么在 `heads = 1` 时**完全看不出来**：那时 `head 0` 就是唯一的头，
`forward.head_keys[0]` 恰好就是它自己的 K —— 形状、数值都对，
`heads=1` 与 day075 的逐位相等断言也会通过。

为什么在 `heads > 1` 时"形状正确、损失也在降"：`grad_raw` 是 `(n, n)`、
`head_keys[0]` 是 `(n, head_dim)` —— 对**任何** `head` 都合法，
因此形状断言不会红；而"至少第 0 头是对的"就足以让损失继续下降。

哪两项梯度校验会红：`w_query` 与 `w_key`。

```text
它们正是"要穿过打分与 softmax"的两项：
dQ_h = dRaw_h · K_h、dK_h = dRaw_hᵀ·Q_h —— 用错 K/Q 会直接算错
而 w_output / w_value 不受影响（它们不经过打分那一步）
```

出处：day076 第 5.1 / 6.1 节；这也是"五项分开校验"的价值——
一个整体误差数字回答不了"是哪一块错了"。

### 13. 两份报告

**report A（头间差异恒为 0，而损失到 0、命中率 100%）**

```text
诊断    多头**退化**：各头学到了同一个分布 → 这一层等价于一个单头注意力
        （付了 heads 份参数、只用了一份注意力）
注意    损失与命中率的表现完全正常——这正说明"损失为 0 可以有多种机制"
下一步  ① 查参数初始化：是否各头拿到的行块完全一样（例如人为重复填的块）
        ② 查划分实现：是不是每一头拿到的维度是同一段（往返恒等那条断言能发现）
        ③ 若两者都没问题，则检查任务本身是否只需要一个模式——
           退化不等于"这层错了"，它只是"多头没有被用上"
```

**report B（损失几乎不动、命中率反而下降、峰值上升、头间差异很小）**

```text
诊断    "注意力变尖了，但 value/output 没能把看到的东西映射成目标"——
        这正是 day075 的**只训 q/k** 指纹：
        冻结对照里 只训 {w_query, w_key} 给出 损失 0.1634 → 0.1554、
        命中率 38% → 12%、峰值 0.232 → 0.587
下一步  ① 查 trainable：是不是漏掉了 w_value / w_output
        ② 若确实只训 q/k，则这正是预期结果（可用它确认冻结确实生效）
        ③ 若 trainable 是全量，则检查 value/output 的梯度是否被误置 0
           （head_gradient_norms / head_gradient_shares 能看出"哪些头没在动"）
```

两份报告合起来是这一课最值钱的一句话：**没有任何一个读数能单独说明"学到了什么"**。

出处：day075 第 10.4 节（冻结对照）、day076 第八/十章。

## 四、推导题

### 14. softmax 的反向

从完整雅可比出发：

```text
目标：dScores_i = Σ_j g_j · ∂p_j/∂z_i

∂p_j/∂z_i = p_j(δ_ji − p_i)                      （已知：day073 验证过）

dScores_i = Σ_j g_j · p_j(δ_ji − p_i)
          = Σ_j g_j p_j δ_ji − p_i Σ_j g_j p_j
          = g_i p_i − p_i Σ_j g_j p_j
          = p_i (g_i − Σ_j g_j p_j)
```

验证 `p = (0.5, 0.5)`、`g = (1, 0)`：

```text
平均 = Σ_j g_j p_j = 1·0.5 + 0·0.5 = 0.5
dScores₀ = 0.5 × (1 − 0.5) = 0.25
dScores₁ = 0.5 × (0 − 0.5) = −0.25
```

为什么不能简写成 `dScores = g`：

```text
简写**不会报错**，方向也"大致"对，因此训练仍然能下降——
只是每一步的幅度不对（差一个"减去整行加权平均"的量）。
一个立刻可验证的反例：p 均匀、g 也均匀时，正确的 dScores 是**全 0**
（括号里那一项恰好等于每一个 g），而 g 本身显然不是 0。
```

出处：day075 第六章。

### 15. 多头的可达集合

```text
① contrib_j = W_o · V_j      （第 j 个位置对**输出空间**的贡献）
   单头一行 = Σ_j w_j · contrib_j，其中 w 是 A_i 上的一份分布
② "任意分布的加权平均" = 凸包：
   { Σ_j w_j · contrib_j : w 是分布 } = conv{ contrib_j : j ∈ A_i }
   单头的结构性限制：**同一组混合系数作用于所有 value 维**
③ 多头：output_i = Σ_h Σ_j w^h_j · contrib^h_j
   闵可夫斯基和形式    Σ_h conv{ contrib^h_j }
   网格点集形式        conv{ Σ_h contrib^h_{j_h} : 每个 j_h ∈ A_i }
   两者相等靠 conv(A) + conv(B) = conv{a + b : a ∈ A, b ∈ B}
```

手算（教程第九章的样本：`W_o = [[1,0,0,0],[0,0,0,1]]`、
两头各沿一条轴、四个位置的 pull 是 `(1,0,0.5,0.5)` 与 `(0,1,0.5,0.5)`）：

```text
单头顶点   (1,0)、(0,1)、(0.5,0.5)
为什么共线 (0.5,0.5) 恰好是 (1,0) 与 (0,1) 的**中点**
单头凸包   线段 (1,0)—(0,1)（直线 x + y = 1，x ∈ [0,1]）
目标 (1,1) 到它的距离：
           垂足是中点 (0.5,0.5) → 距离 = |1 + 1 − 1|/√2 = 1/√2 = 0.707107
多头凸包   网格点 (t_a, s_b) 共 16 个（去重 9 个）→ 正方形 [0,1]²，距离 0
兑现权重   head 0 → (1,0,0,0)（押在位置 0，那里 t = 1）
           head 1 → (0,1,0,0)（押在位置 1，那里 s = 1）
           相加 = (1,0) + (0,1) = (1,1)   两份分布的 TV = 1.0（最大值）
```

三个必须一起记住的限制：

```text
① 前提是 head_dim >= |A_i|：否则真实可达集合更小，而"双头到得了"就**失去证据**
   （本包在前提不成立时直接拒绝计算）
② 它回答**存在性**（输出空间里哪些点到得了），不回答**优化问题**
   （训练能不能找到那组参数）—— 上面那份权重是**构造**的，不是训练出来的
③ 公式值 1/√2 与算法值差最后一位（…475 vs …476，一个 ulp）：
   两条不同的计算路径，判据因此取容差而不是 ==
```

出处：day076 第九章与 `docs/multihead_attention.md` 第 9 节。
