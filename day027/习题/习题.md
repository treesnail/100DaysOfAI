# day027 课后习题：输出质量评估

> 共 10 题：3 道选择题、2 道判断题、3 道问答题、2 道编程题。建议先独立完成再对照[答案](../习题答案/习题答案.md)。

## 一、选择题

**第 1 题**（单选）下列哪项输出质量问题**最适合**用纯规则（正则/解析器）检测，而不需要模型参与？

A. 答案答非所问，没有回应用户的真实意图  
B. 约定输出 JSON，实际返回了一段散文  
C. 答案措辞过度自信，掩盖了不确定性  
D. 答案对两个方案的优劣判断颠倒了

**第 2 题**（单选）`OutputEvaluator` 中模型打分通道失败（返回乱码）时，评估器的行为是：

A. 抛出 `ValueError`，中断 Agent 的 run()  
B. 跳过本次评估，不产出任何 OutputScore  
C. 降级为纯规则评估，仍产出 OutputScore  
D. 用上一次成功的评分结果代替

**第 3 题**（单选）在线输出评估（每次 Agent 输出实时评估）与离线评估（Harness 批量跑数据集）最根本的区别是：

A. 在线评估必须用规则，离线评估必须用模型  
B. 在线评估没有参考答案，只能利用任务、过程证据与输出本身  
C. 在线评估速度更快  
D. 离线评估不能评估 Agent，只能评估 Prompt

## 二、判断题

**第 4 题**（判断）数字一致性检查中，当 Agent 没有调用任何工具（observations 为空）时，输出里的数字会被判定为"疑似编造"并扣分。（对 / 错）

**第 5 题**（判断）在 `ReactAgent._evaluate_output` 中用宽捕获 `except Exception` 吞掉评估器的所有异常，是一种坏味道，应该改成精确捕获特定异常类型。（对 / 错）

## 三、问答题

**第 6 题**（问答）教程中说"评估是旁路，不是闸门"。请解释：(1) 这句话的含义；(2) 如果把评估器改成"闸门"（overall 低于 0.6 就拒绝返回答案、要求 Agent 重试），会带来哪三个具体问题？

**第 7 题**（问答）规则通道与模型通道在**成本、一致性、覆盖面**三个维度上各有何优劣？为什么说它们是"互补"的，而不是"冗余"的？请结合格式合规、准确性、有用性三个指标的分工说明。

**第 8 题**（问答）`OutputQualityLogger` 选择 jsonl 而不是单个 JSON 数组文件来存日志。请给出至少三条理由，并说明"单行损坏不传染"具体指什么场景。

## 四、编程题

**第 9 题**（编程）为 `OutputEvaluator` 增加一个新的规则检查：**任务关键词覆盖**。规则如下——从 `task` 中抽取长度 ≥ 2 的连续中文字符串片段（用正则 `[\u4e00-\u9fff]{2,}`），若输出中一个片段都不包含，记一条 issue（"答案未覆盖任务关键词，疑似答非所问"），并对 `helpfulness` 的规则侧估计扣 0.3（下限 0）。

要求：

- 实现 `_check_task_coverage(output, task) -> tuple[float, list[str]]` 并接入 `evaluate()`（仅影响 helpfulness 的规则侧部分；模型通道正常时，可将其作为 helpfulness 的加权项，权重自定但需说明）；
- 用 MockLLM 编写至少 2 个测试：覆盖缺失时扣分、覆盖正常时不扣分。

**第 10 题**（编程）基于 `EvaluationHarness` 与 `OutputQualityLogger` 写一个**回归对比脚本**：

1. 准备两份 jsonl 日志文件（可用代码生成）：`before.jsonl` 与 `after.jsonl`，各模拟 20 条评估记录；
2. 分别用 `OutputQualityLogger.aggregate()` 聚合；
3. 输出对比结论：若 `after` 的 `avg_overall` 比 `before` 低 0.1 以上，打印"回归告警：输出质量显著下降"，否则打印"无显著回归"；
4. 用 `tmp_path` fixture 写一个 pytest 测试，验证两种分支（回归 / 无回归）都能得出正确结论。

提示：记录可用 `OutputScore(helpfulness=x, accuracy=x, format_compliance=x, overall=x, issues=[])` 配合 `logger.log()` 直接生成。
