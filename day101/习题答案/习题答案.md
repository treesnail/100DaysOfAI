## 一、速答

**1.** 两种：`doc`（仓库 `docs/` 下的 `*.md` 全文，当前 **46 份**）
与 `subpackage`（每个子包的 `__init__.py` docstring，当前 **53 条**）。
合计 **99 份、535049 字**。

**2.** 因为**裸名字会撞车**：`backprop` / `capstone` / `conv_net` / `graduation`
都同时是"一篇手册"与"一个子包"。不带种类前缀时，`Corpus` 的"名字唯一"检查会抛
`CorpusError: 语料里有重复的文档名：['backprop']`——
两件不同的材料共用一个名字，检索结果里就没法区分它们。
带前缀之后它们分别是 `doc:backprop` 与 `subpackage:backprop`，各自可被区分、可被点名。

**3.** 因为**换一个分词库版本就会换一份索引**，而"索引可复算"是这份产物的全部价值。
二元组的代价是**比词粗**：它按字面相邻切（"反向传播" → 反向 / 向传 / 传播），
会多召回一些不含这个词、只是"字面共现"的材料。
本课要的不是最好的检索质量，而是一份能被别人重算出同一结果的索引。

**4.**

```text
tokenize("反向传播") = ("反向", "向传", "传播")   长度 4 ⇒ 3 个相邻二元组
tokenize("好")       = ("好",)                    长度 1 < NGRAM(2) ⇒ 整段作为一个 token
```

依据两条规则：ASCII 词取 `[A-Za-z0-9_]+` 且长度 >= `MIN_WORD_LEN`；
中文串长度 >= `NGRAM` 时切全部相邻 `NGRAM` 元组，更短的整段作为一个 token。

**5.** 两个独立的正则各扫一遍，会把"先 ASCII 后中文"这个**与正文无关的顺序**
写进 `query_tokens` 与 `matched`——而这两个东西会出现在报告里：

```text
tokenize("向量 向量 index index")
  两个正则各扫一遍   ⇒  ('index', '向量')   ← 顺序与正文相反
  一个交替正则       ⇒  ('向量', 'index')   ← 跟着正文走
```

匹配本身是集合运算，顺序不影响结果；但它影响**报告的可读性**。

**6.** 挡住的是**并列的不确定性**。Python 的 `dict` 保留插入顺序，而插入顺序取决于
"构建时先遍历了哪一份文档"。不排序时 `repr(postings)` 会随构建顺序变化，
于是"同一份语料两次编出同一份索引"这条性质会**永远失败**。
排序之后，结果只取决于"有哪些文档"，与遍历顺序无关。

**7.**

```text
① 分数高的在前
② 分数并列时，**文档名**字典序在前
```

第二条必须存在，因为并列真的会发生：本课的金标准查询 `"course_index"`
同时命中 `doc:course_index` 与 `subpackage:course_index`，两条分数都是 `1.0000`。
**没有规则 ②，两份名单都"对"**——而"都对的名单"无法被复算。

**8.** 因为**分数必须能被核对**。`score` 回答"多少分"，`matched` 回答"这个分是怎么来的"
（命中的那几个词）。少了 `matched`，一个 0.5 分就只能被相信、不能被核对——
这与 day099 的"接地判据是编号而不是字符串"、day100 的"自评必须挂证据"是同一条纪律。

**9.**

```text
空查询 / 无词查询   ⇒  QueryError（调用点的问题）
查了但名单为空       ⇒  正常返回空名单（语料的问题）
```

必须分开，因为**出路不同**：前者要改调用或改分词，后者要查语料或改索引。
混成一件事，会让"我把 query 写空了"看起来像"这门课没有讲这个"。
因此"拒绝空名单"被单独做成 `require_hits()`，而不是 `search()` 的默认行为。

**10.** 下界两条：⑥ `every_document_is_indexed`（最小词数 >= 1）、
⑦ `gold_query_finds_gold_document`（命中 >= 1）。
上界一条：⑤ `scores_within_bounds`（最高分数 <= 1.0）。
把下界写成相等（`== 1`）会在"一份文档切出更多词"或"金标准同时出现在前排与后排"时
**误报失败**——也就是在系统**变好**的时候变红。

## 三、对照

**13.** 因为两者**可被反驳的程度完全不同**：

```text
A "可复算"    是一个可以被机器判定的命题：两次构建的摘要是否相同（差异项数 == 0）
B "通常是对的" 是一个无法被反驳的说法：它没有语料、没有金标准、没有阈值
```

A 能落成一条性质（本课的第 ③④ 条），因此它每天都能被重跑；
B 只能落成一句话，因此它在报告里与"我们没测过"长得一样。
本课刻意只承诺 A——**它承诺的不是"好用"，而是"可被信任"。**

**14.** 它们挡的是**两类不同的东西**：

```text
CorpusError（重名）      输入的问题：两份材料共用一个名字 ⇒ 改语料收集
IndexBuildError（未排序）工序的问题：同一份语料两次编出不同的索引 ⇒ 改索引实现
```

这正是失败族"按谁的错、该谁去修"分族的直接体现：
把它们混成一族，会让"补一份漏掉的文档"的人去查索引算法。

**15.** 两者是"**证据**"与"**读数**"的关系：

```text
day100 的四份交付物   是**产物**：剧本 / 清单 / 自评 / 规划，各自回答一个独立问题
day101 的四张表       是**读数**：语料 / 索引 / 检索 / 性质，各自描述一份索引的一个侧面
```

共通的纪律是"每一行都带两个数"：交付物的"四份非空"计数与"哪一份是空的"，
表里的"读数"与"参照"。**产物要被别人拿去用，读数要被别人拿来核对。**

## 四、诊断

**16.** 他改坏的是**语料的名字与它对应的材料之间的对应关系**：

```text
改名前  docs/backprop.md  →  doc:backprop      （与子包 backprop 同名，但带种类前缀，不冲突）
改名后  docs/backprop2.md →  doc:backprop2     （手册那一条换了名字）
```

真正的问题不在"改名"，而在**他没有同步任何参照**：
只要期望名单里仍然是 `doc:backprop`，语料里就少了一条、多了一条。
本课第 ① 条性质 `corpus_covers_all_docs` 会当场变红——

```text
手册 46 份 / 期望 46 份 | 缺失 ['doc:backprop']
```

**这正是"覆盖检查必须由一份独立的期望名单算出来"的理由**：
如果覆盖检查只是"语料里有什么就报什么"，那改名永远不会被发现。

**17.** 最可能的原因是：**按空格切词对中文完全无效**。

```text
"反向传播" 里没有空格  ⇒  按空格切得到 ['反向传播']（一整段）
查询 "反向传播"        ⇒  得到查询词 ['反向传播']
而索引里存的是……        ⇒  要么同样是一整段（能命中），
                           要么语料里的写法不同（如"反向传播的梯度"）⇒ 切出的是"反向传播的梯度"，对不上
```

按空格切词在中文上的典型现象就是"看起来建了索引，实际一个词都没切对"。
本课第 ⑥ 条性质 `every_document_is_indexed`（**最小词数 >= 1**）会在跑起来之前
就把它暴露出来：一份几千字的手册如果只切出 1 个 token，读数会立刻掉到 1；
如果切出 0 个，读数掉到 0、性质当场失败。
**换句话说，"切得太粗"是这条下界性质的读数变小，"完全没切"是它失败。**

## 五、推导

**19.**

```text
① "向量 维度 不一致"
   向量    2 字 ⇒ 1 个二元组      向量
   维度    2 字 ⇒ 1 个二元组      维度
   不一致  3 字 ⇒ 2 个二元组      不一、一致
   tokenize 结果 = ("向量", "维度", "不一", "一致")
   token_count   = 4

② "Course_Index a 反向"
   Course_Index  ASCII ⇒ 小写化 course_index（下划线算词内字符），长度 12 >= 2 ⇒ 保留
   a             ASCII ⇒ 长度 1 < MIN_WORD_LEN(2) ⇒ 丢掉
   反向          2 字 ⇒ 1 个二元组 反向
   tokenize 结果 = ("course_index", "反向")
   token_count   = 2
```

**20.**

```text
① 分数（score = 命中词数 / 查询词总数，这里查询词总数 = 2）
   doc:a  命中 {反向, 梯度} ⇒ 2 / 2 = 1.0
   doc:b  命中 {反向}       ⇒ 1 / 2 = 0.5
   doc:c  命中 {梯度}       ⇒ 1 / 2 = 0.5

② 排序
   规则 ① 分数降序：1.0 在前
   规则 ② 并列时按文档名字典序：doc:b < doc:c
   ⇒ 名单 = (doc:a 1.0, doc:b 0.5, doc:c 0.5)

③ 第 ⑤ 条性质 scores_within_bounds 读的是"最高命中分数"
   最高 = 1.0
   上界 = 1.0（SCORE_CEILING）
   ⇒ 读数 1.0 <= 1.0，性质通过
```

注意 ③ 的写法：它的读数是 **1.0**（一个刚好触到上界的值），
而不是 0。这与第 ③④ 条"差异项数 == 0"的读数长得完全不同——
**判据的方向决定了读数看起来应该是什么样**：
相等判据读 0 才叫通过，上界判据读到上界也叫通过。
