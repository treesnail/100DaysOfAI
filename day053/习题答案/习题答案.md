## 第一部分：选择题

### 第 1 题：**B**

难度不是主观标注，而是**结构负载**：

```text
structural_load = |required_facts| + |forbidden_facts| + |must_contain| + |must_not_contain|
                + (1 if max_chars <= 150 else 0)

load <= 2 → easy      load <= 4 → normal      否则 → hard
```

实测 18 条用例的分布是 `easy 4 / normal 9 / hard 5`，平均负载 `3.6111`、最大 `6`。
`audit_suite` **返回问题清单而不抛异常**：

```python
audit_suite(build_suite()) == []      # 实测：18 条全部自洽
```

理由写在源码注释里：难度标注偏差会让结论变弱，但不会让流程崩掉；把它变成硬错误
只会让人去改阈值，而不是改用例。A 错误（难度不是自由文本）；C 错误（`max_chars`
只是负载里的一个 +1 项）；D 错误（不抛异常）。

### 第 2 题：**D**

D 是错的，而且它恰好是**第一版实现**踩过的坑。逐条核对：

- A 对：`min(n-1, ·)` 是"训练集非空"的硬保证。构造"每桶只有 1 条"的用例集时
  `n_eval = 0`，整桶留在训练侧；反过来若某桶的配额吃光整桶，`min(n-1, ·)` 会兜住。
- B 对：按格子切分时 `max(1, round(1 × 0.25)) = 1`，18 个格子各 1 条 → 全部进评估集，
  训练集为空。这个错误**不会在切分函数里报错**，只会在训练时以"数据集为空"炸出来。
- C 对：实测第一版"每桶取第 0 位"给出 `easy 1 / normal 5 / hard 0`；改成轮转位次后
  是 `easy 1 / normal 3 / hard 2`。**评估集里没有难例，"难例上的表现"就无从谈起。**
- D 错：稳定不等于均匀。位次的稳定性由"按难度升序 + 同难度内按种子打乱"保证，
  不需要靠"永远取第 0 位"。

### 第 3 题：**B**

```python
passed = (missing_facts == ()) and (forbidden == ()) and (violations == ()) and refusal_correct
```

它是一个**合取**，不是阈值判定。理由：加权平均会让"少说一个要点"（扣
`fact_recall` 0.40 的一部分）与"编造一个数字"（同样扣 0.40 的一部分）互相抵消，
而这两件事的业务后果完全不同。加权总分（`ItemOutcome.score`）单独报告，
回答"好多少"。

D 是最有迷惑性的错误选项：**过度拒答同样是失败**。`refusal` 分量在六个桶里都生效，
`expect_refusal=False` 的输出若被判定为拒答，`refusal_correct=False`、该条不合格。

### 第 4 题：**B**

正态近似在 `p = 1.0` 时给出宽度为 0 的区间——"18 条全对"被说成"合格率精确等于
100%"，而在 18 条样本上这个结论明显过强。Wilson 得分区间在 `p` 接近 0 或 1 时
仍然给出合理宽度。实测（`z = 1.96`）：

```text
wilson(4, 6)  = [30.00%, 90.32%]
wilson(3, 18) = [5.84%, 39.22%]
wilson(18, 18) = [82.41%, 100.00%]      ← 上界 1.0，但下界不是 1.0
wilson(0, 0)  = [0.0, 1.0]              ← 空样本的诚实答案是"什么都不知道"
```

C 错（正态近似不是只在 `n > 1000` 才成立，只是小样本 + 极端 `p` 下不可靠）；
D 错（Wilson 的宽度不为 0）。

### 第 5 题：**B**

配对比较看的是**同一条用例上的翻转**，不是两个独立比例：

```text
b = 之前过、之后不过        c = 之前不过、之后过
n = b + c
p = min(1, 2 · Σ_{k ≤ min(b,c)} C(n,k) / 2ⁿ)
```

实测（本课两臂在评估集上）：`b = 0`、`c = 3`、卡方（带连续性修正）
`(|0-3|-1)²/3 = 1.3333`、`p = 0.25`、`significant = False`。

A 错（那两个数是翻转计数，不是合格率之差）；C 错（**明确用精确检验**，
卡方只作参考报出——本课只有 3 个不一致对，卡方近似不可靠）；
D 错（`b + c = 0` 时返回 `p = 1.0`：不一致对为 0 意味着两臂完全一样，
此时没有任何理由说它们不同）。

两尾求和会超过 1（例如 `n=4, k=2` 的原始求和是 `1.375`），所以最后取 `min(1, ·)`。

### 第 6 题：**B**

```python
for key in ("content_sha256", "base_model", "step"):
    if report.manifest.get(key) != expected.get(key):
        raise FinetuneEvalError(...)
```

三项各造一次不一致都抛 `FinetuneEvalError`；报告没有绑定清单
（`report.manifest is None`）时同样抛错——**一份对不上适配器的评估报告，
比没有报告更危险，因为它会被当成证据引用**。

A 错（`base_model` 与 `step` 同样核对：基座不匹配不会报错，只会给出莫名其妙的结果）；
C 错（只核对三项标识性字段，不做浮点相等——那会让报告因浮点噪声失败）；
D 错（是**硬门禁**，不是警告）。

## 第二部分：判断题

### 第 7 题：**错**

配对比较的前提是"同一份评估集、同一条用例"。跑在不同子集上时：

- 条数不同 → `compare_runs` 报"两臂的用例数不一致"；
- 条数恰好相同但内容不同 → 靠 `_align` 的逐条 id 校验拦下（"两臂的用例顺序不一致"）。

顺序也校验，因为报告的渲染是按顺序逐行输出的——允许乱序会让同一份数据渲染出
两种表格，而人眼对比表格时不会去核对每行的 id。管线的顺序因此被固定成
"先切分、再跑两臂"（`pipeline.run_finetune_evaluation`）。

### 第 8 题：**对**

这是**修复后**的行为。`char_ngrams` 在 `order > len(text)` 时返回空 `Counter`；
第一版把"某一侧取不到 gram"记成 `(0.0, 0.0)`，于是不存在的阶也进了宏平均的分母：

```text
修复前：chrf("中文测试", "中文测试", n=4) = 1.0
        chrf("中文测试", "中文测试", n=5) = 0.8
        chrf("中文测试", "中文测试", n=6) = 0.6667    ← 默认 n 就是 6
修复后：n = 4 / 5 / 6 全部 = 1.0
```

修法是"某一阶 n-gram **两侧都不存在**时跳过该阶"——这一阶量不到任何东西。
**"相同文本必须得满分"是任何相似度指标的第一条不变式**，测试里也把它钉住了。

### 第 9 题：**错**

合格是**四项的合取**：事实点全覆盖 + 无禁项命中 + 无格式违规 + 拒答行为与预期一致。
参考答案只满足事实点，仍可能因为缺格式片段、超长、命中禁项或拒答预期不符而失败。

本课的实例就在眼前：修 `ref-01` 之前，它的参考答案缺 `required_facts` 里的"拒绝"，
于是 `score_item(ref-01, ref-01.reference).passed == False`，
`failure_reason()` 是"缺事实点 拒绝"。**一个评估集如果连自己的参考答案都判不过，
它评的不是模型。**

### 第 10 题：**错**

两者的**分母差 1**：

- 训练时"答案的第一个 token"**被计分**，因为它的上下文是 prompt 的最后一个 token；
- 探针在只喂"答案 id"时从第二个 token 才开始计分（位置 0 没有前文）。

所以正确用法是**同口径对比**（微调前 vs 微调后都用探针），而不是把探针读数与
训练日志里的 loss 相减——两个数字的分子分母都不一样，相减得到的差没有含义。
这条更正落在了 `sequence_logprob` 的文档里（第一版文档就是这么写错的）。

### 第 11 题：**对**

`REFUSAL_MARKERS` 里有"不能 / 不会 / 不建议"，这些词在正常解释里也很常见
（"这个改动不会影响性能"）。第一版实现时考虑过上下文判别，但判别需要语义模型
（那是 M3-D6 红队评估的题目），于是保留了"保守清单 + 原文子串匹配"的口径，
**并把代价写进了文档**：真命中会让 `refusal` 分量打成 0。

这条取舍的一般形式：做不到精确时，**把"会误判"写下来，比偷偷用一个看起来
更聪明的启发式好**。

## 第四部分：简答题

### 第 14 题：四个"看起来没问题、实际是错的"

**共同点**：四个都不是算法问题、四个都能通过"代码看起来对不对"的人工检查，
而它们各自有一个**可以写成断言的不变式**。

#### （1）`chrf` 在文本短于 `n` 时把不存在的阶记成零重叠

- **表征**：`chrf(x, x) != 1.0`。默认 `n = 6` 时 `chrf("中文测试", "中文测试") = 0.6667`；
  `n = 4` 时恰好 `1.0`，所以"随手试一个例子"完全可能测不出来。
- **难发现**：分母（宏平均的阶数）是循环变量，而循环体里那两行
  `precisions.append(0.0)` 单看完全合理；只有在"文本比 n 短"时才触发，
  而本课的真实用例（最短 26 字）都长于 6。
- **守住的手段**：**对指标写不变式而不是写样例值**——
  `assert chrf(text, text) == 1.0` 对任意 `n`、任意长度都成立。
  这一条断言在测试里一次就抓出了它。

#### （2）`ref-01` 的参考答案不满足它自己的事实点

- **表征**：`score_item(ref-01, ref-01.reference).passed == False`，
  `failure_reason() == "缺事实点 拒绝"`。表现上只是"这条用例很难"。
- **难发现**：出题的人改了 `required_facts` 却忘了同步参考答案。18 条用例里
  只有 1 条有这个问题，而人眼 review 时读的是"题问得对不对"，不是
  "答案能不能过自己这道题"。
- **守住的手段**：`audit_references` 逐条检查四项（事实点 / 禁项 / 格式 / 拒答），
  外加**一条不变式测试**：

  ```python
  for item in SEED_ITEMS:
      assert score_item(item, item.reference).passed, f"{item.id}: {item.failure_reason()}"
  ```

  注意它是**由测试抓出来的，不是由团队 review 抓出来的**——这正是为什么
  "评估集自己也要被测"。

#### （3）`leakage_rate` 的分母取了"可疑配对数"

- **表征**：`threshold = 0.0` 时 `leakage_rate = 12.0`。一个名叫"率"却大于 1 的数字。
- **难发现**：默认阈值 0.5 下它恰好落在 `[0, 1]`（本课真实切分是 `0.0`），
  所以只有把阈值调到 0 才会暴露；而"阈值 0"看起来是个"更严格"的无害选项。
- **守住的手段**：① 改分母（**被可疑命中的评估条目数 / 评估条目数**），
  并顺手把 `leaked_eval_items` 也交出来（分母的分子都可见）；
  ② 加一条**单调护栏**断言：对 `threshold ∈ {0.0, 0.25, 0.5, 1.0}` 都断言
  `0.0 <= leakage_rate <= 1.0`，且等于 `len(leaked_eval_items) / len(evaluation)`。

#### （4）`EvalReport.passed` 与 `failed_gates()` 口径不一致

- **表征**：`gates = {"min_pass_rate": {"passed": True}, "mystery": {"passed": False}}` 时
  `passed is False` 而 `failed_gates() == []`，摘要打出一个**没有内容的括号**：
  `门禁 未通过（）`。空 `gates` 时同样。
- **难发现**：真实流水线里 `gates` 永远是三个键，所以这个状态在端到端跑时不会出现；
  它只在"有人手工组装报告"或"将来加了第四项门禁"时冒出来。
- **守住的手段**：让两个方法**对同一份 `gates` 给出一致的答案**——
  `failed_gates()` 在 `GATE_NAMES` 之外再列出额外的失败门禁，
  `summary_line()` 在没有失败名时明确写 `未设置门禁`。
  并补两条用例：一条断言额外门禁会被列出，一条断言空 `gates` 的摘要不含 `未通过（）`。

**四条经验的一般形式**：

1. **不变式 > 样例值**（第 1、2 条）；
2. **分母要对，且分母要能看见**（第 3 条）；
3. **同一份数据上的两个视图必须互相一致**（第 4 条）；
4. **边界配置（阈值 0、空集合、额外键）也是被测对象**。

### 第 15 题（三种统计口径一起跑）

```python
"""习题 15：三种统计口径一起跑（不构造模型）。"""

def outcome(item_id: str, passed: bool, score: float) -> ItemOutcome:
    """手工构造一条结果：合格时六个分量全 1，不合格时全 0."""
    return ItemOutcome(
        item_id=item_id,
        bucket="format",
        difficulty="normal",
        metric=MetricBreakdown(
            components={name: (1.0 if passed else 0.0) for name in COMPONENT_NAMES},
            total=score,
        ),
        passed=passed,
    )


BEFORE_SCORES = [0.9, 0.8, 0.7, 0.6, 0.5, 0.4, 0.3, 0.2, 0.1, 0.0]
AFTER_SCORES = [0.4, 0.85, 0.75, 0.65, 0.55, 0.5, 0.6, 0.7, 0.8, 0.9]

#: 前 5 条过；后 8 条过 —— 于是 b = {i00} 共 1 条、c = {i06..i09} 共 4 条
BEFORE_PASS = set(range(5))
AFTER_PASS = {1, 2, 3, 4, 6, 7, 8, 9}


def build_run(name: str, scores: list[float], passed: set[int]) -> EvalRun:
    return EvalRun(
        name=name,
        outcomes=[
            outcome(f"i{index:02d}", index in passed, scores[index]) for index in range(10)
        ],
    )


def main() -> None:
    before = build_run("before", BEFORE_SCORES, BEFORE_PASS)
    after = build_run("after", AFTER_SCORES, AFTER_PASS)
    report = compare_runs(before, after)

    print("① 完整比对")
    print("  合格率：", f"{report.before_pass_rate:.2%} → {report.after_pass_rate:.2%}")
    print("  mcnemar：", report.mcnemar.summary_line())
    print("  bootstrap：", json.dumps(report.bootstrap.to_dict(), ensure_ascii=False))
    print("  门禁：", "通过" if report.passed else f"未通过 {report.regressions}")

    print("② 两个入口是否一致")
    exact = mcnemar_exact(1, 4)
    two_sided = binomial_two_sided_p_value(1, 5)
    print(f"  mcnemar_exact(1, 4).p_value          = {exact.p_value}")
    print(f"  binomial_two_sided_p_value(1, 5)     = {two_sided}")
    print("  一致：", exact.p_value == two_sided)

    print("③ Wilson 区间")
    for successes in (1, 5, 10):
        low, high = wilson_interval(successes, 10)
        print(f"  wilson({successes}, 10) = [{low:.4f}, {high:.4f}]")

    print("④ 自助法的种子敏感性")
    for seed in (0, 1, 42):
        result = paired_bootstrap_delta(BEFORE_SCORES, AFTER_SCORES, seed=seed)
        print(
            f"  seed={seed:2d}: mean={result.mean_delta:+.4f} "
            f"区间=[{result.ci_low:+.4f}, {result.ci_high:+.4f}] "
            f"不含 0={result.excludes_zero}"
        )


if __name__ == "__main__":
    main()
```

```text
  seed= 0: mean=+0.2200 区间=[-0.0150, +0.4550] 不含 0=False
  seed= 1: mean=+0.2200 区间=[-0.0150, +0.4550] 不含 0=False
  seed=42: mean=+0.2200 区间=[+0.0050, +0.4551] 不含 0=True
```

**逐条解释**：

1. **`mcnemar_exact(1, 4)` 与 `binomial_two_sided_p_value(1, 5)` 必然一致**：
   前者内部就是 `binomial_two_sided_p_value(c, b + c)`。手算核对：
   `n = 5`、`tail = min(1, 4) = 1`、`Σ_{k≤1} C(5,k) = 1 + 5 = 6`，
   `p = 2 × 6 / 2⁵ = 12/32 = 0.375`。
2. **卡方是 `0.8`**（带连续性修正）：`(|1-4| - 1)² / 5 = 4/5 = 0.8`，
   它只作参考报出；判定用精确 `p = 0.375`（不显著）。
3. **`wilson(10, 10)` 不是 `[1.0, 1.0]`**：10 条全对时合格率的点估计是 1.0，
   但"真实合格率至少是多少"这件事在 10 条样本上无法确定——Wilson 给出
   `[0.7225, 1.0]`，即"可能低到 72%"。正态近似在这里会给出宽度 0 的区间，
   这正是本课拒绝它的理由。
4. **自助法的种子敏感性（本课最值得记的一条）**：
   - **量级与宽度不随种子变化**：三个种子的均值都是 `+0.2200`，
     区间宽度都是约 `0.47`，形状完全一致。这就是"换种子换区间"本身不可怕的原因——
     自助法抽的是同一批差值，种子只改变重采样的顺序。
   - **但 `excludes_zero` 会翻**：`seed = 42` 给的区间是 `[+0.0050, +0.4551]`（不含 0），
     而 `seed = 0/1` 给的是 `[-0.0150, +0.4550]`（含 0）。原因是这一点估计
     （`+0.22`）本来就贴着 0 的边界，`mean - 1.96·SE` 就在 0 附近过不去。
   - **结论**：`excludes_zero` 是"区间端点的布尔化"，**当端点贴着 0 时它会翻**。
     所以判据应当是"区间有多宽、点估计离 0 有多远"，而不是那一个布尔值；
     样本量足够（或效应足够大）时，任何种子都会给出同一个布尔值。
     这与本课第四章"6 条用例上的 +50% 不显著"是同一条教训的两个面。

**三点必须解释清楚的细节**：

1. **`epochs=2` 与教程里的 `epochs=10` 结果不同**：本脚本只用 24 步，
   训练集困惑度只从 `421.82` 降到 `418.18`（Δ 3.65）、评估集 `421.76 → 420.29`
   （Δ 1.47），泛化间隙 `2.17`。教程里 120 步的标定配置是 `140.79 / 290.49`、
   间隙 `149.76`。**同一个模型、同一份数据，步数差 5 倍，结论的强度差两个数量级**——
   这正是 day049 "先算预算，再谈结论"的意思。
2. **报告的 `run` 与 `comparison` 必须来自同一对运行**。本脚本里两者都取自
   **评估子集**上的那一次（`baseline` / `finetuned`），所以报告里的合格率
   `83.33%（5/6）` 与第 ③ 段逐条结果完全对得上。
   手工组装报告时最容易犯的错，就是拿"全量跑的那一次"当 `run`、
   拿"子集跑的那一对"当 `comparison`——两者的分母不同，报告就成了自相矛盾的证据。
   `pipeline.run_finetune_evaluation` 存在的主要理由就是把顺序钉死。
3. **同一个适配器可以配不同的报告**：本脚本的适配器在**训练子集**上训练
   （12 条），却在**评估子集**上评估（6 条）——这正是 `split_suite` 的意义。
   若把评估子集也拿去训练，`detect_leakage` 会在下一次体检时报出可疑对，
   而分数会"好看得可疑"。**训练与评估必须来自同一份切分**。

## 附：本课最值得带回工作现场的五句话

1. **一个评估集如果连自己的参考答案都判不过，它评的不是模型。**
   （`audit_references` + 一条不变式测试）
2. **"涨了 50%"与"统计上证明涨了"是两件事。**
   （`p = 0.25` vs 自助法区间不含 0）
3. **能被观察到的过拟合才是能被修掉的过拟合。**
   （泛化间隙：`149.76` 是正常，`573.24` 是背题）
4. **没有绑定信息的分数不是证据。**
   （适配器哈希 + 评估集指纹 + 三项门禁）
5. **边界配置也是被测对象。**
   （阈值 0、空集合、额外键、短文本——本课四个坑里有三个出在边界上）
