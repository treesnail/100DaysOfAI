## 一、选择题

**1. B。** 规则是「上游梯度 × 局部导数」（链式法则），纪律是「累加」（`+=`）。
第二条才是会把人绊倒的那条——写错它不报错，只给出一个偏小的梯度。

**2. C。** 在 `x = 3` 处：正确梯度 `x + x = 6`，用 `=` 只保留最后一条路径得到 `3`。
它不会抛任何异常（形状对、数值有限），只是偏小——而"梯度偏小"看起来像"学习率设小了"。

**3. B。** `gelu` 的导数第二项是 `x·e^{−x²/2}`。要看懂这句话，先看 `gelu` 的**输出**
`y = 0.5x(1 + erf(x/√2))`——从 `y` 反解 `x` 不是一件便宜的事（它是超越方程）。
所以逐元素反向的签名带的是 `pre_activation`，而 `sigmoid` / `tanh` 可以只用输出
（`σ(1−σ)`、`1−y²`）。

**4. B。** 取 0 之后，"关掉的神经元"在反向里**恰好**拿到 0——这不是"接近 0"，是 `0.0`。
本课把它做成一条可断言的结论（第 2 条性质），并且演示里那个一层反向表的第 0 行
`dW = (0.0, 0.0, 0.0)` 就是它的直接读数。

**5. B。**
```text
Σ_j J[i][j] = Σ_j p_i(δ_ij − p_j) = p_i·Σ_j(δ_ij − p_j) = p_i(1 − Σ_j p_j) = p_i·0 = 0
```
这是"平移不变"在导数上的样子：概率之和恒为 1 是**前向**的约束，
因此它的导数必须正交于全 1 方向。

**6. B。** `∂(−log p_k)/∂z = p − onehot(k)` 把雅可比"消掉"了。
危险之处正在这里：**正确的实现也不直接用它**，因此雅可比写错时这条梯度仍然是
`p − onehot`。所以本课把雅可比**单独**验一次（第 3 条性质）。

**7. B。** 手写反向 / 图自动微分 / 数值差分。三条互相独立：
第三条（day074 的 `calculus.gradient`）甚至不依赖任何推导。

## 二、简答题

**8.** 三种"不报错、只算错"的接线方式：

```text
① 用 = 代替 +=        现象：梯度偏小 ⇒ 看起来像"学习率设小了"
② 把常量写进梯度      现象：某个参数一直是初值 ⇒ 看起来像"这个参数不需要学"
③ 重复反向不清零      现象：梯度大 k 倍 ⇒ 看起来像"梯度爆炸 / 学习率设大了"
```

三者的共同点是**形状对、数值有限**——因此它们能通过所有"结构检查"，
只有把读数与一份独立来源比一次才会暴露。这一点也是 `ChainError` 独立成族的理由：
它要改的是接线方式，而不是某个公式。

**9.** 三样中间量各自的用处：

```text
Dense 的反向        用「这一层的**输入**」     dW = dYᵀ·X 里要乘 X
逐元素激活的反向     用「激活**前**的值」      gelu' 里有 x·e^{−x²/2}，输出里没有 x
softmax 的反向      用「激活**后**的值」      softmax 的输出就是它自己的概率 p
```

"反向时把前向重跑一遍"在**数学上等价**（同样的输入过同样的函数，得到同样的中间量）；
但在**工程上不行**：重跑需要参数，而参数在反向过程中正是我们要算的东西——
于是"一次反向"会变成"每走一层就重跑一次前向"，代价从 O(n) 变成 O(n²)，
而且**它会让反向与前向在参数上耦合**："这一步的梯度"可能对应的是"另一个参数的中间量"。
`ForwardCache` 把三样中间量留下来，反向就只读它、不碰参数。

**10.** 四条前提：

```text
① 同一组权重        直接用同一份 FFNWeights 的四块，不重新初始化
② 形状约定相同      w_in (d_ff, d)、w_out (d, d_ff)，前向 x·Wᵀ + b
③ 累加方式相同      都用 math.fsum，且乘法的顺序相同
④ 激活公式相同      relu = value if value > 0 else 0.0；gelu = 精确 erf 式
```

"换一个求和顺序"会怎样：`math.fsum` 与"普通累加"给出的**最后一位**可能不同。
这种破坏**很难被发现**，因为：

```text
它只影响最后几位   ⇒ 任何"容差 1e-9"的判据都会放行
它不改变形状与量级 ⇒ 梯度范数、损失曲线、训练效果**看起来完全正常**
```

于是唯一的发现方式是**要求逐位相等**（本课第 7 条性质就是这么做的）。
这也解释了为什么这一课的累加方式要"刻意与前馈生产实现相同"——
它不是"随手挑了一个更精确的求和"，而是为了那条对账。

**11.** 偏差的来源：`softmax_jacobian_vector_product` 的 `⟨p, v⟩` 用的
```text
math.fsum(p * v for p, v in zip(probabilities, vector))
```
而"显式矩阵乘"那一路是把 `J` 的每一列与 `v` 逐项乘再求和——
两条路径的**求和顺序与分组不同**，浮点加法不满足结合律，于是最后一位可能不同。
演示里的 `1.388e-17` 就是这个量级（约为 `eps · 1`）。

本课把判据写成"偏差 <= 1e-12"而不是"相等"，原因是**判据不能比测量手段更严**：

```text
1e-12 远高于浮点求和的最后一位误差量级（~1e-16 ~ 1e-17）⇒ 不会产出假警报
1e-12 远低于"真的写错了"的误差量级（通常 >= 1e-3）      ⇒ 仍有充足的区分度
```

如果把判据写成"逐位相等"，两个都正确的实现会因最后一位不同而被判为"不通过"——
**假警报比漏报更坏**，因为它会让人去改一份本来正确的代码。

**12.** 为什么不会报错：`softmax_jacobian` 的入参只是"一串数"，
它没有（也不该有）办法知道这串数是打分还是概率。用打分 `(1, 2, 3)` 得到的是

```text
J[0] = (0.0, -2.0, -3.0)          ← 一行和为 -5.0
```

而用概率 `p = softmax(1,2,3)` 得到的是

```text
J[0] = (0.0819, -0.0220, -0.0599) ← 一行和为 0
```

两者**形状一样、都是有限的数**，因此编译器不拦、类型检查不拦、
"非有限数"的护栏也不拦。

不靠"每行和为 0"这条判据，至少还有两条办法：

```text
① 对账：拿它去乘一个向量，与**数值雅可比**（day074 的 calculus.jacobian）逐点比
       —— 这正是第 3 条性质做的，代价是慢
② 断言输入确实是一个分布：Σ p_i ≈ 1 且每一项 >= 0
       —— 在 softmax_jacobian 入口加一条"这串数必须是概率"的护栏，
          把"传错了"从"静默算错"变成"当场报错"（本课没有加，因为它的定位是"被对照"）
```

还有第三条更便宜的：**让那个读数自己说话**。本课把"每一行之和"印在表里，
它本来就是一个"如果输入是概率就必然为 0"的量——只要有人看一眼。

## 三、诊断题

**13.** 错在下标的**方向**：

```text
正确   dW[j][k] = Σ_i dY[i][j]·X[i][k]      dW 形状 (out, in)
这份   dW[j][k] = Σ_i X[i][j]·dY[i][k]      dW 形状 (in, out)
```

也就是说，它算出来的是 `Xᵀ·dY`，而正确的量是 `dYᵀ·X`。

**为什么在 `in == out` 时形状对**：`Xᵀ·dY` 的形状是 `(in, out)`，
`dYᵀ·X` 的形状是 `(out, in)`——只有当 `in == out` 时两者才是同一个形状。
因此它在方阵层上**不会被任何形状护栏拦住**。

**没有数值对照时会表现成什么**：训练**仍然会动**（因为梯度方向"大致"还是相关的），
只是收敛明显变慢、或在某些任务上直接不收敛。它看起来像：

```text
"这一层的学习率是不是要单独调一下"
"初始化是不是不好"
```

**归哪一族**：`GradientError`（改推导）。它不是形状问题（形状对）、
不是调用问题（调用完全合法），而是**解析式算错了**。

## 四、推导题

**16.（推导）softmax 的 JVP 恒等式**

```text
已知  J[i][j] = p_i(δ_ij − p_j)，且 Σ_k p_k = 1

(Jᵀv)_i = Σ_j J[j][i]·v_j                     （按定义：Jᵀ 的第 i 行是 J 的第 i 列）
        = Σ_j p_j(δ_ji − p_i)·v_j             （代入 J[j][i] = p_j(δ_ji − p_i)）
        = Σ_j p_j·δ_ji·v_j − Σ_j p_j·p_i·v_j  （拆成两项）
        = p_i·v_i − p_i·Σ_j p_j·v_j           （第一项只剩 j = i；第二项把 p_i 提出来）
        = p_i(v_i − ⟨p, v⟩)                   （把 Σ_j p_j v_j 记作 ⟨p, v⟩）∎
```

**中间量**：显式路径要建 `n×n` 的 `J`（n² 个中间量）再乘 `v`；
这条恒等式只需要 `⟨p, v⟩`（一次 O(n) 的内积）与一次逐元素乘（n 个），
合计 **O(n)**。

**"每一行和为 0"能不能直接看出来**：能。把 `v = 1`（全 1 向量）代入最后一式：

```text
(Jᵀ1)_i = p_i(1 − ⟨p, 1⟩) = p_i(1 − Σ_j p_j) = p_i·0 = 0
```

而 `(Jᵀ1)_i` 恰好就是 `J` 第 `i` 行的和。这一步值得单独写下来：
它把"行和为 0"从"算出来才知道"变成"代入就能看出来"。

**17.（推导）一层全连接的反向**

前向（逐行）：`Y[i][j] = Σ_k X[i][k]·W[j][k] + b[j]`。

```text
（甲）∂L/∂W
  L 通过所有的 Y[i][j] 依赖 W[j][k]，因此
    ∂L/∂W[j][k] = Σ_i ∂L/∂Y[i][j] · ∂Y[i][j]/∂W[j][k]
                = Σ_i dY[i][j] · X[i][k]
  求和的指标是 **i（样本维）** ⇒ 形状 (out, in)，即 dYᵀ·X

（乙）∂L/∂b
  ∂Y[i][j]/∂b[j] = 1（b[j] 被所有行共用）
    ∂L/∂b[j] = Σ_i dY[i][j] · 1
  求和的指标是 **i（样本维）** ⇒ 形状 (out,)，即"按行求和"

（丙）∂L/∂X
  L 通过所有的 Y[r][j] 依赖 X[i][k]，只有当 r = i 时 ∂Y[r][j]/∂X[i][k] ≠ 0
    ∂L/∂X[i][k] = Σ_j ∂L/∂Y[i][j] · ∂Y[i][j]/∂X[i][k]
                = Σ_j dY[i][j] · W[j][k]
  求和的指标是 **j（输出维）** ⇒ 形状 (rows, in)，即 dY·W
```

**"按 W 的行收"为什么形状仍然对**：写成 `Σ_j dY[i][j]·W[k][j]` 会索引
`W[k][j]`（k < in、j < out），这在 `in ≠ out` 时会越界；而真正危险的那种写法
是把求和换到另一个指标上，得到的仍是 `(rows, in)` 形状的矩阵——
**形状对、数值错**，只有数值对照能发现。

**18.（推导）从"两条路径"到 `GradientError`**

```text
（甲）为什么"两份独立实现"更有说服力？
  "一份实现对着一把尺子"只能排除"这一份单独错"，不能排除"两边一起错"：
  尺子若被同一个误解污染（例如两边都用了同一个（错误）形状约定），
  对照会通过，而结果是错的。
  两份**独立写下**的实现（layers.dense_backward 的三段循环 vs graph.dense 的三段式）
  要同时错且错成同一个数，需要一个巧合——因此对上的信息量更大。
  本课的做法是"两条腿走路"：既有 A vs B（互相独立），也有 A vs C（不依赖推导）。

（乙）为什么还需要第三把尺子？
  因为 A 与 B 仍然**共享约定**：同一组形状、同一批算子、同一个 relu 定义。
  如果"约定"本身错了（例如把 softmax 的入参当成概率实际上该是 logits），
  A 与 B 会**一起错**。而 C（数值差分）从函数值出发，不经过任何我们的推导——
  它是唯一能发现"约定整体错了"的那条路径。
  代价是：C 慢（2n 次函数求值）、只到 1e-9、且对不可导点无定义。

（丙）什么条件下不一致？抛哪一族？
  只要"两条路径里的任一条写错了"就不一致。本课把这件事定义成一个**控制流事件**：
    raise GradientError(...)
  为什么它是控制流而不是报告？
    一份对不上的梯度意味着**这次训练从头到尾都不可信**——继续跑下去只会得到
    一个"损失确实在下降"的模型，而它可能正在往一个错误的方向走。
    day073 的 math_foundations 把"梯度对不上"记成一个**对照结论**（报告），
    因为它不改变控制流；day075 分出 GradientError 那一族是为了让调用方**当场停下**；
    而直到 day090，"两条独立路径"这件事才第一次真的发生——
    因此这一族在连续缺席八天之后，今天第一次被抛出。
```
