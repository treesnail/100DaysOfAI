## 第一部分：选择题

### 第 1 题（窗口纪律：只对前 N 条打分）

关于"只对前 N 条打分"这条纪律与它的实测表现，下面哪一句是**对的**？

- A. 全库重排才准，只排前 N 条是偷工减料：窗口只是本课为了把演示脚本跑快而设的折中；真实系统里 `top_n` 应当设成候选总数（本机 12 条候选、`top_n=20` 时窗口覆盖 12 条，这就是"该有的样子"）
- B. 窗口外的条被打了很低的分：`top_n=5` 时窗口外那 7 条的 `score` 是 `0.0`，说明重排器认为它们"最不相关"，只是没有低到被 `min_score` 切掉而已
- C. **`top_n` 是一次有边界的改进，好消息与坏消息都必须写出来：好消息是成本从 O(候选) 降到 O(N)（交叉编码器每对一次前向推理），坏消息是第 N+1 条永远没有机会证明自己、它的名次只由第一阶段决定——而坏消息那一半无条件进 `notes`。实测（12 条候选）：`top_n=5` 时窗口 = 输入的前 5 条 `['d-11','d-01','d-04','d-02','d-03']`、打分了 5 条、没打分 7 条 `['d-12','d-05','d-06','d-07','d-08','d-09','d-10']`，账是 `candidates=12 / scored=5 / window=5`，重排器计数器差量 `calls +1 / scored_pairs +5 / batches +1`；`scored_pairs` 的差量恰好等于 `window`——这正是"窗口循环没有被写成'全量打分再切前 N 条'"的可断言形态**
- D. `top_n=0` 就是关掉重排：把窗口设成 0 等价于"这一次不重排"，两条路径的结果逐位相同，因此关重排有"设 `top_n=0`"与"设 `rerank_enabled=False`"两种等价写法

### 第 2 题（四个特征、权重与分数的可手算性）

关于教学级替身 `cross-encoder-teaching-v1` 的打分方式，下面哪一句是**对的**？

- A. 替身的重排分可以当成"相关性"读：分数落在 `[0, 1]`，`0.916667` 与 `0.125000` 之间的差距就是相关性的差距；`dimension` 返回 4 是因为真实交叉编码器也输出四个相关性维度
- B. **分数 = 四个可手算特征的加权和，而权重 `(0.5, 0.25, 0.125, 0.125)` 的和逐位等于 1.0：`0.5 = 2⁻¹`、`0.25 = 2⁻²`、`0.125 = 2⁻³` 都是二进制精确可表示的数，因此构造期可以用 `math.fsum(...) != 1.0` 这样的精确比较校验，不必引入 epsilon（一个凭空取出的 tolerance 会变成第三个需要标定的参数）；这条不变量同时保证"分数落在 `[0, 1]`"，而 `min_score` 的可标定性正建立在这上面——具体到数字：查询 `'ERR-2043'` 的词元是 `['err','2043']`，`d-11` 的正文 40 字、含整串且两词元紧挨 → 覆盖 1.0、整句 1.0、邻近 `1/(1+2)=1/3`、长度 `min(1.0,240/40)=1.0` → `0.5+0.25+1/24+0.125 = 11/12 = 0.916667`（手算 = 引擎，逐位一致）；`d-12` 正文 336 字 → 长度项 `240/336 = 0.714286`，分数从 11/12 降到 `0.880952`；`d-01` 一个编号都不含 → `0.125000`（只剩长度项），而它在第一阶段是第 1 名**
- C. 权重要取"三项均分"才公平：`(1/3, 1/3, 1/3)` 这样的权重比 `(0.5, 0.25, 0.125, 0.125)` 更中立，只是本课为了突出覆盖率才写成偏向 0.5
- D. 长度惩罚应该做成硬规则：`length_penalty` 只占 1/8 太弱了，长于 `IDEAL_LEN = 240` 的文档应当直接扔掉，这样"冗长偏好"才被真正对冲掉

### 第 3 题（两种模式、量纲与排序键）

关于 `replace` / `blend` 两种模式与排序确定性，下面哪一句是**对的**？

- A. `blend` 就是把两份分数加起来取平均：`0.5 × 重排分 + 0.5 × 第一阶段分数`，不需要归一化——两个数都是浮点数，相加在数学上没问题
- B. 归一化之后的分数是绝对量，可以直接存进库里跨查询比较：它是"这条到底有多相关"的另一个说法，因此 `blended` 值应当在报告里与 `rerank_score` 并列展示
- C. 两份分数**量纲不可比**（第一阶段是余弦 ∈ [-1,1] / BM25 ∈ [0,∞) / RRF 之和 ~0.03 / weighted 融合分，而重排分落在 [0,1]），因此 `blend` 必须**各自**在窗口内 min-max 归一化再加权，并复用 `fusion._min_max_normalize`（同一条纪律只写一份实现）；实测窗口 `top_n=6`、`weight=0.5` 时"阶段一 min=0.360000 / max=1.000000、重排分 min=0.125000 / max=0.916667"，`d-12` 手算 `0.5×0.954887 + 0.5×0.000000 = 0.477444` 与引擎逐位一致；代价是归一化只在**这一次窗口内**做，因此 `d-12` 的 `blended` 从 `top_n=6` 的 `0.477444` 变成 `top_n=8` 的 `0.657444`（差 `+0.180000`）——**这是相对量的固有性质，不是实现缺陷**；`min == max` 时定义为 **1.0**（不是除零、不是 0）
- D. 并列时由 `record_id` 说算：语料里 `d-05` 与 `d-11` 的重排分逐位相同（`0.9166666666666666`），最终 `d-05` 排在 `d-11` 前面，因为 `d-05 < d-11`——第三排序键就是为这件事准备的

### 第 4 题（阈值与第四道减法）

关于重排阈值 `min_score` 与它的记账，下面哪一句是**对的**？

- A. `min_score` 会把不相关的尾部也切掉：给一个够高的阈值（如 2.0）就能把窗口外的条一并清掉，这正是"设一个高阈值换一份干净名单"的用法
- B. 阈值切光窗口就等于空结果：`top_n=5`、`min_score=2.0` 时窗口内 0 条留下、结果命中 7 条这件事说明窗口外的条被 `min_score` "救"了回来，而 `empty_reason` 此时一定是 `below_threshold`
- C. 重排阈值切掉的条数应当并进 `dropped_by_top_k`：两者都是"截断"，合成一个数更方便读；`RetrievalResult` 上多一个 `dropped_by_rerank` 只会让报告变长
- D. **`min_score` 比的是重排分，而且只作用于 `scored=True` 的那一批（窗口外连分数都没有 → 既不会被它切、也不会被它救）：实测 `top_n=5`、`min_score=2.0` 时窗口 5 条 → 留下 0 条、切掉 5 条，而窗口外的 7 条 `['d-12','d-05','d-06','d-07','d-08','d-09','d-10']` 一条都没被切 → 结果命中 7 条、`empty_reason` 是空串（"切光窗口"与"空结果"是两件事）；只有 `top_n=20`、`min_score=2.0`（窗口覆盖全部 12 条、没有尾部）才是真的空结果，`empty_reason` 给出唯一成因；切掉的条数记在第四道减法 `dropped_by_rerank` 里（对应旋钮 `retrieval_rerank_min_score`），它不并进 `dropped_by_top_k`——"同一个数字有两种来源，等于两种来源都没有"；窗口被切完时 `empty_reason` 沿用已有的 `below_threshold`（不新增第六个取值，端点协议不动）**

### 第 5 题（三条指标与 `measure_lift`）

关于 `recall@k` / `RR` / `nDCG@k` 与 `measure_lift`，下面哪一句是**对的**？

- A. `lift` 应当用**比值**：`after / before` 才能表达"提升了几倍"，差值只说明绝对变化，可比性更差
- B. 三条指标里 `recall@k` 就够了：它同时看"命中几条"与"排得多靠前"，另外两条是冗余的
- C. **三条指标的公式与三个口径细节都是钉死的：`recall@k = |前 k 条 ∩ 金标准| / |去重后的金标准|`（分母是去重后的条数）、`RR = 1 / (第一个相关命中的位置 + 1)`（无则 `0.0`）、`nDCG@k = DCG@k / IDCG@k`，其中 `DCG@k = Σ_{i=0}^{k-1} rel_i / log2(i+2)` 是二值增益（重复 id 只有首次出现记增益）、`IDCG@k` 的求和上限是 `min(|金标准|, k)`（金标准 2 条而 `k=5` 时理想名单只填得进 2 个位置）。手算与引擎逐位一致的一组：`ids=['r-t-01','r-t-04','r-t-02','r-t-03','r-t-05']`、`relevant=['r-t-06','r-t-05']` → `DCG@5 = 1/log2(6) = 0.386853`、`IDCG@5 = 1/log2(2) + 1/log2(3) = 1.630930`，于是 `recall@5 = 1/2 = 0.5`、`RR = 1/(4+1) = 0.2`、`nDCG@5 = 0.386853/1.630930 = 0.237198`。而 `measure_lift` 对每条探针只检索一次（`before` 用 `result.ids()`，`after` 用同一批 `result.hits` 重排），因此 before/after 只差"有没有重排"这一个变量——用一个会计数的假检索器，5 条探针就是 `retrieve` 恰好 5 次；`lift` 必须逐位等于 `after − before`；并且`lift` 全为 0 的探针也必须原样报出来（"重排在第一阶段已经排对的地方不会凭空加分"）**
- D. 三条指标都以"分数的绝对值"为输入：如果换成真实重排模型（分数分布不一样），三条指标就会变，因此教学替身跑出来的提升报告不能说明任何问题

### 第 6 题

重排开启后"`score` 越大越靠前"这条不变量不再成立（实测单路名单的 `score` 序列
`[0.48, 0.0, 0.36, 1.0, 0.96]` 不再单调），因此正确的修法是把重排分**写回**
`RetrievalHit.score`，让名单重新单调——否则报告里会出现"分数更小的排在上面"这种
自相矛盾的读法。（对 / 错）

### 第 7 题

重排必须插在多样性裁剪**之前**（单路第 6.5 步：阈值之后、多样性之前；混合第 10.5 步：
融合之后、多样性之前）：因为多样性按 `doc_id` 把同一文档的第 2、3… 条丢掉，若先裁后重排，
被丢掉的候选**再也回不到重排器眼前**；代价是重排**改变了"哪几条会被多样性命中"**——
同一份语料、`max_per_doc=1`、只翻重排开关，`doc-window` 那一组留下的成员就从 `r-t-06`
翻成 `r-t-08`（这不是 bug，而是"重排的结论被尊重"的必然结果）。（对 / 错）

### 第 8 题

逐次覆盖的键名清单 `RERANK_OVERRIDE_KEYS = ("enabled", "mode", "model", "top_n", "weight")`
是一份封闭清单：因为阈值也是重排的一个参数，所以 `min_score` 同样能由
`RetrievalQuery.extra` 逐次覆盖；而清单之外的键（例如把 `mode` 拼成 `mod`）最多是"不生效"，
不会报错；此外 `enabled=False` 时 `extra` 里那些键照样会被应用到这次重排上，只是不写进
`notes` 而已。（对 / 错）
