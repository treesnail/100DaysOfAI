## 一、基础

### 1. 三处差别

```text
① 自注意力的掩码    全开（双向） / 因果（只看过去） / 编码器全开 + 解码器因果
② 有没有第二路      无 / 无 / 有（Q 来自解码器、K/V 来自编码器）
③ 训练目标          MLM / CLM / 去噪（文本到文本）
```

前两处是**结构**，第三处解释了前两处为什么这么选：MLM 要"用左右两边一起预测"，
所以必须双向；CLM 要"预测下一个"，所以必须因果（否则答案就在输入里）；
去噪的源侧被破坏、目标侧完整生成，所以源侧双向、目标侧因果。
代码里它们是 `types.VARIANT_MASKS` / `VARIANT_OBJECTIVES` 两张表
（`study.objectives_table()` 直接把两行拼成教程第 1 章那张表）。

### 2. "同一个块"

`decoder_only` 用的是**同一个** `encoder_block`，只把掩码换成因果的那一张：

```python
# stacks._replay（单流变体这一条路径）
attention = self_attention(attentions[index], normed, mask=stream_mask)   # ← 唯一的差别
block = encoder_block(block_params, current, attention, placement=..., activation=...)
```

于是"因果"不是一条新的代码路径，而是一张掩码。第 6 章的前缀稳定性表
（GPT 只有最后一行变、BERT 四行全变）是这句话的实验版。

### 3. 参数量

```text
encoder_only     1458（解析 1458）
decoder_only     1458（解析 1458）
encoder_decoder  3384（解析 3384）
```

`encoder_only` 与 `decoder_only` 相同，是因为**因果与否不改变参数量**——
掩码不进参数，它只改变"能看到什么"。这条对照被测试钉住：

```python
def test_encoder_and_decoder_only_have_the_same_parameter_count() -> None: ...
```

### 4. 五项解析式（`d = 6`、`f = 24`）

```text
块           2·d·f + f + d + 4·d    = 288 + 24 + 6 + 24 = 342
自注意力      4·d²                   = 144
交叉注意力    4·d²                   = 144
解码器前馈    2·d·f + f + d          = 318
解码器 LN     6·d（三个 LN 各 γ/β）  = 36
```

用它拼出三个变体：

```text
encoder_only     3 × (342 + 144)                              = 1458
decoder_only     同上                                          = 1458
encoder_decoder  3 × (342 + 144) + 3 × (144 + 144 + 318 + 36) = 1458 + 1926 = 3384
```

### 5. 位置对与比值

```text
full     n² = 16
causal   n(n+1)/2 = 10
比值     10/16 = 0.625
```

`n` 增长时比值 = `(n+1)/(2n) → 1/2`。`n = 64` 时是 `0.5078`——
这就是"BERT 与 GPT 的差别在长序列上更贵"的数字基础。

### 6. 熵天花板

```text
full     (1/n)·Σ ln(n) = ln 4 = 1.386294
causal   (1/n)·Σ ln(i+1), i = 0..3 = 0.794513
```

记下它的理由：**注意力熵有一条天花板**，而天花板被掩码压低了。
因果掩码下第 0 行只能看到自己，熵的上限是 `ln 1 = 0`——
因此"注意力很尖"这件事在因果变体上**有一部分是掩码造成的**，不是模型学出来的。
这是 day083 里"熵要跟天花板比"那条纪律的来源（`mask_entropy_ceiling`）。

## 二、掩码与组装

### 7. `or (i == j)` 解决什么

它解决"**某一行的允许位置为空**"这个会让分布没有定义的问题。
不加它时，`pads = (True, True, True, True)`（整条序列都是填充）会让每一行都被拒绝：

```text
day075 的 masked_softmax_rows   →  raise NumericError("第 i 行没有任何允许的位置")
```

加了对角线之后，**每一行至少有一个允许的位置**，于是"这一行的分布"总有定义。
测试把它钉成一条行为：

```python
assert mask_allowed_counts(padding_mask((True, True, True))) == (1, 1, 1)
```

### 8. 第 ③ 条为什么刻意不处理

因为把填充行与其他人**彻底隔离**需要"按行按列同时判"（`(not pads[i] or i == j) and
(not pads[j] or i == j)`），而它换来的只是"噪声更小"。真正该做的是在**池化与损失里
把那一行丢掉**——因为一个填充行的输出是"它自己那一点噪声"，没有任何意义。
本课因此选择"把这件事说清"而不是"多加一层条件"：

```python
mask = padding_mask((True, True, False))
assert mask_allowed_counts(mask) == (2, 2, 1)   # 填充行看得见两个非填充位置与自己
```

### 9. `mask_is_causal` 的两条判据与两个好处

```text
① allowed(i, j) ⇒ j <= i          （不许有"看未来"的格子）
② mask[0][0] 为 True              （第 0 行至少能看到自己）
```

两个好处：

```text
① 它可以被用在**三个地方**：显式掩码、组合掩码（因果 ∧ 填充）、以及实测依赖表
   （实测那张表是浮点读数，因此 probe 里用的是它的阈值版判据 causal_verdict）
② 它不依赖调用方的意图 —— "这张表是不是因果的"与"调用时写了什么参数"无关，
   于是"掩码传错了流"这件事也能被它发现
```

### 10. 长方形掩码调用 `mask_is_causal`

会抛 `ShapeError`：

```text
因果性是**同一段序列内部**的性质（位置 i 不许看 i 之后），
因此它只对 (n, n) 的方阵有定义；收到 (4, 5)——一张长方形的表要么是交叉注意力
（它不该有掩码），要么是把两路的长度搞混了。
```

这个拒绝是对的：交叉注意力面对的是"另一路已经编码好的序列"，它没有"未来"可言。
所以"能不能问'它因果吗'"这件事本身就已经把两路区分开了。

### 11. 交集清空一行的例子

```python
combine_masks(((True, False),), ((False, True),))   # ⇒ (False, False)，第 0 行被清空
```

两张输入各自合法（都有一行、且那一行有允许的位置），而交集什么都没有。
第一版直接把结果返回，于是这个错误会一路传到 `masked_softmax_rows` 才炸——
而那时报错信息与"哪两张掩码组合出的问题"已经隔了很远。修法是在组合处就挡住：

```python
return _checked_mask(first)      # 交集也可能把某一行清空 ⇒ 在这里当场拒绝
```

### 12. T5 为什么不能接受 `pads`

两条接口事实：

```text
① day079 的 decoder_block  要求 self_attention_forward.causal 为真
② day075 的 resolve_mask   拒绝 causal=True 与显式掩码同时给
                            （"两个来源同时生效时到底用哪张要读代码才知道"）
```

两条加起来 ⇒ 本课的 T5 解码器**不能**同时满足"因果"与"显式填充掩码"。
于是在 `mask_for_streams` 里直接拒绝 `pads`。

静默忽略的后果是最坏的一类：**它不会以任何异常的形式露面**——
填充掩码被丢掉之后，前向照跑、形状一模一样、读数只是略有不同
（与 day081 第 10.2 节"漏传 placement"是同一类失败）。

### 13. 为什么检查 `isinstance(value, bool)`

因为"填充是一张**表**"，而不是一个可以随便填的数。`pads = (0, 1, 0, 0)` 用
`if value` 会被放过去（`1` 是真值），而它其实是"有人把 True/False 写成了 1/0"——
这种输入在 JSON 里非常常见，读起来却像"填充标记"。测试：

```python
with pytest.raises(ParameterError):
    padding_mask((False, 1, False))
```

## 三、实测依赖表

### 14. 三步与可信度

```text
① 记下基线：forward(inputs).output
② 逐列扰动：把第 j 行整体乘 1.5（**只改一行**），重新前向一次
③ 逐行取差：D[i][j] = max_c |out_i(after) − out_i(before)|_c
```

它比"读 `causal=True`"可信，因为它跑的是**真实的那条代码路径**，
因此三类失败都会被它抓住：掩码传错了流、掩码算对了但没传进去、
反向没把掩码穿过去（前向正确的那种）。而"读代码"只能确认作者的意图。

### 15. 三个变体的可达位置

```text
encoder_only                (4, 4, 4, 4)          对应全开掩码（每行 4 个）
decoder_only                (1, 2, 3, 4)          对应因果掩码（第 i 行 i+1 个）
encoder_decoder（主流）      (1, 2, 3, 4)          对应因果掩码
encoder_decoder（编码器流）  (5, 5, 5, 5, 5)       对应全开（源序列 5 个位置）
encoder_decoder（交叉那一路）(5, 5, 5, 5)          **长方形 4×5，掩码全开**
```

### 16. 为什么是"恰好 0.0"

`masked_softmax_rows` 的实现是：**只在允许的位置上**取出打分做 softmax，
再把 0 插回被屏蔽的位置：

```python
allowed = [scores[row][column] for column in range(columns) if mask[row][column]]
probabilities = iter(softmax(allowed))
result.append(tuple(next(probabilities) if mask[row][column] else 0.0 ...))
```

因此被屏蔽的那些打分**从来没有被 exp / sum / 加权三步碰过**——改它不会改变
任何一个中间量，输出的每一个浮点都逐位相同。

"逐位"比"容差"强在：**容差有一个无分辨力的区间**。如果判据写成 `Δ < 1e-12`，
那么"掩码少挡了一个位置、但那个位置的权重是 1e-13"就会被放过去；
而 `== 0.0` 没有这个区间。代价是：它只对这种"显式置零"的实现成立——
因此本课把理由（第 4.3 节）与实现（`masked_softmax_rows` 只在允许位置上做 softmax）
一起写在文档里。

### 17. 只用 `blocked_gap` 的假通过

`blocked_gap` 只在"被挡掉的格子"上取值。所以一张**把一切都挡住**的掩码
（比如全 False 的对角阵，或者被错误地清空的行）会让 `blocked_gap == 0.0` 成立，
而实际上什么都没学到。例：

```text
mask = ((True, False), (True, True))
matrix = ((1.0, 0.0), (0.0, 0.0))     ← 允许的 (1,1) 也是 0（"该动没动"）
blocked_gap = 0.0    ⇒ 只看它会判"通过"
allowed_floor = 0.0  ⇒ 这一条会亮红
```

因此两个读数一起给：`blocked_gap` 管"不该看到的没看到"，
`allowed_floor` 管"该看到的确实看到了"。

### 18. 交叉那一路与 day079 的拒绝

它们互为正面/反面：

```text
day079 的拒绝   交叉注意力**不能**被赋因果掩码（加了会悄悄删掉源序列的后半段）
今天的读数      交叉那一路的实测表**一格 0 都没有**（4×5 全正）
```

两者是同一件事的两种说法：**不加掩码 ⇒ 每个解码位置都覆盖整段源序列**。
而这条性质与"自注意力因果"在**同一个解码器块**里同时成立——
这正是 T5 那个块"两条路各自守各自规矩"的样子（`cross_spans_all_sources`）。

### 19. 为什么拒绝 `factor = 1.0`

因为扰动为 0 时，`D[i][j]` 全是 0——而"所有格子都不依赖"会让
**每一条判据都通过**：

```text
blocked_gap = 0.0     ⇒ 第 1 条通过
measured_mask 全 False ⇒ 它恰好等于"一个把一切都挡住的掩码"
```

也就是说：**一张什么都没量的表，与一张"掩码把一切都挡住"的表长得一模一样**。
拒掉这个值让"没有分辨力的实验"无法被写成一次"成功"。

## 四、四张表

### 20. 两行反证的读数

```text
反证一：decoder_only 用全开掩码     越界 6 · 缺失 0
      含义：**未来被看到了**（6 个 j > i 的格子有依赖）——这是安全漏洞
反证二：encoder_only 用因果掩码     越界 0 · 缺失 6
      含义：**双向能力被砍掉**（6 个 j > i 的格子没有依赖）——这是性能损失
```

两行合起来说明：**同一个判据在两个方向上都会亮红**，而两个方向的错是不同的病。

### 21. 为什么用字段

因为"这一行该不该一致"是一个**可被断言**的性质，而不是一句注释。加字段之前，
`ok` 会把反证行一起算进去：

```text
反证生效时   ok = False（因为反证行"不一致"）      ← 看起来像失败
反证失效时   ok = True （因为反证行"一致"）        ← 看起来像成功，而它是最坏的情况
```

加字段之后：

```python
@property
def ok(self) -> bool:
    return all(row.consistent for row in self.normal_rows) and all(
        not row.consistent for row in self.counterexample_rows
    )
```

于是"反证失效"会**明确**表现为 `ok == False`。

### 22. 前缀稳定性为什么用"变了的行"

因为"哪几行动了"这个读数**直接就是因果性**，而标量会把它抹掉。
三个变体（扰动位置 3）：

```text
encoder_only     变了的行 (0, 1, 2, 3)（4 行）   第 0 行的变化 2.869378e-02
decoder_only     变了的行 (3,)（1 行）           第 0 行的变化 0.000000e+00
encoder_decoder  变了的行 (3,)（1 行）           第 0 行的变化 0.000000e+00
```

如果只印"最大变化"，三个变体都会给出一个正数（第 3 行本身总是会变），
于是**看不出差别**。

### 23. 两条路径对照挡住什么

它挡住的是"**忘了数某一类参数**"这种不会报错的错误。具体例子：
如果 `census_of` 漏掉了交叉注意力那 144 个参数，那么报告会给出
`3384 − 3 × 144 = 2952`，而前向照样跑（参数在 `params` 里，只是没被数进去）——
于是"参数量"这个读数会**永久偏低**，而没有任何异常。

它与 day080 的"解析参数量 == 逐块数出来的参数量"同源：

```python
def census_of(params): ...      # 公式算 + 逐个数，两条路径必须相等
```

### 24. 只量"越界"会漏掉什么

会漏掉"**该看到的没看到**"——也就是"双向能力被砍掉"那一类失败。
例：

```text
给 encoder_only 一串因果掩码：
  越界 = 0（因果掩码不会让你看到未来）
  缺失 = 6（j > i 的格子本该有依赖，实测是 0）
```

只量越界时这张表会全绿——而它恰恰是"把 BERT 写成了 GPT"的失败。

## 五、性质与判据

### 25. 两条不适用与 `applicable`

`encoder_only` 上"不适用"的两条是：

```text
decoder_reads_only_past      它没有解码器那一流
cross_spans_all_sources      它没有交叉注意力
```

不加 `applicable` 字段的后果：**"把这条检查删掉"与"它通过了"在报告里长得一样**。
而报告的存在意义就是"读者能判断这些读数是不是应该长这样"。
所以本课把它做成一条构造期的拒绝：

```python
if not self.applicable and self.passed:
    raise NumericError("标了'不适用'却又标了'通过'：两者必须分开")
```

### 26. 拿"它自己那张掩码"当期望

第一版：

```python
passed = report.matches_mask       # 实测 == 本次前向**自己用的**那张掩码
```

根因：`report.mask` 就是这次前向实际用的掩码，于是"实测与它一致"**永远成立**——
判据退化成"前向是确定性的"。修法是让判据自己造期望（不读 `report.mask`）：

```python
def _matches_expected(report, expected) -> bool:
    measured = report.measured_mask
    return all(measured[row][column] == expected[row][column] for ...)

# 第 3 条：expected = mask_of(MASK_FULL, report.columns)
```

测试钉住它：

```python
def test_reads_every_position_fails_on_a_causal_mask() -> None:
    report = dependency_matrix(params_encoder, inputs, mask_kind="causal")
    assert not check_reads_every_position(params_encoder, report).passed
```

### 27. 为什么如实印出那个 0

因为那 0 **本身就是一条读数**：它说明"全开掩码下被掩掉的位置是 0 个，
因此这一条性质在 `encoder_only` 上**没有东西可查**"。
把它印出来，读者能自己判断"这条通过是不是有信息量"；
而把它藏起来（比如只在有格子时才印证据）会让"通过"看起来比实际更强。

同一条纪律在前几天出现过：day079 把 `eps` 印出来、day081 把 `kept_fraction` 印出来——
**读者要能自己判断那个数是不是应该长这样**。

### 28. 为什么放在整条变体上

day075 验过注意力的七步、day079 验过块的九块参数与解码器的九阶段，
但它们各自的被测函数都**只在一个流、一张掩码**上。今天新出现的两处接线风险是：

```text
① 掩码有没有被穿进反向
   前向因果、反向把未来位置的梯度也算上 ⇒ 前向完全正确（第 4.1 节第 ③ 类）
② 两条流的梯度有没有接上
   dEncoder 要**累加**（不是被最后一层覆盖），之后还要**穿过整条编码器链**
   才回到源序列的输入上；漏掉那一段时形状完全合法
```

因此判据是"整条变体上 dLoss/d输入 vs 中心差分"，两条流各比一次
（`main` 与 `source`，后者只在 `encoder_decoder` 上存在）。

## 六、工程与取舍

### 29. 把 264 拆开

```text
① 词嵌入 32 × 6 = 192                       （PyTorch 有 embedding，本包的前向直接吃 (n, d)）
② 注意力的偏置：in_proj_bias(3d = 18) + out_proj.bias(d = 6) = 24 每层，×3 层 = 72
   （校验：PyTorch 的 MultiheadAttention 是 108 + 18 + 36 + 6 = 168，本包是 4d² = 144）
合计 192 + 72 = 264 ✓（与实测的 1722 − 1458 一致）
```

"差值能被逐项解释"比"两个数相等"更有信息，因为它把"我们对两个实现的理解"
变成一条**可失败**的断言：如果哪天差值不再是 264，那么一定是某一项变了
（PyTorch 版本的默认偏置变了、或者本包多/少数了什么）。
反过来，如果为了让两个数相等而把差值凑掉，那么"理解"这件事就消失了。

### 30. 第一个坑

```python
# 第一版（错的）：注意力作用在原始 x 上
attention = self_attention(params.blocks.attentions[index], current, mask=stream_mask)
block = encoder_block(block_params, current, attention, ...)
```

它"前向完全正确"是因为：形状全对（`LN` 保形）、六条性质全绿、
连演示脚本的四张表都对——错的地方只有在**反向**里：
`encoder_block_backward` 按"注意力作用在 `LN(x)` 上"那一条链，
把一部分梯度分给 `γ₁/β₁`，于是**两边算的不是同一个函数**。

抓到它的判据是**梯度校验**（解析 vs 中心差分）：

```text
layers=1 activation=gelu   max_gap = 2.237e-01     ← 第一版
layers=1 activation=relu   max_gap = 1.479e-10     ← 修完之后
```

修法（四行）：

```python
def _first_sublayer_input(inputs, *, placement, gamma, beta) -> Matrix:
    """**第一个子层看到的输入**：pre-LN 是 LN(x)、post-LN 是 x."""
    if placement == NORM_PRE:
        normed, _cache = layer_norm(inputs, gamma=gamma, beta=beta)
        return normed
    return inputs
```
