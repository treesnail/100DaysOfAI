day100 的结语说："这份交付不新增能力，只让已有的能力变得可被信任。"
今天反过来做一件很具体的事：**把这 100 天写下来的字，重新变成能回答问题的东西**。

```text
问题① 100 天之后，仓库里最没有被利用的资产是什么？
问题② "哪一天讲过 XXX" 这件事，现在靠什么回答？
问题③ 如果做一个检索，它的判据应该是什么？
```

今天的答案：

```text
问题① 是那些**已经写好、但不再被读**的文字：46 份手册 + 53 个子包自述，共 53.5 万字
```

## 第一章：为什么结业之后还要再写一天

100 天里，每天结束时都会写一份手册进 `docs/`。它们在当时都是有意义的，但今天它们的状态是：

```text
写得很好 · 再也没被读过
```

这不是"写多了"，而是**缺一道工序**：把这些文字编成一份**索引**。

```text
写手册      把"今天讲的"固化下来
编索引      让"哪一天讲过 XXX"变成一个可以被检索的问题
```

这两件事的区别，就是"资料"与"可用资料"的区别。而索引这件事有一个天然的好处：
**它不依赖任何新的模型能力**——它只依赖"把材料收齐、把词切对、把顺序定死"。

因此今天的读数是四个：

```text
语料 99 份 | 文档 46 / 子包 53 | 合计 535049 字
索引：99 份文档 | 词典 31278 个词 | 词次 157313 | 摘要 1f60d8bf1a2fcb68
查询 'course_index' | 词 1 个 | 命中 2 条 | 首条 doc:course_index 1.0000
七条性质 7/7 通过
```

## 第二章：语料——先说清"哪些材料必须进得来"

绝大多数"做一个搜索"的教程从选算法开始。今天从**收料**开始，因为：

> 一份没进语料的文档，与"这门课没有那份文档"在检索结果里读起来完全一样。

语料有两种，都从仓库里**读**出来：

```text
doc         仓库 docs/ 下的 *.md 全文（课程手册）      46 份
subpackage  每个子包的 __init__.py docstring（包自述）  53 条
```

### 2.1 一条纪律：文档名必须**带种类前缀**

```text
docs/backprop.md              →  doc:backprop
smart_research_agent/backprop →  subpackage:backprop
```

为什么不能只用裸名字？因为**会撞车**：

```text
backprop / capstone / conv_net / graduation …… 都同时是"一篇手册"与"一个子包"
```

撞车之后 `Corpus` 的"名字唯一"检查会抛 `CorpusError`：

```python
CorpusError: 语料里有重复的文档名：['backprop']——
两件不同的材料共用一个名字，检索结果里就没法区分它们。
```

**宁可当场变红，也不要让两件不同的东西共用一个名字。**

### 2.2 一条纪律：没有 docstring 的子包要**被点名**

`subpackage_docstrings()` 对一个没有自述的子包是**抛错**，不是跳过：

```text
跳过它   这个包的存在永远不会被检索到——而"检索不到"比"报错"更难被发现
点名它   要么补一段自述，要么显式把它排除在语料之外（不能两头都不做）
```

这与 day100 的"交付物必须非空"是同一条纪律：**沉默的遗漏是最危险的一类缺陷。**

## 第三章：分词——确定性与零依赖

中文分词有三种常见做法，各自的问题很具体：

```text
按空白切词     中文没有空格 ⇒ 一整段中文变成"一个词"，索引等于没建
引入分词库     多一个依赖，且**不同版本会给出不同切法** ⇒ 索引不再是可复算的
中文二元组     把"反向传播"切成 {反向, 向传, 传播} —— 零依赖、版本无关、逐位可复算
```

本课选第三种。三个手算例子（演示脚本第 2 节）：

```text
tokenize('Course_Index') = ('course_index',)         ASCII 词小写化（下划线算词内字符）
tokenize('反向传播')      = ('反向', '向传', '传播')   长度 4 ⇒ 3 个相邻二元组
tokenize('好')            = ('好',)                  长度 1 < 2 ⇒ 整段作为一个 token
tokenize('a of ab')       = ('of', 'ab')             长度为 1 的词被丢掉
```

**代价写在脸上**：二元组比"词"粗，会多召回一些。本课要的不是最好的检索质量，
而是"一份能被别人重算出同一份结果的索引"——这与 day087 的"位置必须由缓存长度决定"、
day100 的"剧本必须能被重放"是同一条纪律。

### 3.1 一个实现细节值得单独说

分词用了**一个**交替正则，而不是"先扫 ASCII、再扫中文"：

```python
TOKEN_PATTERN = re.compile(r"[A-Za-z0-9_]+|[\u3400-\u4dbf\u4e00-\u9fff]+")
```

两个独立的正则各扫一遍，会把"先 ASCII 后中文"这个**与正文无关的顺序**写进
`query_tokens` 与 `matched`——而这两个东西是会被印进报告的：

```text
tokenize("向量 向量 index index")
  两个正则各扫一遍   ⇒  ('index', '向量')   ← 顺序与正文相反
  一个交替正则       ⇒  ('向量', 'index')   ← 跟着正文走
```

顺序本身不影响结果（匹配是集合运算），但它影响**报告的可读性**。
"读起来对不对"也是工程的一部分。

## 第四章：倒排索引——并列的不确定性要**显式消掉**

倒排表只有一张：

```text
token → ((文档, 次数), ...)     按文档名排序
文档  → 词数                      按语料顺序
```

本仓库当前的读数：

```text
索引：99 份文档 | 词典 31278 个词 | 词次 157313 | 摘要 1f60d8bf1a2fcb68
```

`InvertedIndex.__post_init__` 里有一条护栏，值得逐字读一遍：

```python
names = [name for name, _ in pairs]
if names != sorted(names):
    raise IndexBuildError(f"token {token!r} 的文档名没有排序：{names}——"
                          "并列的不确定性会让'两次构建逐位相同'永远失败。")
```

为什么这条如此重要？因为 Python 的 `dict` **保留插入顺序**，而插入顺序取决于
你先遍历了哪一份文档。正文明明一样，但：

```text
不排序   postings 里 (doc_a, doc_b) 还是 (doc_b, doc_a)，取决于构建时的遍历顺序
排序     结果只取决于"有哪些文档"，与"先遍历了谁"无关
```

于是"索引可复算"这条性质就从"我们希望它成立"变成"它不可能不成立"。
`repr` 出来的东西因此是稳定的，摘要（`sha256` 前 16 位）才有意义。

## 第五章：检索——一条公式 + 一条并列规则

检索的全部数学就一行：

```text
score = 该文档命中的查询词数 / 查询词总数        ⇒  数学上落在 [0, 1]
```

排序规则两条，第二条是"为了确定性"才存在的：

```text
① 分数高的在前
② 分数并列时，**文档名**字典序在前     ⇒ 同一个问题两次得到同一份名单
```

### 5.1 金标准：查询包名、命中该包

```text
查询 'course_index' | 词 1 个 | 命中 2 条 | 首条 doc:course_index 1.0000
金标准材料 subpackage:course_index 的名次 = 2
```

注意这里**命中了两条**，而且金标准材料**不是第一名**：

```text
doc:course_index         1.0000   ← 本课的手册（今天新写的 docs/course_index.md）
subpackage:course_index  1.0000   ← 本包的 docstring
```

两条分数相同，先后由规则 ② 决定（`doc:` < `subpackage:`）。
这正是规则 ② 存在的理由：**没有它，两份名单都"对"。**

因此第 ⑦ 条性质写成：

```text
金标准材料被命中 >= 1 次
```

而不是"它必须排第一"。**名次是排序规则的结果，不是这条性质要管的事**——
把两者混在一起，会让这条性质在"多召回了一条同样相关的材料"时误报失败。

### 5.2 `matched`：让分数可以被核对

`Hit` 里同时有 `score` 与 `matched`：

```text
doc:course_index | 分数 1.0000 | 命中 [course_index]
```

少了 `matched`，一个 0.5 分就只能被**相信**、不能被**核对**。
这与 day099 的"接地判据是编号而不是字符串"、day100 的"自评必须挂证据"是同一条纪律：
**每一个数都要能回答"它是怎么来的"。**

### 5.3 "没查"与"查了没命中"是两件事

```text
空查询 / 无词查询（"、、、"）  ⇒  QueryError      ← 调用点的问题
查了但名单为空                  ⇒  正常返回空名单   ← 语料的问题
```

因此 `require_hits()` 是"拒绝空名单"的那条**可选**的路，而不是 `search()` 的默认行为。

## 第六章：七条性质、六个失败族与五条边界

### 6.1 七条性质（三类判据齐全）

```text
1. corpus_covers_all_docs          | [equality   ] | 读数 0 ✓ | 手册 46 份 / 期望 46 份
2. corpus_covers_all_subpackages   | [equality   ] | 读数 0 ✓ | 子包 53 条 / 期望 53 条
3. index_is_reproducible           | [equality   ] | 读数 0 ✓ | 摘要 1f60d8bf1a2fcb68 / 1f60d8bf1a2fcb68
4. search_is_deterministic         | [equality   ] | 读数 0 ✓ | 查询 'course_index' 命中 2 条
5. scores_within_bounds            | [upper_bound] | 读数 1 ✓ | 最高分数 1.0000 ≤ 上界 1.0
6. every_document_is_indexed       | [lower_bound] | 读数 2 ✓ | 最小词数 2 ≥ 下界 1
7. gold_query_finds_gold_document  | [lower_bound] | 读数 1 ✓ | 命中 1 次 ≥ 下界 1 | 名次 2
合计：7/7 条通过
```

**四条相等、一条上界、两条下界**。三类判据里为什么必须有两类"有方向的界"：

```text
⑥ 每份文档至少被索引一个词    越多越好  ⇒ 只能从下面兜住（写成 == 1 会在词变多时误报）
⑦ 金标准材料必须被命中        越多越好  ⇒ 只能从下面兜住（同上）
⑤ 分数不超过 1                越界不可用 ⇒ 兜的是上限
```

第 ⑥ 条在本课真的"几乎"撞线：最小词数是 **2**（下界是 1）。
阈值设成 5 就会让某一份"自述很短"的子包误报失败——**下界要定在"数学上必然成立"的地方，
而不是"我希望它长这样"的地方。**

### 6.2 六个失败族

| 族 | 该谁去修 |
|----|----------|
| `CorpusError` | 改语料收集：文档名重复或某份材料读不到时，先把那一份补进语料 |
| `IndexBuildError` | 改索引实现：两次构建不一致时，去掉那个没有固定的量（迭代序 / 集合序） |
| `QueryError` | 改查询或改分词：空查询与无词查询都要在调用点被看见 |
| `ScoreError` | 改打分：命中分数越界时，先回到 `score = 命中词数 / 查询词数` 的定义 |
| `NumericError` | 改数据或改实现：非有限读数与非法上下界都属于"数值不可用" |
| `ParameterError` | 改调用：文档种类 / 性质名 / `top_k` / 序号都是调用点的一次决定 |

`FAMILY_OUTCOMES` 与 `_FAMILY_CLASSES` 逐键对齐，导入期断言。两条族常量：

```text
RETURNED_FAMILY = "TokenError"
  day086 的 hf_integration.errors.TokenError 第一次给"分词器配置对不上"命名；
  此后各课都只把它当工具函数。day101 需要**自己决定怎么切词**，
  于是"切出来的东西不对"重新需要一次控制流事件——这个名字**回来**了，
  但基类从 ParameterError 换成 CourseIndexError(ValueError)。

ABSENT_FAMILY = "GradientError"
  本课是编索引与检索，一个新式子都没有写；本课连一次反向都没有触发。
```

一个命名上的教训也值得记下来：本课最初把"检索"模块命名为 `search.py`，
结果它的 `__all__` 里有一个叫 `search` 的**函数**——于是
"`from course_index import search` 拿到的是函数还是模块，取决于导入顺序"。
`__init__.py` 的导入期不变式当场把这条拦了下来：
**子模块名与公开名字不能重名**，于是模块被改名为 `query.py`。

### 6.3 五条边界

```text
1. 不新增任何第三方依赖：分词是自写的 bigram + ASCII 词切分。
2. 不改动任何既有模块、既有测试、pyproject 与 docs 下的既有文件——只新增文件；
   docs/ 下的手册是被**读取**的，不是被改写的。
3. 不承诺检索质量：它承诺的是"同一份语料编出同一份索引、同一查询给出同一份命中"，
   而不是"排在最前面的总是最好的"。
4. 全部读数离线、确定性：只读文件系统与 importlib，不联网、不读密钥。
5. 不含语义检索：bigram 索引认得的是"字面共现"，不是"同义"——
   把"怎么训练"与"训练方法"联系起来不是它要解决的问题。
```

第 3 条与第 5 条必须连起来读：**这份索引不是搜索引擎，它是一张可复算的对照表**。
把它读成"我们的检索质量如何"，是使用它时最危险的一种误读。

## 结语：三条可以带走的工程结论

1. **先把"哪些材料必须进得来"说清，再谈算法。**
   本课的两条覆盖性质（手册 46/46、子包 53/53）排在索引性质之前。
   一份没进语料的文档，与"这份文档不存在"在结果里读起来完全一样。

2. **排版是不确定性最便宜的解法。**
   倒排表里的文档名排序、并列命中按名字兜顺序、分词用单个交替正则——
   三处都是"显式指定一个顺序"，而它们合起来把"两次运行逐位相同"
   从"希望如此"变成"不可能不如此"。

3. **每一条性质的方向要和这个量的方向一致。**
   覆盖数、差异项数是**相等**；"分数不超过 1"是**上界**；
   "每份文档至少一个词""金标准必须被命中"是**下界**。
   方向错了，性质会在系统**变好**的时候误报失败，然后被人关掉——
   而一条被关掉的性质，等于不存在。

> **诚实的说明**：本课是**离线、确定性**的——它不调用任何模型、不做任何向量化，
> 也不测量"检索质量"。bigram 索引能回答的是"这个词在哪几份材料里出现过"，
> 不是"哪一份最相关"。本课**没有** `import` 任何新依赖、**没有** GPU、
> **没有**真实向量库。它给的是**一套能带走的确定性纪律**：
> 当你真的要为一个语料库建索引时，知道该先收齐什么、该把哪个顺序写死、
> 该断言哪七件事。
