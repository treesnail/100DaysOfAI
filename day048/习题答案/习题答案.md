# day048 课后习题：参考答案

## 第一部分：选择题

### 第 1 题（选型规则）

**答案：D**

D 把 `warnings` 的角色说反了。`recommend_method` 里 RLHF-PPO **只出现在告警文案中**，作用是"如果你因为偏好数据太少而想换路，注意 RLHF-PPO 的成本只会更高"——它需要额外训练奖励模型与在线采样，流程最长（SFT → 奖励模型 → PPO），不该做首选。A / B / C 都是四条规则本身：偏好对优先进 DPO（不需要奖励模型与 RL 循环）；`need_full_capability` 且显存 ≥ 80GB 才推荐全参 SFT；`< 16GB` 推荐 QLoRA（4-bit 把权重压到约 1/4）。此外 `examples < 500` 时会**无条件**追加一条"先补数据"的告警，与走哪条分支无关。

### 第 2 题（LoRA 算术）

**答案：A**

```text
全参参数量  = d_in * d_out
LoRA 参数量 = r * (d_in + d_out)      # A 为 r×d_in，B 为 d_out×r
ratio      = r * (d_in + d_out) / (d_in * d_out)
```

实测 `lora_trainable_ratio(4096, 4096, 8) == 0.00390625`（约 0.39%）。B 是它的倒数（提示写法：`lora_trainable_ratio` 返回的是"可训练比例"，恒 ≤ 1，不会大于 1）。C 错：参数非法时抛 `ValueError`，因为在比例无定义的情况下返回 0 会被下游误解成"不用训练"（返回 `inf` 则会被误解成"参数爆炸"）。D 错：比例与 `rank` 成正比（rank 8 → 0.39%、rank 16 → 0.78%）。

### 第 3 题（格式与样本模型）

**答案：D**

`to_alpaca()` 保留空的 `input` 键，是为了让下游拿到**结构稳定**的记录——字段时有时无会让 schema 推断失败。A 错：alpaca 只要求 `instruction` 与 `output` 非空，`input` 可空。B 错：`parse_example` 用 `not output.strip()` 判定空值，**只有空白等价于空**；否则一条 `output="\n\n"` 会变成训练目标长度为零的样本。C 错：chat 分支只支持单轮，多轮样本**显式报错**而不是静默截断——多轮训练需要额外的 loss masking 策略，静默截断是数据工程里最危险的"善意"。

### 第 4 题（采集与答案核对）

**答案：B**

`task-04` 的 `answer_contains` 是 `56`，而轨迹的 Final Answer 是 `答案是 99`，核对不通过 → 打上 `("from:eval", "react-trace", "unverified")` 标签，随后被 `default_rules` 的第 7 条 `unverified_source` 拦截。A 错：评估集是**为评测而造**的，里面刻意包含失败样本（M3 的 Agent 评估需要失败轨迹才能测完成率），直接训练就是把 `7 × 8 = 99` 学进权重。C 错：没有 `answer_contains` 就没有判对错的标准，`EvalTaskSource` 会标记 `unverifiable` 并**跳过**（实测 1 条）。D 错：答案对不上的样本**刻意保留到清洗阶段**——`FilterReport.drop_reasons` 里出现 `unverified_source` 计数，才能证明"评估集轨迹不能无脑当训练数据"这条结论在流水线里真的被执行了。

### 第 5 题（清洗阶段与顺序）

**答案：C**

三个阶段的顺序是硬约束：**清洗最先**（规则与指纹都要看"最终字符"，否则 `"\n\n\n"` 会以 3 个字符通过 `min_output_chars=8` 的门槛），**去重最后**（先按规则丢掉废样本，再对 survivors 取指纹，否则一个本该被拒的样本会抢先占位，把后面合法的重复项挤掉）。A 错：用原始文本跑规则等于在判断"最终不会喂给模型的那串字符"。B 错：先去重会浪费一次 SHA-1 计算，更严重的是破坏"保留首次出现的**合法**样本"这一语义。D 错：`keep_rate` 在空输入时返回 **0.0**——没有数据不代表"全都合格"（与 day029 `retrieval_precision` 遇空召回集返回 0.0 同理）。

## 第二部分：判断题

### 第 6 题

**对**。`dedupe_key` 只看 `clean_text(prompt_text).lower()` 的 SHA-1 前 16 位，不含 `output`。原因正是"同一个问题配两个不同答案"在监督微调里不是冗余而是**冲突**：两条都留着，模型学到的就是一个含糊的平均；去重把它压成一条（保留首次出现），把矛盾**暴露给数据评审**，而不是喂给训练。另外"先清洗再取指纹"让"全角/半角不同""只差空白"的重复也能被识别（实测 `'ＲＡＧ 是什么？'` 与 `'RAG 是什么？'` 清洗后指纹相同）。

### 第 7 题

**对**。用 `random.Random(seed)` 而不是全局 `random`，既不污染全局随机状态，也让测试与并发调用彼此隔离；同一个 seed 永远得到同一个切分，否则"这次评估涨了 2 个点"可能只是切分换了——**切分不稳定，评估就没有可比性**。同时 `eval_count = max(1, round(n * eval_ratio))` 且 `min(eval_count, n - 1)` 保证 `n >= 2` 时两侧都非空：空评估集会让评估静默失效，训练集为空更是退化切分，所以 `eval_ratio = 1.0` 被直接拒绝。

### 第 8 题

**错**。`compute_stats` 对空列表返回**全零统计而不抛错**。因为"清洗后一条不剩"是一种**合法的中间状态**（说明质量门槛把所有样本都挡住了），此时调用方需要的是"0 条"这个事实；抛异常会让"为什么没数据"的排查被错误处理逻辑掩盖——异常应该留给"程序错了"，而不是"数据被正确地全部拒绝了"。

## 第三部分：填空题

### 第 9 题

- `ALPACA`：**`{"instruction", "input", "output"}`**
- `CHAT`：**`{"messages": [{"role", "content"}, ...]}`**
- `PROMPT_COMPLETION`：**`{"prompt", "completion"}`**

`parse_example` 对 **`instruction`（或 prompt）** 与 **`output`（或 completion）** 两个字段做了 `.strip()` 校验，因此"只有空白"等价于"空"。刻意只支持单轮对话，是为了避免对多轮样本做静默截断——多轮训练需要额外的 **loss masking** 策略（只对 assistant 段计算 loss）。

（补充：三种格式在内存里统一为 `TrainingExample`，因此"清洗一次、训练多种格式"成为可能——清洗/去重/统计全程作用在统一对象上，只在落盘那一刻用 `to_dict(fmt)` 投影回目标格式。）

### 第 10 题

与"答案没写完"直接相关的规则是 **`placeholder_output`**，它匹配的常量是 **`PLACEHOLDER_MARKERS = ("todo", "待补充", "lorem", "tbd", "fixme")`**；与"评估集未核对答案"直接相关的是 **`unverified_source`**。去重指纹取 SHA-1 十六进制前 **16** 位（`DEDUPE_KEY_LENGTH = 16`，即 64 bit）。

（七条默认规则按顺序：`output_too_short` / `output_too_long` / `instruction_too_long` / `empty_instruction` / `placeholder_output` / `banned_pattern` / `unverified_source`。）

## 第四部分：简答题

### 第 11 题（为什么 M5 的第一课是数据）

**（1）微调能改变什么、不能改变什么。**

能：① 学会**领域表达与格式**（术语、口吻、结构化输出）；② 学会一种**行为**（工具调用、ReAct 轨迹、面对攻击时拒答）。

不能（或代价极高）：① 灌入大量**新事实**——微调把知识压进权重后不可检索、不可更新、不可归因，改一条事实要重训一次，而且容易引发灾难性遗忘；RAG 把知识留在外部索引里，可增量更新、可引用出处、可按权限过滤，所以"事实"必须由 RAG（day061~072）承担，微调只负责让模型**会用**检索到的内容；② 提升模型的**推理上限**——能力边界由基座决定，微调只能让已有能力更稳定地被激发。

**（2）"效果上限由数据决定，方法只决定能不能逼近"。**

数据封版那一刻，模型的期望性能上限就被固定了：方法（LoRA / 全参）、超参（学习率、rank）、训练轮数，都只决定你逼近这个上限的程度。推论之一就是"样本量不足时换方法几乎无用"——因此 `recommend_method` 把这条判断做成了**无条件告警**：

```python
if examples < 500:
    warnings.append(
        f"样本量偏少（{examples} 条）：500 条以下微调极易过拟合，"
        "先补数据比换方法更有效。"
    )
```

注意它在**四条分支判断之前**执行，所以无论最终推荐 QLoRA、LoRA、DPO 还是 SFT，这条告警都会跟着一起返回。**把工程经验写成代码里的无条件分支，比写在文档里可靠**——docstring 会被跳过，告警会出现在每一次调用的返回值里。

**（3）"评估集不能直接当训练集"的代码链路。**

三段代码共同保证：

- **打标签**（`EvalTaskSource.load`）：`answer_contains` 与轨迹 Final Answer 核对——通过 → `tags=("from:eval", "react-trace")`；不通过 → `tags=(..., "unverified")`；压根没有 `answer_contains` → 计数 `skipped` 并跳过。
- **被规则拦截**（`cleaner.default_rules` 第 7 条 `unverified_source`）：`"unverified" not in example.tags`，不通过即拒，并把原因计入 `FilterReport.drop_reasons`。
- **计数可核对**：`FilterReport.drop_reasons["unverified_source"] == 2`，与 `EvalTaskSource.unverified == 2` 严格对应——**两处独立统计互相印证，账能对上**。

实测 5/2/1 的含义：**5** 条答案包含 `answer_contains`（`task-01/02/03/07/08`）→ 可用；**2** 条答案对不上（`task-04`：期望 `56`，实际 `99`；`task-05`：期望 `225`，实际 `150`）→ 打 `unverified` 后被规则丢掉；**1** 条没有 `answer_contains`（`task-06`）→ 无法核对，直接跳过。

## 第五部分：编程题

### 第 12 题（参考答案）

```python
"""day048 #12 参考答案：给数据流水线补一条规则 + 验证顺序即优先级."""

from smart_research_agent.finetune import (
    DatasetCleaner,
    QualityRule,
    TrainingExample,
    default_rules,
)

MAX_NEWLINES = 8

too_many_newlines = QualityRule(
    name="too_many_newlines",
    reason=f"输出换行数超过 {MAX_NEWLINES}，排版异常（多半是粘贴的长文）",
    check=lambda example: example.output.count("\n") <= MAX_NEWLINES,
)


def make_cleaner() -> DatasetCleaner:
    rules = [too_many_newlines, *default_rules(
        min_output_chars=8, max_output_chars=4000, max_instruction_chars=1000
    )]
    return DatasetCleaner(min_output_chars=8, rules=rules)


long_output = "\n".join(f"第{i}行：这是一段有实际内容的说明文字。" for i in range(1, 11))

cleaner = make_cleaner()
samples = [
    TrainingExample(instruction="什么是 RAG", output="检索增强生成：先检索再生成。", source="t"),
    TrainingExample(instruction="讲讲 RAG", output=long_output, source="t"),
    TrainingExample(instruction="写点东西", output="见后续。", source="t"),
]
kept, report = cleaner.run(samples)

print(f"保留 {len(kept)} 条，drop_reasons={report.drop_reasons}，keep_rate={report.keep_rate:.4f}")
assert len(kept) == 1
assert report.drop_reasons.get("too_many_newlines") == 1
assert report.drop_reasons.get("output_too_short") == 1
assert abs(report.keep_rate - 1 / 3) < 1e-9
print("断言 1-3 通过：保留 1 条、两类原因各 1 条、保留率 = 1/3")

# 顺序即优先级：同一样本同时违反"换行超限"与"含占位符"
# （注意：output_too_short 要求长度 < 8 而换行超限至少 9 行，两者不可能同时命中）
both = TrainingExample(
    instruction="既超限又含占位符", output=f"TODO 待补充\n{long_output}", source="t"
)
_, report2 = cleaner.run([both])
assert report2.decisions[0].rule == "too_many_newlines", report2.decisions[0].rule
print(f"断言 4 通过：竞争场景归到排在前面的规则 -> {report2.decisions[0].rule}")

# 把自定义规则放到后面，则同一个样本归到 default_rules 里的 placeholder_output
reordered = DatasetCleaner(
    min_output_chars=8,
    rules=[*default_rules(min_output_chars=8, max_output_chars=4000,
                          max_instruction_chars=1000), too_many_newlines],
)
_, report3 = reordered.run([both])
assert report3.decisions[0].rule == "placeholder_output", report3.decisions[0].rule
print(f"断言 5 通过：交换顺序后同一样本归到 -> {report3.decisions[0].rule}")

# 反过来也要验证：换行超限但长度正常、无占位符的样本，交换顺序后仍被 too_many_newlines 拦下
_, report4 = reordered.run([samples[1]])
assert report4.decisions[0].rule == "too_many_newlines", report4.decisions[0].rule
print(f"断言 6 通过：无竞争时自定义规则照常生效 -> {report4.decisions[0].rule}")

print("\n全部断言通过")
```

**实测输出**（本机运行）：

```text
保留 1 条，drop_reasons={'too_many_newlines': 1, 'output_too_short': 1}，keep_rate=0.3333
断言 1-3 通过：保留 1 条、两类原因各 1 条、保留率 = 1/3
断言 4 通过：竞争场景归到排在前面的规则 -> too_many_newlines
断言 5 通过：交换顺序后同一样本归到 -> placeholder_output
断言 6 通过：无竞争时自定义规则照常生效 -> too_many_newlines

全部断言通过
```

**几处必须理解的细节**：

1. **规则方向是"返回 True = 通过"**，所以自定义规则的 `check` 写的是 `example.output.count("\n") <= MAX_NEWLINES`。若写反（`>`），这条规则会把**所有正常样本**都拒掉，而报告里的原因文案仍然是"换行数超过 8"——方向写错是最难自查的一类 bug，这也是 `QualityRule` 的 docstring 专门说明真值方向的原因。
2. **竞争场景的规则选择不是随意的**。`output_too_short` 要求长度 `< 8`，而"换行超限"至少 9 行、长度必然 ≥ 9，所以这两个条件**逻辑上互斥、永远无法同时命中**；要验证"顺序即优先级"必须另选一对能同时成立的规则（本题用 `too_many_newlines` + `placeholder_output`）。**先想清楚两个条件能否同时为真，再写这个断言**——否则调试半天，问题其实出在测试用例本身（这正是本题第一版踩的坑）。
3. **`clean_text` 会折叠连续换行**：`"\n\n\n\n"` 清洗后只剩一个 `\n`。所以构造"换行超限"样本必须用**内容不同的多行文本**，而不是连续空行——否则样本在清洗阶段就被折叠掉，规则永远不触发，测试会给出一个"看起来通过但什么都没测到"的假绿。
4. **`rules=` 是整体替换而非追加**：`DatasetCleaner(rules=[...])` 会**完全丢弃** `default_rules`，所以必须显式写 `[too_many_newlines, *default_rules(...)]`。这个设计是对的——若默认追加，"定制一个数据集"就会连带改变**所有**数据集的严格度；但也意味着调用方必须自己负责完整性。
