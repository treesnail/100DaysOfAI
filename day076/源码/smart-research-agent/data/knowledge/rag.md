# 检索增强生成（RAG）

## 概述

检索增强生成（RAG，Retrieval-Augmented Generation）是一种把「信息检索」与
「语言模型生成」结合起来的架构。传统的大语言模型只依赖训练时学到的内部知识，
容易产生幻觉、且无法回答训练截止之后的新信息；RAG 在生成之前先从一个外部知识库
中**检索**出与问题相关的文档片段，再把它们作为上下文拼进提示词，交由模型**生成**
答案。

这样做的核心收益有三点：

1. **可溯源**：答案的每一处关键事实都能对应到检索到的文档，便于人工核对。
2. **降幻觉**：模型被显式约束在检索到的上下文内作答，凭空编造的概率大幅下降。
3. **低成本更新**：知识更新不用重新训练模型，只需向知识库增删文档即可。

## 工作流程

一个典型的 RAG 管线分两个阶段：

- **离线阶段（建索引）**：把知识库文档切块（chunking），用 embedding 模型把每个
  文档片段编码成向量，写入向量库（vector store）。
- **在线阶段（查询时）**：把用户查询也编码成向量，在向量库中做最近邻检索，召回
  Top-K 个最相关的片段，与查询一起组装成提示词交给生成模型。

## 关键组件

| 组件 | 作用 |
|------|------|
| 文档切块 | 把长文档拆成合适大小的片段，粒度影响检索与生成质量 |
| Embedding 模型 | 把文本映射为定长向量，语义相近的文本向量距离更近 |
| 向量检索 | 用余弦相似度/内积做最近邻搜索，召回 Top-K 片段 |
| 生成模型 | 基于检索到的上下文生成最终答案 |

## 评估

检索环节与生成环节应当**分开评估**，才能定位病灶——检索错了答案再好也是「蒙对」，
检索对了答案错了则是生成环节的问题。

- **检索评估**：召回率（recall）、精确率（precision）、倒数排名（MRR）、归一化
  折损累计增益（NDCG）。
- **生成评估**：答案忠实度（faithfulness），常用 LLM-as-a-judge 对比生成答案与
  参考答案。
