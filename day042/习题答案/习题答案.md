# day042 课后习题：参考答案

## 第一部分：选择题

### 第 1 题（Prompt 工程，day036）

**答案：C**

ToT 的多个分支恰恰应当探索**不同**的视角，才能覆盖解空间的不同方向；如果所有分支用相同视角，搜索就退化为"同一个思路重试 n 次"，无法获得多样化路径（这也解释了 `test_tot_consumes_2n_plus_calls` 中"n 个分支 + 1 次汇总"的调用结构）。A 正确：Few-shot 校准的是格式与风格而非知识；B 正确：`render()` 对缺失变量抛 `PromptRenderError`，宁可失败也不把有损提示词发给模型；D 正确：version/changelog 是版本对比评估的前提（承接 day026 的 `PromptEvaluator`）。

### 第 2 题（Function Calling，day037）

**答案：B**

`validate_arguments` 只实现 JSON Schema **子集**（`required` + `type`），并不覆盖枚举/最小值/anyOf 等完整 schema（A 错）。`bool` 特判是关键：`isinstance(True, int)` 为真，但 JSON Schema 中 boolean 与 integer/number 互不相容，因此 `_TYPE_MAP` 里 boolean→bool 必须与 number/integer 区分。C 错：`arguments` 兼容 JSON 字符串或已解析 dict 两种形态。D 错：工具执行失败抛 `ToolExecutionError`（`kind="execution"`），由调用方按 kind 分类处置。

### 第 3 题（FastAPI，day038）

**答案：B**

同步阻塞的 CPU/IO 代码应放进普通 `def`，FastAPI 会把它丢进线程池执行，从而不影响事件循环。A/C 错：把阻塞代码硬塞进 `async def` 或在其中 `await`，会冻结事件循环、拖垮整个进程——这就是 day038 明确强调的"同步 def / 异步 def"陷阱。D 错：不需要独立进程，普通 `def` 即可。

### 第 4 题（流式输出，day039）

**答案：B**

流式解决的只是感知性能（首字延迟 TTFT），**不改变内容正确性**（A 错）。C 错：function calling 与 Agent 轨迹不适合流式（流式中途降级要重头再来，day039 简化为降级时换模型重新生成）。D 错：SSE 用 FastAPI 内建 `StreamingResponse(media_type="text/event-stream")`，无需第三方 SSE 库。

### 第 5 题（多模态，day040）

**答案：B**

`validate_image` 用 magic bytes（文件头字节序列）识别真实 MIME（PNG/JPEG/GIF/WebP），**不信任文件扩展名**（A 错）。C 错：`ImageAnalysisTool._resolve_image_bytes` 只支持 data URL / 本地路径 / 裸 base64，**远程 URL 显式拒绝以防 SSRF**。D 错：视觉请求必须经 `supports_vision` 过滤，绝不能发给纯文本模型。

### 第 6 题（Embedding，day041）

**答案：C**

C 是错误说法：维度越高并不必然更准，且更高维度意味着更大的存储与检索成本，还要考虑提供方/数据分布；"无条件选择最高维度"是典型误区。A、B、D 都是 day041 强调的三性质（定长、归一化、余弦度量语义）。

### 第 12 题

**对**。容器类定义 `__len__` 后空实例布尔值为假，`store or InMemoryVectorStore()` 会把调用方传入的空库静默替换成新库——写入落进新库、调用方拿着旧库查询永远查不到（day041 修复的 bug）。`x or default` 只适用于"假值 == 缺失"，这里必须 `store if store is not None else ...`。

## 第三部分：填空题

### 第 13 题（多模型路由与视觉路由）

**向上**；**多付一次费**；**有任意一个视觉模型**；**`supports_vision` 为 True**。

（完整句：`ModelRouter` 降级链方向是向上——"答错"的代价大于"多付一次费"，失败安全偏向多花钱一侧；`supports_vision` 只要池中有任意视觉模型就返回 True，`chat_vision` 只选择 `supports_vision` 为 True 的候选、跳过纯文本模型。）

### 第 14 题（Embedding 三条性质与批量接口）

① **定长**（维度固定，向量库/检索器/神经网络才能消费）；② **归一化**（L2 归一化后余弦退化为点积，阈值有稳定物理含义）；③ **余弦度量语义**（相似度 = 语义距离 / 余弦相似度趋近 1）。`embed_batch` 的默认实现是**逐条调用 `embed`**；`SentenceTransformerEmbedding` 与 `OpenAIEmbedding` 覆写它以获得**批处理收益**（一次前向 / 一次 HTTP 处理整批）。

## 第四部分：问答题

### 第 15 题（三条主线串讲）

**（1）day036 vs day037：同一个问题、两条技术路线。**

- 同一个问题：都要"让模型按约定输出工具调用"。
- day036 走**文本协议**路线：靠提示词把输出约束成 `Thought/Action/Observation` 文本块，再由解析器容错识别格式。优点是无需模型特殊能力、通用；缺点是格式正确性是**概率性的**——工具名写错、参数带噪声、格式违例都需要提示词约束 + 解析器容错 + 执行校验层层兜底。
- day037 走 **tool_calls 协议**路线：让模型原生产出结构化 `tool_calls`，`validate_arguments` 只做"语义校验"不再做"格式纠错"。格式正确性由 API 协议**保证**，是确定性的。
- 适用场景：day036 的文本协议适合模型不支持 function calling、或需要以文本块呈现推理轨迹的场景；day037 的协议路线适合有参数结构、需要严格校验的工具调用。
- temperature=0 的推论：day033 指出"输出给程序解析"的场景该用低温（分布尖锐、犯错率低）——day037 的 function calling 正是"输出给程序解析"，低温让 `tool_calls` 格式稳定、可解析，两条线在此交汇。

**（2）服务化让能力逐个叠加而不推翻一行业务代码。**

- 工厂 + 依赖注入：`create_app(llm, agent_factory, models, embedding)` 通过注入点扩展——day039 流式、day040 视觉、day041 embedding 接口都是在**不改动既有路由的基础上新增**（如 `embedding` 注入后在 `/embeddings` 复用）。
- "契约自带元信息"：day039 的 `RouteDecision` 记录"为什么选这个模型"、day041 的 `EmbeddingResponse` 带 `provider`+`dimension`——每个新能力都在自己的契约里带上可观测/可归因元信息，下游无需猜测。
- 错误码契约一致：422/404/500 语义统一，day040（视觉 400/404/422）与 day041（embeddings 422）直接沿用，前端分支逻辑不用为新端点重写。

**（3）为什么 `min_score` 在 day041 而非 day009。**

- day009 时记忆用的是 `MockEmbedding`——SHA-256 哈希伪向量，雪崩效应让近义/无关句相似度都在 0 附近随机波动，**任何阈值都是噪声过滤器**，"相似还是无关"无从判断。
- 只有真实的语义 embedding（CharNgram 的字面重叠、神经向量的语义距离）才有可解释的相似度梯度，"低于 0.2 大可能不相关"是可以说出口的判断。
- "凑不满 top_k 不递补"：把不相关的结果硬塞给下游（如 RAG）比少给一条危害大得多，**宁缺毋滥**是检索场景的正确语义。

## 第五部分：编程题

### 第 16 题（综合编程 · 参考答案）

```python
"""day042 #16 离线验证：Function Calling 协议 + 语义 Embedding."""
from smart_research_agent.llm.function_calling import specs_from_tools, parse_tool_calls
from smart_research_agent.llm.mock import MockLLM
from smart_research_agent.llm.base import Message
from smart_research_agent.tools.calculator import CalculatorTool
from smart_research_agent.llm.embedding import CharNgramEmbedding

# ---------- 1) 工具调用协议 ----------
tool = CalculatorTool()
specs = specs_from_tools([tool])
assert len(specs) == 1, f"应只有 1 个规格，实际 {len(specs)}"
assert specs[0].name == "calculator", specs[0].name
assert specs[0].parameters.get("required") == ["expression"], specs[0].parameters
print("[1] 规格断言通过 name/required")

# ---------- 2) 脚本化模拟 + 解析 ----------
llm = MockLLM(tool_call_responses=[
    {"tool_calls": [{"name": "calculator",
                     "arguments": {"expression": "(1 + 2) * 3"}}]}
])
messages = [Message(role="user", content="请计算 (1 + 2) * 3")]
resp = llm.chat_with_tools(messages, tools=[s.to_openai_tool() for s in specs], temperature=0.0)
calls = parse_tool_calls(resp)
assert len(calls) == 1, f"应解析出 1 次调用，实际 {len(calls)}"
assert calls[0].name == "calculator", calls[0].name
assert calls[0].arguments["expression"] == "(1 + 2) * 3", calls[0].arguments
print("[2] parse_tool_calls 断言通过 arguments")

# ---------- 3) 执行与校验 ----------
result = tool.execute(expression=calls[0].arguments["expression"])
assert result == "9.0", result
print("[3] 执行结果 =", result)

# ---------- 4) 语义 Embedding ----------
emb = CharNgramEmbedding()
near = ["我喜欢学习机器学习", "我爱学习机器学习"]
far = ["我喜欢学习机器学习", "今天晚饭吃什么"]


def cosine(a, b, dim):
    return sum(x * y for x, y in zip(a, b))  # 归一化后点积即余弦


VA, VB = emb.embed(near[0]), emb.embed(near[1])
VC, VD = emb.embed(far[0]), emb.embed(far[1])
sim_near, sim_far = cosine(VA, VB, emb.dimension), cosine(VC, VD, emb.dimension)
assert sim_near > 0.5, f"近义相似度应 > 0.5，实际 {sim_near:.4f}"
assert sim_far < 0.5, f"无关相似度应 < 0.5，实际 {sim_far:.4f}"
assert sim_near > sim_far, f"近义应大于无关：{sim_near:.4f} vs {sim_far:.4f}"
print(f"[4] 近义={sim_near:.4f} 无关={sim_far:.4f}")

print("全部断言通过")
```

关键点说明：

- `specs_from_tools` 直接从工具元数据生成 schema，因此第 1 步的 `required` 断言对应 `CalculatorTool.parameters` 里的 `"required": ["expression"]`；
- `MockLLM.chat_with_tools` 的 `tool_call_responses` 脚本在返回前经 `_normalize_tool_response` 规整为 OpenAI 兼容格式，`parse_tool_calls` 可直接消费；
- `CalculatorTool.execute` 返回结果字符串 `"9.0"`（`(1+2)*3 = 9`，`_safe_eval` 走 AST 白名单）；
- 第 4 步用 L2 归一化向量的点积计算余弦，与库内 `cosine_similarity` 同口径；近义句共享 "学习/机器/机器学习" 等大量字符 n-gram，向量方向接近，相似度显著高于无关句（CharNgram 离线可用、无网络依赖）。

> 运行环境：day041 累积快照目录 `src` 下解压并 `pip install -r requirements.txt`（或使用已配置的 venv），在包根目录执行该脚本即可。脚本不发起任何网络调用。
