```text
问题① 是那几百份 .py 里的 __all__：352 份字面量承诺、9184 个对外名字
```

## 第一章：为什么"字""名字""关系"之后要编"承诺"

day101 编的是**字**，day102 编的是**错误名字**，day103 编的是**模块关系**。今天编的是**承诺**：

```text
每个模块各写各的 __all__          "我对外保证这几个名字"
没人把它摆在一起核过              "这些保证到底有没有落点？"
```

这件事有一个天然的好处：**它依然不依赖模型能力**——
它只依赖"把文件收齐、把声明的名字归属对、把顺序定死"。

因此今天的四个读数是扫描 / 清单 / 幽灵 / 性质，而且它们**共用同一份清单**
（`study_lines(catalog=...)`、`check_all(catalog=...)` 读的是同一时刻的状态）。

## 第二章：收料——先说清"哪些文件必须进得来"

```text
被扫描的       smart_research_agent/**/*.py                    464 份
行命名         foo.py → smart_research_agent.foo（每个 .py 一行）
没有进清单的   仓库之外的一切（os / pathlib / 第三方库都不参与）
```

一条纪律与 day101 ~ day103 逐字相同：**一份没进清单的模块，与"这个模块什么都没承诺"读起来完全一样。**
因此 `parse.scan_module` 对"文件读不到"与"语法错"都是**抛错**（`ParseError`），不是跳过。

## 第三章：三种承诺来源，与"读了两次就不算数"的一条边界

一个模块的"承诺"只可能有三种来处：

```text
declared   __all__ = ["A", "B"]         ⇒ 一份可以逐字核对的清单（352 份）
computed   __all__ = sorted({...})       ⇒ 它也算承诺，但这一课读不出来（12 份）
implicit   根本没有写过 __all__          ⇒ 只能退而取顶层公开 def / class（100 份）
```

**没有 `__all__` 不等于没有承诺**，只等于"这份承诺没有被写下来"。
把三种来源混成一类，就会让"没写"看起来和"写错"一模一样。

`__all__` 被写两次、或者写成 `+=`，本课**一律记成 `computed`**——
`collect_bindings` 里那句 `if seen_all > 1 or read is None: declared = None`
就是这条边界：读得出来就说得清，读不出来就说读不出来，**不猜**。

## 第四章：四类绑定——以及"模块级"这条边界

清单的核心工序，是把**声明的名字**变成**清单里的一个去向**。判定只有四类，顺序写死：

```text
① defined     名字在本模块里有 def / class            ⇒ 落点最硬
② assigned    名字在本模块里被赋过值（模块级）         ⇒ 落点是一个变量
③ imported    名字是本模块某条 import 的别名           ⇒ 落点在外面
④ unresolved  以上三类都不是                          ⇒ **幽灵导出**，当场点名
```

### 4.1 为什么顺序不能换

```text
先 assigned 后 defined     一个"既是函数又是变量"的名字会被记成变量
先 imported 后 defined     本模块定义的 foo 会被记成"从别处导进来的同名"
先 imported 后 assigned    一个从别处导入的常量会被记成"本模块赋的值"
```

这与 day102 的"四类归属"是同一条纪律的**第五次**应用。

### 4.2 "模块级"是这一课唯一的边界

一个名字的落点必须**在模块级**：

```text
class Foo:
    def bar(...): ...        ⇒ bar 不算本模块的落点（它在 Foo 里面）
def baz():
    import json              ⇒ json 不算本模块的导入
try:
    from x import Y          ⇒ Y **算**（它就在模块级作用域里）
```

这正是本课与 day103 的分界：day103 关心**任意位置**的一条 import（它要在图上画一条边），
本课关心**模块级**的一个绑定（它要回答"这个对外名字从哪里来"）。
`ast` 提供的语句种类很多，本课只"进 if / try / with / for / while，不进 def / class"
——这条规则写在 `iter_module_scope` 里，并且有一条测试专门钉住它。

## 第五章：一个真实的幽灵导出（本课最值钱的一条读数）

清单跑起来之后，**它报出了一个真的问题**：

```text
smart_research_agent/transformer_stack/verify.py 的 __all__ 里写着 "STAGE_ITEMS"
而这个名字在该模块里既没有 def / class，也没有赋值，也没有 import
```

也就是说：谁写 `from smart_research_agent.transformer_stack.verify import *`，
谁就会在那里拿到一个 `AttributeError`。**这不是分号笔误，它是一个"承诺了却没有落点"的名字。**

本课**不**写一条"幽灵必须为 0"的性质去把它"处理掉"。理由是：

```text
一个幽灵是一个**读数**，不是一次失败
  - 把它做成"必须为 0"的性质 ⇒ 这条性质在仓库合理地变化时会变红，
    最后一定会被人关掉——而一条被关掉的性质，等于不存在
  - 于是本课把它印出来（phantom_pairs()），只对"它是不是真的"做一条相等判据（③）
```

### 5.1 第 ③ 条性质怎么独立复核一个幽灵

这是本课唯一一处"两条独立的路给出同一个结论"：

```text
binding_of(name)         看的是"这个名字被哪一类**绑定**兜住了"（AST 的语法结构）
outside_all_names(path)  看的是"这个名字在 __all__ 之外**出现过没有**"（纯文本）
```

`outside_all_names` 把每一段 `__all__ = [...]` 的源码片段从文本里**挖掉**，
再正则找出剩下的标识符。因此一个**真**幽灵，它的名字在挖掉 `__all__` 之后
应当**一次都不出现**——性质 ③ 就把这件事写成一条 `== 0`。

这条性质能抓住一类很具体的错误：**如果解析漏了一类绑定**（比如忘了 `try` 里的 import），
那个名字会被误报成幽灵；而独立复核会发现它其实写在正文里，于是**第三条当场变红**。

## 第六章：重名表——跨包契约的入口

现场读数里，有几个名字被几十个模块同时导出：

```text
NumericError     40 个模块
ParameterError   40 个模块
FAMILY_OUTCOMES  36 个模块
ShapeError       34 个模块
PropertyOutcome  32 个模块
```

这不是"写重复了"，而是**跨包契约**：`except ShapeError` 之所以能一路兜住后面几十层，
靠的正是这份重名。因此本课把它按"出现模块数降序 × 名字升序"整张印出来，
而不是把它当成"重复代码"删掉——**同一件事在很多层各写一遍，与"这件事没人管"是两回事。**

## 第七章：可复算——把"并列"的不确定性显式消掉

清单的可复算口径只有两行：

```text
comparable() = (modules, ((模块, 来源, 声明, 定义, 赋值, 导入), ...))
digest()     = sha256(repr(comparable()))[:16]        ⇒ 实测 70b5f26213d53b64
```

`comparable()` 里**一个集合、一个字典、一个绝对路径都没有**。为什么这条如此重要？

```text
Python 的 dict 保留插入顺序，而插入顺序取决于"先遍历了谁"：
只要出现一个集合，repr 就会随构建顺序漂移，摘要随之失效
绝对路径会让同一份源码在两台机器上给出两个摘要
```

因此本模块在任何"集合 → 序列"的地方都显式排序：

```text
模块        按名字升序
声明名      按名字升序
重名表      按（-出现模块数, 名字）升序
```

这与 day101 的"倒排表里的文档名必须排序"、day102 的"族按包名升序 × 源码顺序排"、
day103 的"候选按 `(-len, name)` 排"是同一条纪律的**第四次**应用。
为了让它再也不能悄悄坏掉，这一课的测试里有一条**子进程测试**：
两个不同的 `PYTHONHASHSEED` 必须给出同一个摘要。

## 第八章：七条性质、六个失败族与五条边界

### 8.1 七条性质（三类判据齐全）

```text
1. catalog_covers_all_modules                | [equality   ] | 读数 0 ✓ | 模块 464 个 / 期望 464 个
2. catalog_is_reproducible                   | [equality   ] | 读数 0 ✓ | 摘要 …3b64 / …3b64
3. phantom_exports_are_sound                 | [equality   ] | 读数 0 ✓ | 幽灵 1 个 / 不成立 0 个
4. qualified_export_names_are_unique         | [equality   ] | 读数 0 ✓ | 重名条目 3187 个 / 不成立 0 个
5. duplicate_declarations_within_module      | [upper_bound] | 读数 0 ✓ | 重复 0 个 ≤ 上界 0
6. every_declaring_module_promises_something | [lower_bound] | 读数 1 ✓ | 最小承诺 1 ≥ 下界 1
7. export_names_are_reused_across_modules    | [lower_bound] | 读数 3187 ✓ | 跨模块重名 3187 ≥ 下界 1
合计：7/7 条通过
```

**四条相等、一条上界、两条下界**：

```text
⑥ 每个写了 __all__ 的模块至少承诺一个名字    空承诺是**从下面**兜住的
⑦ 至少有一个名字被两个以上模块导出           "有重名"这件事只能从下面兜住
⑤ 重复声明的模块数                          越少越好的量 ⇒ 兜的是上限
```

第 ⑥ 条在本课**真的贴着线**：最小承诺数是 **1**（下界也是 1）。
这意味着仓库里确实有几个"只承诺了一个名字"的模块——`every_declaring_module_promises_something`
读的就是它。**判据的阈值要定在"数学上必然成立"的地方**，而不是"我希望它长这样"的地方。

### 8.2 六个失败族

| 族 | 该谁去修 |
|----|----------|
| `ParseError` | 改解析：某份 `.py` 读不到或语法错时，先把它补进扫描范围或修好它 |
| `DeclareError` | 改声明：字面量 `__all__` 里混进了非字符串时，把它改成一份名字表 |
| `CatalogBuildError` | 改清单实现：两次构建不一致或同一模块重名时，去掉没有固定的量 / 重复项 |
| `BindingError` | 改源码或改声明：承诺没有落点时，要么定义出来，要么从 `__all__` 里删掉 |
| `NumericError` | 改数据或改实现：非有限读数与非法上下界都属于"数值不可用" |
| `ParameterError` | 改调用：承诺来源 / 绑定类别 / 性质名 / 上限都是调用点的一次决定 |

`FAMILY_OUTCOMES` 与 `_FAMILY_CLASSES` 逐键对齐，导入期断言。两条族常量：

```text
RETURNED_FAMILY = "CoverageError"
  day102 第一次给它命名，当时它记的是"某个子包没有 errors.py"——一句关于**覆盖**的话。
  day103（编图）没有它；day104 换了一个对象，问的却是同一个问题：
  "一个模块承诺了 N 个名字，这 N 个名字**落到了哪里**？"——
  一个承诺了却没有落点的名字，正是一种覆盖缺口。于是这个名字**回来**了。

ABSENT_FAMILY = "GradientError"
  本课是纯静态分析：不但没有反向，连一次 import 都不执行。
```

### 8.3 五条边界

```text
1. 不新增任何第三方依赖：解析只用标准库 ast。
2. 不改动任何既有模块、既有测试、pyproject 与 docs 下的既有文件——只新增文件。
3. 不做 import：读的是 __all__ 与 import **语句**（因此函数体里的延迟 import 也算一次绑定）。
4. 全部读数离线、确定性：只读文件系统与 ast，不联网、不读密钥。
5. 不判断承诺的好坏：只如实记录"谁承诺了什么、落到哪里"，不评价"该不该导出"。
```

## 结语：三条可以带走的工程结论

1. **先把"哪些文件必须进得来"说清，再谈读了什么。**
   本课的第一条性质是覆盖（464/464），它排在所有结构性质之前。
   一份没进清单的模块，与"这个模块什么都没承诺"在结果里读起来完全一样。

2. **一个承诺了却没有落点的名字，比一个报错更难被发现。**
   `__all__` 读起来永远像一份已经兑现的清单；因此本课把"幽灵"做成一条**读数**印出来，
   并用一条**独立复核**（挖掉 `__all__` 再看名字出现过没有）保证"报出来的幽灵都是真的"。

3. **"没有 `__all__`"不等于"没有承诺"。**
   三种来源必须分开记：写了字面量、写了但读不出来、根本没写。
   把三者混成一类，读者就会把"这份承诺没有被写下来"读成"这个模块什么都保证不了"。

> **诚实的说明**：本课是**离线、确定性**的——它不调用任何模型、不做任何推理，
> 也不测量"这份 API 设计得好不好"。它给的是**一套能带走的承诺纪律**：
> 当你真的要为一个代码库建一份对外清单时，知道该先收齐什么、
> 该给每个名字一个怎样的去向、该断言哪七件事。
