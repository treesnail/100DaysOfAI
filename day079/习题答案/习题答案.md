## 一、形状与组装

### 1.（手算）

```text
ffn_ratio        = 24 / 6 = 4.0
parameter_count  = 4·d + 2·d·d_ff + d_ff + d
                 = 4×6 + 2×6×24 + 24 + 6
                 = 24  + 288 + 24 + 6 = 342
四类来源：两个 LN 的 γ/β（2×(6+6) = 24）、w_in（24×6 = 144）、w_out（6×24 = 144）、
          b_in（24）、b_out（6）——前馈四块合计 318，再加两个 LN 的 24 = 342
```

注意力那一层的四个投影**不计**：它们在 day075 就已经在那里了，本课把它当**给定函数**，
于是"今天多了多少参数"才是一个能对上的数。

```bash
python -c "from smart_research_agent.encoder_decoder import BlockShape; s=BlockShape(6,24,4); print(s.ffn_ratio, s.parameter_count)"
# 4.0 342
```

### 2.（设计）

因为"块必须**保形**"这条性质需要 `tokens` 才能被**断言**：

```python
BlockForward.__post_init__:  matrix_shape(inputs) != matrix_shape(output) → ShapeError
```

如果每个函数各自去数行数，"块不改变形状"就只能靠每个实现点自律；
把它写进形状之后，"块能不能堆叠"变成一条**契约**（而不是一句注释）——
这与 day078 的 `PositionalShape` 里"两个字段必须相等"是同一手法。

### 3.（概念）

因为它们的**修法不同**：

```text
只有 ParameterError    heads/layers = 0（或 eps <= 0）→ 只需要改一个数
只有 AssemblyError     n_tgt == n_src 的交叉注意力上加因果掩码 → 两个部件要**一起看**
```

`AssemblyError` 继承 `ParameterError`，因此 `except ParameterError` 仍然兜得住它——
但错误消息能告诉调用方"这两个部件怎么接错了"，这是混在一个族里做不到的。

```text
target 4 行、source 6 行 → 权重 (n_tgt, n_src) = (4, 6)——**长方形**，不是方阵
把 source 也改成 4 行 → 权重 (4, 4)——退化成方阵（这正是"加错掩码不会报错"的温床）
```

## 二、LayerNorm 与逐行算子

### 5.（手算）

```text
μ  = 10/4 = 2.5
σ² = (2.25 + 0.25 + 0.25 + 2.25)/4 = 5/4 = 1.25        ← **有偏**（除以 d）
x̂（eps → 0）= (-1.341641, -0.447214, 0.447214, 1.341641)
x̂ 的方差   = σ²/(σ² + eps) = 1.25/1.25001 = 0.999992  → "离 1" 有 8.00e-06
```

```bash
python -c "print([round((v-2.5)/1.25**0.5,6) for v in (1.,2.,3.,4.)])"
# [-1.341641, -0.447214, 0.447214, 1.341641]
python -c "from smart_research_agent.encoder_decoder import layer_norm; out,c=layer_norm(((1.,2.,3.,4.),)); print([round(v,6) for v in out[0]]); print(abs(c.variance[0]/(c.variance[0]+c.epsilon)-1.0))"
# [-1.341635, -0.447212, 0.447212, 1.341635]
# 7.999936000535612e-06
```

### 6.（概念）

因为它**是 `eps` 的定义**，不是误差：

```text
x̂ = (x − μ)/√(σ² + eps)   ⇒   Var(x̂) = σ²/(σ² + eps) < 1，偏差 ≈ eps/σ²
```

`check_rows_are_standardized` 因此对每一行**分别**算期望值 `σ²_i/(σ²_i + eps)` 再比，
而不是拿"方差应当为 1"去比——后者的失败量与 `eps` 成正比，看起来像 bug 而其实是数学。

### 7.（概念）

```text
平移   LN(x + c·1) == LN(x)      **精确**
尺度   LN(λx)      == LN(x)      λ > 0，只精确到 O(eps/σ²)
```

平移不依赖 `eps`：`(x + c) − (μ + c) = x − μ` 逐位成立，而 `eps` 在分子分母里是同一个数。
缩放只在 `eps = 0` 时精确：分母是 `√(λ²σ² + eps)`，与分子的 `λ` 不再恰好抵消。
实测（本课样本）：

```text
加常数 3.5 前后的最大偏差 5.77e-15      ← 精确到浮点分辨率
乘正数 2.5 前后的最大偏差 2.11e-11      ← 由 eps 决定的那一档
```

### 8.（动手）

两条都用 `==`（不是容差）：

```text
LN(πx)  ==  π·LN(x)        置换 (3, 2, 1, 0) 下 True
FFN(πx) ==  π·FFN(x)       同上 True
```

因为它们都是**逐行 / 逐位置**算子：每一行的输出只依赖它自己那一行，
换行序只是把"同一批求和"重新排了个位置——**没有任何求和顺序的变化**，
因此浮点上也逐位相等。这与"两个都对的写法之间"的差（如 day076 的 `6.94e-18`）性质不同。

### 9.（设计）

```text
day078 的一半：additive_injection_breaks_permutation_equivariance（位置编码**打破**它）
day079 的另一半：norm_is_row_independent + feed_forward_is_position_wise（LN/前馈**不**打破它）
```

LN 的统计量在**行内**取（不跨行），前馈的每一行各自过一个两层网络——
两者都不引入跨行的求和，因此换行序时输出只是跟着换。
⇒ 合起来：**打破置换等变性的只有位置编码与掩码**。

## 三、前馈与残差

### 10.（手算）

```text
w_in  (d_ff, d) = (24, 6)       w_out (d, d_ff) = (6, 24)
b_in  (24)                      b_out (6)
参数  24×6 + 24 + 6×24 + 6 = 318
前向  (n, 6) → (n, 24) → (n, 6)     先扩张再压回
```

```bash
python -c "from smart_research_agent.encoder_decoder import feed_forward, make_block_parameters, BlockShape; p=make_block_parameters(BlockShape(6,24,4)); x=tuple(tuple(0.2*(i+1)+0.1*(j+1) for j in range(6)) for i in range(4)); o,c=feed_forward(x,p.ffn); print(c.summary_line()); print(p.ffn.parameter_count)"
# (4, 6) → (4, 24) → (4, 24)（relu，激活后零点占比 38.5%）
# 318
```

### 11.（概念）

ReLU 在 `x = 0` 处不可导，本包取**次梯度 0**：

```text
被关掉的神经元（激活前 <= 0）在反向里梯度**恰好是 0**
⇒ "激活后零点占比" = "这一批里有多少个神经元被关掉"
```

零点占比因此不是一个审美读数，而是一个**与反向直接对应**的读数。GELU 处处可导，
且 `GELU'(0) = 0.5`（`0.5(1 + erf(0)) + 0 = 0.5`）。

### 12.（概念）

```text
"关掉残差"是一个**开关**（use_residual），不是另一份实现：
  关掉之后整段代码路径不变，只是那一项 +x 没有了
⇒ 第 10 节的三个变体才能"一次只改一个旋钮"
```

两个分支都为 0 时：`output == inputs`（**逐位**）。判据用 `==`，
因为恒等映射没有求和顺序问题——这与"两条 LN 链仍在贡献"是两件事：
反向里 `‖dx‖/‖dy‖ = 1.000000`（本课样本）。

### 13.（动手）

```text
有残差 ‖dx‖ 变为原来的 1.13e+00      ← 几乎不动
无残差 ‖dx‖ 变为原来的 6.19e-02      ← 随分支一起被压小
两者相差 18.2 倍
```

倍数从**下界**来：带残差时 `dx = dy + O(s)`，那个 `dy` 不带任何雅可比，`s` 再小也在；
不带残差时 `dx = O(s)` 会与 `s` 一起趋零。这就是"残差是梯度的那条高速路"。

```bash
python -c "from smart_research_agent.encoder_decoder import *; from smart_research_agent.transformer_core.train import default_parameters; p=make_block_parameters(BlockShape(6,24,4)); a=default_parameters(6); x=tuple(tuple(0.2*(i+1)+0.1*(j+1) for j in range(6)) for i in range(4)); print(check_residual_unit_path(p,x,a).evidence)"
# ...两者相差 18.2 倍
```

## 四、九项梯度校验与口径

### 14.（概念）

```text
norm1_gamma → norm1_beta → ffn_w_in → ffn_b_in → ffn_w_out → ffn_b_out
                         → norm2_gamma → norm2_beta → inputs
```

注意力那一层的四个投影**不在**名单里：它的反向在 day075 已经逐项验过，
本课把它当**给定函数**（用它的 `grad_inputs` 接进程），
于是这九项全部落在今天新增的三个子层上。

### 15.（概念）

```text
norm1_gamma / norm1_beta 的比较点数 = d = 6      （每一个 γ/β 分量只有一个数）
ffn_w_in 的比较点数 = d_ff·d = 24×6 = 144
```

因为 γ/β 与两个偏置都被**所有行共用**：它们的梯度是"按行相加"的结果，
因此每一个分量只有**一个**数（不是每行一个）。`ffn_w_in` 则是一个整矩阵。

### 16.（概念）

漏掉第一项**不会报错**：

```text
dx = dOut + dNorm1_inputs + dNorm2_inputs
     ↑ 这一项就是残差那条 +1 的路
```

形状全对、训练也真的在动，只是梯度少了一条不减值的路。
症状：`inputs` 那一项梯度偏小（其余八项都过），而在深堆叠时表现为
"靠近输入的几层学得慢"——即第 10 节 `bare` 变体的那个现象。

### 17.（动手）

```text
pre-LN 残差 开     8.28e-11
pre-LN 残差 关     5.09e-11
post-LN 残差 开    3.61e-10
post-LN 残差 关    3.92e-10        容差 1e-6 → 隔着**四个**数量级
```

四组都能通过的结构性理由：两侧都走**同一个** `block_attention` 与 `encoder_block`，
而 `placement / use_residual / activation / causal` 由同一组参数一路传给两侧——
"忘了传"在结构上不可能发生，因此四组不是"碰巧都对"。

```bash
python -c "from smart_research_agent.encoder_decoder import *; from smart_research_agent.transformer_core.train import default_parameters; p=make_block_parameters(BlockShape(6,24,4)); a=default_parameters(6); x=tuple(tuple(0.2*(i+1)+0.1*(j+1) for j in range(6)) for i in range(4)); t=tuple(tuple(0.4 for _ in range(6)) for _ in range(4)); [print(pl,ur,f'{check_block_gradients(p,x,a,t,placement=pl,use_residual=ur).worst_scaled_error:.2e}') for pl in ('pre','post') for ur in (True,False)]"
```

### 18.（概念）

```text
① 损失口径    两侧都用 mean_squared_error（同一个函数）
② placement   两侧都是同一个 pre/post
③ use_residual 两侧都是同一个残差开关
④ causal      两侧都是同一个因果开关——**而它会影响注意力的输出**
```

四处由**同一组参数**传给两侧（见 `check_block_gradients`），因此"忘了传"不可能发生。
`causal` 是这一课新增的第四处：day076 的教训是"看到 1e-4 量级的差先怀疑口径"，
而因果开关恰好会把注意力输出整体换掉。

## 五、交叉注意力的长方形与两条链

### 19.（概念）

```text
Q = target·W_qᵀ     (n_tgt, d)      K = source·W_kᵀ   V = source·W_vᵀ   (n_src, d)
scores = Q·Kᵀ/√d    (n_tgt, n_src)   weights = softmax_rows(scores)   (n_tgt, n_src)
output = (weights·V)·W_oᵀ           (n_tgt, d)
```

权重是长方形，因为 K 的行数来自 **source**、Q 的行数来自 **target**——
两段序列长度不同，打分矩阵就只能是 `(n_tgt, n_src)`。

### 20.（概念）

```text
自注意力    四个投影作用在**同一个输入**上 → 列数必须相同（= d_in）
交叉注意力  W_q 作用在 target、W_k/W_v 作用在 source → 列数分别等于两路的宽度
W_k 与 W_v  都来自 source → 列数必须相同
```

否则"看哪些源位置"（K）与"取哪些源内容"（V）会指向两拨数据——
这正是 `CrossParameters` 用 `AssemblyError` 拒绝的那种"拼不起来"。

### 21.（概念）

```text
dTarget = dQ·W_q                            ← **只有一条链**（Q 只来自 target）
dSource = dK·W_k + dV·W_v                   ← **两条链之和**
```

少写一条**不会报错**，只会让梯度偏小；它会在 `source_inputs` 这一项里被抓出来
（第 22 题的比较点数也印证了：source 一侧比 target 多一些逐点）。

### 22.（动手）

```text
六项最大相对误差 5.77e-11（容差 1e-6）
target_inputs  24 个逐点（4 行 × 6 列）
source_inputs  36 个逐点（6 行 × 6 列）——比 target 多，因为 source 更长
```

```bash
python -c "from tests.encoder_decoder_samples import cross_parameters, inputs, source_inputs, target; from smart_research_agent.encoder_decoder import check_cross_gradients; r=check_cross_gradients(cross_parameters(), inputs(), source_inputs(), target()); print(f'{r.worst_scaled_error:.2e}'); print([(o.target,o.compared_points) for o in r.outcomes])"

```

## 六、八条性质与因果掩码

### 23.（概念）

```text
逐行（== 断言）   norm_is_row_independent、feed_forward_is_position_wise
关于残差          residual_is_the_identity_when_the_branch_vanishes、
                  residual_keeps_a_unit_path_in_the_gradient
关于交叉注意力    cross_attention_must_not_be_causal（最后一条）
```

其余的前三条是 LN 的（标准化、平移不变、正尺度不变）。

### 24.（推导）

```text
饱和时第 0 行的权重几乎全押在 source 的第 3 列：weights[0] ≈ (0, 0, 0, 1)
因果掩码（column <= row）下第 0 行只能看第 0 列：masked[0] = (1, 0, 0, 0)
最大逐点差 = |1 − 0| = 1.0（分母取 max(1, |ref|)，而权重都在 [0, 1] 内 → 分母 1）
⇒ 代价 1.00e+00
```

```bash
python -c "from tests.encoder_decoder_samples import inputs, saturated_cross_parameters; from smart_research_agent.encoder_decoder import cross_attention, causal_mask_damage; f=cross_attention(saturated_cross_parameters(), inputs(), inputs()); print(f'{causal_mask_damage(f)[0]:.2e}')"
# 1.00e+00
```

### 25.（概念）

因为交叉注意力面对的是一段**已经编码好**的源序列——它没有"未来"可言：

```text
因果性是**同一段序列内部**的性质（位置 i 不许看 i 之后）
交叉注意力的 K/V 来自另一路、已经编码完毕 → 加掩码只会把源序列的后半段删掉
```

失效方式"很坏"：只有在 `n_tgt == n_src` 时掩码形状才"恰好"合适——
那时它**不报错**，输出仍然是一张合法的权重表，而每一行能看到的源位置少了一半。
因此本包把它做成一条**显式拒绝**（`AssemblyError`），并**量出代价**（第 24 题）。

## 七、解码器块与深度实验

### 27.（概念）

相比编码器块多出来的三个（以及被换过的）：

```text
④ norm2 = LN(residual1)              第二个 LN（作用在第一个残差的输出上）
⑤ branch2 = 交叉注意力(·, encoder)    第二个子层——**K/V 来自编码器输出**（另一路）
⑥ residual2 = residual1 + branch2     第二个残差
```

核心差别就是"**K/V 来自另一路**"：自注意力的 Q/K/V 都来自解码器自己的流（必须因果），
交叉注意力的 Q 来自解码器、K/V 来自编码器（绝不能加因果掩码）。

### 28.（概念）

```text
① 自注意力不是因果的        → 解码器会在训练时直接看到要预测的下一个 token
② 编码器输出与解码器不同宽  → 交叉注意力要求 K/V 与 Q 落在同一个空间里
③ γ/β 不是三个              → pre-LN 的每个子层各有自己的 LN
```

它们都不是"一个函数拿了坏参数"，而是"**两个各自合法的部件拼不成一个整体**"：
`6` 与 `8` 各自都合法、三个子层各自都合法，但拼起来不成立——修法要同时看两处，因此单独成族。

### 29.（动手）

```text
交叉注意力在这一层里的权重 (n_tgt, n_src) = (3, 6)   ← 没有掩码
dDecoder 1.591693 | dEncoder 0.094432
```

`dEncoder ≠ 0`：交叉注意力的 **source 那一路**（K/V 来自编码器输出）会把梯度传回到编码器的输出上。
"解码器只读编码器的输出"这句话在**前向**成立，在**反向**不成立——
编码器输出会收到一股梯度（它是否传回编码器参数取决于调用方怎么用它）。
