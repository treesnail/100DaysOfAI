共 10 题，覆盖今天所有学习目标：subword 分词的动机、BPE 核心循环、WordPiece 与 SentencePiece 的差异、tiktoken 精确计数与降级、token 成本预估。建议完成时间：45~55 分钟。

## 第一部分：选择题

### 第 1 题（subword 分词的动机）

关于 subword（子词）分词，下列哪一项描述是**错误**的？

- A. 词级分词的词表无法覆盖所有词形变化与新词，未登录词（OOV）只能记成 `<UNK>`，信息彻底丢失
- B. 字符级分词永不 OOV，但序列长度爆炸，注意力计算量随长度平方增长
- C. subword 分词通过"常见词整体成 token、罕见词拆成片段"在两个极端之间取得平衡
- D. subword 分词依靠人工维护的构词法规则表来处理未登录词，因此需要语言学家长期维护

### 第 2 题（BPE 的合并选择）

BPE 训练循环每轮选择的合并对象是：

- A. 词表中最长的符号
- B. 按词频加权后，出现频率最高的相邻符号对
- C. 语义上最接近的两个符号
- D. 随机挑选的一对相邻符号（随机性是 BPE 多样性的来源）

### 第 3 题（WordPiece 的选择标准）

WordPiece 与 BPE 的训练循环骨架相同，区别在于每轮合并的选择标准。WordPiece 选择分数 `freq(pair) / (freq(a) * freq(b))` 最高的符号对，其含义是：

- A. 选择出现频率最高的对，与 BPE 完全等价
- B. 选择"结合得比偶然更紧密"的对——两符号共现相对于各自独立出现的期望越高，越值得合并
- C. 选择能使词表缩减最快的对
- D. 选择能使序列变短最多的对

### 第 4 题

BPE 依靠一个专门的"未登录词处理机制"（如 `<UNK>` 回退表）来解决 OOV；没有这套机制，遇到训练时没见过的词就无法编码。（对 / 错）

### 第 5 题

tiktoken 的 BPE 词表文件随 Python 包一起安装，因此 `tiktoken.get_encoding("cl100k_base")` 在任何刚装好包的机器上都能离线使用。（对 / 错）

### 第 6 题

在 cl100k_base 词表下，同样语义的文本，中文消耗的 token 数通常显著多于英文（实测约 3 倍），因此中文场景的 token 预算与 max_tokens 设置需要额外放大余量。（对 / 错）

## 第四部分：编程题

### 第 10 题（迷你 BPE 训练 + token 预算对比实验）

**功能要求**：

1. 在项目根目录新建 `scripts/token_budget_demo.py`，用 `bpe_demo.train_bpe` 在语料 `{"deep": 4, "deeper": 3, "deepest": 5, "learning": 6}` 上训练 16 轮合并，打印合并规则表，并断言：（a）第一条规则的 merged 为 `"de"`——`("d","e")` 与 `("e","e")` 频率并列 12（全场最高），字典序小者胜出，这正是训练确定性的体现；（b）`encode("deepest", merges)` 的结果为 `["deepest</w>"]`（最高频整词进入词表）；（c）`encode("deeply", merges)` 的结果为 `["deep", "l", "y", "</w>"]`——语料里没有 "deeply"，它从未出现过的词被拆成已知片段 `deep` 加字符兜底，这就是 BPE 解决 OOV 的现场演示。
2. 准备一组中英文混合的提示词样本（至少 2 条中文、2 条英文），用 `TokenCounter`（默认 tiktoken 路径）与 `TokenCounter(prefer_tiktoken=False)`（字符估算路径）分别计数，打印对照表，并断言：每条文本两种路径的计数都大于 0。
3. 用 `estimate_cost` 对同一条中文提示词分别按 `gpt-4o-mini` 与 `gpt-4o` 价格预估（设 `expected_completion_tokens=200`），打印两者总费用，并断言 gpt-4o 的预估费用严格高于 gpt-4o-mini。
4. 打印 `TokenCounter().backend` 说明本实验走的是哪条计数路径，最后打印"全部断言通过"。

**提示**：`estimate_tokens_chars` 对中文按 1 token/字估算，与 tiktoken 精确值的偏差本身就是观察点；`encode` 返回的符号含词尾标记 `</w>`。
