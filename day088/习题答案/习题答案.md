## 一、选择题

**1. B。** 一条原理要能被反驳，需要一个**能被解析的落点**（`artifact`，`resolve_artifact`
能把它解析成一个真实对象）与一个**能现场量出的读数**（`probe`）。
两者都没有的"原理"只能被相信，不能被检验。

**2. B。** `claims.py` **只有命题、没有数字**：它写 `statement / artifact / probe /
application / source_day`。读数全部由 `reconcile` 的探针现场算出——
某一天底层实现改了，读数会跟着改，而不会"悄悄地不再是真的"。

**3. C。** 抛 `CoverageError`，并且**消息里点名**是哪个应用。
本课实测："没有入边的应用：[]"（完整时为空）；
一旦故意去掉 `serving` 的支撑，`coverage_report()` 抛出的消息里就含有 `serving`。
一个没有依据的能力就是一句口号。

**4. D。** 两族的出路完全不同：`ReferenceError` 只要**把名字改对**（最轻的一族），
`ClaimError` 要**改写命题或重写探针**（要重读论文）。
混成一族会让"查论文"的人去看拼写，而"改拼写"的人去查论文。

**5. A。** 量化那一条是**上界判定**（实测误差 <= scale/2，两个操作数**不该相等**），
缓存公式那一条是**整数相等**（没有容差空间）。`upper_bound` 有值时走"≤"、无值时走"=="。
把两类混成一个判据，就会出现"实测误差恰好为 0（因为输入全是 0）被当成通过"。

**6. C。** 判据是"层的序号在 `LAYER_ORDER` 里**非递减**"。
同一个层用两节讲是允许的（非递减，而不是严格递增）。
本课实测的层次序是 `['math', 'attention', 'representation', 'inference']`。

**7. D。** 数学 2、注意力 4、表征 3、推理 3（合计 12）。
复算：`python -c "from smart_research_agent.principle_map import graph; print(graph.layer_coverage())"`
⇒ `{'math': 2, 'attention': 4, 'representation': 3, 'inference': 3}`。

## 二、简答题

**8.** 因为读数一旦被抄进 `claims`，它就有了两个来源，而**两个来源迟早会分家**：

```text
能失败    探针现场算出读数 ⇒ 底层实现改了，读数跟着改 ⇒ 这张图"能被反驳"
不能失败  读数抄进 claims   ⇒ 底层实现改了，读数不跟着改 ⇒ 这张图"永远看起来对"
```

前者的表现是"某条性质变红了"；后者的表现是"一切正常，而它已经错了三个月"。
本课因此把 `claims` 做成一张**只描述形状与落点**的表，数字全部留给探针。

**9.** `resolve_artifact("模块.函数")` 可能失败的两类原因：

```text
① 模块不存在   把 "math_foundations.attention" 写成 "math_foundation.attention"
               （少一个 s）⇒ 报 "模块 'smart_research_agent.math_foundation.attention' 不存在"
               修法：把模块名改对
② 属性不存在   把 "inference_optim.types.cache_bytes" 写成 "...cache_bytess"
               ⇒ 报 "模块 '...' 里没有 'cache_bytess'"
               修法：把函数名改对
```

**10.** 两条跨天对账：

```text
① 注意力行分布   reconcile.probe_attention_rows_are_distributions ↔ transformer_core.self_attention
                 比法：**容差 / 上界**（行和与 1 的偏差 <= 1e-9，本课实测 1.110e-16）
                 抓的错法：softmax 的分母漏了一部分（被掩码的位置参与了归一化）
② 缓存字节公式   reconcile.probe_cache_bytes_is_a_formula ↔ inference_optim.types.cache_bytes
                 比法：**整数相等**（五个长度上不等个数 0）
                 抓的错法：把 K 与 V 只算了一份，或把层数漏乘（差值是一个整数倍）
```

两条都调用**别的包**来算读数——自证是不成立的，跨包对账才是。

**11.** 因为"注意力排序 = 余弦排序"**不是恒真的**，它只在两个前提同时成立时才对：

```text
前提一  四个投影都是单位矩阵 ⇒ 打分 q·k 就等于输入的点积 x_i·x_j
前提二  每一行已归一化       ⇒ 点积 x_i·x_j 就等于余弦 cos(x_i, x_j)
```

两个前提缺一不可；再加上 softmax 单调，才有"排序完全一致"（实测秩相关 +1.000000）。
如果省略这两个前提，它就变成一句**对所有随机初始化都不成立**的断言——
而"断言不成立"与"实现写错了"在读报告时长得一模一样。
探针因此把前提交代清楚，而不是假装它恒真。

**12.** 如果某个探针偷偷读了时间戳或全局随机状态：

```text
第一次调用  读数 = f(时间/状态) 的第一组值
第二次调用  读数 = f(时间/状态) 的第二组值   ⇒ 两者**不逐位相同**
```

那么 `check_evidence_is_reproducible` 就会失败（不等个数 > 0），
而它的证据行会把"哪一条证据变了"印出来。
它与"图必须单次计算"是同一件事的两面：

```text
单次计算    默认那份图只构建一次（lru_cache），避免"每次看都不一样"
可复现      即便重新构建，读数也必须逐位相同——两条一起才让"图"成为一个可断言的对象
```

**13.** 落点写错（`cache_bytess` 多了一个 `s`）时的表现：

```text
build_graph 不会报错   它只把 Principle.application 填成边，不解析 artifact
失败的是 verify.check_every_principle_has_artifact：
  graph.resolve_artifact("inference_optim.types.cache_bytess")
  ⇒ importlib 找到模块 inference_optim.types，但没有 cache_bytess 这个属性
  ⇒ ReferenceError ⇒ 该条性质 passed=False，"失败：cache_bytes_is_a_formula（... 里没有 'cache_bytess'）"
```

修法：把 `artifact` 改回 `inference_optim.types.cache_bytes`。
复算：`python -c "from smart_research_agent.principle_map import graph; graph.resolve_artifact('inference_optim.types.cache_bytess')"`
会抛 `ReferenceError`，而 `...cache_bytes` 正常返回。

**14.** 它**先**报"应用没有被支撑"。


上面那段代码里每个 `Application` 的 `principles` 都是空的 ⇒ 六个应用全都没有入边 ⇒

## 三、推导题

**16.** （余弦只看方向）对 `k > 0`：

```text
cos(k·a, b) = (k·a)·b / (‖k·a‖·‖b‖)
            = k·(a·b) / (k·‖a‖·‖b‖)
            = (a·b) / (‖a‖·‖b‖)
            = cos(a, b)          ✔
```

即"把任一侧同向放大任意倍，余弦不变"。当 `k < 0` 时，分子多出一个负号、
分母 `‖k·a‖ = |k|·‖a‖` 是正的，于是：

```text
cos(k·a, b) = −cos(a, b)        （k < 0）
```

用得到 / 会出错：

```text
用得到    向量入库前归一化（把长度因素消掉，只留方向）——本课实测 cos(5a,a)=1.0
会出错    用"点积"当相似度时，长向量会因模长大而占便宜——那是"很长的文档看起来更相关"
```

复算：`python scripts/principle_map_demo.py` 第 4 节 "cos(5a,a) = 1.000000；cos(-a,a) = -1.000000"。

**17.** （注意力排序 = 余弦排序）对固定的 `i`，`scores[i][j] = (x_i · x_j) / √d`。
因为 `‖x_i‖ = 1`，有 `x_i · x_j = cos(x_i, x_j)`（单位向量的点积就是余弦）。
于是：

```text
scores[i][j] = cos(x_i, x_j) / √d          （√d > 0，是一个正的常数）
```

softmax 是按行作用的**严格单调**函数：对同一行里的两个下标 `j, k`，

```text
scores[i][j] > scores[i][k]  ⇔  exp(scores[i][j]) > exp(scores[i][k])
                             ⇔  weights[i][j] > weights[i][k]
```

而 `scores` 与 `cos` 只差一个正的常数因子 `1/√d`，它不改变大小关系。因此：

```text
weights[i][j] 的次序  ==  cos(x_i, x_j) 的次序          ✔
```

本课实测：峰值一致 5/5、top-2 重合 10/10、秩相关 +1.000000。
复算：`python scripts/principle_map_demo.py` 第 4 节。

**18.** （两个覆盖条件缺一不可）

反例一：只满足"每条原理都有落点"、不满足"每个应用都被支撑"。

```text
构造   把 serving 的 4 条原理全部删掉（其余不动）
读数   unsupported == ('serving',)；per_application['serving'] == 0
会误导  图看起来"十二条原理都在、都能量出读数"，而 serving 这个能力其实一句依据都没有——
        真到了部署那天，"为什么这个模型在卡上跑不起来"没有任何原理可以回答
```

反例二：只满足"每个应用都被支撑"、不满足"每条原理都有落点"。

```text
构造   让某个应用引用一条 artifact 拼错的原理（例如 cache_bytess）
读数   every_principle_has_artifact 失败："失败：cache_bytes_is_a_formula（... 里没有 'cache_bytess'）"
       而 every_application_is_supported 仍然通过（serving 还有另外几条原理）
会误导  每个应用都"有支撑"，于是没人怀疑；但那一条原理的名下指的是**空气**——
        它不可被检验，却让 serving 的支撑数从 3 变成 4
```

因此完整性是两个条件的**合取**：`complete = (not unsupported) and (not orphans) and
(not missing_evidence)`；缺任何一个，图都是坏的。
