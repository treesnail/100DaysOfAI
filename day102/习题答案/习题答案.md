## 一、速答

**1.** 扫描目标是每个子包里的 `errors.py`（`types.SCAN_FILENAME`），当前快照里 36 份
（35 份历史 + 本课这一份）。之所以是"每个子包一份"而不是"每个 `.py` 一份"：
失败族是**按包命名的一份契约**——一个包对外只承诺"我这一族错误叫什么、它是谁的子类"，
所以它天然是"包级"的。逐文件扫描会把同一族的定义读成很多份，反而看不出"这一族的根是谁"。

**2.** 判定顺序写死为 `local → builtin → imported`（都不是则 `unresolved`）。
顺序不能换，因为会出现撞车：
- 若先 `builtin` 后 `local`：某子包若自定义了一个 `ValueError`（合法），本模块的族会被误认成内置异常；
- 若先 `imported` 后 `local`：本模块里的族会被误认成"从别处导进来的同名字"。
`resolve.py` 的 docstring 第二节把这两句话逐字写出来了。

**3.** 没有 `local` 基类的是 `root`，有 `local` 基类的是 `sub`。
"每份恰好一个根"做成**相等**判据，是因为：0 个根只可能来自源码里的继承环（谁也不是根），
2 个根意味着读者要先猜"我该 `except` 哪一个"。两者都是"这一族的基类"这句话说不清的状态。

**4.** 两条具体好处：
- **不被掩盖**：一个语法错误会被 `import` 抛成 `ImportError`/`SyntaxError` 而看不出是哪一份；
  `ast.parse` 会把文件名与行号当场点名（`ScanError`）。
- **不触发副作用**：`import` 会把被扫描的包真的执行一遍（可能写文件、连网、读密钥）；
  `ast` 只读文本，因此"编台账"这件事是**离线、确定性**的。

**5.** 因为 Python 3.7+ 的 `dict` 保留**插入顺序**，而 `set` / `dict` 的迭代序取决于"先遍历了谁"。
只要 `comparable()` 里出现一个集合或字典，"两次构建逐位相同"就只取决于构建顺序，
摘要（`sha256`）也就失去意义。台账里所有"集合 → 序列"的地方都显式排序：
族按"包名升序 × 源码顺序"，归属表按 `BASE_KINDS` 的固定顺序。

**6.** 回来的族是 `ShapeError`（`RETURNED_FAMILY`）：它在 day075 由 `transformer_core` 命名，
此后被十来个包各写一遍，是本台账里跨包重名之最；day101 没有它，本课要把这些同名族摆在一张表上，
于是"一个族的名字 / 基类与它该有的对不上"重新需要一个控制流事件。
缺席的族是 `GradientError`（`ABSENT_FAMILY`）：本课是一次纯静态扫描，一行张量运算都没有跑。

## 二、对照

**7.** day101 的"两种语料"解决的是**文件名撞车**：`docs/backprop.md` 与子包 `backprop`
同名，于是给名字加种类前缀（`doc:` / `subpackage:`）。
本课的"四类归属"解决的是**基类名撞车**：`ShapeError` 既是"本模块的族"，
也是"从 `transformer_core` 导进来的别名"，还是"内置异常名（理论上）"，
于是给每一个基类名一个 `kind`——两者都是"**宁可当场变红，也不要让两件不同的东西共用一个名字**"。

**8.** 相等（4 条）：① 覆盖 ② 名字唯一 ③ 可复算 ④ 每包恰好一个根；
上界（1 条）：⑤ 未解析基类数 `<= 0`；下界（2 条）：⑥ 最小基类数 `>= 1`、⑦ 最大继承深度 `>= 1`。
把方向写反的后果：把 ⑥⑦ 写成相等（`== 1`）会在"某族写了两个基类"或"链变深"时**误报失败**；
一条被关掉的性质等于不存在。把 ⑤ 写成下界则会在"未解析变成 0"这种**变好**的时候误报失败。

**9.** `LedgerBuildError` 管**自洽**：同名冲突、两次构建不同 ⇒ 改台账实现（去掉未固定的量）。
`CoverageError` 管**完整**：某个包没有 `errors.py`、或某个族没被收进台账 ⇒ 改台账范围。
一个问"这张表自己说得通吗"，一个问"这张表少没少一页"。

## 三、诊断

**10.**
- `CoreShapeError` → `imported`，`target = "smart_research_agent.transformer_core.errors.ShapeError"`
  （来自 `from ... import ShapeError as CoreShapeError` 的别名表）；
- `StackError` → `local`，`target = "StackError"`（本文件里定义的族）。
两者都**不是** `unresolved`；若把 `CoreShapeError` 的 import 删掉，它就会掉进 `unresolved`，
被 `base_references_resolve`（上界判据）当场点名。

**11.** 例子：某子包既 `from somewhere import ValueError as ValueError`，又自己定义了 `class ValueError(Exception)`。
- 正确顺序（`local` 在前）：`ValueError` 判为 `local`，指向本模块的族；
- 错误顺序（`builtin` 在前）：它被判成 `builtin`，于是台账谎称"这一族的父类是 Python 内置的 `ValueError`"，
  而实际上它是本模块自定义的那个。现象：报告不报错，但"这一族的基类是谁"读错了。

**12.** 三种可能：
- 某条 `import ... as ...` 的别名表没被收进 `ScanModule.aliases`（例如用了 `ImportFrom` 之外的写法）⇒ 改解析；
- 基类写了属性形式（如 `errors.ShapeError`）而别名表里没有 `errors` ⇒ 改解析或改成带别名的导入；
- 源码里真的写错了一个名字（拼写错误、或引用了不存在的模块）⇒ 改源码。
三者都会让 `unresolved` 不为 0，因此 `check_base_references_resolve`（上界判据）会失败。

**13.** 会抛 `LedgerBuildError`（消息含"不在同一包里"）。
因为 `local` 的语义是"**同一模块内部**"：一个 `local` 基类名在同一份 `errors.py` 的族里找不到，
说明这条归属本身是坏的。这里**必须当场报**而不是"当成根"：
若当成根，这一族的深度会被算成 0，报告会**全绿**，而"它的父族其实是缺的"这件事被吃掉——
这与 day101 "空查询要抛而不是返回空名单"是同一条纪律。

## 四、推导与动手

**14.** `AError` 是根 ⇒ 深度 0；`BError` 的 local 父族是 `AError` ⇒ 深度 1；
`CError` 有两个 local 父族 `BError`、`AError`，深度取**最大值的父族再加 1**：
`max(1, 0) + 1 = 2`。所以不是 3——深度是"到根的最长路径"，多写一个父族不会让路径变长。

**15.** 证明：
- 根的定义是"没有 `local` 基类"。`class A(B)` 的基类 `B` 是本模块的族 ⇒ `A` 是 `sub`；
- 同理 `class B(A)` ⇒ `B` 也是 `sub`；
- 该模块里没有任何族是 `root` ⇒ 根数 = 0 ≠ 1 ⇒ 性质 ④ 失败；
- 算深度时，`depth(A)` 需要 `depth(B)`，`depth(B)` 又需要 `depth(A)`，
  递归栈里再次遇到自己 ⇒ 抛 `LedgerBuildError`（"继承里出现环"）。∎
