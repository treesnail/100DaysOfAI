## 一、速答

**1.** `prompt` 是同一个提问，`chosen` 是更被偏好的回答，`rejected` 是更差的回答。
它是"第一种没有唯一正确答案"的数据，因为 SFT 数据是"输入 → 唯一输出"、评估数据是
"输入 → 参考答案 + 合格判定"，而偏好数据只告诉你"**A 比 B 好**"——
在两种都说得通的答法里更偏好哪一种，这没有唯一答案。

**2.** 五个维度：`citation`（给出处）、`format`（格式合规）、`conciseness`（简洁）、
`refusal`（安全边界）、`honesty`（不编造）。
写进数据的原因是：**偏好标注的分歧几乎总发生在"维度不明确"的时候**——
同一条回答在"信息更全"上更好、在"更简洁"上更差，标注者按各自的维度打分会得到相反的结果。
把维度写在每条样本里，是降低标注噪声**最便宜的手段**（比增加标注人数便宜得多）。

**3.** `margin = (policy_chosen − policy_rejected) − (reference_chosen − reference_rejected)`，
四个参数都是**对数概率**（整条序列的逐 token 对数概率之和）。
它不含 β 是为了让 margin 保持"纯数据"的语义：**换 β 不改变 margin，只改变它对 loss 的影响强度**。

**4.** 未训练时策略就是参考模型，两个模型对同一个序列的对数概率逐位相同，
于是 `l_c − r_c = 0`、`l_r − r_r = 0`，`margin = 0`，`−log σ(0) = ln 2 ≈ 0.6931`。
它能发现"ref 或 β 接错了"这类接线错误（它们在日志里只表现为"loss 有点怪"）。
但它**发现不了**梯度符号错误——因为起点 `margin = 0` 时方向还没显形，
符号错误要**走几步之后**（p(chosen) 下降）才看得出来。

**5.** 隐式奖励是 `r(x,y) = β·(logπ_θ(y|x) − logπ_ref(y|x))`，即策略与参考模型的对数概率比乘 β。
三个推论：
① 参考模型一动，全部隐式奖励一起平移（**所以参考模型必须冻结**）；
② β 同时缩放奖励与 KL 约束，两者没法独立调；
③ 训练初期（π_θ = π_ref）所有隐式奖励都是 0，排序信息为零。

**6.** `k1 = log p − log q` 有偏且可能为负（偶尔会"奖励"偏离参考模型）；
`k2 = 0.5(log p − log q)²` 恒非负但方差大；`k3 = exp(r) − r − 1` 恒非负、方差最小、无偏，
代价是它需要 `exp`。
三个都报是因为**"只报一个"会掩盖它们的分歧**：训练早期 k1 常常给出负数，而 k3 已稳定为正。

## 二、对照

**7.**

```text
RLHF（PPO）：偏好 → 训奖励模型 r(x,y) → 最大化 E[r] − β·KL(π_θ ‖ π_ref)
DPO       ：偏好 → 直接优化 −log σ( β·[(logπ_θ(y_w)−logπ_θ(y_l)) − (logπ_ref(y_w)−logπ_ref(y_l))] )
```

差别本质是"偏好怎么进到策略里"：RLHF 先把偏好**蒸馏成一个奖励模型**，再用强化学习最大化
"奖励减 KL 惩罚"；DPO 跳过奖励模型，把偏好**直接写成策略上的监督式损失**——
其中"与参考模型的对数比"这一项，正是 RLHF 里那个 KL 惩罚的另一种写法。
两者在数学上汇合到同一个最优策略 `π* ∝ π_ref·exp(r/β)`。

**8.** 共同点：都是"**留出**数据上的可复现判据"，且都要求**分母交出来**
（`total` / `correct`）。必须用留出数据是因为训练集上的 margin 会**单调地涨**
（那是被直接优化的量），只有留出数据能回答"涨到什么时候开始有害"。
用训练集 margin 当早停判据，等价于"训练 loss 降到 0 就停"。

**9.** `over_optimization_flags` 是**运行时读历史给出的旗标**（三条判据），
`ALIGNMENT_RISKS` 里的"过优化"是**静态的风险描述**（症状 / 缓解 / 检测手段），
两者是"检测实现"与"风险台账"的关系。
`DEFAULT_KL_BUDGET` 定义在 `reward` 而不是 `dpo_trainer`，是为了**避免循环导入**：
KL 预算是"读历史"的判据，属于 `reward` 的职责；训练器只负责把历史交出来。

## 三、诊断

**10.** loss 一开始就是 0.8 而不是 ln 2，三种可能：

```text
① ref 接错了     参考模型不是"策略的副本"，括号里的差一开始就不为 0
② β 接错了       括号里是 0 但 β 不是预期的值（−log σ(β·0) = ln 2 对任何 β 都成立，
                 所以这只有在"margin 不是 0"时才成立——即 ① 的变体）
③ 数据有偏置     chosen 与 rejected 规范化后不同但长度差极大，策略与参考模型
                 并非严格同一份权重（例如加载了旧检查点）
```

实际上，若 margin 精确为 0，`−log σ(0) = ln 2` **与 β 无关**，所以 loss 偏离 ln 2 只能是
"margin 不是 0"——也就是策略与参考模型不是逐位相同的同一个模型（ref 接错）。

**11.** 因为"chosen == rejected"在 DPO 里**不产生任何梯度**（margin 恒为 0），
而它在数据统计里仍然计一条。于是：分母被稀释 → 有效的那些样本的梯度被"摊薄" →
loss 看起来在降（因为有效样本仍在学），但**每一对无信息样本都在让训练变慢、
且让人误以为数据量是够的**。它不会报错，只会表现为"跑过了却学得很少"。

**12.** 因为 loss 的**梯度符号**被写反了。`∂(−log p)/∂logits = softmax − onehot` 是交叉熵的
梯度，而 DPO 需要的是**对数概率**的梯度，两者相差一个负号。符号反了之后，
每一步都让 p(chosen) **下降**、p(rejected) **上升**，于是 margin 越来越负、
loss（`−log σ(β·margin)`）在 margin 很负时按 `−β·margin` **线性增长**。
整个过程没有任何一步"非法"，所以不会报错——只有"走几步之后方向要对"的用例能抓住它。

**13.** 因为"chosen 更长"可能是**维度本身决定的**，不是偏置。本课种子数据实测
`chosen_longer_fraction = 0.8333`，但拆开看是两股相反的力：`citation` / `honesty`
的 chosen 更长（要写出处、要说明不确定性），而 `conciseness` 的 chosen 更短
（这一维度的目标就是更短）。所以 `length_bias_report` 必须给**逐维度分解**，
而不是只看总量上的一个比例。

## 四、推导与动手

**14.** 给定 `β = 1`、`l_c = −2`、`l_r = −3`、`r_c = −2.5`、`r_r = −2`：

```text
① margin = (l_c − l_r) − (r_c − r_r) = (−2 − (−3)) − (−2.5 − (−2)) = 1 − (−0.5) = 1.5
② dpo_loss = −log σ(1 · 1.5) = −log σ(1.5) ≈ −log(0.8176) ≈ 0.2014
③ dpo_gradient = −1 · σ(−1.5) = −σ(−1.5) ≈ −0.1824
```

**15.** `dpo_loss_from_margin(0, beta) = −log σ(β·0) = −log σ(0) = −log(1/2) = ln 2`。
其中只用了 `σ(0) = 1/2`，与 β 无关，因此对任意 `β > 0` 恒等于 `ln 2`。□

**16.** 由定义 `σ(x) = 1/(1 + e^{-x})`：

```text
σ(x) + σ(-x) = 1/(1 + e^{-x}) + 1/(1 + e^{x})
             = (1 + e^{x} + 1 + e^{-x}) / ((1 + e^{-x})(1 + e^{x}))
             = (2 + e^{x} + e^{-x}) / (2 + e^{x} + e^{-x}) = 1
```

（分母 `(1 + e^{-x})(1 + e^{x}) = 1 + e^{x} + e^{-x} + 1 = 2 + e^{x} + e^{-x}`。）□

**18.** "过优化"是**仓库（训练过程）的真实状态**，而不是"工具算错了"——
把"必须无过优化"写成一条性质，会在任何一次合理的、甚至是有益的训练里变红
（例如一次恰好在过优化边界上的运行），最后一定会被人关掉；而一条被关掉的性质等于不存在。
本仓库里"是读数、不是失败"的真实例子：day103 的依赖图有 4 个环（环是**读**出来的，
不是删掉的）、day102 的 18 个子包没有 `errors.py`（覆盖情况，不是错误）。
判断标准一句话：**当现象是"仓库的真实状态"就印出来，只有当它是"工具自己算错了"才让性质变红**。
