## 第二部分：判断题

### 第 7 题（day037）

Function Calling 的本质是从"靠提示词求格式"升级为"靠结构化 `tool_calls` 协议保证格式"；`FunctionSpec.from_tool` 直接从 `BaseTool` 生成 schema，让 schema 与工具实现同源、永不漂移。（对 / 错）

### 第 8 题（day038~041 契约）

day038 建立、后续接口沿用的错误码契约是：请求不合法 → 422，合法但资源不存在（如点了不存在的模型）→ 404，全局未捕获 → 500 统一 `ErrorResponse`。（对 / 错）

### 第 9 题（day040）

视觉请求可以直接走普通 `chat` 发给纯文本模型，只要消息里带图片文本描述即可；无需经 `supports_vision` 过滤。（对 / 错）

### 第 10 题（day041）

`EmbeddingProvider.embed_batch` 被设计成抽象方法，所有提供方必须实现，否则无法实例化。（对 / 错）

### 第 11 题（day038）

`/agent/run` 端点应当跨请求复用同一个 `FunctionCallingAgent` 实例，因为 Agent 无状态、只读。（对 / 错）

### 第 12 题（day041）

`InMemoryVectorStore` 定义了 `__len__`，空向量库的布尔值为假；用 `store or InMemoryVectorStore()` 做默认值回退，会把调用方传入的空库静默替换成新库，因此必须用 `is not None` 判断。（对 / 错）

## 第五部分：编程题

### 第 16 题（综合编程 · Function Calling 协议 + 语义 Embedding 离线验证）

**功能要求**（基于 day041 快照，离线可跑，不调任何网络）：

1. **工具调用协议**：构造 `CalculatorTool`，用 `specs_from_tools([CalculatorTool()])` 生成 `FunctionSpec` 列表，断言只生成 1 个规格、其 `name == "calculator"` 且 `parameters` 中 `required == ["expression"]`。
2. **脚本化模拟**：用 `MockLLM(tool_call_responses=[{"tool_calls": [{"name": "calculator", "arguments": {"expression": "(1 + 2) * 3"}}]}])` 调用 `llm.chat_with_tools(messages, tools=[spec.to_openai_tool() for spec in specs])`，对返回结果用 `parse_tool_calls` 解析，断言得到 1 个 `ToolCall`、其 name 为 `calculator`、`arguments["expression"] == "(1 + 2) * 3"`。
3. **执行与校验**：把解析出的参数交给 `CalculatorTool().execute(expression=...)`，断言结果是 `"9.0"`（字符串）。
4. **语义 Embedding**：用 `CharNgramEmbedding()` 分别编码两组句子：近义对（"我喜欢学习机器学习" 与 "我爱学习机器学习"）与无关对（"我喜欢学习机器学习" 与 "今天晚饭吃什么"），用 `cosine_similarity`（复用 `memory/vector_store` 里的实现）分别计算相似度，断言：近义相似度 > 0.5、无关相似度 < 0.5、且近义 > 无关。
5. 打印每一步的关键中间值，最后打印"全部断言通过"。

**提示**：`MockLLM.chat_with_tools` 的 `tool_call_responses` 脚本形如 `{"tool_calls": [{"name": "...", "arguments": {...}}]}`，返回前会规整为 OpenAI 兼容格式；`parse_tool_calls` 接受该返回 dict；`CalculatorTool.execute` 返回结算结果字符串；`cosine_similarity` 可自行用点积计算（向量已归一化，点积即余弦）或复用库内实现。
