## 第一部分：选择题

### 第 1 题（提示词的 v1 → v2）

关于两份受管模板与三个版本号，下面哪一句是**对的**？

- A. 版本号只是一个标签，落不到清单里就当默认值处理：`prompt_version="v3"` 会静默回落到 `v2`，因为"没见过的一版"按缺省走更省事，报错反而会让上游多写一层 try
- B. v2 比 v1 多出来的 262 字只是排版代价：多出来的四个小节标题与空行让它读起来更清楚，**约束的条数与内容没变**（两版都是 4 条），因此"换个版本"不会改变答案的任何性质
- C. `DEFAULT_PROMPT_VERSION` 与 `CURRENT_PROMPT_VERSION` 今天是同一个值（都是 `"v2"`），因此它们其实是同一个常量、可以合并成一个；换版本时改哪一个都一样，反正两处都会一起指过去
- D. **两份模板的四个数字是钉死的：v1 = 238 字、v2 = 500 字；同一份上下文（6 条片段、417 字）渲染出来 v1 = 649 字、v2 = 911 字，差 262 字、比值 1.4037——因为渲染差值恰好等于模板差值（模板里那两个占位符在两份模板里逐字相同）。v1 没有一个小节标题、只有 4 条编号条目；v2 有 `['## 资料片段', '## 问题', '## 约束', '## 输出格式']` 四个小节标题与 9 条编号条目（约束 6 + 输出格式 3），多出来的两条约束各自挡一种真实失败（固定拒答句式让"模型自己说没有"可检测、引用格式让覆盖率这两笔账才有意义）。`PROMPT_VERSIONS = ("v1", "v2")` 是封闭清单，`CURRENT_PROMPT` / `CURRENT_PROMPT_VERSION` 指向 v2，而 `"custom"` 不在 `RAG_PROMPTS` 里却是合法取值——它精确地表示"这一份提示词来自调用方"**

### 第 2 题（引用溯源：四个编号与两张行）

关于一次核对折出来的四组编号与逐编号检查行 `checks`，下面哪一句是**对的**？

- A. `[9]` 与 `[0]` 是同一类问题、应当都进 `invalid`：一个越了界、一个是 0 号，两者都指不到任何片段，因此"幻觉引用的条数"应当把它们一起数进去
- B. **四组编号的方向必须分清：`cited` 来自答案（升序去重）、`valid` 是 `cited` 里真的落在提示词里的、`invalid` 是落不到提示词里的（`record_id is None` 的那几行）、`unused` 是给了它却没被引用的；`[0]` 不是编号（编号从 1 起），它不进 `cited/valid/invalid` 任何一项、只进报告自己的注记；`checks` 的顺序是先 `1..n`、再按升序接上越界编号，因此行数 = 给出去的片段数 + 幻觉引用的条数。实测（上下文固定 4 条片段）：（无）→ `[] / [] / [] / [1,2,3,4] / 0.0000 / False`；`[1]` → `[1] / [1] / [] / [2,3,4] / 0.2500 / True`；`[1][2][3]` → `[1,2,3] / [1,2,3] / [] / [4] / 0.7500 / True`；`[1][9]` → `[1,9] / [1] / [9] / [2,3,4] / 0.2500 / False`；`[0]` → `[] / [] / [] / [1,2,3,4] / 0.0000 / False`（与"无"逐位相同）；6 条片段时报 `[1][2]` 是 6 行（`unused [3,4,5,6]`），报 `[1]` 与 `[9]` 是 7 行（第 7 行是 `[9]` 的幻觉引用行）**
- C. `checks` 是按"答案里出现的先后"排列的，越界那条的 `used` 应当是 `False`（毕竟它没有被真正引用到），因此读 `checks` 时要先按 `marker` 排序才能与人手算的行对齐
- D. `given` 应当作为第 9 个字段**存下来**：它等于 `len(citations)`，多存一份比每次算出来更保险，也让报告不必依赖"提示词编号 1 起连续"这条约定

### 第 3 题（`coverage` 与 `grounded` 的定义）

关于覆盖率与接地判定，下面哪一句是**对的**？

- A. `grounded` 可以用字符串比较算出来：看答案里有没有"资料中没有相关内容"这样的句子——这样实现更省事，而且只要兜底文案改一个字也不会失效
- B. `coverage` 的分母应当是"模型看见的全部编号"，因此幻觉引用（`[9]`）也要算进分母：模型既然写得出 `[9]`，就说明它认为这次给了 9 条片段
- C. **两个定义都写在代码里、且都能用纸笔验算：`coverage = round(len(valid) / 给出去的片段数, 4)`（与 `PackedContext.fill_ratio` 同一个四舍五入口径；分母是提示词里真正给出去的片段数，不是检索召回的条数、也不是答案引用的条数——被预算丢掉的尾部不在提示词里，模型看不到它们；给出去 0 条时是 0.0，不是除零异常）；`grounded = valid 非空 且 invalid 为空`，它是算出来的，构造期还会用 `expected = bool(valid) and not invalid` 反查这个字段，口径不一致直接报错。实测：4 条片段下 `1/4 = 0.2500`、`2/4 = 0.5000`、`3/4 = 0.7500`、`4/4 = 1.0000`；进位与截断各自至少一条（`1/3 → 0.3333` 截断、`2/3 → 0.6667` 进位、`1/7 → 0.1429` 进位、`2/7 → 0.2857` 不进位、`3/8 = 0.375` 精确）；`[1][9]` 那一行是本表里唯一"看起来引了东西、但不接地"的样本——`valid` 非空但 `invalid` 也非空，于是 `grounded = False`，而它的 `coverage` 仍然是 `0.2500`（两个数各说各的）**
- D. `coverage` 用 `round(…, 2)` 就够了：两位小数在报告里更好读，四位小数是过度精确，而且会让"1/3 与 2/3"这种样本产生不必要的争议

### 第 4 题（六种回退与四格矩阵）

关于 `fallback_reason` 的六种取值与它们的处置，下面哪一句是**对的**？

- A. 回退应当合成一个布尔标志（`has_fallback`）：六种原因写成一列自由文本就够读了，统计"这一批里有几次不可交付"只需要那个布尔——多一个清单反而让端点协议变复杂
- B. `llm_error` 那条路上 `llm_called` 应当是 `False`：调用抛了异常就等于"没调用成功"，把 `True` 写进去会让"这次到底调没调"变成一个骗人的数字；`empty_reply` 与 `model_declined` 则应当合并成一种（都是"模型没给出可用的答案"）
- C. **六种情形的判定顺序写死在 `FALLBACK_REASONS = ('no_context', 'llm_error', 'empty_reply', 'model_declined', 'unusable_citations')` 里（顺序即优先级），`FALLBACK_REASON_NONE = ''` 是"没有回退"的哨兵，`FALLBACK_REASON_DESCRIPTIONS` 有 6 个键（含这个哨兵）；`answer` 取谁按原因分级——`no_context` / `llm_error` / `unusable_citations` 取兜底答复，`empty_reply` 原样保留那个空串，`model_declined` 保留模型原文，正常路径取模型原文；`llm_called` 只有 `no_context` 是 `False`（其余四条回退都是 `True`，因为它们都真的调过模型）；四格矩阵（`require_citation` × 有没有合法引用）里只有一格回退：`False × True → '' / is_fallback=False`、`False × False → '' / False`、`True × True → '' / False`、`True × False → 'unusable_citations' / True`（只有这一格的 `answer` 换成兜底答复，被丢弃的原文长度记进 `notes`）**
- D. 空回复应当归到 `model_declined`：两者都是"模型没给出可用的答案"，而 `fallback_reason` 的六个取值本来就是给统计用的，合并之后"这一批有几次没答上来"更直观

### 第 5 题（九步流水线与参数的三个层级）

关于 `RAGGenerator.generate` 的九步与三个参数来源，下面哪一句是**对的**？

- A. 九步里"渲染提示词"应当在判空之前：先把提示词渲染出来，报告里才有 `prompt_text` 可看；至于 `no_context` 那条路，`llm_called=False` 只是表示模型返回了空串
- B. 逐次覆盖提示词版本就可以换模板：`generate(..., prompt_version="v1")` 在**任何**生成器上都会换成 v1 那份模板，因此注入自定义模板之后再覆盖版本号，等价于"临时换成受管模板"
- C. 逐次覆盖参数的清单是开放的：多传的键（例如把 `max_tokens` 拼成 `max_token`）应当静默忽略，因为报错会让上游的通用转发函数每一处都要多写一层白名单
- D. **九步的顺序是固定的（解析 → 空上下文早退 → 渲染 → 调用（宽捕获 `Exception`）→ 空回复判定 → 解析 `[n]` → 拒答判定 → 引用开关 → 正常路径），而且每一步的顺序都用得上：第 2 步排在渲染与调用之前，因此 `no_context` 那条路上 `llm.calls == 0`、`prompt_text == ''`、`citations == ()`、`answer == FALLBACK_NO_CONTEXT`、`latency_ms ≈ 0.423`；第 6 步排在第 7、8 步之前（拒答判定与"一条合法引用都没有"都要读核对结果，而核对是纯字符串对账、不花钱）；逐次覆盖的键是封闭清单 `GENERATION_OVERRIDE_KEYS = ('temperature', 'max_tokens', 'prompt_version')`，清单外的键当场报 `GenerationError` 并列出合法取值，而且校验发生在任何一次模型调用之前；提示词文本不允许由请求体传入（要换模板请在装配期 `prompt=...` 注入，版本号记为 `'custom'`），而对一个注入了自定义模板的生成器逐次覆盖版本号时，覆盖无法生效、只记一句"覆盖无法生效"进 `notes`**

## 第二部分：判断题

### 第 6 题

`no_context` 是一条"调过了但没答案"的路：它发生在渲染提示词**之后**，因此 `prompt_text` 一定
非空（否则报告里看不出"这次问的是什么"）；而 `llm_called=False` 的真实含义是"模型被调用了，
但返回了一段空串"——所以清点"这一批里有几次没让模型发挥"时，`no_context` 应当与
`empty_reply` 一起算。（对 / 错）

### 第 7 题

因为"固定句式"太脆（模型可能换个说法），v2 用一种更鲁棒的启发式代替它：只要答案里出现
"资料"两个字，或者答案与那三个 `DECLINE_MARKERS` 的编辑距离足够近，就判 `model_declined`；
并且由于 `unusable_citations` 是更"硬"的一道闸门，`require_citation=True` 时命中拒答句式的
答案会先落到 `unusable_citations`（第 8 步排在拒答判定之前）。（对 / 错）

### 第 8 题

`Generation.to_summary()` 是 `to_dict()` 的一个子集：两者都是 14 个键，摘要是把
`prompt_text` **截短**之后再放进去的那一份（要看全文就传 `include_prompt=True`）；而
`GroundingReport` 的三组编号、`coverage` 与 `grounded` 都可以手工拼出来，构造期只检查它们
是不是升序去重的整数元组，不与 `grounded` 交叉校验——因此"报告里的数字互相矛盾"这件事
只能靠读的人自己发现。（对 / 错）

### 第 10 题（回退族、两道护栏与四格矩阵）

  [1][9]       | [1, 9]       | [1]        | [9]      | [2, 3, 4]      |   0.2500 | False
