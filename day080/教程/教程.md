## 第一章：为什么"复制 N 份"值得一课

### 1.1 前五天各交出了一件事

```text
day075   一层可训练的自注意力      回答"怎么混合"
day076   把它切成 heads 份        回答"看什么"
day078   把"第几位"加进输入        回答"在哪"
day079   三个子层拼成一个**块**     回答"一块怎么造"
day080   把那个块复制 N 份         回答"一摞怎么接"
```

"接"这件事看上去只是一行 `for`，而它带来一个**只有堆叠里才存在**的问题：

```text
一块    输入与输出必须同形（day079 的一条断言）
一摞    第 i 层的输出必须**正好**是第 i+1 层的输入
        —— 而"正好"这个词有两种读法：
           形状对（弱）      两个 (n, d) 装得下
           逐位对（强）      中间没有被重算一遍
```

今天把判据定在**强**的那一侧，并且用 `==` 断言。理由在 1.3 节。

### 1.2 于是今天的架构是"一条链 + 两张名单 + 一个实验"

```text
types.py     形状、五个阶段、六条性质、两份梯度名单、三种记录（读数 / 前向账 / 反向账）
layers.py    链式前向、链式反向、逐层读数、两个置零开关
verify.py    两处梯度校验（整条链的输入 / 第 k 层的八块参数）+ 六条性质
assembly.py  把形状编译成一段 PyTorch 脚本文本，再用 ast 解析回结构
study.py     堆叠实验：2 变体 × 6 档深度（**这一课的值钱结论**）
```

### 1.3 一条纪律：**逐位可断言的绝不留容差**

```text
保形                  形状是整数 ⇒ 可以逐位
链上传递              两条路径同一串浮点运算 ⇒ 必须逐位
确定性                没有随机数 ⇒ 两次调用逐位相同
每一层分支全零即恒等    IEEE 下 x + 0 精确 ⇒ 逐位
参数量                整数 ⇒ 逐位
```

留下容差的只有两处：数值差分的梯度校验（resolution 决定）与两个**读数**之间的比较
（范数是浮点累积量）。**把容差放在能逐位的地方**，是本课最省事的一条纪律。

## 第二章：五个阶段与那条链

### 2.1 五个阶段

```text
① enter    校验输入形状；把它当作第 0 层的输出（只做一次）
② block    第 i 层：LN → 注意力 → ⊕ → LN → 前馈 → ⊕（day079 的六个阶段）
③ census   记下这一层的 ‖x_i‖、‖y_i‖、两个分支的范数与直通占比
④ carry    把 y_i 交给第 i+1 层——块保形，因此这一步在数学上不可能失败
⑤ exit     返回 y_N：它与输入逐位同形
```

演示脚本第 2 节逐行打印这张表，而 `STAGE_SHAPES` 给出的关键信息是：
**五个阶段全都不改形状**。

```text
enter/block/carry/exit   (n, d) → (n, d)
census                   (n, d) → (n, d) + 一行读数：**记账不碰张量**
```

### 2.2 前向的三行

```python
attention = block_attention(block_params, current, attention_params, placement=placement)
forward = encoder_block(
    block_params, current, attention,
    placement=placement, use_residual=use_residual, activation=activation,
)
current = forward.output
```

注意这里**没有**重复 day079 的摆放位置逻辑：`block_attention` 是 day079 为那个坑
（5.3 节：数值侧看不到的链，解析侧也不能算）专门引入的构造函数，
今天直接用它——**同一个构造函数负责"造"与"用"**这条纪律因此自动继承下来。

### 2.3 `StackForward` 的三条构造检查

```text
① 输入与输出同形                 （块保形 ⇒ 链保形）
② (n, d) 与 shape 的 (tokens, hidden) 一致   （形状与账必须来自同一次前向）
③ 第 i 层的输出 == 第 i+1 层的输入（**逐位**），且 output == 最后一层的输出
```

第三条第 ② 项是本课新增的严格性：`StackShape` 里有 `tokens` 与 `hidden`，
而它们**必须**与张量对得上——否则"我按这个形状算的参数"与"我实际喂进去的东西"
会是两回事。

## 第三章：三个"漏掉不会报错"的地方

这是本课最值钱的一章，因为三处错误的**形状都是对的**。

### 3.1 前向：传递的是"值"，不是"重算一遍"

```text
对的   current = forward.output
错的   current = 重新跑一遍 encoder_block(...).output       ← 数值差 1e-16 量级
```

错法在单层上几乎看不出来，而在链上它会累积；更要紧的是它让
**性质 2（与手写循环逐位一致）** 失去意义——如果两边都"重算"，
那条断言就只是在比较两次相同的重算。

### 3.2 反向：那一行换手

```python
for index in reversed(range(forward.depth)):
    layer = forward.layer_at(index)
    layer_grads = encoder_block_backward(layer.block, layer.params, current, activation=...)
    grads[index] = layer_grads          # 先存账（按层号）
    current = layer_grads.grad_inputs   # 再换手
```

漏掉第三行会退化成：

```text
错的   每一层都拿 dLoss/dy_N 当 grad_output
       ⇒ 第 0 层收到的梯度只反映了**最后一层**的影响
       ⇒ 形状全对、损失曲线看起来也在动，而第 0 层的 dW_in 相对差 2.18e-01（第 11 章实测）
```

`2.18e-01` 这个量级正是最像 bug 的那一档：比数值分辨率大十个数量级，
又比"真的写错了"小一个数量级。

### 3.3 记账：范数要用 `math.fsum`

一层读数是一个平方和。链长了之后普通求和会累积出 `1e-13` 量级的偏差——
而今天的读数是**要跨层比较**的（"第几层开始塌"），两个数必须同口径。

## 第四章：形状与参数量（342 / 144 / 486 / 1944）

### 4.1 三个可手算的数

```text
样本：d = 6，d_ff = 4d = 24，n = 4，N = 4

块参数   4d（两个 LN 的 γ/β）+ 2·d·d_ff（两层线性）+ d_ff（b_in）+ d（b_out）
         = 4×6 + 2×6×24 + 24 + 6 = 24 + 288 + 24 + 6 = 342
注意力   4d² = 4×36 = 144            （day075 起就在那里，今天**不新增**）
一层     342 + 144 = 486
整条链   4 × 486 = 1944
```

`StackShape` 把前三者做成三个**属性**，而不是一个公式里的中间量：

```text
block_parameter_count       块自己新增的那一份
attention_parameter_count   注意力那一份（来源不同：它属于 day075）
layer_parameter_count       一层合计
total_parameter_count       层数乘上去
```

理由在第六章会用到：**解析式与逐块数出来的两个数要分开算**。
只写一边时，"公式错了"与"构造漏了一块"无法区分。

### 4.2 `flatten()` 为什么只压平块参数

```text
flatten()  →  4 × 342 = 1368 个数（**不含**注意力那 4 × 144 = 576 个）
unflatten(flat, shapes, attentions)  →  注意力原样带回
```

因为"需要被逐分量更新的"与"只是被携带的"是两件事。这一条在一次真实的
（且麻烦的）时刻会变成问题：如果哪天注意力也要被优化器更新，
`flatten` 的口径就必须改，而**改口径这件事必须显式**，不能悄悄发生。

## 第五章：逐层读数 —— 增益与直通占比

### 5.1 样本的实测表

演示脚本第 3 节的原始输出（4 层、残差开、0.25 初始幅度）：

```text
    层 |         ‖x‖ |         ‖y‖ |        增益 |      ‖分支一‖ |      ‖分支二‖ |     直通占比
  ----------------------------------------------------------------------------------
    0 |    0.781025 |    1.747158 |  2.237007 |   1.114224 |   0.764351 |   0.2937
    1 |    1.747158 |    2.078160 |  1.189451 |   0.482152 |   0.860416 |   0.5655
    2 |    2.078160 |    1.687401 |  0.811969 |   0.890196 |   0.450274 |   0.6079
    3 |    1.687401 |    1.932848 |  1.145458 |   0.402814 |   0.561668 |   0.6363
```

三个口径：

```text
gain          ‖y_i‖ / ‖x_i‖                      这一层把整体尺度放大了多少倍
carry_share   ‖x_i‖ / (‖x_i‖ + ‖b1‖ + ‖b2‖)       输出里有多少来自残差那条直通路
max_abs_input 入口元素的**最大绝对值**            这是一个单点读数，不是范数
```

### 5.2 表里有一处能直接看出来的自洽

第 0 行的 `‖y_0‖ = 0.781025` 与第 1 行的 `‖x_1‖ = 0.781025` **逐位相同**。
这不是巧合，而是"链上传递的是同一个值"在读数表上的样子——
第七章的第 1 条性质就是逐层核对它。

### 5.3 两条必须写下来的约定

**其一：`gain` 在 `‖x‖ = 0` 时返回 `0.0`。**

```text
返回 nan   会静默污染整张表（"第 2 层开始增益全是 nan" 看不出是哪一步坏了）
返回 1.0   看起来像"这一层什么都没干"，而它其实是"这一层的输入是零"
返回 0.0   在一张增益表里是**显眼的**：任何一次真实的堆叠都不会出现它
```

**其二：`carry_share` 在残差关时**恰好**是 `0.0`。**

第一版把它写成纯比例（与残差开关无关），于是同一张表里的 `0.30`
既可能指"三成来自直通"，也可能指"残差其实关着"。修法是把 `use_residual`
记进读数：

```text
残差 开 | 直通占比 ['0.2937', '0.5655', '0.6079', '0.6363']
残差 关 | 直通占比 ['0.0000', '0.0000', '0.0000', '0.0000']
```

这一条与 day079 的 `eps` 是同一类纪律：**读数必须能自己解释自己**。

## 第六章：链式反向与两处梯度校验

### 6.1 `StackGradients` 在构造时钉死两件事

```text
① 每一环的 grad_inputs 与整条链的 grad_inputs 同形
② grad_inputs 恒等于第 0 环的输入梯度
   —— 否则"整条链的输入梯度"与"最底层那一环"会指两个不同的东西
```

条目 ② 的措辞是刻意的：一个记录里同时有"整条链的输入梯度"与"第 0 层的输入梯度"
两个字段，它们**必须**是同一个东西，而这件事由构造检查来保证，而不是靠调用方小心。

### 6.2 逐层 `‖dx‖`：day079 的一个数变成一条序列

```text
   层号 |        ‖dx‖ | 与上一层的比
      0 |    0.317052 |            —
      1 |    0.286225 |     0.902771
      2 |    0.257685 |     0.900288
      3 |    0.227080 |     0.881232

   链内首尾之比 ‖dx_0‖ / ‖dx_3‖ = 1.396209
   整体比       ‖dx_0‖ / ‖dy_N‖ = 1.561036（分母 ‖dy_N‖ = 0.203104）
```

这两个量**不是同一个数**——`dy_N` 不在 `dx` 序列里（第十二章那条恒等式讲的就是这件事）。

day079 的深度实验只印了**最底层那一个数**（用来看"传得到不到"）；
今天把每一层都留下来，于是"梯度在第几层开始塌"从一个结论变成一个可以画出来的序列。
第 11 章正是拿这条序列做的实验。

### 6.3 两处校验的名单

```text
kind=stack  名单 (stack_inputs,)              整条链的输入梯度（1 项）
kind=layer  名单 八块参数（**不含** 'inputs'）   第 k 层的参数梯度（8 项）
```

**为什么 `layer` 那一份里没有 `inputs`**：中间层的输入不是自变量，它由前一层算出来。
把它当成可扰动对象，会让"这一层的输入"在链上指两个不同的东西。

**为什么必须查第 0 层**：如果反向写成"每层都从 `dLoss/dy_N` 起步"，
**最后一层是完全正确的**（它的 `grad_output` 本来就是 `dLoss/dy_N`），
因此只在最后一层做校验会全绿。数值侧的做法是标准的"扰动一块、重跑整条链"——
它天然知道"这一层的改动要穿过上面所有层才影响损失"，而错法不知道。

### 6.4 四组口径必须两边一致

```text
参数         两侧用同一个 StackParameters
placement    两侧都是同一个 pre/post
use_residual 两侧都是同一个残差开关
activation   两侧都是同一个激活
```

它们全部由**同一组参数**传给两侧，而两侧都走同一个 `stack_forward` 与
同一个 `stack_loss`——因此"忘了传"在结构上不可能发生（day079 6.3 节的同一条纪律）。

### 6.5 实测

```text
stack 梯度校验 1 项：通过 1、失败 0 | 最大相对误差 8.23e-11
    stack_inputs 8.23e-11

layer 梯度校验 8 项：通过 8、失败 0 | 最大相对误差 7.92e-11
    norm1_gamma 5.36e-11、norm1_beta 7.89e-11、ffn_w_in 7.92e-11、ffn_b_in 3.99e-11、
    ffn_w_out 6.20e-11、ffn_b_out 2.05e-11、norm2_gamma 4.43e-11、norm2_beta 4.64e-11
```

容差 `1e-6`，实测 `1e-10` 量级——**隔着四个数量级**。

## 第七章：六条性质

| 性质 | 前提 | 失败意味着 |
|------|------|-----------|
| `stack_preserves_shape_at_every_layer` | 任何链 | 某一层改了形状（于是它不能被复制） |
| `stack_matches_a_hand_written_loop` | 任何链 | 中间多过一次运算，或**参数错位了一层** |
| `stack_is_deterministic` | 任何链 | 引入了不该有的随机性 |
| `stack_is_the_identity_when_every_branch_vanishes` | 两个分支都为零（含注意力） | 残差那条 +1 路没生效 |
| `analytic_parameter_count_matches_construction` | 任何链 | 公式错了，或者构造漏了一块 |
| `generated_torch_assembly_carries_the_same_shape` | 任何链 | 生成器与形状脱钩（数字被写死） |

实测：

```text
性质检查 6 项：通过 6、失败 0
```

### 7.1 三条必须说清的地方

**其一：性质 4 的两个分支里"注意力"那一支不在参数里面。**

```text
前馈那一支      由 BlockParameters 的 w_in/b_in/w_out/b_out 决定 → 置零 w_out/b_out 即可
注意力那一支     来自 day075 的 AttentionParams（today 的参数包里**没有它**）
                ⇒ 必须单独置零
```

因此 `check_stack_identity_when_branches_vanishes` 内部**自己**做这两次置零。
这带来一个反直觉的后果：**传一份"只关了一半"的参数进来，这条性质也会通过**。
所以"只关一个分支 ⇒ 不是恒等"这个负例不能挂在性质上（那会得到一个永远为真的断言），
它必须另外做——`tests/test_stack_layers.py` 里的 `test_only_the_ffn_out_zero_is_not_enough`
就是那个负例。

**其二：性质 2 用 `==` 而不是容差。**

两条路径做的是**同一串浮点运算**，因此它们必须逐位相等。
把参数错位一层会让它立刻亮红——而那类错误**不会**以形状错误的形式出现。

**其三：性质 6 是在"文本层"上核对的。**

它从生成的脚本里把 `CONFIG` 读回来逐键比。这一条的失败方式很具体：
生成器里某个数字被写死成 `6`，而形状换成了 `8`——脚本仍然能跑，只是不是这个模型。

### 7.2 一条跨天的守卫在等着我们

第 7 条性质之外，还有一个配置**一定会失败**，而失败的方式很值得记下来：

```text
残差关 + 分支全零（前馈 w_out 与注意力四个投影都置零）
  一层    算得完：输出是全零矩阵（零矩阵是一个合法的结果）
  两层    第二层的注意力拿到**全零行** ⇒ day075 的 NumericError
```

day075 的 `self_attention` 显式拒绝全零行（它的 softmax 会给出均匀分布，
而"均匀分布"与"还没学到"看起来一样）。这不是 bug，而是**两天的判据在这里接上了**：

> 一个把输入压成全零的堆叠，在 day075 的眼里就是一次"不该交给这一层猜"的调用。

## 第八章：`is` 不是判据（一处很细的边界）

`StackForward` 在构造时会过一遍 `validate_matrix`，而它返回的是一份**重建**的等值元组。
因此：

```text
forward.layers[0].block.output == forward.layers[1].block.inputs   →  True（逐位）
forward.layers[0].block.output is forward.layers[1].block.inputs   →  False（不是同一个对象）
```

第一版把这条性质写成 `is`，于是它在 `==` 成立的地方亮红——而那不是 bug。
修法是把判据写清：

```text
本课承诺      链上传递的是**同一个值**（逐位相等）
本课不承诺    它是同一个**对象**（记录会重建一份等值元组）
```

这一条与 day079 的 `eps` 是同一类教训：**判据必须与定义对齐**，
否则它训练出来的只是"看到红先怀疑判据"的坏习惯。

### 9.2 脚本里最要紧的三行

```python
self.norm1 = nn.LayerNorm(hidden, eps=float(CONFIG["epsilon"]))

self.blocks = nn.ModuleList([TransformerBlock() for _ in range(int(CONFIG["layers"]))])

def forward(self, inputs):

    for block in self.blocks:
        current = block(current)
    return current
```

**和本课的 `stack_forward` 是同一个 `for`。**

## 第十章：参数量对不上不是误差

```text
本课解析式                        4d²           四个 (d, d) 投影，**没有**偏置
nn.MultiheadAttention(bias=True)  4d² + 4d      q/k/v 合进 in_proj_weight 并带 in_proj_bias，
                                              out_proj 也带偏置
样本差值                          96 = N × 4d = 4 × 4 × 6
```

这不矛盾，而是**两份不同的接口约定**：

```text
day075 的 AttentionParams   只有四块矩阵（q/k/v/o 各一块）
PyTorch 的 nn.MultiheadAttention
                            把 q/k/v 三块合成 in_proj_weight（3d × d）并加 in_proj_bias（3d），
                            out_proj 是 d × d 加 d 个偏置 ⇒ 合计 4d² + 4d
```

**把它凑平是最坏的处理方式**（那样下一次差异出现时就没有参照物了）。
正确的做法是把两个数都打印出来、把差值讲清：

> 差异必须被看见，而不是被凑平。

## 第十一章：堆叠实验 —— 每层倍数与总深度无关

> 这是这一课唯一"值钱"的结论。完整数据在 `docs/transformer_stack.md` 第 10 节。

### 11.1 问题只有一个

```text
每经过一层，‖∂loss/∂x‖ 平均乘上多少倍？  而这个"每层倍数"随**总深度**变不变？
```

两个变体，一次只改一个旋钮：

```text
residual   y = x + F(LN(x))     现代实现的主流（残差开）
bare       y = F(LN(x))         **把那一项 +x 关掉**（同一条代码路径）
```

三个读数：

```text
overall_ratio      ‖dx_0‖ / ‖dy_N‖                     整条链把 loss 梯度放大/缩小了多少倍
mean_step_ratio    ‖dx_{i+1}‖/‖dx_i‖ 的**几何平均**       "每层乘上多少"的单一数字
output_drift       ‖y − x‖ / ‖x‖                        前向把输入搬离了多远
```

### 11.2 实测

```text
  变体     |   层数 |     整体比 |   每层倍数 |  输出漂移 | 参数量
  residual |    1 | 1.502475 | 1.000000 | 1.666201 |  486
  residual |    2 | 1.531613 | 0.693868 | 2.175905 |  972
  residual |    3 | 1.425915 | 0.884230 | 1.570048 | 1458
  residual |    4 | 1.561036 | 0.894712 | 1.906604 | 1944
  residual |    6 | 1.688102 | 0.902509 | 3.175736 | 2916
  residual |    8 | 1.614977 | 0.948060 | 2.604913 | 3888
  bare     |    1 | 0.209805 |  1.000000 | 1.547405 |  486
  bare     |    2 | 0.084865 | 11.097718 | 1.257904 |  972
  bare     |    3 | 0.132918 |  3.292021 | 1.164696 | 1458
  bare     |    4 | 0.089017 |  1.430753 | 2.228565 | 1944
  bare     |    6 | 0.003398 |  2.060385 | 1.549745 | 2916
  bare     |    8 | 0.000069 |  3.121139 | 1.397810 | 3888
```

三个读法：

```text
residual  整体比在 1.43 ~ 1.69 之间**来回摆**，没有随深度塌下去
          每层倍数极差 max/min = 1.441197（< 2 ⇒ 与深度无关）
bare      整体比从 2.10e-01 一路塌到 6.90e-05（8 层）
          每层倍数自己就开始乱跳（极差 11.097718）——**逐层形状是噪声**
```

判决 `verdict_ok` 是两条一起成立：

```text
① 最深一层上 bare < residual / 10      （本课实测 6.90e-05 vs 1.61e+00）
② 残差开的每层倍数极差 < 2              （本课实测 1.441197）
```

条件 ② 是今天新增的：一个**与深度无关**的因子应该落在这条线内。
把"残差有用"的判据只定成条件 ①（day079 的做法）会漏掉一个问题——
bare 那一列在 2 层时是 `1.11e+01`、4 层时是 `8.90e-02`：它是**非单调**的。
单看终点是对的，而那条曲线的形状说明"关掉残差之后梯度一定单调衰减"这句话本身是错的。

### 11.3 这一章的三条边界

**其一：它回答的是"每层倍数是多少"，不是"能训多深"。**

```text
它回答      "每层梯度乘上多少、它与深度有没有关系"（一个**数值**问题）
它不回答    "这摞块能不能训好"——那要看损失曲线、学习率与数据（day081 接手）
```

而且 `overall_ratio` 大于 1 **不一定是好事**：那同样可能是"梯度在放大"。
这一条读数只说明**那条路没有被掐断**。

**其二：深度 1 那一行的每层倍数是 `1.0`，是一个真实读数。**

深度 1 没有相邻对，因此几何平均按定义返回 `1.0`（乘法的单位元）。
它被算进极差里——把它悄悄排除掉会让条件 ② 的检验少一档。

**其三：这份表是一次观测。** 一颗种子、一个初始化幅度、一条深度序列——
要下"残差一定更好"的结论需要多种子与统计检验（day076 的同一条纪律）。

## 第十二章：这一课埋的两个伏笔与一处写错过的文档

### 12.1 文档写错过一次：几何平均的那条恒等式

第一版把 `mean_step_ratio` 的解释写成"整体比 = 各层 step 相乘"。
而 4 层链上的实测立刻否掉了它：

```text
逐层 ‖dx‖ = 0.317052, 0.286225, 0.257685, 0.227080
相邻比值   = 0.902771, 0.900288, 0.881232
几何平均   = 0.894712；0.894712³ = 0.716225
‖dx_last‖ / ‖dx_0‖ = 0.716225  ← 逐位对上
而 ‖dx_0‖ / ‖dy_N‖ = 1.561036  ← 另一个量
```

正确的是：

```text
mean_step_ratio ^ (N − 1)  ==  ‖dx_{N−1}‖ / ‖dx_0‖      ← 链**内部**首尾之比
overall_ratio              ==  ‖dx_0‖   / ‖dy_N‖        ← 链的入口与损失之间
```

原因是**数一数个数**：`dx` 序列有 N 个数、只有 N−1 个相邻比值，
而 `dy_N` **不在那个序列里**。这条恒等式现在有一条测试直接钉住它
（`test_the_identity_holds_on_a_real_chain`）。

> 带走一条：**"两个读数看起来是一回事"是最容易写进文档的错误**，
> 而它的修法只有一条——把恒等式写出来，然后在一段真实数据上核对它。

### 12.2 一处被测试顺手抓到的坑：只关前馈不够

第一版的性质 4 负例写成"只把前馈的 `w_out` 置零 ⇒ 输出不等于输入"，
而它**通过了**——因为性质函数内部会自己把注意力也置零。
两件事必须分开写：

```text
性质函数     自己负责关两个分支（因此传什么进来都通过）
负例         必须用 stack_forward 手工构造（tests/test_stack_layers.py）
```

> 带走一条：**一条永远为真的断言比没有断言更坏**，因为它占据了一个"已验证"的位置。
