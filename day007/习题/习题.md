## 第一部分：选择题

### 第 1 题（工程化底座）

关于 `pyproject.toml` 中 `dependencies` 与 `[project.optional-dependencies].dev` 的划分，下列说法**正确**的是：

- A. 两者没有区别，只是写法不同
- B. `dev` 依赖会随 `pip install .` 一起装进生产环境
- C. 运行时依赖（如 pydantic）放 `dependencies`，测试与检查工具（如 pytest、ruff）放 `dev`，生产环境只装前者
- D. `dev` 依赖是给 DevOps 工程师专用的依赖

### 第 2 题（配置管理）

使用 Pydantic Settings 管理配置，"失败要趁早（Fail Fast）"指的是：

- A. 程序出bug时立刻崩溃退出
- B. `Settings()` 在程序启动时即完成环境变量解析与类型校验，配置错误在启动阶段就暴露，而不是运行到一半才失败
- C. 测试失败时不允许重试
- D. 配置文件不存在时静默使用默认值

### 第 3 题（Git 对象模型）

下列关于 Git 的说法，**错误**的是：

- A. Git 存储的是快照（tree），不是差异（diff）
- B. 内容相同的文件在不同 commit 间共享同一个 blob，不重复占用空间
- C. 创建一个分支需要复制当前分支的全部文件
- D. commit 对象的 ID 由其内容（tree、父提交、作者信息等）哈希得出

### 第 4 题（Docker 分层缓存）

Dockerfile 中把 `COPY requirements.txt ./` + `RUN pip install -r requirements.txt` 放在 `COPY` 源码**之前**，原因是：

- A. requirements.txt 文件比较小，先复制更快
- B. Docker 按层缓存：某层内容变化后其后所有层缓存失效。依赖层变化频率低放前面，源码层变化频率高放后面，改代码时依赖层可命中缓存
- C. pip 必须在源码存在之前安装，否则会报错
- D. 这是 Python 官方文档的强制要求

### 第 5 题（Agent 与 ReAct）

关于 ReAct 范式，下列说法**正确**的是：

- A. ReAct 是一种需要专门训练的模型架构
- B. ReAct 循环的驱动者是 LLM 本身，LLM 决定何时继续、何时停止
- C. ReAct 是"prompt 格式约定 + 外部代码循环"：LLM 按 Thought/Action/Action Input/Final Answer 格式输出，Python 循环负责解析、执行工具、回填 Observation
- D. ReAct 中 Observation 由 LLM 自己生成

### 第 6 题（工具安全）

`CalculatorTool` 用 AST 白名单而非 `eval()` 求值，根本原因是：

- A. eval 执行速度慢
- B. 工具输入来自 LLM 输出，属于不可信输入；eval 会执行任意 Python 代码（如 `__import__('os').system(...)`），AST 白名单只放行明确允许的节点类型
- C. AST 可以处理更复杂的数学函数
- D. eval 不支持中文表达式

### 第 16 题（编程题 · 实现新工具）

参照 `CalculatorTool` 的写法，实现一个 `WordCountTool`（单词计数工具），要求：

1. 继承 `BaseTool`；
2. `name` 为 `"word_count"`；
3. `description` 用中文写清楚用途，例如"统计一段文本的单词数量（按空白字符切分）"；
4. `parameters` 声明一个必填的字符串参数 `text`；
5. `execute(text=...)` 返回单词数的字符串形式；空字符串或纯空白应返回 `"0"`；
6. 编写不少于 3 个测试用例（普通句子、空字符串、含多个连续空白的文本），放入 `tests/test_word_count.py`。

提示：`"hello world".split()` 按任意空白切分且自动忽略连续空白。

### 第 17 题（综合编程题 · 驱动完整 ReAct 循环）

使用 day006 快照中的 `ReactAgent`、`MockLLM`、`ToolRegistry`、`CalculatorTool`（以及你第 16 题写的 `WordCountTool`，可选），编写一个**离线可运行**的脚本/测试，完成以下任务：

任务：计算 `(12 + 8) * 5` 并回答。

要求：

1. 组装好注册表与 Agent（`max_steps=5`）；
2. 用 MockLLM 预设两段回复：第一步调用 calculator 计算，第二步给出 Final Answer；
3. 运行 `agent.run(...)`，断言最终答案中包含 `"100"`；
4. 断言 `agent.history` 长度为 2，且第一步的 `action` 是 `"calculator"`；
5. 断言 MockLLM 第二次收到的消息中包含 `"Observation: 100"`（注意 `20.0 * 5` 之类表达式结果的字符串形式，想好你的 Action Input 怎么写）。

### 第 18 题（综合编程题 · 解析器边界情况）

`parse_react_output` 是 Agent 与 LLM 之间的关键边界。请编写一个测试文件 `tests/test_parser_extra.py`，覆盖以下边界情况（每个一条测试）：

1. **Thought 多行**：Thought 跨两行，随后是 Action/Action Input，断言两行都进了 `thought`；
2. **Final Answer 带尾部空白/换行**：如 `"Thought: 完成\nFinal Answer: 42\n\n"`，断言 `final_answer == "42"`（无首尾空白）；
3. **只有 Action 没有 Action Input**：应抛出 `ReActParseError`；
4. **Action Input 多行**：Action Input 的值本身跨两行，断言两行都被捕获；
5. **Final Answer 优先**：一段输出同时包含 Action 字段和 Final Answer 字段时，按当前实现，断言结果是哪一`种形态，并解释为什么。
