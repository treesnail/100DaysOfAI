# day099 习题答案：结业项目整合（一）—— 把八项能力装成一条可复算的链

> 参考答案。每题都尽量给出"**结论 / 读数** + **看源码的哪里** + **怎么复现**"。
> 涉及的模块都在 `smart_research_agent/capstone/` 下，读数可用
> `python scripts/capstone_demo.py` 复现。

## 一、速答

**1.** **"装上了"= `import` 得到；"接上了"= 一次端到端调用里九段都真的跑过、
且同一输入两次运行逐位相同。** 后者被做成 `assembly.SystemRun.is_identical_to`
（以及 `comparable()` / `diff_count()` / `digest()`）——**一条元组比较**就能证明
"这条链是好的"。

**2.** 中文（英文阶段名）：

```text
护栏（guard）→ 规划（plan）→ 检索（retrieve）→ 打包（pack）→ 生成（generate）
→ 接地（ground）→ 评估（evaluate）→ 记账（account）→ 追踪（trace）
```

出处：`types.ASSEMBLY_STAGES`（9 条），导入期与 `STAGE_DESCRIPTIONS` 做闭合断言。

**3.** 因为**手写表会分家**：名字写错、包被删掉、包改名，手写表都察觉不到，
而报告照常打印"覆盖 8/8"。`manifest.resolve_subpackage` 用 `importlib` **真的解析**
一次（存在性 + 公开符号数），于是"覆盖 8/8"这句话是**算出来的**。

**4.** 无 `__all__` 时，本课**按目录数子模块**（`pkgutil` 遍历 `__path__`），
这样结果**与导入顺序无关**。不能直接用 `dir(module)`：`dir()` 的内容取决于
"谁先 import 过它"（导入会往命名空间里塞名字），于是同一个清单跑两次会给出两个数。

**5.** 适配层存在的唯一理由是**把各个子系统各不相同的返回形状收敛成"九种统一读数"**，
让报告不依赖任何子系统的内部类型。"上游改了"时，改动**只落在适配层的那一行**
（`adapters.py`），装配与判据不动。

**6.** 因为护栏是唯一一处**能省下后面所有花费**的阶段：把一次攻击话术拦下来，
检索与生成就一次都不会跑。若把它放到"生成"之后，攻击串**已经进了模型上下文**，
且已经付过一次钱——护栏就只是"事后声明"，不是防线。

**7.** 两个减法叫**截断**（单条太长被截）与**丢尾**（整条超出预算被丢）。
本课读数都是 0：`打包：147/600 字 | 引用 3 条 | 截断 0 / 丢尾 0`。
必须分开报是因为两者的**处置方式不同**：截断要调"单条预算"，
丢尾要调"总预算或 k"，混成一个数就不知道该拧哪个旋钮。

**8.** 三组编号是**有效引用**（答案引用了、提示词里也有）、**幻觉引用**
（答案引用了、提示词里没有）、**未引用**（提示词里有、答案没用到）。
本课读数：`有效 1 / 幻觉 0 / 未引用 2 | 覆盖 33.3%`。
"未引用 2"**不是错误**——它是"给了 3 条、只用了 1 条"这个**事实**，
该做的事是调预算或调提示词，而不是修生成。

## 三、对照计算

**10.**

```text
召回 = 命中金标准 / 金标准总数 = 1 / 1 = 1.0000
精确 = 命中金标准 / 返回条数   = 1 / 3 = 0.3333
MRR  = 1 / 第一条金标准的位置  = 1 / 1 = 1.0000
```

召回满分是因为**金标准只有 1 条、而且它回来了**；精确只有 1/3 是因为
返回了 3 条（`k-3`、`k-2`、`k-6`），其中只有 1 条是金标准。
**两个数必须一起读**：只看召回会以为"检索完美"，只看精确会以为"检索很糟"。
（`NDCG 1.0000` 是分级折损后的归一化值，理想排序也是满分。）

**11.** "手算走的是公式"= `input_no × price_in + output_no × price_out` 这一行纯算术：
`196 × $0.15/1M + 14 × $0.60/1M = $2.94e-05 + $8.40e-06 = $3.78e-05`。
"记账走的是价格表"= `CostTracker` 按模型名查价格表后累加 **2 次调用** 的用量。
两条**独立路径**给出同一个数，才算"记账被核对过"。
相对差 `0.000000e+00` 比"差很小"更强：它说明两条路径在双精度里落到**同一个数**，
而不是"碰巧接近"——后者通常意味着有人把同一个实现抄了两遍。

**12.** 三个数字分别是：`2` = **工具数**（计算器等两个工具）、`3` = **子任务数**、
`4` = **每个工具的调用形态数**（参数组合 / 边界形态）。

```text
2 + 3 × (4 − 1) = 2 + 9 = 11
```

`11` 是"最坏情况下要核验的路径条数"：两个工具各走 1 条基础路径（2），
每条子任务再各追加 3 条变体（3 × (4 − 1)）。
把"要不要给模型开放某个工具"变成**一道加法**，比拍脑袋决定可靠得多。

## 四、诊断

**13.**

```text
读数 A  覆盖 8/8 | 被认领 8 个包 | 无人认领 4 个  →  不需要动作（但要在报告里写明）
读数 B  覆盖 7/8；未覆盖的：offline_evaluation    →  需要动作
```

`无人认领 ≠ 没用`：那 4 个包（`indexing` / `mcp_server` / `finetune` / `api`）都已交付，
只是**不属于今天这 8 项能力的清单**；把它们的名字列出来是"如实交代边界"，
不需要修。而读数 B 是**真的失败**：`offline_evaluation` 是一项应当被覆盖的能力，
它没被任何子包认领，说明清单或装配链缺了一环——
`require_manifest_complete` 会当场点名缺的是谁。

## 五、推导

**15.**

```text
（甲）下界（召回 >= 1.0）反驳的是"漏"：金标准被漏掉、或把 1.0 写成 0.0；
      上界（幻觉引用 <= 0）反驳的是"超"：出现了提示词里没有的编号。
      一句话：下界说"一条都不能少"，上界说"一条都不能多"。
（乙）相等判据（== 1.0）在本例中也成立，因为召回天然落在 [0,1]。
      但本课仍选下界，是因为**语义更准**：它表达的是"金标准一条都不能漏"，
      而不是"这个数字必须恰好等于 1"。判据类型是性质的一部分，不是装饰。
（丙）落点是第 ④ 条 `retrieval_recall_meets_floor`（[lower_bound]，读数 1 >= 1.0）。
      没有它，把"召回 1.0 写成 0.0"这类错误在报告里看不出来——两个数都在 [0,1] 内。
```

**16.**

```text
（甲）这七项覆盖了一次请求的**输入（问题）、过程（九段记录）、输出（答案）、
      判定（指标）、成本（费用 / token）与规模（span 条数）**；
      两次运行在这七项上全部相同，就说明"同输入 ⇒ 同链路 ⇒ 同结果"。
（乙）因为它们**本来就不同**：时间戳每次都变、uuid 每次新生成、耗时受调度影响、
      日志文本带时间前缀。把它们放进读数，第二条性质会**永远失败**，
      而失败原因与链本身无关——于是这条性质会被人关掉。
（丙）性质会永远失败（每个 span 的耗时都不同），失败族仍是 AssemblyError。
      修法只有一条：把耗时留在"报告"里，不要把耗时放进"复算口径"。
```

## 六、情景题

**17.**

```text
（甲）"看起来能用"= 从来没有被反驳过。可被反驳的能力必须有"读数 + 界"，
      否则它在演示里只能证明"这次没崩"，证明不了"它对"。
（乙）示例判据（一条就够）：

      名称   tool_execution_is_exact
      判据   equality（== 0）
      读数   |CalculatorTool.execute("(2 + 3) * 4") 的返回值 − 期望值 "20"|
      期望   0（字符串逐字符相同）

      这条判据是"相等"而不是"差不多"：工具的执行结果是**确定性的**，
      不存在容差空间；写成"接近"反而会放过"返回了 20.0 而不是 20"这类格式错。
（丙）加在**装配层（verify.py）**，因为判据的输入来自真实调用（`tools.calculator`）；
      清单层（manifest）只回答"包在不在"，回答不了"行为对不对"。
```

**18.**

```text
（甲）**改语料或改提示词版本时必须重采**。两份基线都绑定了信息：
      perf_baseline 绑 label=day046-pipeline（samples=3 / mean_stages=6.0），
      rag_baseline 绑 prompt_version="v2" 与 samples=6。
      基线换了锚，旧数字就不可比。
（乙）报告里所有"涨了/跌了 X 个点"的句子**全部作废**——因为它们比的是旧锚。
（丙）若决定不重采，必须补写一句"锁定声明"，例如：
      "本报告的全部对比均基于 <日期> 采的那份基线（prompt_version=v2、6 条样本、
      3 条性能样本），本次语料与提示词版本与之一致，未发生变更。"
      没有这句话，"涨了 2 个点"就是一句无证据的话（day053："没有绑定信息的分数不是证据"）。
```

## 附：本课最值得带回工作现场的五句话

1. **"装上了"与"接上了"是两件事**——后者可以写成一条元组比较，前者什么也证明不了。
2. **清单要能被程序核对**：能力落到子包，`importlib` 说了算；认领不到的包要点名。
3. **读数必须现场算出，并且要能跟一个界比较**：没有界，读数只是描述；有了界，才是证据。
4. **把不确定的量从复算口径里挪出去**（时间戳 / uuid / 耗时），否则"可复现"这条性质会被关掉。
5. **判据类型是性质的一部分**：相等反驳"变样"、上界反驳"超"、下界反驳"漏"——三类缺一不可。
