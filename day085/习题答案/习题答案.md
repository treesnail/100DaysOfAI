## 一、选择题

### 1. 答案：B

HF 的"分头"只是两次形状重排：

```python
query = query.view(n, heads, head_dim).transpose(0, 1)
```

它没有换块类型、没有换掩码口径、没有换缩放，因此同一个 `GPT2Attention`
既能跑 `heads=12` 又能跑因果掩码。本包把它钉成一条逐位性质：
`merge_heads(split_heads(x, heads)) == x`（`heads=1/2/3` 全部 `True`）。
出处：`hf_source/attention.py` 的 `split_heads` / `merge_heads`；教程第 3 章。

### 2. 答案：B

两者是**同一条公式、两个默认值**：GPT-2 的 `layer_norm_epsilon = 1e-5`、
BERT 的 `layer_norm_eps = 1e-12`。因此输出**不相等**，而"差多少"是可以量出来的：

```text
gpt2  实测方差 0.99999500   离 1   5.00e-06
bert  实测方差 1.00000000   离 1   5.00e-13
```

出处：教程第 2 章、第 7.2 节；`hf_source/types.py` 的 `LN_EPS_DEFAULTS`。

### 3. 答案：B

理由只有一行：softmax 前会先减掉本行的最大值 `m`，而被挡格子
`v = s − 1e9 ≤ m − 1e9`，于是 `v − m ≤ −1e9`，而 `math.exp(-1e9) == 0.0`
（**精确下溢**）。实测两处权重的最大差 `0.000000e+00`。
出处：教程第 4 章；`hf_source/attention.py` 的 `additive_bias_of` / `row_softmax`。

### 4. 答案：B

`top_p` 留的是"累积概率刚超过 `p` 的最小集合"，因此保留个数**由数据决定**。
在那个固定分布（`logits = (2, 1, 0.5, 0, −1, −2)`，最大概率 `0.5573`）上，
`top_p = 0.5` 只留 1 个候选，于是采样退化成贪心（峰值 `1.0000`、熵 `0.0000`）。
出处：教程第 8.2 节；`hf_source/generation.py` 的 `top_p_filter`。

### 5. 答案：B

`top_k` 的保留个数是**常数**（由参数决定：`top_k=1/2/3/6 → 1/2/3/6`），
而 `top_p` 的是**数据决定的**（本课实测 `1/1/1/3/4`，且"逐步保留"会随步变化）。
两者又是**串联**的（顺序 `repeat → temperature → top_k → top_p`），
因此 `top_p` 的核是在**已经截断过的**分布上算的。
出处：教程第 8.1、8.2、9 章；`hf_source/types.py` 的 `WARPER_ORDER`。

### 6. 答案：B

beam 优化的是整条序列的累积对数概率，因此**第一步不一定是 argmax**：
本课实测贪心的第一个 token 是 `0`、beam 的第一个 token 是 `6`
（而 beam 的归一化分数 `-1.350130` 说明它选的那条总分确实更好）。
长度惩罚不是可选装饰：`lp = 0` 时"越长的候选总分越负"，系统性偏向短序列。
出处：教程第 9 章；`hf_source/generation.py` 的 `beam_search`。

### 7. 答案：B

HF 的原式是**除**不是减：

```text
score = score < 0 ? score · penalty : score / penalty
```

写成"减一个常数"在 logits 全为正时看起来一样，一遇到负 logits 就变成**放大**
（而"放大一个负 logits"正好是"更想选它"，与惩罚的意图相反）。
出处：`hf_source/generation.py` 的 `apply_repetition_penalty`；教程第 8.1 节。

## 二、简答题

### 8.

```text
① qkv               融合投影（GPT-2 一个 c_attn 出 3·hidden 维；BERT 三次独立 Linear）
② split_heads       多头引入 —— view(n, heads, head_dim).transpose(0, 1)   **一次形状重排**
③ score             Q·Kᵀ（逐头）
④ scale             × 1/√head_dim
⑤ bias              + 加性掩码
⑥ softmax           最后一维 softmax（被挡格子恰好 0.0）
⑦ attention_dropout 只在训练相
⑧ mix               weights·V（逐头）
⑨ merge_heads       多头引入 —— transpose(0, 1).reshape(n, hidden)          **一次形状重排**
⑩ out_proj          输出投影（c_proj / dense）
```

多头只引入 ② 与 ⑨ 两步，而它们各自只是**一次 `view` / `reshape` 加一次 `transpose`**
（切片与拼接），难点不在形状上，而在"每头有自己的 `d_head` 与缩放"这一件事上。
本包把两者钉成一条逐位判据：split → merge 必须逐位还原。
出处：`hf_source/types.py` 的 `ATTENTION_STAGES` / `ATTENTION_STAGE_SHAPES`。

### 9.

```text
逐位（==）  ① 分头 → 拼回恒等（同一次算术）
            ② 掩码外恰好 0.0 / 因果前缀逐位不变 / 融合与分离（拼接顺序一致时）
容差        ① 本包 heads=1 的注意力 vs day076 的 multi_head_attention
            ② 本包 pre 摆放的块 vs day079 的 encoder_block
```

跨包对账只能用容差的理由：两份实现**各自组织浮点运算的顺序不必相同**——
一处乘 `1/√head_dim`、一处除 `√head_dim`（这两者在浮点下不等价），
求和顺序也可以不同。因此 `max_gap` 与 `tolerance` 是两个必须一起给的字段。

本课实测两条对账都是 `0.000e+00`，但**不把"偶然逐位"写成承诺**：
判据仍是 `1e-12`，实测值只是印出来的读数。这条纪律与 day080 的
"参数量差值必须被逐项解释"同源——**差异要么被消灭、要么被写下来**。
出处：`hf_source/verify.py` 的 `CrossCheck`；教程第 1.3、6 章。

### 10.

因为**掩码回答的是"允许 / 不允许"，不是"多少"**。前九天共用的数值校验器
（`math_foundations.types.validate_matrix`）要求元素是有限实数，
因此布尔掩码会被它正确地拒绝——第一版的报错正是：

```text
NumericError: mask[0] 的第 0 个分量不是有限实数（收到 True）
```

这个报错本身是对的（它没有放过一个 `True`），但它暴露出一个设计问题：
**把"允许集合"与"打分"塞进同一个校验器，会得到一个"布尔掩码不能用"的荒唐结果。**

修法是给掩码一个自己的入口 `checked_mask`，它校验"行数齐、列数齐、元素是布尔值"，
并把"写了 `0.0 / -1e9` 而不是 `True / False`"当场拒绝——因为那张表已经**译好**了，
它不该再被当成掩码用一次（"一张掩码"与"一张已经译好的偏置"是两种东西）。
出处：教程第 4.4 节；`hf_source/attention.py` 的 `checked_mask`。

### 11.

那一行保证的是"**至少保留一个 token**"：

```python
sorted_indices_to_remove[..., -min_tokens_to_keep:] = 0
```

它是为了防住"核被清空 ⇒ softmax 的分母是 0 ⇒ nan"这条路。
本包**不把它当判据**，因为它是一条**恒等式**（永远为真）：

```text
删除条件是 cumsum <= 1 − p，而整行的累积和在最后一个位置等于 1 > 1 − p
⇒ 最大的那个 token 永远不会被删
```

"一条永远为真的断言比没有断言更坏，因为它占据了一个'已验证'的位置"
（day083 第 7.2 节）。因此本课的做法是**把信息量如实印出来**：
把"保留个数的最小值"打进 `notes`（本课实测 `top_p` 越小它的保留数越少，
而最小值始终 `>= 1`）。
出处：教程第 8.3 节；`hf_source/generation.py` 的 `MIN_TOKENS_TO_KEEP`。

### 12.

本课给它配了三个数：

```text
① 逐点最大绝对差      1.528e-04（出现在 x = ±1）
② x = 0 处的函数值    两式都为 0      （因子 0.5x 让它必然为 0）
③ x = 0 处的导数      两式都为 0.5    （0.5·(1 + tanh(0)) = 0.5）
```

`x = 0` 那一行是唯一可被手算断言的一行，因为它是**对称性**逼出来的：
两式都以 `0.5x` 为因子、都以"平滑的奇函数"为括号内的部分，
而 `x = 0` 处括号内的值恒为 1（`erf(0) = 0`、`tanh(0) = 0`），
因此函数值为 0、导数为 `0.5 × 1 = 0.5`。其余取点上两式都只有数值结果，
因此它们只能被**核对**（本包把整张表写成"逐点对照"），
"可手算"与"可核对"是两种不同的强度。
出处：教程第 7.1 节；`hf_source/study.py` 的 `ACTIVATION_POINTS` / `activation_study`。

## 三、诊断题

### 13.

错误在**拼接顺序**：`fused_weight` 的参数顺序就是 HF 切开的顺序（`q, k, v`），
而这里写成了 `(w_value, w_key, w_query)`，于是 `split_fused` 之后：

```text
拿到的 "query" 其实是 w_value 的那一块
拿到的 "value" 其实是 w_query 的那一块
```

**三个角色的两个被互换了。** 它为什么"看起来正常"：三块的行数、列数完全一样，
`split_fused` 只看"总行数是否恰好是 `3·hidden`"，因此形状检查全绿、
注意力照样跑、行随机照样成立、六条性质里的"行是分布"也只差一点点。

抓住它的是本课那条最值钱的**逐位**判据（`check_fused_matches_separate`）：

```text
切回来的三块必须与 w_query / w_key / w_value **逐位相同**（实测最大差 0.000000e+00）
再加上跨天对账：heads=1 时输出必须与 day076 的 multi_head_attention 一致
```

修法是一行：把参数顺序改回 `(w_query, w_key, w_value)`，
并把这条顺序写成一条断言（而不是靠记忆）。
出处：教程第 3.3 节；`hf_source/attention.py` 的 `fused_weight` / `split_fused`。

### 14.

错误是**行与列写反了**：`heads[0]` 是若干行（`n` 行、每行 `head_dim` 宽），
因此应当是

```python
    rows  = len(heads[0])          # n
    width = len(heads[0][0])       # head_dim
```

它为什么"自己跟自己比"就没有分辨率：

```text
len(head) != width      →  n != n          ✓ 通过
len(head[0]) != rows    →  head_dim == head_dim  ✓ 通过
```

两个量都来自**同一个对象**，因此无论写得多错，它们总是自洽的。
真正的失败要在"跨对象"时才露面：

```text
heads=1 的样本：rows 被当成 6（head_dim），而矩阵只有 4 行 ⇒ 直接 IndexError
heads=2 的样本：head_dim = 3 < n = 4 ⇒ 取第 0..2 行都还在范围内，
                于是它**静默地少拼了一行**（形状从 (4, 6) 变成 (3, 6)）
```

修法除了改正两行之外，还有一条更重要的：**让形状检查与另一个来源比**
（这里是"切分的顺序"与"拼回的列数"），并把
`merge_heads(split_heads(x, heads)) == x` 写成一条**逐位**判据——
正是这条判据在 `heads=2` 上首先亮红。
出处：教程第 10.1 节；`hf_source/verify.py` 的 `check_split_merge_round_trip`。

### 15.

```text
读数 A → 掩码外出现了非零读数（3.2e-13），说明"恰好 0.0"这条性质**失败了**
  诊断：3.2e-13 是一个"很小但非零"的值，它只有两种来源——
        ① 加性掩码的减法漏了一次（被挡格子的权重没被下溢吃干净）；
        ② softmax 之后有人对整行做了一次**重新归一化**（除以行和），
           而除法会把精确的 0 变成 0（这条其实安全），
           真正危险的是**先加了一个小量再归一化**。
  下一步：把这条读数从"一处"提到"逐格"——打印被挡格子里最大的那个位置
        （行列号），并与 `additive_bias_of` 的偏置表逐格对照；
        如果偏置本身是对的，问题就在 softmax 之后的那一步。
        （注意 day083 的纪律：3.2e-13 在热力图上与 0 长得一样，因此它必须由断言抓。）

读数 B → **这不是故障，而是"核采样退化成贪心"的正确读数**
  诊断：`top_p = 0.5` 留的是"累积概率刚超过 0.5 的最小集合"。
        在这个**尖分布**（最大值概率 0.5573）上，那个集合就是"只有最大值一个"。
        峰值 1.0000、熵 0.0000 都是它应有的样子（保留个数是**数据决定的**）。
  下一步：如果预期是"保留更多候选"，要改的是**策略**（换更大的 `top_p`
        或改用 `top_k`），而不是改代码。判断依据是看 `p` 与**最大概率**的关系：
        `p <= max_probability` 时核必然只有一个元素。
```

出处：教程第 4 章、第 8.2 节；`hf_source/verify.py` 的
`check_masked_entries_are_exact_zero`、`hf_source/generation.py` 的 `top_p_filter`。

## 四、推导题

### 16.

记第 `i` 行的打分为 `s_j`（`j = 1..V`），掩码给出允许集合 `A_i`（非空）与
被挡集合 `B_i`，加性偏置让参与 softmax 的值成为

```text
u_j = s_j          (j ∈ A_i)
u_j = s_j − 1e9    (j ∈ B_i)
```

**第一步（减最大值）**：`m = max_j u_j`。
因为 `A_i` 非空且 `min_{j∈A_i} s_j` 远大于 `−1e9`，所以最大值**一定在 `A_i` 上取到**：

```text
m = max_{j∈A_i} s_j
```

**第二步（取指数）**：

```text
j ∈ A_i:   exp(u_j − m) = exp(s_j − m)
j ∈ B_i:   u_j − m = (s_j − m) − 1e9 ≤ −1e9   ⇒  exp(u_j − m) = exp(−1e9) = 0.0
```

第二步的右边之所以是**精确的 0**：`exp(−1e9)` 在双精度下直接下溢到 0，
而任何 `≤ −1e9` 的自变量同样下溢。

**第三步（归一化）**：分母

```text
Z = fsum(exp(u_j − m))  =  fsum({\ exp(s_j − m)\ }_{j∈A_i}) + 0.0 + … + 0.0
                        =  Σ_{j∈A_i} exp(s_j − m)
```

（加 0 不改变 `fsum` 的结果）。于是

```text
（a）j ∈ B_i：  weight_j = 0.0 / Z = 0.0        —— **恰好是 0.0**
（b）j ∈ A_i：  weight_j = exp(s_j − m) / Σ_{k∈A_i} exp(s_k − m)
```

而 (b) 右边正是"只对允许集合归一化"的 softmax——**逐位相同**，因为两处做的
是同一串浮点运算（同一个 `m`、同一个求和顺序、同一个 `fsum`）。

**两条前提**：`A_i` 非空（否则分母是 0）；`min_{j∈A_i} s_j ≫ −1e9` ——
如果某个**合法**位置的分打本身就接近 `−1e9`，那么 `m` 也会接近 `−1e9`，
被挡格子与合法格子的 `u_j − m` 会落进同一个下溢区间，(a) 与 (b) 都不再成立。
本包因此把 `|score| < floor/2` 做成一条守卫（`check_score_magnitude`）。
出处：教程第 4 章；`hf_source/attention.py` 的 `additive_bias_of` / `row_softmax`。

### 17.

设升序概率为 `q_1 ≤ q_2 ≤ … ≤ q_V`，累积和为 `C_k = Σ_{i≤k} q_i`，阈值 `t = 1 − p`。
删除集合是 `D = {k : C_k ≤ t}`（并从后往前至少保留 `MIN_TOKENS_TO_KEEP = 1` 个）。

**（a）保留的概率之和恒不小于 `p`。**

删除的必然是**一个前缀**（因为 `C_k` 单调不减，`{k : C_k ≤ t}` 是一个前缀），
设它到 `k*` 为止。于是

```text
被删掉的质量 = C_{k*} ≤ t = 1 − p
保留下来的质量 = 1 − C_{k*} ≥ 1 − (1 − p) = p        ∎
```

本课实测印证：`p = 0.80` 时留下的累积概率 `0.8866 ≥ 0.80`；
`p = 0.95` 时 `0.9620 ≥ 0.95`；`p = 0.50` 时 `0.5573 ≥ 0.50`。

**（b）保留个数由数据决定。**

取同一个 `p = 0.5`（阈值 `t = 0.5`），两个不同的分布：

```text
分布 α（尖）：logits = (2, 1, 0.5, 0, −1, −2)
  升序概率 ≈ (0.0102, 0.0277, 0.0754, 0.1243, 0.2050, 0.5573)
  累积和   ≈ (0.0102, 0.0379, 0.1133, 0.2376, 0.4426, 1.0000)
  删除集合 = {C ≤ 0.5} = 前 5 个 ⇒ **保留 1 个**（退化成贪心）

分布 β（均匀，4 个候选，每个 0.25）
  升序概率 = (0.25, 0.25, 0.25, 0.25)
  累积和   = (0.25, 0.50, 0.75, 1.00)
  删除集合 = {C ≤ 0.5} = 前 2 个 ⇒ **保留 2 个**
```

同一个 `p = 0.5`、一个留 1 个、一个留 2 个 ⇒ **保留个数由数据决定。**
两种分布下都成立的是 (a) 那条不等式：`0.5573 ≥ 0.5`、`0.75 ≥ 0.5`。

（本课教程第 8.2 节那张表是同一件事在**固定分布**上的读数：
`p = 0.10 / 0.30 / 0.50 / 0.80 / 0.95 → 保留 1 / 1 / 1 / 3 / 4`，
留下的累积概率 `0.5573 / 0.5573 / 0.5573 / 0.8866 / 0.9620`。）
出处：教程第 8.2 节；`hf_source/generation.py` 的 `top_p_filter`。

### 18.

设候选新生成 `L` 个 token、累加对数概率 `S = Σ_{i=1..L} log p_i`。
每个 `log p_i ≤ 0`，因此 `S ≤ 0`，且 `S` 随 `L` **单调不增**。

**（a）`lp = 0`（不修正）**：

```text
score = S / L^0 = S
前缀长 L 的候选与它的前缀 L' < L 相比：S(L) = S(L') + Σ_{i>L'} log p_i ≤ S(L')
⇒ **越长的候选总分越负** ⇒ 不修正时 beam 系统性偏向短序列
```

（本课 `beams=1 lp=1` 那一行的 `生成 [0,7,5,7,6]` 与 `beams=2` 那一行的
`生成 [6,6,6,6,6]` 正是"目标不同、答案不同"的读数。）

**（b）`lp > 0`**：

```text
score = S / L^lp        （S ≤ 0，L^lp > 0 随 L 单调增）
```

`|score| = |S| / L^lp` 随 `L` 增大而**变小** ⇒ `score` 变得不那么负
⇒ **相对地偏好更长的序列**；`lp` 越大，这个"摊薄"越强。

**（c）`lp < 0`**：

```text
L^lp = 1 / L^{|lp|}      ⇒  score = S · L^{|lp|}
```

而 `S ≤ 0`，乘一个随 `L` 增大的正数会让 `score` **更负** ⇒ 偏好更短的序列。
因此负值**又一次反转了方向**。本包明确拒绝它，理由不是"数值不安全"，
而是**名字与方向已经不一致**：

```text
参数名是"长度惩罚"，而 HF 的文档口径是 lp > 0 **promotes longer sequences**。
一个名不副实的参数再翻一次方向，读代码的人就只能靠试。
```

**实测差别体现在哪**：两个 `lp` 给出的**候选序列完全相同**（都是 `[6,6,6,6,6]`，
因为候选池一样），差别落在**归一化分数**这一个读数上：

```text
beams=2 lp=0.5  归一化分数 -3.018983
beams=2 lp=1.0  归一化分数 -1.350130
beams=3 lp=2.0  归一化分数 -0.270026
```

也就是说：长度惩罚改变的是"**怎么给同一批候选打分**"，
而不是"模型生成了什么"——这条区分正是 `GenerationResult.notes` 里
把"长度惩罚"单列一行、并把归一化分数印出来的原因。
