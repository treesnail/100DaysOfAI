## 一、向量与矩阵

### 1. 手算四件事

```text
a·b = 1·4 + 2·5 + 3·6 = 4 + 10 + 18 = 32
‖a‖ = √(1 + 4 + 9) = √14 ≈ 3.741657
cos(a, b) = 32 / (√14 · √77) = 32 / (3.741657 × 8.774964) ≈ 0.974632
```

与 `a` 正交的向量：**构造法**是"取一个分量置 0，让剩下两个分量满足 `2y + 3z = 0`"：

```text
令 x = 0 → 2y + 3z = 0 → 取 z = 2、y = −3 → c = (0, −3, 2) 或 (0, 3, −2)
验算：1·0 + 2·3 + 3·(−2) = 0 ✓
```

验证：

```bash
python -c "
from smart_research_agent.math_foundations import cosine, dot, norm
a, b, c = (1.,2.,3.), (4.,5.,6.), (0.,3.,-2.)
print(dot(a,b), norm(a), cosine(a,b), cosine(a,c))
"
# 32.0 3.7416573867739413 0.9746318461970762 0.0
```

### 2. "点积大"为什么不等于"方向一致"

把任一侧放大 `k` 倍，点积也放大 `k` 倍，而方向一点没变：

```text
a = (1, 0)   b = (1, 0)    → a·b = 1
a = (1, 0)   b = (100, 0)  → a·b = 100      ← 点积大了 100 倍
```

两组的余弦都是 **1**（完全相同），而点积差了 100 倍。因此"点积大"里混着
**长度**的信息；要只看方向，必须除以两个模长——这就是余弦的定义：
`cos(a, b) = a·b / (‖a‖‖b‖)`。

（顺带：`cos(a, 2a) = 1` 而 `a·(2a) = 2‖a‖²`。本课测试里把这两条都钉成了用例。）

### 3. 零向量的三种答案

| 实现 | 行为 | 使用场景 |
|------|------|---------|
| `math_foundations.linalg.normalize` | 报错 | 这一层要的是**一个方向**；零向量没有方向，替调用方决定"返回什么"会把错误藏起来 |
| `vectorstore.metrics.cosine_similarity` | 返回 0.0 | 检索要**不被打断**：一条脏数据不该让整批查询失败（day064 的说明） |
| `llm.embedding.l2_normalize` | 原样返回 | 写入侧要**写进一份向量**：不能因为"没有方向"就抛异常，否则一条坏输入会中断整批入库 |

三者都对，因为它们回答的是**三个不同的问题**：给一个方向 / 给一个相似度 /
给一份可存储的向量。危险的不是"不一样"，而是"不一样而没人知道"——
因此 `bridge` 把这一条作为**记录差异**（`rejected`）写进报告，
并且测试里专门有一条用例证明"若约定被改掉，它会变成真正的分歧"。

### 4. `fsum` 与 `sum`

```text
sum      顺序累加（左折叠）：((a+b)+c)+d…    误差随项数线性累积
fsum     精确累加（Shewchuk），结果与顺序无关，再一次性舍入
```

找一个让两者不同的序列（把极小项放在极大项之后）：

```bash
python -c "
import math
values = [1e16, 1.0, -1e16] + [1.0] * 3
print(sum(values), math.fsum(values))
"
# 1.0 6.0   （sum：1.0 + 1e16 = 1e16，那个 1.0 被"吃掉"了）
```

关系：检索里两处余弦必须给出**同一份名单**，而余弦的实现里就有求和。
若一处的求和顺序与另一处不同（例如一个有重排、一个没有），
那么"同一个查询"在排序临界点上可能得到不同的第 k 名——
**而那种不一致只在特定输入上出现**，因此最难查。`fsum` 把这类差异从根上消掉。

### 5. 3×4 乘 3×3 会得到什么

`matmul` 的实现里有一个 `zip`：内维不一致时它会**取较短的**（3），
于是每一行只把前 3 个 `k` 配起来——**少算了一列**：

```text
(correct)  (AB)_ij = Σ_{k=1..4} A_ik B_kj
(截断)              = Σ_{k=1..3} A_ik B_kj   ← 少了一项
```

它"看起来正常"是因为：结果是**一组数量级合理的浮点数**，没有 `nan`、
没有异常、形状也对（`(3, 3)`）。除非你手算过某一行，否则不会发现。

本课的取舍是**当场报错**：

```text
矩阵乘法内维不一致：左 (3, 4) × 右 (3, 3)——需要左的列数等于右的行数，
否则逐元素相乘会把 k 配错（结果仍然是一组正常的数）。
```

### 6. 投影为什么返回标量

```text
数学含义   u 在 v 方向上的**坐标**（把 v̂ 当作基）：proj_v(u) = u·v̂
要变回向量 再乘一次 v̂：(u·v̂)·v̂
```

返回标量是因为**报告里要读的是这个数**（"在这个方向上有多长"）。
向量形式只多一次乘法，但读的人要自己再从分量里解读长度；
而"标量 + 明确的基向量"是更少的歧义。

`v` 是零向量时报错：没有"方向上"可言（同第 3 题的纪律）。

## 二、softmax 与数值稳定

### 7. 手算 softmax

```text
softmax([0, 1]) = (1/(1+e), e/(1+e))    ≈ (0.268941, 0.731059)
softmax([0, 2]) = (1/(1+e²), e²/(1+e²)) ≈ (0.119203, 0.880797)
```

关系：**第二个分布的"温度更低"**——把打分整体放大 2 倍，
等价于把温度除以 2（`softmax(2z) = softmax(z, T=1/2)`）。
因此"打分尺度"与"温度"是同一个旋钮的两种说法，这也解释了第八章的 √d 缩放：
**不缩放的高维打分 = 极低温 = one-hot = 梯度消失**。

### 8. 为什么减去最大值不改变结果

```text
softmax(z − c)_i = exp(z_i − c) / Σ_j exp(z_j − c)
                 = [exp(z_i)·exp(−c)] / [Σ_j exp(z_j)·exp(−c)]
                 = exp(z_i) / Σ_j exp(z_j) = softmax(z)_i
```

分子分母同乘一个正数，约掉。它改变的是**数值**：把 `exp` 的自变量压到 `<= 0`，
于是不会上溢（`exp(1000) = inf`）。**数学结果不变、数值结果才正确**——
这正是"数值稳定不是优化，是正确性"。

### 9. 两个极端输入

```bash
python -c "
import math
from smart_research_agent.math_foundations import log_softmax, softmax
print(softmax((1000., 1001.)))          # (0.2689414213699951, 0.7310585786300049)
print([math.exp(z) for z in (1000., 1001.)])   # OverflowError: math range error
print(softmax((0., -1000.)))            # (1.0, 0.0)
print(log_softmax((0., -1000.)))        # (0.0, -1000.0)
"
```

- 朴素写法在 `exp(1000)` 处**直接抛 `OverflowError`**（连 `nan` 都拿不到）。
  即便用能饱和到 `inf` 的实现，也会得到 `inf/inf = nan`。
- `math.log(0.0)` 在 Python 里**抛 `ValueError`**（不是返回 `-inf`）。
  本课的 `log_softmax` **不经过 softmax**：它直接算
  `z − max − log Σ exp(z − max)`，因此概率极小时仍然给出有限值（`-1000.0`）。

测试里把这两条都钉住了（`test_naive_log_softmax_crashes_while_ours_stays_finite`）。

### 10. 温度 `T <= 0` 为什么报错

```text
T = 0   数学上导致 0/0 或 one-hot 的极限，语义是"贪心"——那是 **argmax** 的事
T < 0   概率会变成负数（exp 的自变量反号）——没有概率意义
```

"取个默认值"的后果：**"我调了温度"这件事变成假的**。
一次被静默替换的温度，会让"温度扫描"这类实验的结论完全不可信，
而报告里看不出任何异常。因此：

```text
T = 0 的贪心语义 → 用 argmax 表达（本包提供 linalg.argmax）
温度必须为正的有限数 → 否则 ParameterError（消息里写明"请用 argmax"）
```

## 三、概率

### 11. `p = (0.5, 0.25, 0.25)` 的三个数

```text
H(p) = −[0.5·ln0.5 + 0.25·ln0.25 + 0.25·ln0.25]
     = −[−0.346574 − 0.346574 − 0.346574] = 1.039721 = **1.5·ln2**
困惑度 = exp(H) = exp(1.5 ln2) = 2^1.5 = **2.828427**
H(p, 均匀) = −Σ p ln(1/3) = ln 3 = 1.098612
KL(p‖均匀) = 1.098612 − 1.039721 = **0.058891**
```

验算：`1.5 × 0.693147 = 1.039721` ✓；`2^1.5 = √8 = 2.828427` ✓。
注意 **KL = 交叉熵 − 熵**这条关系在这里直接可用（本课的实现也是这样算的）。

### 12. `p = 0` 的那一项

```text
朴素写法 −p·log(p) 在 p = 0 时 = 0 × (−inf) = **nan**
正确的极限 lim_{p→0} p ln p = 0（用洛必达或 p = e^{−t} 代换可证）
```

因此本课**跳过** `p = 0` 的项：

```python
    for value in checked:
        if value > 0.0:
            total += value * math.log(value)
    return -total
```

"一个 nan 比一个错值更麻烦"的原因是：**nan 会传播**。
一次 `entropy` 返回 `nan`，`mean` 也是 `nan`，整张表的"平均熵"变成空——
而报告中一个空值看起来像"这一列没数据"，不像"算错了"。
相比之下一个错值至少是一个数，能被怀疑。

### 13. `q_i = 0` 而 `p_i > 0`

```text
数学上：−p_i·ln(0) = +inf      → 整条交叉熵 = +inf
```

本课**报错**而不是返回 `inf`：`inf` 流到下游会让均值变 `inf`、图表断线、
"这次评估没有结论"——而根因（那个把概率写成 0 的实现）永远查不出来。
报错消息里把两个数都给出来（"第 i 个事件的真值概率是 X，而预测概率是 0"），
因此它是一条可以照着修的错误。

### 14. 采样频率

```bash
python -c "
from smart_research_agent.math_foundations import sample_index, uniforms
p = (0.7, 0.2, 0.1)
draws = [sample_index(p, u=u) for u in uniforms(2000, seed=42)]
print([round(draws.count(i)/len(draws), 3) for i in range(3)])
"
# [0.703, 0.202, 0.095]  ← 与 (0.7, 0.2, 0.1) 很接近
```

**为什么必须可复现**：这条结论（"采 2000 次的频率接近概率"）是一个**实验**，
而实验的价值在于它能被别人复核。若采样内部调 `random`，
同一段代码两次运行会给出不同的频率——那么"注意到的偏差"到底是真的
还是采样噪声，就永远说不清。

设计上体现为：**随机性从参数进来**（`sample_index(p, u=...)`），
而 `uniforms(count, seed)` 提供一串**确定性**的数（LCG，非密码学安全）。

### 15. `E[X²] − μ²` 的数值问题

两个式子在数学上等价，但 `E[X²]` 与 `μ²` 在**分布集中**时会很接近
（例如取值是 `(1e8, 1e8+1)`），相减得到一个小数：

```text
E[X²] ≈ 1e16 + 2e8 + 1      （双精度只有约 15~16 位有效数字）
μ²    ≈ 1e16 + 2e8 + 1      两者几乎完全相同 → 相减后**有效位全丢**
```

这就是**灾难性抵消**：结果里的每一位都是舍入噪声。
按定义算 `E[(X − μ)²]` 先做减法（`X − μ` 是小量，精度足够），再平方、再加权，
因此没有这个问题。

本课因此按定义算（`probability.variance`），并在 docstring 里写明理由——
也正是这一天"数学课要写代码"的一个具体例子：**等价的两个公式，
在浮点世界里的表现完全不同**。

## 四、联合分布与贝叶斯

### 16. 手算

```text
P(A1) = 0.30 + 0.10 = 0.40        P(A2) = 0.20 + 0.40 = 0.60
P(B1) = 0.30 + 0.20 = 0.50        P(B2) = 0.10 + 0.40 = 0.50

P(B1|A1) = 0.30 / 0.40 = 0.75
P(A1|B1) = 0.30 / 0.50 = 0.60
```

两者**不相等**（0.75 vs 0.60），而这不是矛盾——它们问的是两个不同的问题：

```text
P(B1|A1)  "已经下雨了，带伞的概率"      ← 分母是 P(A1) = 0.40
P(A1|B1)  "看到带伞了，下雨的概率"      ← 分母是 P(B1) = 0.50
```

条件概率的**方向**决定了"用谁去做分母"。贝叶斯公式就是把这两个方向连起来的桥：

```text
P(A1|B1) = P(B1|A1)·P(A1)/P(B1) = 0.75 × 0.40 / 0.50 = 0.60 ✓
```

### 17. 后验与列条件分布的自洽性

```text
先验取边缘 P(A) 时：
P(A|B=b) = P(B=b|A)·P(A) / P(B=b)
         = [P(A, B=b)/P(A)] · P(A) / P(B=b)        ← 似然展开
         = P(A, B=b) / P(B=b)                      ← P(A) 约掉
         = 列条件分布 P(A|B=b)                       ✓
```

分子分母里的 `P(A)` 恰好约掉——这就是"自洽性"的来源。

它能发现的错误：**似然或证据取错了**。例如把似然读成了另一行
（`P(B=b|A=a')`），或者证据用了未归一化的行和——两者都会让
"贝叶斯算出来的后验"与"直接从表里读的列条件分布"对不上。
而这两种错都不会报错：它们会给出**一组和为 1 的正数**。

本课的测试与演示都把这条等式断言了下来（`与列条件分布一致：True`）。

### 18. 两种 0 的误导性

```text
证据 = 0（P(B=b) = 0）      公式变成 0/0 → 本课报错
                            硬算会得到 nan 或"后验全是 0"
                            误导性：看起来像"没有任何原因可能"，而真相是
                                    "这个观测本身不会发生"——是数据问题，不是推断结果

似然 = 0 而先验 > 0         严格按公式得到"这个原因的后验恰好是 0"
                            误导性：看起来像"这个原因彻底不可能"，
                                    而真相是"这一份（有限的）数据不支持它"
                                    正确做法是用平滑后的似然（拉普拉斯/加法平滑），
                                    而不是接受一个 0——因为 0 会永久地把这个原因排除掉
```

两者的共同点：**0 在这里是一个"绝对"的说法**（不可能 / 没关系），
而有限数据给不出"绝对"。因此本课宁可报错，让人显式决定怎么处理。

## 五、幂迭代与低秩近似

### 19. `diag(2, 1, 0.5)` 的三个数

```text
奇异值 = 对角线 = 2、1、0.5（对角矩阵的奇异值就是 |对角线元素|）
‖A‖_F = √(4 + 1 + 0.25) = √5.25 ≈ 2.291288

秩 1：丢掉 1 与 0.5 → 残差 √(1 + 0.25) = 1.118034 → 相对误差 1.118034/2.291288 = **0.487950**
秩 2：丢掉 0.5      → 残差 0.5            → 相对误差 0.5/2.291288      = **0.218218**
秩 3：什么都不丢     → 残差 0              → 相对误差 **0.000000**
```

秩 3 **必然**为 0：矩阵的秩是 3，前 3 个奇异向量张成整个空间
（`Σ_{i≤3} σ_i u_i v_iᵀ` 就是 A 本身），Frobenius 范数是完备的（`‖A‖_F² = Σσ_i²`）。

实测（演示脚本第 8 节）与手算逐位一致。这也说明 `low_rank_approximation`
的实现是对的——**手算是这一课的测试基准**。

### 20. 逐分量比较为什么失败

主向量只在**方向上**有定义：`v` 与 `−v` 表示同一个方向。
幂迭代的相邻两步完全可能整体翻符号（取决于 `AᵀA` 的符号与起始向量的选择）：

```text
v_k     = (0.71, 0.70)
v_{k+1} = (−0.72, −0.69)      ← 其实是同一个方向、已经收敛了
逐分量比较：|0.71 − (−0.72)| = 1.43 > tolerance → 判定"还没收敛" → 一直跑到上限
```

用 `|cos(v, v_prev)|` 就与符号无关：两个单位向量的 `|cos| = 1` 意味着平行。
本课的实现：

```python
        if abs(1.0 - abs(dot(vector, previous))) <= tolerance:
            break
```

### 21. 省掉正交化会发生什么

第二轮幂迭代仍然作用在**残差**上，但残差里那个"主方向"并没有被真正去掉
（幂迭代只减去了一层外积，数值上总留着残余）。没有正交化时，
第二轮会**再次收敛到同一个主方向**上：

```text
A_r ≈ σ1 u1 v1ᵀ + σ1' u1 v1ᵀ + …      ← 同一层的重复叠加
```

后果：**没有任何报错**。`A_r` 仍然是一组正常的数，相对误差也只是"不太准"
（例如本该 0.49 的秩 2 误差变成 0.6），而它看起来像一个"数据本身比较难近似"的结论。

本课用 Gram–Schmidt 显式正交，并在 docstring 里写明"没有它时会怎样"——
**这是唯一能让读的人意识到"这一段不能省"的写法**。

### 22. 低秩近似与 LoRA

一句话：**LoRA 就是把 `ΔW` 约束成低秩，而"低秩"的数学定义正是
`Σ_{i≤r} σ_i u_i v_iᵀ`——即只保留少数几个方向。**

```text
全参数微调    n × n 个参数（每个方向都能学）
LoRA          B(n×r) · A(r×n) = 2nr 个参数（只学 r 个方向）

n = 4096、r = 8：  16,777,216 → 65,536（约 1/256）
```

而它成立的依据是前一节的奇异值衰减：**真实矩阵的"能量"集中在最前面的
少数奇异值上**，所以丢掉后面的那些方向不会实质改变这个变换的行为
（day051 的 `lora_r` / `lora_alpha` 就是在这条曲线上取值）。

## 六、注意力

### 23. 四步与四个算子

```text
① Q Kᵀ            → matmul + transpose（打分）
② / √d_k          → scaling（缩放；本课用标量乘实现）
③ softmax         → softmax（按行：每一行是一个条件分布）
④ · V             → matmul（加权平均）
```

四个算子都在 `linalg.py` 里，且都已在第二章到第三章讲过——
**注意力不是新东西，是四件旧事的组合**。

### 24. 手算一次注意力

```text
queries = ((1,0,0,0),)      keys = ((1,0,0,0), (0,1,0,0))      values = ((1,0), (0,1))

① 打分：QKᵀ = ((1·1+0, 1·0+0)) = ((1, 0))
② 缩放：d_k = 4 → scale = 1/√4 = 1/2 → ((0.5, 0.0))
③ softmax：softmax([0.5, 0]) = (e^{0.5}/(e^{0.5}+1), 1/(e^{0.5}+1))
                             ≈ (1.648721/2.648721, 1/2.648721) ≈ (0.622459, 0.377541)
④ 输出：0.622459·(1,0) + 0.377541·(0,1) = (0.622459, 0.377541)
```

### 25. 生产写法的 `-inf` 与本课的两条理由

生产实现常见写法：

```python
scores = scores + (1.0 - mask) * float("-inf")   # 被屏蔽的位置变成 -inf
weights = softmax(scores)                        # exp(-inf) = 0，正好
```

本课拒绝它的两条理由：

```text
① 非有限数不该进入概率层   softmax 会拒绝 -inf（"非有限数一律拒绝"的纪律
                          不该在这里出现第一个例外）
② -inf 会被后续运算静默破坏  -inf·0 = nan、-inf + inf = nan、
                          归一化/裁剪/温度缩放都会在它上面出问题，
                          而错误出现在离掩码很远的地方
```

第一版实现正是按 `-inf` 写的，跑演示时被 `validate_vector` 当场拦下：

```text
NumericError: logits 的第 1 个分量不是有限实数（收到 -inf）
```

改法是显式掩码：只在允许的位置上 softmax，再把 `0.0` 插回去
（数学上等价：`exp(−∞) = 0` 且不参与分母）。

### 27. 多头为什么是 `1/√(d/heads)`

每个头拿到的不是整个 `d` 维，而是 `d_k = d / heads` 维。
而缩放系数是 `1/√d_k`（第八章的推导只依赖"打分向量有多少维"）：

```text
d = 64、heads = 8  →  每头 d_k = 8  →  缩放系数 1/√8 ≈ 0.3536（不是 1/√64 = 0.125）
```

若误用 `1/√d`，每个头的打分尺度会偏小 `√heads` 倍 → softmax 过于平坦 →
注意力几乎均匀分布（"什么都不看"）。这类错误同样**不报错**，
只表现为"训练效果不如预期"。

**头与头之间没有交互**：各自算、各自 softmax，交互发生在拼接之后的线性层
（本课不含那一层——它只是一个矩阵乘法）。因此"每个头的集中度"是有信息量的读数：
**所有头都一样说明这个多头结构退化成了一头**。

## 七、为什么除以 √d_k

### 28. 推导

设 `q_i`、`k_i` 独立，`E[q_i] = E[k_i] = 0`，`Var(q_i) = Var(k_i) = σ²`。

```text
① 定义展开        q·k = Σ_{i=1..d} q_i k_i
② 和的性质        Var(Σ X_i) = Σ Var(X_i)        （独立性保证协方差项为 0）
③ 积的期望        E[q_i k_i] = E[q_i]·E[k_i] = 0  （独立）
④ 积的方差        Var(q_i k_i) = E[q_i² k_i²] − (E[q_i k_i])²
                              = E[q_i²]·E[k_i²] − 0 = σ² · σ² = σ⁴
⑤ 代回            Var(q·k) = Σ_{i=1..d} σ⁴ = d σ⁴        □
```

第 ② 步用了**独立性**（否则要加协方差项），第 ④ 步也用了独立性
（`E[q_i²k_i²] = E[q_i²]E[k_i²]`）。

因此打分的标准差是 `σ²√d`：`d = 256` 时是 `d = 4` 时的 8 倍。
而 softmax 对尺度极敏感——这就是"不缩放时高维注意力会饱和"的全部原因。

### 29. 实测

```bash
python -c "
from smart_research_agent.math_foundations import sampled_dot_product_variance as v
for d in (4, 16, 64, 256):
    s = v(d, trials=2000, seed=42)
    print(s.summary_line())
"
```

```text
d=4    | Var 0.4481（理论 0.4444）| 标准差 0.6694 | 缩放后 0.3347
d=16   | Var 1.7436（理论 1.7778）| 标准差 1.3204 | 缩放后 0.3301
d=64   | Var 7.5113（理论 7.1111）| 标准差 2.7407 | 缩放后 0.3426
d=256  | Var 28.5472（理论 28.4444）| 标准差 5.3430 | 缩放后 0.3339
```

- 实测与理论 `d/9` 的偏差在 6% 以内——**它来自有限抽样**（2000 次）。
  偏差随 `trials` 增大而减小：这正是"确定性随机数"的用处（同一个 `seed`
  重复跑得到同一组统计量，因此"偏差是不是抽样噪声"可以被单独检验）。
- **未缩放**的标准差从 0.6694 涨到 5.3430（约 8 倍，对应 `√256/√4 = 8` ✓）。
- **缩放后**恒定在 0.3333 附近。**它等于 `σ² = 1/3`，不是 1**——
  因为这里的分量方差是 `1/3`（`[-1,1]` 均匀），而"缩放的目标"是
  **把打分尺度还原成单个分量的方差**，即 `σ²`：

```text
未缩放  std(q·k) = √(d σ⁴) = σ²√d
缩放后  std(q·k/√d) = σ²√d / √d = **σ²**      ← 与 d 无关
```

把这一条读成"应该等于 1"是一种常见的误读：`1` 只在 `σ² = 1`（标准正态分量）
时才成立。判据是"**与 d 无关**"，而不是"等于某个特定的数"。

## 八、对照与工程

### 30. 三种结论

```text
agrees     逐点在容差内一致
differs    超出容差 —— 这才是需要改代码的信号
rejected   两边的**拒绝行为**不同 —— 记录的约定差异，两条都对
```

为什么不能合并成布尔值：

```text
合并成 bool 之后："normalize 的零向量约定不同" 与
"cross_entropy 算错了 0.28" 会得到同一个 False。
而前者不该改代码、后者必须改 —— 一个把两类问题混在一起的门禁
只会有两种下场：要么拦下所有事，要么被关掉。
```

本课的 `BridgeReport` 因此同时给出 `disagreements`（`differs`）
与 `recorded_differences`（`rejected`）两张表，
而 `ok` 的定义是"**没有分歧**"（记录差异不算）。

### 31. 两个坑

**坑一：拿两串顺序不同的数去比。**

```text
本包：把每个样本依次喂给 softmax → [s1, s2, s3, s4, s5, s1, s2, …]
生产：每个样本依次喂给两个实现 → [s1, s1, s2, s2, …]
→ 内容相同、顺序不同 → 逐点比较报 differs、最大误差 0.73
```

危害：**得到的"不一致"是假的**，而它会让人去改一份本来正确的代码
（最坏的情况下真把对的改成错的）。因此对照的第一条纪律是
"**同一组输入、同一个顺序**喂给两边"。

**坑二：把概率当 logits 传。**

```text
sft.loss.cross_entropy(logits, target)   吃打分，真值是 one-hot 下标
probability.cross_entropy(p, q)          吃概率，真值是一个分布
```

它的后果是**又做了一次 softmax**、把概率压向均匀，而方向取决于 target：

```text
target 是 argmax      该类的概率被压小 → loss 变大
target 不是 argmax    该类的概率被推大 → loss 变小
```

**两个方向都会出现**，所以"loss 不对劲"不能只看方向——
必须回到**入参形态**去查。测试里把两个方向都断言了下来
（`TestLogitsVersusProbabilityTrap`）。

### 32. 评价"不加配置项"的取舍

这个取舍成立的前提是"**判据是这一次计算的属性**"。它不成立的场景：

```text
① 同一套判据要在一百个调用点保持一致（例如"全公司统一的数值容差"）
   → 那时散在 100 处的字面量会分家；应当有**一处**定义（模块常量或配置）

② 判据要随环境变化（例如 CI 上的容差比本地宽，以吸收不同 BLAS 的舍入）
   → 那时它确实是环境相关的东西，进配置比进参数更合适

③ 判据要被运维在运行期改动且**不能重启**（例如临时放宽门禁）
   → 参数化到调用点做不到这件事
```

反过来，"进配置"的代价也要说清：**配置是环境相关的，而数学口径不该随环境变**。
一个"在 CI 上容差 1e-6、在本地 1e-9"的对照报告，会让"这次对上了吗"
这个问题的答案取决于**在哪里跑的**——那正是这一课想避免的。

因此本课的选择是：**判据进参数**（每次调用显式给），
**口径进模块常量**（`DEFAULT_TOLERANCE`，改它必须是一次代码 diff），
而"要不要为它加一层配置"留给真正需要环境相关性的那一层去决定。
