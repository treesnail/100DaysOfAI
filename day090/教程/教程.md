## 今日目标

day089 结束时，那句话是被明写的：**"有前向、有损失、没有反向，而且没有交给自动微分"**。
今天补上那一行反向，并第一次让 `GradientError`（day075 定义、连续缺席八天）被真的抛出。

```text
一个神经元的导数  →  一层的三块梯度  →  整条 MLP 的逐层回传  →  一次真的下降
        ↘                ↘                    ↘
      逐元素激活的导数    一张张量级计算图      与生产实现逐位对账
```

三个问题：

1. **"反向传播"到底有几条规则？** 两条。一条是链式法则（上游梯度 × 局部导数），
   一条是纪律（**累加**）。第二条才是会把人绊倒的那条——写错它**不报错**，
   只给出一个偏小的梯度（第二章）。
2. **"梯度算对了"凭什么相信？** 凭**三条互不依赖的路径**在同一个点上给出同一个数：
   手写反向、图自动微分、数值差分（第九章）。三条里两条不一致，才抛 `GradientError`。
3. **softmax 的局部导数是一张矩阵，反向真的要去建它吗？** 不用。
   `(Jᵀv)_i = p_i(v_i − ⟨p,v⟩)` 把 O(n²) 的中间量压成 O(n)（第七章）。

最终产出：10 个新文件（`backprop/`）、1 个新测试文件（**100 个用例**）、
一本手册（`docs/backprop.md`，11 节）与一份演示脚本（`scripts/backprop_demo.py`，十一节）。

## 第二章：一条规则与一条纪律

### 2.1 规则：上游梯度 × 局部导数

```text
z = f(x)         dz/dx 是"这一处的斜率"（局部导数）
y = g(z)         dL/dx = (dL/dy) · (dz/dx)
```

`dL/dy` 叫**上游梯度**（它从输出那边传回来），`dz/dx` 叫**局部导数**（它由这一层的
前向决定）。反向传播的全部内容就是"把这两样乘起来，然后往上一层送"。

### 2.2 纪律：累加

```text
y = x·x        两条边都通向 x ⇒ dy/dx = x + x = 2x（在 x = 3 处是 6）
y = x + x      两条边都通向 x ⇒ dy/dx = 1 + 1 = 2
```

一个值被用了 k 次，它的梯度就是 k 条路径之和。因此本课在
`graph._accumulate` 里一致使用 `add_values`（即 `+=` 的语义）。

**为什么这一条值得单独成一族**（`ChainError`）：写错它**不会报错**。

```text
用 = 代替 +=        只保留最后一条路径 ⇒ 梯度偏小
                    而"梯度偏小"看起来像"学习率设小了"——于是有人去调学习率
把常量写进梯度      一个永远为 0 的梯度被当成"这个参数不学"
重复反向不清零      两次 backward 把梯度加起来 ⇒ "这一步"变成"这两步之和"
```

演示读数（`graph` 那一节）：

```text
同一个 sum_all 节点连续反两次：
  第一次之后 x 的梯度 = 1.0
  第二次之后 x 的梯度 = 2.0      ← 就是"忘记清零"的后果
  zero_grad() 之后 x 的梯度 = 0.0
```

### 2.3 乘法那条局部导数取的是**前向值**

```text
z = x·y        dz/dx = y（**另一个乘数的前向值**），dz/dy = x
```

写成"把 dZ 当成局部导数"是这一层最容易犯的错——它在只有一条链、且左操作数恰好是
叶子时甚至能算对（叶子的梯度初值是 0），因此在简单的例子上根本发现不了。

## 第三章：六个激活的导数 —— 一条口径表与三个工程细节

### 3.1 口径表

```text
relu        d/dx = 1 if x > 0 else 0                在 x = 0 处取次梯度 0（约定）
leaky_relu  d/dx = 1 if x > 0 else 0.01             负半轴那条坡度也出现在导数里
sigmoid     d/dx = σ(x)(1 − σ(x))                   值域 (0,1) ⇒ 上界 0.25
tanh        d/dx = 1 − tanh²(x)                     值域 (−1,1) ⇒ 上界 1
gelu        d/dx = 0.5(1 + erf(x/√2)) + x·e^{−x²/2}/√(2π)   在 0 处恰好 0.5
softmax     J[i][j] = p_i(δ_ij − p_j)               一整行一起看（唯一逐行的激活）
```

现场读数（`x = 1.0`）：

```text
relu        d/dx(1) = +1.000000
leaky_relu  d/dx(1) = +1.000000
sigmoid     d/dx(1) = +0.196612       ← 不是 0.25：0.25 只在 x = 0 处取到
tanh        d/dx(1) = +0.419974
gelu        d/dx(1) = +1.083315
softmax     每行和 max|Σ J| = 8.327e-17（3×3）
```

### 3.2 细节一：**哪些导数需要输入，哪些只需要输出**

```text
sigmoid    σ'(x) = σ(x)(1 − σ(x))     用**前向输出** ⇒ 不必再算一次 exp
tanh       tanh'(x) = 1 − tanh²(x)    同理
relu       relu'(x) = 1 if x > 0 else 0   只看**输入**的符号
gelu       gelu'(x) = 0.5(1 + erf(x/√2)) + x·e^{−x²/2}/√(2π)   ← **三项都要输入 x**
```

最后一条是这一课最容易漏的工程细节。看 gelu 的导数，第二项里有 `x·e^{−x²/2}`——
**输出 `y` 里没有 `x` 这个信息**。因此逐元素反向的签名必须是

```python
def elementwise_backward(name, pre_activation, grad_output): ...
```

而不是 `(output, grad_output)`。生产实现（`encoder_decoder.layers.activation_backward`）
接受的也正是 `pre_activation`——两条实现取同一个签名不是巧合，是为了能逐位对账。

### 3.3 细节二：relu 在 0 处取 0 是一个**约定**

```text
x = 0 处 relu 不可导（左导数 0、右导数 1）
本课取 0（次梯度）
```

取 1 也"说得通"，但那样一个**恒为负**的输入会一直拿到梯度，与"不激活就不学习"的直觉相反。
取 0 之后有一条更硬的结论：

```text
关掉的神经元在反向里梯度**恰好**是 0（不是"接近 0"）
```

这条在演示里有一个直接读数——第 4 章那张一层反向表的第一行 `dW` 全是 0：

```text
dW ((0.0, 0.0, 0.0), (0.75, 0.1875, -0.375), (0.125, -0.25, 0.5), (0.75, -2.0625, 4.125))
db (0.0, 0.75, 0.25, 1.75)
```

第 0 个神经元的 `db` 是 `0.0`、`dW` 整行都是 `0.0`：它在两个样本上的激活前值都不为正，
于是**它在这次反向里完全没有拿到梯度**。这不是"数值上很小"，是**恰好 0**。

### 3.4 细节三：逐元素反向走一条专门的分支

```text
relu 在 x <= 0 时直接返回**字面量 0.0**，而不是 grad * 0.0
```

后者在 `grad` 是 `inf` 时会得到 `nan`（`inf × 0`），而"关掉的神经元"应当**无条件**地
得到 0。这是一行看起来多余的代码，但它把"恰好 0"从"通常为 0"变成了"总是 0"。

## 第四章：一层全连接的反向 —— 三块梯度

### 4.1 形状就是口径

day089 的前向是 `y = x·Wᵀ + b`（`W` 形状 `(out, in)`）。它的反向有三块：

```text
grad_weight  (out, in)  = dYᵀ·X            回传梯度的每一列 · 输入
grad_bias    (out,)     = Σ_i dY[i]        偏置被所有行共用 ⇒ 按**行**求和
grad_inputs  (rows, in) = dY·W             按 W 的**列**收，而不是按行
```

演示读数（`dense(3→4)` + relu）：

```text
层：dense(3→4) | 激活 relu
输入     ((0.5, -1.0, 2.0), (1.0, 0.25, -0.5))
回传梯度 ((0.5, -1.0, 0.25, 2.0), (-0.5, 0.75, 1.0, -0.25))
dW ((0.0, 0.0, 0.0), (0.75, 0.1875, -0.375), (0.125, -0.25, 0.5), (0.75, -2.0625, 4.125))
db (0.0, 0.75, 0.25, 1.75)
dx ((1.1478459198781144, -0.2475310433760743, 1.6685977868067838),
    (0.41918413595018766, 0.1265846221383942, -0.37842959042111785))
三块账：第 1 层  W (4, 3) | ‖dW‖=4.785231e+00 ‖db‖=1.920286e+00 ‖dx‖=2.120846e+00
```

### 4.2 第三条式子的下标最容易搞反

```text
正确   dx_c = Σ_r dY_r · W[r][c]      遍历的是 W 的**列**（r 是输出维）
写错   dx_c = Σ_r dY_r · W[c][r]      形状仍然对（都是 (rows, in)），数值全错
```

**"形状仍然对"是它危险的地方**：一个把 `W` 与 `Wᵀ` 用反的实现不会报任何错，
只会让训练变慢或发散——而它看起来像"学习率没调好"。

### 4.3 累加方式刻意与 `encoder_decoder` 相同

```text
grad_weight / grad_bias   用**普通累加**（与 encoder_decoder.layers.feed_forward_backward 相同）
grad_inputs               用 math.fsum（同样与它相同）
```

两条都对齐，才能让第 7 条性质（与项目里真实的前馈反向**逐位**一致）成立。
这不是"随手挑了一个更精确的求和"，是为了那条对账——**换一个求和顺序，
两个实现会在最后一位上分家，而"最后一位不同"与"实现写错了"在读一个标量时看不出来。**

## 第五章：一个网络的反向与"缓存留什么"

### 5.1 逐层回传

```text
对第 i 层：  激活的反向 → 仿射的反向（dW、db、dx）→ 把 dx 交给第 i−1 层
```

演示读数（MLP `3 → 5 → 2`，32 个参数）：

```text
第 1 层  W (5, 3) | ‖dW‖=4.161506e-01 ‖db‖=2.680254e-01 ‖dx‖=2.298692e-01
第 2 层  W (2, 5) | ‖dW‖=4.597281e-01 ‖db‖=5.809431e-01 ‖dx‖=7.297891e-01
```

### 5.2 缓存三样，而不是重跑前向

```text
Dense 的反向需要        这一层的**输入**（算 dW = dYᵀ·X）
逐元素激活的反向需要     激活**前**的值（gelu 的导数里有 x·e^{−x²/2}）
softmax 的反向需要       激活**后**的值（softmax 的输出就是它自己的概率）
```

三样东西**各不相同**。`ForwardCache` 把它们都留下来：

```text
inputs          每一层的输入（第 0 项是整个网络的输入）
pre_activations 每一层激活前的值（无激活时为 None）
outputs         每一层激活后的值（softmax 的反向读它）
```

为什么不是"反向时把前向重跑一遍"：数学上一样，但**它会让反向依赖前向的参数**，
而参数在反向过程中正是我们要算的东西。留下来之后，反向只读缓存，不碰参数。

`activation_backward` 把"哪个激活需要什么"收在一处：

```python
if activation is None:      return grad_output            # 恒等
if activation == "softmax": return softmax_backward_rows(output, grad_output)
if pre_activation is None:  raise BackwardError(...)      # 缓存不是同一次前向的
return elementwise_backward(activation, pre_activation, grad_output)
```

**把 softmax 也当成逐元素的后果**是：它会被当成"每个数各自一个导数"，
而它其实是一整行一起变——形状对、数值错。这正是 `BackwardError` 存在的理由：
"这一组反向量与缓存不是同一次前向"和"公式抄错了"是两种完全不同的诊断。

## 第六章：一份计算图 —— 张量级自动微分

### 6.1 day074 已经有一张图了，为什么还要再做一张

```text
day074 标量图    讲清"链式法则"与"梯度必须累加"这两件事
day090 张量图    把这两件事**搬到一个真实的层上**
```

区别是具体的：一次矩阵乘的局部导数是一对公式

```text
C = A·B        dA = dC·Bᵀ        dB = Aᵀ·dC
```

它们**不是逐元素的**（每一侧的局部导数都用到对方的转置），因此在标量图里看不到。

### 6.2 三个约定（与 day074 逐字相同）

```text
① 值一旦建图就不改         原地改 value 会让已算出的梯度与新的前向值不对应
② 梯度一律用累加           一个值被用了 k 次，梯度是 k 条路径之和
③ requires_grad=False 是常量  它参与计算，但不接收梯度
```

第三条的用处：否则每一处 `x * 2` 都会在图上留下一个永远为 0 的梯度节点，
而"这个参数不学"与"它的梯度恰好是 0"在读表时长得一样。

### 6.3 两条独立路径对上：**逐位一致**

```text
手写反向：32 个偏导数
图自动微分：32 个偏导数，损失 = 0.344065402687
两条路径最大偏差 0.000e+00（逐位一致：True）
```

这是这一课第一次出现"两份**独立**的反向代码给出逐位相同的结果"。它有意义的前提是
两份代码**不共享任何一行反向逻辑**：`layers.dense_backward` 用的是
"按行 → 按输出维 → 按输入维"的循环 + `math.fsum`，而 `graph.dense` 用的是
"先算 dX、再算 dW、再算 db"的三段式。两者独立写、独立错，因此对上才有信息量。

## 第七章：softmax —— 局部导数是一张矩阵，但从不真的建出来

### 7.1 雅可比

```text
J[i][j] = p_i(δ_ij − p_j)      n² 个元素
```

它有一个立刻可验的性质——**每一行之和为 0**：

```text
Σ_j J[i][j] = Σ_j p_i(δ_ij − p_j) = p_i(1 − Σ_j p_j) = p_i·0 = 0
```

演示读数：

```text
概率 (0.2, 0.3, 0.5)
显式雅可比 ((0.16, -0.06, -0.10), (-0.06, 0.21, -0.15), (-0.10, -0.15, 0.25))
每一行之和 [2.776e-17, 0.0, 0.0]（理论上全为 0）
```

"每一行和为 0"就是"平移不变"在导数上的样子：概率之和恒为 1，因此它的导数
必须正交于全 1 方向。`study` 的导数表里 softmax 那一行印的正是这个读数
（`max|Σ J| = 8.327e-17`），而不是 n² 个元素。

### 7.2 反向真正要算的东西只有 O(n)

```text
(Jᵀv)_i = Σ_j J[j][i]·v_j
        = Σ_j p_j(δ_ji − p_i)·v_j
        = p_i·v_i − p_i·Σ_j p_j·v_j
        = p_i(v_i − ⟨p, v⟩)
```

演示读数：

```text
回传梯度 (0.5, -1.0, 2.0)
Jᵀv（显式）    (-0.06, -0.54, 0.6)
p⊙(v − ⟨p,v⟩) (-0.06000000000000001, -0.54, 0.6)
最大偏差 1.388e-17 <= 容差 1e-12
```

两式**恒等**，但中间量从 `n²` 降到 `n`。因此本课把显式雅可比也实现了——
**它的唯一用途是被对照**；生产路径只走那条 JVP。

## 第八章：两个损失的梯度与"雅可比被消掉"

### 8.1 两个损失

```text
mse             ∂L/∂pred  = 2(pred − target)/N      N = **全部元素**的个数
cross_entropy   ∂L/∂logits = p − onehot(target)      p = softmax(logits)
```

演示读数：

```text
mse_grad(((1,2),(3,4)), ((1.5,1.5),(4,3))) = ((-0.25, 0.25), (-0.5, 0.5))    （N = 4）
cross_entropy_grad((1,2,3), 0)  = (-0.909969, 0.244728, 0.665241)
cross_entropy_grad((0.2,), 0)   = ( 0.0,)
cross_entropy_grad((-1,0,1), 2) = ( 0.090031, 0.244728, -0.334759)
```

两个"不报错但结果错"的地方：

```text
MSE 少一个 2        梯度整体减半 ⇒ 看起来像"学习率需要加倍"
CE 忘记除以行数     梯度大 rows 倍 ⇒ 看起来像"这一批的学习率要除以 batch size"
```

### 8.2 这条恒等式很漂亮，但它藏了一个真实的盲区

```text
∂(−log p_k)/∂z = p − onehot(k)      ← softmax 的雅可比与 −log 的导数相乘之后**化简**了
```

于是：

```text
softmax 的雅可比写错了   ⇒  交叉熵的梯度**仍然是** p − onehot
                            （因为正确的实现也不直接用它）
```

这不是"多验一遍"的问题，而是"**只有这一遍能发现它**"——因此本课把
softmax 的雅可比单独验一次（第 3 条性质），而不是只验交叉熵。

### 9.1 三条路径

### 9.2 三条在同一张网上的读数

```text
A vs B   手写反向 32 个偏导数 vs 图自动微分：最大偏差 0.000e+00（**逐位一致**）
```

```text
逐点导数       5 个激活 × 5 个点 = 25 个读数，最大相对误差 1.398e-10（容差 1e-6）
softmax 雅可比 3 行、26 个元素，最大相对误差 3.681e-11
JVP 恒等式     3 行、最大偏差 2.776e-17（容差 1e-12）
交叉熵梯度     4 组（长度 1~4）、11 个偏导数，最大相对误差 2.465e-10
```

并且与 day074 的那份**独立结论**对上：

```text

day074 gradcheck.check_cross_entropy_gradient  [agrees] 13 个点，最大误差 5.73e-10
```

### 9.4 跨包逐位：与 day079 的真实前馈反向

```text
hidden=4、d_ff=16、输入 2 行 × 4 列、回传梯度 2 行 × 4 列
[relu] 五块梯度共 156 个元素，逐位不一致 0 个
[gelu] 五块梯度共 156 个元素，逐位不一致 0 个
```

`156 = 64(w_in) + 64(w_out) + 16(b_in) + 4(b_out) + 8(dx)`。四条前提：

```text
① 同一组权重            直接用 encoder_decoder.FFNWeights 的四块，不重新初始化
② 形状约定相同          w_in (d_ff, d)、w_out (d, d_ff)，前向 x·Wᵀ + b
③ 累加方式相同          都用 math.fsum，且乘法顺序相同
④ 激活公式相同          relu = value if value > 0 else 0.0；gelu = 精确 erf 式
```

四条里少任何一条，两个实现都可能在最后一位分家——而"最后一位不同"会被误读成"接错了"。

### 9.5 容差从哪来（不是拍一个数）

数值差分自身的误差下限是 `eps·|f|/(2h)`：

```text
|f| ≈ 1      h = 1e-6   →  1.110e-10      容差 1e-6 是它的 9000 倍，够松
|f| ≈ 100    h = 1e-6   →  1.110e-08      仍在容差之内
```

低于这个下限的容差只会产出假警报，而假警报比漏报更坏——它会让人去改一份正确的代码。

## 第十章：一次真的下降

### 10.1 把梯度变成一次下降

```text
θ ← θ − lr·g          g 来自本包的**解析反向**
```

day074 的 `optim.minimize` 里已经有一个训练回路，但它的梯度来自**数值差分**：

```text
day074 minimize(...)   每一步 2n 次函数求值——慢，但不依赖任何推导
day090 train_mlp(...)  每一步 1 次前向 + 1 次反向——快，但依赖"推导是对的"
```

差别不是速度，而是**由谁保证正确性**：

```text
数值差分版    正确性由"尺子"保证（慢，但不会错）
解析反向版    正确性由"对账"保证（快，但必须与尺子比过一次）
```

因此这一课的顺序永远是：**先写反向 → 再与尺子比 → 比过了才敢用它下降。**

### 10.2 演示读数

```text
sgd（20 步，lr=0.05）：  20 步 sgd | 损失 0.344065 → 0.016529（↓95.2%）| 单调 是
adam（20 步，lr=0.05）： 20 步 adam | 损失 0.344065 → 0.016064（↓95.3%）| 单调 否
```

两行里有两个值得注意的地方：

```text
起点相同        两者用的是同一份初始参数（LCG + 写死的种子）
终点相近但路径不同  adam 的曲线**不是单调**的——这正是它"每个参数各自等效步长"的代价
```

优化器**复用 day074** 的那三个（`sgd` / `momentum` / `adam`）：这一课要证明的是
"梯度是对的"，而优化器是对错的**无关变量**。把它复用过来，恰恰是为了让
"损失下降"这件事只可能归因于梯度。

### 10.3 三条护栏

```text
护栏一   梯度必须有限       出现 nan / inf 时当场抛 NumericError
护栏二   参数更新后必须有限 一步走完成了 inf ⇒ StepError（学习率太大，不是数据坏了）
护栏三   长度必须对得上     压平 / 还原之间长度不符 ⇒ ShapeError，绝不"按顺序切"
```

三条都来自同一个观察：**训练里的错误几乎都不会当场报错**，它们只会让曲线
"看起来不太对"。把这三条写成异常，是让它们能被看见的最便宜的办法。

## 第十一章：一个真实的坑 —— 它连报错都没有

### 11.1 撞上什么

写 `study` 的导数表时，softmax 那一行要印"雅可比每行之和"。第一版是这样写的：

```python
if name == "softmax":
    jacobian = gradients.softmax_jacobian(SOFTMAX_SAMPLE_ROW)   # SOFTMAX_SAMPLE_ROW = (1.0, 2.0, 3.0)
    row_sums = tuple(math.fsum(row) for row in jacobian)
    reading = f"每行和 max|Σ J| = {max(abs(value) for value in row_sums):.3e}"
```

跑出来的读数是：

```text
softmax     每行和 max|Σ J| = 1.500e+01（3×3）
```

`15.0`。而正确的读数必须是 `8.327e-17`（也就是 0）。**它没有报错。**

### 11.2 真相

`SOFTMAX_SAMPLE_ROW = (1.0, 2.0, 3.0)` 是**打分**，而 `softmax_jacobian` 的入参是
**概率**。把打分当概率传进去，函数照样返回一张"看起来很像雅可比"的矩阵：

```text
用打分 (1, 2, 3) 算       J[0] = (0.0, -2.0, -3.0)      ← 对角线上是 z_i(1 − z_i)
用概率 p = softmax(1,2,3)  J[0] = (0.0819, -0.0220, -0.0599)  ← 一行和为 0
```

两者形状一样、都是有限的数、都能被 `math.fsum` 求和——因此**编译器不会拦，
测试不写也不会拦**。唯一拦住它的是"每行和必须为 0"这条判据。

### 11.3 同族坑的第三次记录

```text
day088   把 Q 与 K 写成互为转置 ⇒ 报的是形状错误，
         踩的却是**定义**错误（打分是点积，不是矩阵乘法的内维约定）
day089   在中文里写 ASCII 引号 ⇒ 报的是 SyntaxError（"少了一个逗号"），
         踩的却是**定界符**错误（字符串在中文里被提前结束）
day090   把打分当概率传给 softmax_jacobian ⇒ **什么都不报**，
         只是"每行和 = 1.5"这个读数安静地不是 0
```

三次都说明同一件事，而第三次把它推到了极限：

```text
报错的                  最好，顺着栈就能找到
报错但报错位置很远的     要问"报错信息里的局部症状是不是病灶"（day088 / day089）
不报错的                最难——只能靠**判据**
```

顺带记一笔：今天写 `train.py` 时又踩了一次 day089 那个坑（中文里写 ASCII 引号），
`py_compile` 当场报的就是"Perhaps you forgot a comma?"。**同一个坑会在同一天里
以两种面貌出现**——这说明它不是一个手误，而是一条需要被判据覆盖的边界。

## 失败族的第九次改口径：第一次是"加回来"

```text
day075~081   有手写反向            ⇒ 有 GradientError 那一族
day082~089   没有手写反向          ⇒ 这一族连续缺席八天
day090       有手写反向 + 自动微分  ⇒ **它回来了**
```

前面八天每一次都给出一条"为什么今天没有它"的理由（读别人的推理路径、装进来的层、
不可微、没有新式子……）。今天不再需要理由——因为今天的**全部内容**就是这件事。
因此本课第一次让 `ABSENT_FAMILY` 为空：

```text
RETURNED_FAMILY = "GradientError"
ABSENT_FAMILY   = None          （不是"没有理由"，而是"没有缺席者"）
```

而今天新增或首次真正使用的族，各自要改的东西都不同：

```text
GradientError     改推导        解析式与数值差分对不上时，先怀疑漏了一项或符号写反
BackwardError     改调用        cache 必须是**同一次前向**的产物，缺了就重跑前向
ChainError        改推导        梯度一律用 +=、常量不接收梯度、重复反向前先清零
StepError         改调用        调小学习率或加裁剪——梯度合法不代表这一步走完还合法
```

`ChainError` 值得单独说一句：它描述的是**三种不报错、只算错**的接线方式。
把它独立成族，是为了让"这一次要改的是接线"这句话可以被直接读出来——
而不是让改的人去推公式，而公式一直是对的。

## 边界与后续

### 五条边界（**本课明确不承诺的事**）

```text
① 本包实现的是**一阶**反向：只算梯度，不算 Hessian / 二阶导数，也不做二阶优化
② 本包不安装、也不调用 torch / numpy：PyTorch 的语义只写在 TORCH_COUNTERPARTS 对照表里，
   对照的是公式与语义，不是"实测 torch 输出"；具体版本以官方文档为准
③ 本包的自动微分只覆盖一个 MLP 用得到的算子（matmul / 加偏置 / 五个逐元素激活 /
   softmax / mse / 交叉熵），不是"任意计算图"
④ 权重由 LCG 生成、输入写死，因此复现的是**读数**、不是统计规律
⑤ 不承诺浮点意义上的"位逐位跨平台一致"——跨天对账的容差由各自的口径给出
```

### 两个悬念

```text
二阶       今天有了一阶反向；"曲率"（Hessian / 二阶优化）没有——它不在 M8 的这七天里
优化器     今天用的是 day074 的三个优化器；"为什么 Adam 第一步恰好是 lr·sign(g)"
           与"学习率曲线为什么先升后降"是 day092 的主题
```

今天最值得带走的一句话，与前几天那几句对着看：

```text
day087  缓存不是"变快"而是"换"；位置必须由**缓存长度**决定
day088  原理只有落到一个**能被解析的函数**上、并且能被**现场量出读数**，才算真的串起来了
day089  深度本身不产生非线性：让"多层"区别于"一层"的，是**那个激活函数**
day090  反向传播 = **上游梯度 × 局部导数，然后累加**——
        前半句是链式法则，后半句是纪律；而纪律那半句写错时，程序不会报错。
```

四句都是"一句话 + 一个能失败的判据"，而今天这一句的判据就是第九章那张对账表：
手写反向与图自动微分的偏差 `0.000e+00`、与 `encoder_decoder` 的逐位不一致 `0 个`、
与数值差分的相对误差 `5.813e-11`——**三条独立路径同时确认同一批数**，
才叫"这一次反向是对的"。
