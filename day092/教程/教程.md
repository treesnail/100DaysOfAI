## 第二章：一步 = 学习率 × 更新规则

### 2.1 先看六个规则各自"是什么"

`optimizers/types.py` 把六个规则写进一张表，`study.rule_rows()` 把它印出来：

```text
sgd        | shared | 状态 无                          | θ ← θ − lr·g
momentum   | shared | 状态 velocity                    | v ← β·v + g；θ ← θ − lr·v
nesterov   | new    | 状态 velocity                    | v ← β·v + g；θ ← θ − lr·(g + β·v)
rmsprop    | new    | 状态 square_avg                  | s ← ρ·s + (1−ρ)·g²；θ ← θ − lr·g/(√s + ε)
adam       | shared | 状态 first_moment / second_moment | m/v 各带偏差修正；θ ← θ − lr·m̂/(√v̂ + ε)
adamw      | new    | 状态 first_moment / second_moment | Adam 更新后再 θ ← θ·(1 − lr·λ)
```

这张表有三列是同源的：**公式、状态、归属**。三列必须逐键对齐——
否则某个规则在报告里只剩名字、没有它实际执行的那一行更新。

### 2.2 一步表：同一组输入各走一步

`study.one_step_rows()` 从同一组写死输入（θ=(1,−2,3)、g=(0.5,−1,2)、lr=0.1）各走一步：

```text
sgd        | θ₀ 1.000000 → 0.950000 | ‖一步‖ = 2.291e-01
momentum   | θ₀ 1.000000 → 0.950000 | ‖一步‖ = 2.291e-01
nesterov   | θ₀ 1.000000 → 0.905000 | ‖一步‖ = 4.353e-01
rmsprop    | θ₀ 1.000000 → 0.000000 | ‖一步‖ = 1.732e+00
adam       | θ₀ 1.000000 → 0.900000 | ‖一步‖ = 1.732e-01
adamw      | θ₀ 1.000000 → 0.900000 | ‖一步‖ = 1.732e-01
```

三行读数各讲一件事：

1. **momentum 的第一步与 sgd 完全相同。** 因为速度从 0 出发：`v₁ = β·0 + g = g`，
   方向仍是 `g`。动量的作用从**第二步**才开始——这是"动量的好处"最容易被误读的地方。
2. **nesterov 的第一步就比 momentum 大。** 方向 = `g + β·v₁ = g + β·g = 1.9g`。
   它比普通动量"多看了未来一眼"（第四章）。
3. **rmsprop 的第一步大得离谱**（‖一步‖=1.732，是 lr 的 17 倍）。因为二阶动量从 0 出发：
   `s₁ = (1−ρ)g²`，分母很小。这正是 Adam 需要**偏差修正**的原因（第五章）。

### 2.3 为什么"学习率"和"更新规则"必须分开看

一个常数学习率在真实训练里几乎总是错的，而对的原因每次都不同；但**更新规则**回答的是
另一个问题：这个标量作用在"梯度"上，还是作用在"梯度的滑动平均"上，还是"被归一化之后"？

```text
学习率     一步走多远（标量）
更新规则   这一步朝**哪个**方向、这个方向被**怎么加工**过
```

把两者混着调的症状很具体：loss 不降时先怀疑学习率，但真正错的是"更新规则用错了地方"
（例如把解耦衰减写成了耦合）。第二章到第六章分别把这两件事拆开。

## 第三章：训练期优化器 —— 四个动作的顺序

### 3.1 顺序是写死的，不给调用方拼

`optimizers/optimizer.py` 的 `TrainingOptimizer.step()` 按固定顺序做四件事：

```python
def step(self, params, grads):
    checked_params, checked_grads = checked_pair(params, grads)
    self.step_count += 1
    # ① 学习率：调度在**这一步之前**取值
    if self.schedule is not None:
        self.learning_rate = checked_non_negative(self.schedule(self.step_count), ...)
    # ② 裁剪：先记裁剪前范数，再替换梯度
    if self.max_grad_norm is not None:
        self.last_grad_norm = global_norm(checked_grads)
        checked_grads, self.last_clip_factor = clip_gradients(checked_grads, self.max_grad_norm)
    # ③ 耦合衰减：λθ 进梯度（在更新规则之前）
    effective = checked_grads
    if self.decay_mode == DECAY_L2:
        effective = l2_gradient(checked_grads, checked_params, self.weight_decay)
    updated = self._apply_rule(checked_params, effective)
    # ④ 解耦衰减：先更新、再缩参数（AdamW 的那一步）
    if self.decay_mode == DECAY_DECOUPLED:
        updated = apply_decoupled_decay(updated, self.learning_rate, self.weight_decay)
    return self._checked_result(updated)
```

### 3.2 两个顺序问题都不会报错

```text
衰减在裁剪之前   先加 λθ 再裁剪 ⇒ 衰减会被裁剪系数一起缩掉
解耦当成梯度用   θ·(1−lr·λ) 若写成 g + λθ ⇒ 它会被 √v̂ 除成随尺度变化的强度
```

两者都是"结果看起来正常、只是那个系数不再等于你设的值"。因此 `step` 把顺序写死，
**不给调用方自己拼的机会**——这是本模块最重要的一条设计决定。

### 3.3 交付之前先校验

`_checked_result()` 在返回前检查参数是否仍然有限：学习率大到把参数推到 `inf` 时抛
`StepError`，而**不是**让它以 `nan` 的形式流进下一次更新：

```python
for index, value in enumerate(params):
    if not math.isfinite(value):
        raise StepError(f"第 {index} 个参数在这一步之后变成了非有限数（{value!r}）...")
```

跨步状态也有检查：动量 / 二阶动量的长度与参数不符时抛 `StateError`——
它最可能来自"换了任务却忘了 `reset()`"（第十章）。

## 第四章：Nesterov —— 不是"换个动量系数"

### 4.1 差别只有一行

```text
速度更新          v ← β·v + g        两者**逐字相同**
方向              动量: v            方向 = 当前速度
                  Nesterov: g + β·v  方向 = 当前梯度 + 一点未来的速度
```

`rules.nesterov_step()` 把这一步写得很直白：

```python
new_velocity = tuple(beta * previous + slope for previous, slope in zip(velocity, grads))
direction = tuple(slope + beta * speed for slope, speed in zip(grads, new_velocity))
updated = tuple(value - rate * step for value, step in zip(params, direction))
```

### 4.2 一条下界判据

把 Nesterov 写成普通动量，**不会报错**：两条轨迹只是数值不同，都"看起来正常"。
因此 `verify` 的第 ② 条性质用的是一个**下界**判据：

```text
通过 nesterov_is_not_momentum | 读数 3.226e-01 >= 1.0e-06 | momentum vs nesterov
```

读数是两条轨迹在病态峡谷上跑 25 步后最终参数的最大差（**0.3226**），
判据是"必须不小于 1e-6"。这一条专门用来钉住"它俩确实不是一回事"。

### 4.3 病态峡谷上它确实更快

`compare` 在 `anisotropic_valley`（一个方向陡 24 倍）上的读数：

```text
sgd        | 40 步 | 损失 5.250000e+01 → 7.432e-02（↓99.9%）
momentum   | 40 步 | 损失 5.250000e+01 → 2.103e-01（↓99.6%）
nesterov   | 40 步 | 损失 5.250000e+01 → 5.319e-03（↓100.0%）
```

Nesterov 的终值比普通动量好一个数量级（5.3e-3 对 2.1e-1）——lookahead 在陡方向上
提前刹车。这一行是**本机在这个确定性目标上**跑出来的读数，不是一条普遍结论。

## 第五章：RMSProp 与 Adam 的偏差修正

### 5.1 RMSProp 是 Adam 的一半

```text
s ← ρ·s + (1−ρ)·g²          只保留二阶动量
θ ← θ − lr·g/(√s + ε)       分母把每个参数的尺度归一
```

它的价值是"尺度无关"：`s` 的稳态是 `E[g²]`，因此 `g/√s` 的尺度与 `g` 的大小无关。
`verify` 的第 ④ 条性质把这件事量出来：两个相差 1e4 的常量梯度（100 与 0.01），
在稳态下每步位移几乎相同：

```text
通过 rmsprop_equalizes_scale | 读数 5.773e-08 <= 1.0e-05 | g=100 vs g=0.01
```

读数只有 `5.8e-08`——差的那一点来自 `ε`（`g=0.01` 时分母 `√s≈0.0093`，
`ε=1e-8` 不是完全可忽略）。而**SGD 下这两者会差 1e4 倍**。

### 5.2 第一步为什么会"跳"

第二章的一步表里，RMSProp 的第一步是 lr 的 17 倍。原因是 `s` 从 0 出发。
Adam 也有一阶、二阶两个滑动平均从 0 出发，因此它需要**偏差修正**：

```text
m₀ = 0   →   m₁ = (1−β₁)g₁ = 0.1g₁        只有真值的 1/10
v₀ = 0   →   v₁ = (1−β₂)g₁² = 0.001g₁²    只有真值的 1/1000
不做修正时第一步的更新量 ≈ lr·3.16（比设定值大 3 倍多）
除以 1−β₁ᵗ 与 1−β₂ᵗ 之后，第一步恰好是 lr·sign(g)
```

这一步在代码里就是 `math_foundations.optim.AdamOptimizer` 的 `correction1` / `correction2`
（day074 写的，本课一字未改，只在 `test_optimizers.py` 里对账）。

## 第六章：衰减 —— 耦合（L2）与解耦（AdamW）

### 6.1 两种衰减不是"同一个东西的两种写法"

```text
耦合 L2        g ← g + λθ          λθ 会一起被 Adam 的分母 √v̂ 除一下
解耦（AdamW）  θ ← θ·(1 − lr·λ)    λθ 不进梯度，与分母无关
```

后果很具体：耦合版里"梯度大的参数衰减得更弱"，不是我们想要的"人人等量衰减"。
`rules.py` 把它们写成两个函数，`optimizer.step` 分别放在更新规则之前 / 之后：

```python
def l2_gradient(grads, params, weight_decay):
    return tuple(value + weight_decay * param for value, param in zip(grads, params))

def apply_decoupled_decay(params, learning_rate, weight_decay):
    factor = 1.0 - learning_rate * weight_decay
    return tuple(value * factor for value in params)
```

### 6.2 一步的差多少（演示脚本第 4 节）

同一组输入（θ=(1,2)、g=(1,0)、lr=0.1、λ=0.5）：

```text
decay=none       θ=(1,2) → (0.900000, 2.000000)
decay=l2         θ=(1,2) → (0.850000, 1.900000)
decay=decoupled  θ=(1,2) → (0.855000, 1.900000)
```

`l2` 与 `decoupled` 只差在第二位小数（0.850000 对 0.855000），**但它们不是同一个东西**：
在梯度尺度变化时差别会放大。第 ③ 条性质用一个下界判据把它钉住：

```text
通过 decoupled_decay_differs_under_varying_gradients | 读数 2.621e-01 >= 1.0e-09
```

读数 `0.2621` 是两条轨迹跑 25 步后最终参数的最大差。只有 `0.2621` 这一个数，
才说明"解耦不是摆设"。

## 第七章：七条性质与三类判据

### 7.1 判据有三类（本课新增第三类）

```text
相等（逐位）  ① 共享规则与 day074 逐位一致（读数 0.000e+00）
              ⑥ 裁剪与 day074 逐位一致（读数 0.000e+00）
              ⑦ 调度与 day074 逐点一致（读数 0.000e+00）
上界          ④ RMSProp 把相差 1e4 的梯度归一（读数 5.773e-08 <= 1.0e-05）
              ⑤ 裁剪只改长度不改方向（读数 0.000e+00 <= 1.0e-12）
下界          ② Nesterov 与普通动量必须不同（读数 3.226e-01 >= 1.0e-06）
              ③ AdamW 与 Adam+L2 必须不同（读数 2.621e-01 >= 1.0e-09）
```

### 7.2 为什么必须有"下界"这一类

前面各天的判据都是"**≤ 某个上界**"或"**逐位相等**"——它们回答"这个对不对"。
但本课有一半的内容是"**两个规则不是一回事**"。如果只写上界判据，那么：

```text
把 Nesterov 写成普通动量   ⇒ 报告全绿（两条轨迹都"看起来正常"）
把解耦写成耦合             ⇒ 报告全绿（参数都在合理范围）
```

于是 `Check` 增加了 `lower_bound` 字段：**读数必须不小于它**。
这一条是从"报告能不能被反驳"出发的：一个判据如果对错误实现也成立，它就不算判据。

### 7.3 三条跨天对账都在调用 day074

`verify.check_all()` 的 ①⑥⑦ 三条对账分别调用 `math_foundations` 的：

```text
①  make_optimizer("sgd" / "momentum" / "adam")  逐位比
⑥  clip_by_global_norm                           比梯度与缩放系数
⑦  warmup_cosine_schedule                        逐点比
```

**自证是不成立的**：如果本课自己写一份裁剪、再用本课自己的另一处调用去"证明"它，
那只是在证明"我抄得一致"。第 ⑥⑦ 条的对方是 day074——本课没有改动它一行。

## 第八章：收敛对比 —— 同一把尺子上的六个变体

### 8.1 比较的变量收敛到"只剩优化器"

`compare.py` 复用 day074 的 `minimize`，而 `minimize` 的梯度由**数值差分**给出：

```text
数值差分    慢，但独立于任何推导 ⇒ 它验证的是"优化器本身"
解析梯度    快，但与推导绑定     ⇒ 优化器写错时会与梯度错误混在一起，查不清是谁
```

day090 已经用三条路径把梯度钉住；到了这一课，梯度是一个**已经可信的输入**，
因此统一用同一把尺子，把变量收敛到"只剩优化器"。

### 8.2 良态碗上的读数

```text
sgd        | 40 步 | 损失 1.300000e+01 → 2.840e-03（↓100.0%）| 单调 是
momentum   | 40 步 | 损失 1.300000e+01 → 1.750e-01（↓98.7%） | 单调 否
nesterov   | 40 步 | 损失 1.300000e+01 → 2.667e-03（↓100.0%）| 单调 否
rmsprop    | 40 步 | 损失 1.300000e+01 → 3.951e-03（↓100.0%）| 单调 是
adam       | 40 步 | 损失 1.300000e+01 → 1.513e+00（↓88.4%） | 单调 是
adamw      | 40 步 | 损失 1.300000e+01 → 1.513e+00（↓88.4%） | 单调 是
```

这张表最反直觉的一行是 **Adam 在这里最差**（1.5e+00）。这不是"Adam 不好"，而是：

```text
良态碗是各向同性的     ⇒ SGD 本来就能一步一个脚印地走到底
固定 lr=0.05 + 40 步   ⇒ 自适应方法把每步都压到 ≈lr，反而"走不快"
```

这正是"没有免费的午餐"的一个具体读法：**在良态问题上，自适应是负担**；
它的价值要在病态 / 尺度差异大的问题上才显现。

### 8.3 Rosenbrock 上的读数（并有一个必须写下来的边界）

```text
momentum   | 60 步 | 损失 2.420000e+01 → 1.048e-01（↓99.6%）
nesterov   | 60 步 | 损失 2.420000e+01 → 6.115e-01（↓97.5%）
sgd        | 60 步 | 损失 2.420000e+01 → 3.469e+00（↓85.7%）
rmsprop    | 60 步 | 损失 2.420000e+01 → 4.257e+00（↓82.4%）
adam       | 60 步 | 损失 2.420000e+01 → 5.681e+00（↓76.5%）
adamw      | 60 步 | 损失 2.420000e+01 → 5.681e+00（↓76.5%）
```

在香蕉形窄谷上，**普通动量反而第一、Nesterov 第二**——这与第四章"病态峡谷上 Nesterov
更快"不矛盾，因为两个目标的几何完全不同（峡谷是各向异性椭圆，香蕉是弯曲窄谷）。
两种读数都真实，只是各回答一个"在这个目标上"的问题。

> **必须写下来的边界**：这些是**单条确定性轨迹**的读数，不是统计意义上的"哪个更好"。
> 随机初始化、批大小、数据分布都没被扫。它证明的是"这几个更新规则**在这三个写死的
> 目标上**表现如何"。要下普遍结论，必须扫参、跑多次、换多组数据。

## 第九章：为 SmartResearch Agent 选优化器

curriculum 的第三条目标是"为 SmartResearch Agent 的微调脚本选择合适优化器"。
`advisor.py` 把它落成一张表（`scripts/optimizers_demo.py` 第 11 节原样打印）：

| 场景 | 推荐 | 起点 lr | 衰减 | 为什么 |
|------|------|---------|------|--------|
| sft-lora | adamw | 1e-4 | 解耦 0.01 | 解耦衰减不随梯度尺度变化 |
| sft-full | adamw | 2e-5 | 解耦 0.10 | 全参更敏感、更易过拟合 |
| dpo | adamw | 5e-7 | 解耦 0.00 | 偏好优化对 lr 极敏感 |
| scratch-mlp | adam | 1e-2 | 无 | 小网络用 Adam 起步快 |
| ill-conditioned | nesterov | 1e-2 | 无 | 病态峡谷靠动量与 lookahead |
| cpu-tiny | rmsprop | 1e-2 | 无 | 只归一化尺度、最省内存 |

### 9.1 推荐必须**可执行**

`Recommendation.build()` 会按推荐造出一个真的优化器，并且 `test_optimizers.py`
里有一条用例断言"按推荐造出的优化器能在良态碗上真的把损失降下来"：

```python
rec = advisor.recommend("scratch-mlp")
row = compare.run_optimizer(rec.build(), bowl, (3.0, -2.0), steps=40)
assert row.final_loss < row.initial_loss
```

一段"应该用 AdamW"的散文谁都会写；一条**能造出对象、能跑出下降**的推荐才算数。

### 9.2 一句必须写进文档的话

> **这些数字是本仓库的"起点配置"，不是"最优配置"。** 它们来自"从更新公式能读出的
> 默认值 + 工程惯例"，加一句"为什么"。真正的调参必须在自己的数据上跑。
> 把这句话写进文档，是为了不让"推荐值"被误读成"最优值"。

三条推荐的理由都能在公式表里找到依据：例如"LoRA 用 AdamW"的理由是**解耦衰减
不随梯度尺度变化**，而不是"经验告诉我"。

## 第十章：失败族与那条纪律

### 10.1 五个族，按"该谁去修"分

```text
ShapeError       形状不符      参数与梯度长度不符            → 改调用
ParameterError   参数越界      学习率 / 衰减 / 动量参数越界   → 改调用
NumericError     数值不可用    nan / inf 混进参数或状态       → 改数据或改实现
StateError       状态不匹配    动量长度与参数不一致           → 改调用（先 reset）
StepError        更新不成立    一步走完参数不再有限           → 改调用
```

`StateError` 独立成族的理由是**时机**：`ShapeError` 是"这一次调用"的问题，
`StateError` 是"跨步状态"的问题——最典型的是"换了任务、换了参数形状，却忘了 `reset()`"。
`TrainingOptimizer.reset()` 清空步数与全部跨步状态，**参数不动**。

### 10.2 GradientError 再次缺席——但理由与那八天都不同

```text
day082~089   没有手写反向          ⇒ 这一族连续缺席八天
day090       有手写反向 + 自动微分  ⇒ GradientError **回来了**
day091       复盘日
day092       消费梯度、不计算梯度    ⇒ GradientError **再次缺席**
```

本课的全部输入就是一个已经算好的梯度向量 `g`。因此"两条独立路径的梯度对不上"
在今天**不可能发生**：本课一行都不算梯度。把这条写进常量
（`ABSENT_FAMILY = "GradientError"`），是为了让"今天没有它"成为一个可断言的
事实，而不是一段散文——`test_optimizers.py` 直接断言了这两个常量。

## 第十一章：六张表

`study.py` 留下六张表，因为**一个数只有被印出来才可能被反驳**：

```text
① 规则表     六个规则：公式 / 状态变量 / 复用还是新增
② 一步表     六个规则从同一组写死输入各走一步：首分量 + 步长范数
③ 裁剪表     整体范数裁剪：裁剪前范数 / 缩放系数 / 裁剪后范数 / 方向余弦
④ 调度表     先升后降：热身与退火各取几个点，印出实际学习率
⑤ 对比表     三个目标函数上六个优化器的到容差步数与最终损失
⑥ 性质表     七条性质是否通过 / 现场读数 / 跨包对象
```

裁剪表那一行把"只改长度不改方向"写成了两个数：

```text
‖g‖ 1.118e+02 → ‖g'‖ 1.000e+00 | 系数 8.944e-03 | cos 1.000000
```

范数从 111.8 缩到恰好 1.0，而**方向余弦仍是 1.000000**。若换成逐分量裁剪
（`clip_by_value`），在"分量尺度悬殊"的输入上余弦会明显小于 1——这一课选择整体范数，
就是把"方向不变"当成一条要**保住**的性质。

调度表那一行印出的是"先升后降"：

```text
step  1 | lr 0.020000      ← 热身起点 = base_lr/warmup（**不是 0**）
step  5 | lr 0.100000      ← 热身结束 = base_lr
step 13 | lr 0.044774      ← 退火中段
step 20 | lr 0.000000      ← 末步 = min_lr（合法）
```

第一行是 0.02 而不是 0，是因为"第 1 步 lr = 0"会让第一次更新完全不发生——
它在日志里表现为"第 1 步的 loss 与初始 loss 一模一样"，看起来像"梯度算错了"。
最后一行是 0，则触发了第十章那个**真实撞到的坑**：训练回路对调度必须用**非负**校验，
否则常见的 `warmup_cosine` 会在最后一步报错，而前面每一步都对。

## 结语：三条工程线索

1. **参数分组还没做**：本课所有参数共享一个学习率与一个衰减系数。真实微调里
   "LoRA 层与主干层用不同 lr"是常态——这是一个**工程问题**（哪一组用哪个值），
   不是数学问题，`TrainingOptimizer` 的接口（`learning_rate` 可写）已经为它留了口子。
2. **压平/还原的契约继续沿用**：day074 的 `flatten_matrices` / `unflatten_matrices`
   把矩阵参数压成一串数，本课的逐分量更新因此不需要知道"它优化的是不是矩阵"。
   这正是 day093（CNN）要用到的地方：**卷积核也是参数**。
3. **对比要变成统计**：本课只给单条轨迹。下一步是把 `compare.py` 的外层包一层
   "多组随机初始化 → 分位数"，让它从"这一次的读数"变成"这一类问题的分布"——
   这衔接 day095（训练技巧与正则化）。

明天（day093）我们将进入 **卷积神经网络 CNN**：第一次遇到"参数不是一串数，
而是若干卷积核"，以及"同一组权重在输入的不同位置被重复使用"这件事。
