# day059 课后习题

共 10 题，覆盖今天所有学习目标：阶段依赖表与主链、绝对判定与相对判定的分工、
三类门禁结果、退步判定的方向、确定性 run_id 与"不可覆盖历史"、`blocked` 与
`failed` 的区分、卡片与注册表的一致性、模型卡的"不能做什么"、workflow 由渲染器
生成的理由。建议完成时间：50~60 分钟。

## 第一部分：选择题

### 第 1 题（阶段依赖表的校验）

`validate_stage_order()` 逐条检查"每个 `requires` 都能在它之前的 `produces`
里找到"。下列哪一项**是它最值钱的那类发现**？

- A. 阶段名写错了一个字母
- B. 顺序写错（例如把 `publish` 挪到 `gate` 之前）
- C. **依赖漏写**：给 `package` 加了对 `metrics` 的依赖却忘了写进 `requires`
- D. 阶段数量不是六个

### 第 2 题（主链的取法）

`critical_path()` 在多个上游里取**序号最大**的那一个。若改成"取第一个上游"，
主链会变成什么？为什么这是错的？

- A. `ingest → publish`；漏掉了训练
- B. `ingest → train → publish`；漏掉了评估、门禁与打包
- C. 结果不变，因为依赖是唯一的
- D. 会死循环，因为 `publish` 有三个上游

### 第 3 题（两道判定的分工）

`registry.evaluate_candidate`（day058）与 `mlops.evaluate_gates`（今天）都在
判"行不行"。当**缺少评估指标**时，两者的结论分别是：

- A. 都判"不通过"
- B. 都判"无法判定"
- C. 相对判定说"无法判定"（gain 为 None），绝对判定判"不通过"
- D. 相对判定判"不通过"，绝对判定说"无法判定"

### 第 4 题（退步判定的方向）

`delta = 候选 − 基线`，`max_regression = 0.0`。下列哪一条判定式是**正确**的？

- A. `passed = delta <= max_regression`
- B. `passed = delta >= -max_regression`
- C. `passed = abs(delta) <= max_regression`
- D. `passed = delta == 0`

### 第 5 题（`blocked` 与 `failed`）

门禁不通过时，流水线把 `publish` 阶段标为 `blocked`、`outcome.failed` 为
`False`、追踪器里的 run 状态为 `finished`。这样做的核心理由是：

- A. `failed` 只能用于编程错误（异常），门禁不通过属于业务判定
- B. CI 的红灯会掩盖真正需要看的那份门禁报告，而那份报告就在同一个构建产物里
- C. `blocked` 更容易在 YAML 里表达
- D. 为了让 `pytest` 的覆盖率更容易达标

## 第二部分：判断题

### 第 6 题

`ExperimentTracker` 的 `run_id` 是确定性的（`sha256(name + params)[:12]`）。
因此"两次实验的 run_id 相同"**等价于**"两次实验的参数完全相同"；而
`log_metrics` 对同一个 `(指标名, step)` 重复记录会**报错**，因为覆盖会让
loss 曲线变成"最后一次写入的曲线"。（对 / 错）

### 第 7 题

`compare_runs(left, right, metric="eval_pass_rate")` 在左臂没有该指标时，
返回 `relation="worse"`——因为"没测过"等价于"更差"。（对 / 错）

### 第 8 题

模型卡里的指标表**包含**六项门禁的结论标记（`gate_pass_rate=1.0` 这样），
因为它们是本次运行最可靠的观测值，应该和 `eval_pass_rate` 并列展示。

   只留一份的后果是什么？

## 第四部分：编程题

### 第 10 题（用"会变红的机制"钉住三件事）

在 day059 快照的基础上写一个脚本或测试文件（离线、确定性，不联网、不写盘），
完成三件事：

1. **验证阶段依赖表与主链**
   - 断言 `validate_stage_order()` 对缺省表不抛异常；
   - 构造一张"把 `publish` 挪到 `train` 之前"的表，断言它抛 `MLOpsError`
     且错误信息里含"尚未产出"；
   - 断言 `critical_path()` 等于六阶段的完整顺序，**并额外断言它不等于
     `["ingest", "train", "publish"]`**（把错误答案也钉住）；
2. **验证门禁的两个方向与三类结果**
   - 用一份全项达标的指标，断言 `report.passed is True` 且
     `report.skipped_checks` 里恰好只有 `cost`；
   - 把 `eval_pass_rate_delta` 改成 `+0.05`，断言 `regression` 这一项
     **通过**（方向回归）；再改成 `-0.01`，断言它**不通过**且是唯一的
     `blocking_failures`；
   - 用 `ReleaseGates(require_artifacts=False)` 跑一次，断言
     `artifact_completeness` 落在 `warnings` 而不是 `passed`；
3. **验证 `blocked` 与 `failed` 的区分**
   - 用注入的确定性回调跑一次 `FinetunePipeline`，让合格率只有 0.30；
   - 断言 `publish` 阶段状态是 `blocked`、`outcome.failed is False`、
     `outcome.run.status == "finished"`、`outcome.published is False`；
   - 再断言 `gate` 阶段的 `produced` 里带着完整报告，且 `package` 阶段
     仍然是 `ok`（**门禁不通过也要打包**）。

要求给出完整可运行的代码，并回答：**为什么"主链不等于错误答案"这条断言
值得单独写？**它保护的是哪一类未来的改动？
