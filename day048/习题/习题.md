## 第二部分：判断题

### 第 6 题

`dedupe_key` 只用 `prompt`（不含 `output`）作为去重依据；理由之一是"同一个问题配两个不同答案"在监督微调里不是冗余而是**冲突**，去重把它压成一条，等于把矛盾暴露给数据评审。（对 / 错）

### 第 7 题

`split_dataset` 用 `random.Random(seed)` 打乱并保证 `n >= 2` 时两侧都非空；这样同一份数据配同一个 seed 永远得到同一个切分，否则"这次评估涨了 2 个点"可能只是切分换了。（对 / 错）

### 第 8 题

`compute_stats` 在传入空列表时应抛异常，因为"清洗后一条样本都没有"说明流水线出了故障，必须让调用方立刻感知。（对 / 错）

## 第五部分：编程题

### 第 12 题（给数据流水线补一条规则 + 一个断言）

**背景**：`DatasetCleaner` 的规则表可整体注入（`rules=`），这样给某个数据集定制规则时不必去改 `default_rules`。

**要求**（基于 day048 快照，离线可跑）：

1. 用 `QualityRule` 自定义一条名为 `too_many_newlines` 的规则：输出的换行数超过某个上限（自定，例如 8）即判为"排版异常"（多半是粘贴的长文），返回 `False`。
2. 用 `DatasetCleaner(rules=[...])` 构造一个清洗器，规则表 = **自定义规则 + `default_rules(...)` 的结果**（顺序：自定义规则在前）。
3. 构造 3 条样本：一条正常、一条换行数超限（但仍满足 `min_output_chars`）、一条输出过短。跑 `run()`，断言：
   - 保留 1 条；
   - `report.drop_reasons` 同时含 `too_many_newlines == 1` 与 `output_too_short == 1`；
   - `report.keep_rate` 约等于 1/3。
4. 再写一个断言验证**顺序即优先级**：构造一个**同时违反两条规则**的样本（例如换行数超限 **且** 输出含 `TODO` 占位符），断言它被归到**排在前面的那条规则**；然后把自定义规则挪到 `default_rules` 之后，断言同一样本改归到 `placeholder_output`。提示：`next((rule for rule in self.rules if not rule.check(...)), None)` 取的是第一条不通过的规则；注意 `output_too_short`（要求长度 < 8）与"换行超限"（至少 9 行）不可能同时命中，竞争场景要另选一对规则。
5. 打印每一步的关键中间值，最后打印"全部断言通过"。

**提示**：`FilterReport` 的字段是 `total` / `kept` / `rejected` / `duplicates` / `drop_reasons` / `decisions`；`FilterDecision` 有 `example` / `rule` / `reason`；`clean_text` 会保留换行但把连续多个换行折叠成**一个**，所以构造"换行超限"的样本时要用**内容不同的多行文本**（例如 10 行各不相同的句子），而不是连续空行。
