# day020 课后习题

共 10 题，覆盖今天所有学习目标：MCP Client 的连接与握手、常驻事件循环架构、能力发现、适配器模式与异常回退。建议完成时间：40~50 分钟。

---

## 第一部分：选择题

### 第 1 题（MCP 的价值）

MCP 把"Agent 接入外部工具"的集成复杂度从 N×M 降到 N+M，其核心机制是：

- A. 把所有工具都改写成本地 Python 类，消除网络调用
- B. 标准化"工具供给"协议：Server 实现一次协议即可被任何 Client 消费
- C. 由 LLM 直接阅读外部服务的源代码并生成调用代码
- D. 用统一的消息队列替代所有点对点连接

### 第 2 题（常驻连接）

关于"每次调用工具都新建连接"（随用随连），以下说法**错误**的是：

- A. 每次都要支付子进程启动与 initialize 握手的成本
- B. Server 侧的连接级缓存（如有）会在每次调用间失效
- C. 实现更简单，因为不需要管理连接生命周期
- D. 它依然是生产环境的推荐做法，因为更"无状态"

### 第 3 题（跨事件循环）

在循环 A 中用 `create_connected_server_and_client_session` 建立了会话，循环 A 关闭后，在循环 B 中对该会话调用 `list_tools()`，会发生：

- A. 正常返回，会话与事件循环无关
- B. 抛出 `anyio.ClosedResourceError` 一类错误，因为流绑定的循环已关闭
- C. 自动迁移到循环 B 继续工作
- D. 静默返回空工具列表

## 第二部分：判断题

### 第 4 题

`McpClient` 公开方法（`list_tools`、`call_tool` 等）定义成 `async def`，但同步的 ReAct 循环可以通过 `asyncio.run(...)` 逐次调用它们，因为真正的 I/O 始终发生在客户端的常驻事件循环上。（对 / 错）

### 第 5 题

MCP Server 的工具内部抛出异常时，协议层会让连接断开，Client 需要重新建连才能继续调用其他工具。（对 / 错）

### 第 6 题

`McpToolAdapter` 在向 LLM 展示工具描述时，会对 Server 返回的 description 做润色改写，以匹配本地工具的行文风格。（对 / 错）

## 第三部分：问答题

### 第 7 题（架构权衡）

`McpClient` 内部用 `run_coroutine_threadsafe` + `asyncio.wrap_future` 做跨线程桥接。请说明：

1. 这两个调用各自解决什么问题？
2. 为什么不能让公开方法直接 `await self._session.list_tools()`（即不桥接，在调用方循环上直接操作会话）？

### 第 8 题（异常回退）

今天的异常处理分两层：`McpClient.call_tool` 在 `isError=True` 时抛 `McpToolCallError`，`McpToolAdapter.execute` 则捕获一切异常并返回错误说明字符串。请回答：

1. 为什么 Client 层不直接返回错误字符串？
2. 为什么 Adapter 层用宽 `except Exception` 是合理的，尽管它通常被 linter 警告？
3. 错误字符串最终如何被 ReAct 循环"消化"？

## 第四部分：编程题

### 第 9 题（能力发现 + 动态注册）

基于今天的代码，写一个**同步函数** `build_registry_with_mcp(command: str, args: list[str]) -> ToolRegistry`，要求：

1. 用 `StdioServerParameters(command=command, args=args)` 建立 MCP 连接；
2. 发现全部远程工具，包装成适配器，与 `CalculatorTool` 一起注册进同一份 `ToolRegistry`；
3. 函数返回前**不能断开连接**（注册表里的适配器还要靠它调用）；因此同时返回 client，函数签名改为 `-> tuple[ToolRegistry, McpClient]`；
4. 用 `smart_research_agent.mcp_server.demo_server` 模块写一个测试验证：注册表至少包含 `calculator` 和 `search_docs`，且 `registry.get("search_docs").execute(query="测试")` 返回真实远程结果。

提示：`McpClient.run(coro)` 是同步桥接；别忘了测试结束时 `client.shutdown()`。

### 第 10 题（回退策略观察实验）

写一个测试，验证"远程工具失败不会打断 ReAct 循环"的完整行为链：

1. 用 `build_demo_server()` 起内存 Server，建好 client（可参考 `tests/test_mcp_client.py` 的 fixture 写法）；
2. 只把 `unstable_tool` 注册进 ToolRegistry；
3. MockLLM 预设三步输出：第一步调用 `unstable_tool`；第二步读到错误后再次调用它；第三步输出 `Final Answer`；
4. 断言：循环正常结束拿到 Final Answer；三次 LLM 调用的消息里能观察到**两次**包含"调用失败"的 Observation；
5. 思考（写在注释里）：这个实验暴露了纯字符串回退的什么风险？生产上应该加什么机制？
