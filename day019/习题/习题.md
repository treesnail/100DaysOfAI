# day019 课后习题

共 10 题，覆盖今天所有学习目标：FastMCP 框架的价值、Server 生命周期与能力协商、三类能力的装配、错误处理设计、stdio 与 SSE 传输差异。建议完成时间：40~50 分钟。

---

## 第一部分：选择题

### 第 1 题（能力协商）

MCP 的 initialize 握手中，Server 响应里**不包含**以下哪一项？

- A. 服务端支持的协议版本
- B. 服务端能力声明（capabilities：tools / resources / prompts 等）
- C. 知识库文档的完整内容
- D. instructions（给模型阅读的服务端使用说明）

### 第 2 题（资源模板）

我们的 Server 注册了 `@app.resource("research://knowledge/{doc_id}")`。客户端调用 `resources/list` 时会发生什么？

- A. 返回 `research://knowledge/{doc_id}` 这个 URI
- B. 返回知识库目录下所有文档的完整 URI 列表
- C. 不返回该条目——带参数的资源模板出现在 `resources/templates/list` 中
- D. 返回错误，因为 URI 中含有未替换的参数

### 第 3 题（错误处理）

客户端调用 `calculate`，传入表达式 `1 / 0`。以下哪种结果**符合**我们 Server 的设计？

- A. Server 进程抛出 ZeroDivisionError 并退出，客户端连接断开
- B. 返回 `isError=false` 的正常结果，content 为字符串 `"计算失败: ..."`
- C. 返回 `isError=true` 的结构化错误结果，会话保持可用
- D. 框架自动重试该工具调用三次后再返回错误

## 第二部分：判断题

### 第 4 题

stdio 传输模式下，MCP Server 可以随意向 stdout 打印日志，因为日志和 JSON-RPC 消息可以通过格式区分。（对 / 错）

### 第 5 题

MCP 没有定义专门的"关闭会话"消息：stdio 下 stdin 关闭、SSE 下 HTTP 连接断开，传输层的结束即会话的结束。（对 / 错）

### 第 6 题

`create_connected_server_and_client_session` 在测试中会启动一个子进程并通过 stdio 管道与 Server 通信，因此它能验证真实传输层的行为。（对 / 错）

## 第三部分：问答题

### 第 7 题（工具设计）

`calculate` 工具没有重新实现算术逻辑，而是包装了 day004 的 `CalculatorTool`。请回答：

1. 这种"包装而非重写"的做法在维护性上有什么具体好处？
2. `CalculatorTool.execute` 用返回字符串 `"计算失败: ..."` 表达业务失败，为什么 MCP 适配层要把它转换成 `raise ToolError(...)`，而不是直接把这段字符串返回给客户端？

### 第 8 题（传输选型）

团队提出两个部署方案，请分别给出选型建议（stdio 还是 SSE）并说明理由：

1. 智研助手作为本地桌面 Agent 的内置能力，随 Agent 启动、随 Agent 退出，只服务本机这一个 Agent。
2. 公司希望把调研知识库做成全团队共享的服务，十几个人的 Agent 都要能读取同一份实时更新的知识库。

## 第四部分：编程题

### 第 9 题（新增一个 Prompt 能力并测试）

在 `full_server.py` 的 `create_server()` 中新增一个 Prompt：`compare_frameworks(frameworks: str)`，其中 `frameworks` 是逗号分隔的框架名（如 `"LangChain,LlamaIndex,Haystack"`）。要求：

1. 返回一段提示词文本，引导模型从"易用性、生态、文档质量、社区活跃度"四个维度对这些框架做对比分析，并要求结论用表格呈现。
2. 在 `capability_descriptors()` 的 prompts 列表中补充对应的 `PromptDescriptor`。
3. 在 `tests/test_full_server.py` 中补两个测试：`prompts/list` 现在应同时列出 `research_report` 与 `compare_frameworks`；`prompts/get` 传入 `frameworks="A,B"` 后返回的消息文本中应包含这两个框架名与四个维度。

提示：参考 `research_report` 的写法；注意 `prompts/list` 返回的 prompt 有 `arguments` 字段。

### 第 10 题（写一个真实的 stdio 客户端冒烟脚本）

新建 `scripts/mcp_stdio_smoke.py`（放在项目 `scripts/` 目录下），要求：

1. 使用 `mcp.ClientSession` 与 `mcp.client.stdio.stdio_client`，以子进程方式拉起 `python -m smart_research_agent.mcp_server.full_server --transport stdio`。
2. 完成 `initialize()` 握手，打印 `serverInfo.name` 与 `instructions` 的前 30 个字符。
3. 调用 `tools/list` 并打印所有工具名。
4. 调用 `calculate` 计算 `6 * 7`，断言返回文本为 `"42"`；再调用 `calculate` 计算 `1 / 0`，断言 `isError` 为 `True`。
5. 脚本以 `asyncio.run(main())` 收尾，退出码为 0 表示冒烟通过。

提示：拉起子进程用 `StdioServerParameters(command=sys.executable, args=[...])`；脚本需在项目根目录下运行（保证子进程能 import 到项目包）。思考一下：这个冒烟脚本与 `tests/test_full_server.py` 的内存会话测试各验证了什么、为什么不能互相替代？
