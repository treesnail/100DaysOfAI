## 第一部分：选择题

### 第 1 题 → **C**

依赖漏写是最值钱的那一类，因为它的**表现最隐蔽**：

> 给 `package` 加一个对 `metrics` 的依赖却忘了写进 `requires`，
> 平时不会报错——只会在某次运行时出现 `KeyError`，
> 而那时的堆栈指向阶段内部的某一行，不是"依赖表漏了一项"。

B（顺序写错）也很重要，但它一旦发生就**立刻**暴露（`publish` 需要的
`gate_report` 没人产出，校验直接失败），因此代价小得多。A、D 属于表层错误，
看一眼表就能发现。

一次构造期校验把这两类问题都变成**启动即失败**，而不是运行时的一个 `KeyError`。

### 第 2 题 → **B**

实测的正确答案是：

```text
主链：ingest → train → evaluate → gate → package → publish
```

`publish` 的 `requires` 是 `(adapter_sha256, model_card, gate_report)`，
三者分别由 `train` / `package` / `gate` 产出。若取"第一个上游"，得到的是
`train`（它在列表里的顺序），于是主链变成 `ingest → train → publish`——
**它漏掉了评估、门禁与打包**。

因此代码里取的是**序号最大**的那个上游（"离终点最近的上游"）：

```python
upstream = [produced_by[item] for item in spec.requires if item in produced_by]
current = max(upstream, key=lambda name: order[name]) if upstream else None
```

C 是错的：`publish` 有三个上游，依赖不唯一；D 是错的：这是 DAG 上的
反向单链遍历，不会成环（表本身已被 `validate_stage_order` 校验过）。

### 第 3 题 → **C**

两者面对"缺数据"的结论**相反**，这正是它们必须分开的理由：

| | `evaluate_candidate`（day058） | `evaluate_gates`（今天） |
|---|---|---|
| 问题 | 候选比当前**更好吗**？ | 这次产物**够格发布吗**？ |
| 判据 | 相对（与当前版本比差值） | **绝对**（与固定阈值比） |
| 缺指标时 | `gain = None`（无法判定） | **不通过**（缺证据不能发布） |

理由：相对判定缺一个分数就**没有可比的基准**；绝对判定里
**没有证据本身就是不发布的理由**。

A、B 都错在"把两者当成同一类判定"；D 把两者说反了。

把两者合并的那一天，就会出现"因为没测延迟所以延迟门禁通过"这种事故。

### 第 4 题 → **B**

`delta = 候选 − 基线`，**退步是负值**。因此"最多允许 0.0 的退步"翻译成
数学式是 `delta >= -0.0`。

A 是最危险的错答：`delta <= 0` 会把**所有改进都拦下**（`+0.05` 被判失败），
而"所有候选都被拒绝"看起来很像"门禁很严格"，不会有人立刻怀疑方向写反。
本课实现时确实写反过一次，因此现在有一条专门的回归断言：

```python
def test_positive_delta_passes_the_regression_gate():
    report = evaluate({**BASE_METRICS, "eval_pass_rate_delta": 0.05})
    assert report.check(GATE_REGRESSION).passed is True
    assert report.check(GATE_REGRESSION).threshold == ">= -0.0"
```

C 是错的：它会把"退步 0.05"与"提升 0.05"同等对待，而门禁要拦的只有前者；
D 是错的：它禁止任何变化，包括本课最想看到的提升。

### 第 5 题 → **B**

四处表达必须同时成立，缺一不可：

| 位置 | 值 | 含义 |
|------|-----|------|
| `gate` / `publish` 阶段 | `blocked` | 上游判定不允许继续 |
| `outcome.failed` | `False` | **没有任何东西坏了** |
| run 状态 | `finished` | 这次实验正常跑完了 |

选 B 的理由是具体的：若报成 `failed`，CI 会标红，而**那份门禁报告就在
同一个构建产物里**——它被一个"失败"的标签挡住了，而"这一版为什么不能发"
恰恰是所有人最想看的东西。

这与 day058 把"回滚没有退路"输出成 `hold` 而不是抛异常是同一条纪律：
**一个悄悄违反自己约束的护栏，比没有护栏更糟。**

A 是一种常见的误解：`failed` 并不只用于编程错误——回调抛异常、契约字段
缺失都会走 `failed` 分支；而门禁不通过属于"预期内的结论"。
C、D 与设计理由无关。

## 第二部分：判断题

### 第 6 题 → **对**

两个性质都成立，而且各有具体理由：

**确定性 `run_id`**（`sha256(name + canonical(params))[:12]`）:

```text
  第一次：97fa8e5a0da1 lora-ablation [running] 3 参数 / 0 指标 | 0 产物 | 0.00s
  reuse=True  → 同一个 run_id：True
  reuse=False → 新 id（同参数第二次运行）：97fa8e5a0da1-2
  改一个参数 → 全新 id：d6be7bb3c8b0
```

于是"id 相同 ⟺ 参数完全相同"这条性质成立——**这正是"这个数字是哪次跑出来的"
能被直接回答的原因**。注意 `run_id` 只覆盖 `params`、**不覆盖 metrics**：
指标是这次运行的结果，算进去会让"同一次实验的两条记录"分裂成两个 id。

**同 step 不可覆盖**：

```text
  step 冲突被拒：指标 train_loss 在 step=42 已记录过（旧值 0.3187）：
  覆盖会让曲线变成'最后一次写入的曲线'，要记录第二次请换一个 step
```

这不是苛刻：覆盖写正是"loss 曲线"最容易失效的方式——**它不会报错，
只会让历史安静地变成最后一次写入的样子**。两个细节：无 step 的标量指标
落在 `-1` 槽位而**不是 0**（step 0 是一个真实的训练步）。

### 第 7 题 → **错**

缺指标时返回的是 `comparable=False` 且 `relation=None`，**不是** `worse`。

实测：

```text
  compare(mode=max): left=0.5493 right=0.58 delta=0.0307 → better
  compare(mode=min): left=0.5493 right=0.58 delta=0.0307 → worse
  缺指标时：comparable=False relation=None
```

把"没测过"报成 `worse` 是这类比较函数最危险的默认行为：
它会让人以为"左臂更差"，而去优化一个**根本没有测量**的东西。
这与 day058 的 `pass_rate` 返回 `None`、`Run.metric` 返回 `None` 是同一条纪律：
**缺失与 0 是两件事。**

顺带看前两行：同一个 delta 在两种 `mode` 下得到**相反**的结论——
这正是"方向参数真的被用上了"的证据。因此 `mode` 没有全局缺省：
同一个数字（例如 loss）在监督微调里越小越好、在奖励模型里越大越好。

### 第 8 题 → **错**

`gate_` 前缀的指标被**刻意过滤掉**：

```python
if not name.startswith(GATE_METRIC_PREFIX)
```

它们是门禁自己的结论（`gate_pass_rate=1.0` 这样），而卡片有专门的
"发布门禁"一节。保留它们会给读者两个错误印象：

1. **"门禁通过"看起来像是一个独立于门禁的观测值**——而它其实是门禁
   对同一批指标给出的判定；把它列进"指标"，读者会以为有一个叫
   `gate_pass_rate` 的测量量；
2. **同一份事实在一份文档里出现两次且措辞不同，会让评审开始怀疑
   哪一处才是对的**——不信任的成本远大于省下的那两行。

这与 day027 的"分数用于聚合、问题清单用于诊断"是同一种思路：
一份文档里每一个数字都要有**唯一的出处**。

## 第三部分：简答题

### 第 9 题

#### (1) 通用免责声明会失去什么

它会失去**否掉一个结论的能力**。

对比两条限制：

```text
不带数字：本模型可能在某些情况下表现不佳
带数字：  领域评估集只有 18 条用例，合格率的最小可分辨变化是 1/18 ≈ 0.0556：
          小于它的分数差异不可作为提升证据
```

第二条可以直接用在一次评审里：

```text
"这两次训练的合格率是 0.7222 与 0.7500，差 0.0278。"
"小于 0.0556，**这个差异不可作为提升证据**。"
```

而第一条什么也否不了——它既不能支持"该上线"，也不能支持"不该上线"，
于是讨论只能回到"我觉得"。**一条无法被用来否掉任何结论的限制，
等于一条免责声明**。

这就是为什么本课有一条专门的用例断言四条限制里分别出现
`1/18`、`557`、`单一来源`、`事实正确性`：

```python
def test_limitations_each_carry_a_checkable_number_or_source():
    joined = " ".join(LIMITATIONS)
    assert "1/18" in joined and "557" in joined
```

四条限制各自的数字来源都写在 `packaging.py` 的模块 docstring 里
（day053 的评估套件、day050 的参考模型、day048/057 的数据画像），
因此"这条限制说的是哪一次实测"永远可查。

#### (2) 为什么过滤 `gate_` 指标

见第 8 题。补充一点实现层面的理由：过滤发生在
`build_model_card` 而不是在流水线里"少记几个指标"——后者会让追踪器
也丢掉门禁结论，而**追踪器里的门禁标记是有用的**（它让"哪一次实验
通过了门禁"可以直接查）。因此过滤只发生在**渲染那一层**：

```python
metrics = {
    name: value
    for name, value in run.flat_metrics().items()
    if not name.startswith(GATE_METRIC_PREFIX)
} if run is not None else {}
```

**一份数据，两种展示，各自服务不同读者**——而"该给谁看什么"这个决定
应该写在展示层，不是数据层。

#### (3) 为什么两份产物

| | `MODEL_CARD.md` | `release_manifest.json` |
|---|---|---|
| 读者 | 人 | 机器 |
| 目标 | 五分钟内判断"能不能用" | 另一个脚本能直接取字段 |
| 形状 | 四段叙述 + 表格 | 平铺字典 |

只留一份的后果是**总有一方要去解析对方的格式**：让脚本去正则解析
markdown 表格是脆弱的（改一次排版就崩），而让人去读一个 200 行的 JSON
也不现实。

因此本课有一条断言保证两份产物里的**版本号 / 适配器哈希 / 数据集指纹 /
指标完全一致**：

```python
def test_manifest_and_card_are_two_renderings_of_the_same_facts():
    assert manifest["version"] == card.version
    assert manifest["adapter_sha256"] == card.adapter_sha256
    assert manifest["metrics"] == card.metrics
```

**重叠不是问题，"重叠且可能不一致"才是问题**——一条断言就把后者排除了。

### 第 10 题

```python
"""day059 习题 10 参考实现：阶段表、门禁方向、blocked 与 failed（离线、确定性）."""

from __future__ import annotations

from smart_research_agent.mlops import (
    ARTIFACT_ADAPTER,
    ARTIFACT_DATASET,
    ARTIFACT_GATE_REPORT,
    STAGE_BLOCKED,
    STAGE_OK,
    ExperimentTracker,
    FinetunePipeline,
    MLOpsError,
    ReleaseGates,
    StageSpec,
    critical_path,
    evaluate_gates,
    validate_stage_order,
)
from smart_research_agent.registry import STAGE_STABLE, ModelRegistry, ModelVersion, VersionTriple

BASE_MODEL = "Qwen3-8B"
DATA_A = "3f1b0c9d7e5a2468"
DATA_B = "aa77c31e90f4b258"
ADAPTER_NEW = "5c6d7e8f9012345678" + "b" * 46
ADAPTER_OLD = "1a2b3c4d5e6f70819293a4b5c6d7e8f90123456789abcdef" + "0" * 8

GOOD = {
    "eval_pass_rate": 0.65,
    "eval_pass_rate_delta": 0.05,
    "adapter_mebibytes": 0.05,
    "dataset_fingerprint": DATA_A,
    "base_model": BASE_MODEL,
}
ARTIFACTS = {"adapter": "a/adapter", "merged": "m/merged"}


def part_one() -> None:
    """阶段依赖表与主链."""
    assert validate_stage_order() is None
    broken = (
        StageSpec(name="ingest", description="", produces=(ARTIFACT_DATASET,)),
        StageSpec(
            name="publish", description="", requires=(ARTIFACT_ADAPTER,), produces=("version",)
        ),
    )
    try:
        validate_stage_order(broken)
    except MLOpsError as exc:
        assert "尚未产出" in str(exc)
        print(f"顺序写错的表被拒：{str(exc)[:44]}…")
    path = critical_path()
    assert path == ["ingest", "train", "evaluate", "gate", "package", "publish"]
    # 把**错误答案**也钉住：取第一个上游会得到这一串
    assert path != ["ingest", "train", "publish"]
    print(f"主链：{' → '.join(path)}（且不等于错误答案）")


def part_two() -> None:
    """门禁的两个方向与三类结果."""
    clean = evaluate_gates(GOOD, policy=ReleaseGates(), artifacts=ARTIFACTS)
    assert clean.passed is True
    assert [item.name for item in clean.skipped_checks] == ["cost"]

    improved = evaluate_gates(
        {**GOOD, "eval_pass_rate_delta": 0.05}, policy=ReleaseGates(), artifacts=ARTIFACTS
    )
    assert improved.check("regression").passed is True
    regressed = evaluate_gates(
        {**GOOD, "eval_pass_rate_delta": -0.01}, policy=ReleaseGates(), artifacts=ARTIFACTS
    )
    assert regressed.check("regression").passed is False
    assert [item.name for item in regressed.blocking_failures] == ["regression"]

    relaxed = evaluate_gates(
        {"eval_pass_rate": 0.6, "adapter_mebibytes": 1.0},
        policy=ReleaseGates(require_artifacts=False),
        artifacts={},
    )
    assert [item.name for item in relaxed.warnings] == ["artifact_completeness"]
    assert relaxed.check("artifact_completeness").passed is False


def part_three() -> None:
    """blocked 与 failed 的区分."""
    registry = ModelRegistry()
    registry.register(
        ModelVersion(
            triple=VersionTriple(
                base_model=BASE_MODEL, adapter_sha256=ADAPTER_OLD, dataset_fingerprint=DATA_A
            ),
            version="1.0.0",
            stage=STAGE_STABLE,
            metrics={"eval_pass_rate": 0.60},
            artifacts={"adapter": "a/base", "merged": "m/base"},
        )
    )

    def train(params: dict) -> dict:
        """确定性训练回调."""
        return {
            "adapter_sha256": ADAPTER_NEW,
            "adapter_mebibytes": 0.05,
            "train_loss": 0.3187,
            "artifacts": {"adapter": "a/new", "merged": "m/new"},
        }

    def evaluate(artifacts: dict) -> dict:
        """确定性评估回调：合格率 0.30，低于门禁 0.5."""
        return {"eval_pass_rate": 0.30, "eval_pass_rate_delta": -0.30}

    pipeline = FinetunePipeline(
        registry, ExperimentTracker(), base_model=BASE_MODEL, train=train, evaluate=evaluate
    )
    outcome = pipeline.run(dataset_fingerprint=DATA_B, params={"lora_r": 8})

    statuses = {stage.name: stage.status for stage in outcome.stages}
    assert statuses["gate"] == STAGE_BLOCKED
    assert statuses["publish"] == STAGE_BLOCKED
    assert statuses["package"] == STAGE_OK          # 门禁不通过也要打包
    assert outcome.failed is False                  # blocked 不算失败
    assert outcome.published is False
    assert outcome.run.status == "finished"         # 这次实验正常跑完了
    assert ARTIFACT_GATE_REPORT in outcome.stage("gate").produced


if __name__ == "__main__":
    part_one()
    part_two()
    part_three()
    print("全部断言通过")
```

#### 为什么"主链不等于错误答案"值得单独写

因为它保护的是**一次"简化"**。

`critical_path` 里那一行 `max(upstream, key=...)` 很容易被后人改写成：

```python
current = upstream[0] if upstream else None     # "取第一个就够了"
```

这个改动**不会让任何既有用例失败**——所有用例都只断言"主链的每个节点
都在 `PIPELINE_STAGES` 里"或"起点是 ingest"。而它的后果是主链悄悄少掉了
评估、门禁与打包三段。

那三段恰好是**这条流水线的价值所在**：`ingest → train → publish`
描述的是"训练完直接发布"，而本课花了十天建立的东西全部在中间三步里。

把错误答案写成断言，等价于**把"这条规则排除了什么"也变成代码**：

```python
assert path != ["ingest", "train", "publish"]
```

这条断言的写法有一个通用形式，值得带走：

> **当一段逻辑的关键在于"从多个候选里挑一个"时，断言里要同时出现
> 挑中的那个与"看起来最自然的错误候选"。** 只断言正确答案的用例，
> 在有人把挑选规则改成"取第一个"之后依然会通过——因为候选集合没变。

同一课里的另一处例子是门禁方向：`test_positive_delta_passes_the_regression_gate`
同时断言 `threshold == ">= -0.0"`，因为方向写反的另一种表现是
**把阈值写成 `<= 0.0`**——只断言 `passed is True` 的话，
"+0.05 通过"在下一次有人改动阈值时仍然可能通过，而"-0.01 拦下"就废了。
