## 第 1 题（选择 · 循环状态机）

ReAct 循环单步的正确状态转换顺序是：

A. LLM 推理 → 感知输入 → 解析 → 执行工具 → 回填观察  
B. 感知输入 → LLM 推理 → 解析 → 执行工具 → 回填观察  
C. 感知输入 → 解析 → LLM 推理 → 执行工具 → 回填观察  
D. 感知输入 → LLM 推理 → 执行工具 → 解析 → 回填观察

## 第 2 题（选择 · 终止条件）

`ReactAgent.run()` 的终止条件组合是：

A. 只有 LLM 输出 Final Answer 时终止，否则无限循环  
B. LLM 输出 Final Answer 正常终止；达到 max_steps 熔断终止并返回说明字符串  
C. 工具执行失败时立即抛出异常终止  
D. 消息列表长度超过阈值时终止

## 第 3 题（判断 · Observation 闭环）

判断对错：`ReactAgent._execute_tool` 在工具执行抛出异常时，会让异常向上传播、中断整个 ReAct 循环，因为工具失败属于系统故障。

## 第 4 题（判断 · 熔断）

判断对错：当循环达到 `max_steps` 仍未得到 Final Answer 时，`run()` 抛出 `MaxStepsExceeded` 异常。

## 第 5 题（问答 · Prompt 工程）

为什么 ReAct 的输出格式契约必须"写死"在 System Prompt 里，而不是依赖 LLM 自己理解"请用工具解决问题"这类自然语言意图？请从 LLM 的概率本质和解析器的工作方式两个角度作答。

## 第 6 题（问答 · 解析容错）

今天的 `SYSTEM_PROMPT` 没有提供 few-shot 输出示例。如果接入真实 LLM 后发现解析失败率偏高，你会如何设计一个实验来评估"在 prompt 中追加 1~2 个 few-shot 示例"是否能降低解析失败率？请说明实验变量、样本与判定指标。

## 第 7 题（问答 · 容错策略）

`parse_react_output` 在解析失败时抛出 `ReActParseError` 而不是返回 `None`，这样设计的好处是什么？如果你要在 `ReactAgent.run()` 中实现"解析失败重试"策略（把错误反馈给 LLM 让它按格式重新输出），请描述实现思路（不需要写代码）。

## 第 8 题（问答 · 双轨记录）

`ReactAgent` 同时维护了 `messages`（局部变量）和 `self.history`（实例属性）两份历史。它们各自服务谁？为什么不合并成一份？如果把 `history` 删掉、需要时从 `messages` 重新解析，会有什么问题？

## 第 9 题（编程 · 新工具接入）

给 Agent 增加一个**时间查询工具** `TimeTool`（新文件 `smart_research_agent/tools/time_tool.py`），要求：

1. 继承 `BaseTool`，`name` 为 `"current_time"`；
2. `description` 要让 LLM 能看懂用途；
3. 无必填参数（`parameters` 用基类默认值即可），`execute` 返回当前时间字符串（格式如 `2024-01-01 12:00:00`，用 `datetime.now().strftime` 实现）；
4. 写一个端到端测试：用 MockLLM 脚本化两步响应（第一步调用 `current_time`，第二步输出 Final Answer），断言 `run()` 正常返回答案，且第二次 LLM 调用的消息中包含 Observation。

提示：无必填参数的工具在 `_execute_tool` 中走的是 `kwargs = {}` 分支，想一想为什么这个分支今天就已经能工作。

## 第 10 题（编程 · 多参数支持）

今天的 `_execute_tool` 只支持单个必填参数（取 `required[0]` 注入）。请扩展它，支持**多参数工具**：

1. 约定：当工具有多个必填参数时，LLM 的 `Action Input` 输出 JSON 对象字符串，如 `{"a": 1, "b": 2}`；
2. 修改 `_execute_tool`：若 `len(required) > 1`，把 `action_input` 用 `json.loads` 解析为 dict 后作为 `**kwargs` 传入；JSON 解析失败时返回错误描述字符串（不中断循环）；
3. 新增一个演示工具 `AddTool`（`name="add"`，必填参数 `a`、`b`，返回两数之和）验证你的实现；
4. 写一个端到端测试：MockLLM 第一步输出 `Action: add` + `Action Input: {"a": 3, "b": 4}`，第二步输出 Final Answer，断言最终答案中包含 `7`。
