## 第一部分：选择题

### 第 1 题（MCP 的价值）

关于 MCP 解决的核心问题，下列说法**正确**的是：

- A. MCP 让 LLM 的推理能力更强，回答更准确
- B. MCP 把"M 个应用 × N 个外部能力"的两两私有对接（M×N 工作量），变成各自只对接一次标准协议（M+N 工作量）
- C. MCP 是一种新的模型微调方法，可以把工具知识注入权重
- D. MCP 的主要价值是加密 LLM 与工具之间的通信

### 第 2 题（三种角色）

关于 Host / Client / Server 三种角色，下列说法**错误**的是：

- A. Host 是用户直接面对的 AI 应用（如我们的 SmartResearch Agent、Claude Desktop）
- B. Client 是 Host 内部的协议连接器，负责发请求、收响应，本身不做任务决策
- C. 一个 Client 实例可以同时连接多个 Server，统一管理所有能力
- D. Server 不挑 Host——同一个 MCP Server 既能被我们的 Agent 用，也能被 Claude Desktop 挂载

### 第 3 题（JSON-RPC 建模）

day016 中 `JsonRpcResponse`（含 result）与 `JsonRpcError`（含 error）被建模成**两个独立的 pydantic 类**，而不是一个类里两个可选字段，主要原因是：

- A. 两个类序列化后体积更小
- B. 成功与失败互斥；拆成两个类让"result 和 error 同时为 None"这类非法状态在类型层面无法表达
- C. pydantic 不支持可选字段
- D. JSON-RPC 2.0 规范强制要求使用两个 Python 类

### 第 4 题（三原语辨析）

团队要在 MCP Server 上暴露"网络搜索"能力——LLM 在调研任务中自行决定何时搜索、搜什么关键词。这个能力最适合做成：

- A. Resource，因为它返回数据
- B. Prompt，因为它和调研任务相关
- C. Tool，因为它有外部副作用、且由模型决定何时调用
- D. 三者任选其一，只是名字不同

### 第 5 题（FastMCP 与 stdio）

用 `app.run(transport="stdio")` 启动的 FastMCP Server，下列做法**会直接导致协议损坏**的是：

- A. 用 `logging` 把日志写入文件
- B. 在工具函数里 `print("debug 信息")`，输出到 stdout
- C. 用 `logging` 输出到 stderr
- D. 给工具函数写很长的 docstring

### 第 6 题（Client 集成）

day020 把 MCP 工具接入 Agent 的做法是：写一个适配器类，把 MCP Tool 包装成 `BaseTool` 子类后注册进 `ToolRegistry`。这套设计最大的收益是：

- A. 适配器让 MCP 工具的执行速度变快
- B. Agent 的 ReAct 循环、SYSTEM_PROMPT 拼装等 M1 代码一行不改，MCP 工具与本地工具对上层完全同构
- C. 适配器可以绕过 MCP 的握手流程
- D. 适配器能把多个 MCP Server 合并成一个

## 第四部分：编程题

### 第 14 题

参照 day016 快照（`../day016/源码/smart-research-agent/smart_research_agent/mcp_server/protocol.py`）的共享规格，用 pydantic 实现 JSON-RPC 2.0 的三个消息模型：

- `JsonRpcRequest(id, method, params, jsonrpc="2.0")`
- `JsonRpcResponse(id, result, jsonrpc="2.0")`
- `JsonRpcError(id, error, jsonrpc="2.0")`，其中 `error` 内含 `code: int` 与 `message: str`

要求：

1. `jsonrpc` 字段用 `Literal["2.0"]` 钉死并带默认值；
2. 写一个 pytest 测试文件（放任意临时目录即可，不进项目），验证：
   - 正常构造三种消息并 `model_dump()` 往返；
   - 传入 `jsonrpc="1.0"` 时抛出 `ValidationError`；
   - `JsonRpcError` 缺 `code` 字段时抛出 `ValidationError`。

提示：全部离线可跑，venv 里已有 pydantic 2.13 与 pytest。

### 第 15 题

参照 day019 快照的 FastMCP 用法，完成以下任务（同样放任意临时目录验证，不进项目）：

1. 用 FastMCP 建一个名为 `"review-mcp"` 的 Server，注册：
   - 一个 Tool：`add(a: int, b: int) -> int`，返回两数之和；
   - 一个 Resource：`review://notes/{topic}`，返回字符串 `f"{topic} 的复习笔记"`；
   - 一个 Prompt：`summarize(topic: str)`，返回 `f"请用三句话总结 {topic} 的核心概念。"`；
2. 用 `create_connected_server_and_client_session` 写一个**异步** pytest 测试（pytest-asyncio，测试函数加 `@pytest.mark.asyncio` 或配置 `asyncio_mode = "auto"`），验证：
   - `list_tools()` 能找到 `add`，`call_tool("add", {"a": 2, "b": 3})` 的结果包含 `5`；
   - `read_resource("review://notes/MCP")` 返回的内容包含 `"MCP"`；
   - `get_prompt("summarize", {"topic": "MCP"})` 返回的消息内容包含 `"总结"`。

提示：mcp 1.29 的内存测试 helper 是异步 API；tool 调用的返回值中，`result.content` 是内容块列表，文本块有 `.text` 属性。全部离线可跑，严禁访问网络。
