## 第一部分：选择题

### 第 1 题（规划的必要性）

以下哪一项**不是** ReAct 纯循环在复杂任务上的典型失控模式？

- A. 迷失方向：走到中途忘记最初的全局目标
- B. 步骤冗余：重复执行已经做过的搜索或计算
- C. 提前收场：任务只完成一部分就输出 Final Answer
- D. 工具不可用：注册表中没有模型想调用的工具

### 第 2 题（Plan-and-Execute 的调用结构）

在 Planner + ReactAgent 的协作中，假设 Planner 把目标拆成了 5 个子任务，每个子任务的 ReAct 循环平均调用 LLM 3 次。整个流程大约调用 LLM 多少次？

- A. 3 次
- B. 5 次
- C. 8 次
- D. 约 16 次（1 次规划 + 5 × 3 次执行）

### 第 3 题（解析容错）

`parse_plan` 使用 `find("[")` 与 `rfind("]")` 截取 JSON 片段。对于输入 `"] 错误顺序 ["`，以下描述正确的是：

- A. 能正常解析，返回空列表
- B. 截取后 `json.loads` 抛 `JSONDecodeError`
- C. 被 `end < start` 检查拦截，抛 `PlanParseError("输出中未找到 JSON 数组")`
- D. 抛出 `IndexError`

## 第四部分：编程题

### 第 10 题（实现计划执行器 PlanExecutor）

教程第 5.4 节给出了执行器的最简形态。请动手实现一个完整的 `PlanExecutor`，要求：

**功能要求**：

1. 构造函数接收一个 `Planner` 和一个**工厂函数** `agent_factory`（调用它返回一个新的 `ReactAgent` 实例，保证每个子任务使用独立的 Agent）。
2. 提供 `execute(goal: str) -> dict` 方法：先用 `planner.plan(goal)` 拆解目标，再把每个子任务交给一个新建的 `ReactAgent` 执行，收集所有结果。
3. 返回字典格式为 `{"goal": ..., "steps": [...], "results": [...]}`，其中 `results[i]` 是 `steps[i]` 的执行结果。
4. 某个子任务的 `agent.run()` 抛异常时，**不中断整个计划**，而是把该位置的结果记为 `"子任务执行失败: <异常信息>"`，继续执行后续子任务。

**测试要求**：用 `MockLLM` 写一个端到端测试，构造"规划 1 次 + 2 个子任务各 1 次直接给 Final Answer"的脚本，断言返回字典的 `goal`、`steps`、`results` 三个字段都正确。

**提示**：

- MockLLM 的 responses 是按顺序消费的列表，规划消耗第 1 个，两个子任务各消耗 1 个，共需准备 3 个响应；两个子任务的 Agent 共享同一个 MockLLM 即可。
- `ReactAgent` 收到 `Final Answer` 格式的输出会立即返回，不需要任何工具调用。
- 思考：为什么用"工厂函数"而不是直接传一个 `ReactAgent` 实例？（提示：回顾教程第 5.4 节关于 `history` 累积的讨论）
