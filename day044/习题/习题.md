## 第一部分：选择题

### 第 1 题（校验型 PII）

银行卡号为什么不能像手机号那样"正则匹配就直接脱敏"？

- A. 银行卡号的正则比手机号复杂，写不出来
- B. 银行卡号是 16~19 位纯数字，与订单号/时间戳同形，纯正则脱敏会大面积误伤，必须加 Luhn 校验确认
- C. 银行卡号不属于 PII，不需要脱敏
- D. 银行卡号只能用外部 SDK 脱敏，标准库做不到

### 第 2 题（IPv4 的误报防护）

项目里 IPv4 的正则是 `(?:25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)` 的四段组合。它的作用是：

- A. 让正则匹配更快
- B. 把"每段 0~255"的约束编码进正则本身，从而让 `999.999.999.999` 这类伪 IP 失配
- C. 支持 IPv6 地址的脱敏
- D. 允许匹配 `999.999.999.999` 这样的地址

### 第 3 题（输出侧审核的落点）

day044 把输出审核放在 `/chat`、`/agent/run` 的**路由函数**里，而不是放进 `AccessLogMiddleware` 中间件，原因是：

- A. 中间件的性能开销太大
- B. 审核结果（`moderation` 报告）要随响应体返回给客户端，中间件拿不到响应体、也无法往响应体加字段
- C. 中间件只能处理 GET 请求
- D. FastAPI 不支持在中间件里调用同步代码

### 第 4 题（审计的分工）

`AccessLogStore`（day044）与 `AuditLogger`（day031）的分工是：

- A. 两者功能重复，day044 是 day031 的重写
- B. `AccessLogStore` 记 HTTP 层请求（方法/路径/状态码/耗时/IP），`AuditLogger` 记 Agent 内部工具调用，一外一内
- C. `AccessLogStore` 记工具调用，`AuditLogger` 记 HTTP 请求
- D. `AccessLogStore` 是 `AuditLogger` 的父类
