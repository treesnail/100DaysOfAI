## 今日目标

1. **先把"一条训练管线"拆成七个阶段**——`dataset → sampler → dataloader → device
   → train → checkpoint → inference`。今天所有的读数都能指回这七段里的某一段，
   而"某个数字不对"的第一个问题永远是"它属于哪一段"。
2. **数据集的基本性质是"不可变 + 可指纹"**——`TabularDataset` 是 `frozen` 的，
   `share` 与切分都返回新对象；`dataset_fingerprint` 用 sha256 前 16 位回答
   **"这两个分数能比吗"**。本课实测：全集指纹 `22bc0a3f878c7012`，
   训练集 `f8f70f5ccf76bc9c`，评估集 `0f2166367b3b3e58`——三个分数彼此不可比。
3. **DataLoader 的读数只有三个，但每一个都容易被写错**：批数、丢弃、尾批。
   `drop_last=True` 时批数 = `n // b`；`drop_last=False` 时 = `ceil(n / b)`。
   本课 24 条样本、批 7 的实测：不丢尾批 → 4 批 / 丢弃 0；丢尾批 → 3 批 / 丢弃 3。
4. **多进程加载的第一性原理是"分片"而不是"开进程"**：`worker k` 拿的是
   `{ i : i % workers == k }`。它必须满足**互不相交 + 并集为全集**——这是一条
   下界判据（覆盖 = 1.0），而不是"看起来对"。
5. **设备与显存是纯算术**：参数 + 激活 + `optimizer_multiplier × 参数`。
   本课实测（lstm(H=4,D=1) → bn(4) → dropout → dense(4→2)，114 个参数）：
   `456 + 128 + 1368 = 1952` 字节。预算不足**不抛异常**，由 `fits` 暴露——
   把"放不下"做成布尔量，比做成崩溃更容易被上层处理。
6. **检查点是五件套 + 一份清单**：`meta.json` / `params.json` / `optimizer.json` /
   `metrics.json` / `history.jsonl`，外加只覆盖权重与优化器状态的哈希。
   缺文件必须**点名是哪一件**，而不是抛一个"文件不存在"。
7. **本课最值钱的一条：恢复训练必须逐位相等**——"第 3 轮落盘后恢复训到第 6 轮"
   与"一口气训到第 6 轮"，114 个参数的最大绝对差是 `0.0`。它不是"差不多"，
   而是**同样的 (数据序, 学习率, 优化器状态) 必须给出同样的结果**。

昨天留下的三件事今天逐一兑现：**day095 的四个旋钮**（今天被搬进数据管线，
成为 `PipelineConfig` 的字段而不是脚本里的 if/else）、
**"两把尺子"**（相等 / 上界 / 下界三类判据被沿用到今天的七条性质上）、
**"四张图"**（今天的训练报告同样是"一行一轮 + 汇总一行"的可读读数）。

## 第一章：七个阶段——先有地图，再谈实现

把一条训练管线拆开，只有七段：

```text
1. dataset     数据集：一批**不可变**的 (输入, 标签)，带内容指纹
2. sampler     采样器：把 epoch 号映射成一串**确定**的访问顺序（同种子同顺序）
3. dataloader  装载器：按批切分并可选丢弃尾批；多进程时先分片再切批
4. device      设备：把参数量换成字节数，并与设备预算对账（不足由 fits 暴露）
5. train       训练：前向 / 反向 / 梯度守卫 / 优化器 step / 每轮推理相评估
6. checkpoint  检查点：五件套落盘 + 清单哈希，可校验、可恢复
7. inference   推理：**只走推理相**（BN 用 running、dropout 恒等），带可注入时钟
```

这张表被写进代码（`types.STAGES` / `STAGE_DESCRIPTIONS` / `STAGE_OWNERS`），
并在导入期做 `set(...) == set(...)` 的闭合断言。**为什么值得写进代码**：
读一个报告里的数字时，第一个问题总是"它属于哪一段"；如果这张表只存在于
教程里，那你读报告时只能靠记忆。

四个轴（`PIPELINE_AXES`）也一并写下来了：`batch`（批数与丢弃）、
`worker`（分片）、`device`（字节）、`time`（延迟与吞吐）。今天的七个阶段、
四个轴、七条性质、五条边界，四张名单**互相引用**，任何一张改了另一张就会在
导入期报错。

## 第二章：数据集——不可变、可切分、可指纹

### 2.1 为什么 `frozen=True` 不是形式主义

```python
@dataclass(frozen=True)
class TabularDataset:
    name: str
    samples: tuple[Sample, ...]        # Sample = (输入, 标签)
```

一次训练里最贵的错误是"数据被就地改过"。它不会报错，只会让**同一个种子
跑出两个不同的结果**——而这恰好是今天最想守住的性质（第七章）。
把数据集做成不可变的元组，`split_dataset` 就只能返回**新对象**，
于是"我改了训练集，评估集怎么也变了"这类问题从类型上就不存在。

### 2.2 内容指纹：回答"这两个分数能比吗"

```text
sign           |  32 条 | 正 16 / 负 16 | 指纹 22bc0a3f878c7012
sign/train     |  24 条 | 正 10 / 负 14 | 指纹 f8f70f5ccf76bc9c
sign/eval      |   8 条 | 正 6 / 负 2  | 指纹 0f2166367b3b3e58
```

指纹的做法与 day053 的评估套件、day088 的 `principle_map` 一致：把样本规范化成
JSON、`sort_keys=True`、紧凑分隔符，取 `sha256` 的前 16 位。三个指纹不同，
说明**这三条曲线上的分数不可直接比较**——这是 day053 就立过的纪律
（"没有绑定信息的分数不是证据"），今天把它用在了数据管线上。

一个容易忽略的细节：**顺序参与指纹**。同一批样本换个顺序落盘就是换了一份数据，
指纹理应变化。上一课的 `preference_fingerprint` 踩过同一个点（当时它是一条
"看起来应该无关顺序、实际有关"的错误测试断言）。

### 2.3 切分：只依赖 `(seed, n)`

```text
口径：切点 = round(n × eval_ratio) 再夹到 [1, n−1]（两侧都非空，打乱用 LCG）
```

"夹到 `[1, n−1]`"这一句是重点：`eval_ratio=0.0` 或 `1.0` 时如果不夹，
就会切出一个空的评估集或空的训练集，而**空集的平均损失是未定义的**——
day095 与 day053 都各自记过一次"空集合的诚实答案是什么都不知道"。
这里选择**直接拒绝**：两侧都非空是一条不变式。

## 第三章：DataLoader 的三个读数

### 3.1 批数与丢弃

```text
批数公式：drop_last=True：批数 = n // b；drop_last=False：批数 = ceil(n / b) = (n + b − 1) // b
丢弃公式：dropped = n − b × 批数（drop_last=True 时它是被整批丢掉的尾批）
```

本课实测（训练集 24 条、批 7）：

```text
装载器 | sign/train | b=7 | shuffle=True | drop_last=False | 批数 4 | 丢弃 0
装载器 | sign/train | b=7 | shuffle=True | drop_last=True  | 批数 3 | 丢弃 3
第 1 轮第 1 批：7 条 | 下标 4..18 | 标签 正 3 / 负 4
```

### 3.2 坑：`dropped` 在"保留尾批"时是负数

第一版直接照抄公式 `dropped = n − b × 批数`。`drop_last=False` 时
`b × ceil(n/b) > n`，于是 10 条样本、批 4 给出：

```text
10 − 4 × 3 = −2        ← "丢弃了负 2 条样本"
```

修法是 `max(0, n − b × 批数)`。这个 `max` **正是保留与丢弃的分界线**：
保留尾批时它恒为 0（没有样本被丢），丢弃尾批时它等于 `n % b`
（被整批丢掉的余数）。一条公式同时覆盖两种语义，比写两个分支更不容易写错。

这类错误的形态值得记住：**它不报错、不崩溃，只是给出一个物理上不可能的数字**。
负的样本数、负的耗时、超过 1 的覆盖率，都属于同一族。

### 3.3 打乱的确定性

`Sampler(seed=...).order(epoch)` 用 LCG 把 `(seed, epoch, n)` 映射成一串置换。
它必须满足：**同一个 seed 的第 k 轮，两次调用给出逐位相同的顺序**。
第 ① 条性质量的就是这个（读数 `0.000e+00`）。

为什么这件事重要：没有它，"第 3 轮落盘、恢复训到第 6 轮"与"一口气训到第 6 轮"
就不可能逐位相等——恢复之后读到的数据顺序会和原来不一样，而**这不会让程序报错**，
只会让两次训练悄悄分叉。

## 第四章：工作进程分片——一条下界判据

多进程加载的第一性原理不是"开进程"，而是"**把索引划分成互不相交、并集为全集的
若干份**"：

```text
worker k 的分片 = { i : i % workers == k }
```

本课实测（24 条样本、4 个 worker）：

```text
worker 0：6 条 | 前 6 个下标 (0, 4, 8, 12, 16, 20)
worker 1：6 条 | 前 6 个下标 (1, 5, 9, 13, 17, 21)
worker 2：6 条 | 前 6 个下标 (2, 6, 10, 14, 18, 22)
worker 3：6 条 | 前 6 个下标 (3, 7, 11, 15, 19, 23)
并集覆盖 1.0，重叠项数 0
```

第 ② 条性质用**下界**判据：并集覆盖率必须 `>= 1.0`。
"互不相交"用相等判据（重叠项数 `== 0`），"并集为全集"用下界判据（覆盖率 `>= 1.0`）。

**为什么"并集为全集"要用下界而不是相等**：覆盖率天然落在 `[0, 1]`，
写 `== 1.0` 也成立，但下界判据的语义更准——它说的是"**一条样本都不能漏**"，
而上界判据说的是"不能超过"。判据类型不是装饰：day095 记过一句
"没有下界判据时，把两个规则写成同一个，报告会全绿"。今天这条覆盖率下界
就是那句话在数据管线上的落点。

## 第五章：设备与显存是纯算术

### 5.1 三块字节

```text
total = params + activations + optimizer_multiplier × params
params      = 参数量 × DTYPE_BYTES[dtype]
activations = batch_size × width × DTYPE_BYTES[dtype]
```

优化器状态按"参数的 `optimizer_multiplier` 倍"估（缺省 3 倍，对应 Adam 的
一阶动量 + 二阶动量 + 主权重）。本课实测：

```text
结构：lstm(H=4, D=1) → bn(4) → dropout → dense(4→2) | 参数 114
cpu/float32  | 参数 456 B + 激活 128 B + 优化器 1368 B = 1952 B / 8.0 GiB | fits=True
cuda/float32 | 参数 456 B + 激活 128 B + 优化器 1368 B = 1952 B / 4.0 GiB | fits=True
mps/float32  | 参数 456 B + 激活 128 B + 优化器 1368 B = 1952 B / 2.0 GiB | fits=True
```

（`456 = 114 × 4`、`1368 = 3 × 456`、`128 = 8 × 4 × 4`。）

### 5.2 放不下时**不抛异常**

把预算人为压到 0：

```text
cuda/float32 | ... = 1952 B / 0.0 GiB | fits=False
  警告：超出预算 928 字节——先降 batch_size、再降 width，最后才考虑换精度
```

`fits=False` 与一条 `warn_line()`，而不是 `raise`。理由是分层的：
"放不下"是一个**可被上层处理的决策输入**（降 batch、换设备、分片），
不是一个非法状态。真正非法的只有"未知设备名"或"非正的批大小"这类
（那两种才抛 `DeviceError` / `ParameterError`）。

这与 day051 的"显存预算表**显式标注不含激活**"是同一条纪律：
**把结论交出来，而不是替调用方做决定。**

### 5.3 搬运报告

```text
CPU → CUDA:0：搬运 1952 字节（参数 456 + 激活 128 + 优化器 1368）
```

`move_report` 把"`.to(device)`"写成一行可读文本。它当然不是真的搬运，
但它把"这一步搬了多少、为什么是这个数"变成了报告的一部分——
**下一课（day087 的量化 / day051 的显存预算）读到的每一个字节都能指回这一行。**

## 第六章：检查点五件套

### 6.1 五个文件、一份清单

```text
五件套 = meta.json + params.json + optimizer.json + metrics.json + history.jsonl
```

本课实测（`step=0`、114 个参数）：

```text
清单：step=0 | 参数 114 | 权重 f2aee63dbed7…9076 | 优化器 e997cccf1505…c7b0 | 文件 5
meta.json        |    345 字节 | 在场=True
params.json      |   2830 字节 | 在场=True
optimizer.json   |    426 字节 | 在场=True
metrics.json     |     34 字节 | 在场=True
history.jsonl    |      0 字节 | 在场=True
```

这个"五件套"的口径来自 day050 的 `sft/checkpoint.py`（超参 / 词表 / 权重 /
指标 / 逐步日志）。今天的区别是**它第一次成为训练回路里的一等公民**：
每个 epoch 落一次、缺文件当场点名、哈希不符当场拒绝。

### 6.2 哈希只覆盖"权重与优化器状态"

清单里的 `params_sha256` 与 `optimizer_sha256` **不包含** `metrics.json` 与
`history.jsonl`。理由与 day052 的适配器清单完全一样：
**这两个哈希回答的是"权重是不是同一份"，不是"文件有没有被动过"**。
把指标也纳进来，会让"我补写了一行日志"变成"权重变了"——
一个永远不会被怀疑、但会让人反复重训的假警报。

### 6.3 缺文件必须点名

```python
raise CheckpointError(f"检查点缺少 {name}：{directory}")
```

不点名的话，调用方看到的是"文件不存在"，然后要去猜是哪一个。
**能点名就点名**——这是 day050 以来一直沿用的写法
（`load_jsonl` 报行号、`load_preferences` 报行号、这里报文件名）。

## 第七章：本课最值钱的一条——恢复训练必须逐位相等

```text
一口气训到第 6 轮：114 个参数
第 3 轮落盘后恢复：114 个参数
最大绝对差：0.0
```

口径写死在代码里：

```text
恢复 = 载入 params + 装回优化器跨步状态 + 从 epoch k+1 继续（order(k+1) 逐位相同）
```

三件事**缺一不可**，而且每一件都可以单独破坏逐位相等：

| 缺哪一件 | 现象 | 为什么不报错 |
|----------|------|--------------|
| 只存参数、不存优化器状态 | Adam 的动量从 0 重新开始，前几步的方向不同 | 训练照常下降，只是曲线与原来分叉 |
| 恢复后重新 `Sampler(seed)` | 第 k+1 轮的顺序与原来不同 | 数据确实变了，程序无法察觉 |
| 从 epoch k 重新训而不是 k+1 | 多训了一轮 | 损失更低，看起来"恢复得很好" |

这三行合起来解释了为什么这条性质值得当成本课的核心：
**它的失败模式全都是"结果更好看或差不多"，而不是"崩了"。**

也正因为它是"相等"判据（`upper_bound=0.0`），它同时钉住了
上一章的分片、上上章的打乱确定性、以及 day092 的优化器状态契约——
一条断言跨了四个模块。

## 第八章：推理封装——只走推理相，时钟可注入

### 8.1 推理相与训练相不是一回事

推理必须**只走推理相**：BatchNorm 用 `running` 统计量（不是本批的 μ/σ），
dropout 恒等。day095 记过一句"训练相与推理相必须不同"，今天把它变成
推理封装的**默认行为**：`predict_one` 内部固定 `phase="eval"`。

第 ⑦ 条性质把它做成可断言的：`predict_batch` 的输出与逐条 `predict_one`
的输出最大绝对差 `0.000e+00`。

### 8.2 延迟读数怎么才可复现

```text
延迟口径：seconds_per_sample = seconds / samples；throughput = samples / seconds
```

问题很直接：`time.perf_counter()` 每次都不同，写进报告的延迟数字**无法复现**，
于是"吞吐从 1e6 涨到 8e6"这句话永远无法被验证。修法是把时钟做成**可注入**的：
默认是 `time.perf_counter`，测试与演示里注入一个确定性的假时钟。

本课实测（假时钟，32 条样本）：

```text
b=1  | 调用 32 次 | 样本 32 | 0.000032s | 每条 0.000001000s | 吞吐 1000000.0/s
b=4  | 调用  8 次 | 样本 32 | 0.000008s | 每条 0.000000250s | 吞吐 4000000.0/s
b=8  | 调用  4 次 | 样本 32 | 0.000004s | 每条 0.000000125s | 吞吐 8000000.0/s
```

**这张表不是"批越大越快"的性能证据**——它证明的是"**读数可复现**"：
把调用次数从 32 降到 4，每样本耗时按同一比例下降，因为假时钟按"每次调用
固定开销"计费。真实的加速比要留给真实硬件去量；本课量的是**口径**。

### 8.3 三个计数

`InferenceEngine` 记 `calls` / `samples` / `latency_seconds` 三个计数，
`reset_counters(engine)` 归零。**把计数与读数分开**：计数器是可变状态，
读数（`LatencyReport`）是不可变快照——于是"我要在报告里放一个中途读数"
不会意外污染后面的累计量。

## 第九章：端到端小项目

把七段串起来，跑一次 M8 的收口实验：

```text
10 轮 × 3 批 | 训练 2.026e+00 → 3.892e-02（↓98.1%）| 推理 2.447e-02（最好 2.447e-02）| 30 步 | 丢弃 0
设备：cpu/float32 | 参数 456 B + 激活 128 B + 优化器 1368 B = 1952 B / 8.0 GiB | fits=True
数据集指纹：22bc0a3f878c7012
```

训练回路的顺序是写死的（与 day095 同一个骨架）：

```text
构造 DataLoader → 每轮打乱 → 逐批 前向/反向（转发 day095 的 loss_and_grad）
  → 梯度范数守卫（转发 day094 的 check_gradient_norm）
  → 优化器 step（转发 day092 的 make_train_optimizer，学习率调度在它内部）
  → 每轮用推理相评一次 → 若给了 checkpoint_dir 则落一次五件套检查点
```

`PipelineReport` 把这次训练的**每一个可核对量**都留下来：
`epochs_run` / `steps` / `batch_count` / `dropped_samples` / `initial_loss` /
`final_train_loss` / `final_eval_loss` / `best_eval_loss` / `improvement` /
`device_plan` / `dataset_fingerprint` / `history`。

**"丢弃 0"这一项为什么必须进报告**：它让"这次训练到底用了几条样本"可核对。
批次切分写错了、`drop_last` 配反了、分片漏了一半——这三种错都会改变实际用到的
样本数，而它们**都会让损失照常下降**。

### 消融表（第 11 节）

```text
基准   | 6 轮 × 24 步 | 训练 1.976e+00 → 5.361e-01（↓72.9%）| 推理 1.955e-01 | 丢弃 0
不洗牌 | 6 轮 × 24 步 | 训练 1.855e+00 → 1.291e-01（↓93.0%）| 推理 9.732e-02 | 丢弃 0
丢尾批 | 6 轮 × 18 步 | 训练 2.084e+00 → 7.294e-01（↓65.0%）| 推理 3.089e-01 | 丢弃 3
```

读法**不是**"不洗牌更好"，而是：**每一个旋钮的代价都出现在一列可读的数字上**。
"不洗牌"这一行训练损失更低、步数却一样——因为固定顺序让模型在同一个顺序上
重复拟合；"丢尾批"这一行步数从 24 降到 18（3 条样本被整批丢掉），
所有读数都要打上这个折扣才能比较。day095 的消融表结论同样是这句话。

## 第十章：七条性质、五个失败族与五条边界

### 10.1 七条性质（三类判据齐全）

```text
通过 shuffle_order_is_deterministic        | 读数 0.000e+00 == 0      | 同 seed 两次 order(3)
通过 worker_shards_partition_the_dataset   | 读数 1.000e+00 >= 1.0    | 覆盖率（下界）
通过 drop_last_matches_batch_formula       | 读数 0.000e+00 == 0      | 批数 vs n // b
通过 device_bytes_match_formula            | 读数 0.000e+00 <= 1e-09  | 上界
通过 checkpoint_round_trip_is_bitwise      | 读数 0.000e+00 == 0      | save → load 逐位
通过 resume_matches_uninterrupted          | 读数 0.000e+00 == 0      | 恢复 vs 一口气
通过 predict_batch_equals_sequential       | 读数 0.000e+00 == 0      | 批推理 vs 逐条
合计：7/7 条通过
```

**五条相等（读数 `== 0`）、一条上界（`<= 1.0e-09`）、一条下界（`>= 1.0`）**——
判据类型是性质的一部分，它们与 `types.PIPELINE_PROPERTIES` 逐名对齐，
并在导入期做闭合断言。

### 10.2 五个失败族

| 族 | 该谁去修 |
|----|----------|
| `ShapeError` | 改调用：批的列数与模型宽度对齐 |
| `ParameterError` | 改调用：`batch_size` / `workers` / `eval_ratio` / `epochs` 都是调用点的一次决定 |
| `NumericError` | 改数据或改实现：出现 nan 时先查更早的那次除法 |
| `DeviceError` | 改调用：设备名不认识，或者精度不在 `DTYPE_BYTES` 里 |
| `CheckpointError` | 改产物：五件套缺一件、或权重哈希对不上 |

`FAMILY_OUTCOMES` 与 `_FAMILY_CLASSES` 逐键对齐，导入期断言；
`RETURNED_FAMILY = "CheckpointError"`（day050 第一次给它命名，此后各课只把它当
工具函数用，今天它成为训练回路里的一等公民），
`ABSENT_FAMILY = "GradientError"`（梯度守卫由 day094 装好，本课只**调用**它，
不重新抛）。

### 10.3 五条边界

```text
1. 不真的探测硬件：设备与预算是**算术表**，不 import torch、不做 cuda 查询。
2. 不做真正的多进程：worker 分片是**索引层的划分**，为的是可复算的读数。
3. 不做异步 IO / 预取：DataLoader 是纯同步的批切分器，延迟读数由假 clock 钉住。
4. 不新增第三方依赖：全部纯标准库实现，不 import torch / numpy。
5. 不改动 day095：网络、损失与梯度全部**调用** regularization 的那一份。
```

## 结语：三条可以带进结业项目的工程结论

1. **把"流程"也变成可断言的算术。** 今天的七条性质里，有六条断言的是流程而不是
   数学：打乱是否确定、分片是否覆盖、批数是否符合公式、字节数是否符合公式、
   检查点是否逐位、恢复是否等价。**流程的正确性同样需要判据**，
   而且它比数学更容易被"结果看起来没问题"掩盖。
2. **"结果更好看"是最危险的失败模式。** 恢复训练时忘了装回优化器状态、
   忘了从 `k+1` 开始——这两件事都会让损失**更低**。所以恢复要用
   **相等判据**（`== 0`）而不是"损失差不多"。
3. **把"不确定的东西"注入进去。** 时钟、随机源、设备预算、数据顺序——
   今天把它们全部做成可注入参数。**可注入才能可复现；可复现才能被断言。**

> **诚实的说明**：本课的所有读数都来自**纯 Python 的算术与一个 114 参数的小模型**
> （lstm(H=4,D=1) → bn(4) → dropout → dense(4→2)），数据集是 32 条合成样本
> （`make_sign_dataset`）。第 8 节的"吞吐提升 8 倍"来自**注入的假时钟**，
> 它证明的是读数口径可复现，**不是**真实 GPU 的加速比；第 5 节的"字节数"
> 是算术表，**不是**实测显存。本课没有 `import torch`、没有 GPU、没有 DataLoader
> 的异步预取，也**不声称**替代真实的 `torch.utils.data`。它给的是
> **一套能带走的判据**：当你真的去写 `DataLoader` 时知道该断言哪七件事。

一张地图，复盘七条性质的组织方式、失败族的演进史，并把"原理 → 应用"这条线
接回主线项目的上层能力。今天定下的三件事会直接复用：**七阶段地图**、
**三类判据（相等 / 上界 / 下界）**、**"缺席要可断言"的族常量**。
