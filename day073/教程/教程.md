### 1.1 三个理由

```text

                                这些都不在公式里，而在"实现公式"的每一步里

③ 数学是后面每一课的"度量衡"     day080 从零实现 Transformer 时，
                                今天这些算子就是它的全部零件
```

### 1.2 与既有实现的关系：不是重复，是"第二种用途"

```text
生产实现    为某一层服务：检索要快、训练要稳、采样要能被温度控制
            取舍写在各自的注释里（例如"零向量返回 0.0 让查询不中断"）
教学实现    为了让公式能被逐行读出来：不加缓存、不为性能让步、

```

两者**必须对得上**。否则会出现最坏的一种情况：教程里算的是 A、线上跑的是 B，
而读者照着教程理解的"模型在做什么"是错的。

## 第二章：向量与矩阵——四种读法，一个零向量

### 2.1 一个向量的四种读法

演示脚本第 1 节的实测（`a = (1, 2, 3)`、`b = (2, 4, 6)`、`c = (0, 3, -2)`）：

```text
a·b         28.000000      两个向量逐分量相乘再相加（1·2 + 2·4 + 3·6）
‖a‖         3.741657       长度 √14
cos(a, b)   1.000000       同向 → 1（与长度无关）
cos(a, c)   0.000000       正交 → 0（1·0 + 2·3 + 3·(−2) = 0）
â            (0.267261, 0.534522, 0.801784)
proj_e1(a)  1.000000       投到 e1 上就是第一个分量
```

四者之间的关系是这一课的第一条主线：

```text
点积只含方向与长度 → 除以两个模长 → 只剩方向（余弦）→ 投影是"在这个方向上有多长"
```

**为什么这四步就是检索的全部**（day064 的语境）：`cos(query, doc)` 的排序
决定了把哪几条拼进提示词。**为什么它也是注意力的全部零件**（第八章）：
`q·k` 就是打分，而"除以 ‖q‖‖k‖"在注意力里被换成了"除以 √d_k"——
因为那一层假设向量已经被归一化过，剩下要控制的只是**维度带来的方差**。

### 2.2 零向量：同一个输入，四种正确行为

演示脚本第 2 节的实测：

```text
math_foundations.linalg.normalize        拒绝：零向量没有方向，无法归一化
math_foundations.linalg.cosine           返回 0.0（0.000000）
vectorstore.metrics.cosine_similarity    返回 0.0（day064：让一条脏数据不打断整批查询）
llm.embedding.l2_normalize               原样返回 [0.0, 0.0]（写入侧不能因此抛异常）
```

四条都不算错，但它们**必须各自说清为什么**。而真正危险的是第五种情况：
**不一样而没人知道**。因此 `bridge` 把这一条写成"有意记录的约定差异"
（状态 `rejected`），而不是"分歧"（状态 `differs`）——见第九章。

代码上的体现（`linalg.normalize`）：

```python
    checked = validate_vector(vector)
    length = norm(checked)
    if length == 0.0:
        raise NumericError(
            "零向量没有方向，无法归一化："
            "如果你要的是'这两个东西像不像'，请用 cosine（它对零向量的约定是 0.0）；"
            "如果你要的是一个单位方向，请先在上游修掉那个零向量。"
        )
    return tuple(value / length for value in checked)
```

**错误消息里给出"另一条路"**是这一课的一个习惯：报错的目的不是拦住调用方，
而是让它知道下一步该走哪。

### 2.3 求和为什么用 `math.fsum`

```python
def dot(left: Vector, right: Vector) -> float:
    ...
    return math.fsum(x * y for x, y in zip(checked_left, checked_right))
```

`sum` 是**顺序**累加，浮点误差随维度线性累积；`fsum` 用精确累加
（Shewchuk 算法）把误差压到与顺序无关。它与"检索里两处余弦必须一致"
是同一类要求：**同一个式子在不同维度上不该给出系统性偏差**。

### 2.4 形状错误必须当场拒绝

```python
    if inner_left != rows_right:
        raise ShapeError(
            f"矩阵乘法内维不一致：左 {matrix_shape(checked_left)} × 右 "
            f"{matrix_shape(checked_right)}——需要左的列数等于右的行数，"
            "否则逐元素相乘会把 k 配错（结果仍然是一组正常的数）。"
        )
```

`zip` 的静默截断是这一课最想拦下的：一个 3×4 乘 3×3 不会报错，
只会**少算一列**（或把两个不同的 k 配到一起），而结果看起来是一组正常的数。

因此 `validate_vector` / `validate_matrix` 是**所有算子的第一行**，
它们一并校验"非空 + 全是有限实数 + 每行等长"：

```text
空向量     没有维度，任何逐元素操作都没有定义
非数值     字符串/None 会一路混到公式里变成 TypeError（栈更深、更难读）
NaN / inf  会污染整条链路：一个 NaN 进来，均值、模长、相似度全变 NaN，
           而"全 NaN"在一张表里看起来像"这一列没数据"
```

## 第三章：softmax——把打分变成概率，且不会炸

### 3.1 一条恒等式，三种输入

```text
softmax(z)_i = exp(z_i) / Σ_j exp(z_j)
```

演示脚本第 4 节的实测：

```text
softmax([0, 0])          (0.5, 0.5)                     平分
softmax([1, 2, 3])       (0.090031, 0.244728, 0.665241)
softmax([1000, 1001])    (0.268941, 0.731059)           ← 直接 exp 会溢出成 nan
softmax([1, 2], T=0.01)  (0.0, 1.0)                     低温 → 趋近 one-hot
softmax([1, 2], T=100)   (0.4975, 0.5025)               高温 → 趋近均匀
```

第三行是这一节的重点：**减去最大值**。

```python
    scaled = [value / temperature for value in values]
    peak = max(scaled)
    exponentials = [math.exp(value - peak) for value in scaled]
    total = math.fsum(exponentials)
    return tuple(value / total for value in exponentials)
```

分子分母同乘 `exp(−max)` 不改变结果，但把 `exp` 的自变量压到 `<= 0`。
在 `z = [1000, 1001]` 上：朴素写法得到 `exp(1000) = inf`、`inf/inf = nan`；
本实现给出正确的 `(0.268941, 0.731059)`。

### 3.2 温度的作用方向

```text
T → 0    概率质量集中到最大值（趋近 one-hot，即贪心）
T = 1    原始分布
T → ∞    趋近均匀分布（输出近乎随机）
```

`temperature <= 0` 当场报错，而不是"取个默认值"：

```python
    if not math.isfinite(temperature) or temperature <= 0:
        raise ParameterError(
            f"温度必须为正的有限数，收到 {temperature!r}："
            "T = 0 的贪心语义请用 argmax 表达（本函数不做截断，"
            "否则'我调了温度'这件事会变成假的）。"
        )
```

最后一句是这一课的纪律：**一次被静默替换成默认值的温度，会让"我调了温度"变成假的。**

### 3.3 log-softmax：朴素写法会直接崩

```python
def log_softmax(logits: Sequence[float]) -> Vector:
    values = validate_vector(tuple(logits), name="logits")
    peak = max(values)
    shifted = [value - peak for value in values]
    log_total = math.log(math.fsum(math.exp(value) for value in shifted))
    return tuple(value - log_total for value in shifted)
```

测试里把这个差异钉住了：

```python
        probabilities = softmax((0.0, -1000.0))
        assert probabilities[1] == 0.0
        with pytest.raises(ValueError):
            math.log(probabilities[1])          # ← math.log(0.0) 直接抛 ValueError
        assert approx(log_softmax((0.0, -1000.0))[1], -1000.0)   # ← 本实现仍然有限
```

注意：`math.log(0.0)` 在 Python 里**不是**返回 `-inf`，而是抛 `ValueError`——
"朴素写法会得到 -inf"是一句常见的错话，实测才知道它会直接把程序打断。

## 第四章：概率——熵、交叉熵、KL 与三个期望

### 4.1 演示脚本第 5 节的实测

```text
预测分布 next-token | 3 个事件 | H=0.8324 nats | 困惑度 2.2988
均匀分布 uniform    | 3 个事件 | H=1.0986 nats | 困惑度 3.0000
H(预测)              0.832396
H(预测, 均匀)         1.098612      ← 交叉熵 ≥ 熵
KL(预测‖均匀)         0.266217
KL(均匀‖预测)         0.308994      ← 非对称
```

四行读数对应四条性质：

```text
H(均匀 n) = ln n          "在 n 个等可能事件之间最没主意"
H(独热) = 0               全押一个事件，没有不确定性
H(p, p) = H(p)            用自己编码自己 = 自己的熵
KL(p‖q) ≠ KL(q‖p)         "用 q 编码 p"与"用 p 编码 q"是两件事
```

而 `困惑度 = exp(H)` 的单位最好解释：**"平均在多少个等可能的候选之间犹豫"**。
均匀 3 事件的困惑度恰好是 3.0000——这不是巧合，它就是它的定义。

### 4.2 两处"不能返回的东西"

```python
def entropy(probabilities, *, tolerance=DEFAULT_SUM_TOLERANCE) -> float:
    ...
    total = 0.0
    for value in checked:
        if value > 0.0:
            total += value * math.log(value)
    return -total
```

**`p_i = 0` 的项贡献 0，而不是 `0·(−inf) = nan`**：一个 `nan` 会顺着"平均熵"
污染整张表。这一条是这一课最容易写错的地方：`-p*log(p)` 在常见输入上完全正确。

```python
        if guessed <= 0.0:
            raise NumericError(
                f"第 {index} 个事件的真值概率是 {actual}，而预测概率是 {guessed}："
                "交叉熵在数学上是 +inf。本包不留这个 inf——"
                "inf 流到均值里会让整张表变成空，而根因是那个给出 0 概率的实现。"
            )
```

**`q_i = 0` 而 `p_i > 0` 时报错**，而不是返回 `+inf`：`inf` 会让下游的均值
变成 `inf`、图表断线、"这次评估没有结论"——而根因（把概率写成 0 的实现）查不出来。

### 4.3 期望与方差的写法

```python
def variance(values: Vector, probabilities: Vector) -> float:
    """方差 ``Var[X] = E[X²] − (E[X])²``（按定义算，不用"平移公式"化简）."""
    ...
    return math.fsum(
        probability * (value - mean) ** 2
        for value, probability in zip(checked_values, checked_probabilities)
    )
```

直接算 `E[(X − μ)²]` 而不是 `E[X²] − μ²`：两个式子在数学上等价，
但后者在 `E[X²]` 与 `μ²` 接近时会发生**灾难性抵消**（两个大数相减得到一个小数，
有效位全丢）——而那正是"同一个分布算两次方差得到两个值"的常见原因。

### 4.4 采样：把随机性变成入参

```python
    cumulative = 0.0
    for index, value in enumerate(checked):
        cumulative += value
        if u < cumulative:
            return index
    return len(checked) - 1
```

演示脚本第 7 节的实测：

```text
概率 (0.5, 0.3, 0.2) → 段边界 0.5 | 0.8 | 1.0
  u = 0.0  → 第 0 个事件      u = 0.5  → 第 1 个事件（边界取后一段）
  u = 0.42 → 第 0 个事件      u = 0.99 → 第 2 个事件
用确定性随机数采 1000 次：(0.487, 0.306, 0.207) —— 接近上面的概率
```

`u` 由调用方给（而不是内部调 `random`），因此"按这个分布采 1000 次"这条结论
**可以被逐位复现**——与 day065 的"能重算的才叫版本号"是同一条纪律。
`uniforms(count, seed)` 用 LCG（线性同余），**不是密码学安全的**，但确定性。

## 第五章：联合分布——条件概率与贝叶斯

### 5.1 一张 2×2 的表

演示脚本第 6 节（"下雨/不下雨" × "带伞/不带伞"）：

```text
joint | 2×2 | I=0.0863 nats | 最大偏差 0.1000
P(A)          (0.4, 0.6)
P(B)          (0.5, 0.5)
P(带伞|下雨)   (0.75, 0.25)
P(下雨|带伞)   (0.6, 0.4)      ← 贝叶斯后验
与列条件分布一致：True
互信息 I(A;B)  0.086305 nats（独立时为 0）
```

### 5.2 贝叶斯后验的三条纪律

```python
        P(A = a | B = b) = P(B = b | A = a) · P(A = a) / P(B = b)
                            └── 似然（表里读） ──┘ └ 先验 ┘   └ 证据 ┘
```

**纪律一：先验缺省取表的边缘，此时后验必然等于列条件分布。**

```python
        resolved_prior = prior if prior is not None else self.marginal_a()
```

这不是巧合，而是一条**可以断言的自洽性**：两者用的都是同一份数据。
若两者不等，说明似然或证据有一处取错了。演示脚本把这一行打了出来
（`与列条件分布一致：True`），测试里也把它钉成了一条用例。

**纪律二：证据为 0 时报错**，不给"后验全是 0"：

```python
        if evidence <= 0:
            raise NumericError(
                f"证据 P(B = {self.names_b[index]}) 为 0：无法做贝叶斯更新——"
                "一个概率为零的观测不会让任何假设变得可能（它只会让整条式子变成 0/0）。"
            )
```

**纪律三：似然为 0 而先验不为 0 时报错**：

```python
            if prior_value > 0 and like == 0:
                raise NumericError(
                    f"似然 P(B = {self.names_b[index]} | A) 为 0，而先验不为 0："
                    "严格按公式会得到'这个原因彻底不可能'，"
                    "但那只是这一份数据不支持它——请改用平滑后的似然，而不是接受一个 0。"
                )
```

### 5.3 互信息：整体 vs 逐格

```python
    def mutual_information(self) -> float:
        joint = entropy(tuple(value for row in self.cells for value in row), ...)
        return self.marginal_a().entropy() + self.marginal_b().entropy() - joint
```

它与 `independence_gap()`（逐格最大偏差）是两种读法：
一个"每格都差一点"的表在逐格判据上可能看着不大，但互信息会明显大于 0。

**为什么两个都要**：逐格偏差能指出"差在哪一格"，互信息能回答"到底有没有关系"。
一个数字都不够。

## 第六章：幂迭代与低秩近似——LoRA 的数学原型

### 6.1 反复乘一个矩阵，主方向会自己浮现

```python
    for _ in range(max_iterations):
        product = matvec(checked, vector)
        candidate = matvec(transposed, product)          # AᵀA v
        vector = tuple(value / norm(candidate) for value in candidate)
        # 收敛判据用"两个单位向量是否平行"（|cos| → 1），而不是逐分量比大小
        if abs(1.0 - abs(dot(vector, previous))) <= tolerance:
            break
        previous = vector
```

为什么把"求 A 的主奇异向量"化成"求 `AᵀA` 的主特征向量"：后者对称半正定，
**一定有实特征值、且幂迭代一定收敛**。

演示脚本第 8 节的实测（对角矩阵 diag(2, 1, 0.5)）：

```text
σ1 = 2.000000   u = (1.0, 0.0, 0.0)   v = (1.0, 0.0, 0.0)
秩 2 提取到的奇异值 (2.0, 1.0)
秩 1 近似的相对误差  0.487950
秩 2 近似的相对误差  0.218218
秩 3 近似的相对误差  0.000000
```

秩 3 的误差是 0（满秩重建必然精确），秩 1 的 0.487950 = `0.5·√…/√5.25`
也是手算可验证的（丢掉的是 1 与 0.5 两层）。

### 6.2 收敛判据为什么不能逐分量比

主向量可能在两步之间**整体翻符号**（`v` 与 `-v` 是同一个方向）。
逐分量比较会把那次翻转当成"还没收敛"，于是永远跑到迭代上限——
而结果其实早就对了。因此判据是"两个单位向量是否平行"：

```python
        if abs(1.0 - abs(dot(vector, previous))) <= tolerance:
```

**精度是二次的**：余弦差 `1e-12` 对应分量误差 `1e-6`（实测：3×3 对角矩阵跑
约 20 轮就到了这个量级）。所以"σ 精确到多少"必须与"方向精确到多少"一起读——
这条经验直接写进了测试的注释，因为第一版断言就是按"应该是精确的"写的，
结果被实测数据推翻。

### 6.3 低秩近似：为什么正交化不能省

```python
        for previous in right_vectors:
            coefficient = dot(v, previous)
            v = subtract(v, scale(previous, coefficient))
```

没有这段 Gram–Schmidt 正交化时，第二轮幂迭代会**再次收敛到同一个主方向**上
（残差里那个方向并没有被真正去掉），于是 `A_r` 变成 `σ₁u₁v₁ᵀ` 的重复叠加——
**误差也没大得离谱**，只是"低秩近似好像不太准"。这类错误没有异常。

**这一节与 day051 的关系**：LoRA 说"冻结 W，只训练 `B·A`（r 很小）"，
今天这一节说"矩阵可以被少数几个方向的叠加近似"——**同一件事的工程实现与数学原型**。
`r=8` 时参数从 `n²` 降到 `2nr`，而它的依据正是前一节的奇异值衰减。

## 第七章：注意力——softmax(QKᵀ/√d_k)·V

### 7.1 四步，每一步都是学过的

```text
① Q Kᵀ            每一行是一个 query 对所有 key 的**打分**（点积 = 方向重合度）
② / √d_k          把打分的方差拉回 1（第八章量给你看）
③ softmax         把打分变成**每一行和为 1 的分布**
④ · V             用这个分布对 value 做**加权平均**
```

形状约定（与原论文一致）：

```text
queries (n_q, d_k)   keys (n_k, d_k)   values (n_k, d_v)
weights (n_q, n_k)   output (n_q, d_v)
```

**K 与 V 的行数必须相同**（一一对应）：不许把"第 3 个 key 的打分"配到
"第 5 个 value"上——而 `zip` 的静默截断正好会做这件事。

### 7.2 演示脚本第 9 节的实测

```text
scaled | (3×3)·2 | 平均熵 1.0514 nats | 集中度 4.3% | scale=0.500000
  第 0 行权重 (0.274069, 0.274069, 0.451863)   峰值 0.4519 @ 位置 2  H=1.0684
  第 1 行权重 (0.274069, 0.274069, 0.451863)   峰值 0.4519 @ 位置 2  H=1.0684
  第 2 行权重 (0.422319, 0.155362, 0.422319)   峰值 0.4223 @ 位置 0  H=1.0174

因果版（平均熵 0.5702 nats | 集中度 48.1%）
  第 0 行权重 (1.0, 0.0, 0.0)                     ← 只能看自己
  第 1 行权重 (0.5, 0.5, 0.0)
  第 2 行权重 (0.422319, 0.155362, 0.422319)     ← 能看全部
```

**因果掩码做了什么**：第 0 行从"看三个位置"变成"只能看自己"（权重恰好 1.0），
因此平均熵从 1.0514 掉到 0.5702、集中度从 4.3% 升到 48.1%。
这正是"看不到未来"在数字上的样子。

三行 query **刻意不同**（见 `bridge.sample_outputs` 的说明）：
如果三行相同，"所有行权重一样"会被误读成结论；现在第 2 行与前两行不同，
读的人一眼能看出"权重取决于这一行的 query"。

### 7.3 因果掩码为什么不用 `-inf`

生产实现常见写法是 `scores + (1-mask)·(-inf)` 再一次性 softmax
（`exp(-inf) = 0`，向量化友好）。本包**不这么做**：

```text
① 非有限数不该进入概率层   softmax 会拒绝 -inf（"非有限数一律拒绝"这条纪律
                          不该在这里出现第一个例外——例外会变成第二个、第三个）
② -inf 会被后续运算静默破坏  -inf·0 = nan、归一化/裁剪/温度缩放都会出问题，
                          而错误出现在离掩码很远的地方
```

第一版实现就是按 `-inf` 写的，跑演示时**被自己的校验层当场拦下**：

```text
NumericError: logits 的第 1 个分量不是有限实数（收到 -inf）：
              NaN / inf 会污染整条链路……
```

这个报错来自 `validate_vector`——也就是说，**"输入一律有限"这条纪律
在最需要它的地方起了作用**。改法是把"掩码"变成显式的：

```python
        allowed = [checked[row][column] for column in range(columns) if mask[row][column]]
        probabilities = iter(softmax(allowed))
        result.append(
            tuple(next(probabilities) if mask[row][column] else 0.0 for column in range(columns))
        )
```

只在"允许看"的位置上做 softmax，再把 `0.0` 插回去。数学上两种做法**完全等价**
（被屏蔽的位置权重就是 0，且不计入分母），但显式掩码让"每一行仍然是一个
合法的概率分布"在这一层**可校验**。

### 7.4 多头：每个头的 `d_k = d/heads`

```text
缩放系数是 1/√(d/heads)，**不是** 1/√d（每个头自己是一个完整的小注意力）
头与头之间没有交互（交互发生在拼接之后的线性层）
```

演示实测：`各头缩放系数 [0.7071..., 0.7071...]`（每头 `d_k = 2` → `1/√2`）。

**多头存在的意义不是"更准"，而是并行的多套子空间**：一个头关注"上一个 token"、
另一个头关注"句子的主语"，各自在自己的低维子空间里算，最后拼起来。
因此 `focus_by_head()`（每个头的集中度）是有信息量的读数：
**所有头都一样说明这个多头结构退化成了一头**。

### 7.5 位置编码：注意力本身是置换不变的

```text
PE(pos, 2i)   = sin(pos / 10000^{2i/d})
PE(pos, 2i+1) = cos(pos / 10000^{2i/d})
```

为什么需要它：把 token 的顺序打乱，`QKᵀ` 只是行列跟着换，**权重集合一模一样**。
因此"顺序"必须由输入带进来，否则"猫追老鼠"与"老鼠追猫"在模型眼里是同一句话。

演示实测（前 4 个位置 × 前 4 维）：

```text
pos=0  (0.0, 1.0, 0.0, 1.0)              ← pos = 0 时 sin 全是 0、cos 全是 1
pos=1  (0.841471, 0.995004, 0.01, 1.0)
pos=2  (0.909297, 0.980067, 0.019999, 0.999998)
pos=3  (0.14112, 0.955336, 0.029996, 0.999996)
```

**每一维是一条不同波长的波**：第 0 维（`10000^0 = 1`）变化最快、
第 2 维（`10000^{0.5} = 100`）变化慢 100 倍。这样不同位置在编码空间里
对应**不同的相位组合**，而"位置差 k"对应一个近似固定的旋转——
模型因此可以从"两个位置编码之差"里读出相对距离。

## 第八章：为什么要除以 √d_k

### 8.1 手推

若 `q`、`k` 的每个分量独立、均值 0、方差 `σ²`，则

```text
Var(q·k) = Var(Σ q_i k_i) = Σ Var(q_i k_i) = d · σ² · σ² = d σ⁴
```

**线性增长**——而 `softmax` 是"指数的归一化"，打分的尺度一大，
它就会把概率质量全押到最大值上（趋近 one-hot，梯度随之消失）。

### 8.2 量出来

`sampled_dot_product_variance` 用确定性随机数做这个实验
（分量取 `[-1, 1]` 均匀，因此 `σ² = 1/3`）：

```text
d=4    | Var 0.4481（理论 0.4444）| 标准差 0.6694 | 缩放后 0.3347
d=16   | Var 1.7436（理论 1.7778）| 标准差 1.3204 | 缩放后 0.3301
d=64   | Var 7.5113（理论 7.1111）| 标准差 2.7407 | 缩放后 0.3426
d=256  | Var 28.5472（理论 28.4444）| 标准差 5.3430 | 缩放后 0.3339
```

两列读数各自说明一件事：

```text
标准差（第 4 列）      0.67 → 5.34：不缩放时打分尺度随维度爆炸
缩放后（第 5 列）      0.3333 附近恒定 = σ²：除以 √d 之后与维度无关
```

第五列恒等于 `σ²` 而不是 1：因为这里的分量方差是 `1/3` 而不是 1。
判据是"**与 d 无关**"，不是"等于 1"——这一点在教程里必须说清，
否则读的人会以为公式记错了。

### 8.3 一条工程纪律（从这一节带走的）

**"能算出来的东西就不要只用一句话带过。"** 这一节完全可以用一句
"点积方差随 d 增长，所以除以 √d"讲完；但把它量出来（并且可复现）有三个好处：

```text
① 它同时验证了推导（理论值）与实现（实测值）
② 读的人能看见"缩放后恒定"这件事**真的成立**
③ 它顺带证明了另一个实现细节：确定性随机数让"这个实验做过"可复核
```

## 第九章：八项对照——公式只有一份真相

### 9.1 对照表

```text
[agrees]   cosine        5 个点，最大误差 0.00e+00     ← vectorstore.metrics
[rejected] normalize     16 个点，最大误差 0.00e+00    ← 零向量上**刻意不同**
[agrees]   softmax       22 个点，最大误差 0.00e+00    ← sft.loss + llm.sampling
[agrees]   log_softmax   11 个点，最大误差 0.00e+00
[agrees]   cross_entropy 4 个点，最大误差 5.55e-17     ← 只有求和顺序之差
[agrees]   perplexity    4 个点，最大误差 0.00e+00
[agrees]   sigmoid       7 个点，最大误差 0.00e+00     ← alignment.objectives
[agrees]   log_sigmoid   7 个点，最大误差 0.00e+00
```

三种结论各有含义，**不能合并**：

```text
agrees     逐点在容差内一致
differs    超出容差 —— 这才是需要改代码的信号
rejected   两边的**拒绝行为**不同 —— 记录的约定差异，两条都对
```

`cross_entropy` 的 `5.55e-17` 是**浮点求和顺序**之差（本包用 `fsum`，
`log_softmax` 里的求和是顺序累加）——它不是错误，而是"逐点比较"这种做法的分辨率下限。

### 9.2 坑一：两边的取样顺序必须逐位对齐

第一版 `check_softmax` 写成：

```python
    def ours() -> list[float]:
        return [value for logits in LOGIT_SAMPLES for value in softmax(logits)] * 2
```

而生产那边是"每个样本依次喂给两个实现"。两条序列内容相同、**顺序不同**，
于是对照报出 `differs`、最大误差 0.73——而两边的实现都完全正确。

```text
这一步最容易做错的地方不是"算错"，而是"拿两串顺序不同的数去比"——
那样得到的"不一致"是假的，而它会让人去改一份本来正确的代码。
```

### 9.3 坑二：同名不同物——logits 还是概率

第二版 `check_cross_entropy` 把**概率**当成了**打分**传进去：

```text
sft.loss.cross_entropy(logits, target)   第一个参数是**打分（logits）**
                                          真值是 **one-hot 下标**
probability.cross_entropy(p, q)          两者都是**概率**（真值是一个分布）
```

它**不报错**：形状对、数值合法。只是又做了一次 softmax、把概率压向均匀：

```text
target 是 argmax      该类的概率被压小 → loss **变大**（像是"模型变差了"）
target 不是 argmax    该类的概率被推大 → loss **变小**（像是"模型变好了"）
```

**两个方向都会出现**，所以"loss 不对劲"这件事不能只看方向——
必须回到**入参形态**去查。修法是把两边的入参形态写明：

```python
    def ours() -> list[float]:
        return [
            our_cross_entropy(one_hot(target, len(logits)), softmax(logits))
            for logits, target in cases
        ]
```

测试里专门留了一条用例把这两个方向都断言下来（`TestLogitsVersusProbabilityTrap`）。

### 9.4 一条更普遍的纪律

```text
"同一个名字"最容易骗人的地方就在于：形状对、数值合法、不报错。
它不会给你一个异常，只会给你一个**可以解释得通**的错结果。
```

这也是为什么这一课的对照不是"跑一遍看差不多"，而是**逐点比较 + 写明入参形态**。

## 第十一章：这一课踩到的四个坑

### 11.1 `-inf` 掩码被自己的校验层拦下（第七章 7.3）

第一版因果掩码按生产写法用 `-inf`，结果 `softmax` → `validate_vector`
当场报"不是有限实数"。**这是纪律生效**，而不是 bug：要么放弃"非有限数一律拒绝"，
要么把掩码改成显式参数。选了后者（数学上等价，且每一行仍是合法分布）。

### 11.2 收敛判据的两处错（第六章）

```text
错法一  逐分量比大小 → 主向量翻符号时永远不收敛（结果其实早对了）
错法二  以为"点对了"就是精确到 1e-12 → 实测只是 1e-6 量级（二次误差）
```

第二处是**被测试推翻的**：第一版断言写的是 `v ≈ (1, 0)`（容差 1e-9），
实测 `v = (0.9999999999997641, 6.867614881771631e-07)`——
差 7 个数量级。修法是把"二次误差"这件事写进测试注释，
并按实测精度放宽断言。

### 11.3 对照里"拿两串顺序不同的数去比"（第九章 9.2）

得到的是一个假的不一致（最大误差 0.73），而两边实现都正确。
**对照工作最大的风险不是算错，而是对照的方法错了。**

### 11.4 `Path("")` 之类的"看起来对"（day072 的延续）

day072 踩过 `Path("") == Path(".")`；今天同类的一个是"空向量当零向量"：
`cosine((0.0, 0.0), a)` 会先撞上**维度不一致**，而不是返回 0.0——
因为"零向量返回 0.0"的约定只在**维度相同**时才有意义。

带走的结论：**"先校验形状，再谈语义"**。今天的每个算子第一行都是
`validate_vector` / `validate_matrix`，就是为了让"形状问题"在语义之前暴露。

## 第十二章：今日总结

| 设计决策 | 背后的原理 | 落地位置 |
|----------|-----------|----------|
| 纯 Python，不用 numpy | 确定性、零依赖、公式可逐行读（代价是慢，已在文档写明） | `linalg` / `probability` |
| 求和一律 `fsum` | 顺序累加的误差随维度线性累积 | 全部算子 |
| 零向量四种约定 | 四处用途不同，各有各的理由；危险的是"不一致而没人知道" | `linalg` / `bridge` |
| 形状先于语义 | `zip` 静默截断会给出"看起来正常"的数 | `validate_vector` / `validate_matrix` |
| softmax 先减最大值 | 一条恒等式换来数值稳定（`[1000, 1001]` 不会炸） | `linalg.softmax` |
| log-softmax 不经由 softmax | `math.log(0.0)` 直接抛 `ValueError` | `linalg.log_softmax` |
| `p=0` 的熵项贡献 0 | 否则 `0·(−inf) = nan` 污染整张表 | `probability.entropy` |
| `q=0` 而 `p>0` 时报错 | `+inf` 会让下游均值变 inf、图表断线，查不到根因 | `probability.cross_entropy` |
| 方差按定义算 | `E[X²] − μ²` 在接近时发生灾难性抵消 | `probability.variance` |
| 采样吃调用方给的 `u` | 让"采 1000 次"这条结论可逐位复现 | `sample_index` / `uniforms` |
| 贝叶斯后验自洽性可断言 | 先验取边缘时后验必然等于列条件分布 | `JointTable.posterior_a_given_b` |
| 幂迭代判据用 \|cos\| | 主向量会整体翻符号，逐分量比较会误判未收敛 | `power_iteration` |
| 低秩近似必须正交化 | 否则第二轮会重复收敛到同一主方向（误差还不太离谱） | `low_rank_approximation` |
| 掩码显式传参，不用 `-inf` | 非有限数不该进入概率层；`-inf` 会被后续运算静默破坏 | `masked_softmax_rows` |
| 多头每头 `d_k = d/heads` | 缩放系数是 `1/√(d/heads)`，不是 `1/√d` | `multi_head_attention` |
| √d 缩放"量出来" | 能算出来的东西不要只用一句话带过 | `sampled_dot_product_variance` |
| 对照的三种结论不合并 | `differs` 才是信号；`rejected` 是记录；合并会掩盖两者 | `CheckOutcome` |
| 对照必须写明入参形态 | "同名不同物"不报错，只给一个可以解释得通的错结果 | `check_cross_entropy` |
| 本课不加配置项 | 容差/温度/秩是"这次计算的判据"，进函数参数 | `types.DEFAULT_TOLERANCE` |
