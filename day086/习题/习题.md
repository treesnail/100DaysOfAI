## 一、选择题（7 题）

**1.** `from_pretrained("org/tiny")` 的第一步是：

- A. 下载权重并反序列化
- B. **把文件找齐**：`repo_id → models--org--tiny/snapshots/<commit>/<相对路径>`
- C. 构造分词器
- D. 读 `config.json` 里的 `architectures` 字段

**2.** 关于"缓存命中"，正确的说法是：

- A. 命中是整仓的：只要有一个文件缺失就整仓重下
- B. 命中是**逐文件**的：第二次解析同一个 commit 时，每一个文件的下载量都是 0
- C. 命中与 revision 无关
- D. 快照目录里存的是哈希名，因此 `config.json` 找不到

**3.** 本包的 `HubError` **不**继承 `ParameterError`，理由是：

- A. 它是一个 `ValueError`
- B. 它要改的是**环境**（联网 / 换 revision / 补缓存），而不是调用参数
- C. 它只在 Windows 上出现
- D. 它继承自 `NumericError`

**4.** 关于 `tie_word_embeddings` 的默认值，正确的说法是：

- A. GPT-2 默认 True、BERT 默认 False
- B. 两个架构都默认 True（真实的 `bert-base-uncased` 也共享词嵌入）
- C. 两个架构都默认 False
- D. 它只影响推理速度，不影响参数量

**5.** 关于前馈中间维，正确的说法是：

- A. 两个架构都按 `4·hidden` 推
- B. GPT-2 的 `n_inner` 缺省时按 `4·hidden` 推，而 BERT 的 `intermediate_size` 缺省是**固定的 3072**
- C. BERT 的缺省是 `2·hidden`
- D. 它由头数决定

**6.** 把三条因果样本拼成一条长序列、仍然只用一张 `(n, n)` 的下三角掩码，后果是：

- A. 会抛形状错误
- B. 第 2 条样本会看到第 1 条样本的全部 token，而输出看起来正常
- C. 只有第 1 条样本会出错
- D. 填充那几行会变成 NaN

**7.** 关于"在进程模型"（`in-process`）与 Ollama，正确的说法是：

- A. 两者的上下文窗口都来自配置文件
- B. 在进程模型的窗口来自**位置表长度**（模型的硬上界），而 Ollama 的默认 4096 是一个部署参数
- C. 在进程模型不需要 `describe`
- D. 两者的 `chat_with_tools` 都支持工具调用

## 四、推导题（3 题）

**16.**（推导）参数量差值的逐项解释。
设隐藏维为 `h`、层数为 `L`。已知配置口径的每一层是 `12h² + 13h`、
本包权重的每一层是 `12h² + 9h`。
（a）请写出本包那一层 `12h² + 9h` 的五项来源（四个投影 + 两个 LayerNorm + 前馈的四块），
并说明每一项各带不带偏置。
（b）证明两者之差恰好是 `4h·L`。
（c）把 `4h` 拆成两个架构各自的项，并说明为什么它们都加起来是同一个数。

**17.**（推导）段内掩码为什么必须是"段内下三角"。
设三条样本长度分别为 `n₁, n₂, n₃`，把它们首尾相接成一条长序列。
（a）写出"整条长序列的下三角"允许集合 `A_full(i)` 与"段内下三角"允许集合 `A_block(i)`。
（b）证明当 `i` 落在第 2 段的首行时，`A_full(i)` 比 `A_block(i)` 多出来的那些列
**恰好是第 1 段的全部位置**。
（c）说明为什么"第 1 条样本的输出在两种掩码下相同"，并解释这件事为什么让这个 bug 很难被发现。

**18.**（推导）均值池化的分母。
设某一条样本的真实长度为 `k`、填充到宽度 `w`（`w > k`），
真实位置上的 hidden state 为 `x₁ … x_k`，填充位置上是 `p₁ … p_{w−k}`。
（a）写出正确版与违反版的输出，并求两者之差的表达式。
（b）证明当 `k = w`（没有填充）时两者**逐位相同**。
（c）若填充位置的值恰好都是零向量，证明违反版的输出**恰好是正确版的 `k/w` 倍**——
并说明这意味着"违反版让向量变短"，从而在余弦相似度上会被**放大**（而不是缩小）。
