## 第一部分：选择题

### 第 1 题（内容身份）

同一份 Markdown 文档被改名为 `a.md` → `b.md`，内容一个字节没变。重新入库之后：

- A. `doc_id` 变了，`chunk_id` 不变
- B. **`doc_id` 不变，`chunk_id` 也不变（两者都由内容派生）**
- C. `doc_id` 不变，`chunk_id` 变了
- D. 两者都变，因为文件路径参与了计算

### 第 2 题（默认度量器）

`chunking_max_tokens = 320` 在项目默认配置下，含义是 320 个：

- A. token（`tiktoken` 精确计数）
- B. 汉字
- C. **字符（默认度量器是 `chars`）**
- D. 字节

### 第 3 题（过滤与排序的顺序）

`where={"source": "handbook"}` 的过滤落在哪一步，直接决定了 Top-K 的结果。正确顺序是：

- A. 先按相似度排全库，再在 Top-K 结果里按元数据筛
- B. **先按元数据把候选缩到子集，再在这个子集里排序取 Top-K**
- C. 两步的结果永远一样，顺序无所谓
- D. 由后端决定，项目不做约定

### 第 4 题（四道减法）

`RetrievalResult` 上四个 `dropped_*` 数字里，哪一个对应 `max_per_doc` 这个旋钮？

- A. `dropped_below_threshold`
- B. **`dropped_by_diversity`**
- C. `dropped_by_top_k`
- D. `dropped_by_rerank`

### 第 5 题（空结果的成因）

一个空结果上写着 `empty_reason="no_data"`。它与 `"filtered_out"` 的区别是：

- A. 两者都是"库里没有数据"，只是写法不同
- B. **`no_data` 是库本身为空；`filtered_out` 是过滤之后候选为零——处置动作不同（建索引 vs 放宽条件）**
- C. `no_data` 是索引漂移导致的
- D. `filtered_out` 说明阈值设得太高

### 第 6 题（重排窗口）

`retrieval_rerank_top_n = 20` 而某次检索召回 35 条候选。关于第 21~35 条，正确的说法是：

- A. 它们会被重排器的分数排在后面
- B. 它们会被直接丢弃，且这件事必须进 `notes`
- C. **它们连重排分都没有拿到，因此"第 25 条其实最贴题"这件事无法被发现**
- D. 它们会被自动补一个默认分

## 第二部分：简答题

### 第 7 题

为什么 M6 的每一层都要留下"我丢了几条"的数字（`dropped_below_threshold` / `dropped_by_diversity` / `dropped_by_top_k` / `dropped_by_rerank` / `dropped_hits`），而不是合成一个 `dropped`？请用"一个可执行的下一步动作"来解释。

### 第 8 题

`index_version_id` 由"编码器身份 + 度量 + 后端 + 内容摘要"算出，**刻意不含时间戳**。请说明：如果加上时间戳，哪三件事会同时失效？

### 第 9 题

### 第 10 题

`min_score` 在混合检索下只作用于向量路，而这件事"无条件进 `notes`"。请解释为什么"进 notes"比"文档里写一句"更可靠——它防的是哪一类事故？

## 第三部分：诊断题

给定一条真实形态的记录（字段名与取值来自 `RetrievalResult.to_dict()` 与 `RagAnswer.to_dict()`）：

```json
{
  "query": {"text": "如何评估生成答案的忠实度", "top_k": 3},
  "count": 0,
  "fetch_k": 9,
  "candidates": 0,
  "filter_applied": true,
  "dropped_below_threshold": 0,
  "dropped_by_diversity": 0,
  "dropped_by_top_k": 0,
  "empty_reason": "filtered_out",
  "channels": ["vector"],
  "llm_called": false,
  "fallback_reason": "no_context",
  "check": null
}
```

### 第 11 题

这一条记录里，**第一个**该被怀疑的环节是哪一个？第二个？请按链路顺序写出你的排查顺序，并说明每一步要看哪个字段。

### 第 12 题

同一个 `query`，把 `filter_applied` 去掉（不带过滤条件重跑）之后 `count=4`、`candidates=6`、`empty_reason=""`（非空），但金标准文档 `rag-006` 仍不在这 4 条里。请判断：问题出在"检索没抓到"还是"排序不对"？还需要看哪两个字段才能区分？

### 第 13 题

一条 case 的记录里出现：

```text
check.given = 3
check.cited = [1, 2, 5]
check.valid = [1, 2]
check.invalid = [5]
check.unused = [3]
check.coverage = 0.6667
check.grounded = false
```

请回答三问：这条答案有没有幻觉引用？`grounded` 为什么是 `false`？如果把 `coverage` 的分母换成"检索到的命中数（4 条）"，读数会变成多少、这个读数错在哪？
