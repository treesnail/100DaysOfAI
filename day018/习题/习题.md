## 第一部分：选择题

### 第 1 题（原语控制权）

MCP 三类原语按"控制权在谁手里"划分。以下对应关系**错误**的是：

- A. Tools —— 模型可控：LLM 自主决定是否调用、传什么参数
- B. Prompts —— 用户可控：由用户显式触发（如斜杠命令）
- C. Resources —— 应用可控：Host 应用根据上下文自动附加
- D. Tools —— 用户可控：每次调用都必须由用户手动确认触发

### 第 2 题（stdio 进程模型）

关于 stdio 传输，以下描述正确的是：

- A. Server 需要预先启动并监听一个 TCP 端口，Client 通过端口连接
- B. Server 是 Client 拉起的子进程，双方通过子进程的 stdin/stdout 管道交换 JSON-RPC 消息
- C. 一个 Server 进程可以同时服务多个 Client 的并发会话
- D. Server 侧可以用 `print()` 往 stdout 输出调试日志，不影响协议

### 第 3 题（错误分层）

`CalculatorTool.execute()` 遇到非法表达式（如 `"import os"`）时返回字符串 `"计算失败: ..."` 而不是抛异常。在 MCP 语义下，这属于：

- A. 协议级错误：响应应该是带 `error.code = -32602` 的 JsonRpcError
- B. 业务级错误：工具被成功调用，失败原因以文本形式放在正常 result 里，LLM 能读到并自我修正
- C. 设计缺陷：所有错误都应该抛异常让 MCP 框架统一处理
- D. 传输级错误：stdio 管道会因此中断

## 第四部分：编程题

### 第 10 题（实现一个 word_count MCP Tool 并测试）

请为本项目新增第三个 MCP tool：`word_count(text: str, top_k: int = 5)`，统计文本中各词的出现频次，返回出现次数最多的 top_k 个词及其次数（格式如 `的: 12\n是: 8\n...`）。

**功能要求**：

1. 在 [mcp_server/server.py](../源码/smart-research-agent/smart_research_agent/mcp_server/server.py) 中用 `@app.tool()` 注册，写清楚 name 与 description（description 要包含一个调用示例——回忆教程 2.3 节，示例是给 LLM 的 few-shot 信号）。
2. 分词规则从简：按空白与常见标点切分，统计长度 ≥ 1 的词；不必实现中文分词器。
3. 频次并列时按字典序排，保证输出确定性。

**测试要求**：在 tests/ 下新增测试，用 `create_connected_server_and_client_session` 内存会话验证：

- `list_tools` 的结果中包含 `word_count`，且其 inputSchema 中 `text` 在 required 列表里、`top_k` 不在；
- 调用 `word_count`，传入 `"a b a c a b"`，断言返回文本中 `a: 3` 排在 `b: 2` 之前；
- 调用时省略 `top_k`，断言使用默认值 5（例如传入 7 个不同词，返回恰好 5 行）。

**提示**：

- 先想清楚 `top_k` 的默认值为什么要体现在函数签名里而不是函数体内——FastMCP 是从签名推导 schema 的。
- 测试是 async 函数，`pyproject.toml` 已配置 `asyncio_mode = "auto"`，无需额外装饰器。
