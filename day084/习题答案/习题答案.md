## 一、选择题

### 1. 答案：B

对齐频率（`aligned`）的正弦表每一对 `(sin, cos)` 贡献 `sin² + cos² = 1`，
共 `d/2` 对 ⇒ `‖PE(p)‖² = d/2`，与 `p` 无关，因此 `‖PE(p)‖ = √(d/2)`。
内积 `sin(a)sin(b) + cos(a)cos(b) = cos(a−b)` 让 `<PE(p), PE(q)> = Σ_i cos((p−q)/f_i)`，
只依赖位移。`staggered` 配对（`cos` 用了隔壁频率）两条一起失效——
实测行范数变成 `(1.414214, 1.642622, 1.669655, 1.390494)`。
出处：day078 第四章、第九章（性质 7）。

### 2. 答案：B

反向两步是
```text
dx          = dInjected                       （逐位传回）
dTable[p]  += dInjected[i]  for i: p_i == p    （按位置**累加**）
```
因为同一个位置可以被多行使用（`positions = (0, 1, 0, 1)`），
"按行覆盖"会让表梯度偏小——实测在位置重复时两种写法差 `4.90e-03`，
而位置互不相同时差恰好 `0.00e+00`（所以覆盖写法在简单样本上完全看不出来）。
出处：day078 第 7.2 节。

### 3. 答案：B

`pre-LN` 是 `y = x + F(LN(x))`（现代主流），`post-LN` 是 `y = LN(x + F(x))`（原论文）。
两者是**同一条代码路径上的一个位置差**，六个阶段的顺序不同：
`pre` 是 `norm1 → branch1 → add1 → norm2 → branch2 → add2`，
`post` 是 `branch1 → add1 → norm1 → branch2 → add2 → norm2`。
出处：day079 第 2.2 节、第 5.1 节。

### 4. 答案：B

```text
4d（两个 LN 的 γ/β）+ 2·d·d_ff（两层线性）+ d_ff（b_in）+ d（b_out）
= 4×6 + 2×6×24 + 24 + 6 = 24 + 288 + 24 + 6 = 342
```
`486 = 342 + 144`（再加注意力那 `4d²`），`1944 = 4 × 486`。
出处：day079 第 4.1 节、day080 第 4.1 节。

### 5. 答案：B


### 6. 答案：B

随机性属于**掩码的生成**，不属于"这一次计算"。掩码固定之后 `y = x ⊙ m · s`
是线性对角算子，梯度完全可以用中心差分逐项核对：正确实现在 `1e-6` 以内，
"先反传再乘掩码"的错法与中心差分差 `> 1e-3`。
注意 `rate = 0` 时两种顺序都对（掩码全是 1），因此该检查只在 `rate > 0` 时有分辨力。
另外 inverted dropout 把缩放放在**训练侧**，推理时什么也不做（因此推理路径逐位相同）。
出处：day081 第 3.1、3.2、2.2 节。

### 7. 答案：B

`encoder_only`（BERT）与 `decoder_only`（GPT）的参数量**完全一样**（都是 1458）——
"差别不在参数量，只在接法"。三者共用同一个 `encoder_block` / `decoder_block`，
注意力算术一行未改。交叉注意力的权重是 `(n_tgt, n_src)` 的**长方形**。
出处：day082 第 3.1、5.2 节。

### 8. 答案：B

一行的熵 ≤ `ln(这一行能看到的位置数)`（Jensen 不等式）。
全开掩码第 0 行天花板是 `ln n`（`n = 4` 时 `1.386294`）；
因果掩码第 0 行天花板是 `ln 1 = 0`，全表平均 `(1/n)Σln(i+1) = 0.794513`。
因此"GPT 比 BERT 尖"里有一半是掩码的账 ⇒ 必须先归一化。
未训练模型的注意力**几乎是均匀的**（实测平均归一化熵 `0.9985`）。
出处：day083 第四章、第 5.1 节。

## 二、简答题

### 9.

```text
① positions   (n,)     → 取位置序列
② table       (n,)     → (n, d)      造表（公式或参数）
③ add         (n, d_in) + (n, d) → (n, d)   要求 d_in == d
④ attend      day075 的七步前向
⑤ project     (n, d_v) → (n, d_out)，y = context·W_oᵀ
⑥ loss        仅监督行 MSE

反向
dx         = dInjected                        （逐位传回）
dTable[p] += dInjected[i]（对所有 p_i == p）   （按位置累加）
```

`dx` 逐位是因为**加法算子对输入的雅可比是单位阵**：`y = x + t` ⇒ `∂y/∂x = I`，
所以上游梯度原样传回。`dTable` 累加是因为**同一个表行可能被多行使用**——
加法对表那一侧的雅可比是"求和"（一个位置被用了 k 次就累加 k 份），
而不是"覆盖"。覆盖写法在位置互不相同时差 `0.00e+00`、在位置重复时差 `4.90e-03`。
出处：day078 第六、七章。

```text
② day079 source_inputs 少一条链（dSource = dK·W_k + dV·W_v 只写了 dK 那一项）
```

### 11.

因为**块必须拥有它的第一个子层**。在 `pre-LN` 摆放下，块内部的注意力作用在
`LN(x)` 上（不是 `x`），因此 `γ₁/β₁` 会影响注意力的输出，进而影响下游的
前馈、第二个 LN 乃至块输出。如果调用方在块外面先算好注意力账、再把"原始 x"
传进块，那么数值差分侧（重新走一遍块、包含 `LN(x)`）与解析侧（用外面那份账）
算的**不是同一个函数**——`norm1_gamma` 那一项会差 `1e-1` 量级（实测 day079 的
第一版正是如此），而形状、行随机、六条性质全都"看起来正常"。
修法是把"造注意力"这件事搬进块里（`block_attention`），
让摆放与子层输入由**同一个构造函数**负责。
出处：day079 第 5.3、11.2 节；day082 第 8.1 节（同一类坑以 `max_gap = 2.237e-01` 再出现一次）。

### 12.

因为两者的**接法相同、只是掩码与训练目标不同**：都只用主流（一个块栈），
都用同一份 `BlockStackParameters`（`d = 6`、`d_ff = 24`、`layers = 3`），
交叉注意力那一整套参数在 `encoder_only` / `decoder_only` 里**不存在**。
因此两者的参数量都必须是 `1458`（PyTorch 侧 `1722`）。

这条等式挡住的是**"忘了数某一类参数"**这种不会报错的错误：
参数少了一块时前向照样跑，只是那一块永远停在初始化值——
而"两条路径数出来的参数量必须相等"这条断言会让它当场亮红。
它还顺带给出了一句值钱的结论：**BERT 与 GPT 的差别不在参数量，只在接法。**
出处：day082 第 5.2 节。

### 13.

因为"可解释性"最容易出的错是**读的不是模型算的那一份**——形状一样、行随机、
熵与天花板都算得出来、热力图也画得出来，**所有读数都合理，只是它们属于另一个问题**。
如果"重算一遍"，会出现两类症状：一是缩放口径不同（单头 `1/√d_k`、多头 `1/√d_head`，
差 `√heads` 倍）；二是作用位置不同（多头必须作用在"某一层的输入"上，
而不是"把模型输入直接喂给第 k 层"——day083 第一版正是这样：
`heads = 1` 在第 0 层逐位相等、在第 2 层**不相等**。
发现它的是这条断言：

```python
def test_the_records_are_the_forward_weights_bit_for_bit() -> None:
    forward = variant_forward(params, inputs)
    records = extract.self_records(params, inputs)
    assert tuple(record.weights for record in records) == forward.block_weights
```

出处：day083 第 1.3、2.2 节。

### 14.

认知科学依据是 **提取练习（Retrieval Practice）**：主动回忆的记忆效果远好于重复阅读
（反复阅读会产生"熟悉感"，而熟悉感会被误当成"掌握了"）。
工程上的等价物是**"两处独立实现 + 一条断言"**——
数值差分 vs 解析梯度、`heads=1` vs day075、`self_records` vs `block_weights`、
生成的 PyTorch 脚本 vs 解析式：**一次独立复现比一次重复阅读有价值得多**，
而"两处分别跑一遍看起来都对"从来不是证据。
出处：day077 序言与第 4 章、day074 第二章。

## 三、诊断题

### 15.

错误在**写法**：`grad_table[positions[i]] = row_gradients[i]` 是"按行覆盖"，
而正确做法是"按位置累加"：

```python
    for i in range(n):
        grad_table[positions[i]] += row_gradients[i]     # 累加，不是覆盖
```

为什么在位置互不相同时完全看不出来：此时每个位置只被用一次，
"覆盖"与"累加"恰好做的是同一件事——实测差 `0.00e+00`。
只有位置重复（如 `positions = (0, 1, 0, 1)`）时，位置 0 被两行共用，
覆盖写法丢掉其中一份，表梯度偏小，偏差量级实测 `4.90e-03`。
症状：**位置编码学得慢一点**——它不会报错，也几乎看不出来。
修复：改成累加，并把"位置重复"作为梯度校验的专测样本（`test_position_encoding_gradients.py`
里的位置序列写成 `(0, 1, 0, 1)`）。
出处：day078 第 1.2、7.2、8.2 节。

```text
读数 A → 反向漏掉了"换手"那一行
```

### 17.

最可能的原因是**某个配置项没有从调用方传到计算函数**——
day081 第一版就是 `step_loss` 没把 `placement` 传下去，于是"post-LN"那几行
实际跑的是 pre-LN。

这一信号（"两条不同的配置给出同一个结果"）是**漏传最典型的表现**：
两条本该不同的曲线**逐位重合成一条**，连四个读数都一模一样，完全看不出异常。
在 day082 里它以 `pads` 的形式再出现一次（T5 的解码器读不到填充信息）。
动作：
```python
def test_placement_is_threaded_through() -> None:
    assert loss_of(placement="pre") != loss_of(placement="post")
```
——把"两条配置必须给出不同结果"写成一条断言。
出处：day081 第 10.2 节；day082 第 3.1、8.2 节。

### 18.

这个读数（`0.997268`）**在掩码不同的两张表之间没有意义**：
一张全开、一张因果时，因果表的上三角**逐位是 0.0**，所以余弦比的其实是
"这张表能看到多少位置"，而不是"两张表看了哪里"——两张掩码不同的表
即使注意力模式完全一样，也会得到一个小得多的余弦。
正确做法是在入口处直接拒绝：

```python
if record.mask != first.mask:
    raise AssemblyError("不同掩码的两张表之间比余弦，比的是'能看到多少'")
```

即：**要求形状与掩码都相同**再比。这也是 day083 第二版修掉的那条"写松了的判据"。
另外还有一条边界：余弦**不区分**"看同一个位置"与"看同一片区域"，
因此判定"死头"要另用一条读数（归一化熵）。
出处：day083 第 5.2、五节。

## 四、推导题

### 19.

设 `θ_i = p/f_i`、`φ_i = q/f_i`。对齐频率的表在第 `i` 对上放的是
`(sin θ_i, cos θ_i)`，因此

```text
<PE(p), PE(q)> = Σ_i [ sin θ_i·sin φ_i + cos θ_i·cos φ_i ]
               = Σ_i cos(θ_i − φ_i)                        （和角公式）
               = Σ_i cos((p − q)/f_i)
```

它只依赖 `p − q`，因为右边只出现差 `p − q`。
**为什么配对必须正确**：如果 `cos` 用了隔壁频率（`φ = q/f_{i+1}`），
那么 `θ_i − φ_i = p/f_i − q/f_{i+1}` 里 `p` 与 `q` 系数不同，
和角公式再也化不成 `cos((p−q)/f_i)`；同时 `sin²θ_i + cos²θ_i = 1` 也失效
（两个三角项不属于同一个角度）。

实测反例：`staggered` 各行范数 `(1.414214, 1.642622, 1.669655, 1.390494)`
（对齐表是四个 `1.414213562373`）；`check_staggered_pairing_breaks_both_laws`
量出的两条偏差是 **行范数偏差 `1.82e-01`、位移律偏差 `1.80e+00`**。
出处：day078 第三章、第四章、第九章（性质 7）。

### 20.

```text
① 等变性     模型 f 是置换等变的：f(π_k x) = π_k f(x)
              ⇒ 序列的轨道（n 个循环位移）给出 n 个输入输出对
② 逐行损失   单行损失是 ‖G_j − o_k‖²（o_k 是目标 one-hot），
              总损失对行求和
③ 轨道平均   等变模型在每个位移上的表现相同 ⇒ 平均损失
              = (1/(n²V))·Σ_j Σ_k ‖G_j − o_k‖²
④ 每行最优   上式对每个 j 独立，`G_j = mean_k o_k` 时最小
              —— 轨道只覆盖 n 个类别（不是全部 V 个），
                 因此最优输出是**袋子分布**（涉及的 n 个 token 上各 1/n），
                 而不是均匀分布 1/V
⑤ 代回       Σ_k ‖袋子 − o_k‖² 平均 = n·(1 − 1/n) = n − 1
              平均损失 = n(n−1)/(n²V) = (n−1)/(n·V)
```

`n = 4`、`V = 6` 时是 `3/24 = 0.125000`。实测：袋子预测器的平均损失恰好 `0.125000`，
**下界是紧的**；而训练出来的等变变体停在 `0.125003`，破对称变体（加正弦位置编码）
越过界到 `0.003188`（命中率 100%）。

两个边界（写进答案才算完整）：
```text
① 它管的是"等变模型"这一类，不是"这个实现"
② 它管的是"能不能到达"，不是"训练能不能找到"
```
出处：day078 第十一章、第 12 章、第 13.1 节。

### 21.

```text
前向   y = x + F(x)
反向   dx = dy + Jᵀ·dy = (I + Jᵀ)·dy
```

`dy` 那一项**不带任何雅可比**：它是"直接加法"这条边反向传回来的梯度，
按定义就是 `dy` 本身。因此无论 `J` 多小（甚至 `J → 0`），
`dy` 那条通路都原样到达下游——这就是"残差给了一条不减值的路"。

`bare`（把 `+x` 关掉）相当于 `y = F(LN(x))`，反向里 `dx = Jᵀ·dy` 只有雅可比那一条路。
深度实验（8 层，`‖∂loss/∂x‖` 相对第 1 层）：
```text
pre_residual   9.27e+00     （基本保持不变）
post_residual  9.45e-01
bare           1.92e-03     （衰减到万分之一量级）
```
`pre` 与 `bare` 在 8 层上相差 **4832 倍**。
出处：day079 第 5.1、5.2、9.2 节。

### 22.

设第 `i` 行的打分向量为 `scores[i][:]`，其中 `(i, j)` 被掩码挡住。
本包的 softmax（`masked_softmax_rows`）分三步：

```text
① 只在**允许的位置**上算 exp（被挡的位置不参与）
② 分母只对允许的位置求和
③ 加权时只用允许的位置
```

因此 `scores[i][j]` 虽然在矩阵里被算出来了，但 **exp / sum / 加权三步都不碰它**——
它不参与任何一个算术运算，所以改它不会改变输出里的任何一个浮点。
这正是"掩码是显式的表"这条纪律的价值：它让"被掩码位置的影响恰好是 0"
成为一条**推论**（而不是靠特判或靠 `-inf` 的极限行为）。

两个前提缺一不可：
```text
① 掩码必须是显式的表（True/False 矩阵）
   写成"把打分设为 -inf 再指望 exp 变成 0"会把 -inf 带进概率层：
   0·(-inf) = nan，一个 nan 会顺着"平均熵"污染整张表
② 被掩码位置的权重必须**恰好是 0.0**
   只有"恰好 0.0"才能让 s_j = 0 ⇒ s_j(g_j − 平均) = 0 这条梯度推论成立；
   "很小的正数"不行——它会带上一点梯度，而前向看起来完全正常
```

day082 把它做成一条可实测的判据：
```text
扰动输入第 j 个 token（乘 1.5），重新前向
  被挡掉的 (i, j)   Δ **恰好 0.0**（逐位）
  允许的 (i, j)     Δ 明显大于 0（最小的读数 allowed_floor > 0）
```
出处：day073 第七章、day075 第五章、day082 第 4.2 节。

## 五、综合题

### 23.（诊断顺序）

从"输出的某一层读数异常"出发，推荐顺序如下（每一步都给出"正常"的判据）：

```text
① 先看读数本身是不是被算错的
   判据：范数用 math.fsum；gain 在 ‖x‖ = 0 时返回 0.0（不是 nan、不是 1.0）；
         carry_share 在残差关时**恰好** 0.0（读数必须能自己解释自己，day080 第 5.3 节）
② 再看前向的"记账"有没有污染张量
   判据：census 只读到张量、不写回张量；stack_forward 每层的输出与下一层输入**逐位**相等
        （`==`，不是 `is`）
③ 再看链上传递的是"值"还是"重算一遍"
   判据：forward.output 与手写循环逐位一致（这个错误的量级是 1e-16，会累积）
④ 再看反向的换手
   判据：第 i 层拿到的 grad_output == 第 i+1 层的 grad_inputs；
        逐层 dW_in 的相对差在 1e-10 量级（不是 2.18e-01）
⑤ 再看反向里的两条链与掩码
   判据：残差那条（dx = dy + dF）、交叉那两条（dSource = dK·W_k + dV·W_v）、
        掩码有没有穿进反向（前向因果 ⇒ 反向也应只有下三角）
⑥ 再看摆放（pre/post）与子层输入
   判据：pre 改 γ₁ 权重会变（断言 !=）；post 改 γ₁ 权重不变（断言 ==）
⑦ 最后才怀疑"训练配置"
   判据：五条配置（参数 / placement / 残差 / 激活 / 掩码）两侧完全一致；
        若两条**本该不同**的配置给出同一个结果 ⇒ 先查漏传（day081 第 10.2 节）
```

顺序的原则：**先排除"读数本身错"，再排除"前向错"，最后才动反向与配置**——
因为前面的每一层错误都会以"后面几层看起来都不对"的形式出现。
出处：day079 第七、十一章；day080 第 3.3、6.3 节；day081 第 10.2 节。

### 24.（最小验收脚本）

```text
第 0 节：构造（离线、确定性）
  from ...positional_encoding import sinusoidal_table, default_positions
  from ...encoder_decoder import make_block_parameters, make_stack_parameters
  from ...transformer_stack import make_shape, make_stack_parameters, stack_forward, stack_backward
  from ...arch_variants import mask_of, mask_allowed_counts, variant_forward, all_scripts
  全部参数由 LCG（day073 probability.uniforms）生成 ⇒ 同一个 seed 完全可复现

第 1 节：位置编码的两条性质读数
  调用：sinusoidal_table(dimension=6, positions=...) / matrix_row_norms / closed_form_offset_inner
  判据：行范数与 √(d/2)=1.732051 的偏差为 0.00e+00（容差 1e-12）；
        对 δ ∈ (1,2,3,5) 的内积与闭式 Σcos(δ/f_i) 的偏差 ≤ 2.22e-16

第 2 节：一条 4 层链的逐层梯度范数
  调用：stack_forward(shape, params, inputs, ...) / stack_backward(forward, ...)
        / stack_gradient_profile(...)
  判据：‖dx‖ 序列与几何平均满足 mean_step_ratio ** (N−1) == ‖dx_{N−1}‖ / ‖dx_0‖；
        逐层 dW 的解析 vs 数值（numerical_layer_parameter_gradients）最大相对误差 < 1e-6
        （实测 7.92e-11），且**第 0 层必须在校验名单里**

第 3 节：三个变体的"掩码外读数"
  调用：for name in VARIANTS: variant_forward(...) → dependency_matrix(...)
        → check_weights_are_zero_where_masked(...) / mask_allowed_counts(...)
  判据：掩码外格子 `== 0.0`（逐位）；允许的格子里最小读数 > 0
        （encoder_only 的 allowed_floor = 5.061108e-03）；
        encoder_only 与 decoder_only 的参数量逐位相等（1458）；
        反证：把掩码换错立刻亮红（decoder_only 用全开 ⇒ 越界 6 格）
```

三条纪律：**每个数标注来源（哪个包、哪个函数）**；
**不同口径不混列**（掩码口径 / 损失口径 / 训练相与推理相）；
**一次只改一个旋钮**。
出处：day078 第 14 章、day080 第 6.5 节、day082 第 5.1、6.3 节。
