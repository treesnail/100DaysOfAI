## 一、选择题（单选）

**1.** MCP 的三大原语与其本质对应正确的是（ ）。

A. Resource = 可执行的行为；Tool = 可读取的数据；Prompt = 提示词模板  
B. Resource = 可读取的数据；Tool = 可执行的行为；Prompt = 提示词模板  
C. Resource = 提示词模板；Tool = 可读取的数据；Prompt = 可执行的行为  
D. Resource = 可执行的行为；Tool = 提示词模板；Prompt = 可读取的数据

**2.** 客户端调用 `resources/read` 请求一个**不存在**的 URI（如 `research://knowledge/nope`）时，在 `create_connected_server_and_client_session` 建立的会话中，客户端侧观察到的现象是（ ）。

A. `read_resource` 返回一个空内容的 `ReadResourceResult`  
B. `read_resource` 返回 `None`  
C. `read_resource` 抛出 `McpError`，其消息包含服务器端处理器的错误信息  
D. 会话直接断开，无任何返回

**3.** JSON-RPC 2.0 响应消息中 `id` 字段的作用是（ ）。

A. 标识服务器身份，防止中间人伪造响应  
B. 标识协议版本，等价于 `jsonrpc` 字段  
C. 把响应与原请求配对——客户端并发发出多个请求后，靠它把响应还给正确的等待者  
D. 作为响应内容的校验和，用于检测传输错误

**4.** 关于 MCP 传输层，下列说法正确的是（ ）。

A. stdio 传输与内存传输使用不同的消息格式，前者是 JSON-RPC，后者是 protobuf  
B. 内存传输只适用于测试，因为它跳过了 JSON-RPC 序列化，消息是 Python 对象直传  
C. stdio 传输要求服务器与客户端在同一台物理机器上，内存传输则没有此限制  
D. 内存传输与 stdio 传输承载完全相同的 JSON-RPC 消息流，差别仅在字节通道，因此用内存传输测过的协议语义在 stdio 部署后保持不变

## 二、判断题（对 / 错，并说明理由）

## 四、编程题

> 在 `day017/源码/smart-research-agent/` 内完成；测试必须离线可跑（内存传输），不得引入新依赖。

**9.** 给服务器新增一个**静态资源**（无参数的固定 URI）：

- URI：`research://knowledge-index`
- 行为：返回 `data/knowledge/` 目录下所有可用文档的清单（每个 `doc_id` 一行，按字典序排序），`mime_type` 为 `text/plain`。
- 同时在 `RESOURCE_DESCRIPTORS` 中补充对应描述。
- 写两个测试：① `list_resources`（注意：静态资源出现在资源列表而非模板列表）能看到该 URI；② 通过内存会话 `read_resource` 读出内容，断言三篇示例文档的 `doc_id` 都在其中。

**10.** 第三章讲了订阅通知的原理：通知只携带 URI，是否重读由客户端决定。请动手模拟这一机制（不要求文件监控，手动触发即可）：

- 在测试文件中写一个 async 测试：先 `read_resource("research://knowledge/rag")` 得到内容 A；然后用 `monkeypatch` 或临时目录把 `load_knowledge_doc` 依赖的文件内容替换（提示：`resources_server.KNOWLEDGE_DIR` 是模块级常量，可用 `monkeypatch.setattr` 指向临时目录，在临时目录里放一份内容不同的 `rag.md`）；再次 `read_resource` 得到内容 B。
- 断言 A ≠ B，并据此回答：这个测试模拟了订阅时序中的哪一段？真实订阅机制补上的是哪一环？
