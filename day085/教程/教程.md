### 1.3 两条纪律：**只承诺行为** + **逐位与容差分开**

```text
承诺      给定同样的权重与输入，复现那几个类的**计算语义**
不承诺    某个符号在第几行、某个内部变量的名字、某个版本的中间张量形状
```

理由与 day080 的"参数量差值必须被逐项解释"同源：源码会随版本重构，
而结构事实（"`ln_1` 在自注意力之前"）跨版本稳定。因此本课的每条断言都写成行为。

第二条纪律是**比法的分家**：

```text
逐位（==）      同一份算术里的两个量：分头/拼回、掩码外是否为 0、因果前缀、融合与分离
容差（1e-12）   两份**独立实现**之间的量：本包 vs day076、本包 vs day079
```

day080 那条"差异要么被消灭、要么被写下来"在这里第三次兑现：跨包对账带着
`max_gap` 与 `tolerance` 两个字段，而不是一句"应该一样"。

## 第二章：四个默认值 —— 读源码读出来的第一样东西

配置文件里的默认值不是"一般认为"，而是**事实**，因此它们是本课最便宜的一批判据。

| 项 | GPT-2（`GPT2Config`） | BERT（`BertConfig`） | 源码里的位置 |
|----|----------------------|---------------------|--------------|
| LayerNorm 的 eps | `layer_norm_epsilon = 1e-5` | `layer_norm_eps = 1e-12` | 每个 `nn.LayerNorm(...)` |
| 激活函数 | `activation_function = "gelu_new"` | `hidden_act = "gelu"` | `MLP` / `intermediate_act_fn` |
| LN 的摆放 | **pre**（`ln_1`/`ln_2` 在子层之前 + 栈尾 `ln_f`） | **post**（每个子层之后一次） | 块内的接线顺序 |
| 注意力投影 | **融合**（一个 `c_attn` 出 `3·hidden` 维） | **三次独立**（`query`/`key`/`value`） | `GPT2Attention` vs `BertSelfAttention` |
| 嵌入后的 LN | 无 | **有**（`word + token_type + position` 之后） | `GPT2Model` vs `BertEmbeddings` |
| `token_type` | 无 | 有（句子 A / 句子 B） | 同上 |

演示脚本第一节把这张表印成两行（`python scripts/hf_source_demo.py`）：

```text
  gpt2  | 摆放 pre  | eps 1e-05 | 激活 gelu_new | 融合QKV True  | 嵌入后 LN False | token_type False
  bert  | 摆放 post | eps 1e-12 | 激活 gelu     | 融合QKV False | 嵌入后 LN True  | token_type True
```

三条值得单独指出的：

```text
① "pre/post" 这条 day079 的结论，在真实源码里的样子是
   "**norm 放在哪两个 Module 之间**"——不是一个开关，而是一次摆放
② 嵌入后的那一次 LN 会改变**第一层**的输入尺度，因此它不是"实现的自由"
   （本包的 `embedding_of` 按画像分派：BERT 侧做 LN、GPT-2 侧不做）
③ 融合与三次独立不是两种算术：切回来必须**逐位相同**（第 3 章）
```

画像驱动也体现在一处 API 上：`source_shape_of("gpt2").causal_default is True`，
而 `source_shape_of("bert").causal_default is False`——"这一次该不该因果"
来自画像，而不是一个每次都手传的开关（手传会漏，而漏了不报错）。

## 第三章：十个阶段 —— 分头发生在投影内部

### 3.1 一条推理链路的十个阶段

```text
① qkv              融合投影：一个 c_attn 一次算出 3·hidden 维（BERT 用三个独立 Linear）
② split_heads      **分头发生在投影内部**：view(n, heads, head_dim).transpose(0, 1)
③ score            打分 Q·Kᵀ（逐头）
④ scale            乘 1/√head_dim（**不是** 1/√hidden）
⑤ bias             加**加性掩码**（-inf 或一个大负数）
⑥ softmax          在最后一维做 softmax（被挡格子**恰好 0.0**）
⑦ attention_dropout 只在训练相；推理相恒等
⑧ mix              加权求和 weights·V（逐头）
⑨ merge_heads      transpose + view 拼回 (n, hidden)
⑩ out_proj         输出投影（GPT-2 的 c_proj / BERT 的 dense）
```

### 3.2 那一次 `view` + `transpose` 就是"分头"的全部

```python
qkv   = c_attn(hidden)                                    # (n, 3·hidden)
query, key, value = qkv.split(hidden, dim=-1)             # 三个 (n, hidden)
query = query.view(n, heads, head_dim).transpose(0, 1)    # ← 就在这里
```

**它没有换块类型、没有换掩码口径、没有换缩放。** 因此同一个 `GPT2Attention`
既能跑 `heads=12` 又能跑因果掩码——day079 记下的那条接口边界
（"一个块只支持一种掩码"）在 HF 里是被**结构**绕开的，而不是被特判绕开的。

本包把这件事写成两条**逐位**判据：

```text
split_heads → merge_heads 逐位还原      heads=1 / 2 / 3 全部 True
切回来与三次独立投影逐位相同             True（三条投影路径的最大差 0.000000e+00）
```

```text
== 2. 融合投影与「分头发生在投影内部」
  c_attn.weight 的形状   18 × 6 = 3·hidden × hidden
  切回后与三个独立投影逐位相同：True
  heads=1：head_dim=6，split→merge 逐位还原：True
  heads=2：head_dim=3，split→merge 逐位还原：True
  heads=3：head_dim=2，split→merge 逐位还原：True
```

### 3.3 一处"切错了不会报错"的地方

`split(hidden, dim=-1)` 的顺序就是拼接的顺序。如果拼接顺序反了
（比如把 `w_value` 拼在最前面），`split_fused` 之后拿到的 `query`
其实是 value——**三个角色互换**，而形状完全合法、注意力照样跑、
读数只是"看起来有点怪"。

因此本包在 `split_fused` 里校验"总行数**恰好**是 `3·hidden`"：
多一行或少了都不接受（`ShapeError`），而**拼接顺序**由一条逐位判据钉住
（`check_fused_matches_separate` 的三条投影路径最大差 `0.000000e+00`）。

### 3.4 缩放是 `1/√head_dim`，而它是一个**派生量**

```text
head_dim = hidden / heads
scale    = 1/√head_dim
```

同一个量在四天里出现过四个名字：day073 的 `scaling_factor`、
day075 的 `softmax_shape_scale`、day076 的 `head_scale`、今天的 `hf_scale`。
它们必须**逐位**相同——本课的读数：

```text
head_dim=3：hf_scale=0.5773502691896258 / head_scale=0.5773502691896258 /
            softmax_shape_scale=0.5773502691896258 | 逐位相同：True
```

理由与 day077 第 4.2 节逐字相同：**一个量只要被写了两遍，
就必须有一条断言让它无法分家。**

## 第四章：加性掩码 —— `exp(-1e9) = 0.0`

### 4.1 HF 的掩码不是"置 0"，而是"加一个很大的负数"

```python
bias = torch.tril(torch.ones(n, n)).view(...)   # 下三角 1、上三角 0
bias = 1.0 - bias                                # 上三角 1
bias = bias * torch.finfo(dtype).min             # 或直接填 -inf
scores  = scores + bias
weights = softmax(scores, dim=-1)
```

### 4.2 它为什么与"显式掩码"**逐位相同**

因为 softmax 之前会先减掉本行的最大值 `m`：

```text
被挡格子   v = s − 1e9 ≤ m − 1e9      ⇒   v − m ≤ −1e9
而         math.exp(-1e9) == 0.0        ← **精确下溢到 0**
```

于是被挡格子的权重**恰好是 0.0**，与"显式掩码 + 只对允许位置归一化"逐位一致。
实测（演示脚本第三节）：

```text
  floor = 1e+09（HF 在 fp32 下用 -inf、fp16 下用 finfo.min）
  math.exp(-1e9) = 0.0（**精确下溢到 0**）
  两处权重的最大差：0.000000e+00（逐位相同：True）
  被挡格子共 14 个，最大读数 0.000000e+00
```

### 4.3 两条前提，两条守卫

这条等价不是"数值上差不多"，而是**精确**的——而它成立有两条前提：

```text
① 本行至少有一个允许位置        否则 softmax 的分母是 0        ⇒ AssemblyError
② 打分远小于 floor              本包要求 |score| < floor/2      ⇒ AssemblyError
```

第 ② 条不是形式主义：如果某个**合法**位置的打分本身就接近 `-1e9`，
被挡格子与合法格子会挤进同一个下溢区间，那时"恰好 0.0"就不再成立。

### 4.4 一处必须写下来的边界：掩码是**布尔表**，不是打分

本包第一版让掩码走了前九天共用的数值校验器
（`math_foundations.types.validate_matrix`），于是测试立刻亮红：

```text
NumericError: mask[0] 的第 0 个分量不是有限实数（收到 True）
```

这个报错本身是对的——它是一个**有意思的**事实：

```text
掩码回答的是"允许 / 不允许"，不是"多少"。
把两者塞进同一个校验器，会得到一个"布尔掩码不能用"的荒唐结果。
```

修法是给掩码一个自己的入口（`checked_mask`）：它校验"行数齐、列数齐、
元素是**布尔值**"，并把"写了 `0.0 / -1e9` 而不是 `True / False`"当场拒绝——
因为那张表已经**译好**了，它不该再被当成掩码用一次。

## 第五章：因果性用**扰动**量出来

day082 的纪律在这里第二次兑现：**"因果"这件事不读 `causal=True` 四个字**，
而是扰动一个输入位置，看输出怎么变。

```text
把第 n−1 行乘 1.5，重新前向
  第 i < n−1 行：输出**逐位不变**（被挡格子从不参与 exp / sum / 加权）
  第 n−1 行：    确实变了（否则这条检查没有分辨力）
```

实测（演示脚本第四节）：

```text
  gpt2（因果）：前 3 行逐位不变 3/3；最后一行变了 True
  bert（双向）：前 3 行逐位不变 0/3；最后一行变了 True
```

BERT 那一行是这条判据的**反证**：双向前向下"未来"确实影响过去，
因此 `0/3` 是**正确**的读数，而不是一个失败。

它同时解释了第 4.2 节那条等价为什么"必须"：如果被挡格子只是"很小"而不是
"恰好 0"，扰动就会通过一个 `1e-12` 量级的泄露传到前面的行上——
而那种泄露**在权重表上是看不见的**（它是"很小的正数"，不是 0）。

## 第六章：同一件事的两种写法 —— 两条跨天对账

本课从 HF 读出来的东西，必须与本课程自己写过的两个包落在同一个值上：

| 对账 | 本包 | 另一端 | 判据 | 实测 |
|------|------|--------|------|------|
| `heads=1` 的注意力 | `hf_source.attention` | day076 `multi_head.layers` | 容差 `1e-12` | 最大差 `0.000e+00` |
| pre 摆放的块 | `hf_source.blocks` | day079 `encoder_decoder.layers` | 容差 `1e-12` | 最大差 `0.000e+00` |
| 缩放系数 | `hf_scale` | `head_scale` + `softmax_shape_scale` | **逐位** | 三者相等 |

必须说清的一条：**前两条的判据是容差，不是逐位**。两份实现各自组织浮点运算的
顺序不必相同（一处乘 `1/√head_dim`、一处除 `√head_dim`；求和顺序也可以不同）。
本课实测恰好是 `0.000e+00`，但**不把"偶然逐位"写成承诺**：
判据仍是容差，实测值只是印出来的读数。

第二条对账为什么值钱：两边的六个阶段逐字相同，**如果两边的块不一样，
那一定有一个人在某个位置多放或少放了一次 LN**——而那个错误在形状上、
在行随机上、在六条性质上**全都是绿的**（day079 第 5.3 节栽过一次，
day082 第 8.1 节又以 `max_gap = 2.237e-01` 栽过第二次）。

## 第七章：两个激活与三个 `eps`

### 7.1 `gelu` 与 `gelu_new`

```text
BERT   hidden_act = "gelu"       0.5x(1 + erf(x/√2))                      精确式
GPT-2  activation_function = "gelu_new"
                                 0.5x(1 + tanh(√(2/π)(x + 0.044715x³)))   tanh 近似
```

逐点绝对差（演示脚本第七节，共 9 个取点）：

```text
x= -4.0  差 5.644e-05      x= -0.5  差 1.722e-05      x= +2.0  差 9.796e-05
x= -2.0  差 9.796e-05      x=  0.0  差 0.000e+00      x= +4.0  差 5.644e-05
x= -1.0  差 1.528e-04      x= +0.5  差 1.722e-05
                           x= +1.0  差 1.528e-04
逐点最大绝对差 1.528e-04
```

`x = 0` 那一行是唯一可被手算断言的一行：两式的**函数值同为 0**（因子 `0.5x`），
**导数同为 `0.5`**（`0.5·(1 + tanh(0)) = 0.5`——与 day079 第 4.3 节量过的是同一个数）。
而逐点最大差 `1.528e-04` 说明"两个默认值不一样"这句话是**可以带一个数**的。

### 7.2 三个 `eps`：同一个算子、三个默认值

```text
gpt2    eps=1e-05 | 实测方差 0.99999500 | 理论 σ²/(σ²+eps) 0.99999500 | 差 1.110e-16 | 离 1 5.00e-06
bert    eps=1e-12 | 实测方差 1.00000000 | 理论 σ²/(σ²+eps) 1.00000000 | 差 0.000e+00 | 离 1 5.00e-13
t5      eps=1e-06 | 实测方差 0.99999950 | 理论 σ²/(σ²+eps) 0.99999950 | 差 1.110e-16 | 离 1 5.00e-07
```

这张表做了三件事：

```text
① 把"同一件事的两种写法"钉住：day079 第 3.2 节那条 variance = σ²/(σ²+eps)
   在这里被三个 eps 各复核一次（实测与理论的差在 1.1e-16 量级，即浮点求和的有理误差）
② 给出"离 1 多远"的三个数：5.00e-06 / 5.00e-07 / 5.00e-13
   —— **它不是误差，是 eps 决定的一个定义量**（day079 那句话的兑现）
③ 说明"BERT 的 LayerNorm 与 GPT-2 的 LayerNorm 是同一条公式、两个默认值，
   而它们的输出**并不相等**"——因此 day083 里"跨模型比读数"必须先说清用哪一套
```

## 第八章：生成 —— 四个 warper 与它们的顺序

### 8.1 `GenerationMixin` 把两件事放在同一个循环里

```text
① 对 logits 做一连串**纯函数变换**（warper / processor）——不改模型、不碰缓存
② 从变换后的分布里**选一个 token**——贪心 / 采样 / 维护一批 beam
```

本课把 ① 拆成四个按**固定顺序**执行的纯函数：

```text
RepetitionPenalty   score = score < 0 ? score·penalty : score/penalty
Temperature         score = score / temperature
TopK                只留最大的 k 个，其余置成"极小值"
TopP                升序排序 + 累积 softmax 删掉 cumsum <= 1−p 的位置 + 至少留 1 个
```

顺序即语义，而它的两个可读后果：

```text
温度**不改变排名**（乘正数），因此它放在 top_k 前后是安全的
top_k 与 top_p 之间是**串联**：top_p 的核是在**已经截断过的**分布上算的
```

### 8.2 `top_p` 的保留个数**由数据决定**

这是最容易被读错的一处。`top_p = 0.5` **不等于**"留一半的词"，
它留的是"累积概率刚超过 `p` 的最小集合"。实测（固定分布
`logits = (2, 1, 0.5, 0, -1, -2)`，可手算）：

```text
top_p=0.10 | 保留 1 | 删掉 5 | 留下的最小累积概率 0.5573
top_p=0.30 | 保留 1 | 删掉 5 | 留下的最小累积概率 0.5573
top_p=0.50 | 保留 1 | 删掉 5 | 留下的最小累积概率 0.5573   ← **退化成贪心**
top_p=0.80 | 保留 3 | 删掉 3 | 留下的最小累积概率 0.8866
top_p=0.95 | 保留 4 | 删掉 2 | 留下的最小累积概率 0.9620
```

而 `top_k` 正好相反：

```text
top_k=1 | 保留 1 | 峰值 1.0000      top_k=3 | 保留 3 | 峰值 0.6285
top_k=2 | 保留 2 | 峰值 0.7311      top_k=6 | 保留 6 | 峰值 0.5573
```

**一个是常数、一个随数据变**——把两者混着读，就会得到
"我设了 `top_p=0.5` 却退化成贪心"这种看起来像 bug 的读数。

### 8.3 一条"不可能失败"的读数也要印出来

HF 的 `TopPLogitsWarper` 里有一行
`sorted_indices_to_remove[..., -min_tokens_to_keep:] = 0`，
它的作用是把"至少留一个 token"写成一条**恒等式**。本课不把它当判据，
而是把**保留个数的最小值**如实印出来——纪律来自 day083 第 7.2 节：

```text
一条永远为真的断言比没有断言更坏，因为它占据了一个"已验证"的位置。
```

## 第九章：两种搜索 —— 贪心与采样各一条，beam 一条

同一个玩具模型（**确定性**）、同一个种子（`seed=7`）：

```text
  greedy   生成 [7,6,6,6,6,6]   逐步保留 [8, 8, 8, 8, 8, 8]
sample/T=1 生成 [2,7,5,7,1,6]   逐步保留 [8, 8, 8, 8, 8, 8]
 top_k=2   生成 [6,6,7,6,6,7]   逐步保留 [2, 2, 2, 2, 2, 2]
top_p=0.7  生成 [5,7,6,7,5,7]   逐步保留 [4, 4, 3, 3, 3, 3]
```

两条值得指出的读数：

```text
① top_k 的"逐步保留"是常数 2，而 top_p 的是 (4,4,3,3,3,3) —— **随步变化**
② 同一个种子给出同一串 token：采样在"u 的来源"之外是纯函数
   （换成 seed=14 立刻得到另一串；这正是"随机性可注入"的价值）
```

而 beam 与贪心的差别不是"更宽就更准"，是**优化目标不同**：

```text
beams=1 lp=1    生成 [0,7,5,7,6] | 跑满 max_new_tokens
beams=2 lp=1    生成 [6,6,6,6,6] | 归一化分数 -1.350130
beams=2 lp=0.5  生成 [6,6,6,6,6] | 归一化分数 -3.018983
beams=3 lp=2    生成 [6,6,6,6,6] | 归一化分数 -0.270026
```

贪心的第一个 token 是 `0`（那一步的 argmax），而 beam 的第一个 token 是 `6`——
因为 beam 优化的是**整条序列的累积对数概率**。
长度惩罚那一项 `final = score / length ** length_penalty` 不是装饰：

```text
每一步都在乘一个小于 1 的概率（对数概率**非正**）⇒ 候选越长、总分越负
lp = 0     不做任何修正     ⇒ 系统性偏向短序列（**这是"默认"的陷阱**）
lp > 0     把"越负"摊薄      ⇒ 偏好更长的序列（lp 越大越强）
lp < 0     反过来放大"越负"  ⇒ 偏好更短的序列
```

而这一处最值得记的是：**参数名是"长度惩罚"，而 `lp > 1` 其实在偏好长序列。**
名字与方向已经不一致了，因此负值（再一次方向反转）被本包明确拒绝
（`GenerationError`），而不是留给读者去试。

## 第十章：这一课踩到的坑

### 10.1 把 (行, 列) 写反的那一刻，形状检查仍然通过

`merge_heads` 的第一版把两个量读错了位置：

```python
rows  = len(heads[0][0])      # ← 这其实是 head_dim（宽度）
width = len(heads[0])         # ← 这其实是 n（行数）
```

它为什么"看起来完全正确"？因为**它是自己跟自己比**：

```text
len(head) != width      →  n != n        ✓ 通过
len(head[0]) != rows    →  head_dim == head_dim  ✓ 通过
```

而真正的失败只在**跨天对账**时才露出来——`heads=1` 的样本上它直接
`IndexError`（要取第 6 行，而矩阵只有 4 行）。带走的结论：

```text
一个"自己跟自己比"的形状检查没有分辨率。
它必须与**另一个来源**比（这里是"切分的顺序"与"拼回的列数"），
而本包真正抓住它的是那条逐位判据：split → merge 必须逐位还原。
```

### 10.2 一个包不能同时用一个名字既指模块又指函数

第一版把生成策略写在 `hf_source/generate.py`，同时在包入口导出函数 `generate`。
于是测试里这一行拿到的是**函数**：

```python
from smart_research_agent.hf_source import generate      # ← 拿到的是函数，不是模块
generate.FILTER_LOGITS                                   # AttributeError
```

Python 的 `from 包 import 名字` 会先看包命名空间里的属性，而
`__init__.py` 里的 `from .generate import generate` 已经把这个名字
**覆盖**成了函数。修法是把模块改名 `generation.py`（与 day069 的
`retrieval/generation.py` 同名同风格）。

这条坑值得记下来的部分是**它为什么难以被发现**：

```text
`import a.b.c` 与 `from a.b import c` 在"父模块属性被覆盖"时的行为**不同**——
  前者经由 sys.modules 拿到子模块，后者拿到被覆盖的那个属性。
因此"测试里能跑"与"包外能跑"可能是两件事。
```

### 10.3 两个"矩阵状"的参数写反了，报错在很远处才出现

`gpt2_mlp(inputs, weights)` 的第一版调用写成了 `gpt2_mlp(weights, inputs)`。
两个参数**都**长得像"若干行的序列"，因此真正的报错来自校验器的最后一道：

```text
ShapeError: inputs 必须是若干行的可迭代的行的序列，收到 FFNWeights
```

带走的结论：**"两个参数长得像"时必须让报错信息带上类型名**，
否则读者要在心底重排一次参数顺序才能看懂。

### 10.4 两处不可达的分支：先减最大值之后，"分母为 0"不可能发生

第一版的 softmax 里有两处"护栏"：

```python
if peak == float("-inf"): ...        # 整行都是 -inf
if total <= 0.0: ...                 # 偏移后的指数全部下溢
```

而"先减最大值"这一步让两者**都不可达**：`peak` 取自本行最大值，
因此 `shifted` 里一定有一个 `exp(0) = 1`，于是 `total >= 1`，且 `peak` 有限。
两条**永远为真的断言**被删掉，而它们的工作交给了更早的一层：

```text
"整行都是 -inf"这件事由入口的 checked_logits / checked_scores 拒绝（带着自己的族）
```

这正是 day083 那句"一条永远为真的断言比没有断言更坏"的同族：
**不是所有的护栏都放在最靠近计算的地方——但每一条都必须真的能被触发。**

### 10.5 一处"落族差异"：入口要用自己的名字报错

前九天共用的校验器把非有限数报成它自己那一族
（`math_foundations.errors.NumericError`）。而本包的调用方会写
`except hf_source.errors.NumericError`——**兜不住**。

修法是给本包的三个入口各配一个校验函数（`checked_logits` / `checked_scores` /
`checked_mask`），它们校验同样的东西，但**用本包的名字报错**。
这条纪律来自 day077 第 4.3 节（那里记下的是 `split_heads` 在两个包里落进了两族）：

```text
跨包按异常类型筛错误时，"同一个错误有两个名字"是一个必须被写下来的事实。
```

### 11.3 一张"这一课读到了什么"的清单

| 读到的东西 | 一句话 | 可失败的判据 |
|-----------|--------|--------------|
| 投影内部分头 | 分头是 `view` + `transpose`，不是换块类型 | split→merge 逐位还原 |
| 融合投影 | `c_attn` 一次出 `3·hidden` 再切三块 | 切回来与三次独立投影逐位相同 |
| 加性掩码 | 掩码是"加一个大负数"，不是"置 0" | 与显式掩码逐位相同（`exp(-1e9)=0`） |
| 因果性 | 不读 `causal=True`，用扰动量 | 前 n−1 行逐位不变 + 最后一行确实变了 |
| 两个 eps | 同一公式、两个默认值 | 实测方差 == `σ²/(σ²+eps)`（差 1.1e-16） |
| 两个激活 | `gelu` vs `gelu_new` | 逐点最大差 `1.528e-04`；`x=0` 处两式为 0、导数为 0.5 |
| 四个 warper | 顺序即语义 | `top_k` 保留数是常数、`top_p` 由数据决定 |
| 两种搜索 | beam 优化整条序列 | beam 的第一步不是贪心的第一步 |
